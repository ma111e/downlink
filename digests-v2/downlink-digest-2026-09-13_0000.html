Hackers exploit Tencent app flaw to deploy GrayRabbit malware

China-linked UNC3569 is actively exploiting CVE-2026-51990 in Tencent Sogou Input Method for Windows to deploy the GrayRabbit backdoor through a one-click crafted link. Tencent patched the protocol-handler flaw in version 16.3.0.3498, but the app’s outdated, unsandboxed Chromium engine remains a security concern.
KEY POINTS
  • 01Gen Threat Labs reported that UNC3569 is actively exploiting CVE-2026-51990 in Tencent’s Sogou Input Method for Windows to deploy the GrayRabbit backdoor through crafted links.
  • 02The one-click attack abuses Sogou’s sgbiz: link handler to pass attacker-controlled instructions to the application, which then opens an attacker-controlled web page in its embedded browser.
  • 03The malicious page exploits a known flaw in Sogou’s outdated Chromium 80 browser engine, which runs without a sandbox and with key web protections disabled, to execute code and install GrayRabbit.
  • 04GrayRabbit can run programs, provide interactive remote command access, transfer files, collect system and user information, and load additional components into memory.
  • 05Tencent released Sogou Input Method version 16.3.0.3498 on April 21 to restrict protocol-handler URLs, though researchers warned that its underlying browser remains outdated and unsandboxed.

Researchers at Gen Digital say the China-linked UNC3569 group is actively exploiting CVE-2026-51990, a critical one-click remote-code-execution flaw in Tencent’s Sogou Input Method for Windows. The group uses crafted links to deploy the GrayRabbit backdoor. Sogou Input Method is widely used in China, with reportedly hundreds of millions of installations.

The attack abuses Sogou’s sgbiz: link handler to pass unvalidated attacker-controlled arguments to a legitimate program, causing its embedded browser to open an attacker-controlled web page. That page exploits a known weakness in the app’s outdated Chromium 80 engine, which runs without a sandbox and with important web-security protections disabled. GrayRabbit can execute processes, open interactive reverse shells, transfer files, collect system and user details, and load plugins into memory.

Tencent released Sogou Input Method version 16.3.0.3498 on April 21 after Gen Threat Labs reported the issue on April 9. The update validates protocol-handler URL arguments, allows only HTTPS, and limits navigation to approved Sogou and Tencent domains. Researchers cautioned that the underlying browser remains outdated and unsandboxed despite the fix.

  • The reported fix limits which URLs the Sogou protocol handler can open, but researchers said the application still contains an outdated Chromium browser that runs without a sandbox and with multiple web protections disabled.
  • The attack requires only a victim to click a crafted custom link, rather than download and run a separate file first.
  • The analyzed GrayRabbit sample is a more mature 64-bit version with expanded commands and an RC4-encoded command-and-control configuration.
  • Google researchers previously linked UNC3569 to both cybercrime activity and the cyber contractor-for-hire ecosystem.

A China-linked hacking group has used a flaw in Tencent’s Sogou Input Method for Windows, a Chinese typing app with hundreds of millions of installations, to install GrayRabbit, a program that can give attackers control over a victim’s computer. The attack can begin when someone clicks a specially made link, which opens the app’s built-in web browser and runs harmful code. Tencent released a fix in version 16.3.0.3498, but researchers say the app still uses an old browser component with weak safety protections, leaving users at continued risk.

Thorough reorganization at NSA will create five 'mission centers,' including cyber and AI

The NSA is rapidly reorganizing into five mission centers focused on China, cybersecurity, AI, combat support, and global intelligence to move intelligence to military users faster. The overhaul, targeted for full capability by January, leaves key details unresolved and risks repeating problems from past restructurings.
KEY POINTS
  • 01The National Security Agency is replacing its existing directorates with five mission centers focused on China, cybersecurity, artificial intelligence, combat support, and global intelligence.
  • 02NSA Director and U.S. Cyber Command head Army Gen. Joshua Rudd informed the workforce of the changes and began a 30-day implementation period.
  • 03The new mission centers are expected to reach full operational capability by January, according to a former NSA official.
  • 04The placement of some organizations, including the Cybersecurity Collaboration Center, remains unclear, while Tailored Access Operations is expected to fall under global intelligence.
  • 05Current and former officials said agency leaders expect the rapid reorganization to disrupt parts of the NSA bureaucracy and require adjustments during implementation.

The National Security Agency is undertaking a major reorganization that will replace existing directorates with five mission centers focused on China, cybersecurity, artificial intelligence, combat support, and global intelligence. Agency leaders aim to get NSA intelligence to military customers and battlefields faster. Army Gen. Joshua Rudd, who leads both the NSA and U.S. Cyber Command, informed the workforce of the changes and started a 30-day implementation period.

Each mission center will have its own chief, with some appointments potentially announced internally as soon as Monday. The centers are expected to reach full operational capability by January, although important details remain unsettled, including the placement of the Cybersecurity Collaboration Center and changes to the NSA’s relationship with U.S. Cyber Command. Tailored Access Operations is expected to move under global intelligence, while current and former officials say leaders expect the rapid shift to disrupt parts of the NSA bureaucracy and require adjustments during implementation.

  • The reorganization is being implemented on an accelerated timeline: the workforce was given 30 days to begin the change, while the new centers are expected to be fully operational by January.
  • Key organizational decisions remain unresolved despite the rapid rollout, including where the Cybersecurity Collaboration Center will sit and how the restructure will alter NSA’s relationship with U.S. Cyber Command.
  • NSA leaders openly anticipate that the overhaul will disrupt parts of the agency’s bureaucracy and require adjustments during implementation.
  • The NSA’s prior large-scale NSA21 restructuring is viewed negatively by current and former officials, who say it increased bureaucratic confusion, creating a documented caution for the new effort.

The U.S. National Security Agency is reorganizing its workforce into five new groups focused on China, digital security, artificial intelligence, military support, and worldwide intelligence. The goal is to deliver information the agency collects to U.S. military forces more quickly. NSA employees and its closely linked U.S. Cyber Command could be affected because responsibilities and teams may change, while leaders acknowledge the fast shift could disrupt work. The change matters because it could shape how quickly the United States can use intelligence and technology in military and national-security decisions.

Attackers Use Passkey Phishing to Hijack Microsoft Cloud Accounts and Exfiltrate Data

Microsoft reports attackers are using AI-assisted executive invoice scams and passkey-themed phishing to steal or gain access to Microsoft cloud accounts. After access, they register attacker-controlled MFA methods for persistence and use Microsoft Graph to collect email, SharePoint, and OneDrive data.
KEY POINTS
  • 01Microsoft reported a campaign that sent more than one million scam emails from August 3 to 5, 2026, impersonating company CEOs to request ACH payments for fake ServiceNow annual subscriptions.
  • 02The invoice scam used AI-assisted email templates, forged approval threads, fabricated invoices, and lookalike domains to make payment requests appear legitimate.
  • 03A separate campaign detected since May 2026 used phone calls, messages, and fake Microsoft sign-in sites to persuade employees to update passkeys, MFA, or single sign-on settings.
  • 04After gaining access to Microsoft cloud accounts, attackers added phone numbers, authenticator apps, or software one-time-password methods they controlled to maintain access.
  • 05Microsoft observed attackers using Microsoft Graph, SharePoint Online, OneDrive for Business, and mailbox APIs to enumerate organizational information and collect files and email data.

Microsoft disclosed two campaigns targeting organizations: a large-scale invoice scam and passkey-themed social engineering aimed at compromising cloud accounts. Between August 3 and 5, 2026, attackers sent more than one million emails impersonating CEOs and requesting ACH transfers for purported ServiceNow annual subscriptions. The messages used AI-assisted templates, fake invoices, forged approval conversations, vendor branding, and lookalike domains to make the requests appear credible.

In the second campaign, detected since May 2026, attackers contacted employees through personal phone calls or messages and directed them to counterfeit Microsoft sign-in pages under the pretense of updating passkeys, MFA, or SSO settings. These lures enabled adversary-in-the-middle or device-code authentication flows, after which attackers added authentication methods they controlled to establish lasting access. Microsoft observed subsequent reconnaissance and data collection through Microsoft Graph, including SharePoint Online, OneDrive for Business, and mailbox activity, with exfiltration lasting from hours to multiple days.

  • The passkey-themed lure can lead victims into device-code authentication, allowing attackers to take over an account without stealing passwords or browser session cookies and thereby bypassing MFA safeguards.
  • Attackers convert an initial account compromise into lasting access by registering an MFA method they control, such as a phone number or authenticator app, rather than relying only on stolen credentials.
  • Microsoft cautioned that individual Microsoft Graph API requests may appear normal, making the sequence of sign-in, authentication-method changes, reconnaissance, and large-scale downloads more important than any single request.
  • The actors use separate IP addresses for sign-in, reconnaissance, and data theft, which can weaken detection approaches that rely only on network indicators.
  • The invoice fraud campaign increased credibility by combining executive impersonation, vendor branding, fake invoices, and forged supporting email conversations instead of relying on a single deceptive message.

Microsoft described two criminal campaigns: one sends fake invoices that appear to come from company leaders, while the other tricks employees into giving criminals access to their work accounts through fake sign-in pages. The targets include U.S. businesses in technology services, consumer goods, real estate, and manufacturing, and the criminals may use stolen accounts to read email and download files from Microsoft’s online services. These scams matter because they can lead to fraudulent bank payments, theft of sensitive business information, and continued access even after an employee has been fooled.

Microsoft describes active, large-scale fraud and cloud-account compromise campaigns affecting enterprise users, including more than one million invoice-scam emails and persistent access through attacker-controlled MFA enrollment. The account-compromise tradecraft and Microsoft Graph-based data collection are broadly relevant to organizations using Microsoft 365 services.

The W-9 Was Real. That Was the Point.

A fraudulent LinkedIn invoice used a genuine, signed IRS W-9 to make the scam appear legitimate, demonstrating that authentic vendor paperwork does not verify the identity of the sender. Organizations should confirm payment requests and remittance changes through an out-of-band contact method using trusted vendor records.
KEY POINTS
  • 01A fake LinkedIn invoice for $31,471.35 was sent to the accounts-payable mailbox of a global pharmaceutical CDMO’s specialty-chemistry subsidiary alongside an authentic, completed LinkedIn IRS Form W-9.
  • 02The W-9 contained LinkedIn’s genuine federal tax number and California corporate address, was signed in January 2025, and contained no active content such as JavaScript, embedded files, or automatic actions.
  • 03The fabricated invoice used real LinkedIn product lines and genuine company details but contained no bank or routing information, instead seeking a reply or confirmation to begin a payment conversation.
  • 04Microsoft 365 quarantined the message as user impersonation before it was released about eighteen hours later, and IRONSCALES analysts ultimately classified it as confirmed malicious.
  • 05The article recommends verifying first payments or changes to payment details through an out-of-band callback using vendor contact information the organization already holds.

A fraudulent email sent to the accounts-payable mailbox of a pharmaceutical CDMO’s specialty-chemistry subsidiary included a $31,471.35 invoice impersonating LinkedIn Corporation. It was accompanied by a completed, authentic IRS Form W-9 bearing LinkedIn’s real tax number, California address, and a January 2025 signature. The invoice was fabricated, but the genuine tax form made the request appear credible despite proving nothing about whether the sender was authorized to seek payment.

Neither attachment contained malicious code or banking information; instead, the invoice repeatedly sought a reply or confirmation so the attacker could continue the payment conversation. The message used a forged internal forward, an invented vendor persona on a newly registered LinkedIn lookalike domain, a separate newly registered reply domain, and a legitimate company’s authenticated transactional sending path that passed DMARC. Microsoft 365 initially quarantined the email for user impersonation before it was released roughly eighteen hours later, and IRONSCALES later classified it as malicious; the article reports no reply and no funds lost. The article’s central recommendation is to verify first payments and remittance changes through an out-of-band call to contact information already held for the vendor, rather than relying on paperwork or email-provided details.

  • A genuine vendor tax form can validate the company details printed on it while providing no proof that the person emailing it is authorized to request payment.
  • The absence of banking details was deliberate: the invoice repeatedly sought a reply, making the immediate objective to establish a conversation before sending payment instructions.
  • File scanning produced defensible but misleading results because the fabricated invoice was clean and the authentic W-9 was inert; the fraud depended on the relationship between the documents and the email’s claim.
  • The message passed DMARC through a legitimate company’s authenticated transactional sending path, showing that authentication success alone did not establish that the request was trustworthy.
  • A quarantine release can negate an earlier impersonation detection, so payment controls must remain effective after a suspicious message reaches a mailbox.

A scammer sent a fake $31,471 LinkedIn invoice to the payment mailbox of a pharmaceutical manufacturing company and included a real, signed LinkedIn tax form to make it look trustworthy. The tax form contained genuine company details but did not prove that the person sending the email worked for LinkedIn. The email was eventually identified as malicious and no money was reported lost, but it shows how criminals can use real documents to trick companies into starting a payment conversation. Businesses need to confirm payment requests by contacting vendors through phone numbers or contacts they already trust, not information supplied in an unexpected email.

RUSTGate: A Drone-Swarm Lure Points to Potential Defence-Sector Targeting

Researchers uncovered RUSTGate Client v2.0, a Rust-based Windows remote-access trojan delivered through a PDF-themed shortcut and drone-swarm research lure, suggesting possible defence-sector targeting. The implant persists via a scheduled task, can execute commands and exfiltrate files, and communicates with a live but temporarily idle HTTP C2 server.
KEY POINTS
  • 01Researchers identified an exposed staging server hosting a Windows infection chain consisting of a PDF-themed shortcut, a drone-swarm research decoy, a batch downloader, and the RUSTGate Client v2.0 implant.
  • 02The shortcut downloads a batch file that retrieves and launches NetworkDiagnostics.exe from C:\Windows\Temp, creates a NetworkDiagnostics scheduled task that runs every 15 minutes, and deletes the batch file.
  • 03RUSTGate can execute Windows shell commands, transfer files in both directions, and automatically search logical drives for selected files including documents, archives, images, configuration files, logs, and backups.
  • 04The implant communicates with its default HTTP controller using AES-256-GCM-protected JSON messages for registration, command polling, command results, and chunked file transfer.
  • 05A bounded probe on 31 August 2026 successfully registered a synthetic client with the controller, but four subsequent polls returned "No commands" and no payload was delivered.

Researchers identified an exposed staging server hosting a Windows infection chain that included a PDF-themed shortcut, a drone-swarm research decoy, a batch downloader, and a Rust implant identifying itself as RUSTGate Client v2.0. The drone-related lure suggests possible targeting of people working in unmanned systems or defence research, though no victim or targeting was independently confirmed. The batch file downloads and launches the implant from C:\Windows\Temp, creates a NetworkDiagnostics scheduled task that repeats every 15 minutes, and deletes itself.

RUSTGate can run arbitrary Windows shell commands, transfer files in both directions, and automatically search all logical drives for selected documents, archives, images, configuration files, logs, and backups. It communicates with a default HTTP command-and-control server using AES-256-GCM-protected JSON messages for registration, polling, command results, and file transfer. During a bounded probe, the server accepted registration from a synthetic client without observed authentication, but four subsequent polls returned “No commands” and delivered no payload. Defenders are advised to investigate the identified IP-and-port pairs, URI paths, scheduled task, temporary-file locations, and the implant’s upload_state.json collection-state file.

  • Because RUSTGate uses a hardcoded shared AES-256-GCM key while retaining plain HTTP transport, a captured sample can enable retrospective decryption of preserved complete C2 message envelopes.
  • The C2 server accepted registration from an arbitrary synthetic client identifier without observed authentication, indicating that registration alone did not require a cookie, token, or client certificate.
  • Unless an operator supplies or separately preserves a client ID, RUSTGate can generate a new hostname-and-random-UUID identifier, potentially creating multiple server-side records for one host.
  • The implant's upload_state.json may be especially valuable during incident response because it tracks processed file paths, sizes, modification times, and MD5 values before remediation.
  • Although the controller was live during the probe, it returned encrypted "No commands" responses to four polls and delivered no second-stage payload in that observation window.

Researchers found a Windows spying and remote-control program called RUSTGate that is delivered through a fake PDF-style file and a drone-swarm research document, potentially aimed at people involved in unmanned systems or defence research. Once opened, it can stay on the computer, run commands chosen by its operators, and search connected drives for documents, images, archives, and other files to send out. No victim has been identified and the suspected targeting is based on the lure, but the program could expose sensitive work and allow attackers to add further tools to an infected computer.
