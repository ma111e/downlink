How Trail of Bits helps verify the integrity of your Signal chats

Trail of Bits now operates an independent auditor for Signal’s Automatic Key Verification system, helping ensure users see a globally consistent and honest mapping of phone numbers to public keys. This reduces reliance on manual safety-number checks and makes server-based key-substitution attacks harder to hide.
KEY POINTS
  • 01Signal launched Automatic Key Verification to help validate that chats are secure without requiring direct safety number comparison.
  • 02Trail of Bits built and operates one of the three auditors that continuously checks whether Signal’s Automatic Key Verification system behaves honestly.
  • 03The Trail of Bits auditor independently verifies that the user-to-public-key map is globally consistent, well formed, and does not hide entries.
  • 04Signal clients currently require recent valid signatures from all three registered auditors: Signal, Cloudflare, and Trail of Bits.
  • 05Trail of Bits implemented its auditor from scratch based on the specification and has released the code as open source.

Signal recently launched Automatic Key Verification, a feature that helps validate that chats are secure without requiring users to directly compare safety numbers. Trail of Bits built and operates one of the three auditors that make the system trustworthy. Its auditor is an independent implementation written from scratch and continuously checks that the Automatic Key Verification system behaves honestly.

Automatic Key Verification uses key transparency to create a globally consistent view of the public keys associated with each phone number. Signal clients periodically check that all keys stored in the global map for the user’s account belong to that user’s devices, and they warn if the log cannot be verified or unexpected keys are found. This matters because a compromised server could otherwise provide a false public key and cause messages to be encrypted to an attacker instead of the intended recipient.

Trail of Bits updates a local Merkle tree copy of the map when new entries are added and periodically signs the tree head with its own signing key. Signal clients currently require recent signatures from all three registered auditors: Signal, Cloudflare, and Trail of Bits. If valid auditor signatures are not presented, Automatic Key Verification fails, and a fully malicious server can maintain a split view for at most one week before client applications begin displaying warnings.

  • A fully malicious Signal key transparency server can maintain a split view of the system for at most one week before client applications start displaying warning messages, because clients require auditor-endorsed tree heads from the last seven days.
  • Signal clients currently require signatures from all three registered auditors, so Automatic Key Verification depends on the availability and valid signing behavior of Signal, Cloudflare, and Trail of Bits together.
  • Trail of Bits intentionally wrote its auditor from scratch rather than using Signal’s reference implementation, providing an independent check against implementation-level assumptions or shared defects.
  • Automatic Key Verification may not support chats that began by searching for a recipient’s username, so users in that situation may still need to fall back to manual safety number comparison.
