Australia warns of global campaign targeting vulnerable CMS platforms

Australia’s Cyber Security Centre warned that attackers are globally scanning and exploiting vulnerable CMS platforms and plugins, including WordPress, Craft CMS, Joomla JCE, and others, to deploy webshells on compromised sites. Website admins should urgently patch CMS software, themes, and plugins, remove unused components, and monitor for unauthorized files or suspicious server processes.
KEY POINTS
  • 01The Australian Cyber Security Centre issued an alert about a global exploitation campaign targeting vulnerable content management systems and plugins.
  • 02The ACSC said many small- to medium-sized Australian businesses have been impacted, with webshells being deployed on their sites.
  • 03The campaign targets vulnerabilities in CMS platforms and plugins including WordPress, Craft CMS, MaxSite CMS, MetInfo CMS, and Joomla JCE.
  • 04The ACSC noted that the campaign might be supported by AI, which can help threat actors accelerate attacks and scale exploitation of emerging flaws.
  • 05Website administrators are advised to apply the latest security updates, remove unused components, enable automatic updates where possible, and monitor for unauthorized file creation.

The Australian Cyber Security Centre issued an alert about a global exploitation campaign targeting vulnerable content management systems and plugins. The agency said many small- to medium-sized Australian businesses have already been affected. As part of the campaign, malicious cyber actors are scanning websites for opportunities to deploy webshells.

The webshells provide persistent access to compromised sites and can allow threat actors to disrupt services, steal credentials, plant additional malware, and move deeper into the network. ACSC said the campaign targets flaws in several CMS platforms and plugins, including WordPress, Craft CMS, MaxSite CMS, MetInfo CMS, and Joomla JCE. The listed affected products include multiple WordPress plugins such as Simple File List, WavePlayer, Ninja Forms, Breeze Cache, WPvivid Backup, Gravity Forms, and others.

ACSC noted that the campaign might be supported by AI, which can help threat actors accelerate attacks and scale the exploitation of emerging flaws. Website administrators are advised to apply the latest security updates for CMS software, themes, and plugins, remove unused components, and enable automatic updates where possible. The agency also recommends making web directories read-only when possible, monitoring for unauthorized file creation, restricting access to sensitive directories, and blocking unexpected child processes on the web server.

  • The campaign is not limited to a single CMS ecosystem; ACSC lists exploited flaws across WordPress plugins as well as Craft CMS, MaxSite CMS, MetInfo CMS, and Joomla JCE, so defenders should not focus only on WordPress patching.
  • ACSC’s mitigation advice goes beyond applying updates by recommending read-only web directories where possible, restrictions on sensitive directories, and blocking unexpected child processes from the web server.
  • Because webshells provide persistent access, simply patching the exploited CMS or plugin may not remove an attacker who has already placed files on the site.
  • The article notes the campaign may be AI-supported, highlighting ACSC’s concern that attackers can accelerate scanning and exploitation of newly emerging CMS flaws.

Australia’s Cyber Security Centre warned that criminals are scanning websites around the world for weaknesses in popular website software and add-ons, and many small and medium Australian businesses have already been affected. The attackers are placing hidden files on sites that let them keep access, disrupt services, steal login details, add more harmful software, or move further into a company’s network. The warning matters because unpatched website tools can turn ordinary business websites into entry points for wider damage.

jscrambler npm Package Compromised in Supply Chain Attack

The npm package jscrambler@8.14.0 was compromised with a preinstall hook that silently drops and runs platform-specific native infostealer binaries during installation. Anyone who installed it should remove the version, revert to a clean release, and rotate credentials exposed on affected developer or CI systems.
KEY POINTS
  • 01The compromised jscrambler@8.14.0 npm release, published on July 11, 2026, added an undocumented preinstall hook that invokes dist/setup.js during npm install.
  • 02Version 8.14.0 introduced new install-time files and hidden platform-specific binaries for Linux, macOS, and Windows that were absent from jscrambler@8.13.0.
  • 03The loader reads an obfuscated CSI container, selects a binary based on the operating system, decompresses it to a hidden temporary file, marks it executable, and launches it in the background.
  • 04The embedded Rust-built payloads are described as cross-platform infostealers targeting developer-focused secrets including cryptocurrency wallets, AI coding assistant configs, cloud credentials, messaging apps, browsers, gaming sessions, and OS keyrings.
  • 05Users are advised to remove jscrambler@8.14.0, rotate credentials accessible to affected development or CI environments, review installation logs for dist/setup.js execution, and pin to jscrambler@8.13.0 or another verified clean release.

A compromised release of the jscrambler npm package introduced hidden native binaries that execute automatically during npm install. The malicious version, jscrambler@8.14.0, was published on July 11, 2026 and added an undocumented preinstall hook that invokes dist/setup.js. Socket detected the compromised package six minutes after publication, and the package has about 15,800 weekly downloads.

The malicious release added new files, including dist/setup.js and dist/intro.js, that were absent from version 8.13.0. intro.js is described as an obfuscated CSI container holding three gzip-compressed native executables for Linux, Windows, and macOS. During installation, setup.js selects the binary matching the victim’s operating system, decompresses it to a randomly named hidden file in the system temp directory, marks it executable, and launches it in the background.

The embedded Rust-built executables are described as cross-platform infostealers targeting developer and cloud-operator machines. The article says the malware targets cryptocurrency wallets, AI coding assistant and MCP configurations, cloud credentials for GCP, AWS, and Azure, messaging apps, browsers, Steam sessions, and OS keyrings. Users are advised to remove jscrambler@8.14.0, rotate credentials accessible to affected development or CI environments, review installation logs for dist/setup.js, and pin to 8.13.0 or another verified clean release until remediation is published.

  • Because the malicious code ran through a preinstall hook, affected users could be compromised even if they never imported the package or ran the Jscrambler CLI.
  • The payload’s targeting of Claude Desktop, Cursor, Windsurf, Zed, VS Code, and other AI developer tooling shows that configuration files for coding assistants and MCP servers should be treated as sensitive secret stores after an exposure.
  • The malware attempted to gather secrets not only from local files and browsers but also from cloud metadata services and APIs, so credential rotation should include cloud service-account, AWS Secrets Manager, SSM Parameter Store, and Azure-related access available to the install environment.
  • The native payloads were launched as detached background processes from randomly named hidden temporary files, making npm install logs and temporary directories important places to check for evidence beyond the package directory itself.
  • The article reports Socket detected the compromised release six minutes after publication, but the package’s roughly 15,800 weekly downloads mean even a short-lived malicious release could still reach developer workstations or CI systems.

A harmful version of the jscrambler software package was published, and simply installing it could quietly run hidden programs on Windows, macOS, or Linux computers before the user’s own code did anything. Developers and build systems that installed jscrambler@8.14.0 may have exposed source code, passwords, cloud access keys, deployment tokens, cryptocurrency wallet data, and other private information. This matters because the package is used in software build pipelines and gets about 15,800 weekly downloads, so one bad release could reach developer workstations and automated systems that hold valuable secrets.

jscrambler npm package publishes malicious preinstall binary

The npm package jscrambler version 8.14.0 was compromised with a preinstall hook that secretly drops and runs a native credential and crypto-wallet stealing binary on Linux, Windows, and macOS. Anyone who installed it should treat the host as compromised, downgrade to 8.13.0, rotate browser-exposed credentials, and check wallets for unauthorized activity.
KEY POINTS
  • 01Version 8.14.0 of the jscrambler npm package was published on July 11, 2026 with a malicious preinstall hook that drops and executes a platform-specific native binary on Linux, Windows, and macOS.
  • 02The compromised package’s dist/intro.js file is a 7.8 MB custom binary container disguised with a .js extension and contains gzip-compressed native executables for supported platforms.
  • 03Static analysis found signs that the payload targets browser credential stores, cookies, web data, Chromium Local Storage and IndexedDB, and crypto wallet seed phrases.
  • 04Harden-Runner observed the dropped binary making outbound calls to archive.torproject.org, check.torproject.org, 37.27.122.124, and 57.128.246.79.
  • 05The article advises anyone who installed jscrambler 8.14.0 to treat the host as compromised, downgrade to 8.13.0, rotate browser-exposed credentials, and audit crypto wallet browser extensions.

On July 11, 2026, version 8.14.0 of the jscrambler npm package was published with a malicious preinstall hook. The package is the official CLI client for the Jscrambler Code Integrity API and had a clean version history dating back to 0.1.0. The compromised release was detected by StepSecurity’s OSS AI Package Analyst with the maximum suspicion rating on publish.

Compared with version 8.13.0, the 8.14.0 tarball grew from 37.8 kB to 7.9 MB and added a loader that reads a disguised 7.8 MB dist/intro.js file. That file is not JavaScript; it is a custom binary container holding gzip-compressed native executables for Linux, Windows, and macOS. During installation, the loader extracts the host-matching binary to a randomly named file in the system temp directory and launches it detached from the npm install process.

Static analysis found signs that the payload targets browser credential stores, cookies, Chromium Local Storage and IndexedDB, and crypto wallet seed phrases. Harden-Runner observed outbound calls to archive.torproject.org, check.torproject.org, 37.27.122.124, and 57.128.246.79. The article advises anyone who installed jscrambler 8.14.0 to treat the host as compromised, downgrade to 8.13.0, rotate browser-exposed credentials, audit crypto wallet extensions, and hunt for dropped files or orphaned processes in temporary directories.

  • The malicious loader was short and unobfuscated because the attacker hid the real logic inside compiled native binaries disguised as a JavaScript file, reducing the amount of suspicious source code available for reviewers or scanners to inspect.
  • The Linux payload’s use of libbpf functions, including bpf_object__open_mem, indicates that its embedded eBPF code could be loaded into the kernel from memory without first writing the eBPF bytecode to disk.
  • The detached and unref’d process design means the malicious binary could continue running after npm install finished, so investigators should look for orphaned processes created around the package installation time rather than only examining the install process itself.
  • CI/CD environments that installed jscrambler 8.14.0 should rotate every secret exposed to the affected job, because the article says npm tokens, cloud credentials, and signing keys may have been reachable by the dropped process.
  • The package size jump from 37.8 kB in version 8.13.0 to 7.9 MB in version 8.14.0 is a concrete anomaly defenders can use when reviewing suspicious package updates.

A trusted software package called jscrambler was updated with hidden harmful code that runs automatically when version 8.14.0 is installed on Linux, Windows, or macOS. People and companies who installed that version, including in build systems, may have had browser logins, cloud and developer tokens, and crypto wallet data exposed. The broader risk is that attackers can abuse trusted software updates to reach many developer machines and company workflows quickly, so affected users should downgrade and replace any secrets that may have been available on those machines.
