ConnectWise Warns ScreenConnect Attacks Continue as SCKit Targets Unpatched Systems

ConnectWise warns that attackers are still targeting unpatched on-premises ScreenConnect systems with enabled third-party extensions to deploy the SCKit toolkit and establish persistence. Partners should immediately disable the affected extensions and update ScreenConnect to version 26.6.5 or later, while checking for any existing unauthorized access.
KEY POINTS
  • 01ConnectWise says attackers continue to target on-premises ScreenConnect environments that have not been updated and still have certain third-party extensions enabled.
  • 02ScreenConnect version 26.6.5 fixes CVE-2026-84869, a critical flaw that can allow unauthorized file transfer and execution during an active remote session in certain circumstances.
  • 03The SCKit toolkit can spread from infected customer devices to managed service provider technicians’ computers and compromise additional managed networks using a C# component called RelayTrap.
  • 04Huntress reported a new spike of SCKit-related activity on November 13, 2026, affecting 205 hosts across 41 organizations.
  • 05ConnectWise disabled five third-party extensions across 400 partner environments and warned that updating software and disabling extensions does not remove access or persistence attackers may have already established.

ConnectWise says it has completed its investigation into unauthorized access affecting partner ScreenConnect environments, but attacks against unpatched on-premises systems are continuing. The company urged partners to immediately disable identified third-party extensions and update ScreenConnect to the latest supported version. ScreenConnect version 26.6.5 addresses CVE-2026-84869, a critical flaw that can permit unauthorized file transfer and execution during an active remote session in certain circumstances.

Researchers at Huntress and Blackpoint Cyber reported that threat actors were suspected of abusing an authentication flaw in RMM+ versions 1.0.31 and 1.0.32 to run unauthorized commands while bypassing ScreenConnect authentication controls. The activity deploys a multi-component toolkit called SCKit, which can spread from infected customer devices to managed service provider technicians’ computers and potentially compromise additional managed networks using a C# component called RelayTrap. ConnectWise disabled five third-party extensions across 400 partner environments, but warned that disabling extensions and updating the software will not remove unauthorized access or persistence already established on affected devices.

  • Disabling the affected extensions and updating ScreenConnect are preventive steps, but ConnectWise says they do not remove any unauthorized access or lasting foothold that may already exist on affected devices.
  • Although SCKit is capable of using the ScreenConnect flaw to run malicious code on a technician’s computer when the technician connects to an infected device, the article states there is no evidence this worm-like behavior succeeded in the latest campaign.
  • The presence of one of the five disabled third-party extensions does not by itself mean a partner environment was compromised.
  • In one incident, the rogue ScreenConnect client made itself appear legitimate by running as a LocalSystem service named "Windows Update Agent" from a folder with the same name.

ConnectWise says attackers are still targeting organizations that use older, unpatched versions of its ScreenConnect remote-support software, especially where certain add-ons remain turned on. The attackers can use a tool called SCKit to place unauthorized software on affected computers and, in some cases, potentially spread from a customer’s computer to the support technician’s computer and then to other customer networks. This matters because managed service providers use ScreenConnect to access many organizations’ systems, so one compromised support environment could put multiple businesses at risk. ConnectWise has disabled five affected add-ons in hundreds of partner environments and urges customers to update the software and check for signs that attackers have already gained lasting access.

OPEN SOURCE ↗

This is an active exploitation warning involving unpatched ScreenConnect environments, a critical CVE-2026-84869, and the SCKit toolkit’s potential to spread from customer systems to MSP technician computers and other managed networks. Security teams using ScreenConnect should treat the required extension disabling, update, and persistence checks as urgent.

N-able Patches 17 N-central Flaws as Attackers Exploit Earlier Bugs to Deploy Crypto Miners

N-able released N-central 2026.4 Hotfix 3 to fix 17 critical flaws, including issues enabling root-level code execution, authentication bypass, and data exposure. Organizations should immediately update on-premises servers and all Agents and Probes, as earlier 4EverAble2Shell flaws are already being exploited to deploy cryptominers.
KEY POINTS
  • 01N-able released N-central 2026.4 Hotfix 3, a critical security update that addresses 17 vulnerabilities across authentication, agent and probe communications, file handling, server components, legacy APIs, and user management.
  • 02The update permanently removes the legacy API configuration option, which blocks the attack path for 4EverAble2Shell when legacy API mode is enabled.
  • 03N-able said on-premises N-central customers should upgrade their servers promptly, while hosted customers receive server-side updates automatically.
  • 04All hosted and on-premises customers must update their Agents and Probes because unupdated components remain susceptible to impersonation.
  • 05Attackers have actively exploited earlier 4EverAble2Shell flaws to deploy cryptocurrency miners on vulnerable N-central servers.

N-able released N-central 2026.4 Hotfix 3, a critical security update that fixes 17 flaws affecting its remote monitoring, management, and endpoint-management platform. The fixes cover authentication and access controls, Agent and Probe communications, file handling, server components, and user-management controls. The update also completely removes the legacy API configuration option, permanently blocking its use.

The vulnerabilities include issues that could permit local privilege escalation, authentication bypass, root command execution, missing authorization checks, XML external entity injection, server-side request forgery, and remote code execution through path traversal. N-able said on-premises customers should upgrade their servers immediately, while hosted servers are being updated automatically. All customers must also update Agents and Probes, as outdated versions remain susceptible to impersonation; attackers have already exploited earlier 4EverAble2Shell flaws to deploy cryptocurrency miners on vulnerable servers.

  • Hosted N-central customers receive the server-side update automatically, but they still must update every Agent and Probe because older versions can be impersonated.
  • Removing the legacy API entirely eliminates the configuration condition required for successful 4EverAble2Shell exploitation, rather than merely adding a temporary restriction.
  • The security response has operational consequences: N-able states that remote-control functionality and Intune integration remain blocked.
  • The patching urgency is elevated because attackers have already used earlier N-central flaws to install cryptocurrency miners on vulnerable servers.

N-able released an urgent update for its N-central system, which businesses use to monitor and manage computers remotely. The update fixes 17 weaknesses that could let outsiders bypass protections, view information, change records, or take control of affected computers. Organizations using N-central, especially those running it themselves, need to install the update and refresh connected software components because older flaws are already being used to install cryptocurrency-mining programs on vulnerable systems.

OPEN SOURCE ↗

This is a critical N-central patch covering 17 vulnerabilities, including flaws that can enable root command execution and remote code execution. It is especially urgent because earlier 4EverAble2Shell flaws are already being actively exploited to deploy cryptocurrency miners.

Uluru Uses Netskope CASB to Retire VPN and Achieve Company-Wide Zero Trust

Uluru replaced its VPN with Netskope CASB to implement company-wide zero-trust access, improving secure access controls for users and applications.
KEY POINTS
  • 01Uluru uses Netskope CASB as part of its security approach.
  • 02Uluru retired its VPN.
  • 03Uluru achieved a company-wide zero-trust model.

Uluru uses Netskope CASB to retire its VPN and achieve company-wide zero trust. The article presents Netskope CASB as the technology supporting this transition. Uluru’s stated outcome is a company-wide zero-trust approach.

The change replaces VPN use with Netskope CASB in Uluru’s security model. The article frames retiring the VPN and deploying zero trust as connected goals. The named organizations and technology are Uluru, Netskope, and Netskope CASB.

  • Uluru’s case shows that a CASB deployment can be positioned as an alternative to maintaining a traditional VPN.
  • The stated outcome combines two organizational changes: retiring the VPN and extending zero-trust access across the company.
  • Netskope CASB is presented as the central technology supporting Uluru’s zero-trust transition.

The article describes how Uluru stopped relying on a virtual private network, or VPN, and adopted Netskope’s cloud access service to use a “zero trust” approach. This means workers must be checked before accessing company systems rather than automatically receiving broad access after connecting. It matters because organizations can reduce the chance that an unauthorized person gets wide access to important business resources.
