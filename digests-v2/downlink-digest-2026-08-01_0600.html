Hijacked Hotel Wi-Fi Pushes Fake Updates to Deliver Surveillance Malware

Microsoft says Russian-linked Storm-2945, a sub-cluster of Midnight Blizzard/APT29, is hijacking hotel Wi-Fi captive portals to redirect travelers to fake updates and Microsoft device-code login flows that deliver CornFlake surveillance malware or steal cloud access. Travelers should avoid installing anything offered through captive portals and use always-on full-tunnel VPNs where possible.
KEY POINTS
  • 01Microsoft says a fake browser update served over hijacked hotel Wi-Fi has been used to deliver CornFlake, a remote access trojan that can capture webcam images, microphone audio, and keystrokes.
  • 02Researchers track the operation as CaptiveCrunch and Microsoft attributes it to Storm-2945, assessed as an operational sub-cluster of Midnight Blizzard, also known as APT29 and Cozy Bear.
  • 03On compromised networks investigated by ReliaQuest, attackers with administrative control of the captive portal gateway could forge DNS answers and redirect a laptop’s automatic connectivity check to a fake browser or operating system update.
  • 04Since July 16, some CaptiveCrunch landing pages have redirected guests into Microsoft’s device code authentication flow, where entering an attacker-supplied code on Microsoft’s legitimate sign-in page can grant the attacker-controlled session MFA-satisfied access.
  • 05Microsoft reports that CornFlake can steal browser cookies and saved passwords, scan removable media, open a remote shell, and maintain persistence through a Registry Run key, a scheduled task, and a watchdog.

A fake browser update served through hijacked hotel Wi-Fi has been used to deliver CornFlake, a remote access trojan that can capture webcam images, microphone audio, and keystrokes. Microsoft tracks the operation as CaptiveCrunch and attributes it to Storm-2945, which it assesses as an operational sub-cluster of Midnight Blizzard, also known as APT29 and Cozy Bear. Microsoft has observed the traffic manipulation since early May across hospitality networks in several countries, but it has not named a hotel, venue, or captive portal vendor.

On networks investigated by ReliaQuest, the captive portal gateway also acted as the DNS resolver assigned to connected devices, allowing attackers with administrative control to forge DNS answers and redirect traffic. The gateway could send a laptop’s automatic connectivity check to a fake browser or operating system update page, but it did not silently infect endpoints; victims still had to download or execute the payload. Some pages used ClickFix instructions that told victims to open a terminal or Windows utility and run an attacker-supplied command.

Since July 16, some CaptiveCrunch landing pages have redirected guests into Microsoft’s device code authentication flow, where entering an attacker-supplied code on Microsoft’s legitimate sign-in page can grant MFA-satisfied access to an attacker-controlled session. Microsoft’s analysis says CornFlake can steal browser cookies and saved passwords, record clipboard contents, scan removable media, open a remote shell, and maintain persistence through a Registry Run key, a scheduled task, and a watchdog. Researchers also identified ChocoShell, an in-memory PowerShell stealer that collects Microsoft 365 and Azure Active Directory access and refresh tokens, plus Web Account Manager tokens, from Token Broker cache files.

  • The hijacked hotel gateway does not silently infect devices; users still have to download, execute, or run attacker-supplied instructions, making traveler awareness and refusal of captive-portal update prompts a critical control.
  • An always-on full-tunnel VPN is specifically recommended because it sends DNS queries through corporate resolvers before the hotel gateway can answer them, reducing the attackers’ ability to redirect traffic from the local network.
  • The campaign also targets cloud account access through Microsoft’s legitimate device code authentication flow, so compromise can occur even without installing malware if a guest enters the attacker-supplied code.
  • Microsoft found common equipment and management systems across affected networks, suggesting the issue may involve shared services in parts of the captive portal ecosystem rather than only isolated hotel compromises.
  • Public reporting does not quantify how often redirects led to successful malware execution, device-code approval, or stolen accounts, so the known activity is significant but its real-world success rate remains unclear.

Attackers took control of some hotel Wi-Fi sign-in systems and used them to send guests to fake browser or computer update pages. If a traveler followed the prompts, their device could be infected with spying software that can record things like webcam images, microphone audio, typing, screenshots, saved passwords, and online account access. Microsoft links the operation to a Russian government-associated hacking group, and the concern is that travelers in several countries could be tricked through networks they normally trust while away from home.

Adobe Campaign Classic CVSS 10.0 Flaw Could Run Code Without User Interaction

Adobe released security updates for Campaign Classic to fix a maximum-severity CVSS 10.0 flaw that could allow arbitrary code execution without user interaction, plus a high-severity SQL injection bug. Users should update to ACC v7 7.4.3 build 9398, with additional Adobe Bridge fixes also available.
KEY POINTS
  • 01Adobe released security updates for Campaign Classic to address a maximum-severity flaw tracked as CVE-2026-48449 with a CVSS score of 10.0.
  • 02CVE-2026-48449 is described as an incorrect authorization issue that could allow arbitrary code execution in the context of the current user without requiring user interaction.
  • 03The Campaign Classic update also fixes CVE-2026-48448, a high-severity SQL injection flaw with a CVSS score of 8.6 that could allow arbitrary file reads.
  • 04Adobe said it is not aware of any of the Campaign Classic flaws being exploited in the wild.
  • 05Adobe also released updates for Adobe Bridge to fix eight critical-rated flaws that could lead to privilege escalation and arbitrary code execution.

Adobe released security updates for Campaign Classic, its enterprise-focused marketing automation platform, to address a maximum-severity security flaw that could result in arbitrary code execution. The flaw is tracked as CVE-2026-48449 and has a CVSS score of 10.0. Adobe described it as an incorrect authorization issue that could allow code execution in the context of the current user without requiring user interaction.

The Campaign Classic update also fixes CVE-2026-48448, a high-severity SQL injection vulnerability with a CVSS score of 8.6. Adobe said this issue could enable arbitrary file reads. The company said it is not aware of any of the flaws being exploited in the wild, and both Campaign Classic issues have been addressed in ACC v7 7.4.3 build 9398 for Windows and Linux.

Adobe also shipped updates for Adobe Bridge to fix eight critical-rated flaws that could lead to privilege escalation and arbitrary code execution. The listed Bridge issues include untrusted search path, incorrect authorization, path traversal, and out-of-bounds write vulnerabilities. Adobe credited security researchers Kieran, also known as “kaiksi,” and “yjdfy” for discovering and reporting the Bridge flaws, and advised users to apply the latest updates for optimal protection.

  • The most urgent action is specifically to upgrade Adobe Campaign Classic v7 deployments on both Windows and Linux to version 7.4.3 build 9398, which is the fixed release named by Adobe.
  • The Campaign Classic flaws are especially serious because one could run code without any user interaction, while the other could enable arbitrary file reads, giving defenders two different impact paths to consider when prioritizing patching.
  • Although Adobe says it has not seen exploitation in the wild, the CVSS 10.0 rating means the Campaign Classic update should be treated as a top-priority preventive fix rather than deferred until attacks are reported.
  • Adobe Bridge users also need attention because the same update cycle fixes multiple critical-rated issues, including flaws tied to arbitrary code execution and privilege escalation.

Adobe released fixes for serious security problems in Adobe Campaign Classic, a marketing automation platform used by enterprises, and also fixed several problems in Adobe Bridge. The most serious Campaign Classic issue could let someone run their own code without the user doing anything, and another issue could let someone read files they should not access. Adobe says it has not seen these problems being used in real attacks, but users are advised to install the latest updates to stay protected.

Hackers Poison Adform Script to Swap Crypto Wallet Addresses Across Customer Sites

Attackers compromised Adform’s shared JavaScript tracking file to swap Bitcoin, Ethereum, and Tron wallet addresses on customer websites, creating a supply-chain risk for visitors who copied or entered crypto addresses. Adform removed the code and advises users to clear browser caches and verify wallet addresses before sending funds.
KEY POINTS
  • 01Attackers modified Adform’s trackpoint-async.js JavaScript file served from s2.adform.net to rewrite Bitcoin, Ethereum, and Tron wallet addresses on customer sites.
  • 02Adform detected the incident on July 27, 2026, removed the malicious code, notified affected clients, reported it to authorities, and advised users to clear browser caches and verify wallet addresses before sending funds.
  • 03The captured malicious code operated only while an affected page remained open and was not designed to install software or establish persistence, according to Adform.
  • 04The captured sample watched copy, cut, paste, and input events, rewrote text nodes and form fields, and attempted an HTTP request to 84.32.102.230:7744 with the page hostname and path.
  • 05The public scope remains unclear, including how many websites carried the altered file, how many visitors were exposed, how attackers reached Adform’s deployment path, and whether any funds were diverted.

Attackers modified a JavaScript file served by advertising technology company Adform, turning it into browser-side code that rewrote cryptocurrency wallet addresses. Adform detected the incident on July 27, 2026, removed the malicious code, notified affected clients, and reported it to authorities. Anyone who visited a site carrying the affected script on July 27 and copied a Bitcoin, Ethereum, or Tron address may have pasted a different address inserted by the malicious code instead.

The compromised resource was trackpoint-async.js, served from s2.adform.net, and Adform’s tracking code can run on one page, several sections, or across an entire website. Because the same shared resource could be used by unrelated downstream sites, the article describes the incident as a supply-chain compromise. The public scope remains unclear, including how many websites carried the altered file, how many visitors were exposed, how the attackers reached Adform’s deployment path, and whether any funds were diverted.

A captured sample contained two malicious blocks appended to the legitimate library, with replacement strings obfuscated using a six-byte XOR key. The code watched clipboard and input-related events, rewrote text nodes and form fields, hooked value setters for input and textarea elements, and attempted an HTTP request to 84.32.102.230:7744 with the page hostname and path. Adform says the code was not designed to install software or establish persistence and operated only while an affected page remained open, and it advised people to clear browser caches and check wallet addresses before sending funds.

  • Clearing the browser cache is specifically important because the altered Adform file may remain cached even after Adform removed the malicious code.
  • The address replacement was not limited to clipboard copying, because the captured script also rewrote values entered into input fields, textareas, contenteditable elements, and programmatic writes to form values.
  • A single compromised shared Adform resource could affect unrelated downstream websites without each site being separately breached, because Adform’s tracking code can be deployed across one page, multiple sections, or an entire website.
  • The exposure window cannot be confidently estimated because Adform’s notice identifies July 27 as the affected date while Kevin Beaumont reported seeing malicious activity via Adform over the prior week.
  • Traditional reputation checks may have provided little warning at the time, as Beaumont reported that the file and associated URLs, domains, and IP addresses had no VirusTotal detections when he checked.

Hackers changed a JavaScript file from Adform, an advertising technology company, so that websites using it could silently replace Bitcoin, Ethereum, or Tron wallet addresses with the hackers’ addresses. People who visited an affected site on July 27 and copied or typed a crypto wallet address may have pasted or submitted a different one without realizing it. This matters because one changed address at payment time could send money to the wrong place, and the same shared file may have reached many unrelated customer websites.

OPEN SOURCE ↗

This reports a specific supply-chain compromise of a shared Adform JavaScript resource that could affect unrelated customer websites and visitors handling cryptocurrency addresses. It is broadly relevant because the altered script ran in browsers, rewrote wallet addresses, may remain cached, and the full exposure scope is still unclear.
