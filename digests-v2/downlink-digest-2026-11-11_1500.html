eBPF Rootkits: Why Underground Actors Are Taking Notice

eBPF’s legitimate kernel capabilities are increasingly being adapted into stealthy Linux rootkits that can hide processes, filter traffic, and activate on crafted network packets without loading traditional kernel modules. Defenders should tightly restrict eBPF privileges, inventory loaded programs and XDP attachments, and monitor for suspicious BPF activity and packet triggers.
KEY POINTS
  • 01Flare reported that Russian-language underground forum posts shared eBPF rootkit code and instructions for hiding processes and activating implants with specially crafted network packets.
  • 02eBPF programs can operate through Linux’s legitimate bpf() interface without loading a traditional kernel module, so routine lsmod checks may not detect them.
  • 03Prior Linux malware and research projects, including BPFDoor, Symbiote, ebpfkit, TripleCross, Boopkit, and LinkPro, have demonstrated BPF or eBPF techniques for stealth, traffic handling, or remote activation.
  • 04Flare found that one tutorial described hooking getdents64 to hide processes, using XDP to inspect incoming HTTP traffic, and encrypting command-and-control traffic with AES-256-GCM.
  • 05The article recommends that Linux operators audit loaded eBPF programs, restrict eBPF privileges, patch BPF verifier flaws, and watch for unexpected XDP programs and suspicious packet triggers.

Flare reported finding Russian-language underground forum posts that share eBPF rootkit source code and step-by-step instructions. The posts describe hiding processes, activating an implant with specially crafted network packets, and using encrypted command-and-control traffic. The article says this shows eBPF rootkit techniques moving beyond conference research and into underground tutorials.

Unlike traditional Linux rootkits that load kernel modules, eBPF programs use Linux’s legitimate bpf() interface, so routine checks such as lsmod may not find them. The article cites BPFDoor, Symbiote, ebpfkit, TripleCross, Boopkit, and LinkPro as examples of malware or research that used BPF or eBPF for stealth, traffic handling, or remote activation. It recommends auditing loaded eBPF programs with bpftool, restricting eBPF-related privileges, patching BPF verifier flaws, and monitoring for suspicious XDP programs and packet triggers.

  • eBPF-based implants can evade checks focused on loaded kernel modules because they use a legitimate kernel interface rather than requiring a traditional module load.
  • LinkPro reportedly attempted to hide its eBPF programs from bpftool prog list, but investigators could still identify associated BPF maps and links, showing the value of comparing multiple host telemetry sources.
  • Several documented eBPF backdoors use unusual network-packet conditions, such as a specific TCP SYN window size or malformed TCP SYN packet, as remote activation triggers.
  • The article notes that an exploit PoC claiming support for all Linux kernels from version 4.18 onward was incompatible with upstream Linux 4.18 and had not been verified on Ubuntu 22.04 or 24.04.

The article says that code features built into Linux, widely used on production servers, are being discussed in underground forums as a way to create hidden malicious programs. These programs can conceal running activity, watch or alter network traffic, and wait for a specially formed internet message before activating, while avoiding checks designed to find older types of hidden software. Organizations that run Linux systems are affected because these tools can make intrusions harder to spot, so they need to limit who can use the feature, keep systems updated, and check for unexpected activity.

Unit 42 identified Falcon, also known as XG or Xiàng Gē, a command-and-control framework that compromises visitors’ browsers through malicious JavaScript inserted into websites. Between March and May 2026, campaigns using Falcon affected government entities in one Middle Eastern country and four Southeast Asian countries, including foreign affairs, defense, interior, police and justice organizations. The framework was used to steal passwords, emails, session cookies and communications from users of webmail portals and government web applications. Unit 42 assesses that Falcon and the previously reported PeckBirdy framework are variants of the same core framework because of their closely matching delivery paths, communication mechanisms and session-ID naming patterns.

Falcon generates a separately obfuscated browser implant for each victim session and uses a persistent encrypted WebSocket connection to communicate with its operator. Its Chrome and Firefox extensions, disguised as a PDF viewer, request extensive permissions and can collect credentials, cookies, browser history, downloads, clipboard contents, web requests, Gmail data, Discord information, Zalo chat databases and X/Twitter direct messages.   • The malicious browser extension can cancel a legitimate executable download and replace it with an operator-controlled file while preserving the original filename, making the replacement appear more trustworthy to the victim.
  • Falcon can route an operator’s requests through a victim’s browser using that victim’s existing cookies and saved credentials, enabling access to resources as the victim.
  • Antino’s use of Microsoft OneDrive for small heartbeat files and command files can blend command-and-control activity into legitimate cloud-storage traffic.

Researchers found a spying tool called Falcon that can hide inside compromised government websites and webmail pages, then run inside visitors’ browsers. It was used against government organizations in one Middle Eastern country and four Southeast Asian countries, including foreign affairs, defense, interior, police and justice organizations. The tool can steal passwords, emails, login information, messages and files, and can even replace legitimate downloads with harmful ones. This matters because it can turn an ordinary visit to a trusted work website into long-term access to sensitive government information.
