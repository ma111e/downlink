Microsoft testing Remote Lock for lost or stolen Windows devices

Microsoft is testing Remote Lock in Windows 11 Insider builds, allowing Intune administrators to remotely lock lost or stolen managed devices without erasing data. Only an administrator can unlock the device remotely, while BitLocker remains essential because recovery and external boot options are not blocked.
KEY POINTS
  • 01Microsoft is testing Remote Lock in Windows 11 Insider Preview Beta build 26320.10003 and Experimental build 26340.10013.
  • 02Remote Lock allows Intune administrators to lock lost or stolen Microsoft Entra-joined, hybrid-joined, or MDM-enrolled Windows Enterprise, Education, and Pro devices without wiping them.
  • 03When a device is remotely locked, active sessions are signed out, sign-in options are hidden, and passwords, PINs, local administrator accounts, and web sign-ins cannot unlock it.
  • 04The lock remains in place across restarts and while the device is offline, and only an administrator can remove it remotely through Intune.
  • 05Remote Lock does not isolate the device from an enterprise network or prevent recovery-mode, Safe Mode, or external-media booting, so Microsoft advises keeping BitLocker enabled to protect data.

Microsoft is testing a Remote Lock feature for lost or stolen Windows devices in Windows 11 Insider Preview Beta build 26320.10003 and Experimental build 26340.10013. The feature lets IT administrators lock Microsoft Entra-joined, hybrid-joined, or MDM-enrolled Windows Enterprise, Education, and Pro devices through Microsoft Intune without erasing them. It is intended to preserve the device’s enrollment, management, user data, and BitLocker protection while preventing access.

After Remote Lock is applied, Windows signs out active sessions, hides sign-in options, and prevents unlocking with PINs, passwords, local administrator accounts, or web sign-in. The lock persists through restarts and while offline, and only an administrator can remove it remotely through Intune; the user’s credentials remain usable on other unlocked devices. Administrators can use custom Intune configuration profiles with LockState set to 1 to lock devices and LockState set to 0 to unlock them, using separate assigned device groups. Remote Lock does not isolate a device from the enterprise network or block recovery, Safe Mode, or booting from external media, so Microsoft advises keeping BitLocker enabled and using separate Intune controls for network isolation or wiping.

  • Remote Lock is designed as a reversible response to device loss: it preserves user data, enrollment, management, and BitLocker protection rather than wiping the computer.
  • Locking can be operationalized through Intune group membership, with separate configuration profiles for LockState 1 and LockState 0 applied when the device next checks in.
  • A locked device is not automatically cut off from the enterprise network, so administrators must separately use Intune’s device-isolation controls when network containment is required.
  • Remote Lock does not block Windows Recovery Environment, Safe Mode, or booting from USB and other media, making continued BitLocker use important if the device is reimaged or its drive is removed.
  • The user’s credentials remain usable on other devices that have not been locked, limiting the lock action to the specific affected endpoint.

Microsoft is testing a Windows 11 feature called Remote Lock that lets company IT staff lock a lost or stolen work computer without deleting its files. It is aimed at organizations that manage Windows Enterprise, Education, or Pro devices through Microsoft’s management service. Once locked, the person holding the computer cannot sign in with a password or PIN, and only the organization’s IT staff can restore access. This can protect company information while preserving the device and its data, although encryption must remain enabled because someone could still try to start the computer in special recovery modes or remove its drive.
