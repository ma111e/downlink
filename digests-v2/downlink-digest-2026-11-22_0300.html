Researchers Demonstrate Ghostscript Sandbox-Escape RCE via Crafted File Uploads in Popular Apps

A patched Ghostscript use-after-free flaw (CVE-2026-125396) lets crafted uploaded documents bypass the -dSAFER sandbox and execute commands on servers through common rendering paths in apps such as WordPress, Roundcube, and ImageMagick. Organizations should update Ghostscript to 10.08.0 or later, including copies embedded in containers and application bundles.
KEY POINTS
  • 01Ghostscript flaw CVE-2026-125396 allowed crafted files to bypass its -dSAFER protections and run commands on the server processing them.
  • 02The issue was a use-after-free bug in Ghostscript's font-loading code, and Artifex fixed it in Ghostscript version 10.08.0 on September 8.
  • 03pwn.ai demonstrated that upload, preview, and print features in about ten applications could route crafted PostScript or EPS content to Ghostscript, including through image and document libraries.
  • 04Some tested paths required no login, including anonymous jobs sent to a shared Debian 13 print queue, Roundcube email attachments processed when opened, and public WordPress plugin upload forms.
  • 05Updating only the host operating system may not fix the exposure if an application or container includes its own older Ghostscript copy.

Researchers at pwn.ai demonstrated that CVE-2026-125396, a now-patched Ghostscript flaw, can let a crafted document escape Ghostscript’s -dSAFER security sandbox and run commands on the processing server. The vulnerability is a use-after-free in Ghostscript’s font-loading code. Artifex fixed the issue in Ghostscript 10.08.0 on September 8, and the article states there are no reports of exploitation in attacks.

The issue can be reached indirectly when applications use libraries such as ImageMagick, Pillow, libvips, or Qt plugins to render uploaded documents or images, including content named with .png, .jpg, or .pdf extensions. pwn.ai tested about ten applications and found reachable paths through web uploads, email attachments, and printing; some required no login, including a shared Debian 13 print queue, Roundcube attachments, and public WordPress plugin upload forms. Updating the host operating system alone may not be sufficient if an application or container image contains its own older Ghostscript copy, while controls such as authenticated print queues, restricted accepted file types, and AppArmor can reduce exposure until the renderer is updated.

  • A file does not need to be identified as PostScript or EPS to reach Ghostscript, because libraries may send that content to the renderer even when the file is named with .png, .jpg, or .pdf extensions.
  • Network-facing features turned a CVE classified as a local flaw into reachable server-side command execution paths through email attachments, print jobs, and web uploads.
  • Updating WordPress alone is insufficient where Ghostscript remains outdated, because the WordPress and Ghostscript fixes address separate links in the same attack chain.
  • Updating an operating system package may leave systems exposed when an application or container image carries its own older Ghostscript copy.
  • In one test, an AppArmor profile prevented the compromised Ghostscript process from starting a shell, showing that system-level restrictions can reduce impact before the renderer is updated.

Researchers found and helped fix a flaw in Ghostscript, a widely used program that turns uploaded documents and images into other formats. A specially made file could make a server run commands when services such as WordPress upload forms, Roundcube email, shared print queues, or image-processing tools try to preview or convert it. This matters because even ordinary features like creating a thumbnail can expose a server, so organizations need to update Ghostscript everywhere it is installed, including inside separate application packages or containers.

OPEN SOURCE ↗

This is a high-impact patched remote command-execution path in widely used Ghostscript that can be reached through common upload, email, print, and image-processing workflows. There is no reported exploitation in the wild, but organizations may remain exposed through bundled or containerized older Ghostscript copies.

OpenRouter Drops 3 Providers After Researchers Catch Months of Prompt Theft at AI Hosting Firms

Dragos found that attackers and unscrupulous AI inference providers had been copying customer prompts, including Zero Data Retention requests, for months, exposing credentials and sensitive data. OpenRouter removed three providers and 125 endpoints from Zero Data Retention eligibility while notifying potentially affected users.
KEY POINTS
  • 01Dragos seeded roughly two million AI prompts with unique links and credentials between July and November and found evidence that data from three AI inference providers had been copied for months.
  • 02Some copied requests were marked Zero Data Retention, a setting intended to ensure that prompts are not stored.
  • 03OpenRouter said it removed three providers from its platform, removed 125 endpoints from Zero Data Retention eligibility, and notified potentially affected customers.
  • 04Researchers observed attackers using stolen planted AWS keys to list S3 buckets, search AWS Secrets Manager and Parameter Store, and attempt to create Bedrock API keys and IAM users.
  • 05Phala, Together AI, and Novita each publicly disclosed separate incidents involving exposure, storage, or unintended forwarding of customer AI requests.

Dragos said attackers copied data from inside three AI inference providers for months before researchers alerted them, including prompts marked Zero Data Retention. Its researchers seeded about two million prompts with unique web links and credentials between July and November, then monitored for use of those planted secrets. OpenRouter said its own systems were not breached, but it removed three providers from its platform, removed 125 endpoints from Zero Data Retention eligibility, and notified potentially affected customers.

In the largest incident, planted AWS credentials sent to one provider in late October were used within hours to list S3 buckets, search AWS Secrets Manager and Parameter Store, and attempt to create Bedrock API keys and IAM users. Researchers said requests rejected before a model ran were also copied, suggesting the traffic was captured when it first arrived at the provider. Other findings involved low-priced marketplace sellers that enabled request logging, undisclosed routing to another marketplace, and a Chinese AI lab whose systems fetched secret links from more than half of seeded prompts sent to its models, including many marked with no-data-collection or Zero Data Retention settings.

Phala reported that an attacker controlled an inference server and could view requests being processed, while Together AI said an unauthorized party downloaded stored prompt samples after a credential was committed to its public GitHub repository. Novita said a routing configuration issue caused some MiniMax requests to be forwarded to MiniMax’s official API beyond what was intended. Dragos warned that privacy labels do not protect prompts if an attacker is already inside a provider or if requests are passed to additional companies, and OpenRouter said it is adapting the researchers’ testing approach for ongoing checks.

  • The fact that stolen prompts included requests rejected before any model ran indicates that at least one attacker was copying data at the provider's initial intake point rather than from the model-processing system.
  • A marketplace seller could collect customer prompts without breaking into a system simply by offering low-priced models while request logging was enabled.
  • Route tracing of about 2,000 paths found several hundred unidentified systems, and one seller was adding about 1,000 hidden tokens to every prompt.
  • A secret link from one prompt was posted in a Feishu chat 24 days later and opened from multiple devices, showing that a full cached prompt had been accessed by people after the original request.
  • OpenRouter said it is adapting the researchers' planted-secret testing approach for continuous checks and is reviewing network paths where requests or responses could be forwarded to third parties.

Researchers found that attackers and some AI service sellers were able to copy customer requests for months, including requests marked as not to be stored. Those requests can contain passwords, access keys, private code, and other sensitive information, and the stolen keys were used to try to access cloud accounts and data. OpenRouter removed three AI providers and changed which services can use its stricter privacy label, but the incidents show that a privacy setting cannot protect information if the company handling it has already been compromised or passes it to another company.

OPEN SOURCE ↗

This is a high-impact supply-chain data exposure finding affecting AI inference providers and customers whose prompts may have contained cloud credentials, passwords, and private repositories. The reported misuse of stolen AWS keys and the removal of providers from OpenRouter make it broadly relevant to organizations using third-party AI routing or hosting services.
