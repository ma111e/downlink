Cisco warns of FMC static credential flaw exploited in zero-day attacks

Cisco warned that a static credential flaw in Secure Firewall Management Center, CVE-2026-20316, has been exploited in zero-day attacks and urged customers to install hot fixes because there are no workarounds. Administrators should check logs for the /var/tmp/license.tmp indicator and rotate credentials, keys, and certificates if compromise is suspected.
KEY POINTS
  • 01Cisco warned that CVE-2026-20316, a high-severity static credential vulnerability in Secure Firewall Management Center Software, has been actively exploited in zero-day attacks to gain unauthorized access to vulnerable devices.
  • 02The vulnerability is caused by static credentials for a low-privilege account built into Cisco Secure FMC Software, which an unauthenticated remote attacker can use to log in and access sensitive data available to that account.
  • 03Cisco released hot fixes for Secure FMC releases 7.0, 7.2, 7.4, 7.6, 7.7, and 10.0, and said there are no workarounds that address the vulnerability.
  • 04Cisco advised administrators to check /var/log/messages for entries involving /var/tmp/license.tmp and to rotate all user credentials, keys, and certificates on affected FMC devices if that indicator is present.
  • 05Cisco also updated its advisory for CVE-2026-20079, a separate critical FMC authentication bypass flaw with a maximum CVSS score of 10.0, but said it is not aware of malicious exploitation of that vulnerability.

Cisco warned that a high-severity Secure Firewall Management Center static credential vulnerability, tracked as CVE-2026-20316, was actively exploited in zero-day attacks. The flaw is caused by static credentials for a low-privilege account built into Cisco Secure FMC Software. Cisco says an unauthenticated remote attacker can use those credentials to log in to an affected system and access sensitive data available to that account.

Although CVE-2026-20316 has a CVSS score of 5.3, Cisco assigned it a High severity rating because the access can be combined with other FMC vulnerabilities to elevate privileges. The flaw affects Cisco Secure FMC Software regardless of device configuration, but does not affect Cloud-Delivered FMC, Firewall Device Manager, Secure Firewall ASA Software, Secure Firewall Threat Defense Software, or Security Cloud Control. Cisco released hot fixes for Secure FMC releases 7.0, 7.2, 7.4, 7.6, 7.7, and 10.0, and said there are no workarounds that address the vulnerability.

Cisco said it became aware of active exploitation in July 2026 and advised administrators to review the /var/log/messages file for signs of compromise, including entries containing /var/tmp/license.tmp. If that indicator is found, administrators should rotate all user credentials, keys, and certificates on the affected FMC device and contact Cisco TAC for recovery assistance. Cisco also updated an advisory for a separate critical FMC authentication bypass flaw, CVE-2026-20079, but said it is not aware of malicious exploitation of that vulnerability.

  • Cisco rated CVE-2026-20316 as High severity despite its 5.3 CVSS score because the low-privilege access can be combined with other FMC vulnerabilities to elevate privileges.
  • Cisco published the same /var/tmp/license.tmp indicator for both CVE-2026-20316 and CVE-2026-20079, but the article says the company has not explained whether the two vulnerabilities are connected.
  • The FMC management interface being exposed to the public internet increases risk, while Cisco notes that keeping it unexposed reduces the attack surface.
  • If the /var/tmp/license.tmp indicator is found, Cisco advises rotating all user credentials, keys, and certificates on the affected FMC device because exploitation has been ongoing.

Cisco says attackers have been using a built-in login weakness in its Secure Firewall Management Center software to get into affected systems and view sensitive data. Organizations that use this Cisco management software are affected, and Cisco has released fixes because there is no simple setting change that fully solves the problem. This matters because the same access could be combined with other weaknesses to gain more control, so Cisco is telling customers to install the fixes and check their logs for signs of break-in.

Critical Rails Flaw Could Let Unauthenticated Attackers Read Server Files via Image Uploads

Ruby on Rails patched a critical Active Storage flaw, CVE-2026-66066, that could let unauthenticated attackers use crafted image uploads with libvips to read sensitive server files and steal secrets. Affected operators should upgrade immediately and rotate any credentials the Rails process could access.
KEY POINTS
  • 01Ruby on Rails released fixes for CVE-2026-66066, a critical Active Storage vulnerability that could let unauthenticated attackers read arbitrary files from application servers through crafted image uploads.
  • 02The flaw affects applications that use libvips for Active Storage image processing and accept image uploads from untrusted users, with affected ranges including Rails 7.0.0 through 7.2.3.1, Rails 8.0.0 through 8.0.5, and Rails 8.1.0 through 8.1.3.
  • 03Rails 6.0.0 through 6.1.7.10 releases are affected only when Active Storage is configured to use Vips, while applications using MiniMagick are not exposed through this specific attack path.
  • 04Operators are advised to upgrade to Rails 7.2.3.2, 8.0.5.1, or 8.1.3.1 and rotate secrets readable by the application process, including secret_key_base, the Rails master key, database credentials, Active Storage service keys, and third-party tokens.
  • 05Neither Rails nor the researchers reported in-the-wild exploitation at publication, and The Hacker News found no public proof-of-concept or exploit repository as of 17:30 UTC on July 29, 2026.

Ruby on Rails released fixes for a critical Active Storage vulnerability tracked as CVE-2026-66066 with a CVSS score of 9.5. The flaw could let unauthenticated attackers read arbitrary files from application servers through crafted image uploads. Exposed data could include the Rails process environment and secrets such as secret_key_base, the Rails master key, database passwords, cloud storage credentials, and API tokens.

Affected applications use libvips for Active Storage image processing and accept image uploads from untrusted users. Ethiack and GMO Flatt Security list affected ranges as Rails 7.0.0 through 7.2.3.1, Rails 8.0.0 through 8.0.5, and Rails 8.1.0 through 8.1.3, while Rails 6.0.0 through 6.1.7.10 are affected only when configured to use Vips. Applications using MiniMagick are not exposed through this specific attack path, and Rails 7.0 and 7.1 are end of life with no fixed releases.

Operators should upgrade to Rails 7.2.3.2, 8.0.5.1, or 8.1.3.1 and rotate every secret readable by the application process. The patch calls Vips.block_untrusted(true) when Active Storage starts, and patched installations require libvips 8.13 or later and ruby-vips 2.2.1 or later when ruby-vips is installed. Neither Rails nor the researchers reported in-the-wild exploitation at publication, and The Hacker News found no public proof-of-concept at 17:30 UTC on July 29, 2026.

  • Applying the Rails patch is not enough if the flaw may already have been exploited, because Rails warned that credentials potentially read by attackers must still be rotated.
  • A vulnerable app does not need to expose a separate resize or thumbnail feature, because Rails said variant generation is not a separate requirement for the attack path.
  • Rails 7.0 and 7.1 users cannot simply apply a fixed release on those branches because they are end of life, so they must move to Rails 7.2.3.2 or later.
  • The mitigation depends on newer image-processing components, since patched installations require libvips 8.13 or later and ruby-vips 2.2.1 or later when ruby-vips is installed.
  • There is a difference between the official advisory’s broad package range of activestorage below 7.2.3.2 and the researchers’ practical Vips-based attack path, which they place at Rails 6.0 and later.

Ruby on Rails fixed a serious problem in its file upload feature that could let outsiders send a specially made image and read files from a website’s server. This affects Rails apps that use libvips for image handling and accept image uploads from untrusted users, especially versions listed in the article. The exposed files could include passwords, keys, and service tokens, which might let attackers take further control or reach connected systems, so affected sites need to update and replace those secrets.

OPEN SOURCE ↗

This is a critical patch for widely deployed software, with CVE-2026-66066 rated 9.5 and enabling unauthenticated arbitrary file reads through crafted image uploads in affected Rails Active Storage deployments. Although no in-the-wild exploitation or public PoC was reported, the potential exposure of secrets and need for immediate upgrades and credential rotation make it a must-read for security professionals.
