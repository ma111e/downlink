Attackers Exploit Issabel Framework Flaw Enabling Unauthenticated OS Command Execution

Issabel Framework users should immediately apply the August 2026 patch for CVE-2026-89026, an actively exploited flaw that lets unauthenticated attackers forge JWTs and execute OS commands through Asterisk.
KEY POINTS
  • 01CVE-2026-89026 is a critical Issabel Framework flaw that allows unauthenticated remote attackers to execute arbitrary operating-system commands.
  • 02The flaw stems from a hard-coded HS256 JWT signing key in pbxapi/index.php that was identical across Issabel installations, allowing attackers to forge bearer tokens.
  • 03Forged tokens can be used with the /pbxapi/manager/originate endpoint and Asterisk's System application to execute commands as the Asterisk user.
  • 04Issabel patched the issue on August 1, 2026, by replacing the hard-coded JWT key with one stored in /etc/issabel.conf.
  • 05Shadowserver Foundation first observed active exploitation of CVE-2026-89026 on September 9, 2026, and users are advised to apply the latest fixes.

A critical flaw in the Issabel Framework, a web-based framework for open-source unified communications PBX software, is under active exploitation. Tracked as CVE-2026-89026, it has a CVSS v3.1 score of 9.8 and can allow unauthenticated remote attackers to execute arbitrary operating-system commands. Users are advised to apply the latest fixes.

The issue was caused by a hard-coded HS256 JWT signing key in the pbxapi/index.php file that was identical across installations, enabling attackers to forge valid bearer tokens. Attackers can use those tokens with the /pbxapi/manager/originate endpoint and Asterisk’s System application to execute commands as the Asterisk user. Issabel pushed a patch on August 1, 2026, replacing the hard-coded key with a JWT key stored in /etc/issabel.conf. Shadowserver Foundation first observed exploitation on September 9, 2026, but the article says the actors, methods, and scale of the activity are currently unknown.

  • Because the JWT signing key was identical across every Issabel Framework installation, a token forged using that key could be valid on any unpatched installation.
  • The fix was released on August 1, 2026, more than a month before Shadowserver Foundation first observed exploitation on September 9, 2026.
  • Although active exploitation has been observed, the article states that the responsible actors, their methods, and the scale of the activity are not currently known.

A serious flaw in the Issabel Framework, software used with open-source business phone systems, is being actively abused. Because the same secret access key was built into every installation, an attacker could create a fake login token and remotely run commands on the underlying system without a password. This could let outsiders take control of affected phone-system servers, so users are urged to install the available fix.

Emerging Threat: (CVE-2026-70756) Oracle WebLogic Server Takeover via T3 and IIOP

Oracle WebLogic Server CVE-2026-70756 is a critical pre-authentication flaw that can allow remote takeover through exposed T3 or IIOP services. Organizations should urgently apply Oracle’s September 2026 CPU and restrict external access to WebLogic listen ports until patching is complete.
KEY POINTS
  • 01CVE-2026-70756 is a critical Oracle WebLogic Server flaw with a CVSS v3.1 score of 9.8 that can allow an unauthenticated network attacker to take full control of a server through T3 or IIOP.
  • 02Oracle lists WebLogic Server versions 12.2.1.4.0, 14.1.1.0.0, 14.1.2.0.0, and 15.1.1.0.0 as affected by CVE-2026-70756.
  • 03WebLogic instances can accept T3 and IIOP traffic on default HTTP listen ports such as TCP/7001 and TCP/7002, including when they appear externally as ordinary web application servers.
  • 04Oracle released fixes for all affected versions in its September 15, 2026 Critical Security Patch Update.
  • 05Until patching is confirmed, the article recommends identifying internet-facing WebLogic systems and restricting T3 and IIOP access to trusted internal sources.

CVE-2026-70756 is a critical Oracle WebLogic Server Core-component vulnerability with a CVSS v3.1 score of 9.8. An unauthenticated attacker with network access through T3 or IIOP can compromise an affected server and take full control of it. Oracle disclosed the issue on September 15, 2026, as part of its September 2026 Critical Security Patch Update.

Affected WebLogic versions are 12.2.1.4.0, 14.1.1.0.0, 14.1.2.0.0, and 15.1.1.0.0. T3 and IIOP can be accessible on the same default listen ports used for HTTP traffic, including TCP/7001 and TCP/7002, meaning externally visible web application servers may also accept the vulnerable protocols. Oracle has released patches for all affected versions, while defenders are advised to inventory internet-facing instances, restrict T3 and IIOP access, disable unnecessary IIOP services, and review load balancer rules that forward full listen ports.

  • WebLogic can expose the affected T3 and IIOP services on the same default ports used for web traffic, so a server that appears to be only a normal website may still be reachable through the vulnerable interfaces.
  • Many affected systems may be missed by internal asset records because CyCognito identified most observed assets through service fingerprints rather than confirmed version detection.
  • Staging, testing, and development WebLogic instances are especially likely to remain externally reachable without the patch discipline applied to production systems.
  • Load balancers or reverse proxies that forward an entire WebLogic listen port, rather than limiting traffic to web requests, can unintentionally leave the affected services accessible from outside.
  • For older WebLogic 12.2.1.4.0 deployments, patch availability may depend on the organization’s Oracle support contract, so teams should verify eligibility rather than assume access.

Oracle disclosed a critical flaw in WebLogic Server that lets someone who can reach an affected server over the internet take complete control without a password or any help from a user. It affects several widely used WebLogic versions, including systems that may appear to be ordinary websites but also accept the vulnerable connections. This matters because WebLogic often supports business applications, supply chains, logistics, and partner services, so an unpatched exposed server could put important operations and data at risk. Oracle released fixes, and organizations should identify exposed servers, install the appropriate update, and limit outside access in the meantime.
