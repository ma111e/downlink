Optimizely supply chain attack infects major brands' sites with malware

A suspected compromise of Optimizely customer projects injected malicious JavaScript into websites used by major brands, loading a payload that skimmed payment cards, replaced cryptocurrency wallet addresses, and attempted to deliver iOS exploits. The incident affected at least 178 organizations, though most infected scripts had been cleaned up by November 16.
KEY POINTS
  • 01Security researcher Scott Helme identified 188 infected Optimizely JavaScript files belonging to 178 organizations after reviewing 1,611 scripts used by the platform.
  • 02Attackers inserted code into Optimizely customer projects that loaded an additional script from 1688360[.]cc/track.js on affected websites, including Zoom, CNN, BBC, Salesforce, and GitLab.
  • 03The malicious script could replace cryptocurrency wallet addresses, capture payment-card details entered on webpages, collect cookies, URLs, and screenshots, and send captured card data to 1688360[.]cc/card.php.
  • 04The script also loaded additional code targeting iPhones and iPads, identified by Helme as the Coruna and DarkSword exploit kits.
  • 05Helme reported that only one of the 188 previously compromised Optimizely files still contained malicious code as of 21:52 UTC on November 16, while the method used to access and modify the projects remained unknown.

A suspected supply-chain attack targeting Optimizely caused malicious JavaScript to be loaded on websites belonging to numerous organizations, including Zoom, CNN, Fox News, BBC, Salesforce, GitLab, KLM, and Air France. Security researcher Scott Helme identified 188 infected Optimizely JavaScript files associated with 178 organizations after examining 1,611 platform scripts. The attackers inserted code into customer projects that loaded an additional malicious script from 1688360[.]cc/track.js.

The malicious script could replace cryptocurrency wallet addresses with attacker-controlled ones, capture payment-card information entered into webpages, and collect browser cookies, page URLs, and screenshots. It also loaded additional code targeting iPhones and iPads, identified as the Coruna and DarkSword exploit kits. Cryptocurrency wallets embedded in the script received about $7,000 in transactions on November 16, while cleanup efforts reduced the known infected scripts to one by 21:52 UTC that day; how the attackers accessed and modified so many projects remained unknown.

  • The compromise turned a widely used third-party website service into a route for harmful code to reach visitors of many otherwise unrelated, well-known sites.
  • Some infected files included a built-in copy of the harmful code that could run even if the attackers’ remote script was blocked, reducing the effectiveness of blocking that single web address alone.
  • Transactions totaling roughly $7,000 reached cryptocurrency wallets embedded in the script on November 16, providing evidence that its cryptocurrency-payment redirection function succeeded.
  • Although cleanup reduced 188 known compromised scripts to one by late November 16, the article says the method used to gain access to so many Optimizely customer projects was still unknown.

Attackers appear to have altered website code delivered through Optimizely, a service companies use to test and personalize their sites, causing harmful code to run for visitors. Sites associated with companies including Zoom, CNN, BBC, Salesforce, GitLab, and others were affected. The code could steal payment-card details, redirect cryptocurrency payments to the attackers, collect browser data and screenshots, and try to target iPhones and iPads, putting ordinary visitors’ money and personal information at risk.

This is a high-impact, active supply-chain incident affecting numerous major websites through Optimizely-delivered JavaScript. The payload can skim payment cards, redirect cryptocurrency payments, collect browser data, and target iOS devices, creating immediate risk for affected organizations and their visitors.

QUIC and Covert: Novel HTTP/3-Powered RATs Target Southeast Asian Governments

Unit 42 reports that TGR-STA-0049 is targeting Southeast Asian government entities with the new PerfectPioneer and KUKURAT RATs, using HTTP/3 over QUIC to conceal command-and-control traffic and evade TCP-focused inspection. The campaign combines server exploitation and phishing with credential theft, Active Directory logon-script propagation, mailbox access abuse, and stealth features such as modular payloads and artificial endpoint activity.
KEY POINTS
  • 01Unit 42 tracked the campaign as TGR-STA-0049, also known as REF7707, Earth Alux and Ink Dragon, and reported that it has targeted Southeast Asian government entities since at least July 2025.
  • 02The campaign used PerfectPioneer RAT and its later modular successor KUKURAT, both of which used HTTP/3 over QUIC for command-and-control communications, with some variants also using HTTP/2.
  • 03Attackers obtained access primarily by exploiting vulnerable Microsoft Exchange and web servers to deploy web shells, while also using phishing files and lookalike government domains.
  • 04KUKURAT dynamically downloads capability modules for functions including screenshots, keystroke logging, file operations, network scanning, remote command execution, credential brute-forcing and SOCKS tunneling.
  • 05The attackers used domain logon scripts for propagation, harvested credentials through LSASS memory dumping and DCSync, and sought sensitive documents and broad mailbox access in compromised Exchange environments.

Unit 42 reports that TGR-STA-0049, also tracked as REF7707, Earth Alux and Ink Dragon, has targeted Southeast Asian government organizations since at least July 2025. The cyberespionage campaign used two previously undocumented remote-access tools, PerfectPioneer RAT and its later modular successor KUKURAT, following earlier activity involving the Squidoor backdoor. The attackers primarily exploited vulnerable Microsoft Exchange and web servers to deploy web shells, while also using phishing documents and lookalike government domains.

Both malware families used HTTP/3 over QUIC, a web communications method that runs over UDP and may receive less inspection than traditional TCP-based web traffic. PerfectPioneer includes extensive file, process, screenshot, keystroke-logging and proxy capabilities, while some variants prevent operators from running destructive or conspicuous commands that could expose the intrusion. KUKURAT downloads functions only when needed and can generate fake web, registry and file activity to obscure its real behavior.

The attackers moved through networks by modifying domain logon scripts, stole credentials through LSASS memory dumping and DCSync, and used administrative access to seek mailbox impersonation rights or grant a compromised account access to all Exchange mailboxes. They attempted to exfiltrate documents with filenames suggesting sensitive international-relations and internal-political content. The report recommends monitoring or restricting QUIC traffic, auditing Active Directory logon scripts and Exchange permissions, and detecting rundll32 use of comsvcs.dll for LSASS dumping.

  • Two PerfectPioneer variants contain an isDangerousCommand feature that blocks operators from running destructive or highly visible commands, reducing the risk that the attackers themselves trigger security alerts.
  • KUKURAT can create fake web requests, browser-like registry activity and temporary-file activity at the same time, allowing its real actions to blend into deliberately generated endpoint noise.
  • KUKURAT’s core program keeps most post-compromise functions in separate modules downloaded only when needed, which reduces the amount of malicious capability visible in the initial file.
  • The actors used compromised domain controllers to alter logon scripts, causing KUKURAT to download and run automatically when legitimate users signed in.
  • In compromised Exchange environments, the attackers checked for mailbox-impersonation rights and, if necessary, used administrative access to grant a controlled account full access to every mailbox.

Researchers found a cyber-espionage campaign targeting government organizations in Southeast Asia, using two newly identified pieces of remote-control malware called PerfectPioneer and KUKURAT. The attackers gained access through unpatched servers and deceptive emails or files, then stole passwords, accessed email accounts, spread to other computers, and tried to take sensitive government documents. It matters because the tools are designed to stay hidden by making their internet traffic and computer activity look ordinary, making it harder to detect long-term theft of information related to government and international affairs.

WPPConnect Compromised: Malicious Releases Steal Secrets and WhatsApp Sessions Through the Project's Own Pipeline

Malicious WPPConnect npm packages and Docker images exfiltrated environment variables, configuration files, and WhatsApp session tokens to Telegram when imported or started. Organizations that used the affected versions should treat reachable secrets and WhatsApp sessions as compromised, rotate them, and pin known-clean package versions and image digests.
KEY POINTS
  • 01Malicious releases of @wppconnect-team/wppconnect 2.4.1 and @wppconnect/server 2.10.82 collected environment variables, configuration files, and WhatsApp session tokens and uploaded them to a Telegram bot.
  • 02The malicious code ran when the library was imported or the server started, so installing with npm install --ignore-scripts did not prevent it.
  • 03The affected releases were published through the projects’ GitHub Actions trusted-publisher workflows with valid credentials, and the library release carried valid SLSA provenance despite the malicious code.
  • 04Docker images for wppconnect/wppconnect-server versions 2.10.82 and 2.10.83, along with floating tags during the affected period, contained the payload.
  • 05Organizations that loaded affected packages or ran affected images should treat secrets reachable by those processes and WhatsApp sessions as compromised and rotate or replace them.

Malicious releases of @wppconnect-team/wppconnect and @wppconnect/server were published through the WPPConnect projects’ existing GitHub Actions release pipelines in November 2026. The code collected environment variables, selected .env and configuration files, and WhatsApp session-token files, then uploaded the data to a Telegram bot. The affected library release 2.4.1 was npm’s latest version for about 4.5 hours, while affected server releases and Docker images were also made available.

The payload ran when the library was imported or the server started, rather than during installation, so npm install --ignore-scripts did not prevent it. Although the releases used valid trusted-publisher credentials and the library release had valid SLSA provenance, the provenance accurately identified a malicious commit that had not been reviewed. After public issues were opened, the default branches were force-pushed and the v2.4.1 tag was rewritten to point to a clean look-alike commit, leaving GitHub’s current tagged source different from the npm tarball.

Organizations that loaded the affected package versions or ran the affected Docker images should treat secrets reachable by those processes and WhatsApp sessions as compromised. The article recommends rotating accessible environment and configuration secrets, unlinking and re-pairing WhatsApp sessions, pinning library 2.4.0 and server 2.10.81, and comparing Docker image digests rather than tags. It also recommends package release-age delays, outbound network allowlists, protected publishing environments with independent reviewers, and protections against unreviewed pushes and force-pushes.

  • Valid GitHub trusted-publisher credentials and a valid SLSA provenance attestation did not establish that the released source had been reviewed; the attestation accurately identified the malicious commit and workflow.
  • The v2.4.1 GitHub tag was rewritten to point to a similar-looking clean commit, meaning a review of the current tagged GitHub source would not reveal the code that npm distributed.
  • A fresh installation of the affected server package could have pulled the malicious WPPConnect library indirectly because the server depended on a version range that included 2.4.1.
  • The temporary marker files only show that the payload started, so their absence cannot be used to determine that a system was unaffected.
  • A package release-age delay of 24 hours would have prevented installation of the malicious library version, which was the npm latest release for roughly 4.5 hours.

Someone used the WPPConnect project’s normal release process to publish altered software that secretly sent passwords, settings, and WhatsApp login information from computers and servers to a Telegram account. People and organizations that installed the affected WPPConnect packages or ran the affected Docker images may be affected, including those whose systems merely started or loaded the software. This matters because stolen login details can let others access connected services and WhatsApp accounts, even though the downloads appeared to come from the project’s official publishing system.

OPEN SOURCE ↗

This is a concrete supply-chain compromise involving malicious npm packages and Docker images that steal environment secrets, configuration data, and WhatsApp session credentials when loaded or started. It is particularly important because valid GitHub Actions publishing credentials and SLSA provenance were used, while rewritten tags concealed the source that actually shipped.

OPTIMJACK: Optimizely-Hosted Scripts Loaded a Crypto Clipper and Card Skimmer on 186 Confirmed Sites

A compromise of Optimizely-hosted JavaScript reportedly exposed at least 186 websites to the OPTIMJACK payload, which swaps cryptocurrency wallet addresses, skims payment cards, and delivers a separate stage to iOS devices. Organizations should investigate Optimizely snippets and block the identified malicious domains immediately.
KEY POINTS
  • 01The OPTIMJACK campaign used malicious code loaded from 1688360[.]cc through compromised third-party JavaScript files, including scripts served from cdn.optimizely.com.
  • 02Researcher Scott Helme counted 186 infected sites and 188 infected script files, while public urlscan.io data recorded requests to the payload host from pages on organizations including CNN, BBC, Fox News, Zoom, Salesforce, GitLab, Air France, and KLM.
  • 03The payload can replace copied cryptocurrency wallet addresses, capture payment-card numbers, expiry dates, and CVVs, and send cookies and a screenshot of the visible page after a cryptocurrency-address swap.
  • 04For iPhone, iPad, and iPod visitors, the payload loads additional boot.js files from .icu domains and, on iOS 18.6 or earlier, loads a hidden iframe.
  • 05The article advises organizations to block 1688360[.]cc and the listed .icu hosts, review Optimizely snippets for references to the malicious infrastructure, and investigate relevant logs beginning at 08:00 UTC on November 16.

The article reports that OPTIMJACK malicious code was delivered through third-party JavaScript files, including files hosted on cdn.optimizely.com, and loaded a payload from 1688360[.]cc. Researcher Scott Helme counted 186 infected sites and 188 infected script files, while public scan records showed affected pages from organizations including CNN, BBC, Fox News, Zoom, Salesforce, GitLab, Air France, KLM, and others. The article states that the exposure lasted at least 13 hours on November 16, 2026, and that Optimizely was cleaning infected files that evening.

The approximately 30 KB payload can replace cryptocurrency wallet addresses, intercept copied addresses, collect payment-card numbers, expiration dates, and CVVs, and send captured information to attacker-controlled endpoints. After a cryptocurrency-address swap, it can also capture a screenshot of the visible page and send cookies accessible to page JavaScript. For iPhone, iPad, and iPod users, it loads additional files from .icu domains and adds a hidden iframe on iOS 18.6 or earlier. The article advises blocking the listed domains, reviewing Optimizely snippets for references to the malicious infrastructure, checking logs and CSP reports, and treating cards or wallet activity exposed during the incident window as potentially compromised.

  • The malicious payload changed at least four times within roughly two hours, so detection based on a single file hash could miss earlier or altered versions; the article recommends matching on behavior and domains instead.
  • The code captures screenshots and cookies only after it performs a cryptocurrency-address swap on a visible page, meaning visitors who never interact with a wallet address do not trigger that particular data collection.
  • The card-stealing component cannot read payment fields in a cross-origin payment iframe, making provider-hosted payment fields a concrete mitigation described in the article.
  • A Content Security Policy that uses strict-dynamic with a nonce may still permit the malicious download because a trusted Optimizely script can add another script; host allowlists for script-src and connect-src provide the protections described.
  • Some iOS-stage domains were registered before the main payload domain and one served content four days before the campaign, indicating that part of the supporting infrastructure existed before November 16.

Malicious code was added to web files hosted by Optimizely, a service that many websites use, causing it to run on visitors’ browsers at sites including CNN, BBC, GitLab, Zoom, and retailers. The code can replace a cryptocurrency payment address with the criminal’s address, collect card details entered on checkout pages, and try to load more code on some iPhones and iPads. This matters because a trusted outside service can put visitors at risk even when the website they are visiting has not directly been changed.

OPEN SOURCE ↗

This is a high-impact active third-party JavaScript compromise affecting at least 186 sites, including major news, software, airline, retail, and financial-related organizations. The payload can steal payment-card data, alter cryptocurrency addresses, capture accessible cookies, and target iOS devices, with actionable indicators and mitigation steps provided.
