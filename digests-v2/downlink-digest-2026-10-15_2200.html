AI-Powered Espionage Campaign Targets Government Linux Infrastructure

Palo Alto Networks’ Unit 42 tracked CL-UNK-1211, an espionage campaign targeting government and state-affiliated Linux infrastructure that used AI-assisted scripts, web shells, credential theft, SysGoRAT, reverse shells, and data-exfiltration tools. The campaign combined persistent access and anti-forensic cleanup with attempts to steal government mailboxes and database data.
KEY POINTS
  • 01Unit 42 tracked the activity as CL-UNK-1211, a campaign observed from October 2025 through April 2026 targeting government entities and state-affiliated infrastructure running Linux.
  • 02The attackers used AI-generated or AI-assisted PHP and shell scripts, evidenced by conversational annotations and developer-reasoning comments embedded in multiple payloads.
  • 03The campaign used web shells, including persistent PHP configuration changes that caused a malicious file to execute before other PHP scripts.
  • 04The attackers deployed a custom cross-platform Go remote-access Trojan named SysGoRAT, which communicated with its command server over WebSocket and supported command execution, interactive shells, proxying, file download, and persistence.
  • 05The attackers attempted to harvest credentials, access government mailboxes and databases, exfiltrate data, disable endpoint protections, delete logs, alter file timestamps, and disguise some activity as red-team work.

Unit 42 identified CL-UNK-1211, an espionage campaign observed from October 2025 through April 2026 that targeted government entities and state-affiliated infrastructure, particularly Linux systems. The attackers sought persistent access, performed extensive reconnaissance, and attempted to obtain sensitive database contents and government mailboxes. Unit 42 reported that the activity included attempts to use official government email accounts to facilitate access to social-media accounts. The cluster has not been attributed to a specific nation-state or cybercrime group.

The campaign used web shells, custom and open-source tools, in-memory remote shells, SSH access, proxy utilities, and a custom cross-platform Go remote-access Trojan called SysGoRAT. Attackers established persistence by modifying PHP configuration files so a malicious script would execute before other PHP scripts, and they also harvested passwords through a modified .bashrc file that imitated the sudo password prompt. Several payloads contained conversational comments and developer-reasoning notes that Unit 42 said were consistent with AI-assisted generation or automated AI-agent execution. The attackers also used scripts and commands to search for cleartext credentials, scan networks and databases, move between systems, and prepare data for exfiltration.

The operators attempted to evade investigation by trying to terminate Cortex XDR-related processes, deleting logs and temporary files, changing file timestamps, and planting red-team-themed markers such as RedTeamOps2025 and pentest123. Unit 42 stated that Cortex XDR detected and mitigated attempts to suppress endpoint protections, and that protections were not disabled. The report provides file hashes, IP addresses, and domains associated with the activity, along with descriptions of the observed techniques. Palo Alto Networks said its Advanced WildFire, URL and DNS protections, Cortex XDR, XSIAM, and Cortex Cloud are designed to help detect or prevent threats discussed in the report.

  • The attackers used PHP’s auto_prepend_file setting across standard and Plesk PHP configuration directories, causing their malicious script to run before other PHP scripts and making the web shell persist broadly on affected servers.
  • A modified .bashrc file impersonated the sudo password prompt, recorded users’ passwords in a file named Solarwinds.StatusLog.txt, and then passed the password to the legitimate sudo command so the interception would be less noticeable.
  • The mailbox-search script was aimed at finding social-media-related messages in government email accounts, indicating that official mailboxes were used as a route toward access to associated external accounts.
  • Some attacker-generated scripts contained syntax errors that would prevent them from running, including a mailbox-compression script with a broken variable assignment.
  • The attackers planted markers such as RedTeamOps2025 and a user password of pentest123 to make malicious activity appear to be an authorized security assessment during later investigation.

Researchers found a campaign targeting government organizations and government-linked systems that run Linux, a common computer operating system. The attackers used AI-assisted code and hidden access tools to steal passwords, search government email accounts and databases, and try to send sensitive information out of the victims’ networks. This matters because access to official email, social-media accounts, and government data could enable espionage, impersonation, and further compromise, while the attackers also tried to erase evidence of their activity.

This is a detailed report on a specific espionage campaign targeting government and state-affiliated Linux infrastructure, with observed activity, persistence mechanisms, malware analysis, exfiltration methods, and actionable indicators. It is especially relevant to teams operating Linux web servers, PHP/Plesk deployments, mail infrastructure, databases, and government-sector environments.
