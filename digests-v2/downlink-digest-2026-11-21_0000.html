GnuPG warned of CVE-2026-129975, a critical flaw in GPGME that can be triggered by a malicious OpenPGP key with an unusually long user ID. The issue affects software using GPGME versions before 2.3.0, including programs that load it as a shared library, Windows DLL, or statically linked component. The problem is a double-free memory error in the read_status() and read_colon_line() routines, which process status lines and key listings from GnuPG.   • Updating only a system-installed GPGME library will not protect applications that include their own bundled or statically linked copy; those applications require rebuilt releases from their developers.

  • The bug can be reached through signed data sent to an application, rather than necessarily requiring a user to manually import a malicious key.
  • The double-free occurs when an error interrupts buffer resizing, leaving the program with a reference to memory that has already been released.
