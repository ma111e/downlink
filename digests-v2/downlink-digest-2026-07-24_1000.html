ChatGPT AgentForger Flaw Could Deploy Rogue Workspace Agents via a Phishing Link

Researchers disclosed AgentForger, a now-fixed ChatGPT Workspace Agents flaw that could let a phishing link silently create and deploy a rogue AI agent inside a victim’s organization using their existing app connectors. The agent could persist, run scheduled tasks, access sensitive workspace data, and act on attacker instructions without further user interaction.
KEY POINTS
  • 01Zenity Labs disclosed a critical vulnerability called AgentForger in OpenAI's ChatGPT Workspace Agents that could allow a phishing link to build, authorize, and deploy an attacker-controlled AI agent inside a victim's organization.
  • 02OpenAI addressed the AgentForger issue on June 8, 2026, following responsible disclosure.
  • 03The attack required a victim who was logged into ChatGPT, had access to Workspace Agents, and had at least one already authorized connector such as Outlook, Gmail, Google Calendar, Google Drive, Slack, or Teams.
  • 04The malicious link could cause ChatGPT Agent Builder to automatically execute a prompt from the URL, attach available connectors, disable approval prompts, publish the agent, schedule it to run hourly, and invoke Preview Mode to run immediately.
  • 05Zenity said the forged agent could persist inside the organization, receive tasks through emails with subjects beginning with “TASK,” access sensitive data through connected apps, report results to the attacker, and send phishing links through Teams as the victim.

Cybersecurity researchers at Zenity Labs disclosed a critical vulnerability in OpenAI’s ChatGPT Workspace Agents called AgentForger. The flaw could have allowed a single phishing link to stealthily build, authorize, and deploy an attacker-controlled autonomous AI agent inside a victim’s organization. OpenAI addressed the issue on June 8, 2026, following responsible disclosure.

Zenity said the attack worked because ChatGPT Agent Builder accepted an initialization state through URL parameters, including an agent template and an initial prompt. When the page loaded, the initial_assistant_prompt value was automatically submitted and executed, so an instruction embedded in a URL could become the first command the Builder acted on. The attack required a logged-in ChatGPT user with access to Workspace Agents and at least one authorized connector such as Outlook, Gmail, Google Calendar, Google Drive, Slack, or Teams.

The malicious prompt could create an agent from the chief-of-staff template, attach available connectors, set them to “Never ask,” publish the agent, schedule it to run hourly, and invoke Preview Mode to run immediately. Zenity said the forged agent could receive tasks through emails with subjects beginning with “TASK,” execute those tasks, and report results to the attacker’s email address. The article says such an agent could conduct reconnaissance, harvest sensitive documents from cloud storage services, steal passwords mentioned in Slack messages, and impersonate the victim to send phishing links on Teams.

  • The flaw was not limited to creating an unwanted agent; Zenity said the agent could also turn off approval prompts for existing connectors, making previously authorized workplace integrations a major part of the risk.
  • Preview Mode became an execution path in the attack because it ran the newly created agent against the victim’s connected accounts rather than acting only as a harmless test or dry run.
  • The forged agent did not require the victim to keep the Builder tab open or click additional links, because scheduled runs and attacker-sent “TASK” emails could keep it operating after the initial click.
  • The attack used normal workplace tools such as email and Teams as both command channels and delivery paths, allowing the rogue agent to receive assignments and potentially spread phishing links while impersonating the victim.
  • Zenity framed AgentForger as an “agent trust failure,” where the platform treated agent creation, connector approvals, scheduling, and operation as if they were all intentional actions by the user.

Researchers found a flaw in OpenAI’s ChatGPT Workspace Agents that could let a single phishing link create a hidden AI helper inside a company using a real employee’s account and connected apps like email, Slack, Teams, or Google Drive. It affected logged-in ChatGPT users who had access to Workspace Agents and had already connected at least one workplace app, and OpenAI fixed the issue on June 8, 2026. This matters because the hidden agent could keep running, read or send information through the employee’s work apps, follow new instructions sent by email, and help attackers steal documents, passwords, or trick more coworkers.

Hacker Runs Hermes AI Agent Unattended for Post-Exploitation at Thai Finance Ministry

A hacker used the open-source Hermes AI agent in unattended “YOLO” mode to automate post-exploitation activity inside Thailand’s Ministry of Finance after already gaining access. The key lesson is that self-hosted AI agents can quietly scale routine intrusion tasks without vendor oversight, while exposed logs and misconfigured services like HiveServer2 can reveal or enable the activity.
KEY POINTS
  • 01An operator installed the open-source Hermes AI assistant on a rented server, enabled its YOLO mode to remove approval prompts for risky commands, and pointed it at Thailand’s Ministry of Finance after already gaining access to the ministry’s network.
  • 02Hunt.io and researcher Bob Diachenko found the operator’s exposed Hermes logs on a web server with directory listing enabled, along with 585 files and 470 MB of attack tooling.
  • 03The Hermes agent performed repetitive post-exploitation tasks including kernel vulnerability scanning, LinPEAS runs, elevated-permission binary searches, filesystem listing, and recursive crawling of a ministry web root containing personnel records dating to 2012.
  • 04The recovered files included scripts targeting the ministry’s Hadoop cluster through HiveServer2, whose default authentication mode accepts any password, and a malicious Java add-on called HiveCmd.jar for running operating-system commands through database queries.
  • 05Nothing in the recovered material shows data leaving the network, and Thailand’s national CERT and cybersecurity agency were notified on July 15 but had not published anything by July 24 when The Hacker News checked.

Someone installed the open-source Hermes AI assistant on a rented server, disabled the setting that asks for approval before risky commands, and pointed it at Thailand’s Ministry of Finance after already gaining access to the ministry’s network. The agent then worked through the network on its own, running scans, checking for ways to gain root access, searching file systems, and crawling a folder containing staff personnel records dating back to 2012. Hunt.io and researcher Bob Diachenko found the operator’s exposed logs on a web server with directory listing enabled, along with 585 files and 470 MB of attack tooling.

The case is significant because the operator used Hermes in its documented YOLO mode, which removes human approval prompts, and ran it on their own machine where no vendor account could be monitored or banned. The article says Hermes is not a hacking tool and that nothing here is a flaw in it, but the recovered logs show how an AI agent can automate repetitive post-exploitation commands that a person would otherwise type. Nothing in the recovered material shows data leaving the network, and the initial route into the ministry is unknown.

Much of the custom code targeted the ministry’s Hadoop cluster through HiveServer2, whose default authentication mode accepts any password according to Apache documentation. One script installed a malicious Java add-on called HiveCmd.jar as a user-defined function, allowing operating-system commands to be run through ordinary database queries as the Hive service account. The article recommends checking HiveServer2 authentication, restricting user-defined functions, watching for web servers connecting to Hadoop ports, searching web roots for hidden PHP files, and patching the named Linux kernel, sudo, polkit, and IIS 6.0 flaws.

  • The case differs from previously reported AI-assisted attacks because Hermes was self-hosted by the operator, meaning there was no vendor account to monitor, suspend, or ban.
  • The operator did not need Hermes to discover a new vulnerability or choose the target; the recovered material shows the agent mainly automated ordinary repetitive commands that a human attacker would otherwise run manually.
  • A practical detection opportunity is the consistent Hermes output path, because Hunt.io found exposed results under a predictable /hermes-results/ folder with predictable filenames.
  • The Hadoop targeting was built around a documented default setting in HiveServer2 where authentication mode NONE accepts any password, making configuration review more important than looking only for novel exploits.
  • The exposed directory listing on the operator’s own server, rather than an AI safety control, is what revealed the activity and the associated tooling.

Someone who had already broken into Thailand’s Ministry of Finance used an AI helper called Hermes to keep looking through ministry computers without having to approve each step. The activity exposed staff records going back to 2012 and targeted systems used by the ministry for large amounts of data, although the recovered logs do not show the files being taken out. It matters because the AI tool was running on the attacker’s own server, so no company could shut off the account, and a simple exposed folder is what revealed what had happened.

Bing Images Flaws Let Crafted SVGs Run Commands as SYSTEM on Microsoft's Servers

Researchers found that crafted SVG images submitted to Bing’s image search could trigger ImageMagick delegate command execution, running commands as SYSTEM on Windows workers and root on Linux servers. Microsoft fixed the two critical server-side flaws, but the case highlights the danger of letting untrusted image processing reach shell-enabled delegates or outbound network access.
KEY POINTS
  • 01XBOW found that a crafted SVG submitted to Bing’s image search could run commands as NT AUTHORITY\SYSTEM on Microsoft’s Windows image-processing workers and as root on Linux workers.
  • 02Microsoft assigned CVE-2026-32194 and CVE-2026-32191 to the two flaws, rated both 9.8 on the CVSS scale, and fixed them server-side before the March advisories were published.
  • 03The two unauthenticated routes were the public Search by Image upload using the imageBin field to /images/kblob and the crawler route using the imgurl parameter, which bingbot/2.0 fetched into the same processing pipeline.
  • 04The exploit path involved an SVG image reference beginning with a pipe character that reached a delegate-enabled ImageMagick-compatible layer and was treated as a shell command rather than a filename.
  • 05The article recommends denying ImageMagick delegates in policy.xml, reducing accepted formats, reviewing delegates.xml, sandboxing conversion workers, reducing privileges, blocking outbound network access, and allowlisting server-side fetch destinations.

XBOW found that crafted SVG files submitted to Bing’s image search could run commands on Microsoft’s production image-processing workers. The commands ran as NT AUTHORITY\SYSTEM on Windows workers and as root on Linux machines in the same fleet. Microsoft assigned two critical CVEs, CVE-2026-32194 and CVE-2026-32191, rated both 9.8 on the CVSS scale, and fixed them server-side before the March advisories were published.

The two unauthenticated routes were the public Search by Image upload to /images/kblob using the imageBin field and a crawler route where bingbot/2.0 fetched an SVG supplied through the imgurl parameter. The exploit worked because the image-processing path still had a delegate-enabled layer, and an SVG image reference beginning with a pipe character was treated as a shell command rather than a filename. XBOW used benign read-only commands and out-of-band callbacks to prove execution, while the frontend could return an error even though the backend worker executed the payload.

The article says the issue reflects a broader risk in image-processing stacks that pass untrusted uploads or fetched URLs through ImageMagick or compatible tools. It recommends denying delegates in policy.xml, reducing accepted formats such as SVG, MVG, and EPS, reviewing delegates.xml, sandboxing conversion, lowering worker privileges, blocking outbound network access, and allowlisting server-side fetch destinations. It also compares the bug class to ImageTragick, noting that converter components can become part of the attack surface when they parse attacker-controlled content.

  • The frontend could return an error while the backend worker still fetched, parsed, and executed the submitted content, so a failed user-facing request did not mean the processing path was safe.
  • Blocking outbound network access from image-processing workers would have limited the researchers’ ability to prove command execution, because the proof relied on curling command output back to a collector they controlled.
  • Some ImageMagick pseudo-protocols behaved safely or failed in XBOW’s probes, but the exploitable path was specifically an image reference inside the SVG that reached a delegate-enabled layer.
  • The same bug shape as ImageTragick resurfaced because the converter was treated as plumbing rather than as an attacker-controlled parser in the application’s attack surface.
  • Microsoft’s CVE records still listed no public disclosure on July 24 even though XBOW had published exploit mechanics on July 23 after remediation had landed.

A security company found that specially made image files sent to Bing’s image search could make Microsoft’s own image-processing servers run commands with the highest level of control. Microsoft fixed the problem on its servers before publicly listing the issues, so Bing users do not need to do anything. It matters because systems that accept or fetch images can be fooled if the hidden tools used to process those images are too powerful, allowed to run commands, or allowed to contact the internet.

Seeing AI Agents Is Not Enough. Security Teams Must Enforce What They Can Do

Security teams should not stop at discovering AI agents; they need identity-centric, context-aware enforcement that controls what each agent can do based on ownership, permissions, usage, and intent. The key shift is from static inventories to consistent rules that govern agent actions across platforms.
