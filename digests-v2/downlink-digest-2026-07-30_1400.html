After the Break-In: What Attackers Do Once They're Already Inside

A Huntress-investigated incident showed that after exploiting a SQL injection flaw, an attacker carefully established persistence, enabled RDP, created an admin account, disabled Windows Defender, installed BadIIS modules, and deployed an XMRig miner. The key lesson is that incident cleanup must include finding and fixing the original entry point, not just removing malware and rogue accounts.
KEY POINTS
  • 01Huntress investigated a June incident in which an attacker used a SQL injection flaw in a webpage on the same server as Microsoft SQL Server to gain access to the underlying Windows machine.
  • 02After gaining access, the attacker ran a built-in Windows command to list running services and sent the scan results to a server they controlled.
  • 03The attacker enabled Remote Desktop, created a new local administrator account, logged in through Remote Desktop, and disabled Windows Defender while leaving other monitoring tools untouched.
  • 04The attacker installed BadIIS modules on the IIS web server and deployed an XMRig cryptocurrency miner configured to run as a Windows service with hidden, system, and read-only file attributes.
  • 05The article emphasizes that defenders must identify and fix the original entry point, because removing attacker tools and accounts without fixing the SQL injection flaw would allow the attacker to return.

Huntress describes a June incident in which an attacker gained access to a Windows machine through a SQL injection flaw in a webpage on the same server as Microsoft SQL Server. The attacker did not go directly to stealing data, encrypting files, or dropping ransomware, but instead spent time establishing a foothold and changing the environment. The article emphasizes that what happens after initial access matters because attackers may create backdoors, cover tracks, and disable tools meant to catch them.

After gaining access, the attacker ran a Windows command to list running services and sent the results to a server they controlled. They enabled Remote Desktop, created a new local administrator account, logged in through Remote Desktop, and disabled Windows Defender while leaving other monitoring tools untouched. The attacker also installed BadIIS modules for Internet Information Services, dropped an XMRig cryptocurrency miner, hid files with system attributes, configured the miner as a Windows service, and used PowerShell and batch files from external servers.

The article’s main lesson for defenders is that removing attacker tools and accounts is not enough if the original entry point remains unfixed. In this case, the SQL injection flaw could have allowed the attacker to return even after surface-level cleanup. Huntress recommends maintaining an inventory of systems and applications, reducing exposed services, removing unnecessary software, locking down access with MFA where possible, keeping applications patched and monitored, and investigating root cause in every incident.

  • The attacker did not immediately steal data or deploy ransomware, showing that post-access activity can focus first on reshaping the environment for persistence, concealment, and future use.
  • Huntress noted it was unusual that the attacker disabled Windows Defender but left other security monitoring tools such as EDR untouched, suggesting the remaining tools may still provide visibility during an intrusion.
  • The incident stood out because the attacker combined many environment changes on a single machine, including remote access, account creation, defense disabling, web server manipulation, cryptocurrency mining, and detection-evasion tooling.
  • The article highlights that cleanup is incomplete if it removes visible attacker tools but leaves the original SQL injection flaw in place, because the same entry path can be reused.
  • A basic asset and application inventory is presented as a starting point for defense because teams need to know which systems, applications, and versions exist before they can reduce exposure, patch, and monitor them.

Huntress investigated a case where an attacker got into a Windows web server through a poorly checked input field on a website. Once inside, the attacker made new ways to return, created a powerful new user account, weakened built-in protection, changed the website server to misuse visitor traffic, and added software that secretly used the victim’s computer power to make cryptocurrency. This matters because the organization that owns the server can keep being harmed if it only removes the attacker’s tools but does not fix the original website flaw that let the attacker in.

Attackers are impersonating IT support on Microsoft Teams to trick employees into granting remote access, then using tools like Quick Assist or RemSupp to deploy backdoors and, in some cases, Chaos ransomware. KEY POINTS
  • 01Threat actors impersonated IT support staff in Microsoft Teams chats and calls to convince employees to start remote support sessions or install remote management tools.
  • 02Sophos tracks the campaign as STAC4749 and says it targeted dozens of North American organizations between February and June 2026, with about 95% of attacks aimed at organizations in Canada and the United States.
  • 03The attackers used tools including Microsoft Quick Assist, RemSupp, DWAgent, AnyDesk, PowerShell, and attempts to enable Remote Desktop Protocol after gaining access to employee devices.
  • 04At least three STAC4749 intrusions led to Chaos ransomware deployment, and one attack went from initial Microsoft Teams contact to file encryption in less than 17 hours.
  • 05Sophos says Chaos ransomware-as-a-service has been active since at least February 2025 and is believed to be linked to former members of the BlackSuit and Royal ransomware gangs.

Threat actors are impersonating IT support staff in Microsoft Teams chats and calls to gain remote access to corporate devices and deploy Chaos ransomware. Sophos tracks the campaign as STAC4749 and says it targeted dozens of organizations between February and June 2026. About 95% of the attacks targeted organizations in Canada and the United States, with services, manufacturing, energy, and construction and engineering among the most affected sectors.

The attackers used external Microsoft Teams accounts and IT-themed .top domains such as sequrityupdate[.]top, scan-security[.]top, system-connect[.]top, corp-connect[.]top, and supportsoft[.]top. They tried to convince employees to start remote support sessions with Microsoft Quick Assist or install remote monitoring and management tools, later favoring RemSupp when Quick Assist was unavailable or blocked. After gaining access, they used PowerShell to download a backdoor into the compromised user’s %AppData% folder and disguised persistence entries as Realtek and Windows audio components.

At least three STAC4749 intrusions led to Chaos ransomware deployment, and one attack moved from initial Microsoft Teams contact to file encryption in less than 17 hours. In ransomware cases, files were encrypted across compromised devices and ransom notes named readme.chaos.txt were created. Sophos says Chaos ransomware-as-a-service has been active since at least February 2025 and is believed to be linked to former members of the BlackSuit and Royal ransomware gangs.

  • The campaign moved away from the common use of Microsoft onmicrosoft.com tenants and instead used IT-themed .top domains, making its Teams impersonation infrastructure different from earlier Teams social engineering attacks described in the article.
  • The attackers shifted from primarily using Microsoft Quick Assist to primarily using RemSupp beginning in April, because Sophos says RemSupp may have been less likely to appear on corporate application blocklists.
  • The attackers disguised persistence entries as Realtek and Windows audio components, using names such as "Realtek HD Audio," "Realtek Audio UHD," and "WinAudio life2" to make malicious registry entries appear legitimate.
  • Sophos observed the attackers repeatedly changing malware filenames, persistence mechanisms, and deployment methods between February and May to avoid detection.
  • The short time from first Teams contact to ransomware deployment in one incident led Sophos to assess with high confidence that STAC4749 was financially motivated and either directly deployed ransomware or coordinated with affiliates.

Criminals are pretending to be company IT support staff on Microsoft Teams calls, convincing employees to let them remotely control work computers, and then using that access to lock files with Chaos ransomware. Sophos says this campaign targeted dozens of organizations between February and June 2026, mostly in Canada and the United States, especially in services, manufacturing, energy, construction, and engineering. In at least three cases the break-ins led to ransomware, and in one case the attackers went from first contact to file encryption in less than 17 hours, showing how quickly a fake support call can turn into a major business disruption.

Google’s AI security work includes earlier fuzzing improvements, Project Zero’s Naptime system, and Big Sleep, an AI-powered vulnerability discovery agent developed with Google DeepMind and Project Zero. The company is also working to reduce the delay between committing a fix to Chrome’s public source code and delivering that fix to users.   • The discovery of a 13-year-old Chrome sandbox escape shows that Google’s AI systems are being used to search older, broader parts of the Chrome codebase rather than only newly written code.
  • Google treats faster bug discovery as creating a new delivery problem, because once fixes appear in public source code, attackers can study them before users receive the update.
  • Google is trying to make security updates less dependent on user action by developing dynamic patching and enabling Chrome on macOS to restart automatically when it is running in the background without open windows.

Google says artificial intelligence helped it find and fix 1,072 security problems in Chrome 149 and Chrome 150, far more than in many previous releases combined. This matters to people who use Chrome because some flaws could let attackers break out of the browser’s protections or try to learn from public fixes before everyone has updated.
