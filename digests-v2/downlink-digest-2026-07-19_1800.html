Critical NGINX Vulnerability Can Crash Workers and May Allow Remote Code Execution

F5 patched a critical NGINX heap buffer overflow, CVE-2026-42533, that can let unauthenticated attackers crash worker processes and may enable remote code execution in certain configurations. Organizations should upgrade to nginx 1.30.4/1.31.3 or NGINX Plus 37.0.3.1 because temporary mitigations may not fully close the issue.
KEY POINTS

  • 02The flaw can let a remote, unauthenticated attacker trigger a heap buffer overflow in the nginx worker process using crafted HTTP requests.

F5 shipped fixes for CVE-2026-42533, a critical nginx flaw that allows a remote, unauthenticated attacker to trigger a heap buffer overflow in the worker process with crafted HTTP requests. The issue was patched on July 15 in nginx 1.30.4 stable, nginx 1.31.3 mainline, and NGINX Plus 37.0.3.1. Triggering the flaw can crash or restart the worker process, causing denial of service, and F5 says it may allow remote code execution where ASLR is disabled or can be bypassed.

The vulnerability depends on configuration, not just version, and appears in a specific pattern involving a regex-based map whose output variable is referenced after a capture from an earlier regex match. The article explains that nginx’s two-pass script engine first measures the needed buffer size and then writes the result, but the shared capture state can be overwritten between those passes. As a result, the buffer may be sized for one capture while the write uses a different attacker-sized capture, producing an overflow controlled by the request.

F5 lists the flaw as affecting core nginx, NGINX Plus, NGINX Ingress Controller, Gateway Fabric, App Protect WAF, and Instance Manager, though fixed builds for the latter four were not listed at publication. F5 recommends upgrading and offers a temporary mitigation of switching affected regex maps to named captures, but researcher Stan Shaw says upgrading is the only complete fix because a narrower named-capture path remains. As of July 20, CVE-2026-42533 was not in CISA’s Known Exploited Vulnerabilities catalog and no public exploit code had appeared, while Shaw said he would publish a proof-of-concept 21 days after the patch.

  • The vulnerability is configuration-dependent, so simply running a vulnerable nginx version is not enough to confirm exposure; administrators need to inspect whether regex-based maps and capture variables are used in the specific ordering described.
  • Researcher Stan Shaw claims the bug can leak uninitialized heap data when the clobbered capture is smaller than the original, potentially providing the address information needed to bypass ASLR on a default Ubuntu 24.04 build.
  • F5’s suggested mitigation of switching affected regex maps to named captures may not fully address the issue, because Shaw says a map that defines the same named group as the location regex can still reach the overflow through another code path.
  • The article says no public exploit code or CISA Known Exploited Vulnerabilities listing existed as of July 20, but Shaw plans to publish a proof-of-concept 21 days after the patch, creating a limited window to upgrade before exploit details may become public.

F5 fixed a serious problem in NGINX, a widely used web server, that can let someone on the internet send specially made web requests to crash parts of the server and may even let them run their own code in some cases. Not every NGINX server is affected, but systems using certain configuration patterns in older versions of nginx, NGINX Plus, and related F5 NGINX products may be at risk. This matters because the issue can take websites or services offline, and researchers say a public demonstration of how to exploit it may be released soon, making upgrades especially urgent.
