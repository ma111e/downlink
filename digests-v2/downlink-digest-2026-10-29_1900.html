AMOS Malware in AI Agent Skills: Analysis and IoCs

Cyera found 516 AI-agent skills linked to the Atomic macOS Stealer campaign, including 70 confirmed malicious skills that still received high automated security grades on a popular marketplace. The poisoned documentation hides OS-specific setup commands that lure users or agents into downloading credential-stealing payloads, underscoring the need to inspect skill instructions and external dependencies before execution.
KEY POINTS
  • 01Cyera Research identified 516 AI skills tied to the Atomic macOS Stealer (AMOS) campaign across its broader dataset of 1.3 million AI skills, MCP servers, and plugins.
  • 02Of 70 confirmed malicious skills identified from non-Hugging Face sources in September 2026, all received A or B automated security grades on a popular skills marketplace.
  • 03The poisoned skills concealed malicious installation instructions in otherwise plausible documentation, commonly directing macOS users to decode Base64 text and execute it with Bash while directing Windows users to download and run a separate package.
  • 04AMOS is a macOS information-stealing malware family that can collect browser passwords and session cookies, keychain information, and sensitive files before sending the data to attacker-controlled infrastructure.
  • 05The payload host 91.92.242.30 accounted for 83.7% of IP references in the dataset, while two glot.io snippets accounted for 95.9% of paste-relay references.

Cyera Research identified 516 AI skills associated with the Atomic macOS Stealer (AMOS) campaign across its dataset of 1.3 million AI skills, MCP servers, and plugins. The campaign places malicious setup instructions inside otherwise plausible skill documentation, directing users or AI agents to install supposed prerequisites. Of 70 confirmed malicious skills identified from non-Hugging Face sources in September 2026, all had received A or B automated security grades on a popular marketplace.

The instructions commonly provide separate paths for macOS and Windows: macOS users are told to decode Base64 text and run it through Bash, while Windows users are directed to download and execute a separate package. The article identifies repeated use of fake OpenClaw-related utilities, glot.io paste relays, and a heavily reused payload host, 91.92.242.30, which represented 83.7% of referenced IP addresses. AMOS can steal browser passwords and session cookies, keychain information, and sensitive files, illustrating how trusted-looking AI skills can expose employee credentials and organizational data.

  • High marketplace security grades were not reliable safety indicators because the cited grading methodology evaluated only SKILL.md and did not account for bundled scripts or other files.
  • The most useful warning signs were installation behavior rather than the advertised topic of a skill, including Base64-decoded commands piped to Bash, external paste-site links, and claims that a fake OpenClaw utility was required.
  • Most newly identified malicious skills were reportedly labeled malicious and removed about a week after collection, indicating a potentially meaningful exposure period between publication and removal.
  • A visible benign-looking address in a command can be deceptive: in one macOS example, the displayed swcdn.apple.com address was only printed to the screen, while the real download location was hidden in Base64-encoded text.
  • Reviewing only SKILL.md can miss harmful content because the article cites an example of an encoded dropper hidden in an approximately 22 MB README.md.

Researchers found hundreds of AI assistant add-ons that looked useful but contained setup instructions designed to install Atomic macOS Stealer, a program that can steal passwords, browser login data, and sensitive files from Macs. These add-ons were aimed at people using AI assistants for developer work, social media, and office tasks, and some also directed Windows users to a different harmful download. The danger is that marketplace safety scores gave many of these add-ons high marks even though the harmful instructions were hidden among normal-looking documentation, so users and organizations can be tricked into giving criminals access to valuable accounts and data.

Malicious AI Skills: The Risk to Corporate Endpoints

Cyera researchers found fake copies of Anthropic’s PDF AI skill that retain legitimate files but replace SKILL.md instructions and add an obfuscated Linux Go reverse shell connecting to a hard-coded remote server. The case shows that organizations must verify entire AI-skill packages—not just their names or bundled scripts—before allowing agents to run them.
KEY POINTS
  • 01Cyera Research analyzed a package named “pdf” that copied Anthropic’s PDF skill, with 11 files matching the official version byte for byte.
  • 02The package’s SKILL.md retained Anthropic’s name and description but was reduced from 315 lines to 19 lines and replaced its original instructions with a command to contact an external hostname.
  • 03The package added a 5 MB obfuscated Go executable named system_linux that connects to 81.70.101[.]115:2345 and attaches /bin/bash to the connection if run.
  • 04Researchers identified five similar tar files observed from May 23 through July 14, 2026, all containing the modified SKILL.md, system_linux, and a text file named 1.
  • 05The researchers did not observe a user installing the skill, an agent running its curl instruction, or the system_linux binary being launched.

Cyera Research analyzed a malicious package named “pdf” that impersonated Anthropic’s official PDF skill. Eleven files, including the legitimate PDF scripts, matched Anthropic’s version exactly, while the package replaced the 315-line SKILL.md instruction file with a 19-line version containing a command to contact an external hostname. It also added a 5 MB file named system_linux, an obfuscated Linux executable not present in the official skill.

The added executable is a statically linked Go program that decrypts a hard-coded destination and, if run, opens a TCP connection to 81.70.101[.]115:2345 before attaching /bin/bash to it. Researchers observed five similar tar files between May 23 and July 14, 2026, but did not observe an installation, execution of the curl instruction, or launch of the binary. The case demonstrates that checking only a skill’s familiar name or bundled scripts can miss altered instructions and added executables, so organizations should verify whole skill packages and investigate unexpected commands, network destinations, and binaries before agents use them.

  • A script-only review could miss the threat because 11 bundled files were unchanged from Anthropic’s legitimate PDF skill, while the harmful behavior was concentrated in the altered instruction file and added executable.
  • The package used the legitimate skill’s original name and description, meaning an agent or user selecting a familiar PDF tool could have little indication from its label that its instructions had been replaced.
  • The researchers could verify that the added Linux program was configured as a reverse shell, but they found no evidence that the program was executed or that the malicious instruction completed, which limits conclusions about any completed compromise.
  • The external hostname named in the altered instructions resolved to a private IP address during analysis, so the article identifies the package’s malicious components without establishing the full intended execution path.

Researchers found files pretending to be Anthropic’s tool for working with PDF documents, with most of the real files copied exactly so the package looked trustworthy. Hidden changes told an AI assistant to contact an outside website and included a program that could give a remote person control of a Linux computer if it was run. Organizations and people using shared AI tools could be affected, because a familiar name and legitimate-looking files may hide harmful instructions. The case shows why the full contents of an AI tool should be checked before letting it run commands or access a computer.

How to Vet AI Agent Skills: Lessons From a Fake PDF Skill

A malicious copy of Anthropic’s PDF skill preserved legitimate scripts and branding while replacing its instructions and adding a Linux backdoor, showing that AI-agent skills must be vetted as complete packages. Organizations should verify provenance, inspect every file and instruction, restrict execution and network permissions, and review updates before use.
KEY POINTS
  • 01Cyera Research identified a malicious copy of Anthropic’s PDF skill that retained its familiar name, description, and 11 files matching the official skill while altering the main SKILL.md instructions and adding a Linux executable.
  • 02The altered SKILL.md file was reduced from 315 lines to 19 and instructed the agent to make a network call to a Chinese domain.
  • 03The package included a 5 MB system_linux binary that Cyera said could provide a remote operator with a shell if executed.
  • 04Cyera found no direct code or instructions to execute the binary, but said the altered instructions called an external URL whose domains resolved to a private IP address during the research.
  • 05The article recommends verifying complete skill packages against their claimed sources, inspecting instructions and bundled code, and limiting agent permissions for network access and software execution.

Cyera Research analyzed a malicious copy of Anthropic’s PDF skill that retained the familiar name, description, and 11 files matching the official version. The package changed the main SKILL.md instruction file from 315 lines to 19 and added a 5 MB Linux executable named system_linux. The altered instructions told an agent to make a network call to a Chinese domain, while the added binary could give a remote operator a command shell if executed.

Cyera found no direct code or instructions to execute the binary, but reported that the domains referenced in the instructions resolved to a private IP address at the time of research. The original ZIP file and five related archives were observed between May 23 and July 14, 2026. The article says the case demonstrates that organizations must evaluate complete AI-skill packages, including instructions and unexpected files, rather than relying on recognizable branding, names, descriptions, or known scripts.

Companies should assign ownership for skills used in sensitive workflows, compare every file against claimed sources, and investigate changed instructions, unfamiliar network destinations, and unexpected executables. The article recommends scanning both bundled code and instructions, limiting agent permissions for network access and software execution, and reviewing components again after updates. If a suspicious package is found internally, responders should determine whether it was present, whether its instructions were followed, and whether any added program ran.

  • Matching known-good scripts is not sufficient to establish trust in an AI skill: in this case, 11 files matched the official PDF skill exactly while the changed instruction file and added executable altered the package’s risk.
  • An AI skill’s instructions are a security-relevant part of the software package because they can direct an agent to use the tools and permissions already available to it.
  • Previously reviewed skills require renewed scrutiny after updates, since familiar names, descriptions, and legitimate files can coexist with changed instructions or unexpected bundled programs.
  • A narrowly scoped document-processing request can create wider organizational exposure when a skill can make network connections or run added software under the permissions of the account that launched it.
  • For an internal suspicious package, responders should determine not only whether the package was present, but also whether its instructions were followed and whether any bundled program ran.

Researchers found a fake version of Anthropic’s PDF helper for AI agents that kept familiar names and working PDF files but changed the directions and included a program that could let someone remotely control the computer. Employees and companies using AI helpers to handle documents could be affected, especially if those helpers can access company files, passwords, or internal systems. The case shows that a familiar brand or normal-looking files are not enough to prove a tool is safe; organizations need to check everything included and limit what AI helpers are allowed to do.

Malicious AI Skills: A Risk to Corporate Endpoints

Cyera researchers identified 70 malicious AI skills that posed as productivity and developer tools but instructed users to install Atomic macOS Stealer (AMOS), risking theft of credentials, browser sessions, and corporate data. Marketplace security grades did not reliably detect the full malicious packages, so organizations should require human approval for software installs and review AI skills and their dependencies.
KEY POINTS
  • 01Cyera Research identified 516 exhibits associated with an operation distributing Atomic macOS Stealer (AMOS) in a study of more than one million AI skills, and confirmed 70 net-new malicious skills across six repositories and platforms in September 2026.
  • 02The malicious skills posed as developer and productivity tools and instructed users to install an additional component that delivered AMOS, which can collect saved passwords, browser sessions, and sensitive files.
  • 03All 70 confirmed malicious skills had high security grades from Skills Directory when collected, although the platform’s published grading methodology covers the main SKILL.md instruction file rather than all bundled scripts and supporting files.
  • 04Developer tooling represented 35.7% of the exhibits, office productivity represented 12.8%, and documents and knowledge represented 3.5%, together accounting for about 52% of the samples.
  • 05The article recommends preventing agents from installing software without direct human approval, reviewing full skill packages and their changes, educating employees, and monitoring actual agent behavior.

Cyera Research examined more than one million AI skills and found 516 exhibits tied to an operation distributing Atomic macOS Stealer (AMOS). In September 2026, it confirmed 70 new malicious skills across six repositories and platforms. The skills posed as developer and productivity tools and told users to install a supposedly required add-on that instead delivered credential-stealing malware.

AMOS is designed to collect saved passwords, browser sessions, and sensitive files, which on a corporate Mac could expose company accounts, code, cloud access, or operational information. All 70 confirmed skills had high security grades from Skills Directory when collected, but its published grading method covers the main SKILL.md file rather than all bundled scripts and supporting files. The article recommends requiring direct human approval before agents install software, reviewing full skill packages and changes, educating employees to report suspicious AI assets, and continuously monitoring agent behavior.

  • High marketplace grades can create misplaced trust because Skills Directory’s published methodology evaluates the main instruction file rather than every bundled script and supporting resource.
  • Removing a malicious skill from a repository limits future downloads but does not establish whether anyone already installed it or what company information may have been exposed.
  • Approval of an AI product is not a one-time decision: a skill can later add dependencies, request additional access, or direct activity to an outside service.
  • The researchers identified a malicious delivery route but stated that they could not measure how many enterprise compromises actually resulted from the campaign.

Researchers found 70 fake AI add-ons that looked like useful tools for developers and office work but told people to install software that steals saved passwords, web logins, and files from Mac computers. These listings received strong safety grades in a popular directory, showing that such ratings may not catch dangerous hidden instructions. This matters to businesses because one employee trying to work faster could give criminals access to company accounts, code, cloud services, or sensitive information.

Health-ISAC Hacking Healthcare 10-27-2026

Singapore’s Cybersecurity Strategy 2026 adopts a whole-of-ecosystem approach that strengthens protection of critical infrastructure, including healthcare, while expanding mandatory standards, AI-enabled defense, quantum preparedness, and international partnerships.
KEY POINTS
  • 01Singapore announced its Cybersecurity Strategy 2026 on October 13 at the opening ceremony of Singapore International Cyber Week, replacing its 2021 strategy.
  • 02The strategy identifies four pillars: defending critical infrastructure, securing the wider cyberspace, strengthening capabilities for AI and quantum, and enhancing resilience through global partnerships.
  • 03Healthcare is among the 11 sectors covered by Singapore’s Critical Information Infrastructure framework, and the strategy calls for stronger capabilities to defend these services against advanced and AI-enabled threats.
  • 04The strategy supports stronger cybersecurity regulations and baseline standards, including mandated adoption of cyber standards for higher-risk organizations.
  • 05Singapore frames AI as a cyber threat, a defensive tool for faster detection and response, and a target that must be secured as it becomes embedded in organizations and critical systems.

Singapore announced its Cybersecurity Strategy 2026 on October 13 at the opening of Singapore International Cyber Week. The 68-page strategy replaces the 2021 version and continues Singapore’s five-year refresh cycle for national cybersecurity planning. It presents a whole-of-ecosystem approach intended to strengthen national cyber resilience amid more complex threats, emerging technologies, supply-chain complexity, and geopolitical instability.

The strategy is organized around four pillars: defending critical infrastructure, securing the wider cyberspace, strengthening AI and quantum capabilities, and improving resilience through global partnerships. Healthcare is included among the 11 sectors covered by Critical Information Services, with an emphasis on helping operators defend against advanced and AI-enabled threats and build technical, operational, leadership, and workforce capability. The plan also supports stronger regulations and minimum standards for higher-risk organizations, explores proactive actions such as scanning and taking down malicious infrastructure, and treats AI as a threat, a defensive tool, and a target requiring protection.

  • Singapore’s strategy moves beyond recovering from cyber incidents by considering pre-emptive measures, including scanning for and taking down malicious infrastructure.
  • The government intends to adopt AI for cybersecurity early and use lessons from its own implementation to help critical-information-infrastructure entities.
  • The strategy signals a shift away from relying only on voluntary security adoption by supporting new minimum standards and mandatory requirements for higher-risk organizations.
  • Cyber resilience is treated as an ecosystem-wide responsibility that includes public education for groups such as students and seniors, not only government and critical-service operators.

Singapore has released its Cybersecurity Strategy 2026, a five-year plan for improving the country’s digital safety as threats become more complex. The plan includes stronger protection for essential services such as healthcare, higher security requirements for organizations considered at greater risk, and efforts to use artificial intelligence to spot and respond to problems faster. It matters because hospitals, public services, businesses, and individuals increasingly rely on digital systems, and disruptions or misuse of those systems can affect everyday services and personal safety.
