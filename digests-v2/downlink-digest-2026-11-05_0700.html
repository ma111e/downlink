GhostMap: The Android flaw that crashes your phone before you open the app

Bitdefender researchers disclosed GhostMap, an Android 10+ ZIP/APK parsing flaw that can let a specially crafted app crash system_server repeatedly after installation—even without being opened or granted permissions—potentially forcing a factory reset. The issue stems from inconsistent handling of unsupported ZIP compression methods and declared file sizes, and Google reportedly has not issued a security fix.
KEY POINTS
  • 01Bitdefender researchers found that a specially crafted APK can trigger a persistent Android crash loop after installation without being opened, requesting permissions, or containing executable code.
  • 02The GhostMap flaw arises because Android libraries handle unsupported ZIP compression methods differently, allowing an APK entry’s declared uncompressed size to exceed the actual file data and causing a SIGBUS crash when it is read.
  • 03Bitdefender reproduced the persistent crash loop on a Pixel 10 running Android 17 with the August 5, 2026 security patch and reported reproductions on Android 10 and later.
  • 04The crash can affect system_server, causing Android to restart the process and parse the malicious resource again, while safe mode does not stop the loop and recovery may require a factory reset.
  • 05Google reportedly classified the finding as outside the scope of a security update, referred it to a feature team for possible future consideration, and had not provided a fix as of the article’s publication.

Bitdefender Labs reported GhostMap, an Android flaw in which installing a specially crafted APK can cause a persistent crash loop without the app being opened, granted permissions, or containing executable code. Researchers reproduced the issue on a Pixel 10 running Android 17 with the August 5, 2026 security patch and on Android versions from 10 onward. When a core system service repeatedly reads the malformed app resource, it crashes and restarts, leaving the phone stuck at boot. Bitdefender stated that recovery may require a factory reset, unless USB debugging was already enabled and an ADB-based removal succeeds before the crashes occur.

The issue stems from inconsistent handling of ZIP entry compression methods and declared file sizes by Android libraries. One library validates an entry’s declared uncompressed size only when it is labeled as stored, while another maps that size for any entry that is not labeled deflated; an unsupported compression value can fall between those rules. When Android reads beyond the actual end of the mapped APK data, the process receives a SIGBUS crash. Bitdefender reported the issue to Google twice, and said Google considered it outside the scope of a security-update fix while referring it to a feature team for possible future consideration.

  • The triggering APK can contain no executable code because the failure occurs when Android reads a malformed resource file rather than when the app runs.
  • The flaw exists in a gap between two Android ZIP-reading libraries: one validates oversized data only when an entry is labeled “stored,” while another treats every method other than “deflated” as stored data.
  • A normal Android app that tries to inspect a malformed APK can be terminated by a native system crash, and wrapping the inspection call in ordinary Java error handling does not prevent that termination.
  • A malicious app could potentially corrupt its own icon so that the launcher and Settings screens crash when attempting to display it, making common uninstall paths inaccessible while the phone otherwise continues to run.
  • Safe mode does not resolve the demonstrated crash loop because the affected system service reads the malformed file before safe mode takes effect.

Bitdefender researchers found that a specially altered Android app can make a phone repeatedly crash and restart as soon as it is installed, even if the owner never opens it or gives it any permissions. The problem affects Android 10 and newer, including a tested Pixel 10 running Android 17, and may leave the owner needing to erase the phone completely to recover. It could be used to disable phones, make harmful apps difficult to remove, or crash programs that inspect suspicious apps, although Bitdefender says it has not seen these uses in the wild.

CERT-In Flags AI-Driven Attacks as Backdoored ARTEX Exposes 62 Consoles to Root Access

CERT-In warns that AI-assisted actors, including Crafty Falcon, are targeting India’s financial sector with automated attacks to steal API credentials and move funds. Separately, a backdoored ARTEX Docker image exposed at least 62 internet-facing consoles to an unauthenticated root shell, highlighting supply-chain risks from unvetted offensive-security tools.
KEY POINTS
  • 01CERT-In said the AI-assisted threat actor Crafty Falcon is actively targeting Indian banking, financial services, insurance, cryptocurrency exchanges, and digital asset service providers using tools including ARTEX, PentAGI, Cairn, and CyberStrikeAI.
  • 02The campaigns exploit internet-facing applications, exposed APIs, privileged endpoints, stolen API tokens, plaintext credentials, and services without multi-factor authentication to obtain credentials and conduct unauthorized fund transfers.
  • 03CERT-In reported that attackers perform small test transactions, abuse payment-aggregator merchant settlement APIs, deploy malicious code to cloud infrastructure, and delete logs or tamper with endpoint security tools to hinder detection.
  • 04A copied ARTEX version configured to pull the tomicdd/artex Docker image contains a hidden login routine that lets an unauthenticated requester run commands as root.
  • 05Researchers found 62 internet-facing ARTEX consoles serving the backdoored build between November 2 and 4, 2026, while Docker Hub reported 9,000 downloads of the tomicdd/artex image.

CERT-In warned that an AI-assisted threat actor tracked as Crafty Falcon is actively targeting organizations in India’s banking, financial services, insurance, cryptocurrency exchange, and digital-asset sectors. The group uses publicly available tools including ARTEX, PentAGI, Cairn, and CyberStrikeAI to automate attack chains, rapidly create tailored scripts, and adapt payloads based on responses. CERT-In said the operators target exposed applications, APIs, privileged endpoints, static API tokens, plaintext credentials, source-code repositories, and services without multi-factor authentication. Stolen payment and partner-bank API credentials can then be used from allow-listed infrastructure to invoke fund-transfer APIs and bypass application-level safeguards.

The attackers conduct small test transactions, such as Rs. 1 transfers, before moving larger sums to mule accounts, and they attempt to remove logs and interfere with endpoint security tools. CERT-In also said they target cloud and publicly accessible non-production systems to obtain credentials, tokens, or network paths that can be used to reach production environments. Separately, researcher Badbyte identified a copied ARTEX project that pulls the backdoored tomicdd/artex Docker image, whose hidden login behavior enables unauthenticated command execution as root. Between November 2 and 4, 2026, 62 internet-facing ARTEX consoles were found serving the malicious build, while the affected Docker image had been downloaded 9,000 times.

  • By using stolen payment and partner-bank API credentials from within an organization’s own allow-listed infrastructure, attackers can bypass business checks such as beneficiary verification, balance checks, and transaction limits.
  • The ARTEX copy altered only one docker-compose.yml line to retrieve a malicious Docker image, while the root-shell backdoor was concealed inside that image and therefore would not appear during a repository code review.
  • Attackers use very small transactions, including Rs. 1 transfers, to confirm that unauthorized payment paths work before attempting larger transfers.
  • Publicly accessible non-production systems can provide attackers with shared credentials, tokens, or network routes that allow them to move into production environments.
  • A compromised ARTEX console can expose unpatched findings, active credentials, captured sessions, and a network position, and its backdoor operator can alter the behavior of agents on later runs.

India’s cyber emergency agency says a group called Crafty Falcon is using AI-assisted tools to target banks, financial firms, payment services, and cryptocurrency businesses, aiming to steal account-access information and transfer money. The attackers can test small transfers first, then quickly send larger amounts to accounts they control while trying to erase evidence. Separately, a copied version of the ARTEX security-testing tool contained a hidden way for anyone to take full control of servers running it, affecting at least 62 internet-facing installations. Together, these cases show that both financial companies and people who install unverified security software can face serious theft and system-control risks.

Zyxel GS1900 Patch Fails to Block Zero-Day Exploit Allowing Root Command Execution

Zyxel GS1900 switches remain vulnerable to unauthenticated root command execution even after the earlier Patch 2 update; affected owners must install model-specific 2.90 Patch 3 firmware. The flaw, CVE-2026-107441, was already used in attacks that harvested switch configurations and hashed root credentials.
KEY POINTS
  • 01Zyxel’s earlier GS1900 2.90 Patch 2 firmware did not block an exploit that lets an unauthenticated person who can reach the web management interface execute commands with root privileges.
  • 02Zyxel released 2.90 Patch 3 firmware for 10 GS1900 switch models to address CVE-2026-107441, which affects Patch 2 and earlier firmware.
  • 03Binarly reported that the exploit uses an oversized request parameter to write beyond an allocated memory area and alter which function the switch’s web-request program calls.
  • 04GreyNoise reported that attackers collected data from 996 GS1900 switches around August 17, including switch configurations, hashed root credentials, and network information.
  • 05CISA added CVE-2026-7273 to its Known Exploited Vulnerabilities catalog on September 21, but CVE-2026-107441 was not listed in the catalog data cited by the article.

Zyxel GS1900 network switches that received the earlier 2.90 Patch 2 update remain vulnerable to an exploit that allows anyone who can reach the web management interface to run commands without logging in. Zyxel has released 2.90 Patch 3 firmware for 10 GS1900 models to fix the separate flaw, CVE-2026-107441. Binarly reported the issue to Zyxel on September 29 and said attackers already had a working exploit.

According to Binarly, the switch’s web-request program could be tricked by an oversized 140th request parameter into writing outside its allocated memory and changing the function it would call, enabling commands with root privileges. Patch 2 added a parameter-count check, but it occurred after the oversized parameter was copied and could therefore be bypassed; Patch 3 checks the count before copying and limits the copy size. GreyNoise reported that attackers collected data from 996 GS1900 switches around August 17, including configurations, hashed root credentials, and network information, while 564 of those switches still used factory-default credentials.

  • The Patch 2 safeguard checked the number of request parameters only after an oversized parameter had already overwritten the counter it relied on, allowing the existing exploit to work without changes.
  • Organizations that complied with CISA’s Patch 2 deadline could still have remained exposed because the newly identified CVE-2026-107441 is present in all 10 Patch 2 builds.
  • Zyxel’s advisory provides no workaround for owners unable to update and does not state whether Patch 3 removes an attacker’s existing access or what compromise checks owners should perform.
  • Of the 996 GS1900 switches from which attackers collected data, 564 still used factory-default credentials, according to GreyNoise.

Zyxel released a second software update for 10 GS1900 network switch models because the first update did not stop outsiders from taking control of them through their web management pages. Anyone able to reach that page could run commands as the device’s most powerful user without signing in, so owners using the earlier update still need the new Patch 3 version. Attackers have already used a matching method against hundreds of these switches to collect network settings and protected administrator password data, putting connected networks at greater risk.

The SOC Files 5: Ghost in the pipeline, or a fileless SharePoint breach by Storm-2603

Storm-2603 exploited ToolShell flaws in on-premises Microsoft SharePoint to implant a fileless webshell inside IIS w3wp.exe, enabling covert tunneling, privilege escalation, and attempted Warlock ransomware deployment. Defenders should treat SharePoint RCE as a host-level incident and hunt runtime and memory artifacts, anomalous IIS behavior, and post-compromise remote-access tooling—not just files or known IOCs.
KEY POINTS
  • 01Storm-2603 activity exploited CVE-2025-53770 and CVE-2025-53771 in on-premises Microsoft SharePoint to achieve remote code execution through crafted HTTP requests.
  • 02In the analyzed intrusion, attackers injected a fileless webshell into the IIS worker process, w3wp.exe, where it remained in memory until the application pool recycled or IIS restarted.
  • 03The webshell used a custom VirtualPathProvider and a User-Agent-triggered command channel to proxy TCP traffic to arbitrary hosts inside the victim network.
  • 04After compromising the server, the attackers installed Velociraptor and deployed several tunneling mechanisms, including Zoho Assist, VS Code CLI tunneling, Cloudflare Tunnel, and a reverse proxy utility.
  • 05The attackers attempted to deploy Warlock ransomware, but Kaspersky Endpoint Security's Proactive Defense Module blocked the ransomware process.

Kaspersky’s retrospective analysis identified activity consistent with Storm-2603 targeting an on-premises Microsoft SharePoint server through the ToolShell vulnerabilities CVE-2025-53770 and CVE-2025-53771. A vulnerability-fingerprinting request was observed on December 20, followed by three days of silence before the actor executed the full remote-code-execution chain on December 24. The intrusion used a fileless webshell injected into the IIS worker process, w3wp.exe, rather than writing the access mechanism to disk.

The implant used an ASP.NET VirtualPathProvider hook and a specific User-Agent to process attacker requests while remaining dormant for normal traffic. It supported a custom obfuscated command channel and TCP proxying to arbitrary internal hosts, and included capabilities for process and network discovery, file downloads, MSI installation, account creation, and SYSTEM-level privilege escalation using EFSRPC-based token impersonation. After the initial compromise, the actor installed Velociraptor and multiple remote-access and tunneling tools, attempted to disable security products with a vulnerable driver and malicious DLL, and attempted to deploy Warlock ransomware; Kaspersky Endpoint Security blocked the ransomware process.

The article emphasizes that confirmed SharePoint exploitation should be treated as a host-level compromise, not merely remediated by patching the initial flaw. It recommends preserving memory and IIS telemetry and hunting for unusual w3wp.exe behavior, unexpected outbound traffic, token impersonation, RPC coercion, and remote-management tools. It also describes detection opportunities in CLR assembly-loading artifacts associated with ToolPane deserialization and IIS ETW events that reveal virtual paths not backed by physical files.

  • The initial SharePoint vulnerability probe occurred three days before exploitation, and this delay initially caused the low-priority reconnaissance event to be missed as part of the same intrusion.
  • The in-memory implant was activated only when requests contained a specific User-Agent, allowing ordinary web traffic to pass without triggering its command-processing logic.
  • A VirtualPathProvider-based implant can be detected by comparing IIS configuration-path mappings in events 25 and 47 with the absence of a corresponding file and normal file-change-monitoring events 17, 18, 19, and 21.
  • The combination of App_Web_toolpane.aspx and Microsoft.GeneratedCode assemblies in the same application domain shortly after ToolPane access can indicate that attacker-supplied serialized data was being processed.
  • Storm-2603 used several independent remote-access and tunneling tools after initial compromise, reducing its dependence on the SharePoint process and creating multiple paths to retain access.

The article describes how a group tracked as Storm-2603 broke into an organization’s self-hosted Microsoft SharePoint server by exploiting known software flaws, then hid its control tool inside the server’s running memory instead of leaving an obvious file behind. Organizations that run SharePoint on their own servers are affected because attackers can use this access to explore internal systems, create powerful accounts, install remote-control tools, and try to deploy ransomware that locks data for payment. The case shows that a seemingly small early probe can lead to a much larger compromise days later, so organizations need to investigate confirmed server break-ins beyond simply fixing the original flaw.
