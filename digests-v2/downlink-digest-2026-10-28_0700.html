Aikido launches external network pentesting

Aikido has launched an AI-powered external network pentesting service that continuously discovers and tests internet-facing assets under a customer’s domain. The service aims to identify and validate exploitable weaknesses safely, providing evidence-backed findings and retesting as the external perimeter changes.
KEY POINTS
  • 01Aikido launched an external network pentesting service that maps and tests publicly reachable systems under a customer’s domain using AI agents.
  • 02The service discovers internet-facing assets such as websites, APIs, VPN gateways, mail servers, and self-hosted tools, while filtering out services the customer does not own.
  • 03Aikido says its agents test hosts for known CVEs, misconfigurations, and exposed secrets, and only report findings that are supported by validated and reproduced evidence.
  • 04The service can run continuously so newly discovered hosts are tested shortly after they go live, and its pricing is based on the number of publicly accessible assets found.
  • 05Aikido states that agents operate with safeguards including action review, limits on deeper exploitation, ownership checks, no downloading or storing customer data, and an emergency stop button.

Aikido has launched external network pentesting, an AI-agent service that starts with a customer’s domain and maps publicly reachable systems such as websites, APIs, VPN gateways, mail servers, and self-hosted tools. After ownership verification, agents test each host for known CVEs, misconfigurations, and exposed secrets. Aikido says findings are included only when agents provide concrete evidence that is validated and reproduced by other agents.

The launch is presented as a response to attackers using automated tooling to rapidly discover and exploit newly disclosed flaws. Aikido cites Cloudflare observations of escalating PHP2Shell exploit attempts and a16z figures showing that 86.7% of vulnerabilities exploited so far in 2026 were attacked on or before the day they became public. The service can run continuously to test newly discovered public-facing hosts, provides remediation suggestions and retests, and includes safeguards intended to avoid disruption, prevent testing systems the customer does not own, and stop agents immediately through a panic button.

  • The article cites a16z data showing that the share of exploited vulnerabilities attacked on or before public disclosure rose from 18.7% in 2018 to 86.7% so far in 2026, underscoring how little time organizations may have to respond.
  • Aikido distinguishes external network testing from a web application test: the external test evaluates publicly reachable infrastructure and unauthenticated application surfaces, while logged-in workflows and business logic require a separate web app pentest.
  • The article illustrates how several individually lower-severity exposures—an exposed .git folder, reused SSH credentials, and Azure credentials on a second server—can be chained into administrative access to a cloud tenant.
  • According to Aikido’s survey of 400 security and engineering leaders, 48% said pentest findings are already outdated by the time they arrive, supporting the article’s case for testing whenever the public-facing perimeter changes.

Aikido has launched a service that checks everything publicly visible under a company’s web address, such as websites, servers, email systems, and remote-access portals, for ways an outsider could break in. It is aimed at companies whose online systems can change faster than traditional once-a-year security reviews. This matters because criminals increasingly use automated tools to find and misuse newly disclosed flaws within hours, so unknown or newly added internet-facing systems can become an entry point into a company.

It may be relevant to teams evaluating continuous external exposure testing, but its core content is promotional and broadly applicable.

Millions of security cameras at risk: DoS vulnerability in Intelbras devices

Intelbras patched an unauthenticated firmware-update endpoint in several Mibo IP camera models that let anyone on the local network repeatedly force cameras offline. Users should update to firmware R.260804 to mitigate the denial-of-service flaw.
KEY POINTS
  • 01Researchers identified an unauthenticated firmware-update endpoint in Intelbras IP camera firmware that could be used by someone on the local Wi-Fi network to force a camera offline.
  • 02The issue affected firmware v240927 on the Intelbras iM3B-C and, according to Intelbras, the same firmware was compatible with the iMX C, iM4 C, iM5 SC, iME 360 C, and iM7+ FC models.
  • 03Sending a firmware upload request triggered the camera reboot process even when the supplied firmware was not valid, and periodic requests could keep the device offline indefinitely.
  • 04Intelbras released firmware R.260804, which adds checks for authentication session and cookie data before allowing firmware updates through the affected endpoint.
  • 05MITRE assigned the issue candidate ID CAN-2026-2035970 and classified it as medium severity with a CVSS 4.0 score of 5.1, pending final CVE assignment.

Researchers identified a denial-of-service flaw in Intelbras IP cameras that allowed an unauthenticated person on the local Wi-Fi network to force a camera offline. The issue was in the /firmwareUpgrade_service/Demo firmware-update endpoint, which accepted requests without checking authentication. A single request disrupted a camera for about a minute, while repeated requests could keep it unavailable indefinitely.

The affected firmware initiated a reboot process before verifying that the uploaded firmware was valid, so even an invalid firmware file could cause disruption. The research used an iM3B-C camera running firmware v240927, and Intelbras said the same firmware was compatible with iMX C, iM4 C, iM5 SC, iME 360 C, and iM7+ FC models. Intelbras released firmware R.260804, which requires authentication checks for the endpoint, and users are advised to update because the flaw can prevent access to live monitoring and camera management.

  • The camera’s normal management functions required an authenticated session, but the firmware-update route bypassed those checks entirely in the affected firmware.
  • The endpoint initiated a reboot before confirming that the uploaded firmware was legitimate, so even an invalid file could disrupt the camera.
  • Although one request took a camera offline for only about a minute, repeated requests could maintain the outage indefinitely.
  • Because the same affected firmware was compatible with multiple Intelbras camera models, a single firmware-level flaw extended beyond the iM3B-C model used in the demonstration.

Researchers found that some Intelbras internet-connected cameras could be forced offline by anyone connected to the same local Wi-Fi network, without needing a password. The problem affected several Mibo camera models and could be repeated to keep a camera unavailable, preventing owners from watching live video or managing it. This matters because these cameras are used to monitor homes and businesses, and the related Mibo Smart app has more than four million downloads, mainly in Brazil and other South American countries. Intelbras released updated firmware that fixes the issue.

OPEN SOURCE ↗

This is a concrete, technically detailed disclosure of a patched local-network denial-of-service flaw affecting multiple Intelbras IP camera models. It has meaningful operational impact for affected camera owners, but the issue is medium severity, requires local Wi-Fi access, and has already been fixed in updated firmware.
