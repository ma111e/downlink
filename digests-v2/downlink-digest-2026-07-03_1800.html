Unpatched Flaws Disclosed in Filesystem Bundled Into Millions of Embedded Devices

runZero disclosed seven unpatched FatFs vulnerabilities affecting millions of embedded devices, where malicious USB drives, SD cards, or firmware images could cause memory corruption, code execution, crashes, or data leaks. With no upstream fixes for most flaws, vendors using FatFs must audit and patch their own firmware while users restrict physical media access and watch for updates.
KEY POINTS
  • 01runZero disclosed seven vulnerabilities in FatFs, a small filesystem library used to read and write FAT and exFAT formats on USB drives and SD cards.
  • 02The vulnerabilities can be triggered by deliberately malformed storage volumes or firmware images, and the worst cases can cause memory corruption and possible code execution on affected embedded devices.
  • 03runZero named affected platforms including Espressif ESP-IDF, STMicroelectronics STM32Cube, Zephyr, MicroPython, ArduPilot, RT-Thread, Mbed, Samsung TizenRT, and SWUpdate.
  • 04Only CVE-2026-6684, a malformed GPT partition table hang, is fixed upstream in FatFs R0.16, while runZero says there is no upstream fix for the memory-corruption bugs.
  • 05runZero said no attacks using these bugs had been reported as of its July 1 disclosure, but it published proof-of-concept disk images, a test harness, and a QEMU-based exploit example.

runZero disclosed seven vulnerabilities in FatFs, a small filesystem library used by devices to read and write FAT and exFAT formats on USB drives and SD cards. The library is bundled into firmware for many embedded devices, including security cameras, drones, industrial controllers, hardware crypto wallets, and other devices built on real-time operating systems. The flaws can be triggered when a device reads a deliberately malformed storage volume or firmware image.

The most serious issues can corrupt memory and potentially allow code execution on affected systems, especially where devices lack the memory protections common on phones and desktops. The highest-ranked flaw is CVE-2026-6682, an integer overflow in FAT32 mounting that can create a false file size later used as a read length. Other issues include an exFAT volume-label buffer overflow, long-filename handling problems in wrapper code, a cache-handling math wrap, an exFAT divide-by-zero, a data leak from extended files, and a malformed GPT partition-table hang.

Only CVE-2026-6684, the malformed GPT hang, is fixed upstream in FatFs R0.16, while runZero says there is no upstream fix for the memory-corruption bugs. runZero named affected platforms including Espressif ESP-IDF, STMicroelectronics STM32Cube, Zephyr, MicroPython, ArduPilot, RT-Thread, Mbed, Samsung TizenRT, and SWUpdate. As of the July 1 disclosure, no attacks using these bugs had been reported, but runZero published proof-of-concept disk images, a test harness, and a QEMU-based exploit example.

  • Some of the FatFs flaws are not limited to removable media, because CVE-2026-6682 and CVE-2026-6683 are also reachable through certain firmware update flows.
  • The article highlights wrapper code around FatFs as a specific risk area, especially long-filename handling such as copying fno.fname into a fixed buffer with strcpy.
  • Updating to FatFs R0.16 only addresses the malformed GPT partition table hang, so downstream vendors still need their own fixes for the remaining memory-corruption issues.
  • runZero found bugs in 2026 using an off-the-shelf AI-assisted fuzzing setup after a 2017 manual audit found little worth reporting, showing that newer automated approaches can expose issues missed by earlier review.
  • The lack of a responsive upstream maintainer, security mailing list, or broad notification mechanism makes remediation dependent on downstream vendors across many embedded platforms.

Researchers at runZero found seven flaws in FatFs, a small file-reading component used inside many devices such as security cameras, drones, industrial controllers, hardware crypto wallets, kiosks, ATMs, and voting machines. If someone gets a specially prepared USB drive, SD card, or update file onto some of these devices, the device may crash, leak old data, or even let that person take control of it. This matters because FatFs is built into many products, most of the flaws do not yet have a central fix, and updates may take years to reach real-world devices.

New "Bad Epoll" Linux Kernel Flaw Lets Unprivileged Users Gain Root, Hits Android

A newly disclosed Linux kernel use-after-free flaw called Bad Epoll (CVE-2026-46242) can let unprivileged users gain root on Linux systems and may affect Android, with no workaround besides applying the kernel fix. The bug is difficult but highly reliable in the published proof-of-concept, and there is no evidence yet of real-world exploitation.
KEY POINTS
  • 01Bad Epoll (CVE-2026-46242) is a newly disclosed Linux kernel use-after-free flaw that lets an unprivileged user gain root access on affected Linux desktops, servers, and Android systems.
  • 02Researcher Jaeyoung Chung found Bad Epoll, submitted it as a zero-day to Google's kernelCTF program, and built a proof-of-concept exploit that reached root about 99% of the time on tested systems.
  • 03The flaw can reportedly be triggered from inside Chrome's renderer sandbox and can reach Android, which the article says makes it more dangerous than many other Linux privilege bugs.
  • 04There is no sign Bad Epoll has been used in real attacks, and as of the article's writing it was not listed in CISA's Known Exploited Vulnerabilities catalog.
  • 05There is no workaround because epoll cannot be turned off, so affected users should apply upstream commit a6dc643c6931 or install their distribution's backported fix when available.

A newly disclosed Linux kernel flaw called Bad Epoll (CVE-2026-46242) can let an ordinary unprivileged user gain root access on affected systems. The article says it affects Linux desktops, servers, and Android, and that a fix is available. Researcher Jaeyoung Chung found the flaw, submitted it to Google’s kernelCTF program, and published technical details.

Bad Epoll is a use-after-free bug in epoll, a standard Linux feature used by servers, network services, and web browsers to watch many files or network connections at once. The bug happens when two parts of the kernel try to clean up the same internal object at the same time, allowing memory corruption. Chung’s exploit reportedly widens a very small timing window and reached root about 99% of the time on tested systems.

The article says the flaw is more dangerous because it can reportedly be triggered from inside Chrome’s renderer sandbox and can reach Android, though an Android version of the exploit is still in progress. There is no sign it has been used in real attacks, and it was not on CISA’s Known Exploited Vulnerabilities list at the time of writing. Epoll cannot be turned off, so the article says affected users should apply upstream commit a6dc643c6931 or install their distribution’s backported fix when it becomes available.

  • Bad Epoll sits in the same small section of kernel code as another bug found by Anthropic's Mythos, showing that even a leading AI model can find one race-condition flaw while missing a closely related one.
  • The exploit is notable because the race window is only about six machine instructions wide, yet Chung's technique reportedly widens the window and retries without crashing to reach about 99% reliability on tested systems.
  • Bad Epoll usually does not trigger KASAN after the first related bug is patched, meaning the kernel's main bug detector may not flag the remaining memory error.
  • The affected code was introduced in Linux 6.4, so some older 6.1-based kernels, including some Android phones such as the Pixel 8, are not affected.
  • Because epoll is a standard feature used by servers, network services, and web browsers, the article says it cannot simply be disabled as a workaround.

The article is about a newly disclosed Linux problem called Bad Epoll that can let someone with a normal account take full control of a computer or device as the top-level user. It affects Linux desktops and servers, and may also affect Android, though some older 6.1-based Android kernels such as the Pixel 8 are not affected. This matters because Linux is widely used and the feature involved cannot simply be turned off, so the real fix is to install the updated kernel when it is available.

Even though there is no evidence of real-world exploitation, the combination of broad exposure, root access impact, and no workaround makes it a must-read for security professionals.

New Avalon Malware Framework Packs CrownX Ransomware Capabilities

Researchers uncovered Avalon, a previously undocumented modular malware framework delivered through a phishing chain that can steal credentials, evade defenses, move laterally, disrupt recovery, and deploy its CrownX ransomware component. The case highlights how AI-assisted development is making complex ransomware tooling more accessible to less sophisticated attackers.
KEY POINTS
  • 01Cybersecurity researchers discovered a previously undocumented modular malware framework called Avalon that is distributed through a multi-stage phishing chain using a spoofed legal document email and a password-protected Proton Drive archive.
  • 02Avalon combines credential collection, lateral movement, remote access, recovery disruption, and ransomware execution, with its ransomware component internally named CrownX.
  • 03The attack chain uses an ISO image containing a document-themed Windows Shortcut that launches an MSBuild project, which loads an embedded .NET assembly and downloads a next-stage payload over HTTPS.
  • 04Avalon includes defense evasion capabilities aimed at reducing telemetry and hiding execution from security tools including Microsoft Defender, SentinelOne, CrowdStrike, Sophos, Elastic Endpoint, FortiEDR, ESET, McAfee, and Bitdefender.
  • 05Blackpoint Cyber said Avalon shows signs of AI-assisted development, while the article also describes separate research on an LLM-driven agentic ransomware infection and an AI malware that converts Telegram messages into shell commands through a public LLM API.

Cybersecurity researchers discovered a previously undocumented modular malware framework called Avalon that is distributed through a multi-stage phishing chain designed to bypass traditional security controls. The attack begins with a spoofed legal document email that directs recipients to a password-protected archive on Proton Drive. If the recipient opens the document-themed Windows Shortcut inside the mounted ISO image, it triggers a staged malware sequence that ultimately deploys Avalon.

Avalon combines credential collection, lateral movement, remote access, recovery disruption, and ransomware execution, with its ransomware component internally named CrownX. The framework can harvest browser data, cryptocurrency wallet data, messaging and collaboration app data, VPN-related data, Windows Credential Manager contents, SSH known hosts, saved RDP connections, Wi-Fi profiles, and Group Policy Preferences cpassword artifacts. It can also exfiltrate data to a remote server, poll for tasking commands, encrypt business and infrastructure-related files, delete shadow copies, and interact directly with disk structures in ways that could render a system unusable.

Blackpoint Cyber said Avalon shows signs of AI-assisted development and argued that the presence of extensive capabilities is no longer a reliable indicator of a threat actor’s sophistication or maturity. The article also describes separate research from Sysdig on an LLM-driven agentic ransomware infection tied to JADEPUFFER, as well as Unit 42 findings on AI malware that uses Telegram and a public LLM API to turn plain-language attacker instructions into shell commands. Together, these findings highlight how AI can lower the barrier to creating and operating damaging malware tools.

  • Avalon’s use of an ISO image and a password-protected Proton Drive archive shows the phishing chain was designed to reduce detection before the malware ever reached endpoint defenses.
  • The article cautions that the presence of advanced capabilities, such as ransomware execution, recovery disruption, and defense evasion, is no longer a reliable sign that the operator is highly sophisticated because Avalon shows signs of AI-assisted development.
  • CrownX was only the final extortion stage, meaning victims may already have suffered credential theft, command-and-control communication, lateral movement preparation, and weakened recovery options before the ransom note appears.
  • The separate JADEPUFFER case shows that a large language model was reportedly able to retry and adjust actions in real time during a ransomware operation, lowering the skill needed to run such attacks.
  • The Telegram-and-LLM malware demonstrates that an attacker can issue plain-language instructions instead of knowing shell commands, with the public LLM API translating those instructions into commands executed on the victim system.

Researchers found a new harmful software package called Avalon that is spread through fake legal-document emails and can steal saved logins, collect app and wallet data, spread inside a victim’s network, block recovery, and lock files for ransom using a part called CrownX. People and organizations that open the fake document can be affected, especially businesses because the software targets work files, development files, data storage, and virtual systems. The article matters because it shows that tools helped by artificial intelligence may let less skilled criminals build damaging attacks more easily and cheaply.
