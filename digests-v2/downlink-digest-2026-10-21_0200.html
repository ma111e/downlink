Operation FlashHole: Lazarus breaks security, defies control

Kaspersky reports that Lazarus Group’s Operation FlashHole targeted South Korean organizations by abusing mandatory CrossWeb EX security software and tailored phishing sites to deliver a highly modular, largely memory-resident malware chain. The campaign combines updated TechHub, Cubridge, TouchShift, ClientHub, and LPEClient tooling with GitHub- and compromised-site-based C2 infrastructure for espionage and payload delivery.
KEY POINTS
  • 01Kaspersky identified Operation FlashHole as a Lazarus Group campaign targeting at least three South Korean organizations in the software, construction, and wired communication equipment sectors.
  • 02The campaign used tailored phishing links to GitHub Pages sites posing as a job résumé or interior design portfolio, with evidence suggesting the lure content included AI-generated material.
  • 03The infection chain abused the South Korean financial-security software CrossWeb EX and executed much of its malware chain in memory to reduce traces on disk.
  • 04The operation used updated and newly identified malware including TechHub, Cubridge, TouchHub, TouchShift, ClientHub, and LPEClient, with GitHub repositories and compromised South Korean websites used for command-and-control communications.
  • 05Kaspersky assessed with medium-to-high confidence that Operation FlashHole is the latest wave of the broader Cascade Hole campaign and is linked to Lazarus Group activity.

Kaspersky describes Operation FlashHole, a Lazarus Group campaign that targeted at least three South Korean organizations in the software, construction, and wired communication equipment sectors. The earliest evidence dates to July 2025, and the campaign followed Operation SyncHole while expanding into different industries. Researchers assess with medium-to-high confidence that targets received spear-phishing emails linking to tailored GitHub Pages sites posing as a job seeker’s résumé or an interior design portfolio. The sites contained external malicious JavaScript and may have initiated infection involving the mandatory financial-security product CrossWeb EX.

The infection chain executed fsquirt.exe under the CrossWeb EX service process and injected shellcode containing TechHub, with much of the initial chain existing only in memory. TechHub used private GitHub repositories for command-and-control communication, while later payloads included Cubridge, TouchHub, TouchShift, ClientHub, and LPEClient. Persistence involved DLL side-loading through a malicious mscoree.dll and a service created from a legitimate Windows executable, allowing TouchShift to run with SYSTEM privileges. Cubridge and ClientHub could load tools and plugins for activities including process and browser-data collection, Active Directory queries, file collection and archiving, file deletion, and remote-session monitoring.

The article highlights LPEClient as a longstanding Lazarus tool that was substantially updated to profile systems, inspect patch and security-mitigation status, and receive payloads through ClientHub. Its communication used several cryptographic methods, including ML-KEM-1024 post-quantum key encapsulation, GOST, and Threefish, before reflectively loading Cubridge in memory. Kaspersky links FlashHole to the broader Cascade Hole campaign and to Lazarus’s Dream Job-related toolsets, while distinguishing it from concurrent COPPERHEDGE activity associated with ransomware and data exfiltration. The researchers expect attacks abusing South Korea’s mandatory security software to remain active until that software is eliminated or mitigated.

  • The attackers used private GitHub repositories as a command-and-control channel, with TechHub creating and updating GitHub issues and exchanging encrypted files through repository filenames and content.
  • Much of the initial infection chain operated only in memory, while the few persistent files were disguised through DLL side-loading and legitimate Windows binaries running as services with SYSTEM privileges.
  • LPEClient’s updated version checks Windows patch-level information and low-level security protections, including Kernel VA Shadow and Shadow Stack status, before receiving later-stage payloads.
  • The campaign used several cryptographic methods, including ML-KEM-1024 post-quantum key encapsulation, to protect payload delivery; Kaspersky noted that this adoption outpaced many legitimate security products.
  • South Korea’s plan to phase out mandatory security-software installation beginning in 2026 may leave the currently installed software an attractive attack route until it is eliminated or mitigated.

The Lazarus Group, a suspected North Korean-linked hacking group, used convincing fake job résumé and design websites to target at least three South Korean companies in software, construction, and communications equipment. Visiting the sites may have abused a commonly required South Korean banking and government security program, allowing the attackers to secretly install tools that can gather information, steal browser data, and control infected computers. This matters because the campaign shows how widely installed security software can become a gateway for espionage, and the attackers are rapidly improving and reusing their tools across multiple campaigns.

vlt 1.5.0 Adds Agent Skills Management

vlt 1.5.0 adds opt-in agent-skill management, allowing developers to link coding-agent instructions from installed package dependencies and keep them synchronized with lockfile-pinned versions. It also uses Socket security data to exclude skills from packages flagged as malware or other security risks.
KEY POINTS
  • 01vlt 1.5.0 introduces the vlt skills command, which finds agent instruction folders in installed dependencies and links selected skills into directories used by coding agents.
  • 02Skill selections are saved as allow-skills in vlt.json, allowing subsequent installs, updates, and vlt ci to maintain the configured links.
  • 03By default, vlt links skills into .agents/skills and can also use existing agent-specific folders such as .claude/skills.
  • 04When no selection is saved, vlt skills link excludes packages flagged as malware by Socket’s high-confidence alerts.
  • 05pnpm 12.11.0 also added support for linking skills from approved direct dependencies, indicating that JavaScript package managers are adding management of coding-agent instructions.

vlt 1.5.0 introduces vlt skills, a command that discovers coding-agent instruction folders in installed JavaScript dependencies and links selected skills into project directories read by agents. Developers install a package, list its available skills, and select which ones to link. The chosen skills are tied to the dependency version in the project’s lockfile, so dependency updates also update the linked instructions. Selections are stored as allow-skills in vlt.json and are maintained by subsequent installs, updates, and vlt ci.

By default, vlt uses .agents/skills and can also link into detected agent-specific directories, including .claude/skills; destinations can be changed with skills-dir. Developers can select individual skills through the :skill() selector rather than linking every skill from a package. Linking is opt-in, and when no selection has been saved, vlt skills link excludes packages marked as malware by Socket’s high-confidence alerts. Teams can also use Socket-powered rules to exclude packages flagged for typosquatting, vulnerabilities, or obfuscated code before their instructions are made available to coding agents.

  • vlt treats installing a package and making its instructions available to a coding agent as separate decisions, so package-provided guidance is not automatically exposed to agents.
  • Because linked skills come from the dependency version recorded in the lockfile, updating a dependency also updates the instructions associated with that specific version without manually copying files.
  • Teams can apply Socket-based rules beyond malware, such as excluding packages flagged for typosquatting, vulnerabilities, or obfuscated code before those packages can supply agent instructions.
  • The :skill() selector allows developers to approve individual instruction sets within a package rather than accepting every skill the package includes.

vlt 1.5.0 lets software developers choose and automatically keep up to date the instruction files that installed JavaScript packages provide for coding assistants. This matters because those instructions can shape what an assistant does, so vlt lets teams avoid instructions from packages flagged as harmful and set rules for which packages may provide them. The change affects developers and teams using JavaScript packages and coding assistants, as package managers increasingly become responsible for controlling what instructions reach those assistants.

OPEN SOURCE ↗

This is a specific product release with relevant supply-chain security implications, as it adds controls for which dependency-provided instructions reach coding agents. It is not an urgent incident or advisory, but security professionals working with JavaScript development environments may find the Socket-based filtering and opt-in linking model useful.
