Cursor confirms security breach led to malicious Claude Code extension

Cursor confirmed that attackers used credentials exposed through Fireworks AI and leaked coding-agent traces to access internal systems and publish trojanized Claude Code extensions that attempted to install persistent SSH backdoors. Up to 5,000 developers may have downloaded the malicious builds during their roughly 11-hour availability window.
KEY POINTS
  • 01Cursor said attackers obtained an access key stored on Fireworks AI and used it to copy data from a read-only storage bucket shared with the provider.
  • 02Historical AI coding-agent traces in the bucket included unredacted API credentials in some cases, which attackers used to access additional Cursor systems and data from several SaaS tools.
  • 03On October 29, attackers used a stolen credential to publish malicious versions 2.1.312 and 2.1.313 of Anthropic's Claude Code extension through Cursor's marketplace cache.
  • 04The malicious extensions were available for about 11 hours and attempted to install persistent SSH backdoors, with Cursor estimating that up to 5,000 users may have received them.
  • 05Cursor said it revoked and rotated exposed credentials, moved inference traffic away from Fireworks, rebuilt its extension marketplace, and redeployed production infrastructure.

Cursor confirmed that attackers obtained an access key stored on AI infrastructure provider Fireworks AI and used it to copy data from a read-only storage bucket shared between the companies. The bucket held historical AI coding-agent traces from users who had not enabled Privacy Mode, and some traces contained unredacted API credentials. Attackers used those credentials to access additional Cursor systems and steal information from several SaaS tools, including archived non-production source code, support information, usage data, and some customer-shared credentials.

On October 29, the attackers used a stolen credential to publish malicious copies of Anthropic’s Claude Code extension, versions 2.1.312 and 2.1.313, through the cache serving Cursor’s VS Code extension marketplace. The altered extensions were available for about 11 hours and attempted to collect system information, install attacker-controlled SSH keys, enable remote SSH access, and remain on affected computers. Cursor estimates that up to 5,000 users may have received the malicious builds, although researchers found coding errors that likely prevented the backdoor from working on many Windows and macOS systems where SSH was not already enabled.

Cursor said fewer than 0.05% of users had coding-agent traces exposed and fewer than 0.01% of customers had API credentials compromised. It said its production infrastructure, official application releases, customer code repositories, and code and prompts from Privacy Mode users were not affected. Cursor revoked and rotated exposed credentials, moved inference traffic away from Fireworks, rebuilt its extension marketplace, redeployed production infrastructure, and advised affected extension users to follow its remediation guidance.

  • The exposure was limited to users who had not enabled Privacy Mode, while Cursor said code and prompts from Privacy Mode users were not affected.
  • The attackers did not compromise Anthropic’s legitimate Claude Code extension or the Open VSX marketplace; they placed altered copies directly in the cache serving Cursor’s extension marketplace.
  • The malicious extension’s coding errors likely stopped the SSH backdoor from working on many Windows and macOS computers where SSH was not already enabled, but the extensions still attempted to collect system information and establish persistence.
  • Credentials previously shared with Cursor’s support team were among the data taken from Cursor’s SaaS tools, showing that support communications were within the scope of the incident.
  • Cursor linked the incident to a broader October pattern in which stolen AI-service credentials were used for unauthorized model usage, including incidents that generated substantial customer charges.

Cursor says attackers gained access after obtaining a key from Fireworks AI and then used customer data that included some unhidden passwords and access keys to reach more of Cursor’s systems. They placed fake versions of Anthropic’s Claude Code add-on in Cursor’s software marketplace, potentially exposing up to 5,000 developers to software designed to give the attackers remote access to their computers. The incident shows how one stolen access key and sensitive information left in user activity records can spread from one company to many users and services, causing data exposure, unwanted access, and potentially costly misuse of AI services.

US disrupts North Korean campaign behind $400 million crypto theft

U.S. authorities disrupted FaceStealer, a BlueNoroff-linked North Korean social-engineering campaign that used deepfake video meetings and fake technical fixes to steal more than $400 million in cryptocurrency and compromise crypto professionals and open-source developers.
KEY POINTS
  • 01The U.S. government disrupted the cloud-based infrastructure behind FaceStealer, an 18-month North Korean social-engineering campaign linked by researchers to the BlueNoroff group that stole more than $400 million in cryptocurrency.
  • 02FaceStealer operators hijacked Telegram, LinkedIn, Slack, and Discord accounts to invite targets to fake video meetings, where they used recorded footage of people known to the target and then presented a fake technical error.
  • 03Victims who followed links for supposed updates or installers were infected with software that could steal cryptocurrency data, meeting-platform credentials, contact lists, social-media and communication-app access, and webcam recordings.
  • 04Researchers identified 677 targets in 58 countries, primarily company founders and senior executives, while the FBI also confirmed attempts against developers in the npm and Rust crate ecosystems.
  • 05The U.S. Justice Department said that the government and private-sector companies froze more than $2.7 billion connected to the $6.4 billion Binance crypto heist, with court authorization obtained to seize or restrain more than $1.2 billion.

The U.S. government disrupted cloud-based infrastructure used by FaceStealer, an 18-month North Korean social-engineering campaign that stole more than $400 million in cryptocurrency. Researchers attributed the activity to the BlueNoroff group, and the FBI said the operation targeted people in cryptocurrency and Web3 roles as well as open-source developers. The campaign affected targets worldwide, with Arctic Wolf identifying 677 targets across 58 countries, especially founders and senior executives.

The attackers hijacked accounts on Telegram, LinkedIn, Slack, and Discord to invite targets to fake video meetings, using recorded footage of familiar people to make the meetings appear credible. They then claimed a technical problem and directed victims to a supposed update, installer, or other fix that installed software capable of stealing cryptocurrency data, meeting-platform credentials, contacts, communications access, and webcam recordings. The FBI also described attempts against npm and Rust crate developers, including a thwarted effort against a maintainer of a popular JavaScript library with tens of millions of weekly downloads.

  • The operators sometimes waited months or more than a year after compromising someone before targeting them further, apparently allowing cryptocurrency holdings to grow first.
  • The campaign turned victims into convincing lures by secretly recording their webcam footage and replaying it during later fake meetings with people who knew them.
  • The FBI described a thwarted attempt against the maintainer of a widely used JavaScript library, showing that a single targeted developer could have affected software used by tens of millions of people each week.
  • The article’s recommended defenses are practical behavioral checks: join meetings through official apps with an invite code, independently verify unexpected invitations, keep webcams off unless needed, and do not run scripts presented as technical fixes.

The U.S. government shut down online infrastructure used in an 18-month North Korean fraud campaign that stole more than $400 million in cryptocurrency. The criminals tricked cryptocurrency workers, company leaders, and open-source software developers into fake video meetings, sometimes using recordings of people the targets knew, then persuaded them to install a supposed technical fix that gave the criminals access to their accounts and digital wallets. This matters because the scheme could harm not only individual victims but also widely used software projects and the many people and companies that depend on them.

Its use of hijacked trusted accounts, convincing fake video meetings, and malicious “fixes” has broad relevance, including potential software supply-chain impact.

Attackers Exploit UnrealIRCd Flaw That Enables Server-Level Command Injection

CISA added CVE-2026-114713, a critical UnrealIRCd flaw actively exploited to inject server-to-server commands with server-level privileges, to its Known Exploited Vulnerabilities catalog. Organizations should urgently upgrade to UnrealIRCd 6.2.7.1 or apply the available workaround.
KEY POINTS
  • 01CISA added CVE-2026-114713, an actively exploited high-severity UnrealIRCd flaw, to its Known Exploited Vulnerabilities catalog.
  • 02The flaw affects UnrealIRCd versions 6.0.0 through versions before 6.2.7.1 and can allow users to inject server-to-server commands with server-level privileges on networks with at least two linked servers.
  • 03UnrealIRCd released version 6.2.7.1 to address CVE-2026-114713 and other security issues.
  • 04The UnrealIRCd maintainer said exploitation began a day after the November 7, 2026 hotfix release and described it as the project’s most critical issue in 15 years.
  • 05Federal Civilian Executive Branch agencies must apply fixes by November 16, 2026 under Binding Operational Directive 26-04.

CISA added CVE-2026-114713, a high-severity flaw in the open-source UnrealIRCd IRC server, to its Known Exploited Vulnerabilities catalog after reports of active exploitation. The issue has a CVSS score of 8.6 and affects UnrealIRCd versions 6.0.0 through versions before 6.2.7.1. CISA’s addition means Federal Civilian Executive Branch agencies must apply fixes by November 16, 2026 under Binding Operational Directive 26-04.

The vulnerable labeled-response module does not safely handle the IRCv3 “label” message tag when echoing it in replies. On networks with two or more linked servers, this can allow any user to inject server-to-server commands that run with server or IRC operator privileges. UnrealIRCd released version 6.2.7.1 to fix the issue, and maintainer Bram Matthys warned that attackers began exploiting it a day after the November 7, 2026 hotfix release. He called it the most critical issue found in UnrealIRCd over the past 15 years and urged administrators to update, hot-patch, or deploy the stated spamfilter workaround.

  • The flaw can be triggered by any user rather than requiring administrator access, but only on UnrealIRCd networks with two or more linked servers.
  • The vulnerable labeled-response feature fails to safely handle a message label when it is copied into replies, allowing crafted input to be interpreted as server commands.
  • Active exploitation reportedly began one day after the November 7, 2026 hotfix was released, making rapid patching or use of the stated workaround especially urgent.
  • CISA gave federal civilian agencies until November 16, 2026 to remediate the issue after adding it to its Known Exploited Vulnerabilities catalog on November 13.

U.S. cybersecurity officials warned that criminals are actively abusing a serious flaw in UnrealIRCd, software used to run Internet Relay Chat servers. The flaw can let an ordinary user send commands that the server treats as if they came from an administrator, potentially giving them control over affected servers. Server operators should install UnrealIRCd version 6.2.7.1 or use the temporary workaround, because the problem is already being used in attacks.

Fake Purview Card: Three Footer Links, One Tutorial Page

A phishing email convincingly impersonated Microsoft Purview Message Encryption, but its Read the message button and legal footer links all led to the same newly created tutorial-hosted page. The key lesson is to hover footer links as well as action buttons: a genuine Purview message routes them to distinct Microsoft destinations.
KEY POINTS
  • 01A counterfeit Microsoft Purview Message Encryption email reached four employees at a manufacturer, including the Italian general manager.
  • 02The email's Read the message button, Privacy Statement link, and Learn More link all led to the same page on a public tutorial-builder site, unlike a genuine Purview wrapper.
  • 03The message passed SPF, DKIM, DMARC, and ARC checks because it was sent from the sender organization's authenticated Microsoft 365 tenant.
  • 04The linked tutorial page displayed an Italian fake protected-file notice and a document-viewing button, and it was created about two days before capture.
  • 05A human analyst classified the email as malicious and quarantined all four affected mailboxes.

A counterfeit Microsoft Purview Message Encryption email was delivered to four employees at a manufacturer of caravan and recreational-vehicle components, including the Italian general manager. It mimicked a protected-message card with a Microsoft-hosted lock icon, Purview wording, and a Redmond address in the footer. A human analyst classified the messages as malicious, and all four affected mailboxes were quarantined.

The Read the message button, Privacy Statement link, and Learn More link all resolved to one public tutorial-builder page rather than separate destinations expected in a genuine Purview wrapper. The underlying destination appeared only in the platform’s preserved original-URL field because delivered links had been rewritten by receiver-side security controls. The hosted page displayed an Italian fake protected-file lure and had reportedly been created about two days earlier; the article does not establish what occurred after a recipient selected its document-viewing button.

The email passed SPF, DKIM, DMARC, and ARC checks because it was sent through the sender organization’s authenticated Microsoft 365 tenant, while link reputation checks rated the tutorial-hosted URLs clean. An unrelated Italian business thread from 2016 appeared beneath the card under a subject referring to a proposal, creating another mismatch with the protected-message notice. The article’s practical lesson is to hover the privacy and help links, not only the main action button, because matching links to a non-Microsoft host can reveal a fake Purview message.

  • Authentication checks can confirm that an email was sent through an authorized system without confirming that its content or destination is trustworthy, as this message passed SPF, DKIM, DMARC, and ARC validation.
  • A clean reputation result was not useful here because the destination was a long-lived, legitimate tutorial platform being abused to host a user-created lure rather than an attacker-owned domain.
  • Comparing the intended roles of links can expose impersonation: the primary action button, privacy notice, and help link should not all resolve to one non-Microsoft destination in a genuine Purview message.
  • The unrelated 2016 business thread and the subject line referring to a proposal provided a second structural inconsistency with the protected-message card.

Four employees at a manufacturer, including its Italian general manager, received an email made to look like a protected Microsoft message. Although the email came through a legitimate Microsoft 365 account and its links were not flagged as dangerous, the main button and the small privacy and help links all led to the same fake page hosted on a public tutorial website. This matters because convincing scams can use trusted-looking services and clean links to trick people into opening fake documents or giving away information, so checking where even small footer links lead can reveal the deception.

ESLint Ends Paid Contributor Program as AI Upends Open Source Collaboration

ESLint has ended its five-year paid contributor program after AI-generated pull requests and disputes over disclosure made it too burdensome to determine which work deserved compensation. The move reflects a broader open-source shift toward stricter contribution controls as maintainers struggle with AI-driven review volume and low-quality submissions.
KEY POINTS
  • 01ESLint ended its paid contributor pool after five years, citing the difficulty of handling AI-generated issues and pull requests and disputes over undisclosed AI use.
  • 02From 2022 through 2025, ESLint paid outside contributors $51,180 through the program, including $24,680 in 2025.
  • 03ESLint still permits AI-assisted contributions when their use is disclosed, the contributor reviews the work, and the contributor remains responsible for the submission.
  • 04Several open-source projects, including Godot, LLVM, tldraw, Node.js, and the Linux kernel, have introduced restrictions or additional requirements in response to the review burden created by AI-generated submissions.
  • 05A Linux Foundation study published in October found that 59% of surveyed maintainers reported growing generative-AI-related contributions, while respondents estimated that 25% of incoming pull requests were low-quality AI-generated submissions.

ESLint has ended its paid contributor pool after five years, citing the difficulty of administering payments amid a growing volume of AI-generated issues and pull requests. The program paid outside contributors more than \(51,000 from 2022 through 2025, including \)24,680 in 2025, and helped recruit several people who later joined the team. ESLint said the decision was not driven by expense, but by disputes over undisclosed AI use and the growing difficulty of determining whether work was primarily created by a person or an AI tool.

ESLint still permits AI-assisted contributions when contributors disclose the use of AI, review the resulting work, and accept responsibility for it, but AI-generated pull requests must address issues explicitly accepted by the team. Other projects, including Rust, Godot, LLVM, Node.js, tldraw, the Linux kernel, and curl, have imposed new restrictions or changed their processes as AI-assisted submissions increase review workloads. The article warns that while tighter controls can reduce low-quality or irrelevant submissions, they may also limit opportunities for newcomers to learn, build relationships with maintainers, and become future project contributors.

  • AI has changed the practical value of a polished pull request because it may no longer show that its author understands the codebase or will be able to maintain the change after it is accepted.
  • At tldraw, one AI system generated inaccurate tasks from vague notes while other AI systems produced seemingly valid fixes for those tasks, showing that code can pass tests while solving a problem the project never intended to address.
  • LLVM excludes AI tools from work labeled "good first issue" because those tasks are intended to help newcomers learn the codebase rather than simply produce a completed change.
  • ESLint’s contributor-payment model became difficult to operate not because it was too expensive, but because maintainers could no longer reliably determine whether paid work was primarily produced by a person or by AI assistance.
  • Some projects are limiting outside pull requests even though those contributions have historically been a way to mentor newcomers and recruit future maintainers.

ESLint, a widely used software project, has stopped paying outside contributors because AI tools made it much easier to send in large numbers of code changes while making it harder to tell how much work a person actually did. The project’s maintainers and contributors are affected, along with other open-source communities such as Rust, Godot, LLVM, Node.js, Linux, tldraw, and curl that are facing more low-quality or unnecessary submissions. This matters because volunteers who maintain shared software can become overwhelmed reviewing changes, and limiting outside contributions may also make it harder for new people to learn and eventually help run these projects.
