Northflank security breach leads to abuse of customers' AI API keys

Northflank says a security breach may have exposed and decrypted customer environment variables, with reports of attackers abusing stored AI API keys. Customers should immediately rotate all secrets and review AI-provider usage and billing for unauthorized activity.
KEY POINTS
  • 01Northflank warned customers to assume that environment variables stored on its platform had been decrypted and to rotate all credentials and secrets immediately.
  • 02Multiple Northflank customers reported unauthorized use of AI API keys that they had supplied to the platform.
  • 03Northflank enabled credential rotation for PostgreSQL, MongoDB, MySQL, and Redis, and enabled audit logs for all customers, including free accounts.
  • 04Wiz warned Northflank about the incident on October 30, and Northflank subsequently applied multiple network policy patches and sought Wiz incident-response assistance.
  • 05Wiz identified at least nine security incidents affecting AI development platforms during October, with attackers often seeking environment variables containing AI service credentials.

Northflank disclosed a security incident after Wiz alerted it on October 30 and told customers to assume environment variables stored on the platform had been decrypted. The company urged customers to disable or rotate all stored keys and secrets, including those in workloads, secret groups, and global secrets. Multiple customers later reported unauthorized use of AI API keys they had provided to Northflank.

Environment variables can contain database passwords, cloud credentials, authentication tokens, and API keys, so exposure could enable access to other customer services or unauthorized charges. Northflank applied several network-policy patches, requested Wiz incident-response assistance, enabled rotation for PostgreSQL, MongoDB, MySQL, and Redis credentials, and made audit logs available to all customers. The company has not disclosed how attackers obtained access, how many customers were affected, or whether credentials beyond the reported AI API keys were stolen or abused.

  • The reported misuse of AI API keys can create direct financial harm because stolen keys may be used to generate large usage charges or resold for access to AI models.
  • Wiz documented two cases in which compromised enterprise credentials generated about 2.5 million Amazon Bedrock API calls and approximately $100,000 in AI usage.
  • Northflank made audit logs available to all customers, including free-account users, giving affected users a way to investigate suspicious activity.
  • Northflank reviewed Wiz’s warning one minute after receiving it and applied an initial network-policy patch shortly afterward, according to its incident timeline.

Northflank, a service companies use to run apps online, says a break-in may have exposed customers’ stored passwords, access keys, and other secret settings. Some customers have already reported that their paid AI service keys were used without permission, which can create unexpected bills and potentially let others access connected services. Northflank is telling customers to replace those secrets and check their AI-service activity, as similar incidents have recently targeted platforms that hold valuable AI access keys.

It is immediately actionable for Northflank customers and broadly relevant to teams that store AI-service credentials in cloud development platforms.

New Android SMS of Death exploit can remotely crash unpatched phones

A proof-of-concept for Android's "SMS of Death" flaw (CVE-2026-58882) can remotely crash unpatched phones and disrupt cellular and emergency calls using a malformed WAP Push data SMS. Users should install the latest Android security updates, as older Android 12 and 13 devices may remain vulnerable.
KEY POINTS
  • 01A proof-of-concept exploit for CVE-2026-58882 can cause unpatched Android phones to lose cellular service or crash when sent a specially crafted text message.
  • 02The flaw requires no interaction from the target and can interrupt active calls, including emergency calls, before the message appears in the SMS inbox.
  • 03The issue stems from improper validation in Android's WapPushOverSms.decodeWapPdu function, which can trigger a crash in the com.android.phone process.
  • 04Google reportedly fixed the flaw in its October 2026 Android security updates for Android 14 through 17, while Android 12 and 13 devices did not receive the fix.
  • 05Repeated delivery or processing of malicious messages can cause recurring crashes, and testing found that 20 messages could put some phones into reboot loops requiring a factory reset.

A security researcher released a proof-of-concept exploit for CVE-2026-58882, an Android flaw dubbed “SMS of Death.” A specially crafted data text message can remotely disrupt cellular service or crash unpatched phones without the recipient taking any action. The crash can interrupt ongoing calls, including emergency calls, and victims may not see the malicious message because Android processes it before it reaches the SMS inbox.

The flaw is caused by improper validation of a header-length value in Android’s WapPushOverSms.decodeWapPdu function. A malformed WAP Push message can produce a negative memory-allocation value and trigger a NegativeArraySizeException that crashes the com.android.phone process, which manages cellular functions. Google reportedly fixed the issue in October 2026 updates for Android 14 through 17, including measures to remove malicious messages from the SMS database, while Android 12 and 13 devices remain vulnerable because they did not receive the fix.

  • The malicious message is processed before it reaches the SMS inbox, so a victim may have no visible indication of what caused the phone to crash.
  • The flaw can disrupt emergency calls because the crashed com.android.phone process manages cellular functions.
  • Google's fix both catches the processing exceptions and removes malicious messages from the SMS database, helping prevent repeated crashes after a device restarts.
  • Although Android security updates are generally installed automatically on supported devices, availability depends on the device manufacturer and carrier, and a restart may be needed to complete installation.
  • An ADB-based method can remove malicious messages, but it requires a computer and advanced technical knowledge.

A researcher released a demonstration showing that a specially crafted text message can crash some Android phones without the owner doing anything. It can cut off mobile service and end calls, including emergency calls, and repeated messages may leave a phone restarting until it is reset. Google says it fixed the issue in updates for supported Android 14 through 17 devices, but older Android 12 and 13 phones may still be affected, so installing available updates is important.

OPEN SOURCE ↗

This is a concrete, high-impact Android denial-of-service finding with a public proof of concept that can remotely disrupt cellular and emergency calls on unpatched devices. It is especially relevant because older Android 12 and 13 devices reportedly remain without a fix, although the article does not report active exploitation in the wild.
