Microsoft shares workaround for Windows domain login issues

Microsoft confirmed that September 2026 Windows 11 security updates can break domain trust and prevent valid domain logins when Machine Identity Isolation enforcement is configured on unsupported domain environments. Administrators should disable the feature through its original management method, restart affected devices, and repair the secure channel while Microsoft develops a permanent fix.
KEY POINTS
  • 01Microsoft confirmed that September 2026 Windows 11 security updates can cause domain-joined devices to lose their secure trust relationship with the domain and reject valid login credentials.
  • 02The issue occurs when the updates begin honoring existing or policy-provisioned Machine Identity Isolation enforcement settings.
  • 03Microsoft says Machine Identity Isolation enforcement is supported only in environments connected to domain controllers running at the Windows Server 2025 Domain Functional Level or higher.
  • 04Microsoft’s temporary workaround is to disable Machine Identity Isolation using the same management method that enabled it, restart the device, and repair its secure channel.
  • 05Microsoft is developing a future Windows update to temporarily prevent Machine Identity Isolation enforcement.

Microsoft confirmed that September 2026 Windows 11 security updates can prevent some users from signing in with valid domain credentials. Reports from users and IT administrators indicate that affected enterprise systems may lose their domain trust relationship and display domain trust or credential errors. The issue is linked to Machine Identity Isolation enforcement after installation of KB5124008 for Windows 11 24H2/25H2 or KB5124012 for Windows 11 26H1.

Microsoft said the updates do not directly enable Machine Identity Isolation enforcement, but cause Windows to honor existing policy or registry settings that enable it. The feature is supported only in environments connected to domain controllers running at the Windows Server 2025 Domain Functional Level or higher, and Microsoft says it should be disabled elsewhere. As a temporary workaround, administrators should disable the feature through the method used to enable it, restart the device, and repair its secure channel; Microsoft is working on an update to temporarily prevent enforcement.

  • The September updates do not directly turn on Machine Identity Isolation enforcement; they cause Windows to honor enforcement settings that were already configured through policy or the registry.
  • The feature is supported only when devices connect to domain controllers at the Windows Server 2025 Domain Functional Level or above, so Microsoft says it should be disabled in other environments.
  • For registry-configured systems, Microsoft’s workaround specifically requires changing the MachineIdentityIsolation value from 2 to 0, restarting the device, and then repairing its secure channel.
  • The same month’s security updates also prompted separate emergency fixes for Remote Desktop Services, Hyper-V shared-folder access in Linux virtual machines, and some USB audio issues.

Microsoft says some recent Windows 11 security updates can stop employees from signing in to work computers that are connected to an organization’s central account system, even when they use the correct password. The problem affects organizations whose computers use a Windows security setting that is not supported by their server setup. This can disrupt normal access to company devices and services, so Microsoft has provided temporary steps for IT staff to turn off the setting and restore the computer’s connection to the organization’s network.

This is a concrete, current Windows security-update issue that can prevent valid domain users from logging in and disrupt enterprise operations. It is broadly relevant to organizations running affected Windows 11 versions, particularly those with Machine Identity Isolation settings, and Microsoft has issued a specific workaround while developing a permanent fix.

Cisco warns of max severity ISE zero-day exploited in attacks

Cisco is urging customers to immediately patch Cisco Identity Services Engine and ISE-PIC for CVE-2026-76460, a maximum-severity authentication-bypass flaw that is actively being exploited. No workaround is available, and suspected compromises may require node reimaging and restoration from backups.
KEY POINTS
  • 01Cisco released security updates for CVE-2026-76460, a maximum-severity authentication-bypass flaw in Cisco Identity Services Engine and Cisco ISE Passive Identity Connector that is actively exploited in attacks.
  • 02The flaw stems from insufficient authentication controls on an API endpoint and can allow a remote attacker to bypass the web-based management interface and gain unauthorized access.
  • 03No workaround is available; Cisco recommends upgrading to fixed releases, including ISE 3.1 Patch 12, 3.2 Patch 11, 3.3 Patch 12, 3.4 Patch 7, or 3.5 Patch 4.
  • 04Cisco advised administrators to check access.log files for suspicious usernames and to reimage affected nodes and restore backups if malicious activity is suspected.
  • 05CISA added CVE-2026-76460 to its Known Exploited Vulnerabilities Catalog and ordered U.S. federal agencies to patch affected systems within three days.

Cisco released security updates for CVE-2026-76460, a maximum-severity flaw in Cisco Identity Services Engine (ISE) and Cisco ISE Passive Identity Connector (ISE-PIC) that is being actively exploited. The issue allows remote attackers to bypass authentication through a vulnerable API endpoint and gain unauthorized access by getting around the web-based management interface. Cisco said the flaw is present regardless of configuration and that no workaround exists.

Cisco recommends upgrading affected systems to fixed releases, including ISE 3.1 Patch 12, 3.2 Patch 11, 3.3 Patch 12, 3.4 Patch 7, or 3.5 Patch 4. It also advised administrators to inspect access.log files on every node for suspicious usernames and, if malicious activity is suspected, to reimage nodes and restore them from backups. CISA added CVE-2026-76460 to its Known Exploited Vulnerabilities Catalog and directed U.S. federal agencies to patch affected systems within three days.

  • The authentication bypass affects Cisco ISE and ISE-PIC regardless of configuration, so changing settings is not presented as a way to reduce exposure.
  • Cisco advises reviewing access.log files on every node for suspicious usernames, indicating that investigation must cover the full deployment rather than a single system.
  • Attackers may remove evidence after gaining root-level command execution, so Cisco recommends checking firewall and network logs for suspicious external uploads and downloads as well.
  • For suspected compromise, Cisco strongly recommends reimaging affected nodes and restoring from backups rather than relying only on cleanup.

Cisco released urgent updates for a serious flaw in its Identity Services Engine software, which organizations use to control who and what can access their networks. Attackers are already using the flaw to get past the software’s web-based sign-in controls and gain unauthorized access, regardless of how it is set up. Organizations using the affected Cisco products should install the updates because there is no temporary fix, and U.S. federal agencies were ordered to patch within three days.

OPEN SOURCE ↗

This is a must-read advisory for organizations using Cisco ISE or ISE-PIC because CVE-2026-76460 is a maximum-severity authentication bypass under active exploitation, with no workaround available. Cisco and CISA both urge immediate patching, and suspected compromise may require reimaging affected nodes.

Chinese hackers use SparroWocky malware in govt espionage attacks

China-linked espionage group FamousSparrow has deployed the new SparroWocky backdoor against government organizations across Latin America, replacing its older SparrowDoor malware. The modular tool uses DLL side-loading and advanced Windows evasion techniques to steal intelligence, capture screens, execute commands, and move data.
KEY POINTS
  • 01ESET reported that the China-linked espionage group FamousSparrow has used the SparroWocky backdoor against government organizations in Latin America for more than a year.
  • 02ESET observed targets in Argentina, Ecuador, Guatemala, Honduras, Panama, Peru, Puerto Rico, and Venezuela, with telemetry showing a primary focus on Latin America from mid-2025.
  • 03SparroWocky can execute commands and files, gather system and user information, manage files, capture screenshots, create processes in other logged-in users' sessions, and act as a TCP proxy.
  • 04The malware is deployed through DLL side-loading after a loader decrypts an RC4-encoded payload from a .dat file and maps it directly into memory.
  • 05SparroWocky can persist through a Windows service named ProcAuditManager or a SnapCart registry key, and ESET identified at least 18 command-and-control addresses associated with the activity.

China-linked espionage group FamousSparrow has used a new C++ backdoor called SparroWocky in attacks against government organizations in Latin America for more than a year. The malware replaces the group’s previously used SparrowDoor custom backdoor. ESET observed affected organizations in Argentina, Ecuador, Guatemala, Honduras, Panama, Peru, Puerto Rico, and Venezuela, and believes the campaign sought intelligence on governments’ responses to increased U.S. pressure on Chinese economic interests.

SparroWocky can run commands and programs, collect system and user details, manage files, take screenshots, create processes in another logged-in user’s session, and act as a TCP proxy. It is deployed through DLL side-loading, with a loader decrypting an RC4-encoded payload from a .dat file and loading it directly into memory. The backdoor also uses several methods to evade detection, including making security products see a legitimate Windows function, AnimateWindow, as the start of threads created by the malware.

For persistence, SparroWocky can create a Windows service named ProcAuditManager or add a SnapCart registry key, depending on available privileges. ESET identified at least 18 command-and-control addresses used by the malware, communicating directly over ports 443 or 8080 or through HTTP and SOCKS5 proxies. ESET’s telemetry indicates that FamousSparrow’s activity has focused primarily on Latin America since mid-2025, and its report provides technical details and indicators of compromise for the campaign.

  • SparroWocky reduces screenshot data after the first capture by taking images every 500 milliseconds but sending only the screen regions that changed.
  • The backdoor hooks Windows thread creation so that security products may see AnimateWindow, a legitimate Windows function, as the thread’s starting point instead of the malware’s real code.
  • Its persistence method changes with available permissions: it can use the ProcAuditManager Windows service or create a SnapCart registry entry under either the machine-wide or current-user registry area.
  • ESET identified at least 18 command-and-control addresses, with the malware communicating directly over ports 443 or 8080 or through HTTP and SOCKS5 proxy connections.

A China-linked hacking group called FamousSparrow has used a new spying program, SparroWocky, against government organizations in several Latin American countries, including Argentina, Ecuador, Guatemala, Honduras, Panama, Peru, Puerto Rico, and Venezuela. The program can collect information about computers and users, copy files, run commands, take screenshots, and hide itself from security tools. This matters because the campaign appears aimed at gathering intelligence about how Latin American governments respond to growing U.S. pressure on Chinese economic interests.

MedTech Security Baselines

Health-ISAC’s Medical Device Security Council outlines baseline cybersecurity capabilities that healthcare organizations should expect from medical device manufacturers during evaluation, procurement, and deployment. Where devices cannot support controls natively, risks should be addressed through documented, context-specific compensating controls and HDO governance.
KEY POINTS
  • 01The paper identifies baseline cybersecurity capabilities that healthcare delivery organizations commonly expect medical device manufacturers to support during product evaluation, procurement, and intake.
  • 02The guidance distinguishes devices running full operating systems from those using embedded, real-time, or otherwise constrained platforms because their technical and operational limitations differ.
  • 03The document is a decision-support resource rather than a certification standard or mandatory procurement checklist.
  • 04When a device cannot provide security controls natively, organizations should assess documented compensating controls based on clinical context, threat model, patient-safety impact, and operational burden.
  • 05Controls dependent on healthcare delivery organization infrastructure require explicit agreement with the manufacturer, while final risk acceptance remains with an authorized healthcare delivery organization decision-maker.

Health-ISAC’s Medical Device Security Council published a paper describing baseline cybersecurity capabilities that healthcare delivery organizations commonly expect medical device manufacturers to support. The paper is intended to help align product evaluation, procurement, and intake decisions while supporting safe, reliable patient care. It covers nine survey-selected capability domains and is a decision-support resource rather than a certification standard or mandatory procurement checklist.

The guidance distinguishes between devices that run full operating systems and devices built on embedded, real-time, or otherwise constrained platforms, because their capabilities and operating constraints can differ significantly. When a device cannot provide security controls natively, organizations should use documented compensating controls tailored to clinical context, threat model, patient-safety impact, and operational burden. Controls that depend on healthcare delivery organization infrastructure require explicit agreement with the manufacturer, and final risk acceptance remains with an authorized healthcare delivery organization decision-maker without removing manufacturer responsibilities.

  • The paper explicitly rejects treating compensating controls as automatically acceptable; their suitability must be weighed against patient safety, the device’s clinical use, likely threats, and the operational work they create.
  • A healthcare delivery organization can make the final decision to accept risk, but that decision does not remove the manufacturer’s responsibilities.
  • Security measures that depend on hospital infrastructure require explicit agreement between the healthcare delivery organization and the medical device manufacturer.
  • The guidance is designed to support exception reviews as well as routine evaluation, procurement, and deployment decisions.

Health-ISAC’s Medical Device Security Council published guidance on the basic security features that hospitals and other care providers commonly expect medical-device makers to support. It recognizes that some devices, especially those with limited built-in computing capabilities, cannot use every protection. In those cases, the care organization and manufacturer need clear agreements and alternative safeguards suited to the device, patient safety, and daily clinical work. This matters because medical technology must remain safe and reliable for patient care while being protected from digital risks.

OPEN SOURCE ↗

This is a substantive but evergreen white paper on baseline medical-device security expectations, not reporting a specific incident, vulnerability, or urgent patch. It may be useful to healthcare and medical-device security professionals for procurement and risk-acceptance decisions, but it has limited immediate urgency.
