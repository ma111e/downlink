Plex Urges Immediate Updates After Patching Multiple Undisclosed Security Flaws

Plex is urging users to immediately update Plex Media Server to 1.43.3 and Plex Desktop to 1.115.0 after patching multiple undisclosed security flaws. The company has not shared technical details yet, but CVEs have been requested and exposed Plex servers have been targeted in past attacks.
KEY POINTS
  • 01Plex is urging users to update to Plex Media Server 1.43.3 and Plex Desktop 1.115.0 after releasing fixes for multiple security flaws.
  • 02Plex did not provide details about the newly patched issues but said CVE identifiers have been requested for them.
  • 03Plex said NAS users may need to install the updated Plex Media Server package manually if it is not yet available through their package manager.
  • 04In August 2025, Plex addressed CVE-2025-34158, a high-severity authentication bug that could expose a server owner’s account details and administrative access token to lower-privileged authenticated users.
  • 05Censys data shows more than 360,000 devices exposing the Plex Media Server web interface, although not all of them are vulnerable.

Plex is urging users to update their instances after releasing fixes for multiple security flaws. The fixes are available in Plex Media Server 1.43.3 and Plex Desktop 1.115.0. Plex did not provide details about the issues, but said CVE identifiers have been requested. The company recommends that all server owners and Desktop users update to the latest version as soon as possible.

Plex said users running Plex Media Server on NAS devices may not yet see the update in their package manager, but can install the package manually. The update follows an August 2025 fix for CVE-2025-34158, a high-severity authentication bug affecting the “/myplex/account” endpoint. That earlier flaw could expose the server owner’s account details, including an administrative access token, to authenticated non-owner or lower-privileged users. A subsequent “/api/resources” API call could reveal other servers accessible by the owner, potentially exposing the owner’s Plex infrastructure to unauthorized access.

Censys data shows more than 360,000 devices exposing the Plex Media Server web interface, though the article notes that not all of them are vulnerable. The article also notes that Plex Media Server vulnerabilities have been exploited by threat actors in the past. In February 2021, Plex fixed an issue that allowed affected servers to reflect UDP packets to amplify denial-of-service attacks. The article further states that the August 2022 LastPass breach was driven by attackers compromising an employee’s home computer through a Plex Media Server vulnerability, CVE-2020-5741.

  • Plex’s recommendation to update before publishing CVE details makes the update time-sensitive even though the exact flaws remain undisclosed.
  • NAS users may face a delay through normal package managers, so Plex specifically points them to manual installation as the faster update path.
  • The previously fixed CVE-2025-34158 showed that a lower-privileged authenticated Plex user could obtain an owner’s administrative access token and then discover other servers tied to that owner.
  • Plex Media Server vulnerabilities have had real-world consequences beyond media servers, including the LastPass incident where attackers compromised an employee’s home computer through a Plex flaw.

Plex released updates for Plex Media Server and Plex Desktop after fixing several security problems, and it is telling server owners and desktop users to update as soon as possible. The company has not yet explained the problems in detail, but past Plex issues have exposed owner account details or helped attackers misuse servers. This matters because more than 360,000 devices expose the Plex Media Server web page, and Plex flaws have previously been used in real attacks, including one connected to the LastPass breach.

Over 440,000 Exploit Attempts Target Super Forms and Elementor Pro RCE Flaws

Attackers are actively exploiting critical arbitrary file upload flaws in the Super Forms and Elementor Pro WordPress plugins to plant PHP web shells and potentially take over sites. Site owners should update to the fixed versions immediately and check for suspicious recently modified PHP files.
KEY POINTS
  • 01Threat actors are exploiting two critical security flaws in the WordPress plugins Super Forms and Elementor Pro, according to Wordfence.
  • 02CVE-2026-14894 in Super Forms allows unauthenticated attackers to upload files of any type, including executable PHP files, leading to remote code execution, and it was fixed in version 6.3.314.
  • 03CVE-2026-32475 in Elementor Pro allows unauthenticated attackers to upload files of any type, including executable PHP files, leading to remote code execution, and it was fixed in version 4.2.2.
  • 04Wordfence said it has blocked over 250,000 exploit attempts targeting CVE-2026-14894 and over 190,000 exploit attempts targeting CVE-2026-32475.
  • 05WordPress site owners using the two plugins are advised to apply patches immediately, scan for indicators of compromise, and audit for unexpected or recently modified .php files.

Threat actors are exploiting two critical security flaws in the WordPress plugins Super Forms and Elementor Pro, according to Wordfence. The flaws are CVE-2026-14894 in Super Forms – Drag & Drop Form Builder and CVE-2026-32475 in Elementor Pro. Wordfence said it has blocked over 250,000 exploit attempts targeting CVE-2026-14894 and over 190,000 exploit attempts targeting CVE-2026-32475.

Both vulnerabilities allow unauthenticated attackers to upload files of any type, including executable PHP files, which can lead to remote code execution. The article says attackers can use this kind of flaw to write a PHP web shell to a site and then create administrator accounts, exfiltrate data, or seize control of the entire WordPress site. Super Forms fixed CVE-2026-14894 in version 6.3.314, and Elementor Pro fixed CVE-2026-32475 in version 4.2.2.

For Super Forms, attackers send an HTTP POST request to /wp-admin/admin-ajax.php using the super_submit_form endpoint with a Base64-encoded PHP payload and attacker-controlled file name. For Elementor Pro, Wordfence said the attacker submits the File Upload field as an array where the first element is empty and the second contains a PHP payload with a .php file name. WordPress site owners using the two plugins are advised to apply patches immediately, scan for indicators of compromise, and audit for unexpected or recently modified .php files.

  • The Super Forms exploitation uses a file labeled with a "data:image/gif;base64" prefix while actually delivering a PHP file-uploader web shell named "Mushr00w_upl.php."
  • Elementor Pro exploitation depends on a specific site condition: the target must have at least one published Elementor page containing a Form widget with a File Upload field.
  • The Elementor Pro validation bypass is triggered by submitting the File Upload field as an array where the first element is empty and the second carries a PHP payload with a .php filename.
  • Wordfence observed Super Forms exploitation activity beginning on July 14, 2026, with a peak of more than 40,000 exploit requests on August 18, 2026, while Elementor Pro exploitation began on August 19, 2026.

Attackers are taking advantage of serious flaws in two WordPress add-ons, Super Forms and Elementor Pro, and Wordfence says it has blocked more than 440,000 attempts so far. Websites using these add-ons are affected if they have not installed the fixed versions. The flaws can let attackers place harmful files on a site, which could allow them to create administrator accounts, steal data, or take control of the entire website.

Google Releases Chrome Update to Patch Actively Exploited V8 Zero-Day

Google released Chrome updates to fix CVE-2026-85046, an actively exploited high-severity V8 type confusion zero-day that can allow arbitrary code execution via a crafted HTML page. Users should update Chrome and other Chromium-based browsers as fixes become available.
KEY POINTS
  • 01Google released security updates for Chrome to patch 12 vulnerabilities, including an actively exploited zero-day.
  • 02The actively exploited flaw is CVE-2026-85046, a high-severity type confusion bug in Chrome’s V8 JavaScript and WebAssembly engine with a CVSS score of 8.8.
  • 03CVE-2026-85046 could allow a remote attacker to execute arbitrary code inside the Chrome sandbox using a crafted HTML page.
  • 04Security researcher Salvatore Gulizia reported the flaw on August 4, 2026 and described it as a V8 compiler bug that can be turned into arbitrary read and write access on the JavaScript heap.
  • 05Users are advised to update Chrome to versions 152.0.7977.82/.83 for Windows and macOS and 152.0.7977.82 for Linux, while users of other Chromium-based browsers should apply fixes when available.

Google released security updates for Chrome to patch 12 vulnerabilities, including one that has been actively exploited in the wild. The actively exploited flaw is tracked as CVE-2026-85046 and has a CVSS score of 8.8. Google described it as a high-severity type confusion bug in V8, Chrome’s JavaScript and WebAssembly engine.

According to the vulnerability description, CVE-2026-85046 affected Google Chrome prior to version 152.0.7977.82 and could allow a remote attacker to execute arbitrary code inside the sandbox using a crafted HTML page. Security researcher Salvatore Gulizia, also known as Serotav, reported the flaw on August 4, 2026 and received a $1,000 bug bounty. Gulizia described the issue as a V8 compiler bug that could be turned into arbitrary read and write access on the JavaScript heap.

Google acknowledged that an exploit for CVE-2026-85046 exists in the wild but did not disclose attack details to help ensure users can update before further exploitation. The company has now addressed six actively exploited Chrome zero-days since the start of the year. Users are advised to update Chrome to versions 152.0.7977.82/.83 for Windows and macOS and 152.0.7977.82 for Linux, while users of Chromium-based browsers such as Microsoft Edge, Brave, Opera, and Vivaldi should apply fixes when available.

  • Google withheld details about the active exploitation to reduce the risk of further attacks before most users install the fix.
  • This is the sixth actively exploited Chrome zero-day Google has patched since the start of 2026, showing that Chrome zero-days have been a recurring issue this year.
  • The flaw was reported on August 4, 2026, but Google’s public update says exploitation is now known to exist in the wild, making prompt installation more urgent than a routine browser update.
  • The issue may affect more than Chrome users because the article specifically advises users of Chromium-based browsers such as Microsoft Edge, Brave, Opera, and Vivaldi to apply fixes when available.

Google released an update for Chrome to fix 12 security problems, including one that attackers are already using. The main issue could let a remote attacker run their own code through a specially made web page, so people using Chrome on Windows, macOS, and Linux should update to the fixed versions. People using other browsers built on the same technology, including Microsoft Edge, Brave, Opera, and Vivaldi, may also be affected and should install fixes when they are available.

A Phishing Kit Padded Its Payload With Someone Else's Mail

A credential-phishing email passed SPF, DKIM, DMARC, and Microsoft composite authentication by using controlled or repurposed infrastructure, then hid a malicious settlement-agreement link behind an ESP tracker. Its key evasion tactic was padding the short lure with a stolen legitimate commercial email to make the message look statistically normal to scanners while keeping the real phish visible to the victim.
KEY POINTS
  • 01A fully authenticated phishing email reached two mailboxes at a food service packaging manufacturer with SPF, DKIM, DMARC, and Microsoft composite authentication all passing.
  • 02The visible lure was a four-line settlement approval message using the recipient’s first name, full email address, and company name, with a single link disguised as a signer approval settlement agreement PDF.
  • 03The link used a Mandrill click tracking URL that relayed to a credential page on secure.individual-elegance.co.za, which the platform scored as malicious.
  • 04The email’s HTML contained roughly seventy blank line breaks followed by a complete, unrelated legitimate commercial email that had been sent to a different person at a different organization.
  • 05Themis flagged the message as credential theft with 89% confidence, and both affected mailboxes were quarantined and mitigated.

A fully authenticated phishing email reached two mailboxes at a food service packaging manufacturer with an empty subject, a four-line settlement approval lure, and a single link. SPF, DKIM, DMARC, and Microsoft composite authentication all passed, but the sender alias asserted the recipient organization’s own name from an unrelated sending domain. Themis scored the message at 89% confidence for credential theft, and both affected mailboxes were quarantined and mitigated.

The link was labeled as a signer approval settlement agreement PDF using the recipient company’s name, but no attachment was present. Its hover text advertised one unrelated commercial domain, while the actual link went through a Mandrill click tracking URL to a credential page on secure.individual-elegance.co.za. The article says the tracker received a mixed verdict and the terminal page was scored as malicious.

The most notable technique was padding: after roughly seventy blank line breaks, the email reproduced a complete, unrelated legitimate commercial email that had been sent to a different person at a different organization. This stolen filler changed the message’s link ratios, text volume, and boilerplate profile while pushing the borrowed content below what a reader would likely see. The article recommends normalizing messages before scoring them, detecting unrelated appended markup, resolving tracking links to their final destination, and checking for display-name impersonation, malformed sender local parts, and mismatched anchor titles and destinations.

  • The strongest available authentication result did not reduce the phishing risk in this case because the sending domain authenticated itself, not the organization named in the sender alias.
  • The stolen legitimate email padding changed measurable content ratios such as link count, text volume, and boilerplate presence, making the message appear more like normal commercial mail to automated analysis.
  • Long runs of blank line breaks served a dual purpose: they hid the borrowed content from the reader while still allowing parsers to count it as part of the message.
  • The malformed sender local part containing marketing tracking parameters was an actionable signal that the kit had likely pasted a scraped tracking string into an email address field.
  • Comparing an anchor’s visible hover title with its actual destination and resolving ESP tracking links to their final landing page were decisive checks that did not depend on sender authentication.

Two mailboxes at a food service packaging manufacturer received a fake settlement approval email that looked properly authenticated and used the recipient company’s name, but its link led to a page meant to steal login details. The message was padded with a real commercial email stolen from someone else, making it look more normal to automated checks while hiding the extra content far below what a person would likely read. This matters because even emails that pass normal sender checks can still be scams, and stolen legitimate mail is being reused to make phishing harder to spot.

Angry Birds: Toy Ghouls’ new toys

Kaspersky reports that the financially motivated Toy Ghouls group has added custom backdoors to its arsenal, using HiveMQ MQTT and Matrix/Element as command-and-control channels. The shift from public tools to custom malware suggests the group is becoming more sophisticated and harder to detect.
KEY POINTS
  • 01Kaspersky observed Toy Ghouls using a custom backdoor for the first time in early July 2026 after previously relying on public GitHub tools, leaked Babuk and LockBit ransomware builders, and later its own GenieLocker ransomware.
  • 02The researchers identified two versions of the backdoor: mqtt-bird-agent 0.1.0, which uses the HiveMQ MQTT broker as its command-and-control server, and matrix-bird-agent 0.1.0, which relies on the Element messenger.
  • 03The attackers deliver the backdoors and their configuration files to compromised systems using Windows Remote Management with open-source tools such as Evil-WinRM and WinRM-fs.
  • 04Both backdoor versions can establish persistence as Windows services, encrypt or store configuration data tied to the infected machine, and stop running if the configuration cannot be decrypted.
  • 05The backdoors collect system status and metrics, receive remote commands, execute them through PowerShell or the Windows command line, and send command results back through HiveMQ or Matrix/Element channels.

Kaspersky reports that Toy Ghouls, also known as Bearlyfy, Laboo.boo, and Feral Wolf, has begun using a custom backdoor against Russian organizations. The group previously relied on tools from public GitHub repositories, leaked Babuk and LockBit ransomware builders, and later its own GenieLocker ransomware. In early July 2026, researchers observed the group using a custom backdoor for the first time.

Two versions of the backdoor were identified: mqtt-bird-agent 0.1.0, which uses the HiveMQ MQTT broker as its C2 server, and matrix-bird-agent 0.1.0, which relies on the Element messenger. The attackers deliver the backdoors and configuration files to compromised systems using Windows Remote Management with tools such as Evil-WinRM and WinRM-fs. Both versions can run interactively or establish persistence as Windows services, and they use configuration data that may be encrypted with a machine-bound key.

Both backdoor versions contact ip-api.com at startup to determine the system’s public IP address and country of origin. They send status and system metrics, receive commands from the attackers, execute those commands through PowerShell or the Windows command line, and return execution results. The article concludes that Toy Ghouls’ move from public tools to custom-built malware and unconventional C2 channels suggests an effort to make attacks more sophisticated and evade detection for longer.

  • The backdoor’s configuration becomes tied to the infected machine using the Windows MachineGuid value, so investigators may need access to the original host to decrypt sealed configuration data.
  • The Element version removes its configuration file after first run and stores the sealed configuration in HKLM\Software\synapse\Config\SealedConfig, making registry examination important even if config.toml is missing.
  • The attackers disguise persistence with service names and descriptions that resemble legitimate Windows components, including cplsupport as “Problem Reports Control Panel” and wtas as “Windows Telemetry Aggregator Service.”
  • The use of legitimate services such as broker.hivemq.com, meet.element.tw, and ip-api.com means suspicious activity may appear as connections to otherwise normal internet resources rather than obviously malicious infrastructure.

Kaspersky found that Toy Ghouls, a money-driven criminal group targeting Russian organizations, has started using its own hidden access programs on compromised Windows computers. These programs let the attackers keep control of an infected device, collect basic system information, and run commands remotely through services such as HiveMQ and Element. This matters because the group is moving from publicly available tools to custom-built ones, which may help it stay unnoticed for longer and make its attacks more serious.
