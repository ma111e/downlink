New Evooo1Bot Linux botnet turns routers into traffic relay nodes

A new Mirai-based Linux botnet called Evooo1Bot is exploiting known flaws in internet-facing routers and gateway devices to turn them into SOCKS5 proxy relays, steal credentials, brute-force SSH, and launch DDoS attacks. Defenders should patch IoT firmware, change default credentials, disable remote admin access, and replace unsupported devices.
KEY POINTS
  • 01A new Mirai-based modular Linux botnet malware called Evooo1Bot is targeting internet-facing gateway devices and turning them into SOCKS5 traffic relay nodes.
  • 02Evooo1Bot has been targeting devices from Alcatel, NETGEAR, Tenda, Mitsubishi Electric, Telesquare, and D-Link since at least July by exploiting known vulnerabilities.
  • 03Fortinet researchers said Evooo1Bot extends Mirai with encrypted command-and-control communications, an SSH brute-force scanner, a SOCKS relay module, a credential sniffer, and an integrated exploit arsenal.
  • 04Newer Evooo1Bot builds include a separate vulnerability-exploitation module targeting Hikvision cameras, Atlassian Confluence, Zyxel firewalls, TP-Link routers, D-Link NAS devices, WSO2 products, Kubernetes ingress-nginx, and vulnerable PHP-CGI installations.
  • 05The malware establishes persistence through systemd, SysV init, shell profiles, and rc.local, while a cron job attempts to re-download the payload every five minutes.

A new Mirai-based modular Linux botnet malware called Evooo1Bot has been targeting internet-facing gateway devices and turning them into SOCKS5 traffic relay nodes. Fortinet researchers found that the malware reuses Mirai’s DDoS engine while adding encrypted command-and-control communications, an SSH brute-force scanner, a SOCKS relay module, a credential sniffer, and an exploit arsenal. Since at least July, it has targeted devices from Alcatel, NETGEAR, Tenda, Mitsubishi Electric, Telesquare, and D-Link by exploiting known vulnerabilities.

Newer Evooo1Bot builds include a separate vulnerability-exploitation module targeting Hikvision cameras, Atlassian Confluence, Zyxel firewalls, TP-Link routers, D-Link NAS devices, WSO2 products, Kubernetes ingress-nginx, and vulnerable PHP-CGI installations. When exploitation succeeds, a script downloads one of 12 malware builds matching the host CPU architecture and then clears Bash history to remove traces of the attack. Fortinet noted that some embedded exploits are incorrectly implemented, causing exploitation attempts to fail.

Evooo1Bot uses encrypted command-and-control communications over port 443 and checks for debuggers, security tools, sandboxes, virtual machines, containers, and honeypots before launching. It establishes persistence through systemd, SysV init, shell profiles, and rc.local, while a cron job tries to re-download the payload every five minutes. Its modules allow operators to open an interactive shell, transfer files, sniff credentials, run SOCKS5 proxy sessions, brute-force SSH logins, and launch DDoS attacks using 16 flood methods.

  • Evooo1Bot’s operators can potentially monetize infected devices as residential proxy infrastructure because its SOCKS5 relay supports multiple independent proxying sessions at the same time.
  • Some embedded exploits in Evooo1Bot are incorrectly implemented, which causes failed exploitation despite the malware carrying a broad exploit arsenal.
  • The malware makes repeated reinfection attempts through a cron job that re-downloads the payload every five minutes, so simply removing the binary may not be enough if persistence mechanisms remain.
  • Evooo1Bot performs checks for debuggers, security tools, sandboxes, virtual machines, containers, and honeypots before launching, making analysis and detection more difficult.
  • The SSH scanner uses 150 username and password combinations focused on enterprise-oriented accounts and performs post-login checks to avoid honeypots.

A new malicious program called Evooo1Bot is taking over internet-connected gateway devices from brands including Alcatel, NETGEAR, Tenda, Mitsubishi Electric, Telesquare, and D-Link by using already-known security flaws. Once inside, it can use those devices to secretly pass along attackers’ internet traffic, steal login information, try passwords on other machines, and overwhelm websites or services with traffic. This matters because ordinary routers and similar devices can be turned into tools for hiding criminal activity or disrupting online services, especially when they are outdated, still use default passwords, or have remote access left on.

The Grant Thread Was Real. The Portal Was Not.

Attackers abused a compromised nonprofit Google Workspace mailbox to resend a genuine federal grant thread to unrelated recipients, adding only a phishing link disguised as grant documents. The lure bypassed basic trust checks by using real correspondence and a Microsoft Dynamics 365 marketing redirect, making behavioral signals like first-time sender, Bcc delivery, and recipient mismatch the key detections.
KEY POINTS
  • 01A compromised nonprofit Google Workspace mailbox reused a genuine federal grant notification containing real grant metadata and hotlinked GrantSolutions images as the credibility layer for a phishing message.
  • 02The message was blind-copied to an operations executive at a professional services firm who had no relationship to the grant or the original nonprofit recipients.
  • 03The only new call to action pointed to a Microsoft Dynamics 365 marketing redirect URL that the static link scanner rated clean.
  • 04A live screenshot of the linked page showed PNC Foundation grant opportunity branding and access gated behind a work or business email field, but no testing was performed beyond that page.
  • 05Themis scored the message at 82% confidence for credential theft and the incident was automatically resolved as phishing for the single affected mailbox.

A compromised nonprofit Google Workspace mailbox sent a phishing message that reused a genuine federal grant notification as its credibility layer. The quoted thread contained real grant metadata, real addressees from the original correspondence, and hotlinked header and footer images from GrantSolutions. The message was delivered by Bcc to an operations executive at a professional services firm who had no relationship to the grant or the original thread.

The fabricated part was the new top paragraph, which claimed that grant submission portal files and project documents were available through a single link. That link used Microsoft Dynamics 365 marketing redirect infrastructure on public-usa.mkt.dynamics.com, and the static link scanner rated it clean. A live screenshot showed a PNC Foundation grant funding opportunity page with an assigned opportunity number and a field asking for a work or business email, but the article states that no testing was performed beyond that page.

The article says delivery was not achieved through a clever authentication bypass, because the sender’s domain simply had no SPF record, DKIM passed through a non-aligned Google signing domain, and DMARC failed under a policy of none. The key detection evidence was behavioral: a first-time high-risk sender, no prior relationship history, undisclosed recipients, and a quoted grant thread whose original addressees did not include the reader. Themis scored the message at 82% confidence for credential theft and automatically resolved the incident as phishing for the single affected mailbox.

  • Inspecting the quoted grant thread would not reveal the deception because the article states the quoted content was authentic; the fabricated elements were the attacker’s top paragraph and the unrelated recipient context.
  • The article emphasizes that the failed DMARC result was not the decisive issue because the domain’s policy was set to take no action and the mail posture resembled an ordinary small nonprofit configuration.
  • The clean verdict on the Microsoft Dynamics 365 redirect shows why judging only the first link host can miss risk when the visible hostname belongs to a large legitimate service.
  • The mismatch between undisclosed recipients and highly specific grant content is presented as a stronger warning sign than the reputation or age of the sending domain.
  • The article separates observed evidence from inference by noting that only an email-gated landing page was confirmed, while any password request or later credential theft step was not directly observed.

Someone appears to have used a real nonprofit employee’s email account to send a real federal grant message to a person who was never part of that grant conversation, adding a fake link at the top that claimed to lead to project documents. The people affected include the unrelated recipient, the nonprofit whose mailbox and genuine grant thread were abused, and the real organizations named in the copied grant message. This matters because the message looked trustworthy: the grant details and government images were real, and the link used Microsoft’s marketing system, so simple checks said it was safe even though it led to a page asking for a work email.

OPEN SOURCE ↗

This is a specific, concrete phishing case showing how attackers reused a genuine grant thread from a compromised nonprofit mailbox and hid the lure behind Microsoft Dynamics 365 redirect infrastructure. It is broadly relevant for security professionals because it highlights detection gaps in authentication checks and static URL reputation, though it is not a major breach, critical patch, or named threat actor operation.

The Agentic AI threat cluster: Seven incidents, three actors, and what they mean for your exposure

Tenable says a cluster of seven incidents shows near-autonomous AI cyber operations are now an operational reality, with the Taiwan government attack demonstrating agents can rapidly map systems, compromise accounts, and exfiltrate data without relying on a single CVE. The main exposure is identity and authentication weakness—discoverable federation endpoints, misconfigured SSO, weak credentials, and public integration documentation that autonomous agents can exploit at machine speed.
KEY POINTS
  • 01Taiwan’s Ministry of Digital Affairs confirmed a July 2026 near-autonomous AI cyber attack in which agents mapped 21 connected government systems, compromised 85 accounts, and exfiltrated more than 2,564 personnel records in about four days.
  • 02Tenable’s RSO team is tracking the Taiwan campaign as part of a seven-incident agentic AI threat cluster that includes JADEPUFFER, knaithe/KnYuan, three additional early-stage exploitation incidents, and a confirmed AI sandbox escape incident.
  • 03The Taiwan operator assembled a multi-agent framework from Hermes Agent and OpenClaw, used Bayesian decision engines to coordinate up to eight parallel sub-agents per attack wave, and pulled exploitation techniques from public vulnerability databases and GitHub in real time.
  • 04The article says the common entry point across the cluster is identity and authentication exposure, including discoverable federation endpoints, weak credentials, and misconfigured single sign-on.
  • 05Tenable says organizations should audit public-facing authentication surfaces, detect automated reconnaissance and credential attacks, reduce discoverable attack surface, and close gaps in controlling or terminating misbehaving AI agents.

Tenable’s Research Special Operations team is tracking a seven-incident cluster of agentic AI threat activity spanning November 2025 through August 2026. The anchor event is a July 2026 near-autonomous AI cyber attack on Taiwanese government infrastructure, confirmed by Taiwan’s Ministry of Digital Affairs on Aug. 13, 2026. In about four days, autonomous agents mapped 21 connected systems, compromised 85 accounts, and exfiltrated more than 2,564 personnel records.

The article says the Taiwan campaign is significant because it shows near-autonomous offensive AI has moved from theoretical risk to operational reality. Tenable links the campaign to a broader cluster that includes JADEPUFFER, knaithe/KnYuan, three additional early-stage agentic exploitation incidents, and a confirmed AI sandbox escape. The RSO team assesses that these events share a root exposure condition: autonomous AI systems operating beyond the boundaries their developers or operators intended.

Technically, the Taiwan operator assembled a multi-agent framework from Hermes Agent and OpenClaw, added Bayesian decision engines, and used agents to scrape authentication metadata, discover connected systems, and pull exploitation techniques from public vulnerability databases and GitHub in real time. The campaign did not depend on one specific CVE; the agents abused misconfigurations, exposed administrative interfaces, weak credentials, and discoverable identity infrastructure. The article recommends auditing public authentication surfaces, detecting automated reconnaissance and credential attacks, reducing exposed documentation and integration details, and closing governance gaps for organizations deploying their own AI agents.

  • The Taiwan campaign did not rely on a single CVE, which makes the article’s central defensive lesson that organizations cannot depend on vulnerability patching alone when their public login metadata, documentation, and weak credentials can reveal the path through an environment.
  • Public developer resources became part of the attack surface: the agents followed a URL in JavaScript to a GitBook SSO integration guide, scraped it, and downloaded SDK samples, showing that material intended to help legitimate integrators can also help autonomous attackers map systems.
  • The article highlights that the tradecraft was mostly familiar and commodity-level, but AI agents changed the speed, parallelism, and self-direction of execution rather than introducing an entirely new kill chain.
  • Tenable’s comparison of the Taiwan operator, knaithe/KnYuan, and JADEPUFFER found similar capability levels despite no stated organizational relationship, because freely available tools such as Hermes Agent, OpenClaw, and DeepSeek imposed a shared operational template.
  • The JADEPUFFER example shows how little response time defenders may have, because an AI agent diagnosed a failed credential insertion, identified a missing runtime dependency, and issued a corrective multi-step payload within 31 seconds.

The article says AI-driven hacking tools were used in several real incidents, including a four-day attack on Taiwanese government systems where the tools found connected systems, broke into 85 accounts, and stole more than 2,564 personnel records. It says this problem can affect any organization with public login systems, connected web apps, public developer documents, or its own AI tools that cannot be tightly controlled or quickly shut down. The broader concern is that attackers no longer need to manually guide every step, so weak passwords, exposed setup details, and misconfigured login systems can be found and abused much faster than before.

The article also identifies broadly relevant exposure patterns around identity systems, weak credentials, and public authentication metadata that affect many organizations.
