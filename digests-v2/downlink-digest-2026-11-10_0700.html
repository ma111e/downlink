Google patches eighth Chrome zero-day exploited in attacks this year

Google released emergency Chrome updates to fix CVE-2026-125350, a high-severity use-after-free flaw in the browser's XML component that is already being exploited in the wild. Users should update Chrome to version 157.0.8103.50/.51 as soon as possible.
KEY POINTS
  • 01Google released emergency Chrome security updates for CVE-2026-125350, a high-severity use-after-free flaw in Chrome's XML component that it says is being exploited in the wild.
  • 02The flaw can enable memory corruption when Chrome later accesses memory that has already been freed, potentially allowing attackers to manipulate memory layout and execute malicious code.
  • 03Google did not disclose details about the observed attacks and said vulnerability details may remain restricted until most users have received the fix.
  • 04The update is rolling out through Chrome's Stable Desktop channel for Windows, macOS version 157.0.8103.50/.51, and Linux version 157.0.8103.50.
  • 05CVE-2026-125350 is the eighth Chrome zero-day vulnerability Google has patched this year after evidence of active exploitation.

Google released emergency Chrome updates to fix CVE-2026-125350, a high-severity flaw that the company says is being exploited in the wild. The issue is a use-after-free weakness in Chrome’s XML component, where the browser can retain a reference to memory after the associated object has been deleted. Attackers could use this memory-corruption condition to manipulate memory layout and execute malicious code. Google has not provided details about the observed attacks.

The fix is rolling out through Chrome’s Stable Desktop channel for Windows, macOS, and Linux, with macOS receiving versions 157.0.8103.50/.51 and Linux version 157.0.8103.50. Google said the update may take days or weeks to reach all users, though it was available immediately when BleepingComputer manually checked for updates. Chrome can also check for and install updates automatically after the next launch. This is the eighth Chrome zero-day Google has patched this year after evidence of active exploitation.

  • Although Google says the rollout may take days or weeks to reach all users, the article reports that the patched version was immediately available when manually checking for updates, making a manual update check more timely than waiting for the normal rollout.
  • Chrome can automatically install the update after the browser is launched again, so users who do not update manually can still receive the fix through Chrome’s built-in update process.
  • Google is withholding further technical and attack details until most users are protected, which limits public information about how the flaw is being used while the update is deployed.
  • This is the eighth actively exploited Chrome flaw patched by Google since the start of the year, following several other memory-handling and JavaScript-engine issues.

Google released an emergency update for Chrome to fix a security flaw that attackers are already using. The flaw could let a malicious website interfere with a computer’s memory and run harmful code, although Google has not shared details about the attacks. People using Chrome on Windows, Mac, or Linux should update because this is the eighth Chrome security flaw known to be exploited this year.

Russia-linked Turla used its new Cereal malware framework to covertly spy on Microsoft Exchange email servers at government organizations in Kazakhstan and Romania. The toolset intercepts selected emails and executes commands in memory while avoiding separate command-and-control infrastructure.
KEY POINTS
  • 01ESET found Turla's Cereal toolset on Microsoft Exchange servers at a government organization in Kazakhstan in late 2025 and at a Romanian government agency compromised on December 23, 2025.
  • 02Turla used the CerealBox component to enter Exchange's EdgeTransport.exe process and take over existing email-processing handlers without registering a new handler or interrupting mail delivery.
  • 03The malware selectively collected emails matching specified sender, recipient, and subject criteria, particularly messages with DOC, DOCX, or PDF attachments.
  • 04CerealNeuron accepted encrypted requests disguised as legitimate Exchange service paths, ran attacker-provided programs in memory, and returned encrypted results.
  • 05ESET observed no external command-and-control infrastructure in the campaign, with the compromised Exchange server acting as the attackers' only control point.

ESET documented a late-2025 campaign in which the Russia-linked Turla group used a new malware toolset called Cereal against Microsoft Exchange servers at government organizations in Kazakhstan and Romania. At the Romanian agency, compromised on December 23, 2025, the attackers selectively gathered correspondence involving NATO and European Union representatives. Turla, also known as Snake, Secret Blizzard, and Waterbug, is linked to Russia’s Federal Security Service and has been active for more than two decades.

CerealBox enters Exchange’s EdgeTransport.exe process and takes over existing email-processing handlers, allowing it to inspect messages without adding a new transport agent or interrupting normal mail delivery. The malware was configured to collect messages matching selected sender, recipient, and subject criteria, including emails with DOC, DOCX, and PDF attachments. CerealNeuron receives encrypted commands through web paths resembling legitimate Exchange services, executes supplied programs in memory, and sends encrypted results back to the attackers. ESET observed no external command-and-control infrastructure, while a separate CerealHermit variant can instead read encrypted commands from files stored on the compromised server.

  • Cereal avoids creating a new Exchange transport agent by hijacking handlers that already exist, which helps it inspect email while normal delivery continues.
  • The campaign did not use external command-and-control infrastructure; instead, the compromised Exchange server itself served as the control point.
  • The large number of near-identical, task-specific command programs led ESET to conclude that Turla likely uses an internal system to automatically compile and package commands.
  • A CerealNeuron variant called CerealHermit can read encrypted commands from local files rather than network requests, providing a possible fallback if the web-based control channel is unavailable.

A Russian state-linked hacking group called Turla used new software named Cereal to secretly read selected emails on Microsoft Exchange servers used by government organizations in Kazakhstan and Romania. In Romania, it targeted messages involving NATO and the European Union, especially those with document attachments. This matters because the software can hide inside a normal email system, steal sensitive correspondence, and run other commands without noticeably disrupting email delivery, making long-term spying harder to detect.

  • 03CVE-2026-120017 can allow an attacker to sign in as any user, including privileged users, on affected SAML single-sign-on configurations.
  • 04CVE-2026-89103 can allow an external attacker to impersonate an SAP application server and take unauthorized actions through SAP Gateway.
  • 05SAP and RedRays recommend prioritizing the patches, updating kernels and Web Dispatchers together, and restricting direct network access to Gateway and Internet Communication Manager ports.

SAP issued fixes during its monthly Security Patch Day for four unauthenticated vulnerabilities rated CVSS 10.0. Three flaws affect SAP NetWeaver application server components, while one affects SAP Web Dispatcher, which accepts internet web requests and forwards them to the application server. SAP says none of the four flaws require user action for exploitation. The vendor recommends that affected organizations prioritize the updates.

Two flaws, CVE-2026-76964 in the Internet Communication Manager and CVE-2026-89126 in SAP Web Dispatcher, involve malformed WebSocket traffic that can corrupt memory and potentially let a network-reachable attacker run code. CVE-2026-120017 affects the SAML2 service provider and can let attackers log in as any user, including privileged users, in certain single-sign-on configurations; the article states that no workaround is available. CVE-2026-89103 affects SAP Gateway and can let an external attacker impersonate an internal application server and perform unauthorized actions.   • The SAML issue may affect any AS ABAP system using SAML2 for browser logon, including Fiori Launchpad or Web GUI behind an identity provider, and the article states there is no workaround besides applying SAP’s correction or support package.
  • Patching a Web Dispatcher can temporarily shield the underlying ICM from the WebSocket flaw only when no one can directly reach ICM ports, so exposed backend access defeats that mitigation.
  • For SAP Gateway, the article recommends not relying on default access rules: administrators should use explicit secinfo and reginfo rules, verify that gw/acl_mode is set to 1, and restrict access to port 33xx.
  • A single unpatched Web Dispatcher can leave an organization exposed because the flaw affects standalone and embedded deployments, including SAP HANA XS Classic and XS Advanced.
  • The article advises reviewing trusted identity providers and SAML audit logs for privileged-user logons from unexpected sources after addressing the SAML authentication issue.

SAP fixed four extremely serious software flaws that can be used by someone on the network without needing a username or password. The problems affect SAP NetWeaver systems, Web Dispatcher services that handle incoming web requests, SAP Gateway connections, and some systems that use SAP’s single sign-on feature. If left unpatched, attackers could run their own commands, sign in as any user including administrators, or pretend to be a trusted SAP server, potentially taking control of connected business systems.
