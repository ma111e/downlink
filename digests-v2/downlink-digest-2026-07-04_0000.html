JadePuffer ransomware used AI agent to automate entire attack

Sysdig says JadePuffer is the first documented ransomware operation run end-to-end by an autonomous LLM agent, which exploited a Langflow RCE flaw, stole credentials, moved laterally, persisted, and encrypted Nacos configuration data. The case shows AI agents can now adapt during intrusions like human attackers, while also leaving new detectable patterns in generated payloads.
KEY POINTS
  • 01Sysdig researchers identified JadePuffer as what they believe is the first documented ransomware operation conducted entirely by a large language model agent.
  • 02JadePuffer gained initial access by exploiting CVE-2025-3248, an unauthenticated remote code execution vulnerability in Langflow that was fixed on April 1, 2025.
  • 03The AI agent dumped Langflow's PostgreSQL database, collected host information, searched for sensitive files and environment variables, retrieved credentials, enumerated a MinIO object store, and established persistence with a cron job.
  • 04From the Langflow instance, the attacker pivoted to a production MySQL server running Alibaba Nacos and targeted Nacos with multiple payloads, including one exploiting CVE-2021-29441.
  • 05Sysdig said JadePuffer encrypted 1,342 Nacos service configuration items, dropped the original config_info and history tables, and created a README_RANSOM extortion table with a demand, Bitcoin address, and Proton Mail contact.

Researchers at Sysdig identified what they believe is the first documented ransomware operation conducted entirely by a large language model agent. The operation, called JadePuffer, used the autonomous AI agent for reconnaissance, credential theft, lateral movement, persistence, privilege escalation, and data encryption. Sysdig said the agent adapted to failures during the intrusion, including moving from a failed login to a working fix in 31 seconds.

JadePuffer gained initial access by exploiting CVE-2025-3248, an unauthenticated remote code execution flaw in Langflow that was fixed on April 1, 2025. After obtaining code execution, the agent dumped Langflow’s PostgreSQL database, collected host information, searched for environment variables and sensitive files, retrieved credentials, and enumerated a MinIO object store. It also established persistence by installing a cron job that beaconed to attacker infrastructure every 30 minutes.

From the Langflow instance, the attacker pivoted to a production MySQL server running Alibaba Nacos, using root credentials whose origin Sysdig could not determine. JadePuffer targeted Nacos with multiple payloads, including one exploiting CVE-2021-29441, and encrypted 1,342 Nacos service configuration items before deleting the originals. Sysdig said the case shows the arrival of “agentic threat actors,” while also noting that LLM-generated payloads may create new detection opportunities for security solutions.

  • The AI agent adapted to errors during the intrusion, including moving from a failed login to a working fix in 31 seconds and changing MinIO parsing logic after receiving XML instead of JSON.
  • The ransom process showed signs of flawed AI-generated behavior, including a Bitcoin address widely used in public documentation and an encryption key that Sysdig said was randomly generated but not stored or transmitted to the attacker.
  • Sysdig said natural-language comments in generated code and rapid, error-specific attack iteration were indicators that an AI agent was controlling the operation.
  • The article notes that while agentic attacks may lower the skill required for damaging cyberattacks, LLM-generated payloads can also create new detection opportunities for security tools.

Researchers say a ransomware group called JadePuffer used an AI agent to carry out an entire break-in, from entering through a flaw in Langflow software to stealing credentials, spreading to another server, and locking 1,342 Nacos configuration items. The affected systems were internet-exposed Langflow and production Nacos services, which can contain important cloud credentials, API keys, and service settings. This matters because the attack suggests AI can now handle many steps of a damaging cyberattack on its own, lowering the skill needed for criminals to cause real disruption.

North Korean Hackers Publish 108 Malicious Packages and Extensions in PolinRider Campaign

North Korea-linked Contagious Interview actors are expanding the active PolinRider supply-chain campaign, publishing or compromising 108 malicious npm, Packagist, Go, and Chrome packages/extensions to infect developer environments. Victims should treat affected systems as compromised, rotate secrets from a clean machine, and audit repositories for hidden VS Code task execution and suspicious config-file changes.
KEY POINTS
  • 01North Korea-linked actors associated with the Contagious Interview campaign have published 108 unique malicious packages and web browser extensions across npm, Packagist, Go, and Google Chrome as part of the PolinRider activity.
  • 02Socket reported that 162 malicious release artifacts correspond to 108 unique packages and extensions, including 19 npm libraries, 10 Composer packages, 61 Go modules, and one Google Chrome extension.
  • 03PolinRider involves obfuscated JavaScript payloads planted in public GitHub repositories to deliver a new variant of BeaverTail malware associated with Contagious Interview.
  • 04As of April 11, 2026, the activity had compromised 1,951 public GitHub repositories associated with 1,047 unique owners and had merged with the TaskJacker cluster that drops malicious VS Code task files into repositories.
  • 05Socket said the latest payload reaches out to TRON, Aptos, and BNB Smart Chain services to fetch an encrypted second-stage payload that unpacks to DEV#POPPER RAT and OmniStealer.

North Korean threat actors linked to the Contagious Interview campaign have been observed publishing 108 unique malicious packages and web browser extensions across npm, Packagist, Go, and Google Chrome as part of an ongoing activity called PolinRider. Socket reported 162 malicious release artifacts across those packages and extensions, including 19 npm libraries, 10 Composer packages, 61 Go modules, and one Google Chrome extension. The campaign remains active, and Socket said new malicious packages are likely to continue appearing as actors compromise maintainer accounts, modify legitimate repositories, and publish infected versions where they retain or obtain registry access.

PolinRider was first flagged by the OpenSourceMalware team in March 2026 as involving obfuscated JavaScript payloads implanted in public GitHub repositories to deliver a new variant of BeaverTail malware associated with Contagious Interview. As of April 11, 2026, the activity had compromised 1,951 public GitHub repositories associated with 1,047 unique owners, and it had merged with the TaskJacker cluster that drops malicious VS Code task files into existing repositories. Those task files can use the runOn: 'folderOpen' option to execute code when a folder is opened in tools such as VS Code or Cursor.

The latest payload acts as a JavaScript loader that reaches out to TRON, Aptos, and BNB Smart Chain services to fetch an encrypted second-stage payload that unpacks to DEV#POPPER RAT and OmniStealer. The article says the actors use tactics such as whitespace padding, fake .woff2 font files, Git history rewriting, force pushes, and anti-dated commits to hide malicious changes and make them appear older. Users who installed affected packages are advised to treat the environment as compromised, rotate exposed secrets from a clean machine, remove affected versions, rebuild from a known good lockfile, and audit workstations and repositories for hidden execution paths or suspicious changes.

  • Visible GitHub commit history is not a reliable way to judge whether a repository is clean because the actors use force pushes and anti-dated commits to make malicious changes appear older and less suspicious.
  • Opening a compromised project folder in tools such as VS Code or Cursor can trigger malicious code automatically through the "runOn: 'folderOpen'" option in VS Code task files.
  • The campaign does not rely only on stolen GitHub credentials; OpenSourceMalware said victims were compromised through malicious VS Code extensions or npm packages, with maintainer account takeovers likely occurring through expired domain takeover or another account recovery path.
  • Defenders are advised to inspect repository activity logs, package release metadata, VS Code task configuration, and suspicious changes to files such as .vscode/tasks.json, config.js, vite.config.js, and eslint.config.js rather than relying on repository landing pages.
  • The latest payload uses blockchain infrastructure from TRON, Aptos, and BNB Smart Chain to retrieve an encrypted second-stage payload that unpacks to DEV#POPPER RAT and OmniStealer.

Hackers linked to North Korea have been putting harmful code into public software libraries and browser add-ons used by developers, as part of a campaign called PolinRider. The people most affected are software developers, especially those approached through fake job interviews or who installed the listed packages, because their computers, accounts, and work projects may be taken over. This matters because the attackers can hide changes in real projects, steal secrets, and spread the infection through software that other people trust and reuse.

U.S. Government Entity Paid Kairos $1 Million in Data-Theft Extortion Case

A likely Union County, Ohio government entity paid Kairos about $1 million after the group stole sensitive data and threatened to leak it, despite no evidence of actual file encryption. The case highlights a growing shift from traditional ransomware to pure data-theft extortion, where paying offers no real guarantee stolen files are deleted.
KEY POINTS
  • 01A U.S. government entity paid about $1 million to Kairos to prevent stolen files from being leaked, according to a Ransom-ISAC case study based on a leaked negotiation chat and blockchain tracing.
  • 02Rakesh Krishnan found no evidence that Kairos used an encryptor, locked machines, or demanded payment for a decryption key, indicating the case was data-theft extortion rather than traditional ransomware.
  • 03The leaked chat points to Union County, Ohio, which reported a May 2025 cyber incident and later notified 45,487 residents and staff that stolen data included Social Security numbers, financial details, fingerprints, and passport numbers.
  • 04The negotiation lasted about a month, with Kairos reducing its demand from $3 million to a final $1 million payment made on June 13, 2025, in roughly 9.44 bitcoin.
  • 05Krishnan traced the payment through wallets toward deposit addresses tied to Bybit, OKX, and BELQI, but the article notes that Kairos’s “proof of deletion” did not prove the stolen files were actually erased.

A U.S. government entity paid about $1 million to keep stolen files from being leaked, according to a Ransom-ISAC case study by Rakesh Krishnan based on a leaked negotiation chat and blockchain tracing. The group that took the payment calls itself Kairos, but Krishnan found no sign that it locked machines or used an encryptor. The article says the threat was to publish stolen files rather than to withhold a decryption key.

The victim is not named in the case study, but the chat points to Union County, Ohio, through file names and statements about a small county with limited resources. Union County said it detected ransomware in May 2025 and later notified 45,487 residents and staff that their data had been taken. The stolen records included Social Security and financial details, fingerprints, and passport numbers.

The negotiation lasted about a month, with Kairos starting at \(3 million and the victim countering at \)100,000 before a final $1 million demand. The payment was roughly 9.44 bitcoin on June 13, 2025, and Krishnan traced it through wallets toward deposit addresses tied to Bybit, OKX, and BELQI. Kairos provided a “proof of deletion” file, but the article notes that such proof only shows the attacker once had the files and does not prove the originals were erased.

  • The most sensitive folders, such as prosecutor’s office records, can become the main pressure point because attackers can threaten harm beyond privacy loss, including helping criminals avoid charges.
  • The case shows that blockchain tracing can identify money flows toward exchange-linked deposit addresses, but the article stresses that this provides investigative leads rather than real-world identities.
  • The negotiation pattern resembled leaked Black Basta chats, suggesting that large opening demands, low victim counteroffers, and eventual million-dollar settlements are a recurring extortion playbook.
  • The article emphasizes that a “proof of deletion” file is not meaningful assurance, because it can show only that attackers once had the files, not that they erased all copies.

The File Format Your Gateway Forgot: EPS Macros Hidden in a Logo ZIP

A real supplier’s DKIM-passing email delivered a logo ZIP that looked harmless but contained EPS vector files with macro-like code, exposing a blind spot in gateways that don’t deeply parse programmable file formats. The key lesson is that authenticated senders and clean first-pass scans are not enough when compromised vendors can send unusual attachment types hidden inside legitimate-looking archives.
KEY POINTS
  • 01A marine manufacturing company received an Italian email from a known supplier with a ZIP attachment named Logo nuovo.zip that appeared to contain new company logo materials.
  • 02A first-pass attachment scan marked the ZIP as clean, but deeper content analysis unpacked it and rated it CRITICAL with a 0.90 score.
  • 03The archive contained a brand-manual PDF and two EPS vector files that were flagged for VBA-like or macro-like strings, while the DOCX files had no macro hits and a PNG signature image was judged low risk.
  • 04The article explains that EPS is a programmable PostScript format that email gateways may treat like a simple image and fail to parse deeply.
  • 05The message passed DKIM from the supplier’s real domain but had no SPF record and no DMARC policy, and the article describes this as likely vendor email compromise.

A marine manufacturing company received a short Italian email from a known supplier announcing a new company logo and attaching a ZIP file named Logo nuovo.zip. The message passed DKIM from the supplier’s real domain and did not ask for money, credentials, or urgent action. The article says the likely pattern was vendor email compromise, where a genuine supplier mailbox is used to send malicious content to trusted contacts.

The ZIP was initially marked clean by a first-pass attachment scan, but deeper content analysis unpacked it and rated it CRITICAL with a 0.90 score. The archive contained 63 entries, including a brand-manual PDF, two EPS logo files, DOCX files, and a PNG signature image. The PDF streams and the two EPS files were flagged for VBA-like or macro-like strings, while the DOCX files had no macro hits and the PNG was judged low risk.

The article highlights EPS as the key blind spot because it is a programmable PostScript format that can be treated by gateways as a simple image rather than parsed as executable instructions. It maps the case to MITRE ATT&CK Spearphishing Attachment T1566.001, with obfuscation and deobfuscation-related techniques also listed. The article’s main defensive point is that attachment scanning should unpack nested archives, inspect document and vector file internals, and not treat a passing authentication result as proof that the sender or attachment is safe.

  • A clean result from a first-pass attachment scan can be misleading when the scan does not unpack archives and inspect the internal streams of less common file types such as EPS.
  • A passing DKIM result can increase trust in a malicious email when the sender’s real supplier account or domain is being abused, because DKIM verifies signing but not intent or attachment safety.
  • Design and branding workflows create a practical blind spot because EPS files are legitimate business assets but are also programmable PostScript files rather than simple static images.
  • The absence of malicious links does not reduce the risk in this case, because the article states the danger was entirely contained in the attachment.
  • Defenders should treat code-like content in formats where it does not belong, including vector and document formats, as a reason to stop delivery rather than relying on file extensions or known-bad hashes.

A marine manufacturer received a short, believable email from a real supplier about a new company logo, with a ZIP file attached that looked like normal design materials but included risky hidden code-like content inside logo files. The first scan said the attachment was clean, while a deeper check found the danger, showing how harmful files can get through when they are disguised as ordinary business documents. This matters because trusted supplier emails can be taken over and used to spread harmful attachments, and one missed email can start a costly security incident.
