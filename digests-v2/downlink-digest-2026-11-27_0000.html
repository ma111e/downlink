KEY POINTS
  • 01CVE-2026-99362, dubbed NFS2ROOT, is a critical heap buffer overflow in the Linux NFS server that can allow remote attackers to gain root privileges.
  • 02The flaw has existed since Linux kernel 3.16, released in March 2014, and affects systems running nfsd with NFSv4.1 or v4.2 when TCP port 2049 is reachable.
  • 03OpenSec disclosed that crafted NFS requests can corrupt kernel memory, defeat address randomization protections, and cause a command to run as root when the attacker closes the NFS connection.
  • 04Patched kernel versions include 6.12.117, 6.18.61, 7.3.2, and 7.4-rc1, and administrators should update and reboot systems to use the fixed kernel.
  • 05No exploitation in the wild has been reported, but organizations that cannot patch immediately should restrict NFS TCP port 2049 to trusted clients or disable the NFS server if it is unnecessary.

A critical Linux kernel flaw tracked as CVE-2026-99362, and dubbed NFS2ROOT, can allow remote attackers to gain root privileges through the Network File System server. The issue was found by ANSSI’s Jérémy Jean, while OpenSec shared a remote-root exploit and patch with NFSD maintainers. It has existed since Linux kernel 3.16, released in March 2014. No exploitation in the wild has been reported.

The flaw is a heap buffer overflow in nfsd affecting systems with NFSv4.1 or NFSv4.2 enabled and TCP port 2049 reachable over the internet. Crafted requests can let an attacker corrupt kernel memory, read memory to bypass KASLR, and place a callback that executes a command after the NFS connection is closed. Affected organizations should update to patched kernel versions and reboot, or restrict port 2049 to trusted networks and disable NFS where it is not required. OpenSec also identified potential warning signs, including nfsd4_check_respsize messages, short bursts of NFSv4.1 sessions, and kernel errors involving nfsd4, svc_, or call_usermodehelper frames.

  • The exploit chain described by OpenSec does not end with a malicious request alone: closing the NFS connection triggers the kernel to execute the attacker’s embedded command with root privileges.
  • Although OpenSec says NFS2ROOT has no network signatures, defenders can look for kernel warnings involving nfsd4_check_resp_size, bursts of short NFSv4.1 sessions from one source, kernel errors with nfsd4_, svc_, or call_usermodehelper frames, and shells launched by kernel worker processes.
  • The issue is specifically exposed when the NFS server is running NFSv4.1 or v4.2 and TCP port 2049 is reachable over the internet, making internet-facing NFS services the immediate priority for patching or access restrictions.
  • If updates cannot be applied immediately, the article identifies two practical containment options: limit TCP port 2049 to trusted clients or networks, or stop and disable the NFS server when file sharing is not needed.

A newly disclosed flaw in Linux, the software that runs many servers, could let someone on the internet take complete control of an affected machine without first logging in. It affects systems running the Linux file-sharing service called NFS, especially when that service is reachable through internet port 2049. The bug has existed since 2014, so it may affect file servers, storage devices, build systems, and systems that provide storage for Kubernetes unless they install updated software or limit who can connect.
