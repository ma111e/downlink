Modern Adventures in Azure Privilege Escalation

Azure privilege escalation analysis should focus on individual RBAC permissions and ABAC conditions, not just role names, because built-in and custom roles can hide dangerous paths. Using this approach, the researchers found and Microsoft fixed a built-in Anyscale role that could allow escalation to Owner via unconstrained role assignments.
KEY POINTS
  • 01Azure’s growth to more than 200 services, 897 built-in RBAC roles, and 22,018 permissions has expanded the Azure attack surface and made privilege escalation mapping more complex.
  • 02The article argues that reviewing individual Azure RBAC permissions, along with ABAC conditions, gives a more thorough view of privilege escalation paths than reviewing role names alone.
  • 03Azure ABAC conditions are used heavily in built-in roles, especially around Microsoft.Authorization/roleAssignments/write, to constrain which role assignments a principal can create or delete.
  • 04The 2023-07-01-preview version of the Azure Role Definitions List API can filter roles by specified permissions and help map dangerous permissions to built-in and custom roles.
  • 05The researchers found that the built-in Anyscale Platform Administrator Role had unconstrained role assignment write and delete permissions, and Microsoft later removed those permissions after the issue was reported to MSRC.

The article examines Azure privilege escalation by focusing on Azure RBAC permissions, ABAC conditions, and how individual permissions can reveal attack paths in built-in and custom roles. It notes that Azure had grown to more than 200 services, 897 built-in RBAC roles, and 22,018 permissions as of June 2026, increasing the attack surface. The author argues that reviewing permissions directly provides a more complete view than reviewing only role names.

A major focus is Azure ABAC, which Microsoft uses in built-in roles to constrain sensitive actions such as Microsoft.Authorization/roleAssignments/write. The article explains that these conditions can limit which roles may be assigned, but also shows that a portal-recommended condition for Owner or User Access Administrator can be bypassed by creating and assigning a custom role because it does not constrain Microsoft.Authorization/roleDefinitions/write. The article also describes privilege escalation categories such as direct RBAC escalation, managed identity access, secrets access, and dependent service control.

The researchers used the 2023-07-01-preview version of the Azure Role Definitions List API to map specific permissions to roles, including permissions such as Microsoft.Storage/storageAccounts/listkeys/action. This process led them to identify the built-in Anyscale Platform Administrator Role as allowing unconstrained role assignment write and delete permissions, making it equivalent in that respect to highly privileged roles like Owner, User Access Administrator, and Role Based Access Control Administrator. Microsoft removed those role assignment permissions after the issue was reported to MSRC.

  • Microsoft’s portal-recommended condition for limiting Owner or User Access Administrator role assignment can still be bypassed because it blocks only specific privileged role IDs and does not constrain permissions such as Microsoft.Authorization/roleDefinitions/write.
  • A role that appears service-specific can have tenant-wide security impact if it includes Microsoft.Authorization/roleAssignments/write without ABAC constraints, as shown by the Anyscale Platform Administrator Role.
  • Control-plane permissions can sometimes provide data-plane access, such as Microsoft.Storage/storageAccounts/listkeys/action granting access to Storage Account shared access keys and therefore full data access to Blob Storage and File Shares.
  • Roles that administrators may not expect to grant Storage Account data access, including Azure AI Administrator, Log Analytics Contributor, and Virtual Machine Contributor, contain Microsoft.Storage/storageAccounts/listkeys/action.
  • The undocumented 2023-07-01-preview Role Definitions List API reduces the need for manual wildcard and NotActions resolution when identifying roles that contain specific permissions.

The article explains how access permissions in Microsoft Azure can create hidden paths for someone to gain much more control than they were meant to have. The researchers found one built-in Azure role, called the Anyscale Platform Administrator Role, that could have let a person give themselves full Owner-level control, and Microsoft later removed the risky permissions. This matters for organizations using Azure because even official built-in roles can include unexpected powers, especially when assigned too broadly. The broader risk is that a mistake or a compromised account with one of these roles could lead to control over many cloud resources.

This is a specific Azure privilege escalation research finding with broad relevance for cloud security teams, including a built-in role that Microsoft changed after MSRC reporting. It is not active exploitation or an emergency patch story, but the permission-focused methodology and ABAC bypass discussion are highly actionable for Azure defenders.

MECCHA CHAMELEON can't hide from the RCE

Researchers found that malicious MECCHA CHAMELEON custom maps could abuse Unreal Engine audio recording functions to write attacker-controlled files to a victim’s Windows Startup folder, enabling delayed remote code execution after reboot. The issue was reported to the developers and patched in version 4.0.0.
KEY POINTS
  • 01Researchers found that MECCHA CHAMELEON custom maps could abuse the exposed Unreal Engine function StopRecordingOutput to write files to arbitrary locations on a victim’s filesystem.
  • 02The attack worked because maps can contain Unreal Engine Blueprints that run inside the MECCHA CHAMELEON process when a map is loaded.
  • 03The proof of concept wrote a file into the Windows Startup folder so it would execute after the victim’s system restarted.
  • 04The researchers used a null character in the filename to bypass Unreal Engine’s automatic .wav suffix and created an HTA payload inside an uncompressed PCM WAV recording.
  • 05The developers fixed the vulnerability in MECCHA CHAMELEON 4.0.0 by preventing StopRecordingOutput from creating files, and the update is installed automatically before launching the game.

Researchers found a delayed remote code execution issue in MECCHA CHAMELEON involving attacker-made custom maps. When a victim played on an attacker’s map, the map could abuse an exposed Unreal Engine function to write files to arbitrary locations on the victim’s system. The issue was reported to the game’s maintainers and fixed in the 4.0.0 update, which is automatically installed before launching the game.

The article explains that MECCHA CHAMELEON maps can contain Unreal Engine Blueprints, which are visual scripts that run inside the game process when a map loads. Because lobby hosts can pick a custom map and prompt other players to download it, community maps became an important attack surface. The researchers searched Blueprint-callable functions and focused on ones that interacted with the operating system, eventually identifying the audio recording function Finish Recording Output.

The proof of concept used audio recording to create a file in the Windows Startup folder, then used a null character in the filename to bypass Unreal Engine’s automatic .wav suffix. Because the written file contained WAV data rather than a normal executable, the researchers embedded an HTA payload inside uncompressed PCM audio samples so mshta.exe would run the script despite the WAV header. The patched version prevents StopRecordingOutput from creating files, and the researchers said they found no Steam Workshop maps already exploiting the issue.

  • The attack surface came from a legitimate convenience feature: lobby hosts can pressure all players to download the selected community map before a match starts.
  • A function intended for saving audio became dangerous because it accepted attacker-controlled paths and ran with the player’s normal filesystem permissions.
  • The proof of concept depended on a mismatch between Unreal Engine’s simple string handling and Windows path interpretation, where a null character could cause the added .wav suffix to be ignored.
  • The researchers avoided needing a normal Windows executable by using an HTA file, because mshta.exe would ignore the WAV header bytes and still run the embedded script.
  • The patch removed file creation from StopRecordingOutput entirely, showing that the maintainers chose to eliminate the risky capability rather than only filter specific malicious paths or filenames.

The article explains how a custom map for the game MECCHA CHAMELEON could secretly make the game save a harmful file onto a player’s Windows computer when they joined a match using that map. Players who downloaded and played attacker-made maps were affected because the file could run after the computer restarted, giving the attacker a way to make the victim’s computer run their code. This matters because community-made game content can do more than just add scenery, so downloading maps from strangers can carry real computer-safety risks. The developers fixed the reported problem in version 4.0.0, which is installed automatically before the game launches.

OPEN SOURCE ↗

This is a concrete technical analysis of a patched remote code execution path in a widely played game, with useful lessons about user-generated content, exposed scripting functions, and unsafe file writes. It is not a must-read because the issue has been fixed, no exploitation was found in Steam Workshop maps, and the affected product is relatively narrow for most security professionals.

Malware on the Blockchain: An Ongoing Campaign’s New WebRTC Twist

Netskope found an ongoing EtherHiding campaign using BNB Smart Chain testnet contracts to deliver payloads through more than 5,400 compromised small-business websites. A newer variant replaces the usual ClickFix lure with a covert WebRTC data-channel stager that bypasses normal signaling and pulls executable code directly from attacker-controlled infrastructure.
KEY POINTS
  • 01Netskope observed more than 5,400 compromised small-business websites making JSON-RPC calls to BNB Smart Chain testnet endpoints to retrieve payloads from a smart contract.
  • 02The compromised sites, often WordPress and sometimes PrestaShop, carried an injected loader as either an inline script or a spoofed package, but the initial compromise method is unknown.
  • 03The common delivery chain retrieves a second-stage script from the blockchain that displays a ClickFix lure instructing visitors to paste and run a command that downloads the final payload.
  • 04A newer variant delivers a WebRTC data-channel stager that hand-writes its own session answer to open an encrypted UDP channel to the attacker without normal signaling traffic.
  • 05The WebRTC stager buffers code received from the command channel and executes it in the browser by injecting a script into the page, reusing an existing Content Security Policy nonce when available.

Netskope observed an EtherHiding campaign affecting more than 5,400 compromised small-business websites across more than 2,200 organizations worldwide. The compromised sites include businesses such as clinics, plumbers, and e-commerce shops, and were most often WordPress and sometimes PrestaShop where individual sites were examined. Each site carried an injected loader, either as an inline script or spoofed package, that called a BNB Smart Chain testnet endpoint and retrieved the next payload from a smart contract.

The campaign uses the BSC testnet as takedown-resistant payload storage because it behaves like mainnet but uses free testnet BNB from faucets. This lets the operator update a single contract and change what all compromised sites deliver to visitors on the next page load. The common chain delivers a ClickFix overlay that blurs the page behind a fake CAPTCHA and instructs visitors to paste and run a command that downloads and runs the final payload.

Netskope also found a newer variant that delivers a WebRTC data-channel stager instead of the ClickFix overlay. This script hand-writes its own WebRTC answer using hardcoded connection values, opening an encrypted UDP channel to the cyberattacker without the normal signaling handshake. Once the channel opens, the stager buffers code sent over it and executes the reassembled result in the browser by injecting a script into the page, reusing an existing Content Security Policy nonce when available.

  • Blocking only the primary BSC testnet endpoint is insufficient because Netskope recommends blocking the full BSC-testnet RPC pool for this campaign.
  • The use of BSC testnet gives the operators mainnet-like smart-contract hosting and takedown resistance without transaction cost because testnet BNB is free from faucets.
  • The operator can change what all compromised sites deliver by updating a single smart contract, so the same compromised website network can rapidly shift payloads for future visitors.
  • The WebRTC variant reduces visibility for defenders because it avoids the normal signaling-server exchange while still opening an encrypted channel that HTTP inspection may not see.
  • Site owners can look for the loader by integrity-checking CMS assets, since Netskope observed it appended to legitimate JavaScript files or placed in fake plugin directories.

Researchers found that more than 5,400 small-business websites, including clinics, plumbers, and online shops, had been secretly altered to load harmful instructions for visitors. Some versions try to trick people into running a command on their computer, while a newer version quietly opens a hidden connection in the browser to receive more instructions. This matters because the attackers store and change their instructions in a place that is hard to remove, so many unrelated websites can be made to deliver new threats at once.

OPEN SOURCE ↗

This is a must-read because it reports an ongoing in-the-wild campaign affecting more than 5,400 compromised websites and using blockchain smart contracts as resilient payload storage. The newer WebRTC command-channel variant is technically notable and actionable for defenders because it can avoid normal signaling visibility and HTTP inspection.

Urgent Threat Alert: ShinyHunters Vishing Campaigns and Domain Impersonation

Health-ISAC warns that ShinyHunters is actively targeting global healthcare organizations with vishing and lookalike domains to steal SSO credentials and bypass MFA. Organizations should urgently block suspicious .claim/.claims domains, harden MFA and helpdesk workflows, monitor impersonation infrastructure, and restrict access to verified corporate devices.
KEY POINTS
  • 01Health-ISAC warns that ShinyHunters is actively targeting the global health sector with persistent, highly targeted voice phishing campaigns using malicious medical-themed impersonation domains.
  • 02The campaigns attempt to trick employees into entering credentials on fake login pages and have succeeded in some recent cases by bypassing multi-factor authentication.
  • 03After compromising an identity, the actors rapidly pivot from single sign-on platforms into connected SaaS applications such as Microsoft 365, SharePoint, and Salesforce to exfiltrate data and internal communications.
  • 04Observed impersonation domains commonly use the target company’s name followed by patterns such as company-claims.com or company.claims.
  • 05Health-ISAC recommends blocking .claim and .claims domains unless legitimate, improving employee awareness, enforcing device-context verification, adopting phishing-resistant MFA, hardening helpdesk and MFA reset workflows, and monitoring lookalike infrastructure.

Health-ISAC warns that ShinyHunters is actively targeting the global health sector with persistent, highly targeted vishing campaigns and medical-themed impersonation domains. The campaigns try to trick enterprise personnel into exposing credentials on fake sites that mimic legitimate login pages. Health-ISAC says the group has been successful in several recent cases by bypassing MFA and gaining unauthorized access.

The article says the most identifiable domain pattern is the use of company-claims.com or company.claims to impersonate a target company. Actors have contacted employees on personal mobile devices through calls and voicemails, and have also emailed users en masse from multiple random accounts. Recent registrations of medical-themed domains indicate an expanding scope targeting health operations and specialized business units.

Once an identity is compromised, ShinyHunters rapidly pivots from the SSO platform into connected SaaS applications such as Microsoft 365, SharePoint, and Salesforce. The article says this enables large-scale data exfiltration and access to internal communications, which supports later extortion demands. Health-ISAC recommends blocking .claim and .claims domains unless legitimate, improving employee training, enforcing device-context verification, adopting phishing-resistant MFA, hardening helpdesk and MFA reset workflows, monitoring lookalike infrastructure, and improving session management.

  • Health-ISAC characterizes ShinyHunters as behaving less like a traditional ransomware group and more like an identity- and SaaS-access extortion operation.
  • The article identifies the SSO platform as the attackers’ main control point, because one compromised identity can give them access to multiple connected cloud applications.
  • The campaign’s domain pattern is highly actionable for defenders because impersonation sites often use the target company name followed by endings such as company-claims.com or company.claims.
  • The actors are instructing victims to use personal devices to navigate to malicious links, which is why the article emphasizes restricting access to corporate-managed devices rather than relying on identity checks alone.
  • The article says attackers use reverse-proxy phishing kits to relay stolen credentials to the real login portal in real time, then pressure the victim by phone to provide or approve an active MFA step.

Health-ISAC warns that the ShinyHunters cybercrime group is targeting health organizations around the world by calling, leaving voicemails, and emailing employees to trick them into entering work login details on fake medical-themed websites. Some attacks have succeeded, letting the criminals get into company systems such as Microsoft 365, SharePoint, and Salesforce and steal large amounts of sensitive data. This matters because stolen access can expose private health-sector information and give criminals leverage to demand money from affected organizations.

OPEN SOURCE ↗

This is a must-read alert about active ShinyHunters campaigns targeting the global health sector with vishing, domain impersonation, MFA bypass, and SaaS data exfiltration. It reports recent observed activity and provides concrete defensive actions for organizations at immediate risk.
