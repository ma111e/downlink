13 Malicious NuGet Packages Turn Fake .NET Job Assessments Into Malware Delivery Traps

Researchers uncovered 13 malicious NuGet packages disguised as .NET UI controls and linked to fake job assessments, which execute payloads through MSBuild hooks, GitHub downloads, and DLL sideloading of Windows osk.exe. The campaign also ties to fake Axios repositories and freelance job lures targeting developers, though attribution remains unconfirmed.
KEY POINTS
  • 01Researchers identified 13 malicious NuGet packages masquerading mainly as WinUI 3 and WPF button controls, all of which had been removed from the NuGet gallery at the time of reporting.
  • 02A fake GitHub take-home assessment for a WinUI 3 project referenced malicious packages that could run code after each project build, download files from GitHub, and use the Windows On-Screen Keyboard executable to load a malicious DLL.
  • 03Other packages, including WinUI.Button, downloaded and ran Windows executables from GitHub when developers created particular button controls.
  • 04The campaign was promoted through a LaborX freelance listing seeking a C# WPF developer for a crypto-wallet inventory application and offering $8,500 to $10,000.
  • 05Researchers found related fake Axios repositories and npm packages that downloaded Windows executables, including a loader using GitHub for command-and-control and a program that stole Google Chrome profile information.

Researchers identified 13 malicious NuGet packages that posed primarily as WinUI 3 and WPF button controls for Windows .NET developers. The packages were tied to a fake GitHub take-home job assessment that asked candidates to enhance a FileButton control and handle exceptions. All identified packages had been removed from the NuGet gallery when the article was published. The campaign demonstrates how a seemingly legitimate coding task can expose job seekers to harmful software.

The assessment project referenced packages that could run code after every build, download files from GitHub, and copy the Windows On-Screen Keyboard program alongside a malicious file so that the trusted program loads it. Other packages downloaded and ran Windows executables when particular button controls were created. Socket also linked the activity to counterfeit Axios repositories and npm packages, including tools that used GitHub for remote control, stole Google Chrome profile data, or sent system details to a Telegram bot. A related LaborX listing advertised a C# WPF job involving software that inventories cryptocurrency wallets, while researchers said the campaign has not been attributed to a named threat actor or group.

  • The malicious MSBuildAnalyzer package was designed to execute its bundled code automatically after every project build, meaning simply building the supplied assessment could trigger the download of a harmful file.
  • After NuGet removed the VS_Builder packages, similarly named HappyOne packages were uploaded and the assessment was changed to reference the replacement WinUI controls package.
  • Some harmful behavior was embedded in seemingly ordinary user-interface components, so creating a button control could download and run a Windows executable.
  • The related activity used GitHub not only to host assessment code and payloads, but also as a channel for a loader to receive commands and as a destination for stolen Chrome-profile data.
  • The operators used names resembling the legitimate Axios maintainer’s account, alongside counterfeit Axios repositories and npm packages, to make malicious dependencies appear credible.

Researchers found 13 harmful software add-ons on NuGet, a site where .NET developers download code, disguised as ordinary Windows button controls and included in a fake job test. When a job candidate builds or runs the provided project, the hidden code can download and start unwanted programs on their Windows computer, including by making a trusted Windows tool load a harmful file. This matters because attackers can use realistic freelance listings and coding assessments to target developers, potentially gaining access to their files, browser wallet information, and computer details.

OPEN SOURCE ↗

This is a concrete software supply-chain campaign targeting .NET developers through malicious NuGet packages and fake recruitment assessments, with automatic build-time execution and related npm/GitHub infrastructure. It has broad relevance for developer security and hiring workflows, though the packages were removed and the article does not report confirmed victim impact.

1Password Hacked, Customer Data and Source Code Stolen in GitHub Account Breach

1Password said an attacker compromised an employee’s GitHub account, accessed backend systems, copied private source code, and obtained limited customer account metadata. The company says encrypted vault contents, passwords, recovery keys, and encryption keys were not accessed.
KEY POINTS
  • 011Password disclosed that an attacker gained access to an employee’s corporate GitHub account on November 19, 2026 and used it to access backend systems.
  • 02The attacker accessed a limited amount of customer account information, including names, email addresses, account and user identifiers, public keys, Secure Remote Password protocol parameters, and tokens in certain emailed links.
  • 031Password said no customer vault contents, passwords, account recovery keys, or the keys used to secure vaults were accessed or compromised.
  • 04The attacker copied source code from private repositories and gained access to 1Password’s CI/CD system, according to the company.
  • 051Password said it disabled the affected GitHub account, revoked the stolen token, restored clean versions of affected services, rotated internal credentials, and lengthened invitation and recovery email codes.

1Password disclosed that an attacker gained access to an employee’s corporate GitHub account on November 19, 2026. The attacker used the account to access some backend systems, copy source code from private repositories, and gain access to the company’s CI/CD system. 1Password said it detected suspicious activity, contained the incident, and disabled the affected GitHub account.

The attacker accessed a limited amount of customer account information from a subset of customers, including names, email addresses, account identifiers, account creation and sign-in times, public keys, Secure Remote Password parameters, and tokens included in certain emailed links. 1Password said customer vault contents, passwords, other vault items, account recovery keys, and the keys securing them were not accessed or compromised. The company revoked the stolen token, restored clean service versions, rotated internal credentials, hardened controls, and expanded invitation and recovery email codes from six digits to ten characters. Customers were advised to remain alert for unexpected phishing attempts, while a small number of affected users were notified individually.

  • The exposed invitation, provisioning, and recovery-link tokens cannot by themselves unlock customer accounts because access also requires single sign-on authentication or a verification code sent to the registered email address.
  • 1Password increased invitation and recovery email codes from six digits to ten characters as a precaution after the incident.
  • Although password vaults were not accessed, the exposure of names and email addresses creates a reason for customers to be alert for unexpected phishing attempts.
  • The company said the copied private source code contained no user secrets and that the incident did not affect service availability or product security.

1Password said someone got into an employee’s company GitHub account and used that access to view some customer account details and copy company source code. The affected information included some customers’ names, email addresses, account activity details, and certain links used for invitations or account recovery; a small number of people were notified directly. The company says users’ stored passwords and other vault contents were not accessed, but customers should watch for unexpected phishing messages because exposed contact details could be used to make scams seem more convincing.

OPEN SOURCE ↗

This is a significant incident involving 1Password, in which an attacker accessed backend systems, private source code, CI/CD infrastructure, and limited customer account information. Although 1Password says vault contents and encryption keys were not compromised, the event has broad relevance because of the company’s role as a password-management provider and the phishing risk to affected customers.
