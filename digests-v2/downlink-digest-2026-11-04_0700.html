Hackers use n-day exploits in zero-click attacks on iOS, Android devices

APT29-linked attackers used compromised and spoofed websites to silently profile iOS and Android visitors and deliver device-specific exploit chains that stole cookies, credentials, messaging data, and other sensitive information. Apple and Google have patched the exploited flaws, so users should install the latest available updates.
KEY POINTS
  • 01Sekoia attributed a large-scale watering-hole campaign to APT29 with moderate-to-high confidence, targeting iOS and Android users through compromised websites and lookalike domains.
  • 02Injected JavaScript profiled visitors’ devices and browser versions, after which a command-and-control server delivered platform-specific exploit chains without requiring user interaction.
  • 03The iOS exploit chains targeted Safari cookies and, on iOS 18.5, could collect WhatsApp and Telegram databases, Keychain credentials, location data, and photos.
  • 04The Android chain targeted Chrome versions 139 through 145 except 143 and used AndroSnitch to collect Chrome cookies, login data, browsing history, and saved Wi-Fi credentials.
  • 05Apple and Google have patched the vulnerabilities used in the campaign, and Sekoia said the payloads did not establish persistence, so rebooting ends the malicious activity until the victim revisits a compromised site.

Sekoia linked a large-scale watering-hole campaign to the Russian APT29 group with moderate-to-high confidence. The operation targeted iOS and Android users who visited compromised legitimate websites or lookalike domains impersonating real portals in the United States, Ukraine, the Czech Republic, and Bulgaria. The attackers also compromised Plerdy’s SEO tracker, which was loaded by thousands of websites, mostly in Ukraine, from August 27 through September 3.

Injected JavaScript first profiled visitors’ devices and browser versions, then a command-and-control server delivered a matching exploit chain without requiring the victim to interact. The iOS chains could steal Safari cookies, WhatsApp and Telegram databases, Keychain credentials, location data, and photos, while the Android chain used AndroSnitch to collect Chrome cookies, login data, browsing history, and saved Wi-Fi credentials. Apple and Google have patched all flaws used in the campaign, and Sekoia said the payloads did not establish persistence, meaning a reboot stops the malicious activity unless the user visits a compromised site again.

  • The compromise of Plerdy’s SEO tracker exposed visitors across thousands of sites, mostly in Ukraine, between August 27 and September 3 rather than relying only on individually compromised websites.
  • The lookalike America250 and Raffles London at The OWO domains relayed content from the genuine sites, making the fraudulent sites appear more convincing while enabling attackers to intercept visitors.
  • The campaign used already-known flaws with available fixes rather than undisclosed flaws, making timely Apple and Google updates a direct protective measure.
  • The analyzed payloads did not remain active after a reboot, but a device could be targeted again if its user revisited a compromised site.

Researchers say a Russian-linked group used hacked websites and convincing copies of real sites to target people using iPhones and Android phones. Simply visiting one of these sites could let the attackers identify the visitor’s device and use known software flaws to steal browser cookies, passwords, chat-app data, photos, location information, and saved Wi-Fi details. The affected flaws have been fixed by Apple and Google, so installing the latest phone and browser updates is important to reduce the risk.

Google Issues Patches for Critical Android Flaw That Could Allow RCE Without User Interaction

Google’s November 2026 Android security update fixes CVE-2026-58868, a critical heap buffer overflow affecting Android 14–17 that could enable remote code execution without user interaction. Users should install the 2026-11-01 patch level or later, while the 2026-11-05 level includes all November fixes.
KEY POINTS
  • 01Google’s November 2026 Android security bulletin fixes CVE-2026-58868, a critical flaw affecting Android 14 through 17 that could allow remote code execution without user interaction.
  • 02CVE-2026-58868 is an out-of-bounds write caused by a heap buffer overflow in the onOutputReceived function in FrameDecoder.cpp.
  • 03Android devices need the 2026-11-01 security patch level or later for fixes covering CVE-2026-58868, while the 2026-11-05 patch level covers every flaw in the November bulletin.
  • 04Another critical flaw, CVE-2026-58882, could allow a remote denial-of-service attack through Android’s WAP Push SMS message code without user interaction.
  • 05Google’s November bulletin lists 216 vulnerabilities, including 23 rated Critical, and reported no known exploitation as of November 4.

Google’s November 2026 Android security bulletin fixes CVE-2026-58868, a Critical flaw that could allow remote code execution without any user interaction. The issue affects Android 14 through 17 and is fixed by the 2026-11-01 security patch level or later. As of November 4, Google had not reported known exploitation of the bulletin’s vulnerabilities.

CVE-2026-58868 is an out-of-bounds write caused by a heap buffer overflow in the onOutputReceived function of FrameDecoder.cpp. Google’s bulletin and the CVE record do not explain how an attacker could reach the affected code, and Google’s Critical rating assumes built-in Android and Google-service protections are disabled or bypassed. The 2026-11-05 patch level includes all November fixes, including issues in the kernel and components from Arm, Imagination Technologies, MediaTek, Unisoc, and Qualcomm.

The bulletin also includes CVE-2026-58882, a Critical issue in Android’s WAP Push text-message code that could enable a remote denial-of-service attack without user interaction. A related researcher write-up says a malformed WAP Push message can crash the phone service, terminate active calls including emergency calls, and trigger repeated crashes during startup because the device retries the message. Google’s November bulletin lists 216 vulnerabilities in total, including 23 rated Critical.

  • The Android security update date, rather than the Google Play system update date, is the one users must check for CVE-2026-58868 because that flaw is not included in this month’s Google Play system update list.
  • Google uses two November patch levels: 2026-11-01 delivers fixes common across Android devices sooner, while 2026-11-05 includes additional fixes for the kernel and components from hardware vendors.
  • A malformed WAP Push text message described in the article can crash the phone service without appearing in the recipient’s inbox, and the phone may crash again at startup as it retries processing the message.
  • The reported WAP Push issue can end an active call, including an emergency call, and requires an attacker to know only the target’s phone number.

Google released fixes for a serious Android problem that could let someone take control of a phone from a distance without the owner doing anything. It affects phones running Android 14 through 17, and users need an Android security update dated November 1, 2026 or later to receive the main fix. The update also addresses other serious problems, including one that could let a specially made text message repeatedly crash a phone and interrupt calls, so installing updates promptly helps protect phones and their users.

Russian Police Arrest 3 Suspected VasyGrek Hackers, Dismantle Criminal Infrastructure

Russian police arrested three suspected members of the financially motivated VasyGrek (Fluffy Wolf) hacking group and dismantled infrastructure used to phish organizations and steal funds. The group has targeted organizations across Russia, Belarus, and Kazakhstan using phishing-delivered malware and remote-access tools.
KEY POINTS
  • 01Russian authorities arrested three suspected VasyGrek members, searched their residences and offices, and seized computers, communication devices, and other evidence.
  • 02The Russian Interior Ministry said the group is suspected of stealing funds from organizational accounts and creating, distributing, and using malicious software.
  • 03In a September 2025 case, attackers allegedly sent a fake business email carrying a supposed reconciliation report, leading to the theft of 660,000 rubles from an unnamed organization.
  • 04Kaspersky recorded more than 100 attempted VasyGrek attacks against organizations in Russia, Belarus, and Kazakhstan between January and September 2026.
  • 05The group primarily targeted metallurgical organizations, wholesale suppliers, and government agencies, while healthcare, oil and gas, energy, finance, and agriculture organizations were also affected.

Russian authorities arrested three suspected members of the VasyGrek, or Fluffy Wolf, threat group and said they dismantled its criminal infrastructure. The Russian Interior Ministry said the suspects are accused of stealing money from organizational accounts and creating, distributing, and using malicious software. Searches of residences and offices resulted in the seizure of computers, communication devices, and other evidence.

In one September 2025 case, the attackers allegedly sent a phishing email disguised as business correspondence with a supposed reconciliation report, which led to malware execution and the theft of 660,000 rubles from an organization’s bank account. Authorities said the group used phishing domains imitating financial and accounting services, foreign-hosted virtual servers, and covert remote-administration tools obtained from the dark web. Kaspersky recorded more than 100 attempted VasyGrek attacks against organizations in Russia, Belarus, and Kazakhstan from January through September 2026, primarily affecting metallurgical organizations, wholesale suppliers, government agencies, and several other sectors.

  • VasyGrek reportedly combined a large network of fake financial and accounting websites with servers located abroad, making its phishing operations harder to trace and disrupt.
  • The group expanded beyond its earlier focus on Russian organizations to include potential victims in Belarus and Kazakhstan during 2026.
  • Its use of legitimate online services to host harmful components and multi-stage delivery methods was specifically intended to conceal activity and complicate investigation.
  • The alleged September 2025 theft of 660,000 rubles shows that a phishing email disguised as routine financial correspondence could directly lead to money being transferred from an organization’s bank account.

Russian police arrested three people suspected of belonging to VasyGrek, a group accused of tricking companies with fake business emails and stealing money from their bank accounts. The group reportedly targeted organizations in Russia, Belarus, and Kazakhstan, including industrial, government, healthcare, energy, finance, and agriculture organizations. The case matters because the group used convincing financial-document lures and online services to hide its activity, showing how a single deceptive email can lead to financial losses and disruption across important sectors.

UK Cybercrime Journal: Beacon CRM Breach Impacts Over 1,500 Charities

Beacon CRM exposed database backups for more than 1,000 UK charities after an AWS access key was leaked in public JavaScript artifacts, putting donor and service-user personal data at risk. The incident underscores the supply-chain impact of poor secret management and overly broad cloud access permissions.
KEY POINTS
  • 01Beacon CRM reported that attackers used an AWS access key exposed in publicly accessible JavaScript build artifacts to gain access around 27 July 2026.
  • 02From 27 to 28 July 2026, the attackers downloaded full database backups containing records from more than 1,000 UK charity customers.
  • 03The affected backups included names, email addresses, phone numbers, home addresses, donation histories, and uploaded attachments, but did not contain payment card numbers or live bank details.
  • 04Beacon CRM detected the unauthorised activity on 29 July, revoked the exposed credentials, and began notifying affected organisations between 30 July and 3 August.
  • 05The article states that some stored backups contained historical records and data that individuals had previously requested be deleted.

Beacon CRM, a UK customer relationship management platform serving more than 1,500 non-profit and charitable organisations, suffered a cyber incident in late July 2026. Attackers reportedly gained access around 27 July using an AWS access key exposed in publicly accessible JavaScript build files. Between 27 and 28 July, they downloaded full database backups containing records from more than 1,000 UK charity customers.

The backups contained names, email addresses, phone numbers, home addresses, donation histories, and uploaded files such as Gift Aid declarations and user notes, although they did not contain payment card numbers or live bank details. Some charities said older records and information that people had requested be deleted were retained in backups and were therefore exposed. Beacon detected the activity on 29 July, revoked the credentials, and began notifying affected organisations from 30 July to 3 August.

The article says the incident demonstrates how a security problem at a central software supplier can affect many smaller organisations that rely on it. It also warns that the exposed information could be used for targeted scams, phishing, and identity fraud against donors and vulnerable service users. Its recommended measures include automated secret scanning before software is published, limiting what cloud access keys can reach, planning for supplier incidents, and rotating connected credentials after an upstream compromise.

  • The incident shows that data retained in backups can expose people’s historical records even after they have requested deletion from the live system.
  • Although payment card numbers and live bank details were not stored in the affected database, the combination of contact details, home addresses, donation histories, Gift Aid declarations, and user notes can support targeted scams and identity fraud.
  • A publicly exposed application-layer AWS key was able to access full database backups, highlighting the importance of ensuring such credentials cannot read or export sensitive backup stores.
  • Because Beacon CRM served more than 1,500 non-profit and charitable organisations, one supplier credential exposure created a cascading incident for many organisations with limited in-house security resources.

Beacon CRM, a UK service used by charities to manage supporter information, had copies of its customer databases taken after an access key was accidentally left visible in public website code. More than 1,000 charities may be affected, and the copied information included names, contact details, home addresses, donation histories, and some uploaded documents, including records that people had previously asked to be deleted. Although payment card and live bank details were not included, the information could be used to trick donors and vulnerable service users through convincing scams or identity fraud. The incident shows how a security mistake at one widely used supplier can create problems for many smaller organisations at once.

OPEN SOURCE ↗

This reports a concrete, high-impact supply-chain incident in which exposed AWS credentials enabled the theft of database backups affecting more than 1,000 UK charities. It is broadly relevant because it illustrates the downstream impact of leaked cloud credentials and overly permissive access to sensitive backup data.
