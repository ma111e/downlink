The challenge of defending against bulletproof dead drops on public blockchains

Threat actors are using immutable public blockchains—including Bitcoin, EVM smart contracts, TRON, and Solana memo transactions—as resilient dead drops for encrypted C2 configuration data that cannot be conventionally taken down. Defenders should shift from domain blocklists toward detecting anomalous blockchain JSON-RPC queries and in-memory decryption activity on endpoints.
KEY POINTS
  • 01Threat actors are using public blockchains as resilient dead drop resolvers to store encrypted command-and-control configuration data that cannot be removed through conventional domain or hosting takedowns.
  • 02The Glupteba botnet used Bitcoin transactions to retrieve AES-encrypted command-and-control domains and fallback addresses from public Electrum server queries.
  • 03EtherHiding uses EVM-compatible smart contracts to store encoded command-and-control destinations that malware can retrieve through read-only JSON-RPC calls such as eth_call.
  • 04Researchers reported that North Korea-aligned actors, including UNC5342 and UAT-12643, have used blockchain-based mechanisms involving BNB Smart Chain, TRON, or Solana memo transactions to obtain payload locations or command-and-control URLs.
  • 05The article recommends that defenders monitor anomalous outbound blockchain JSON-RPC activity, inspect unexpected encoded data in requests, and detect in-memory decryption before malware contacts the resolved destination.

Threat actors are increasingly using public blockchains as durable repositories for command-and-control (C2) configuration data, replacing centralized servers and domains that defenders can seize, sinkhole, or block. Encrypted C2 addresses, payload locations, and instructions can be stored in immutable transaction records, smart contracts, wallet activity, or Solana memo data. This removes the traditional single point of failure associated with a hardcoded C2 domain or IP address. Malware can retrieve the data through public blockchain services and then connect to the current operational destination.

The article describes earlier Bitcoin-based use by the Glupteba botnet, which queried Electrum servers and extracted AES-encrypted C2 information from transactions. It also describes EtherHiding, in which actors use EVM-compatible smart contracts, including BNB Smart Chain contracts, to store encoded C2 destinations retrieved through read-only eth_call requests. UNC5142, linked to ClearFake, and North Korea-linked UNC5342 are cited as groups that adopted this technique, while UAT-12643 is described as using Solana Memo Program transactions to store encrypted C2 URLs. TRON is also presented as part of multi-chain fallback designs that can make disruption more difficult.

The article argues that traditional domain blocklists and hosting takedowns are insufficient when the C2 discovery information is preserved across decentralized ledgers. It recommends baselining legitimate blockchain use and detecting automated or high-frequency outbound JSON-RPC calls, including eth_call, getTransaction, and getSignaturesForAddress. Defenders are also encouraged to inspect suspicious encoded data in RPC traffic and prioritize endpoint telemetry that can identify in-memory decryption before malware connects to a resolved C2 server.

  • Read-only smart-contract queries such as eth_call let malware retrieve current command-and-control details without creating a new blockchain transaction, so the retrieval itself leaves no transaction record on the ledger.
  • Although blockchain records are immutable, smart contracts can hold configuration values that attackers update through later transactions, allowing compromised systems to obtain replacement destinations without receiving a new malware binary.
  • Solana memo transactions can provide a lightweight update channel: an attacker can publish a new encrypted destination in a fresh transaction, and malware can retrieve the newest transaction associated with a wallet during its next polling cycle.
  • The article notes that blocking a single malicious website or server is insufficient when attackers use multiple chains such as BNB Smart Chain, TRON, and Solana as fallback sources for command-and-control information.
  • The same public blockchain lookups used by malware can resemble legitimate activity, making behavioral monitoring of automated JSON-RPC calls and endpoint memory more useful than static domain blocklists alone.

The article explains how criminal and state-backed groups can hide the internet addresses used to control harmful software inside public blockchain records, which are shared widely and cannot easily be removed. Infected computers can look up these hidden addresses and receive new instructions even after defenders shut down known websites or servers. This affects organizations and individuals whose devices are compromised, and it makes stopping long-running malicious campaigns harder because defenders must watch for suspicious connections to blockchain services instead of only blocking bad websites.
