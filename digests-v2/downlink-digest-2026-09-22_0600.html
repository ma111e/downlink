CISA orders feds to patch Zyxel flaw exploited for data theft

CISA has added CVE-2026-7273, an actively exploited command-injection flaw in Zyxel GS1900 switches, to its Known Exploited Vulnerabilities catalog and ordered U.S. federal agencies to patch it. GreyNoise reports that attackers have compromised nearly 1,000 vulnerable switches worldwide and exfiltrated sensitive data.
KEY POINTS
  • 01CISA added CVE-2026-7273, an actively exploited high-severity flaw affecting Zyxel GS1900 series switches, to its Known Exploited Vulnerabilities Catalog.
  • 02The flaw allows an unauthenticated person on a local network to run operating-system commands on affected switches through specially crafted web requests.
  • 03Zyxel released firmware updates for affected GS1900 switch models on June 16 and advised customers to upgrade for protection.
  • 04CISA ordered Federal Civilian Executive Branch agencies to secure affected switches by Thursday under Binding Operational Directive 26-04.
  • 05GreyNoise reported that a suspected Chinese-speaking actor exploited CVE-2026-7273 and stole sensitive data from 996 Zyxel switches across 48 countries.

CISA has added CVE-2026-7273, a high-severity vulnerability in Zyxel GS1900 series switches, to its Known Exploited Vulnerabilities Catalog after confirming active exploitation. The flaw is a stack-based buffer overflow in a CGI program that allows an unauthenticated attacker on a local network to execute operating-system commands through specially crafted HTTP requests. Zyxel issued firmware fixes on June 16 and advised affected customers to upgrade.

Federal Civilian Executive Branch agencies must secure affected switches by Thursday under Binding Operational Directive 26-04, while CISA encouraged all organizations to prioritize remediation. GreyNoise reported first observing exploitation last Thursday and said a suspected Chinese-speaking actor compromised 996 Zyxel GS1900 switches in 48 countries, exfiltrating sensitive data. Zyxel devices are frequently targeted in part because internet service providers commonly supply them as default equipment to customers worldwide.

  • Although Zyxel had released fixes in June, GreyNoise first observed public exploitation of the flaw in September, highlighting the importance of applying firmware updates promptly.
  • CISA added the issue to its Known Exploited Vulnerabilities Catalog even though Zyxel had not updated its own advisory to confirm that attackers were exploiting it.
  • The reported campaign was not limited to Zyxel equipment: GreyNoise said the suspected actor also targeted more than a dozen other flaws across various software and technology products.
  • Zyxel devices may have broad exposure because internet service providers commonly supply them as default equipment with new internet service contracts.

U.S. officials say attackers are actively taking advantage of a serious flaw in Zyxel GS1900 network switches, devices that help connect computers and other equipment on a local network. Zyxel released updates in June, and federal civilian agencies have been ordered to install them by Thursday; other organizations using these switches are also urged to update. Researchers say a suspected Chinese-speaking attacker accessed nearly 1,000 switches in 48 countries and stole sensitive information, showing that unpatched network equipment can expose organizations worldwide.

SideCopy Broadens India Targeting to Academia With ReverseRAT Spear-Phishing

Pakistan-linked SideCopy is expanding its spear-phishing campaign against India from government targets to academic institutions, using disguised LNK files and mshta.exe to deploy the ReverseRAT backdoor. The malware enables persistence, surveillance, command execution, and data theft while using multilayered obfuscation and in-memory loading to evade detection.
KEY POINTS
  • 01Pakistan-linked SideCopy has expanded its spear-phishing activity to target academic institutions in India, after historically focusing on Indian government and defense entities.
  • 02The campaign sends weaponized ZIP archives containing a Windows shortcut disguised as a DOCX document, which downloads an HTML application from docsportal[.]in and runs it through mshta.exe.
  • 03The attack establishes persistence through a Windows Registry Run Key and uses layered obfuscation and in-memory loading to reduce disk-based detection.
  • 04The final payload is ReverseRAT, which can collect system details, installed software, screenshots, passwords, clipboard contents, and files, execute commands, and open a shell session.
  • 05ReverseRAT encrypts command-and-control traffic with a hard-coded key and sends collected data over port 5863 to dns.educationportals[.]biz, resolving to 45.61.157[.]22.

Pakistan-linked SideCopy has used spear-phishing emails to target academic institutions in India, expanding beyond its historical focus on Indian government and defense entities. Trellix said the group’s latest activity reflects an expanding set of intelligence-collection priorities. SideCopy, active since at least 2019 and also tracked as TAG-140, has overlaps with the Transparent Tribe cluster.

The campaign delivers a weaponized ZIP archive containing a Windows shortcut disguised as a DOCX file with a PDF icon. Opening it retrieves an obfuscated HTML application from docsportal[.]in and runs it with mshta.exe, leading to a DLL that establishes persistence through a Windows Registry Run Key and loads further code in memory. The final ReverseRAT payload can collect system information, installed-software lists, screenshots, passwords, clipboard data, and files; execute commands; upload files; and open a shell session. Its encrypted command-and-control traffic uses port 5863 to send collected data to dns.educationportals[.]biz, which resolves to 45.61.157[.]22.

  • SideCopy’s move toward Indian academic institutions broadens its target set beyond the government and defense organizations it historically targeted, signaling that academia has become part of its intelligence-collection priorities.
  • The initial file is designed to exploit familiar document expectations: it uses a PDF icon and the misleading name "commskll.docx.lnk," even though it is a Windows shortcut rather than a Word document.
  • The malware reduces forensic traces by deleting the downloaded HTA file after launching the next stage and by decoding its main payload directly into memory rather than keeping it on disk.
  • The campaign provides concrete network indicators for detection and investigation, including docsportal[.]in, dns.educationportals[.]biz, 45.61.157[.]22, and port 5863.

A Pakistan-linked hacking group called SideCopy is sending deceptive emails to academic institutions in India, using files that appear to be ordinary documents but install spying software when opened. The software, called ReverseRAT, can collect passwords, screenshots, clipboard contents, and files, run commands, and give the attackers ongoing access to a victim’s computer. This matters because the group is expanding beyond its previous focus on Indian government and defense targets, putting universities and their potentially sensitive information at risk.

WordPress Comment2Shell Flaw Can Turn Anonymous Comment XSS Into RCE via Admin Session

WordPress fixed Comment2Shell (CVE-2026-93485), a flaw allowing anonymous commenters to plant XSS that could lead to server-side code execution if a logged-in administrator views the affected page. Site owners should update to the latest security release immediately and review for unauthorized plugins or files if they suspect targeting.
KEY POINTS
  • 01WordPress fixed Comment2Shell, tracked as CVE-2026-93485, in version 7.1.1 and corresponding security releases for supported branches.
  • 02The flaw allowed an anonymous visitor to submit a crafted comment that could run automatically when a page displaying it was opened.
  • 03If a logged-in administrator opened the affected page, the injected script could use that administrator’s session to upload a plugin containing a web shell and execute commands on the server.
  • 04The attack worked on sites using block themes and, for classic themes, on posts or pages containing comment blocks.
  • 05WordPress stated that exploitation was subject to comment approval, but the article notes that comments can reach pages without manual approval under default or bypassable settings.

WordPress fixed Comment2Shell, tracked as CVE-2026-93485, in version 7.1.1 and security releases for supported branches. The flaw let an anonymous visitor submit a crafted comment that planted a hidden script on a page. If a logged-in administrator later opened that page, the script could use the administrator’s session to upload a plugin containing a web shell and run commands on the server.

The issue arose between WordPress checking a comment for dangerous HTML when it was saved and reformatting it for display. A line break inside an allowed HTML-tag attribute could be transformed during display into an automatically running browser event handler. The attack affected sites using block themes, including default WordPress themes since Twenty Twenty-Two, while classic-theme sites were affected only on pages or posts containing comment blocks.

WordPress described exploitation as subject to comment approval, but the article notes that moderation is off by default and first-time commenter controls can be bypassed. Affected versions range from WordPress 4.7 through 7.1, and site owners are advised to install the fixed release for their branch. Updating fixes the flaw but does not undo changes already made, so sites that suspect targeting should check for unrecognized plugins or files.

  • Comment moderation should not be treated as a security safeguard because moderation is off by default and settings intended to hold first-time commenters can be bypassed.
  • Updating WordPress closes the flaw but does not remove any unauthorized plugins or files that may already have been added through a successful attack.
  • The full server takeover required an administrator to view the affected page while logged in, meaning the malicious comment could affect any visitor but had far greater consequences for administrators.
  • The issue was reported as not known to be used in attacks and was not listed by U.S. authorities as actively exploited at the time of the article.

WordPress fixed a security problem that could let a stranger post a specially crafted comment that secretly runs when someone opens the page. If a site administrator viewed that page while signed in, the comment could use the administrator’s access to place harmful files on the website and take control of its server. Sites using WordPress versions from 4.7 through 7.1, especially those showing comments, should install the available security update because approval settings alone may not keep the harmful comment off the site.

OPEN SOURCE ↗

This is a high-impact WordPress core security fix affecting versions 4.7 through 7.1, where an anonymous comment can lead to server command execution if viewed by a logged-in administrator. Although no active exploitation was reported, WordPress is widely deployed and the article provides concrete update guidance.

One Hidden Meta Muse Setting Could Let Attackers Turn the AI Assistant Into a Backdoor

A hidden macOS Muse setting can be altered by malware already running as the logged-in user to redirect voice dictation, steal session tokens, and hijack Meta’s AI assistant with its granted access. Users should avoid Muse voice input, review or revoke its permissions, and avoid ClickFix-style Terminal commands until Meta clearly confirms a fix.
KEY POINTS
  • 01Security researcher Patrick Wardle released a proof of concept showing that malware already running as the logged-in Mac user can alter Muse’s hidden endo_voyager_dictation_endpoint preference.
  • 02Changing that setting redirects Muse voice dictation to an attacker-controlled address, allowing the attacker to receive the user’s audio and text.
  • 03Wardle demonstrated that an attacker could add instructions Muse trusts and capture a Muse account token to read chat history and control the assistant directly.
  • 04The technique does not independently break into a Mac or bypass macOS protections around another app’s saved passwords and tokens; it relies on Muse sending its token with redirected dictation.
  • 05Meta reportedly pushed a change described as a fix, but the article says Meta had not published a security advisory and the change could not be independently confirmed.

Security researcher Patrick Wardle released a proof of concept showing that malware already running as the logged-in user on a Mac can alter a hidden setting in Meta’s Muse assistant. The setting, called endo_voyager_dictation_endpoint, determines where Muse sends voice dictation and can be changed without extra permissions. Once changed, spoken prompts are redirected to an attacker-controlled address rather than Meta.

Wardle demonstrated that an attacker could read dictated content, insert additional instructions that Muse trusts, and capture a token for the user’s Muse account. The token could then be used to read chat history and control Muse on other signed-in devices, including access to functions such as location reporting, Bluetooth scanning, and smart-home command listings. The attack does not independently compromise a Mac or bypass macOS protections for stored credentials, but it can abuse the broad access a user has granted Muse; users can reduce exposure by quitting or removing Muse, reviewing its permissions, avoiding voice input, and not pasting website-provided commands into Terminal.

  • The issue can turn Muse’s own broad, user-granted access into a pathway for an attacker, even though macOS normally limits one app’s ability to access another app’s data and permissions.
  • Security software may be less likely to flag harmful activity because commands would appear to come from Muse, a legitimate signed application, rather than directly from malware.
  • A stolen Muse token can be used to control the assistant on other signed-in devices, not only on the compromised Mac.
  • Avoiding Muse voice input closes the specific path demonstrated by the researcher, because the attack depends on the user dictating a prompt.

A researcher showed that harmful software already running on a Mac could change a hidden Meta Muse setting and send a user’s spoken requests to an attacker instead of Meta. This affects Mac users who have installed Muse and given it access to personal information or connected apps, especially if they are tricked into running a command from a website or message. The attacker could read spoken requests, influence what Muse does, and take control of the user’s Muse account on other devices, potentially reaching emails, files, messages, smart-home controls, and other connected services.

OPEN SOURCE ↗

This is a concrete proof-of-concept finding affecting Meta’s Muse app on macOS, showing that malware already running as the user can redirect voice prompts, capture account tokens, and abuse the assistant’s granted access. It is relevant to organizations evaluating AI assistants, but the attack requires prior code execution on the Mac and no active exploitation is reported.

UK Cyber Security and Resilience Bill vs NIS2: What Dual Exposure Means for your organisation

OT-heavy organizations operating across the UK and EU may face direct NIS2 obligations and indirect UK Cyber Security and Resilience Bill pressure, so they should build a unified resilience foundation while handling each regime’s distinct reporting, governance, and scope requirements.
KEY POINTS
  • 01NIS2 has applied since October 2024, while the UK Cyber Security and Resilience Bill cleared the House of Commons in June 2026 and is progressing through the House of Lords.
  • 02Both regimes call for an early warning within 24 hours of a significant incident and a fuller report within 72 hours, and both emphasize managing cyber risks from suppliers.
  • 03NIS2 directly covers 18 sectors, including food, manufacturing, chemicals, and postal services, whereas the UK Bill does not directly include manufacturing and food as currently set out.
  • 04The UK Bill can directly oversee suppliers designated as critical, while NIS2 places supply-chain obligations on organizations in scope without directly regulating their suppliers.
  • 05Organizations with exposure to both regimes need separate attention for reporting routes, governance, and technical expectations, but OT visibility and current risk information support readiness for both.

The article compares the EU’s NIS2 Directive, in effect since October 2024, with the UK Cyber Security and Resilience Bill, which cleared the House of Commons in June 2026 and is progressing through the Lords. It argues that organizations with operations, customers, or supply-chain relationships in both jurisdictions may need to address both regimes. Both frameworks seek to improve cyber resilience in critical sectors through incident reporting, supply-chain risk management, and substantial turnover-based penalties.

Both regimes require an early warning within 24 hours of a significant incident and a fuller report within 72 hours, but their reporting routes differ. NIS2 directly covers 18 sectors, including manufacturing, food, chemicals, and postal services, while the UK Bill currently focuses more narrowly on managed service providers, data centres, and large load controllers; manufacturers may instead be affected indirectly through customers or designation as critical suppliers. The article says organizations with dual exposure should build continuous visibility of their operational technology environments while separately addressing differences in reporting destinations, board accountability, and technical expectations such as UK alignment with the NCSC Cyber Assessment Framework.

  • A manufacturer may be directly regulated under NIS2 for its EU operations while facing UK requirements indirectly through regulated customers or possible designation as a critical supplier.
  • Organizations can reuse much of the same incident-response structure because both regimes use 24-hour early warnings and 72-hour fuller reports, but they still need separate reporting paths because the UK requires notification to both a sector regulator and the NCSC.
  • For organizations subject to both rules, NIS2 sets the higher governance bar because it explicitly requires management-body involvement and can create personal liability, while the UK Bill is less prescriptive.
  • ISO 27001 certification may support NIS2 readiness, but it does not remove the need to address the UK Bill’s expected alignment with the NCSC Cyber Assessment Framework.
  • Building and continuously maintaining visibility of operational technology environments is presented as a shared foundation for compliance, rather than treating the two regimes as separate snapshot exercises.

The article compares new European Union rules and a proposed United Kingdom law intended to make important organizations better prepared for cyber incidents. Manufacturers, food producers, and other organizations operating in Europe and the UK may need to report serious incidents quickly, manage risks from suppliers, and give leaders greater responsibility for security decisions. This matters because failing to prepare can bring major fines and make it harder to respond effectively when systems are disrupted.

Emerging Threat: (CVE-2026-69197) Umbraco CMS Protected Content Disclosure via Delivery API Expansion

CVE-2026-69197 is a high-severity Umbraco CMS Content Delivery API authorization flaw that can expose protected content through expanded referenced nodes, potentially without authentication when public API access is enabled. Organizations should upgrade to Umbraco 13.15.1, 17.5.3, or 18.0.2 and review Delivery API exposure and access settings.
KEY POINTS
  • 01CVE-2026-69197 is a high-severity authorization flaw in Umbraco CMS's Content Delivery API that can expose protected content referenced from otherwise accessible pages.
  • 02When anonymous Delivery API access is enabled, callers can use the expand request option to retrieve full property values from protected referenced content without authentication.
  • 03The issue affects Umbraco CMS versions 12.0.0 through 13.15.0, 14.0.0-rc1 through 17.5.2, and 18.0.0 through 18.0.1.
  • 04Umbraco fixed the issue in versions 13.15.1, 17.5.3, and 18.0.2.
  • 05Until patching is confirmed, the article recommends checking whether the Content Delivery API is enabled, disabling anonymous API access where unnecessary, rotating the organization-wide API key, and monitoring for unusual use of the expand parameter.

CVE-2026-69197 is a high-severity authorization flaw in Umbraco CMS’s Content Delivery API. The API applies access checks to content directly requested by a caller but not consistently to protected content referenced through Content Picker, Multi-Node Tree Picker, Block List, Block Grid, or Rich Text Editor properties. An accessible page that references protected content can therefore reveal the protected content’s name, route, and identifier, while use of the ?expand parameter can return its full property values.

The issue affects Umbraco CMS versions from 12.0.0 through 13.15.0, from 14.0.0-rc1 through 17.5.2, and from 18.0.0 through 18.0.1 when the Content Delivery API is enabled. Anonymous callers may exploit the issue when DeliveryApi:PublicAccess is enabled, while holders of an organization-wide API key can also bypass per-page Public Access controls through the same expansion path. Umbraco fixed the flaw in versions 13.15.1, 17.5.3, and 18.0.2; the article recommends inventorying Umbraco sites, reviewing Delivery API settings, restricting anonymous access, rotating API keys, and monitoring for unusual ?expand requests.

  • The flaw can disclose protected content even though directly requesting that same protected page returns a 401 response, because the access checks are not consistently applied when content is referenced from another page.
  • The same expansion behavior bypasses content-type allow and deny restrictions for referenced content, extending the problem beyond Public Access settings alone.
  • External asset inventories and scanners may identify Umbraco services but cannot reliably determine the installed patch level or whether the Delivery API is enabled and publicly accessible, requiring owner-side verification.
  • Organizations with many microsites or regional portals on a shared Umbraco platform may face amplified exposure because a single Delivery API configuration can affect every site built on that platform.

A flaw in Umbraco, software used to build and manage websites, can let people view content that site owners meant to restrict, such as member-only pages, internal notices, campaign material, or protected documents. It affects certain Umbraco versions when the site’s content-sharing feature is turned on, especially if that feature is open to the public. Organizations running affected sites should update the software and check their settings, because one shared website system can expose restricted material across many public-facing sites.

OPEN SOURCE ↗

This is a high-severity, concrete authorization flaw in Umbraco CMS that can expose protected content to anonymous callers when the Content Delivery API is publicly accessible. Security professionals responsible for Umbraco sites should promptly verify configuration and upgrade to the fixed releases.
