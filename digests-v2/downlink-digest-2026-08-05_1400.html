Paperclip AI Flaws Let Attackers Run Host Commands via Malicious Agent Imports

Paperclip AI fixed critical flaws that could let attackers run host commands by importing malicious agent configurations, either against exposed authenticated servers or via DNS rebinding against local developer instances. Operators should upgrade to v2026.416.0 or later and review registration and exposure settings.
KEY POINTS
  • 01Two critical Paperclip flaws could let attackers execute commands on a network server or a developer's computer by importing a malicious agent and starting it.
  • 02CVE-2026-41679 has a CVSS score of 10.0 and affects network-accessible authenticated deployments using the default registration configuration, allowing a newly registered user to create and activate credentials and import a process-based agent for a new company.
  • 03GHSA-x8hx-rhr2-9rf7 has a CVSS score of 9.6 and uses DNS rebinding against Paperclip running in default local_trusted mode, allowing an attacker-controlled web page to reach the local service and trigger command execution.
  • 04A third flaw, GHSA-xfqj-r5qw-8g4j, exposed sensitive data and control-plane details through API routes that did not consistently enforce authentication or company-access checks.
  • 05Paperclip v2026.416.0 contains fixes for import authorization, hostname validation, and several missing route checks, and operators are advised to upgrade to v2026.416.0 or later.

Paperclip, an open-source control plane for teams of AI agents, had two security flaws that could let attackers execute commands on a network server or a developer’s computer by importing and starting a malicious agent. A third flaw could expose sensitive data and control-plane details through API routes that did not enforce expected access checks. The most severe issue, CVE-2026-41679, has a CVSS score of 10.0 and affects network-accessible authenticated deployments using the default registration configuration.

The server-side attack chain used Paperclip’s default open-signup flow, self-approved CLI authorization, and an import route that accepted board-level access for creating a new company. An attacker could supply a .paperclip.yaml bundle defining a company, a process-based agent, and the command the agent would run, causing Paperclip to launch the command with the operating-system privileges of the server process. Oasis Security said the impact could include application data, source repositories, locally stored credentials, secrets available to agent processes, and internal services reachable from the machine.

The second critical path, GHSA-x8hx-rhr2-9rf7, used DNS rebinding against Paperclip running in its default local_trusted mode, where the service historically treated requests reaching localhost as implicitly administrative. Paperclip v2026.416.0 contains fixes including stricter import authorization, hostname validation, and added route checks, although the article notes that public version records do not fully line up. No authoritative source reviewed by The Hacker News reported exploitation in the wild as of August 5, 2026, but Rapid7 has released a Metasploit module for CVE-2026-41679 and operators are advised to upgrade to v2026.416.0 or later.

  • Paperclip’s core risk came from a legitimate feature: agent configuration could become executable behavior because the built-in process adapter intentionally launches configured commands as child processes of the server.
  • The server-side exploit chain abused several normal flows together: open signup, self-approval of a CLI challenge, board-level credentials, and a new-company import route that accepted less privilege than direct company creation required.
  • The DNS-rebinding issue shows that Paperclip’s default local_trusted mode treated access from localhost as administrator identity, allowing a malicious browser page to cross from the web into the local service without stealing any Paperclip token or cookie.
  • The public records are inconsistent because the GitHub release is labeled v2026.416.0 while package manifests inside the tag report version 0.3.1, and the DNS-rebinding advisory still lists no patched version despite the tagged source containing the hostname guard.
  • Rapid7 has already published a Metasploit module for CVE-2026-41679, and NVD’s CISA-ADP enrichment marks the flaw as automatable with proof-of-concept exploitation, even though no authoritative source reported exploitation in the wild as of August 5, 2026.
