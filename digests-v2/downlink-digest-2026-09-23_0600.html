F5 patches BIG-IP APM zero-day flaw exploited in RCE attacks

F5 patched CVE-2026-94127, a critical BIG-IP Access Policy Manager flaw that is actively being exploited for remote code execution on deployments configured as OAuth authorization servers. Organizations should apply the updates immediately or use F5’s iRule mitigation and check for compromise indicators.
KEY POINTS
  • 01F5 released security updates for CVE-2026-94127, a critical BIG-IP Access Policy Manager flaw that the company says has been exploited in remote code execution attacks.
  • 02The flaw affects BIG-IP APM deployments configured as OAuth Authorization Servers when an APM access policy and OAuth profile are set on a virtual server.
  • 03Deployments that use APM strictly as an OAuth Client or Resource Server without OAuth authorization server profiles are not affected, according to F5.
  • 04F5 advises customers to review systems for signs of compromise and provides an iRule mitigation for affected virtual servers when patches cannot be installed immediately.
  • 05CISA added CVE-2026-94127 to its Known Exploited Vulnerabilities Catalog and directed U.S. federal agencies to secure affected networks by Friday.

F5 released security updates for CVE-2026-94127, a critical zero-day flaw in BIG-IP Access Policy Manager (APM) that has been exploited in remote code execution attacks. The issue affects BIG-IP APM instances configured as OAuth Authorization Servers when both an APM access policy and an OAuth profile are configured on a virtual server. Deployments that use APM only as an OAuth Client or Resource Server, without OAuth authorization-server profiles, are not affected.

F5 advises customers to investigate for possible compromise when multiple OAuth authentication failures and suspicious commands are followed shortly by a TMM SIGABRT. Organizations unable to install the updates immediately can apply an F5-provided iRule to the affected virtual server as a mitigation. CISA added the flaw to its Known Exploited Vulnerabilities Catalog and ordered U.S. federal agencies to secure affected networks by Friday; Shadowserver tracks more than 14,700 IP addresses with BIG-IP APM fingerprints, although that number may include patched devices and honeypots.

  • A practical sign of possible compromise is a sequence of multiple OAuth authentication failures and suspicious commands followed shortly by a TMM SIGABRT crash.
  • The affected population is narrower than all BIG-IP APM users: risk depends on the specific combination of an OAuth authorization-server profile and an APM access policy on a virtual server.
  • Shadowserver identifies more than 14,700 internet-facing IP addresses with BIG-IP APM fingerprints, although the article notes that this total may include patched systems and honeypots.
  • Organizations unable to patch immediately can apply an F5-provided iRule to the affected virtual server as a temporary mitigation.

F5 released fixes for a serious flaw in its BIG-IP Access Policy Manager software that attackers are already using to run commands on affected systems from afar. The risk applies to organizations using this software as the part of their login system that authorizes access, while setups using it only to connect to other authorization services are not affected. U.S. federal agencies have been told to fix the issue by Friday, and the problem matters because F5 products are widely used by major companies and have repeatedly been targeted to gain access to networks and steal or destroy data.

A critical vulnerability in Next.js ImageResponse, tracked as CVE-2026-94545, could allow attackers to run code on a server through specially crafted SVG-related input. It affects Next.js versions 16.2.0 through 16.3.5 when ImageResponse runs on the Node.js runtime, which is the default. The Edge version of ImageResponse and Next.js 15 are not affected.

ImageResponse uses Vercel’s Satori library to turn image layouts into SVG before producing PNG social-preview images. Certain attacker-controlled values could reach Satori’s SVG output without proper escaping and be interpreted as SVG code rather than ordinary text, potentially reaching flaws in other unnamed dependencies and leading to code execution. Vercel fixed the issue in Next.js 16.3.6, while developers unable to upgrade are advised to keep untrusted values out of SVG content, attributes, and styles; as of September 23, no public exploitation or exploit code had been reported.

  • The vulnerable Satori component is bundled inside Next.js, so checking a lockfile alone will not show it as a Next.js dependency; applications need to verify their installed Next.js version directly.
  • Vercel did not state whether applications hosted on its platform are protected, unlike its messaging for two critical Next.js flaws fixed in August.
  • The advisory provides no method to determine whether an affected image-generation route was abused before patching, and recommends keeping untrusted values out of SVG output if an upgrade must wait.

Next.js fixed a serious flaw that could let an attacker run commands on a website’s server by putting specially crafted text into an image-generation request. It affects apps using Next.js versions 16.2.0 through 16.3.5 that create social-preview images on the standard Node.js server setup and place user-controlled information into those images. Website owners should update to version 16.3.6 because successful misuse could give an attacker control over the server running the site.

Manchester Airports Group, which runs Manchester, London Stansted, and East Midlands airports, reported that customer information from services such as airport Wi-Fi, parking, lounges, and faster security bookings was accessed. The group FulcrumSec claimed it stole 86 GB of data, potentially including email addresses, phone numbers, postcodes, vehicle registrations, and details of upcoming travel. Flight operations, passenger safety, and aviation security continued normally, but the stolen information could be used to create convincing scam emails or text messages and to commit identity fraud.

This reports a significant named data-extortion incident affecting approximately 8.7 million MAG customers, with potential downstream phishing and identity-fraud risk. It also provides a concrete alleged access method—Iterable API credentials exposed in client-side JavaScript—and identifies FulcrumSec as the claiming threat actor.
