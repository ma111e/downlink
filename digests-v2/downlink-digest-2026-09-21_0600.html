Jade Sleet Linked to Indian IT Provider Breach With FLATROOF and ROOFDECK Backdoors

North Korean-linked Jade Sleet compromised an Indian IT services provider’s DevOps engineer using macOS backdoors FLATROOF and ROOFDECK, likely as part of its developer-focused supply-chain operations. The campaign uses fake job-interview repositories with malicious Terraform lockfiles to infect Apple Silicon Macs and steal data, maintain persistence, and enable remote control.
KEY POINTS
  • 01SentinelOne attributed the compromise of an India-based IT services provider to the North Korean threat actor Jade Sleet, also known as PUKCHONG, Slow Pisces, TraderTraitor, and UNC4899.
  • 02The campaign uses fake job-interview coding repositories containing a malicious Terraform dependency lock file that directs developers running terraform init to attacker-controlled modules.
  • 03The attackers deployed the Rust-based macOS backdoors FLATROOF and ROOFDECK, which can steal information, execute commands, manipulate files, and establish persistent access.
  • 04The compromised system was an Apple Silicon MacBook used by a DevOps engineer, where the backdoors were detected from March 18, 2026, and became active on March 29.
  • 05SentinelOne said developer endpoints can expose cloud environments, software pipelines, and source code, making them a high-priority target in third-party and software supply-chain compromises.

SentinelOne attributed the compromise of an India-based IT services provider to the North Korean threat actor Jade Sleet, also known as PUKCHONG, Slow Pisces, TraderTraitor, and UNC4899. The group is known for targeting cryptocurrency and blockchain organizations, as well as vendors connected to them. In this case, the affected device was an Apple Silicon MacBook belonging to a DevOps engineer. FLATROOF and ROOFDECK backdoors were detected on the system as early as March 18, 2026.

Jade Sleet uses job-interview lures that present victims with coding repositories themed around infrastructure engineering projects. These repositories contain a weaponized Terraform dependency lock file that points Terraform to attacker-controlled modules when a developer runs terraform init. FLATROOF can execute commands, transfer files, and steal browser data, command histories, system details, and the Mac login keychain database, while ROOFDECK supports reconnaissance, file operations, remote shell access, lateral movement, and persistence. SentinelOne said the implants became active after Cursor opened a specific development workspace, and an updated ROOFDECK version later removed existing malware binaries and stripped debugging information to evade detection.

The incident highlights the risk posed by compromised developer endpoints, which can hold access to cloud environments, software pipelines, and source code. SentinelOne said Jade Sleet’s campaigns target third parties and software supply chains one engineer at a time, using backdoored Terraform builds tailored to individual victims. ROOFDECK was also observed as a follow-up tool after initial access had been established, using the decentralized Nostr protocol for command-and-control communications. The article notes that the exact delivery method used against the Indian IT services provider is not yet known.

  • The implants remained dormant on the DevOps engineer’s MacBook until activity began when Cursor opened a specific cloudshield development workspace, showing that the malicious tools were tied to a developer’s working environment.
  • The malicious Terraform project files were tailored for individual victims and directed Terraform to download attacker-controlled modules through lookalike registry domains.
  • ROOFDECK uses the decentralized Nostr protocol for communications and verifies operator-signed commands with an embedded public key before running them.
  • An updated ROOFDECK version deployed after the KelpDAO incident removed earlier malware binaries and stripped debugging information, making analysis and detection more difficult.

North Korean-linked hackers known as Jade Sleet broke into an Indian IT services company through a DevOps engineer’s Apple MacBook, using hidden programs called FLATROOF and ROOFDECK to control the computer and steal information. The group often disguises harmful code as job-interview projects, tricking developers into downloading it while completing a coding task. This matters because developers’ computers can provide access to company source code, cloud services, and automated software-building systems, allowing one compromised employee to put many connected organizations at risk.

This is a concrete, recent Jade Sleet operation involving an Indian IT provider and developer-focused supply-chain targeting with malicious Terraform files and macOS backdoors. It is particularly relevant to teams protecting developer endpoints, cloud access, source code, and software build pipelines, though the known victim scope is limited.

ClickFix Lures Deploy ChainScript RAT Using Polygon to Rotate C2 Infrastructure

Threat actors are using ClickFix lures and fake software installers to deploy the ChainScript Node.js RAT, which uses a Polygon smart contract to rotate its WebSocket command-and-control infrastructure and resist takedowns. Related ClickFix campaigns also abuse trusted accounts, search results, and fake AI-tool downloads to deliver information stealers on Windows and macOS.
KEY POINTS
  • 01ClickFix-style lures deliver the previously undocumented ChainScript remote-access trojan through a malicious Windows installer disguised as Spotify.
  • 02ChainScript deploys a Node.js runtime and JavaScript agent, establishes persistence through a scheduled task with a Registry Run key fallback, and connects to its command server over WebSockets.
  • 03The malware uses a Polygon smart contract to discover active command-and-control infrastructure, allowing operators to redirect infected systems while retaining the same implant.
  • 04ChainScript supports command-line and PowerShell access, file operations, screenshot capture, payload deployment, cryptocurrency-wallet enumeration, and remote JavaScript execution.
  • 05Separate ClickFix campaigns used HBO Max’s compromised Reddit account and fake Codex download pages to distribute information-stealing malware to Windows and macOS users.

Threat actors are using ClickFix-style lures to distribute ChainScript, a previously undocumented remote-access trojan that has appeared under names including ComponentTask33, UpdateDigital, HostShared, and OrchidViolet66. A malicious Windows installer disguised as Spotify deploys the Node.js runtime and launches the ChainScript agent through hidden PowerShell and VBScript stages. The malware provides operators with command-line access, file operations, screenshots, payload deployment, cryptocurrency-wallet enumeration, and remote JavaScript execution.

ChainScript uses a Polygon smart contract to locate its active WebSocket control infrastructure, enabling operators to redirect infected devices to new servers without changing the implant. It establishes user-level persistence with a scheduled task and a Registry Run key fallback, while its components are stored in Microsoft-looking folders under %LOCALAPPDATA%. The article also describes separate ClickFix campaigns that used HBO Max’s compromised Reddit account and fake Codex download pages to distribute information stealers to Windows and macOS users, showing how trusted accounts, search results, and fake installation instructions can be used to persuade users to infect themselves.

  • ChainScript separates its instructions for finding the operator’s server from the malware itself by using a Polygon smart contract, allowing the operator to change servers without replacing the malware on infected computers.
  • The ChainScript installer uses several hidden stages—Windows Installer, PowerShell, and VBScript—to place its components in Microsoft-looking folders under the user’s local application-data directory.
  • The PasteSwitch operation used HBO Max’s verified Reddit account to publish 108 malicious advertisements over 48 hours, leveraging a trusted corporate identity to reduce user skepticism.
  • The macOS ClickFix activity evolved to use browser fingerprinting on the server side, showing the lure mainly to visitors whose environment appears to be a genuine macOS browser and reducing exposure to crawlers and automated analysis.

Criminals are tricking people into running fake software downloads or copying commands from fake pages, which can install programs that let the criminals control a computer or steal information. Windows and Mac users are affected, including people drawn in by malicious ads posted through HBO Max’s compromised Reddit account or fake downloads for tools such as Codex. The criminals can quickly change where their control servers are located, making the operation harder to shut down and increasing the risk of stolen files, cryptocurrency wallet data, and account information.

OPEN SOURCE ↗

The article reports active ClickFix campaigns delivering a newly documented ChainScript RAT with Polygon-based command-and-control discovery, persistence, and broad remote-control capabilities. It also documents large-scale distribution of information stealers through a compromised verified HBO Max Reddit account, making it broadly relevant to defenders monitoring Windows and macOS threats.

Government AI Use Cases Have Passed 3,600. Security Must Catch Up

Federal agencies are rapidly deploying thousands of AI use cases, but legacy security tools lack the visibility and controls needed to manage AI-driven risks. Agencies should continuously discover AI use, classify risk, monitor autonomous agents, and enforce inline safeguards and red-team testing.
KEY POINTS
  • 01OMB's 2025 Federal Agency Artificial Intelligence Use Case Inventory documented 3,611 AI use cases across 56 submitting federal agencies.
  • 02The article says traditional enterprise security tools often lack visibility into AI usage, prompts, model interactions, and AI-driven workflows.
  • 03Federal agencies are expected to meet security, transparency, and risk-management requirements under the NIST AI Risk Management Framework, OMB M-25-21, and CISA guidance while deploying AI rapidly.
  • 04The article recommends continuous discovery of AI tools and usage, risk classification based on data sensitivity and mission impact, visibility into AI agents, and inline safeguards.
  • 05NIST red-team exercises in 2025 found that novel attacks against AI agents succeeded 81% of the time, according to the article.

The Office of Management and Budget’s 2025 inventory documented 3,611 AI use cases across 56 submitting federal agencies, and several civilian agencies have since reported more than 300 use cases each. The article says this rapid adoption could repeat problems seen during the federal government’s Cloud First push if security architecture does not keep pace. Agencies must accelerate deployment while meeting security, transparency, and risk-management requirements under the NIST AI Risk Management Framework, OMB M-25-21, and CISA guidance.

Traditional enterprise security tools often cannot see AI use, inspect prompts or model interactions, or enforce policy across AI-driven workflows. The article recommends continuous discovery of AI tools and shadow AI, classifying use cases by risk and data sensitivity, tracking AI agents and their connected assets, and applying controls during AI interactions rather than only reviewing logs afterward. It also recommends early and continuous red-team testing for self-hosted AI, noting that NIST red-team exercises in 2025 found novel attacks against AI agents succeeded 81% of the time.

  • AI oversight must be continuous rather than based on periodic inventories, because unmanaged or "shadow" AI can appear between review cycles.
  • The article identifies subscription-based AI services as a major concern because employees may obtain them without going through larger procurement processes.
  • As AI systems evolve from chatbots into agents that can act across systems, agencies need to track not only human use but also which assets each agent can access.
  • The article argues that controls applied during AI interactions are more effective than reviewing logs afterward, especially when sensitive data could be involved.
  • For self-hosted AI, ongoing adversarial testing before and after deployment can help detect new attack paths or declining model resilience.

U.S. federal agencies have reported more than 3,600 ways they are using artificial intelligence, including work involving sensitive government information. The article warns that existing security practices may not show what these AI tools are doing or prevent them from sharing data with malicious people. This affects government agencies and the public they serve, because poorly secured AI could expose government data or systems. Agencies are urged to identify all AI use, assess its risks, monitor automated AI tools, and test protections before problems occur.

OPEN SOURCE ↗

This is a broad best-practice and trend article about securing growing federal AI adoption, not a report of a specific active incident, breach, or urgent vulnerability. Its recommendations and cited agency inventory may be useful for federal security teams, but it has low immediate operational urgency.
