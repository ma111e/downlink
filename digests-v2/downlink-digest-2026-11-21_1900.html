Rackspace Spot breach let hackers access customer Kubernetes secrets

Rackspace Spot was breached using leaked credentials, allowing attackers to impersonate users, deploy unauthorized Kubernetes pods, and access secrets that may contain passwords, API keys, and tokens. Affected customers should rotate exposed credentials and review logs from November 17 for misuse.
KEY POINTS
  • 01Rackspace said an unauthorized party used leaked credentials to access parts of its Rackspace Spot cloud platform on November 17, 2026.
  • 02The attackers could act as legitimate users in some customer organizations, create Kubernetes pods, read Kubernetes Secrets, and list nodes and volumes.
  • 03Rackspace warned that any Secret in an affected user’s clusters, along with that user’s Spot API and refresh tokens, could have been exposed.
  • 04Rackspace revoked affected tokens and sessions, removed unauthorized pods, rotated keys, and restored the Spot service on November 21 after temporarily disabling access.
  • 05Affected customers were told to reissue tokens, replace automation refresh tokens, obtain new Kubernetes configuration files, rotate stored credentials, and examine relevant logs dating from November 17.

Rackspace said attackers used leaked credentials to access parts of its Rackspace Spot cloud platform on November 17, 2026. The intruders could act as legitimate users in some customer organizations, create Kubernetes pods, read Kubernetes Secrets, and list nodes and volumes. Rackspace learned of the incident on November 18 after a customer report and confirmed that organization was affected the same day.

The exposure could extend beyond the platform because Kubernetes Secrets may contain passwords, authentication tokens, and API keys for databases, cloud services, and other systems. Rackspace revoked affected tokens and sessions, removed unauthorized pods, rotated keys, strengthened controls and monitoring, and restored service on November 21 after disabling access during containment. Affected customers were instructed to replace API and refresh tokens, download new Kubernetes configuration files, rotate credentials in Secrets, review relevant logs from November 17, and check for the listed indicators, including IP address 23.224.79.106 and object prefixes i1, glm-, and probe.

  • The potential impact extended beyond the Rackspace Spot platform because Kubernetes Secrets can contain credentials for databases, cloud services, code repositories, storage, and third-party services.
  • Rackspace’s response required customers to replace several different forms of access material, including Spot API tokens, automation refresh tokens, Kubernetes configuration files, and credentials held in cluster Secrets.
  • The administration-console outage temporarily prevented customers from managing clusters and rotating potentially compromised credentials, illustrating the operational disruption caused by the containment effort.
  • Customers can use the reported IP address 23.224.79.106 and the suspicious Kubernetes object prefixes i1, glm-, and probe when reviewing activity associated with the incident.

Hackers used stolen login details to get into parts of Rackspace Spot, a service customers use to run and manage applications. They could pretend to be legitimate users, create unauthorized programs, and view stored sensitive information such as passwords, access keys, and login tokens. Organizations using the affected service may need to replace those credentials and check whether their other online services were accessed, because stolen keys can open the door to databases, cloud storage, code repositories, and other systems.

OPEN SOURCE ↗

This is a concrete cloud-platform breach in which leaked credentials enabled access to Kubernetes Secrets, potentially exposing passwords, API keys, and tokens across affected customer environments. It includes actionable indicators and remediation steps, though the reported scope and confirmed data theft remain unknown.
