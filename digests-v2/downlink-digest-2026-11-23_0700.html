CISA has added CVE-2026-76466, a critical vulnerability in Cisco Expressway, to its Known Exploited Vulnerabilities Catalog after determining that attackers are actively exploiting it. CISA ordered U.S. Federal Civilian Executive Branch agencies to secure affected systems within three days under Binding Operational Directive 26-04. The vulnerability results from hard-coded credentials and incomplete validation of client certificates. An unauthenticated attacker with the relevant cookies can connect to the database service and invoke specific remote procedure call commands, allowing arbitrary operating-system commands to run as root. Cisco released patches in late October and said at that time that its PSIRT had no knowledge of active exploitation or publicly available proof-of-concept exploits. Hackers Exploit Critical ASP.NET Anti-CSRF Library Flaw Allowing Unauthenticated RCE

A critical, actively exploited insecure deserialization flaw in the abandoned Idunno.AntiCsrf ASP.NET library lets unauthenticated attackers execute code on affected IIS servers with a single crafted POST request. Organizations should immediately remove the library, migrate to a supported anti-CSRF mechanism, and investigate for compromise.
KEY POINTS
  • 01CVE-2026-131914 is a critical insecure deserialization flaw, rated CVSS 9.3, affecting Idunno.AntiCsrf versions 0.9.1.0 and 0.9.1 Beta.
  • 02The flaw allows an unauthenticated remote attacker to execute arbitrary code on an affected ASP.NET WebForms server through a single crafted HTTP POST request.
  • 03Google Mandiant reported that the vulnerability is being actively exploited in the wild.
  • 04Idunno.AntiCsrf is an abandoned third-party ASP.NET anti-CSRF library that has not been updated since December 2008.
  • 05Organizations are advised to discontinue Idunno.AntiCsrf, use a supported anti-CSRF alternative, and review IIS logs and webroots for evidence of exploitation.

Researchers have warned organizations to stop using Idunno.AntiCsrf, an obsolete ASP.NET anti-CSRF library, after a critical flaw was found to be actively exploited. The vulnerability, CVE-2026-131914, has a CVSS score of 9.3 and affects versions 0.9.1.0 and 0.9.1 Beta. Idunno.AntiCsrf is a third-party component for ASP.NET WebForms applications and has not been updated since December 2008.

The issue occurs because the library processes untrusted form-token data without cryptographic verification when handling POST requests to ASP.NET WebForms pages. An unauthenticated attacker can send a single crafted POST request and execute arbitrary code in the IIS worker process, potentially fully compromising the application server. Google Mandiant said attackers need only provide a non-empty configured CSRF cookie value and a specially encoded value in the relevant form field.

Because no official patch is available, organizations are advised to remove the library and replace it with a supported anti-CSRF option, such as System.Web.Helpers.AntiForgery, ViewStateUserKey with protected ViewState, or ASP.NET Core IAntiforgery. Google also recommended auditing Web.config files and bin directories for Idunno.AntiCsrf references and reviewing IIS logs for suspicious POST requests to .aspx endpoints. Where exploitation may have occurred, organizations should rotate secrets in Web.config and applicationHost.config and inspect webroots for unauthorized files.

  • Exploitation does not require a valid anti-CSRF token: an attacker only needs to provide any non-empty value in the configured cookie and a specially encoded value in the form field.
  • Because the library has no official patch and has been unmaintained since 2008, the recommended remediation is to remove and replace it rather than wait for an update.
  • Potential signs of exploitation include unusual POST requests to .aspx pages that return HTTP 302 or HTTP 500 responses with elevated logged request-byte counts.
  • Organizations that find evidence of compromise should rotate secrets in Web.config and applicationHost.config, including machine keys, encryption keys, and database credentials, and inspect website directories for unauthorized files.

Researchers found that hackers are actively abusing a serious flaw in an old, no-longer-maintained ASP.NET web application add-on called Idunno.AntiCsrf. Websites that still use it can be taken over by an outsider with a single specially made web request, without needing to log in. This could give attackers full control of the website’s server and access to sensitive settings and data, so affected organizations should remove the add-on, switch to supported protections, and check for signs of intrusion.

Hackers exploited a flaw in GL.iNet’s GoodCloud remote-management service to install malware on some customer routers and remote-control KVM devices. GL.iNet said it fixed the cloud-side issue and blocked the attacker’s access, but the fix does not automatically clean devices that were already infected. The company has released security firmware for listed router and KVM models and is contacting customers it identifies as affected. It has not disclosed how many devices were infected, when the activity began, or how GoodCloud was breached.

RemoteToHome Consulting verified a root-level remote shell on a GL-AXT1800 router running firmware 4.8.3 with GoodCloud enabled, and reported that the shell connected to an external server. Its analysis says a GoodCloud client handler accepted two cloud-message values and ran them as root without checking them, though GL.iNet has not confirmed that technical finding. The shell reportedly left no files and disappeared after a restart, while the vendor’s published process marker was absent on the router with the verified shell. Although GL.iNet says its new firmware removes malware identified in the incident without a factory reset, researchers advise reinstalling firmware without retaining settings for suspected compromises and treating stored passwords, keys, and cloud credentials as exposed.

  • The vendor’s suggested process marker did not appear on a router where researchers verified the remote shell, so a clean marker check does not reliably rule out compromise.
  • The verified router shell left no files and its traces disappeared after a restart, making it important to inspect a suspected device before rebooting or upgrading it.
  • Researchers found that an earlier KVM firmware upgrade that preserved settings also retained password files, SSH keys, and a user directory containing scripts that run at every boot.
  • Before using netstat on a suspect device, owners are advised to confirm that it still points to BusyBox because the command may have been replaced and running a compromised copy can start malware.
  • Turning off GoodCloud stops its client software from running until an update is installed, but it does not remove malware from a device that was already infected.

Hackers used a weakness in GL.iNet’s online management service to place harmful software on some of the company’s internet routers and devices used to control computers from far away. Owners of affected GL.iNet equipment may have had outsiders gain deep control of their devices, and computers connected through the remote-control devices may also need checking. GL.iNet has closed the entry point and released updates that remove identified malware, but owners should update their devices and change stored passwords and access keys if compromise is suspected.
