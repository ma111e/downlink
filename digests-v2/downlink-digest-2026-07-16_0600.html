Zoom Patches Critical Windows Flaw That Could Enable Account Takeover

Zoom released Windows security updates fixing a critical flaw in Zoom Workplace that could let an unauthenticated attacker take over accounts via network access. The patches also address several high-severity Windows privilege escalation issues, and users should update to the latest versions.
KEY POINTS
  • 01Zoom has released security updates for a critical flaw in Zoom Workplace for Windows that could enable account takeover.
  • 02The critical vulnerability, CVE-2026-53412, has a CVSS score of 9.8 and affects Zoom Desktop Client for Windows, Zoom VDI Client for Windows, and Zoom Meeting SDK for Windows.
  • 03Zoom said CVE-2026-53412 involves improper input validation and may allow an unauthenticated user to conduct an account takeover via network access.
  • 04The latest fixes also address three high-severity flaws: CVE-2026-53411, CVE-2026-53410, and CVE-2026-53409.
  • 05Zoom said there are no indications as of writing that any of the flaws are being exploited in real-world attacks, and users can stay protected by applying the latest updates.

Zoom has released security updates for a critical security flaw affecting Zoom Workplace for Windows. The vulnerability is tracked as CVE-2026-53412 and has a CVSS score of 9.8. Zoom said the issue involves improper input validation and may allow an unauthenticated user to conduct an account takeover via network access.

CVE-2026-53412 affects Zoom Desktop Client for Windows, Zoom VDI Client for Windows, and Zoom Meeting SDK for Windows. The latest security fixes also address three high-severity flaws: CVE-2026-53411, CVE-2026-53410, and CVE-2026-53409. These issues include improper input validation, a time-of-check to time-of-use race condition, and improper privilege management.

CVE-2026-53410 affects several Windows products, including Zoom Workplace, Zoom Workplace VDI Client, Zoom Workplace VDI Plugin, Zoom Rooms, and Remote Control for Zoom Contact Center, with specific fixed versions listed by Zoom. The other high-severity flaws may allow authenticated users to escalate privileges through local access. As of writing, there are no indications that any of the flaws are being exploited in real-world attacks, and users can stay protected by applying the latest updates.

  • The most urgent fix is for Windows users because every listed vulnerability affects Windows versions of Zoom products.
  • CVE-2026-53410 requires particular attention because it affects multiple Zoom product lines, including Workplace, VDI Client, VDI Plugin, Rooms, and Remote Control for Zoom Contact Center.
  • The critical account takeover flaw is especially actionable because Zoom says it can be triggered by an unauthenticated user via network access.
  • Organizations using older VDI branches need to check branch-specific fixed versions, since Zoom lists separate patched versions for the 6.5 and 6.6 branches.

Zoom released fixes for serious security problems in several Windows versions of its software, including Zoom Workplace, Zoom Desktop Client, Zoom VDI Client, Zoom Meeting SDK, Zoom Rooms, and related tools. The most serious problem could let someone take over a Zoom account over a network without being signed in. Other flaws could let a signed-in Windows user gain more control on the device, so affected users should install the latest updates even though Zoom says there are no signs these flaws are being used in real attacks.

OpenAI’s GPT-Red Automates Prompt Injection Testing to Harden GPT-5.6 Sol

OpenAI unveiled GPT-Red, an internal automated red-teaming model used to find prompt injection weaknesses and adversarially train GPT-5.6 Sol. The company says this made GPT-5.6 Sol far more resistant to direct and indirect prompt injection attacks than prior models.
KEY POINTS
  • 01OpenAI disclosed GPT-Red, an internal automated red-teaming model designed to discover prompt injection vulnerabilities at scale before tools are widely deployed.
  • 02OpenAI said it integrated GPT-Red into the training process for GPT-5.6 Sol, which achieved six times fewer failures than GPT-5.5 on a direct prompt injection benchmark.
  • 03GPT-Red is trained using self-play reinforcement learning, where it is rewarded for eliciting valid failures while defender models are rewarded for resisting attacks and completing their original tasks.
  • 04In a real-world test against an AI-based vending machine built by Andon Labs, GPT-Red lowered the price of an expensive item to $0.50, ordered a new $100 item for that price, and canceled another customer’s order.
  • 05OpenAI said an early version of GPT-Red uncovered Fake Chain-of-Thought attacks, which had success rates above 95% on GPT-5.1 but are now below 10% for GPT-5.6 Sol.

OpenAI disclosed GPT-Red, an internal automated red-teaming model designed to find prompt injection vulnerabilities at scale before tools are widely deployed. OpenAI said GPT-Red behaves like a human red-teamer by sending prompts, observing model responses, and iterating toward malicious goals such as uploading sensitive data to an external server. The company said it uses GPT-Red to adversarially train GPT-5.6 Sol, making it more robust to prompt injections.

The article says prompt injections remain a persistent problem for large language models, especially as agentic systems connect to browsers, apps, local files, third-party data sources, and other tools. Malicious instructions can be embedded in seemingly harmless inputs such as emails, web pages, tool responses, or code repositories. OpenAI said GPT-5.6 Sol achieved six times fewer failures than GPT-5.5 on a direct prompt injection benchmark and failed on only 0.05% of GPT-Red’s direct prompt injections.

GPT-Red is trained using self-play reinforcement learning, where it is rewarded for causing valid failures while defender models are rewarded for resisting attacks and completing their original tasks. OpenAI said GPT-Red found attacks including credential exfiltration, fraudulent payment instructions, external script injection, and a new Fake Chain-of-Thought attack class that exceeded 95% success on GPT-5.1 but is now below 10% for GPT-5.6 Sol. In real-world tests, GPT-Red manipulated an Andon Labs AI vending machine and outperformed a prompted GPT-5.5 baseline against a Codex command-line agent on held-out data-exfiltration tasks.

  • OpenAI reported that GPT-Red generated successful indirect prompt injection attacks against GPT-5.1 in more scenarios than human red-teamers, showing automated testing can exceed manual testing in some areas.
  • GPT-Red’s effectiveness depends on an arms-race-style training setup in which stronger defender models force the red-teaming model to find more diverse and potent attack methods.
  • OpenAI said GPT-Red is kept separate from other models because its malicious capabilities could help bad actors bypass safety measures if released more broadly.
  • The Andon Labs vending machine test showed that prompt injection risks are not limited to data exposure, because GPT-Red achieved goals involving pricing changes, purchases, and cancellation of another customer’s order.
  • OpenAI’s benchmark discussion highlights that some reported model capability measurements can be unreliable, as its audit found roughly 30% of SWE-Bench Pro tasks were broken.

OpenAI described GPT-Red, an internal system that automatically tests whether its AI models can be tricked by hidden or crafted instructions into doing harmful things, such as sending private data away or changing orders. OpenAI says it used those tests to make GPT-5.6 Sol much harder to fool than earlier models. This matters because AI systems are increasingly connected to browsers, apps, files, and other tools, so a malicious message on a web page, email, or code repository could affect what the AI does in the real world. In tests, GPT-Red even found ways to manipulate an AI vending machine and a coding tool, showing that these weaknesses can affect customers, developers, and companies using AI agents.

It is broadly relevant to security professionals tracking AI agent risks, though it is not an active exploitation incident, major breach, or critical patch.

UAT-11795 deploys novel Starland RAT and bespoke WLDR C2 implant in financially motivated campaign

Cisco Talos reports that the Russian-speaking, financially motivated actor UAT-11795 is using trojanized installers and likely ClickFix lures to deploy the new Python-based Starland RAT and a bespoke PowerShell WLDR C2 implant against mostly U.S. and European victims. The campaign focuses on stealing credentials and cryptocurrency assets while maintaining persistent, encrypted remote access for additional payloads such as CastleStealer and Remcos RAT.
KEY POINTS
  • 01Cisco Talos is disclosing UAT-11795, a sophisticated Russian-speaking, financially motivated adversary targeting users in the United States and Europe since at least June 2025.
  • 02The campaign delivers a Python-based remote access tool called Starland RAT and a PowerShell-based command-and-control memory implant called the WLDR agent.
  • 03UAT-11795 uses trojanized installers for software including MobaXterm, Cisco WebEx, Zoom, DBeaver Community Edition, and FACEIT, suggesting an opportunistic distribution model across multiple victim profiles.
  • 04Starland RAT can perform defense evasion, system reconnaissance, browser data and cryptocurrency wallet theft, screenshot collection, persistent C2 communication, and execution of additional payloads.
  • 05Talos observed that UAT-11795 can deploy CastleStealer through x64 shellcode, Remcos RAT through x32 shellcode, and WLDR agent through a PowerShell stager executed via Starland RAT.

Cisco Talos is disclosing UAT-11795, a sophisticated Russian-speaking, financially motivated adversary that has targeted users in the United States and Europe since at least June 2025. The campaign is predominantly observed in the United States, with fewer potential impacts in Germany, Romania, and Venezuela based on passive DNS data. The actor uses trojanized installers for software including MobaXterm, Cisco WebEx, Zoom, DBeaver Community Edition, and FACEIT, suggesting an opportunistic, volume-driven distribution model across multiple victim profiles.

The campaign delivers a Python-based remote access tool called Starland RAT and a PowerShell-based command-and-control memory implant called the WLDR agent. Starland RAT performs defense evasion, persistence, system reconnaissance, screenshot collection, browser data and cryptocurrency wallet theft, and communication with command-and-control infrastructure. It can also receive commands to run shell commands, execute 32-bit or 64-bit shellcode, or download and run additional files, with CastleStealer and Remcos RAT observed as additional payloads.

The infection chain likely begins with a ClickFix technique that causes execution of a remotely hosted weaponized HTA file through mshta.exe, which then downloads and runs a trojanized installer. Starland RAT uses hardcoded and fallback command-and-control mechanisms, including a Polygon smart contract that stores an XOR-encrypted fallback domain. The WLDR agent runs entirely in memory, uses encrypted HTTP communications, performs host reconnaissance, polls its command-and-control server, and executes PowerShell tasks through a Runspace engine.

  • Starland RAT uses a Polygon smart contract to recover a fallback command-and-control domain when primary registration fails, giving defenders a blockchain artifact to monitor in addition to conventional domains.
  • The campaign’s command-and-control URLs include a victim hardware identifier derived from the C: drive volume serial number, which means network paths containing unusual numeric host-specific identifiers may be useful hunting clues.
  • The initial HTA file establishes persistence through the HKCU Run key with the generic value name “MyApp” pointing to mshta.exe, creating a concrete host-based indicator for investigation.
  • Starland RAT checks for a Zone.Identifier alternate data stream on the trojanized installer to confirm that the file was downloaded through a browser, showing that the malware is designed to avoid some analysis environments where samples are copied rather than downloaded.
  • The WLDR agent refuses to run unless it inherits a globally scoped command-and-control URL and session password from the loader, indicating that partial capture of later-stage PowerShell code may not be enough to reproduce or analyze its behavior without the loader context.

Cisco Talos says a Russian-speaking criminal group called UAT-11795 has been tricking people in the United States and Europe into installing fake versions of common software such as remote access tools, video meeting apps, database software, and a gaming platform. Once installed, the malicious programs can secretly stay on the computer, collect information about the person’s device, look for saved passwords and cryptocurrency wallets, take screenshots, and receive further instructions from the attackers. This matters because the campaign is aimed at stealing money and accounts, and it can affect many different kinds of users rather than one specific industry.

It provides concrete infection-chain details, payload behavior, infrastructure, and detection coverage for Starland RAT, WLDR agent, CastleStealer, and Remcos RAT.
