Microsoft pushes Windows emergency updates to fix activation failures

Microsoft released emergency out-of-band updates for Windows 10, Windows 11 23H2, and Windows Server to fix activation and licensing failures introduced by November security updates, primarily affecting organizations that automate licensing with Slmgr.vbs.
KEY POINTS
  • 01Microsoft released emergency out-of-band Windows updates to address activation and licensing failures caused by the November security updates.
  • 02The issue affects organizations that use the Slmgr.vbs command-line tool to automate Windows activation and licensing processes.
  • 03Devices that are already activated are expected to remain activated, and customers with the appropriate KMS client key and configuration who do not run affected Slmgr.vbs commands are not expected to be affected.
  • 04The emergency updates cover Windows Server 2019, 2022, and 2025, Windows 10 21H2 and 22H2 variants, and Windows 11 version 23H2.
  • 05Most of the out-of-band updates are available only through the Microsoft Update Catalog, while the Windows 11 23H2 update is also available as an optional Windows Update.

Microsoft released emergency out-of-band Windows updates to fix activation and licensing failures caused by the November 2026 security updates. The issue affects organizations that use the Slmgr.vbs command-line tool to automate Windows activation and licensing processes. Microsoft said devices that are already activated remain activated, and organizations with the correct KMS client key and configuration that do not need to run the affected commands are not expected to be affected.

The emergency updates apply to Windows Server 2019, 2022, and 2025; Windows 10 Enterprise LTSC 2019 and 2021; Windows 10 22H2 ESU; and Windows 11 version 23H2. Updates for Windows Server 2025, Server 2022, Server 2019, and Windows 10 are available only through the Microsoft Update Catalog, while the Windows 11 23H2 update is also available through Optional updates in Windows Update. Microsoft said the cumulative updates also include the improvements from the November 2026 Windows security update.

  • The activation problem is limited to organizations that need to run affected Slmgr.vbs licensing commands, rather than all Windows devices receiving the November security updates.
  • Already activated devices remain activated, which reduces the immediate operational impact for organizations whose licensing configuration is already in place.
  • Organizations using affected Windows Server or Windows 10 versions must obtain the emergency fixes through the Microsoft Update Catalog, while Windows 11 23H2 users can also install its fix through Optional updates in Windows Update.
  • The emergency patches are cumulative and include the November 2026 Windows security-update improvements, so organizations do not need to choose between the security fixes and the activation correction.

Microsoft issued emergency fixes after its November security updates caused some Windows computers to fail when companies tried to activate or manage their software licenses. The problem mainly affects organizations that use Microsoft’s command-line licensing tool to automate this work; computers that were already activated or use the correct licensing setup are generally not affected. This matters because companies rely on valid Windows licenses to keep computers and servers properly configured and operating, and the issue follows other recent update-related problems involving SQL Server, printing, and Windows 11 installation failures.

It is particularly relevant to administrators using Slmgr.vbs or KMS-based licensing automation, though it does not describe active exploitation or a security vulnerability.

New NoisyTCP vulnerability lets attackers crash Linux servers

Researchers disclosed NoisyTCP (CVE-2026-99288), an 11-year-old Linux kernel flaw that lets unauthenticated remote attackers crash affected Linux servers by triggering a TCP race condition. A mainline kernel fix is available; organizations should patch promptly or mitigate by disabling SYN cookies or using a single RX queue if patching is not immediately possible.
KEY POINTS
  • 01NoisyTCP, tracked as CVE-2026-99288, is an 11-year-old Linux kernel flaw that can allow unauthenticated remote attackers to crash affected systems using crafted TCP packets.
  • 02The flaw is caused by a race condition involving SYN cookie handling and socket hashing that can lead to a NULL pointer dereference and a kernel panic.
  • 03Linux systems that receive TCP packets directly and run Nginx, Apache, or an SSH server may be affected, especially systems with two or more receive queues or traffic distributed across multiple CPUs.
  • 04The reported impact is denial of service: the vulnerability can crash the host but does not allow attackers to alter data or execute arbitrary code.
  • 05A fix has been merged into the mainline Linux kernel, and temporary mitigations include disabling SYN cookies or using a single receive queue when immediate patching is not possible.

Researchers disclosed NoisyTCP, tracked as CVE-2026-99288, an 11-year-old Linux kernel vulnerability affecting almost all Linux distributions. The pre-authentication remote flaw can allow attackers to crash Linux systems running Nginx, Apache, or SSH services with default configurations. It is a denial-of-service issue that causes a kernel panic and host outage, but it does not allow data modification or arbitrary code execution.

The issue stems from a race condition in the kernel’s TCP networking subsystem that can access recycled socket memory before it is initialized and properly hashed, resulting in a NULL pointer dereference. Exploitation requires specifically timed packet processing across different receive contexts, and may be possible on systems with at least two RX queues or packet distribution across multiple CPUs; the researcher noted that crashing quiet bare-metal servers can take a long time. A fix has been merged into the mainline Linux kernel, while organizations unable to patch immediately can disable SYN cookies or use a single RX queue, although disabling SYN cookies reduces protection against SYN flood attacks.

  • Successful exploitation depends on a narrow timing window, so crashing a quiet bare-metal server may take a long time.
  • The attack requires packet processing across different receive contexts, meaning systems with two or more receive queues or traffic distributed across multiple CPUs are susceptible to the required race condition.
  • Disabling SYN cookies can mitigate the issue when patching is delayed, but doing so reduces the server's protection against SYN flood attacks.
  • The disclosed impact is limited to service disruption: the flaw crashes the operating system but does not provide data modification or arbitrary code execution.

A newly disclosed 11-year-old flaw in Linux can let an unauthenticated person send specially made internet traffic that crashes a server. It affects many Linux systems that directly receive network traffic and run common services such as Nginx, Apache, or SSH. The flaw does not let attackers steal or change data, but it can take websites and remote-access services offline, making it a serious availability risk until systems are updated with the available fix.

OPEN SOURCE ↗

This is a broadly relevant remote denial-of-service vulnerability in the Linux kernel affecting commonly deployed server services, with a fix already available. It is not reported as actively exploited and does not enable data theft or code execution, but affected organizations should assess and patch promptly.

Amazon Uncovers AI Agent Campaign Targeting LiteLLM, Dify, and Other Apps for API Keys

Amazon observed attackers using ARTEX AI agents to rapidly scan exposed AI application platforms such as LiteLLM, Dify, and RAGFlow for default credentials, unpatched flaws, and leaked API keys. The campaign highlights that internet-facing AI gateways and static CI/CD tokens can expose high-value provider credentials unless organizations patch systems, rotate secrets, and enforce strong access controls.
KEY POINTS
  • 01Amazon Threat Intelligence captured records from AI agents that targeted internet-exposed AI applications, including LiteLLM, One API, and Dify, to obtain stored AI-provider keys.
  • 02Amazon assessed with moderate confidence that the agents used ARTEX, an open-source AI penetration-testing tool, although it could not verify the outcomes the agents reported from systems outside its decoy network.
  • 03The captured playbook included default administrator credentials, unfinished installations, unauthenticated management endpoints, an isCliRequest-header authentication bypass in One API family systems, and server-side request forgery paths to cloud metadata services.
  • 04Cloudflare investigated an ARTEX-related incident involving a compromised account-level API token used for CI/CD, followed by the creation of Worker scripts and roughly 400 database-dump requests within an hour.
  • 05Amazon recommended that organizations change default credentials, remove and rotate exposed secrets, patch affected software, and monitor AI services for unexpected spending or unusual usage.

Amazon Threat Intelligence captured records from decoy AI services showing attackers’ agents searching internet-exposed AI applications, including LiteLLM, One API, and Dify, for AI-provider API keys. Amazon assessed with moderate confidence that the activity used ARTEX, an open-source AI penetration-testing tool, but said it could not verify outcomes the agents reported for systems outside its decoy network. The records suggest that working stolen keys were pooled and reportedly used to run the AI models that supported further searches for credentials.

The agents’ playbook covered default administrator credentials, incomplete installations, unauthenticated settings pages, the isCliRequest authentication bypass in One API family systems, server-side request forgery routes to cloud metadata services, and exposed secrets in code and public files. Cloudflare separately reported an ARTEX-related incident involving a compromised CI/CD API token with no IP restrictions or rate limiting, followed by Worker-script creation and 400 database-dump requests in an hour. Amazon advised organizations to change default credentials, patch affected products, find and rotate exposed secrets, restrict tokens, and monitor for unusual usage or spending.

  • The captured records indicate that stolen AI-provider keys were reportedly used to run the models that helped agents search for additional keys, creating a feedback loop in which compromised accounts could support further targeting.
  • AI gateways and application builders are especially high-value targets because a single exposed administrative interface can store credentials for multiple AI providers and accounts.
  • Cloudflare found that static CI/CD tokens with no expiration, IP restrictions, or rate limiting enabled broad account activity, including hundreds of database-dump requests in one hour.
  • Cloudflare’s newer API-token prefix, `cfut_`, can help secret-scanning tools identify exposed tokens, while the article also lists distinctive `artex-*` Worker-script names defenders can search for.

Amazon found evidence that attackers are using an AI-powered tool called ARTEX to search internet-connected AI apps, including LiteLLM and Dify, for exposed passwords and keys that unlock paid AI services. The attackers’ records suggest they then tested stolen keys and added working ones to a shared collection, potentially letting them use victims’ accounts and services. Organizations running these apps, as well as companies with poorly protected cloud or software-building accounts, may be affected. The concern is that AI tools can help attackers repeat ordinary break-in attempts much faster and across many targets, making basic mistakes such as default passwords or publicly exposed secrets more costly.

SANSAR Linux Cryptomining Malware Uses Modified NVIDIA Library to Hide GPU Activity

Elastic Security Labs reports that the REF3364 cryptomining operation uses the Rust-based SANSAR toolkit, a Linux kernel rootkit, and a modified NVIDIA NVML library to mine cryptocurrency while hiding processes, files, network activity, and GPU utilization. The attackers reportedly gain access through exposed Ray job agents and maintain control via TOR-based C2 and an Ethereum smart-contract-assisted backdoor.
KEY POINTS
  • 01Elastic Security Labs attributed a Linux-focused cryptocurrency-mining operation to a financially motivated cluster tracked as REF3364, which uses a Rust-based toolkit named SANSAR.
  • 02The documented attack chain began with an exposed Ray job agent, which attackers used to run commands, inventory GPUs, establish a reverse shell, and add an SSH key for persistent access.
  • 03After obtaining root access, the attackers installed the acpi_thermal_mgr kernel module through DKMS and an initramfs loader so the rootkit could reload when the host booted.
  • 04A modified NVIDIA Management Library wrapper causes tools such as nvidia-smi to report zero GPU utilization and replaces temperature and power readings with randomized values.
  • 05SANSAR uses a TOR onion service for command-and-control, while the netns backdoor obtains a controller address from an Ethereum smart contract and connects to it on TCP port 8080.

Elastic Security Labs attributed a Linux cryptocurrency-mining operation to the financially motivated REF3364 cluster. The operation uses SANSAR, a Rust-based tool that receives commands through the TOR network and manages CPU and GPU mining software. Attackers were observed gaining access through an exposed Ray job agent, running commands to collect GPU inventory, and then deploying a Python reverse shell. They added an SSH key to maintain access and, after obtaining root privileges, staged their toolkit under /opt/vadi_.

The attackers installed the acpi_thermal_mgr kernel rootkit through DKMS along with an initramfs loader, allowing it to load again at boot. The rootkit uses ftrace to hide selected processes, directories, files, and socket entries, and it can make requests for concealed items return messages such as “No such file or directory.” A modified NVIDIA Management Library wrapper also alters data shown by monitoring tools such as nvidia-smi, reporting zero GPU utilization and replacing temperature and power readings with randomized values.

SANSAR contacts a TOR onion service for command-and-control and can launch or stop miners, update their settings, open interactive shells, and maintain the GPU-monitoring hook. The toolkit uses XMRig for CPU mining and SRBMiner-MULTI for GPU mining, while a separate netns backdoor retrieves a controller address from an Ethereum smart contract and connects over TCP port 8080. Elastic warned that organizations operating GPU infrastructure for AI and large language model workloads should review who can submit jobs and whether GPU monitoring libraries have been altered, as concealed mining can consume legitimate compute resources and raise costs.

  • GPU monitoring alone may not reveal this mining activity because the modified NVIDIA library makes tools such as nvidia-smi report 0% utilization while supplying plausible-looking random temperature and power values.
  • The rootkit’s use of an initramfs loader makes its persistence more durable than a running-process-only infection, because it can be loaded again during system boot before the normal Linux filesystem is used.
  • The operation uses two separate control paths: SANSAR communicates through a TOR onion service, while the netns backdoor retrieves a controller address from an Ethereum smart contract before opening a TCP connection.
  • The attackers’ initial GPU inventory collection through Ray jobs indicates that exposed job-management services can provide both remote command execution and reconnaissance of valuable GPU resources.
  • Organizations using GPU infrastructure for AI and large language model workloads risk losing legitimate compute capacity and incurring higher operating costs when cryptomining activity is concealed.

A group known as REF3364 has been breaking into Linux computers through publicly exposed Ray job-management services and secretly using their CPUs and NVIDIA graphics processors to generate cryptocurrency. Its SANSAR software hides the heavy graphics-card use by making common monitoring tools show zero activity, while other components conceal files and processes and preserve access after a restart. This especially affects organizations running GPU systems for AI and large language model work, because stolen computing capacity can slow legitimate jobs and raise electricity and operating costs.

It is especially relevant to organizations operating NVIDIA GPU infrastructure because the malware falsifies common GPU monitoring data while consuming compute resources.

A USB worm’s second life: Retadup spreading CoffeeLoader

A revived Retadup USB worm infrastructure is distributing a new CoffeeLoader variant that uses an OpenGL-based Armoury packer, persistence via Run registry keys, process injection, and signed HTTPS payload downloads. The campaign has affected roughly 15,000 systems, primarily in Peru, Angola, Russia, and Bolivia.
KEY POINTS
  • 01Kaspersky detected a new CoffeeLoader variant in August 2026 that uses a patched 7-Zip library and a new Armoury packer variant to decrypt malicious code with the GPU through OpenGL.
  • 02The CoffeeLoader downloader establishes persistence by copying itself into ProgramData or LocalAppData, creating a Windows Run registry entry, and launching or injecting into processes such as dllhost.exe, WerFault.exe, svchost.exe, OpenWith.exe, or AtBroker.exe.
  • 03The downloader retrieves CoffeeLoader's main component over HTTPS from a hardcoded command-and-control server, verifies the downloaded data using an embedded public key and an MD5 checksum, and then runs the decrypted code.
  • 04CoffeeLoader is being distributed through revived Retadup command-and-control domains that issue commands to older Retadup infections, including infections spread through USB drives and shortcut files.
  • 05Kaspersky blocked Retadup infection attempts on around 15,000 systems during the first three quarters of 2026, with most detections in Peru, Angola, Russia, and Bolivia.

Kaspersky detected a new CoffeeLoader variant in August 2026 that is delivered through a patched 7-Zip library named 7z.dll, launched with rundll32.exe. The library contains a new version of the Armoury packer, which uses the computer’s graphics hardware through OpenGL to decrypt malicious code. The decrypted CoffeeLoader downloader combines installation, automatic-start, process-injection, and payload-download functions.

The downloader copies itself into ProgramData or LocalAppData, creates a Windows Run registry entry, and attempts to prevent users from disabling that entry through Task Manager. It injects into processes including dllhost.exe, WerFault.exe, svchost.exe, OpenWith.exe, or AtBroker.exe, then downloads CoffeeLoader’s main component over HTTPS and verifies it with an embedded public key and MD5 checksum. The campaign is spread through revived Retadup worm command-and-control domains, which can issue commands to older USB-spreading Retadup infections; Kaspersky blocked attempts on around 15,000 systems in the first three quarters of 2026, mainly in Peru, Angola, Russia, and Bolivia.

  • Retadup systems that survived or remained active after the 2019 takedown can still accept commands in 2026 because its simple command protocol has allowed re-registered former command-and-control domains to take over communication.
  • The new CoffeeLoader downloader creates a StartupApproved registry entry specifically intended to prevent users from disabling its automatic start through Task Manager.
  • CoffeeLoader’s updated Armoury packer still uses the computer’s graphics hardware for decryption but has changed from OpenCL to OpenGL.
  • CoffeeLoader now verifies signed command-and-control responses with an embedded public key instead of validating the server certificate, while also checking the decrypted payload’s MD5 value.
  • The revived Retadup infrastructure has served more than one downstream threat: it initially delivered SmokeLoader and later began distributing CoffeeLoader.

Old internet servers once used by the Retadup USB-spreading worm have been brought back online and are now telling infected computers to download CoffeeLoader, another harmful program. Retadup can move from one computer to another through USB drives when someone clicks a shortcut that looks legitimate. The new program hides itself, starts automatically whenever Windows starts, and can download and run further programs chosen by its operators. About 15,000 attempted Retadup infections were blocked in the first three quarters of the year, mainly in Peru, Angola, Russia, and Bolivia, showing that old infections can remain dangerous long after a criminal network is thought to be shut down.

OPEN SOURCE ↗

This is a concrete, active malware-distribution campaign in which revived Retadup infrastructure is delivering CoffeeLoader through surviving USB-worm infections. It provides actionable technical indicators, persistence behavior, process-injection targets, command-and-control details, and affected geographies, though the reported scale is relatively limited.
