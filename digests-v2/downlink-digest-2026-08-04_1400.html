Massive ChainDrop npm supply-chain attack infects hundreds of packages

A self-propagating npm worm called ChainDrop compromised more than 1,300 packages, including popular utilities like Keyv and Cacheable, by abusing legitimate GitHub Actions releases to steal developer, cloud, and CI/CD credentials. Anyone who installed affected versions should treat their workstation or runner as compromised, rebuild systems, rotate exposed secrets, and check repositories and logs for unauthorized activity.
KEY POINTS
  • 01Self-propagating malware named ChainDrop has compromised more than 1,300 npm packages with a combined 2 billion monthly downloads.
  • 02The attack began after a threat actor compromised the GitHub account of Keyv’s maintainer and spread to packages associated with organizations including Deliveroo, Ornikar, OneReach, Picsart, Qlik, and ServiceTitan.
  • 03The compromised packages contain a setup.mjs dropper, an infostealing script named Math_Symbol.js or math_init.js, and a package.json preinstall entry that runs the dropper during npm install.
  • 04The malware collects developer and cloud credentials, including GitHub and npm tokens, AWS credentials, Kubernetes secrets, Vault tokens, database credentials, private keys, and credentials for Stripe, Slack, Twilio, Azure, and GCP.
  • 05Administrators who installed affected package versions are advised to treat workstations or CI/CD runners as compromised, rebuild systems, rotate accessible tokens, and review logs and repositories for unauthorized activity.

Self-propagating malware named ChainDrop has compromised more than 1,300 npm packages with a combined 2 billion monthly downloads. Infected packages include popular caching utilities such as Keyv, Cacheable, flat-cache, and file-entry-cache. The attack started after a threat actor compromised the GitHub account of Keyv’s maintainer and then spread to packages associated with organizations including Deliveroo, Ornikar, OneReach, Picsart, Qlik, and ServiceTitan.

Security companies found that the attack deployed a Shai-Hulud-based worm that pushed malicious files directly to project main branches and generated new package releases. Because the packages were built and published through legitimate GitHub Actions workflows, the compromised npm releases carried valid provenance information. The poisoned packages included a setup.mjs dropper, a Math_Symbol.js or math_init.js infostealer script, and a package.json preinstall entry that automatically ran the dropper during npm install.

The malware downloads the Bun JavaScript runtime from the official GitHub release to execute the infostealer, which collects developer and cloud credentials from compromised environments. The article says it can gather environment data, local credential files, GitHub and npm tokens, AWS credentials, Kubernetes secrets, Vault tokens, database credentials, private keys, and credentials for services such as Stripe, Slack, Twilio, Azure, and GCP. Administrators who installed an affected package version are advised to treat the workstation or CI/CD runner as compromised, rebuild systems, rotate accessible tokens, and review logs and repositories for unauthorized access or changes.

  • The malware validates npm tokens in real time against registry.npmjs.org/-/whoami before stealing them, indicating that exposed tokens should be assumed usable if they were present in an affected environment.
  • Removing an affected package after installation is not sufficient, because the article says impacted developer workstations or CI/CD runners should still be treated as compromised.
  • The npm-cache.com domain is identified by Wiz as a strong indicator of compromise for data exfiltration and should be investigated in network logs.
  • The use of Bun downloaded from the official GitHub release means defenders should not treat the Bun executable alone as suspicious without also checking the surrounding setup.mjs and Math_Symbol.js or math_init.js activity.
