NGINX HTTP/2 Use-After-Free: CVE-2026-123633

CVE-2026-123633 is a critical NGINX HTTP/2 use-after-free affecting reverse proxies under worker-connection pressure, enabling unauthenticated denial of service and potentially code execution if ASLR is bypassed. Upgrade to NGINX 1.30.7 or 1.31.9 (or a vendor-backported fixed package) and review exposed HTTP/2 proxy configurations.
KEY POINTS
  • 01CVE-2026-123633 is an HTTP/2 use-after-free flaw in NGINX that can let an unauthenticated attacker cause a denial of service when a reverse proxy is low on available worker connections.
  • 02Affected versions are NGINX 1.19.7 through 1.30.6 and 1.31.0 through 1.31.8, while NGINX 1.30.7 and 1.31.9 contain the fix.
  • 03The defect can leave an active HTTP/2 request marked as reusable, allowing NGINX to close its connection and free memory still used by the request under connection pressure.
  • 04The researcher reproduced a read from freed DNS resolver memory using AddressSanitizer on NGINX 1.31.7 and 1.31.8 in an isolated Debian test environment.
  • 05F5 states that code execution may be possible when address space layout randomization is disabled or bypassed, and recommends upgrading to a fixed release or vendor package containing the fix.

CVE-2026-123633 is an unauthenticated use-after-free vulnerability in NGINX HTTP/2 reverse proxies that can cause denial of service when available worker connections are low. F5 assigned it a CVSS 4.0 score of 9.2 Critical and stated that code execution may be possible if address space layout randomization (ASLR) is disabled or bypassed. NGINX lists versions 1.19.7 through 1.30.6 and 1.31.0 through 1.31.8 as affected, with fixes in 1.30.7 and 1.31.9.

The flaw occurs because an HTTP/2 connection that begins with a partial request-frame header can remain incorrectly marked as reusable after NGINX creates an active request stream. Under connection pressure, NGINX may reclaim that still-active connection and free DNS resolver memory that the request continues to use; the researcher reproduced a read from freed memory with AddressSanitizer on NGINX 1.31.7 and 1.31.8. The tested path involved a variable proxy upstream requiring request-time DNS resolution, a new resolver UDP socket, connection pressure, and an abortive client close. Organizations should upgrade to a fixed NGINX release or vendor package containing the fix, and should perform a full restart or live binary upgrade because a normal configuration reload retains the old binary in memory.

  • A standard NGINX configuration reload keeps the old binary in memory, so deploying the fix requires a full restart or a live binary upgrade.
  • The connection-pressure warning relevant to investigation is logged at the warn level, but NGINX defaults to an error-log level that omits warnings; the warning is also not proof of exploitation because it can occur during ordinary load.
  • The reproduced path depended on a request-time DNS lookup opening a new resolver UDP socket, meaning cached answers or an existing in-flight lookup could avoid the specific trigger tested.
  • F5 rated the issue 9.2 Critical under CVSS 4.0, while the NGINX security advisories page labeled it Medium, illustrating that published severity labels differ for the same flaw.

The article describes a flaw in NGINX, widely used software that sits in front of websites and passes visitor requests to other servers. An unauthenticated internet user may be able to crash affected NGINX servers when they use HTTP/2 and are under heavy connection pressure; the vendor also says taking control of the server may be possible if a key memory-protection feature is disabled or bypassed. Organizations using affected NGINX versions as HTTP/2 reverse proxies should update to fixed releases, because outages or server compromise can disrupt the websites and services behind them.
