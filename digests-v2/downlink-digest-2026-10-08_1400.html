FakeGit malware campaign returns with 17,610 malicious GitHub repos

The FakeGit campaign has reactivated more than 17,600 GitHub repositories to distribute SmartLoader, which can deliver the StealC infostealer and other malware. The operation evades takedowns by repointing convincing README download links to backup payloads hosted across GitHub assets, forks, and attachments.
KEY POINTS
  • 01The FakeGit campaign resumed activity on October 4 and uses 17,610 GitHub repositories to distribute SmartLoader malware.
  • 02In 34 hours, the campaign pushed more than 13,000 repositories, reaching a peak rate of 2,999 per hour.
  • 03The repositories use convincing README files with download buttons that commonly link to ZIP archives installing SmartLoader, which can distribute other malware including the StealC infostealer.
  • 04Apiiro found that 97% of sampled commits changed only README files, allowing the existing repository fleet to be redirected without creating new repositories.
  • 05FakeGit persists because operators can redirect download links to backup files in forks, old files, release assets, issue attachments, and separate download-hosting repositories.

FakeGit has resumed activity, using 17,610 GitHub repositories to distribute the SmartLoader malware after previously pushing the StealC information-stealing program. Apiiro reported that the campaign reactivated on October 4 and added more than 13,000 repositories in 34 hours, peaking at 2,999 per hour. The operators use mostly disposable accounts, although researchers identified at least 700 accounts that appear to belong to legitimate developers.

The repositories contain convincing README instructions with a Download button that commonly links to a ZIP archive installing SmartLoader, which can deliver other malware. In sampled commits, 97% changed only the README and 88% redirected the Download button to a SmartLoader ZIP, allowing the existing repository fleet to be repurposed without creating new repositories. The campaign is difficult to remove because alternate malicious archives remain in forks, older files, release assets, issue attachments, and separate download-hosting repositories; Apiiro recommends verifying repository owners and using official registries or vendor repositories for AI skills and MCP servers.

  • The campaign can rapidly repurpose an existing stockpile of repositories by changing README files, rather than needing to create new repositories for each wave.
  • At least 700 accounts used by the operation appear to belong to legitimate developers, making repository-owner verification more difficult for users.
  • Apiiro reported that 71% of the malicious repository fleet was absent from URLhaus before its report, indicating that existing public blocklists covered only part of the operation.
  • Blocking GitHub at the domain level would not selectively stop a single malicious file, while attackers can retain alternate copies in forks, releases, old files, and issue attachments.

A campaign called FakeGit is using more than 17,000 fake GitHub project pages to trick people into downloading files that install harmful software. The pages look believable and often use a download button in their instructions, while some appear under accounts that look like real developers. This puts people seeking software, especially AI-related tools, at risk of having their information stolen or their GitHub accounts taken over. Removing individual links has not stopped the campaign because its operators can quickly redirect downloads to spare copies stored elsewhere on GitHub.

Cisco released advisories for five critical vulnerabilities in NX-OS that could allow attackers to run arbitrary code with root privileges on affected Nexus switches. If code execution is not achieved, the flaws could instead crash processes and reload the device, causing denial of service. Cisco said it found the issues during internal testing and was unaware of public disclosure or malicious exploitation when the advisories were published.

The flaws affect Nexus 3000 and Nexus 9000 Series switches running standalone NX-OS, provided NX-API, Next Generation OAM (NGOAM), or MPLS OAM is enabled. CVE-2026-76471 can be triggered through a crafted HTTP request to NX-API, while CVE-2026-76485, CVE-2026-76486, and CVE-2026-76501 involve crafted IP traffic when NGOAM is active. CVE-2026-76465 involves crafted MPLS echo-request packets; Nexus 7000 devices and Nexus 9000 switches in ACI mode are unaffected by all five flaws.

Cisco recommends upgrading to fixed NX-OS releases identified through its Software Checker tool and disabling affected features that are not needed. For devices that cannot immediately be upgraded and rebooted, Cisco provides temporary Live Protect shields. Cisco also issued Cisco License hardening updates for four other flaws, including a CVSS 10.0 improper cryptographic signature verification issue, and advises upgrading affected installations to version 10-202609 because no workarounds are available.

  • The practical exposure is highly configuration-dependent: all five Nexus flaws require at least one of NX-API, NGOAM, or MPLS OAM to be active, so disabling unused features removes their attack paths.
  • CVE-2026-76486 has additional deployment requirements, needing either SRv6 or an NV Overlay configuration with a learned VXLAN tunnel endpoint peer.
  • Nexus 7000 switches and Nexus 9000 switches running in ACI mode are not affected by any of the five NX-OS flaws.
  • Cisco License flaws are more broadly urgent because affected releases are vulnerable regardless of configuration, no workaround is available, and older Smart Software Manager releases will not receive patches.

Cisco warned about five serious software flaws in certain Nexus network switches, which are devices used to direct data inside large computer networks. If the affected optional features are turned on, an attacker may be able to take full control of a switch or force it to restart and disrupt network service. The issues affect Nexus 3000 and 9000 switches using standalone NX-OS software, and Cisco advises customers to install updates or turn off features they do not need.
