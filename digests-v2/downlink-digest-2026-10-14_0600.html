AI-Found Linux Kernel Flaw Gives Local Users Root, and Can Break a Guest Out to the Host

CVE-2026-74580 (Vghost) is a Linux vhost flaw that can let local users gain root and, in certain virtualized configurations, allow a guest VM to compromise its host’s QEMU process. Organizations should install patched kernels and restrict access to /dev/vhost-net and /dev/vhost-vsock until patching is complete.
KEY POINTS
  • 01CVE-2026-74580, called Vghost, is a flaw in Linux’s vhost subsystem that can allow a local user to read and write kernel memory and gain root privileges.
  • 02In certain virtual-machine configurations using a virtual IOMMU and device-IOTLB mode, an untrusted guest can use the flaw to write outside intended memory in the host’s QEMU process.
  • 03The issue affects Linux kernels from version 4.11 through 7.2-rc4 and was reproduced on Ubuntu, RHEL, Amazon Linux, Microsoft Azure Linux, and Oracle Linux.
  • 04The upstream fix clears vhost’s memory-mapping cache whenever a virtual ring is reconfigured, and organizations should install a kernel containing commit de845981da67 and reboot.
  • 05Until systems are patched, the article recommends restricting access to /dev/vhost-net and /dev/vhost-vsock; only a patched kernel addresses the guest-to-host path.

Tencent Zhuque Lab disclosed CVE-2026-74580, called Vghost, a flaw in Linux’s vhost subsystem that can let a local user read and write kernel memory and gain root access. The issue affects kernels from Linux 4.11 through 7.2-rc4 and was reproduced on Ubuntu, RHEL, Amazon Linux, Microsoft Azure Linux, and Oracle Linux. In tested Ubuntu systems, access was limited to the kvm group, while four other tested distributions exposed the relevant device node as world-readable.

The flaw stems from a stale cache of virtual-device memory mappings that is not cleared when a live queue’s address or size is changed. With device-IOTLB enabled, vhost can use an old mapping for new addresses and copy data outside the intended memory region, enabling kernel memory reads and writes. In certain virtual-machine setups, an untrusted guest can write outside bounds into the host’s QEMU process and potentially take control of it. The upstream fix clears the cache during queue reconfiguration; until patched kernels are installed and systems rebooted, the article recommends restricting access to /dev/vhost-net and /dev/vhost-vsock, although only patching addresses the guest-to-host path.

  • The local privilege-escalation path is described as deterministic, requiring neither favorable timing nor memory-layout manipulation.
  • Exposure varies significantly by distribution: Ubuntu limited the relevant device node to the kvm group, while four other tested images made it world-readable, allowing any local user to access it.
  • The flaw resulted from the interaction of two otherwise reasonable changes made in 2017 and 2020, which left a stale memory-mapping cache usable for roughly nine years.
  • Restricting access to vhost device nodes can reduce local-user risk before patching, but the article states that only a patched kernel remedies the guest-to-host escape path.

Researchers found a serious flaw in many versions of Linux that could let someone with access to a computer become its all-powerful administrator. In some setups, a program running inside a virtual computer could also interfere with the real computer hosting it. The problem affects systems using Linux versions from 4.11 through 7.2-rc4, including tested releases from Ubuntu, Red Hat, Amazon, Microsoft, and Oracle. Installing an updated Linux version is important because the flaw could let untrusted users take control of affected systems.

OPEN SOURCE ↗

This is a high-impact Linux kernel vulnerability with a reliable local privilege-escalation path and a guest-to-host escape scenario in specific virtualized configurations. Security professionals responsible for Linux systems or virtualization should prioritize patching affected kernels and restricting vhost device access, although no public exploitation has been reported.

Introducing the NetSPI Platform MCP

NetSPI has launched a Model Context Protocol integration that lets AI clients such as Claude query live pentest findings, prioritize remediation, and draft code fixes and pull requests. The integration is intended to move vulnerability management from static reports into automated engineering workflows.
KEY POINTS
  • 01NetSPI introduced a Model Context Protocol integration that connects the NetSPI Platform to AI clients so users can query vulnerability findings in natural language.
  • 02The integration is presented as an alternative to relying solely on static PDF pentest reports, providing live insights for prioritizing and remediating findings.
  • 03In the example workflow, users ask an AI client for newly published project findings and then request prioritization with OWASP Top 10 categories and context.
  • 04NetSPI demonstrates using Claude Code to retrieve high-severity findings, locate the described issues in a codebase, and draft pull requests with descriptions of the changes.
  • 05The article suggests combining NetSPI Platform data with other workflows, including creating Jira tickets and providing project updates through Slack.

NetSPI introduced its Platform Model Context Protocol (MCP), an integration that connects the NetSPI Platform with AI tools. The company says the integration provides a live view of vulnerabilities in an organization’s environment and supports faster remediation. MCP is described as an open-source standard that lets AI systems connect to data sources through natural-language requests rather than requiring users to know API formats and parameters.

The article demonstrates connecting the Platform MCP server to Claude Desktop, asking for newly published findings in a project, and requesting prioritization with OWASP Top 10 categories and context. It then shows using Claude Code to retrieve high-severity findings, locate the described issues in a codebase, and draft pull requests explaining the proposed changes. NetSPI says the integration can move pentest findings beyond static PDF reports and can also be combined with workflows such as Jira ticket creation and Slack project updates.

  • The integration is designed to make pentest findings usable directly within AI tools rather than requiring users to know API formats and parameters.
  • The demonstrated workflow spans the full remediation path, from identifying findings published the prior day to generating pull requests for high-severity fixes in a few minutes.
  • The article indicates that finding prioritization can incorporate an organization’s own formats and use cases, not only OWASP Top 10 categories.
  • NetSPI positions the integration for multiple audiences, including engineers preparing code fixes and executives seeking summaries of the organization’s security posture.

NetSPI introduced a connection that lets people use an AI assistant to look up security problems found in their organization’s software. Software developers, security teams, and business leaders can ask questions in everyday language, decide which problems matter most, and prepare code changes or work tickets to fix them. This matters because it can replace slow, static reports with current information and help organizations address serious software weaknesses more quickly as development speeds up.

OPEN SOURCE ↗

This is a vendor announcement and workflow demonstration for NetSPI’s MCP integration, not a report of an active threat, breach, vulnerability disclosure, or urgent patch. It may interest teams using the NetSPI Platform and AI-assisted remediation, but it is primarily product-focused and evergreen.

Beyond the Wallet: How Identity Intelligence Helps Investigators Uncover Crypto Crime

Constella promotes its identity intelligence data, including breach and infostealer-derived records, as a complement to TRM Labs' blockchain analytics for investigating crypto-enabled crime. The combined approach is intended to help investigators link wallet activity with digital identities while treating correlations as leads rather than proof of attribution.
KEY POINTS
  • 01Blockchain intelligence can help investigators trace cryptocurrency transactions, examine wallet relationships, and understand how funds move.
  • 02Identity intelligence can help investigators explore digital footprints around email addresses, usernames, credentials, and other data exposed through breaches, ransomware attacks, and infostealer infections.
  • 03Constella says its data can provide leads that investigators should assess alongside transaction evidence, account records, victim reports, and other case information rather than treating them as proof of identity or wrongdoing.
  • 04Stolen or exposed credentials may mean that an account linked to suspicious activity belongs to a victim or has been compromised, purchased, or shared rather than operated by a criminal.
  • 05Constella is participating as a data partner for TRM Labs' Orion launch, contributing identity intelligence intended to complement TRM's blockchain transaction and network analysis.

Constella describes how identity intelligence can complement blockchain intelligence in cryptocurrency investigations. TRM Labs’ tools help analysts trace transactions, examine wallet relationships, and follow the movement of funds, while Constella provides context from exposed identity-related data. The article argues that investigators need both financial trails and information about the accounts, identities, and online activity surrounding them.

Constella’s intelligence draws on data breaches, ransomware attacks, and infostealer infections to help analysts explore connections among email addresses, usernames, credentials, and other exposed attributes. The company says this information can generate leads, including possible cryptocurrency-related accounts or wallet addresses, but does not establish wallet ownership or criminal responsibility on its own. Constella is participating as a data partner for TRM’s Orion launch, with the stated goal of helping law enforcement, financial-crime teams, and intelligence organizations investigate crypto-enabled fraud and other crime while carefully validating attribution.

  • An email address or username associated with a crypto case may lead to other online personas, but investigators must determine whether those personas are relevant, belong to a victim, or are unrelated.
  • Exposed credentials can indicate that an account used in suspicious activity was compromised or misused, so its apparent owner may not be the person operating it.
  • Infostealer-derived records can sometimes include cryptocurrency wallet addresses, creating additional starting points for tracing funds on the blockchain.
  • Combining identity and transaction information helps investigators test competing explanations before making attribution decisions.

The article says that tracing cryptocurrency payments can show where money moved, but investigators also need clues about the people and online accounts connected to those payments. Constella is providing information from leaked and stolen account data to support TRM Labs’ Orion platform, helping investigators look for links among email addresses, usernames, and possible crypto accounts. This may help police, financial-crime teams, and intelligence groups investigate fraud and other crypto-related crime, but the article stresses that these links are leads to check, not proof that someone committed a crime.

OPEN SOURCE ↗

This is a vendor-promotional, evergreen discussion of combining blockchain and identity intelligence for cryptocurrency investigations. It reports no specific incident, active threat, vulnerability, or urgent defensive action.
