From a Stolen Login to a Ransomware Leak Site: What Our Telemetry Shows About the Path Threat Actors Take

Constella links Fairlife’s public Anubis ransomware leak to a broader pattern where stolen credentials from infostealer-infected vendor laptops can give attackers access to corporate CMS, cloud, SSO, and internal systems. The key takeaway is that third-party credential exposure, including cookies and browser autofill data, must be monitored as seriously as a company’s own endpoints because it can become the first step toward ransomware.
KEY POINTS
  • 01Anubis added Fairlife, a dairy brand owned by The Coca-Cola Company, to its dark web extortion portal, and Coca-Cola publicly confirmed the ransomware incident.
  • 02Anubis claimed it exfiltrated close to a terabyte of internal data and used an optional wipe mode against part of the victim’s virtualization infrastructure.
  • 03The leaked data was organized into engineering and OT documentation, production and formulation data, and HR and people data.
  • 04Constella analyzed a separate credential package believed to belong to a third-party digital agency employee that contained 789 saved credential pairs, 540 browser session cookies, and a local password manager vault store.
  • 05The credential package included hundreds of credentials for brand site content management environments, plus credentials for cloud infrastructure, DevOps, source control, corporate identity, and SSO providers.

Anubis added Fairlife, the dairy brand owned by The Coca-Cola Company, to its dark web extortion portal, and Coca-Cola publicly confirmed the ransomware incident. The group claimed it exfiltrated close to a terabyte of internal data before triggering encryption and said it used an optional wipe mode against part of the victim’s virtualization infrastructure. The leak site organized the stolen data into engineering and OT documentation, production and formulation data, and HR and people data, including employee directories, payroll-related files, disciplinary records, and some identity documents.

The article pairs that public ransomware disclosure with a separate credential package Constella observed through an unrelated channel, while stating that it cannot prove the package was the entry point used by Anubis. The package is described as belonging to an employee of a third-party digital agency contracted to build and maintain staging and production websites for several Coca-Cola brands. It contained 789 saved credential pairs, 540 browser session cookies, a local password manager vault store, and extensive evidence of password reuse across content management, cloud infrastructure, DevOps, source control, corporate identity, and SSO environments.

A major technical point is that the package exposed more than passwords and cookies, because browser autofill data also revealed client-side identity details, internal document references, network information, cloud activity, and deployment environment names. The article says the package included hundreds of credentials for Adobe Experience Manager environments, public IP-based admin consoles, AWS sign-ins across four regions, and evidence that the same vendor employee had access connected to more than one enterprise client. Constella uses the case to argue that third-party credential exposure can create a ransomware pathway outside the victim’s own endpoints, especially when stolen logins surface in infostealer logs, credential compilations, and broker marketplaces before a public leak appears.

  • The article highlights that browser autofill data can reveal internal documents, environment names, infrastructure actions, and client identities, making it a valuable exposure source that many credential monitoring tools may miss.
  • The credential package showed heavy password reuse, with 789 credential pairs protected by only 118 unique passwords and the most common password reused 146 times across 87 hosts.
  • A single vendor employee’s infected laptop can blur third-party and internal risk when the person has both vendor identities and a client-issued email account tied to internal documents and systems.
  • Session cookies in stolen browser data can matter as much as passwords because, if still valid, they may allow access to already authenticated sessions without triggering a password entry or multi-factor prompt.
  • The article emphasizes that credentials may appear first in generic compiled lists before being verified and repackaged by initial access brokers, making early monitoring of compilations potentially important before a public ransomware disclosure occurs.

The article explains that Fairlife, a dairy brand owned by The Coca-Cola Company, was named on a ransomware leak site after attackers claimed to steal nearly a terabyte of internal data, including engineering, production, and employee records. It also shows how a separate stolen login package from a third-party vendor’s laptop could expose access to brand websites, cloud tools, internal documents, and work accounts, even if that laptop was outside the victim company. This matters because one infected vendor device can put many companies and their employees at risk, and stolen logins can quietly circulate for weeks or months before being used in a public extortion incident.

OPEN SOURCE ↗

This is a should-read article because it centers on a specific public ransomware incident involving Fairlife and The Coca-Cola Company, attributed on a leak site to Anubis, and pairs it with concrete telemetry from a related type of credential exposure. Its broader value is in showing how third-party infostealer data, session cookies, autofill data, CMS access, and cloud credentials can create a realistic path toward ransomware impact.

pnpm 12’s Rust Rewrite Cuts Install Times by Up to 90%

pnpm 12 is now stable with a Rust rewrite that keeps pnpm 11 compatibility while delivering major install-time and storage improvements in early real-world testing. Its maintainers have narrowed public benchmark claims after flawed cross-package-manager comparisons, emphasizing faster pnpm performance rather than claiming overall market leadership.
KEY POINTS
  • 01pnpm 12 is now stable and replaces pnpm’s Node.js and TypeScript foundation with a Rust rewrite while preserving the commands, settings, and lockfile format used by pnpm 11.
  • 02In Vercel’s 21-project Turborepo workspace, pnpm 12 reduced median install times by 64.4% to 90.5% compared with pnpm 10.28 across six tested scenarios.
  • 03pnpm removed Bun and Yarn from the comparison displayed on its benchmark page after bugs made published cross-tool package manager rankings unreliable.
  • 04pnpm 12 adds supply chain security-related features including project-aware global bins, direct package manager provisioning, registry revisions, signed remote build artifacts, and deterministic cyclic lockfiles.
  • 05The upgrade has behavioral changes that may affect workflows, including removal of `pnpm install --resolution-only`, canonical HTTPS resolution for Git dependencies on GitHub, GitLab, and Bitbucket, and warnings for unknown settings in `pnpm-workspace.yaml`.

pnpm 12 is now stable and replaces the package manager’s Node.js and TypeScript foundation with a Rust rewrite while preserving the commands, settings, lockfile format, CLI, configuration, and content-addressable store used by pnpm 11. The release is intended to be a major implementation change without becoming a migration project for users, and the same documentation applies to pnpm 11 and 12. As of publication, npm’s latest tag still points to pnpm 11, so pnpm 12 must be installed from next-12.

The Rust rewrite moves performance-sensitive work into a native binary to reduce JavaScript runtime startup and filesystem overhead. In Vercel’s 21-project Turborepo workspace with 1,670 packages, pnpm 12 reduced median install times by 64.4% to 90.5% compared with pnpm 10.28 across six tested combinations of cache, node_modules, and lifecycle-script conditions. The largest reduction occurred when node_modules already existed, while a full install with no store or node_modules and lifecycle scripts enabled fell from 9.850 seconds to 3.472 seconds.

The article also notes that pnpm narrowed its public benchmark claims after flaws made cross-tool comparisons with Bun and Yarn unreliable, and its website now compares the Rust rewrite with npm and pnpm’s previous JavaScript implementation. Beyond performance, pnpm 12 adds supply chain security and reproducibility changes including project-aware global bins, direct package manager provisioning, registry revisions, signed remote build artifacts, and deterministic cyclic lockfiles. Teams upgrading should review behavioral changes such as the removal of pnpm install --resolution-only, canonical HTTPS Git dependency URLs for GitHub, GitLab, and Bitbucket, stricter reporting of unknown workspace settings, and refusal to run global pnpm-modifying commands under sudo.

  • Teams may not get pnpm 12 by default yet because npm’s `latest` tag still points to pnpm 11, so users must install it from `next-12` or run `pnpm self-update next-12` from pnpm 11.10 or newer.
  • The biggest measured speedup in Vercel’s testing occurred when `node_modules` already existed, where install time fell from about 1.4 seconds to about 0.14 seconds, showing the rewrite has especially large benefits for repeated installs in an existing workspace.
  • The Rust rewrite introduces a distribution tradeoff: pnpm 12’s native Corepack artifact is much larger than pnpm 10.28’s artifact and made uncached Corepack startup slower, even though cached startup was much faster.
  • pnpm 12’s stricter handling of unknown `pnpm-workspace.yaml` settings is security-relevant because it can reveal misspelled controls such as `minimumReleaseAge` that were previously ignored silently.
  • Organizations using SSH-based private Git dependencies may need machine-level Git URL rewriting because pnpm 12 records GitHub, GitLab, and Bitbucket dependencies using canonical HTTPS URLs in the lockfile.

pnpm 12, a tool many software teams use to download and organize the outside code their projects depend on, is now stable and has been rebuilt in Rust while keeping the same commands and files as the previous version. Early testing in Vercel’s large project showed installs becoming much faster and using less disk space, though the pnpm team stopped making broad claims that it beats rival tools after benchmark problems were found. This matters to developers and companies because faster, more repeatable installs can save time, and the release also adds checks and controls meant to reduce risks from untrusted or changed software packages.

OPEN SOURCE ↗

This is a specific recent release of a widely used package manager with supply chain security and reproducibility changes, so it is relevant to security professionals who track software dependency tooling. It is not urgent because it does not report active exploitation, a breach, or a critical patch.
