Keeping Your Business Moving When the Network Wants to Stop

Netskope promotes its One Private Access platform as a resilient ZTNA solution that separates management and data planes, uses local policy caching and authentication, and automatically fails over during cloud or ISP outages. The article argues this architecture keeps users securely connected without manual emergency network changes.
KEY POINTS
  • 01The article states that outages at public cloud providers or internet service providers can prevent remote and branch employees from accessing internal corporate applications.
  • 02It says legacy connections and first-generation zero trust network access solutions can fail because their management and traffic-handling components are tightly coupled.
  • 03Netskope says its One Private Access separates management from traffic handling and uses locally operated services to keep access policies enforced if the main management system is unavailable.
  • 04The article describes local authentication, localized policy caching, smart traffic steering, and automatic broker failover as mechanisms intended to preserve connectivity during disruptions.
  • 05Netskope also describes clientless browser access, local brokers, SASE Gateways, and hot-standby tenant configurations as backup options for continuity during outages.

The article describes how outages affecting a public cloud provider or internet service provider can interrupt employee access to internal corporate applications. It says these disruptions can leave remote and branch workers unable to work while network security teams perform manual DNS overrides, firewall changes, or attempts to restore older VPN connections. According to the article, this can lead organizations to use broad, less protected access temporarily to maintain operations.

Netskope promotes Netskope One Private Access as an alternative built on the NewEdge Network. It says the platform separates the management plane, where policies are configured, from the data plane that handles user traffic, allowing local enforcement to continue if the main management plane is unavailable. The article describes local authentication, locally cached policies, automatic path routing, broker failover, browser-based access, and on-premises broker or SASE Gateway options as continuity measures. It also states that Netskope can operate as a hot-standby tenant for organizations using another ZTNA provider.

  • The article presents separation of the policy-management system from the traffic-handling system as the key architectural choice that can preserve user access even when the central management environment is disrupted.
  • Netskope says its clients and Publishers select a point of presence through a gateway selection service rather than relying first on DNS, using DNS only as a fallback.
  • The described fallback options extend beyond cloud services: organizations can operate a local virtual broker or deploy a physical or virtual SASE Gateway in their own data center while applying the same zero-trust policies.
  • The article says Netskope can be configured as a hot-standby tenant for organizations using another ZTNA provider, allowing an outage cutover without requiring users to install a new agent in advance.

The article says that when a cloud provider or internet provider fails, employees may suddenly lose access to the company applications they need, leaving technology teams to make rushed manual changes. It promotes Netskope’s service as a way to keep remote and branch-office workers connected by automatically using alternate routes and locally stored access rules when central systems are unavailable. This matters because outages can stop business operations and may pressure companies to temporarily weaken protections just to restore access.

It may be useful background for teams evaluating access-continuity architectures, but it is low priority for timely security awareness.

Cursor Removes Malicious Claude Code 2.1.313 Extension From Its Marketplace

Cursor confirmed that a malicious Claude Code extension version 2.1.313 was distributed through its marketplace and may have affected up to 5,000 users, prompting removal, key rotation, and user notifications. Investigators found no evidence that the same version was published through Open VSX or npm.
KEY POINTS
  • 01Cursor confirmed that a malicious Claude Code extension version 2.1.313 was available in its marketplace on October 29 and could have affected up to 5,000 users.
  • 02The reported macOS extension contained code that added an SSH authorized key, attempted to create a reverse SSH tunnel, and installed persistence mechanisms.
  • 03Cursor removed the extension, rebuilt its marketplace after rotating keys, worked with the hosting provider to take the attacker’s server offline, and is contacting affected users.
  • 04Socket found no Open VSX change-feed events for Claude Code 2.1.313, despite finding records for versions 2.1.312 and 2.1.314.
  • 05The npm metadata, public GitHub releases, and Claude Code changelog also contain no record of version 2.1.313.

Cursor confirmed that a malicious Claude Code extension labeled version 2.1.313 was available through its marketplace on October 29 and may have affected up to 5,000 users. The reported macOS extension added an SSH authorized key, attempted to create a reverse SSH tunnel, and installed persistence so access could remain on an affected computer. Cursor removed the extension, rebuilt its marketplace after rotating keys, worked with the hosting provider to take down the attacker’s server, and is contacting affected users. Its notice also provides hashes for malicious macOS and Windows packages, indicators of compromise, and remediation scripts.

Socket found no evidence that version 2.1.313 was publicly available through Open VSX or npm during the period examined. Open VSX’s change feed included records for the adjacent Claude Code releases 2.1.312 and 2.1.314, as well as 42 other versions that were published and removed, but contained no event for 2.1.313. npm metadata, GitHub releases, and the Claude Code changelog likewise skip the version, while the initial report acknowledged that the origin of its analyzed directory was not established. The article concludes that organizations should focus on whether developers installed or updated Claude Code through Cursor’s marketplace during the affected window.

  • Open VSX’s append-only change feed retained publication and removal records for 42 other versions that were briefly published and removed during the reviewed period, including one removed after about 90 seconds, making the absence of any 2.1.313 event particularly significant.
  • The screenshot presented as evidence of an Open VSX listing showed Linux and Windows download sizes that matched the public Claude Code 2.1.314 builds, while the alleged malicious sample was described as a macOS build.
  • For exposure assessment, the article identifies installation or updates through Cursor’s marketplace during the affected window as the key factor, rather than use of Open VSX or npm.
  • npm metadata normally retains publication timestamps for unpublished releases, but Claude Code version 2.1.313 was absent from both its current versions list and publication-time records.

Cursor confirmed that a harmful version of the Claude Code add-on was available in its software marketplace on October 29 and may have reached up to 5,000 users. The add-on could add an attacker’s access key to a computer, helping them return later and potentially control it remotely. Cursor removed the add-on, changed its security keys, shut down the attacker’s server, and is contacting affected users. The incident also shows why identifying the exact marketplace where a harmful download appeared matters, since investigators found no evidence that the same version was publicly released through Open VSX or npm.

OPEN SOURCE ↗

This is a confirmed supply-chain incident involving a malicious Claude Code extension distributed through Cursor’s marketplace, with potential exposure of up to 5,000 users and remote-access persistence behavior. It is particularly relevant to organizations whose developers installed or updated Claude Code through Cursor during the affected period.
