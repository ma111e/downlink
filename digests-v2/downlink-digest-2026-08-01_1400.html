Rails patches critical Active Storage flaw with RCE potential

Rails patched a critical Active Storage vulnerability (CVE-2026-66066) that can let unauthenticated attackers read arbitrary server files via crafted image uploads when libvips is used, potentially exposing secrets that enable remote code execution. Admins should urgently update Rails and libvips, rotate exposed credentials, and investigate for compromise.
KEY POINTS
  • 01Rails maintainers patched CVE-2026-66066, a critical Active Storage vulnerability that can let an unauthenticated attacker read arbitrary files from a Rails application and potentially escalate to remote code execution.
  • 02The flaw is exploitable when libvips is used and a vulnerable application allows image uploads from untrusted users, enabling attackers to upload a specially crafted image.
  • 03CVE-2026-66066 affects Active Storage before 7.2.3.2, 8.0.x before 8.0.5.1, and 8.1.x before 8.1.3.1, while Rails 6.x is affected only if Active Storage has been configured outside its defaults.
  • 04Rails recommends upgrading to libvips 8.13 or later and rotating the Rails secret_key_base, database credentials, Active Storage service credentials, and any other secrets accessible to the application process.
  • 05The Rails team initially withheld technical details but later published full details and forensic investigation tooling after public proof-of-concept exploits became available quickly.

Rails maintainers patched CVE-2026-66066, a critical vulnerability in the Active Storage framework. The flaw can allow an unauthenticated attacker to read arbitrary files from a Rails application and potentially escalate to remote code execution. Active Storage is the built-in Rails component used for handling file uploads and attachments.

According to the Rails security bulletin, the issue is exploitable when libvips is used and the server allows image uploads from untrusted users. An attacker could upload a specially crafted image and access application files, including the process environment. Those files may contain secret_key_base, database credentials, cloud storage credentials, and other secrets accessible to the application process.

CVE-2026-66066 affects Active Storage before 7.2.3.2, 8.0.x before 8.0.5.1, and 8.1.x before 8.1.3.1, while Rails 6.x is affected only if Active Storage has been configured outside its defaults. Rails recommends upgrading to libvips 8.13 or later and rotating exposed secrets, with a temporary block option available only for systems using libvips 8.13 or later. The Rails team published full technical details and forensic tooling after public proof-of-concept exploits appeared quickly, and Akamai warned that compromise of secret_key_base can translate into full remote code execution on the underlying server.

  • The risk is higher in common deployment paths because libvips is the default processor in official Rails Docker images and in Debian and Ubuntu setups, while ImageMagick users are not affected by this vector.
  • Credential rotation is a required recovery step because successful exploitation may expose the Rails secret_key_base, database credentials, cloud storage credentials, and other secrets available to the application process.
  • For systems already using libvips 8.13 or later, administrators can temporarily block the vulnerable functionality with VIPS_BLOCK_UNTRUSTED or Vips.block_untrusted(true), but there is no workaround for apps using older libvips versions.
  • The Rails team accelerated disclosure of technical details and forensic tooling because public proof-of-concept exploits appeared quickly, changing the risk balance from withholding details to helping defenders investigate.
  • Akamai warned that compromise of secret_key_base can let attackers forge session cookies, sign global IDs, and manipulate serialized data, which can translate into full remote code execution on the server.

Rails fixed a serious problem in its Active Storage file upload feature that could let someone who is not logged in upload a specially made image and read files from the server. This mainly affects Rails apps that accept image uploads from untrusted users and use libvips, including setups based on official Rails Docker images and Debian or Ubuntu. The danger is that those files may contain secret keys and passwords, which could let an attacker take over the application or reach databases, cloud storage, and other services.

OPEN SOURCE ↗

This is a critical patch for widely deployed Rails software with unauthenticated arbitrary file read and potential remote code execution, and public proof-of-concept exploits appeared quickly. It is especially urgent because common Rails Docker, Debian, and Ubuntu setups may use the affected libvips path, and exposed secrets may require credential rotation and forensic investigation.

Coldcard Hardware Wallet Flaw Linked to $70 Million Bitcoin Theft in 41 Minutes

A Coldcard hardware wallet firmware flaw caused some devices to generate weak, predictable Bitcoin seeds, and researchers linked it to a 41-minute theft of about $70 million in BTC. Updating firmware is not enough for already-created seeds; affected users must create a new seed on patched firmware and move funds.
KEY POINTS
  • 01An attacker drained 1,196 Bitcoin addresses in 41 minutes on July 30, taking 1,082.65 BTC worth about $70.2 million at the time.
  • 02Galaxy Research mapped the sweep and tied it to a firmware flaw in Coldcard, the Bitcoin-only hardware wallet made by Canadian firm Coinkite.
  • 03Block traced the flaw to a March 2021 firmware integration error that routed seed generation to a deterministic software pseudorandom number generator instead of the STM32 hardware random number generator.
  • 04Coinkite shipped emergency firmware for affected Coldcard models and release tracks on July 31, but installing it does not repair an existing seed.
  • 05Coinkite advised owners with exposed seeds to generate a new seed on patched firmware and move their coins, because restoring an old seed to updated firmware or another wallet carries the weakness forward.

An attacker drained 1,196 Bitcoin addresses in 41 minutes on July 30, taking 1,082.65 BTC worth about $70.2 million at the time. Galaxy Research mapped the sweep and tied it to a firmware flaw in Coldcard, the Bitcoin-only hardware wallet made by Canadian firm Coinkite. No one has named the attacker, and Galaxy warned that the sweep pattern identifies the operator, not necessarily the theft, because such a movement can look like an owner moving coins.

The flaw came from a March 2021 firmware integration error that routed seed generation to a deterministic software pseudorandom number generator instead of the STM32 hardware random number generator. Block traced the issue to Coldcard’s production configuration and said an attacker who can determine or sufficiently constrain device-specific and timing information can reproduce candidate output streams offline, then compare derived addresses with public blockchain data. Coinkite estimated effective entropy at roughly 40 bits on the Mk3 and about 72 bits on the Mk4, Mk5, and Q, while Block did not provide one practical figure or a brute-force benchmark.

Coinkite shipped emergency firmware for every affected model and release track on July 31, but installing it does not repair an existing seed. The company told owners with exposed seeds to generate a new one on patched firmware and move their coins, because restoring an old seed to updated firmware or another wallet carries the weakness forward. Exposure depends on the firmware running when the seed was created, and affected ranges include Mk3 versions 4.0.1 through 4.1.9 according to Coinkite, Mk2 and Mk3 versions 4.0.0 through 4.1.9 according to Block, Mk4 and Mk5 before 5.6.0, Q before 1.5.0Q, and listed edge builds before their fixed versions.

  • Exposure depends on the firmware version running when the seed was created, not the firmware version installed on the device now.
  • Updating Coldcard firmware does not make an already-created weak seed safe, and restoring that old seed to another wallet carries the weakness forward.
  • Coinkite says seeds created with at least 50 fair, independent, private dice rolls are not at risk from this bug alone, but users should migrate if the number or privacy of rolls is uncertain.
  • A strong, unique BIP-39 passphrase creates a separate wallet that the seed words alone cannot reach, but Coinkite still recommends replacing the seed.
  • Multisig only helps when the required signing group is not made entirely from affected devices.

An attacker moved about $70 million in Bitcoin from 1,196 addresses in 41 minutes, and researchers linked the incident to a flaw in Coldcard hardware wallets made by Coinkite. The flaw meant some wallets created secret recovery words in a way that could be guessed under the right conditions, especially depending on the device model and the software version used when the wallet was first set up. People who created Coldcard wallets on affected versions may need to make a new wallet on fixed software and move their coins, because simply updating does not fix old recovery words. This matters because a mistake in how a wallet creates its secrets can put large amounts of cryptocurrency at risk even years later.

OPEN SOURCE ↗

This is a specific, high-impact incident involving a reported $70 million Bitcoin theft tied to a concrete Coldcard firmware flaw, with emergency firmware and migration guidance for affected users. It is especially important for professionals working with cryptocurrency custody, hardware wallets, or secure random-number generation, though its direct operational relevance is narrower than widely deployed enterprise software.
