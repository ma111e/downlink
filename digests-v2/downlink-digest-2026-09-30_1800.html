Over 543,000 valid credentials exposed in public GitHub repositories

Truffle Security found 543,699 still-valid credentials publicly exposed across GitHub repositories, with a median exposure period of 784 days. GitHub Push Protection has reduced leaks for credential types it covers, but many exposed secrets remain unblocked or unrevoked, underscoring the need for rapid credential rotation.
KEY POINTS
  • 01Truffle Security identified 543,699 unique credentials that were still valid and publicly exposed in GitHub repositories, appearing across more than 1.1 million files and repositories including forks.
  • 02The analysis drew on a dataset covering 224 million repositories and more than 58 billion files, with a crawl that ended on August 7, 2025.
  • 03The median time a unique credential remained publicly accessible was 784 days, and about 10% of working credentials were more than 6.3 years old.
  • 04GitHub Push Protection reduced exposure of credential categories it covers by 53% after it was enabled by default, but 51.8% of live credentials belonged to categories it does not block by default.
  • 05Of 126,963 exposed Google Cloud service account credentials, 69,041 remained valid, while only one of 101,886 committed npm tokens still worked.

Truffle Security found 543,699 unique credentials that were still valid and publicly exposed in public GitHub repositories. The credentials appeared repeatedly across more than 1.1 million files and repositories, including forks, in a dataset spanning 224 million repositories and more than 58 billion files. The median time a unique credential remained publicly accessible was 784 days, while about 10% of working credentials were more than 6.3 years old.

GitHub’s Push Protection scans incoming code for credential patterns and blocks uploads when it detects them, but it does not revoke secrets exposed previously. Truffle reported that 199,843 valid credentials were exposed after Push Protection was activated for all users in February 2024, and 51.8% of live credentials were types not blocked by default, such as database connection strings and Google API keys. Although the rate of exposed credentials in protected categories fell 53% after the feature became enabled by default, revocation differed sharply by service: only one of 101,886 exposed npm tokens still worked, compared with 69,041 valid Google Cloud service account credentials out of 126,963 found.

  • GitHub Push Protection appears effective for the credential types it covers, reducing their exposure rate by 53%, but more than half of the live credentials found were in categories the default protection does not block.
  • Credential revocation practices vary sharply by service: only one of 101,886 exposed npm tokens remained valid, compared with 69,041 valid credentials among 126,963 exposed Google Cloud service account credentials.
  • More than a third of the valid credentials identified in July had been exposed after GitHub enabled Push Protection by default, showing that public credential exposure continued despite the safeguard.
  • Working credential exposure became denser over time, rising from 3.72 per million files in 2015 to 11.62 per million files in 2025.

Researchers found more than 543,000 passwords, access keys, and other digital credentials left publicly visible in GitHub code repositories that still worked, often for years. The exposed items can give access to services such as cloud accounts, databases, and software packages, affecting the organizations and developers that posted them. GitHub blocks many new leaks before they are uploaded, but it cannot cancel credentials already exposed and does not cover every type. If these credentials are found and misused, outsiders could gain control of affected accounts or services, so organizations need to replace exposed credentials and remove them from their code history.

Russian state hackers use new RedFlick technique to push malware

Russian state-linked group Star Blizzard is using a new RedFlick phishing chain that requires victims only to open a disguised shortcut, then automatically installs the CosmicPulse backdoor through scheduled tasks and remotely hosted payloads. Microsoft says the campaigns have targeted Ukraine-related organizations, NGOs, governments, and financial institutions, primarily in the US and UK.
KEY POINTS
  • 01Microsoft reports that the Russian state actor Star Blizzard has begun using a malware-delivery method dubbed RedFlick to deploy its CosmicPulse backdoor.
  • 02RedFlick begins with phishing emails and a password-protected archive containing a virtual disk and a shortcut disguised as a PDF; opening the shortcut launches hidden commands while displaying a decoy document.
  • 03The infection chain installs scheduled tasks that collect computer and user information, enable access to remote web resources, and run remotely hosted follow-on code.
  • 04A downloader called NOROBOT and BAITSWITCH retrieves Python components and a bootstrapper that decrypts and launches CosmicPulse, which can execute attacker-supplied Python code, download and run files, or retrieve documents.
  • 05Microsoft observed at least 13 large-scale phishing campaigns since the start of the year, affecting more than 100 organizations, including Ukrainian targets and Ukraine-supporting NGOs, think tanks, governments, and financial institutions.

Microsoft reports that the Russian state actor Star Blizzard has adopted a new malware-delivery approach called RedFlick to deploy its CosmicPulse backdoor. The method begins with phishing emails, often an invitation followed by a password-protected ZIP or RAR archive. The archive contains a VHDX virtual disk and a shortcut disguised as a PDF; opening it runs hidden commands while showing the victim a decoy PDF.

The hidden commands download an MSI installer that creates three scheduled tasks for gathering system information, preparing WebDAV access to remote resources, and running a remotely hosted next-stage payload. That payload, known as NOROBOT and BAITSWITCH, downloads Python components and a bootstrapper that decrypts and launches CosmicPulse. Microsoft says the new chain requires only that a victim open the malicious shortcut, reducing interaction compared with Star Blizzard’s earlier ClickFix activity, and reports at least 13 large-scale campaigns affecting more than 100 organizations, including Ukrainian targets and Ukraine-supporting NGOs, think tanks, governments, and financial institutions.

  • RedFlick reduces the required victim interaction to opening one malicious shortcut, unlike Star Blizzard’s ClickFix campaigns, which required several manual actions.
  • The use of separate scheduled tasks for information collection, remote-resource preparation, and payload execution is designed to help the operation evade detection at different points in the infection chain.
  • Star Blizzard continues to rely on impersonated trusted contacts or organizations and free email providers even as it changes how it delivers malicious software.
  • Microsoft recommends phishing-resistant sign-in methods, Conditional Access policies, email protections, independent verification of suspicious messages, and EDR block mode to reduce the risk from these campaigns.

A Russian state-linked hacking group called Star Blizzard is sending convincing email invitations that lead people to open a file disguised as a PDF, which silently installs spying software on their computers. Microsoft says the campaign has targeted Ukrainian people and institutions, as well as groups and organizations in the United States and United Kingdom that support Ukraine. This matters because opening a single deceptive file can give attackers a way to steal documents or run further programs, putting sensitive government, financial, and nonprofit information at risk.

DIVD says Zammad zero-days enabled AI-driven network breach

DIVD says attackers used two zero-day flaws in the Zammad helpdesk platform to hijack sessions, execute code, and gain root access in an AI-agent-driven breach. Zammad users are urged to upgrade to version 7 or take vulnerable instances offline.
KEY POINTS
  • 01DIVD says its network breach involved a chain of two zero-day vulnerabilities in the open-source Zammad ticketing system, identified as CVE-2026-102489 and CVE-2026-102490.
  • 02According to DIVD, the flaws could be combined to hijack sessions, run code remotely, and raise access from a Zammad user account to full server control.
  • 03DIVD said an autonomous AI agent carried out the actions in seconds and left explanations that helped investigators reconstruct the incident.
  • 04Network separation and DIVD's response actions prevented the attacker from moving deeper into the network, although the investigation remains ongoing.
  • 05DIVD recommends that Zammad users upgrade to version 7 or take affected instances offline as soon as possible.

The Dutch Institute for Vulnerability Disclosure (DIVD) says its network breach was enabled by two zero-day vulnerabilities in the open-source Zammad ticketing system. The flaws, identified as CVE-2026-102489 and CVE-2026-102490, reportedly allowed attackers to hijack sessions, run code remotely, and escalate privileges from a Zammad user to root. DIVD said the attack was driven by an autonomous AI agent that performed these actions within seconds.

DIVD said it could reconstruct extensive details of the incident because the AI agent left clear explanations of its decisions. The attacker accessed other services and read and exfiltrated data, but network segmentation and incident-response actions prevented deeper movement through the network; the investigation is ongoing. DIVD discovered the flaws with Merlon Security, notified Zammad, and recommends that users upgrade to version 7 or take affected instances offline as soon as possible.

  • DIVD was able to reconstruct extensive details of the intrusion because the AI agent reportedly left clear explanations for the decisions it made during the attack.
  • The incident shows that combining the two Zammad flaws enabled a rapid progression from taking over a session to running commands and obtaining full server control.
  • Network segmentation and incident-response measures limited the attacker’s movement into the wider DIVD network despite the reported root-level access.
  • The article presents version 7 as the safe Zammad release and advises users unable to upgrade promptly to take their instances offline.

The Dutch Institute for Vulnerability Disclosure says someone broke into its network by taking advantage of two previously unknown flaws in Zammad, a customer-support and internal helpdesk system. The intruder used an AI program that acted on its own to take over user logins, run commands, gain complete control of a server, and copy data within seconds. Organizations using affected Zammad installations may be at risk, so they are advised to update to version 7 or temporarily take the system offline. The case shows how automated AI tools can let attackers move much faster than people can respond.

Automakers routinely share personally identifiable connected-car data with third parties, report says

Some apps transmitted personally identifiable information such as names, emails, precise locations, and VIN-linked data, potentially enabling tracking of drivers’ movements.
KEY POINTS

  • 02Twenty-eight of 30 connected-car apps examined shared data with at least one third-party advertising or analytics firm.
  • 03Seven of the 30 apps sent personally identifiable information, including names, email addresses, or precise locations, to at least one outside company.
  • 04Consumer Reports said GM’s myCadillac, myChevrolet, myBuick, and myGMC apps, along with Honda, Nissan, and Lincoln apps, shared VINs paired with location data or email addresses.
  • 05After Consumer Reports notified Honda of the findings, Honda directed a digital data analytics and tracking vendor to delete ingested location data and stop sharing it with third parties.

Northeastern University researchers and Consumer Reports reported that 19 of 21 major automakers studied collect and broadly share customer data from connected vehicles. The research found that 28 of 30 connected-car apps sent data to at least one third-party advertising or analytics firm. Seven apps sent personally identifiable information, such as names, email addresses, or precise location data, to outside companies.

Consumer Reports said several GM apps, as well as Honda, Nissan, and Lincoln apps, shared vehicle identification numbers paired with location data or email addresses, which can enable data brokers to identify and sell information about driving patterns. Recipients included advertisers, analytics firms, and companies such as Alphabet, Amazon, Microsoft, Meta, Reddit, and Pinterest; several of these firms both provide software and operate advertising auction platforms. Automakers said sharing is opt-in and that some recipients are barred from independently using or selling the data, but Consumer Reports said drivers may not understand their consent choices and may be warned that opting out could affect vehicle operation.

  • Pairing a vehicle identification number with location data or an email address can allow data brokers to identify drivers’ travel patterns and sell that information.
  • Several automakers said external webpages linked from their apps can let third parties place tracking cookies and pixels that collect consumer data, often without the driver knowing.
  • Companies receiving driver data may simultaneously provide automakers’ software and operate advertising auction platforms used to target customers.
  • Although automakers describe sharing as opt-in, Consumer Reports said drivers may not understand what they consent to and some are warned that opting out could make their vehicles inoperable.
  • After Consumer Reports raised its findings, Honda told a tracking and analytics vendor to delete location data it had received and stop sharing it with third parties.

Research from Northeastern University and Consumer Reports found that most major carmakers collect and share data from connected cars and their phone apps with outside companies. This can include a driver’s name, email address, exact location, and vehicle identification number, which can be used to connect a person to their driving habits. Drivers may agree to this sharing without fully understanding it, and some companies warn that opting out could make parts of a vehicle stop working. The findings show how buying and using a modern car can place personal information into a large network of advertisers, technology companies, and data sellers.

After reports on suicide deaths, Pentagon puts Cyber Command on notice

Following reports of suicide deaths among personnel, the Pentagon ordered U.S. Cyber Command to rapidly implement mental-health, workload recovery, and force-resiliency measures for its continuously deployed cyber operators.
KEY POINTS
  • 01Pentagon cyber policy official Katherine Sutton directed U.S. Cyber Command to implement mandatory wellness and resiliency measures after reports of suicide deaths within the command.
  • 02Cyber Command was ordered within 30 days to provide four years of organizational climate survey data and exit-interview summaries and to finalize an agreement with the National Security Agency to share mental and behavioral health professionals.
  • 03The command must establish a Cyber Occupational Resiliency and Engagement Framework and introduce workload phasing measures intended to make recovery time more predictable and reduce cumulative strain on Cyber Mission Force personnel.
  • 04Within 60 days, Cyber Command must submit a proposal to change consecutive-tour policies by adding career, instructor, and education assignments that interrupt continuous operational stress.
  • 05Senior military cyber officials said persistent high-tempo operations have made it necessary to develop rest plans and allow personnel to step away from continuous work against adversaries.

Pentagon cyber policy official Katherine Sutton directed U.S. Cyber Command to take mandatory, rapid steps to improve the well-being of its personnel after reports of suicide deaths at the command. Her August 31 memo described the continuous pace of active cyber operations as imposing cumulative cognitive and psychological strain. It said cyber teams, unlike traditional forces, lack standardized recovery periods between deployments, which can affect retention and long-term performance.

Within 30 days, Cyber Command must provide four years of organizational climate and exit-interview data and finalize an agreement with the National Security Agency to share mental- and behavioral-health professionals in Cyber Mission Force work areas. The command also must create an enduring wellness framework, improve predictable recovery periods, review consecutive-tour policies, and help prioritize operations in a way that accounts for long-term force health. Military cyber leaders said their personnel have operated at a sustained surge pace, prompting efforts such as formal rest plans, access for chaplains in operational spaces, and opportunities for operators to step away from their work.

  • The Pentagon memo says cyber teams lack standardized recovery periods between deployments, unlike traditional military forces, despite the continuous cognitive and psychological demands of active cyber operations.
  • Several resiliency benchmarks reportedly existed in the Cyber Command 2.0 implementation plan but were accelerated, in some cases by years, after the suicide deaths.
  • Marine Forces Cyberspace Command found that giving chaplains and religious program specialists access to operational work areas made personnel more willing to ask for a pause.
  • Army Cyber Command found that some operators spent off-duty time on intensive gaming similar to their work, leading the organization to institute formal rest plans to preserve cognitive resilience.

After reports of several suicide deaths, the Pentagon told U.S. Cyber Command to quickly improve mental-health support and rest time for the people who conduct military computer operations. The changes include bringing counselors into work areas, studying workload and workplace data, and creating predictable breaks from demanding assignments. This matters because these personnel work at a nonstop pace against foreign adversaries, and sustained stress can harm their health, retention, and ability to perform critical national-security work.

  • 01Google’s Threat Intelligence Group reported that monthly vulnerability disclosures rose from 5,045 in January to 10,740 in August, exceeding 10,000 in both July and August.

Google’s Threat Intelligence Group said monthly vulnerability disclosures rose from 5,045 in January to 10,740 in August, exceeding 10,000 in both July and August. The group also reported 141 exploited vulnerabilities during the first eight months of 2026, surpassing the 127 exploited vulnerabilities recorded for all of 2025. Google said AI is changing both the pace of finding and exploiting flaws and the risk profiles of the vulnerabilities involved.

GTIG attributed the increase in exploitation to the rapid, targeted weaponization of high-risk publicly disclosed and patched flaws, rather than a flood of previously unknown flaws. It said attackers may use AI tools to compare product versions, patches, public vulnerability announcements, and proof-of-concept code to prepare exploits more quickly.   • An autonomous third-party research agent, Hacktron AI, found CVE-2026-1731, illustrating that AI-driven research can uncover high-severity flaws in critical enterprise attack surfaces.
  • Although overall disclosure volume increased sharply, Google attributed the rise in real-world exploitation to the focused weaponization of high-risk flaws rather than to a broad increase in unknown flaws being exploited.
  • A substantial share of exploited flaws affected edge and security appliances, while many disclosures came from a small group of vendors including Totolink and Oracle.

Google says the number of publicly reported software flaws doubled from about 5,000 in January to more than 10,000 per month by July and August. Criminals are increasingly using AI tools to quickly study public fixes and turn serious flaws into ways to break into organizations, often targeting internet-facing security devices and business services. This matters because attackers can move within days of a flaw becoming public, potentially stealing data, gaining deeper access, or installing harmful software on affected networks.

How Device Code Phishing Bypasses MFA in Microsoft 365

A live Microsoft 365 phishing campaign abuses the legitimate device code authentication flow to obtain valid, MFA-approved tokens without stealing passwords, then may deploy ConnectWise ScreenConnect for remote access. Organizations should restrict device code flow in Entra Conditional Access, investigate device-code sign-ins, and revoke active sessions/tokens after suspected compromise.
KEY POINTS
  • 01The phishing campaign abuses Microsoft’s legitimate device code sign-in process, allowing victims to complete normal Microsoft authentication and multi-factor authentication while authorizing a session on an attacker-controlled device.
  • 02A compromised Microsoft 365 identity can provide access to Exchange Online mail and calendars, OneDrive and SharePoint files, Teams conversations, and Entra ID directory information, depending on the user’s permissions.
  • 03The campaign’s second-stage page impersonates Adobe Acrobat and prompts victims to download an update that installs a vendor-signed ConnectWise ScreenConnect remote-support client configured for attacker access.
  • 04Traditional controls may not detect this technique because the sign-in occurs on a real Microsoft page, contains no password-capture form, satisfies MFA legitimately, and generates no endpoint activity during the identity compromise.
  • 05The article recommends restricting device code flow through Entra Conditional Access, hunting for device-code sign-ins, explicitly revoking sessions and tokens after suspected compromise, and reviewing delegated permissions and data access.

Cyera Research examined a phishing campaign that abuses Microsoft’s legitimate device code authentication flow. Victims receive a business-themed message, visit a page impersonating a collaboration service, and are instructed to enter a provided code through a real Microsoft sign-in page. After completing normal Microsoft authentication and multi-factor authentication, the victim effectively authorizes a session on an attacker-controlled device without surrendering a password.

Depending on the victim’s permissions, the resulting access can reach Microsoft 365 email, calendars, OneDrive and SharePoint files, Teams content, and Entra ID directory information. The campaign also redirects victims to a fake Adobe Acrobat page that offers an update; the downloaded payload is a vendor-signed ConnectWise ScreenConnect client configured to provide remote access to the threat actor. The article recommends restricting device code flow with Entra Conditional Access, investigating device-code sign-ins, explicitly revoking sessions and tokens after suspected compromise, reviewing delegated permissions, and correlating identity activity with the sensitivity of accessible data.

  • A password reset alone may not remove attacker access because an already issued refresh token can remain valid unless sessions are explicitly revoked.
  • The article identifies device-code sign-ins in Microsoft Entra ID as the most reliable detection point, since the victim’s normal sign-in may appear legitimate and the initial identity compromise produces no endpoint telemetry.
  • Cloudflare Turnstile can hinder automated URL analysis in this campaign even though the challenge itself uses Cloudflare’s genuine, unmodified client library.
  • The impact of a compromised identity depends on the sensitive data it can actually access, so correlating access activity with data sensitivity is more useful for scoping an incident than treating all permissions equally.
  • The remote-access payload is a legitimate vendor-signed ConnectWise ScreenConnect client, meaning detection based only on software signatures is insufficient and organizations should instead watch for unsanctioned relay connections.

The article describes a phishing campaign in which people are sent a fake business document and asked to enter a code on a real Microsoft sign-in page. Even though the person uses their normal password and two-step verification correctly, this can give criminals access to that person’s Microsoft 365 email, files, chats, and other company information. The campaign also tries to persuade victims to install a seemingly legitimate update that gives the criminals remote control of their computer. This matters because normal safety checks may not flag it, and one employee’s approved sign-in can expose sensitive organizational data and enable further attacks.
