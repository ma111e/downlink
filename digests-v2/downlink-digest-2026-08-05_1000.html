Critical Gitea Flaw Let Unauthenticated Attackers Read Server Files via Org-Mode Markup

  • 03Gitea fixed the flaw in version 1.27.1 by overriding the go-org ReadFile behavior so Org-mode include paths are rendered as plain content instead of being read from the server filesystem.
  • 04Gitea said the file-read flaw can become command execution if an attacker reads app.ini, extracts INTERNAL_TOKEN, injects a Git hook through the internal logger, and triggers that hook during an anonymous clone.
  • 05Administrators of exposed instances should review anonymous markup requests, check for unexpected executable hook files, and rotate secrets such as the internal token, OAuth material, JWT signing material, and database credentials if exposure is suspected.

Gitea fixed a critical file-read flaw, tracked as CVE-2026-59774, in version 1.27.1. The issue affects Gitea versions 1.22.1 through 1.27.0 and can let an unauthenticated attacker read any file the service account can access. The attack requires a public repository and crafted Org-mode markup, with no login or repository write access needed.

The flaw runs through the POST /{owner}/{repo}/markup endpoint and Gitea’s Org-mode renderer. Gitea 1.27.0 initialized go-org without replacing its default ReadFile callback, which used ioutil.ReadFile, and Org-mode’s #+INCLUDE directive could pass absolute paths to that callback. Gitea fixed the issue by overriding ReadFile so include paths are rendered as plain content rather than being resolved from the server filesystem.

Gitea said the file-read bug is not direct one-request remote code execution, but it can become command execution if an attacker reads app.ini, extracts INTERNAL_TOKEN, injects a Git hook through the internal logger, and triggers that hook during an anonymous clone. Administrators are advised to upgrade immediately, review anonymous markup requests, check hook directories for unexpected executable files, and rotate credentials if exposure is suspected. Gitea reported no exploitation in the wild, and as of August 5, 2026, CVE-2026-59774 was not listed in CISA’s Known Exploited Vulnerabilities catalog.
