Hackers start exploiting critical WordPress flaw for code execution

Attackers are actively exploiting critical WordPress path traversal flaw CVE-2026-87902 to write PHP files that can execute shell commands. Administrators should update WordPress to 7.1.2 or a patched supported branch immediately and check logs for double-encoded pagename probes and suspicious files in /tmp or /var/tmp.
KEY POINTS
  • 01Threat actors are actively exploiting CVE-2026-87902, a critical unauthenticated WordPress path traversal flaw that can enable remote code execution under certain conditions.
  • 02Patchstack observed reconnaissance requests less than five hours after the WordPress patch release, followed by a tenfold increase in traffic and payloads intended to write attacker-controlled files to disk.
  • 03The observed payloads use PHP's pearcmd.php to create files in /tmp or /var/tmp, including files that execute shell commands when accessed.
  • 04WordPress fixed CVE-2026-87902 in version 7.1.2 and backported fixes to supported branches from 4.7 onward; versions earlier than 4.6 will not receive a fix.
  • 05Administrators are advised to update promptly, review logs for double-encoded traversal sequences in pagename requests with a valid page_id, and block the listed source IP addresses.

Threat actors have begun actively exploiting CVE-2026-87902, a critical WordPress flaw rated 9.2 out of 10 that can allow remote code execution under certain conditions. Patchstack observed the first reconnaissance requests less than five hours after WordPress released a patch, and activity later increased tenfold. The attacks progressed from attempts to include ordinary WordPress core files to payloads intended to write attacker-controlled files to disk.

The flaw is an unauthenticated path traversal issue in WordPress page-template resolution that can include a chosen readable local PHP file outside active theme directories. Remote code execution requires a qualifying theme directory and a readable PHP file, with pearcmd.php cited as an example when PHP’s register_argc_argv setting is active. Observed payloads created files in /tmp or /var/tmp, including PHP files designed to execute shell commands when accessed. WordPress fixed the issue in version 7.1.2 and backported fixes to branches from 4.7 onward, while releases before 4.6 will not receive a fix.

  • Attackers began probing protected WordPress sites less than five hours after the patch was released, showing that scanning began almost immediately after public disclosure.
  • Remote command execution is not automatic on every vulnerable site: it depends on a qualifying theme directory and a readable local PHP file, with pearcmd.php cited as an example.
  • The observed activity progressed from testing with ordinary WordPress core files to attempting to create attacker-controlled PHP files, including files designed to run shell commands when opened.
  • The attacks leave concrete investigation clues, including double-encoded traversal strings in the pagename parameter and suspicious PHP files in /tmp or /var/tmp.
  • Although fixes were backported to WordPress 4.7 and later branches, installations older than version 4.6 will not receive a fix for this issue.

Hackers are actively targeting WordPress websites through a serious flaw that can let an outsider place files on a server and run commands on it. Sites using affected WordPress versions are at risk, especially when their setup meets certain conditions involving website themes and PHP settings. WordPress released fixes for versions 4.7 through 7.1.2, so site owners need to update quickly and check whether suspicious files or requests appeared on their sites.

New RemControl Android banking malware targets users in Europe and Canada

RemControl is a new Android banking malware service spread through fake TVTap Google Play pages and malvertising, targeting users in Europe, Canada, and the Middle East. It abuses Accessibility permissions and a VPN-based Play Protect bypass to overlay banking apps, steal credentials, and remotely control infected devices.
KEY POINTS
  • 01RemControl is a new Android malware-as-a-service platform distributed through malicious advertising campaigns and fake Google Play pages impersonating the TVTap IPTV app.
  • 02Group-IB reported that RemControl targets users in Italy, France, Spain, Poland, Portugal, Canada, and countries in the Middle East.
  • 03After victims grant Accessibility Service permissions, RemControl can show fake screens over banking apps, steal banking credentials and card details, record user input, capture screenshots, and remotely control device interactions.
  • 04The malware starts a VPN service that blocks Google Play services traffic, preventing Play Protect from conducting real-time checks against known malware.
  • 05RemControl obtains encrypted command-and-control information from Telegram channels, allowing its operators to rotate their infrastructure dynamically.

Group-IB has identified RemControl, a new Android malware-as-a-service platform distributed through malicious advertising and fake Google Play pages impersonating the TVTap IPTV app. The malware has been active in infrastructure since at least May, with first samples seen in July containing more than 30 fake banking screens designed to steal credentials. It targets users in Italy, France, Spain, Poland, Portugal, Canada, and countries in the Middle East. Group-IB tracks its operator as UNKK and suspects a connection to the Medusa banking trojan.

After installation, RemControl requests Accessibility Service permissions and starts a VPN service that blocks Google Play services traffic, preventing Play Protect from performing real-time checks against known malware. If granted permissions, it can display fake screens over legitimate banking apps, steal PINs, codes, card details, and credentials, record user input, stream screenshots and interface information, and remotely control device interactions. It can also capture pattern-lock coordinates and exit automatically when victims open settings related to app management, accessibility, or factory resets. RemControl obtains encrypted command-and-control information through Telegram channels, enabling its operators to rotate infrastructure, and users are advised to avoid untrusted APK downloads and decline unnecessary Accessibility Service requests.

  • A phishing screen included what appeared to be an AI assistant response, which Group-IB said strongly indicates that AI models helped build the malware.
  • The malicious download sites contained Meta Pixel tracking IDs, which Group-IB viewed as evidence that the operators may have used Meta’s advertising ecosystem to direct people to them.
  • RemControl can detect when a victim opens app-management, accessibility, or factory-reset settings and automatically exit to make removal more difficult.
  • Its initial command-and-control proxy exposed FastAPI documentation that revealed endpoints used to retrieve fake banking screens and submit stolen credentials.

A new harmful Android app called RemControl is being spread through fake download pages that pretend to offer the TVTap TV-streaming app. It targets phone users in several European countries, Canada, and the Middle East, then can place fake bank screens over real banking apps to steal passwords, PINs, card details, and security codes. If a person approves the app’s special phone-control permission, criminals can also watch what appears on the screen and control parts of the phone remotely, putting bank accounts and other personal information at risk.

Researchers at Aikido identified Go-based malware distributed through two Terraform providers in HashiCorp Registry and two Go modules. The packages, including gocommunity-io/dockerd and kreuzwenker/docker, share infrastructure with the Graphalgo campaign, which has been attributed to North Korean threat actors. The discovery marks the first reported use of HashiCorp’s centralized Terraform Registry to distribute malicious payloads. The malware collects system and hardware information, hostname, operating-system details, and Node.js availability before sending the data to an attacker-controlled Slack channel.   • Terraform providers are an especially consequential distribution route because Terraform can offer a direct path to credentials used for critical production environments.
  • The blockchain command system limits operators because every infected client receives all messages but only acts on messages it can decrypt, reducing the risk of commands or data being exposed between infected hosts.
  • The GHAPPIER loader remained available through npm for only 35 minutes and 38 seconds, yet similar code was found in 65 public repositories after attackers used developers’ stored credentials to write to repositories they could access.

Researchers found harmful software hidden in downloadable tools for Terraform and the Go programming language, extending a campaign linked to North Korean threat actors. Developers may be tricked through fake job opportunities into using or publishing software that appears legitimate but secretly sends information from their computer to the attackers and can receive further instructions. Emerging Threat: (CVE-2026-94545) Next.js Remote Code Execution via ImageResponse SVG Injection

CVE-2026-94545 is a critical RCE flaw in Node.js-based Next.js ImageResponse routes when attacker-controlled input is rendered into SVG content. Organizations should upgrade affected Next.js 16.2–16.3 deployments to 16.3.6 and identify dynamic Open Graph image routes that process request data.
KEY POINTS
  • 01CVE-2026-94545 is a critical remote code execution vulnerability in Next.js's next/og ImageResponse API, caused by insufficient escaping of values rendered into SVG output.
  • 02The issue affects Next.js versions 16.2.0 through 16.3.5 when the Node.js ImageResponse implementation uses attacker-influenced data in generated SVG content, attributes, or styles; the Edge implementation is not affected.
  • 03Next.js 16.3.6 contains the fix, while Next.js 15.5.26 provides hardening for the 15 line and no backport is available for 16.2.x.
  • 04Affected applications commonly include public-facing sites with dynamic Open Graph image routes that generate per-page social preview cards from request-derived values such as titles, product names, or campaign slugs.
  • 05Defenders should inventory internet-facing Next.js sites, determine whether dynamic ImageResponse routes accept request data, upgrade affected deployments, and monitor image routes for malformed or unusually long parameters.

CVE-2026-94545 is a critical remote code execution vulnerability in Next.js’s next/og ImageResponse API. The issue occurs when the Node.js implementation renders attacker-influenced values into SVG output without correctly escaping them, allowing those values to be interpreted as SVG markup. Publicly reachable Open Graph image routes are a common potential exposure point because they often generate social-preview images using request-derived titles, product names, authors, or campaign slugs.

The vulnerability affects Next.js versions 16.2.0 through 16.3.5 when untrusted data reaches SVG content, attributes, or styles; Edge-based ImageResponse implementations are not affected. Next.js 16.3.6 contains the fix, and there is no backport for the 16.2 line, requiring 16.2.x users to upgrade forward. Organizations should inventory internet-facing Next.js sites, identify dynamic image-generation routes and their data flows, avoid relying on input filtering alone, and monitor those routes for malformed or unusually long parameters.

  • External discovery alone cannot reliably determine true exposure because the Next.js version, ImageResponse usage, runtime choice, and data flow into image generation are not all externally visible.
  • Filtering suspicious-looking input is not considered a reliable mitigation because the flaw lies in how values are converted into SVG, rather than only in the contents of those values.
  • Organizations running Next.js 16.2.x must upgrade to 16.3.6 rather than apply a same-minor-version patch, because no backport exists for the 16.2 line.
  • The exposure is spread across many industries instead of concentrated in one sector, reflecting Next.js's broad use for public-facing websites.
  • Ownership can complicate remediation because affected sites may be managed by marketing or digital teams and deployed through managed hosting platforms rather than being handled through a conventional infrastructure patch cycle.

The article warns about a critical flaw in Next.js, a widely used tool for building websites, that could let an outsider run commands on a website’s server through specially crafted social-media preview image requests. It mainly affects sites using certain Next.js versions that create these images on their own servers and include information supplied by visitors, such as page titles or product names. This matters because such image features are common across public websites, including marketing, publishing, documentation, and shopping sites, and their owners may not know which smaller sites are affected. Updating to Next.js 16.3.6 and checking these image-generation features are the recommended steps.

Although exploitation is conditional and no active exploitation is reported, the affected framework is broadly used and a fixed release is available, making prompt triage and upgrading important.
