Modern Adventures in Azure Privilege Escalation

  • 04NetSPI found that the built-in Anyscale Platform Administrator Role contained Microsoft.Authorization/roleAssignments/write and Microsoft.Authorization/roleAssignments/delete without ABAC conditions, allowing arbitrary privilege escalation to Owner before Microsoft removed those permissions.
  • 05The article recommends that Azure administrators review every role for unexpected permissions, follow least privilege, reduce use of highly privileged roles, and assign roles at the narrowest possible scope.

Azure has grown to more than 200 services, 897 built-in Azure RBAC roles, and 22,018 permissions as of June 2026, increasing the cloud attack surface. The article explains Azure RBAC fundamentals, Attribute Based Access Control, and why privilege escalation mapping should focus on individual permissions rather than only role names. It argues that reviewing permissions alongside ABAC conditions gives a more accurate view of effective access and real escalation paths.

The article highlights that ABAC is used heavily in built-in Azure roles, especially around Microsoft.Authorization/roleAssignments/write, to constrain which roles can be assigned. It also describes a bypass of a Microsoft Portal recommended condition, where a principal with constrained Owner or User Access Administrator access could create and assign a custom role because Microsoft.Authorization/roleDefinitions/write was not covered by the condition. The article notes that Microsoft closed this reported behavior as “by design.”

Using a permission-focused methodology and the 2023-07-01-preview Role Definitions List API, NetSPI identified that the built-in “Anyscale Platform Administrator Role” included Microsoft.Authorization/roleAssignments/write and Microsoft.Authorization/roleAssignments/delete without ABAC conditions. The article states this could allow arbitrary privilege escalation to Owner and made the role equivalent to highly privileged Azure roles such as Owner, User Access Administrator, and Role Based Access Control Administrator. Microsoft later removed those role assignment permissions from the Anyscale role after the issue was reported to MSRC.

  • Microsoft’s portal-recommended condition for limiting Owner or User Access Administrator role assignments can be bypassed because it blocks only specific privileged role IDs and does not constrain Microsoft.Authorization/roleDefinitions/write.
  • A control-plane permission such as Microsoft.Storage/storageAccounts/listkeys/action can effectively grant full data access to Storage Account contents through shared access keys, blurring the expected separation between management actions and data access.
  • The undocumented 2023-07-01-preview version of the Azure Role Definitions List API can map specific permissions to built-in and custom roles while handling Actions versus NotActions, making permission-level privilege escalation reviews more practical.
  • Roles that administrators may not expect to expose Storage Account data, including Azure AI Administrator, Log Analytics Contributor, and Virtual Machine Contributor, include Microsoft.Storage/storageAccounts/listkeys/action.
  • Among 28 built-in roles with Microsoft.Authorization/roleAssignments/write, only four lacked ABAC conditions before Microsoft changed the Anyscale Platform Administrator Role, making the absence of conditions a high-signal review target.

The article explains how permissions in Microsoft Azure can sometimes let someone gain much more control than intended, especially when those permissions are hidden inside built-in roles. NetSPI found one built-in Azure role, called Anyscale Platform Administrator Role, that could have let a user give themselves full Owner-level access, and Microsoft later removed the dangerous permissions. This matters because organizations using Azure could accidentally give people or compromised accounts too much power, putting cloud resources and data at risk.

  • 03The exposed Unreal Engine audio recording function could be abused to write files to arbitrary locations on the victim’s filesystem by supplying absolute or relative paths.
  • 04The researchers bypassed Unreal Engine’s added .wav suffix by using a null character in the filename, then used controlled PCM WAV audio data to create a Windows HTML Application payload.
  • 05The game’s maintainers fixed the reported vulnerability in MECCHA CHAMELEON 4.0.0 by preventing the StopRecordingOutput function from creating files.

Researchers found a delayed remote code execution issue in MECCHA CHAMELEON involving attacker-made custom maps. The game lets players create and share maps through Steam Workshop, and lobby hosts can prompt other players to download the selected map. Because MECCHA CHAMELEON maps can contain Unreal Engine Blueprints, a downloaded map can run graph logic inside the game process and call functions exposed to Blueprint.

The researchers focused on exposed functions that interacted with the operating system and identified Finish Recording Output / StopRecordingOutput as a way to create files on the filesystem. By supplying absolute or relative paths, they could write files outside the default recording directory and target locations such as the Windows Startup folder. They also used a null character in the filename to bypass Unreal Engine appending a .wav suffix, allowing arbitrary filenames.

To make the written file useful for code execution, the researchers controlled bytes in an uncompressed 16-bit PCM WAV recording and embedded a Windows HTML Application payload in the audio data. Their proof of concept wrote the file to the Startup folder so it would run after the victim restarted the device. The maintainers patched the issue in MECCHA CHAMELEON 4.0.0 by preventing StopRecordingOutput from creating files, and the researchers said they found no Steam Workshop maps already exploiting the issue.

  • A file did not need to be a valid Windows executable to achieve code execution, because Windows HTML Applications could still run script even when WAV metadata appeared before the HTML content.
  • The researchers avoided interference from normal game audio by recording through a private submix before writing the malicious audio-derived file.
  • The fixed issue removed even intended file creation through StopRecordingOutput, showing the maintainers chose to eliminate that file-writing capability rather than only restrict malicious paths.
  • The researchers reviewed existing Steam Workshop maps and reported that they found none already exploiting the issue.

Researchers found that a malicious custom map for MECCHA CHAMELEON could secretly place a file on a Windows player’s computer, which could then run after the computer restarted.   • The WebRTC variant reduces visibility for defenders because it avoids the normal signaling-server exchange while still opening an encrypted channel that HTTP inspection may not see.
  • Site owners can look for the loader by integrity-checking CMS assets, since Netskope observed it appended to legitimate JavaScript files or placed in fake plugin directories.
