The incident raised temperature and defrost thresholds in cold-storage chambers used for blood products and biological samples. EFS said it was not directly targeted and that its monitoring and alarm systems detected the changes quickly. Staff repaired affected equipment or transferred products to other refrigerated facilities, and EFS reported no health impact, no product losses, and no disruption to collection or distribution.

The event follows attacks on supermarket refrigeration systems in France and other European countries that remotely changed temperature settings or activated defrost functions. A critical flaw in APT, the package manager used by Debian and Ubuntu, can allow an attacker who modifies package-download traffic to replace a checked package with a malicious one. The malicious package can then run code as root when installed. The issue is tracked as CVE-2026-109518, and Debian, Ubuntu, and APT developers published advisories on November 4.

The attack requires APT to retry failed downloads, a behavior enabled by default in Debian 12 and Ubuntu 22.04 and later. According to the advisories, an attacker who can alter HTTP traffic, including through a malicious mirror or proxy, can use redirects and temporary server errors to trigger retries and swap the download.   • At the time reported, Debian's testing branch was still using vulnerable APT version 3.3.5 despite fixed versions being released elsewhere.
  • The published advisories did not provide a workaround for systems that cannot install an update immediately.

A flaw in the software updater used by Debian and Ubuntu can let someone who interferes with internet traffic replace a legitimate software download with their own. When the computer installs that altered software, the attacker’s code can run with the highest level of control over the machine. Debian and Ubuntu have released fixes, and newer versions that automatically retry failed downloads are affected by default, while older versions may be affected if that retry option was turned on. This matters because a compromised software update can give an attacker control of a computer even when the package was originally checked as genuine.

Mi Scusi, My SCSI: Abusing iSCSI Target Server

Windows iSCSI targets configured without CHAP authentication can be accessed by impersonating authorized initiator IQNs, allowing attackers to enumerate and read shared virtual disks. This can expose sensitive clustered workloads such as Hyper-V VM disks and, potentially, Active Directory credential data unless iSCSI is authenticated, segmented, and protected.
KEY POINTS
  • 01Windows iSCSI Target Server can be configured to permit initiator connections without CHAP authentication.
  • 02An unauthenticated iSCSI discovery session can return target names when presented with an initiator name that is listed as authorized.
  • 03Microsoft iSCSI initiator names are predictably built from a host's DNS name, allowing potential initiator names to be generated from Active Directory or DNS enumeration.
  • 04An attacker who can impersonate an authorized iSCSI initiator can access shared block storage without NTFS permission checks and may retrieve virtual hard-disk files.
  • 05The article recommends enabling CHAP, using IPsec where appropriate, and isolating iSCSI storage with network segmentation and host-based firewalls.

The article examines how Windows iSCSI Target Server configurations without CHAP authentication can allow a party to impersonate an authorized iSCSI initiator and access shared virtual disks. iSCSI provides block-level storage over TCP, and Windows can identify permitted initiators by IP address, DNS name, MAC address, or an iSCSI Qualified Name (IQN). When CHAP is not configured, the article states that establishing a connection requires knowledge of the target server, target IQN, and an accepted initiator IQN. This can bypass NTFS file permissions because access occurs directly at the virtual-disk level.

The author explains that iSCSI target servers can be identified through Active Directory SPN enumeration, while Windows initiator IQNs are predictably constructed from host DNS names. An iSCSI discovery session using a candidate initiator IQN can return target IQNs available to that identity, and the author reports observing no rate limiting or brute-force protection during this process. In the demonstrated path, the retrieved disk contained Hyper-V virtual-machine files, enabling extraction of registry hives and NTDS.dit from a virtualized domain controller and subsequent credential-material recovery. The article recommends enabling CHAP, considering IPsec to reduce network-sniffing risk, and using network segmentation and host-based firewalls to isolate iSCSI storage.

  • Windows iSCSI Target Server registers an SPN on its Active Directory computer account when the target service starts, which can make target servers discoverable through LDAP queries.
  • The article reports that iSCSI initiator names are constructed from a server's DNS hostname, allowing a list of Active Directory computer names to be turned into candidate initiator identities.
  • The author observed no rate limiting or brute-force protection on the service, enabling repeated discovery attempts using potential initiator identities.
  • Accessible shared disks may expose the $RECYCLE.BIN directory, which can reveal the security identifiers of users who previously logged on interactively to systems that mounted the volume.
  • In the author's BloodHound Enterprise customer-tenant data, about half of tenants had at least one computer with the iSCSI target SPN, and one tenant had nearly 700.

The article shows that some Windows servers can share virtual hard drives over a network without requiring a password, relying only on predictable computer names to decide who may connect. Someone who finds the right names may be able to pretend to be an approved computer and copy everything stored on those drives, including virtual-machine files and potentially password-related data from a domain controller. Organizations using Windows shared storage for systems such as Hyper-V, SQL Server, Exchange, or backups could be affected, making network isolation and connection authentication important safeguards.
