How APT41 revived the BlackLotus bootkit to attack diplomatic organizations in Central Asia

Kaspersky links a BlackLotus-like UEFI bootkit called BlackX to APT41, which targeted Central Asian diplomatic organizations after gaining administrator access and used it to disable defenses and deploy espionage payloads. Fully patched systems remained exposed because Microsoft’s Baton Drop mitigation requires administrators to manually activate Secure Boot certificate revocation.
KEY POINTS
  • 01Kaspersky identified an early-2026 campaign targeting diplomatic agencies in Tajikistan, Uzbekistan, and Turkmenistan that used a UEFI bootkit named BlackX.
  • 02BlackX was installed after attackers compromised victim networks and obtained administrator privileges, and its installation chain closely resembled the BlackLotus use of the Baton Drop flaw to bypass Secure Boot.
  • 03The BlackX kernel driver attempted to tamper with security software, including security-related process, thread, and registry monitoring and event logging, while protecting bootkit files by returning handles to calc.exe instead.
  • 04BlackX delivered espionage payloads including a remote-access tool that used Google Drive, OneDrive, or Yandex.Disk for command-and-control communications and OxiDLLRunner, which contacted www.archivetj.com.
  • 05Kaspersky attributed the campaign to APT41 with medium confidence and found that targeted systems were fully patched but had not had Microsoft’s manual Secure Boot certificate-revocation step activated.

Kaspersky identified an early-2026 campaign against diplomatic agencies in Tajikistan, Uzbekistan, and Turkmenistan that used a UEFI bootkit named BlackX. The attackers deployed it after compromising networks and obtaining administrator privileges. BlackX closely resembles the BlackLotus bootkit and uses the Baton Drop flaw to manipulate Secure Boot and load malicious components before Windows starts. Kaspersky attributed the campaign to APT41 with medium confidence based on overlaps with previously reported FishMonger activity and other payload characteristics.

BlackX installs a kernel driver that attempts to weaken security products by disabling certain monitoring callbacks and interfering with event logging, while also hiding bootkit files by returning a handle to calc.exe instead. It deployed espionage payloads including a remote-access tool that used Google Drive, OneDrive, or Yandex.Disk for communications, as well as OxiDLLRunner, which contacted www[.]archivetj[.]com to retrieve and run additional DLLs. Although the targeted systems were fully patched, the relevant Microsoft protection required a separate manual step to revoke the certificate used by vulnerable boot components. The article warns that this gap can leave organizations exposed even after installing updates, particularly when administrators do not activate the additional Secure Boot revocation process.

  • Installing the relevant Microsoft updates alone did not block BlackX because the revocation of the certificate used by vulnerable boot components required a separate manual activation step.
  • The October 2026 expiration of the “Windows Production PCA 2011” certificate does not stop vulnerable boot components from loading unless the certificate is explicitly blocklisted.
  • BlackX’s installer keeps the required bootkit components in an RC4-encrypted, extensionless file rather than embedding them in its installer executable, complicating component recovery during incident response.
  • The BlackX driver attempted product-specific tampering when Kaspersky or Avast software was present, but Kaspersky’s dynamic analysis found that the Kaspersky-targeting procedures did not interfere with its products.
  • BlackX closely resembles BlackLotus even though BlackLotus source code has not been published, indicating the operators may have reverse-engineered it or acquired its source code.

Researchers found that APT41, a suspected China-linked spying group, used a powerful type of malware to target diplomatic organizations in Tajikistan, Uzbekistan, and Turkmenistan. The malware starts before Windows and can hide itself, weaken security software, and install tools for stealing information. The affected computers had received Microsoft updates, but remained vulnerable because an extra manual step was needed to fully turn on the protection. This matters because organizations can believe they are protected after updating their systems while attackers may still be able to gain deep, long-lasting access.

The Keys Are in the Browser: Secret Exposure Across AI-Built Websites

Cyble found that 35 of 22,306 AI-built websites exposed live server-side credentials, including OpenAI, Stripe, Supabase, AWS, GitHub, and Slack keys, directly in public front-end code. Reused templates can spread a single exposed secret across many domains, enabling billing fraud, database compromise, cloud access, or internal phishing.
KEY POINTS
  • 01Cyble scanned more than 1.3 million newly registered domains and identified 22,306 websites built with AI app-builders.
  • 02Thirty-five of the identified AI-built sites exposed private credentials in public front-end code, including OpenAI API keys, Stripe secret keys, Supabase service-role tokens, AWS access keys, and GitHub or Google OAuth secrets.
  • 03Five sites exposed 16 OpenAI API keys, including one AI-writing site that shipped 12 distinct keys in its client-side bundle.
  • 04A shared Slack incoming-webhook URL appeared across 13 near-identical Bubble-hosted domains, while a single Stripe secret key was reused across four domains under two brands.
  • 05Cyble recommends keeping private keys in server-side functions or backend workflows, rotating any key that appeared on the client side, and reviewing shipped page code for exposed secrets.

Cyble Research and Intelligence Labs scanned more than 1.3 million newly registered domains and identified 22,306 websites built with AI app-builders. Of those sites, 35 exposed credentials that should remain private in publicly delivered front-end code. The exposed items included OpenAI API keys, Stripe secret keys, Supabase service-role tokens, AWS access keys, GitHub tokens, Google OAuth secrets, and Slack incoming webhooks. Cyble excluded browser-safe or conditionally risky values, such as reCAPTCHA site keys, Stripe publishable keys, and many Google API keys, from its confirmed count.

The most significant pattern was credential reuse across cloned site fleets. One Slack webhook was embedded in the same client bundle across 13 near-identical Bubble sites, while one Stripe secret key appeared on four domains under two brands. Cyble also found five sites with 16 live OpenAI keys, including one AI-writing site that contained 12 distinct keys, and four sites exposing Supabase service-role tokens that bypass database access rules. The report recommends placing secrets only in server-side functions or backend workflows, rotating any key exposed in client code, and checking public site code for private credentials before deployment.

  • The confirmed exposure count was limited to credentials that should never be public, excluding thousands of browser-safe keys and other strings that can look sensitive but are not necessarily dangerous.
  • A single exposed credential can create a much larger problem when AI-built templates are cloned, as shown by one Slack webhook appearing on 13 domains and one Stripe secret key appearing across four domains under two brands.
  • Supabase service-role tokens are especially consequential because they bypass the database’s normal access restrictions and allow full reading and writing of the project database.
  • The issue was observed across both Bubble and Next.js-based sites, indicating that the exposure pattern is not limited to one AI-builder platform.

Cyble examined more than 1.3 million newly registered websites and found 35 AI-built sites that publicly revealed private account keys in the code visitors download. The exposed keys could let strangers spend a site owner’s money, access payment and customer information, change or steal database records, send messages into company chat rooms, or reach cloud accounts and source code. Website owners using AI site builders are affected, especially when they copy the same template across many domains, because one leaked key can expose the entire group of sites.

OPEN SOURCE ↗

Cyble reports concrete findings from a scan of 1.3 million newly registered domains, including 35 AI-built sites that exposed live high-impact credentials such as Stripe, OpenAI, Supabase, AWS, GitHub, and Slack secrets. The findings are actionable and demonstrate template-driven credential reuse, but the report does not identify active exploitation or a broadly deployed product flaw requiring immediate action.
