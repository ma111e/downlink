New DOUBLECUP ClickFix service hides malware in browser cache images

A new Russian loader-as-a-service called DOUBLECUP uses ClickFix lures to make victims run commands that extract malware hidden in cached PNG images. The campaigns deliver CountLoader on Windows and macOS and a new Windows RAT called DeviceManager, which uses blockchain-based C2 discovery to resist takedowns.
KEY POINTS
  • 01A new Russian loader-as-a-service named DOUBLECUP uses ClickFix attacks to hide malicious code in PNG images cached by victims' browsers.
  • 02SOCRadar says DOUBLECUP has operated since early June 2026 and provides customers with licenses and a Go-based Windows tool for creating malicious campaigns.
  • 03DOUBLECUP ClickFix campaigns used fake CAPTCHA prompts on login pages impersonating NetSuite, Odoo, HubSpot, and Salesforce.
  • 04When victims run the copied command, it searches the browser cache for the PNG by exact file size and uses findstr or certutil to recover and execute the hidden first-stage payload.
  • 05SOCRadar identified DOUBLECUP delivering an updated CountLoader targeting Windows and macOS and a previously undocumented Python-based Windows RAT called DeviceManager.

A new Russian loader-as-a-service named DOUBLECUP uses ClickFix attacks to hide malicious code in PNG images cached by victims’ browsers. SOCRadar says the service has operated since early June 2026 and provides customers with licenses and a Go-based Windows tool for creating malicious campaigns. The service handles infrastructure such as hosting steganographic PNG images, managing session and signal endpoints, providing encryption keys, and automatically rebuilding payloads.

SOCRadar observed DOUBLECUP campaigns using fake CAPTCHA prompts on login pages impersonating NetSuite, Odoo, HubSpot, and Salesforce. When a victim visits one of these sites, DOUBLECUP registers the session, determines the victim’s public IP address, and forces the browser to download and cache a malicious PNG image. The page then tries to convince visitors to paste and run a command that was automatically copied to their clipboard.

Once executed, the command searches the browser cache for the PNG by exact file size and uses findstr or certutil to recover and run the hidden first-stage payload. The payload launches a fileless second-stage dropper that uses the victim’s public IPv4 address to create a decryption key for the final encrypted payload, verifies it against a hardcoded SHA-256 hash, and executes it in memory. SOCRadar identified the final payloads as an updated CountLoader targeting Windows and macOS and a previously undocumented Python-based Windows RAT called DeviceManager.

  • DOUBLECUP shifts much of the attack complexity away from its customers by hosting steganographic PNGs, managing session and signal endpoints, providing encryption keys, and automatically rebuilding payloads.
  • The victim’s public IPv4 address is used to create the decryption key for the final payload, tying successful execution to information collected during the specific victim session.
  • The malicious command is customized for the victim’s browser and searches the browser cache for the PNG by exact file size, showing that ordinary cached browser files are part of the delivery chain.
  • DeviceManager uses Ethereum or Polygon smart contracts to retrieve its current command-and-control address, making its infrastructure more resistant to disruption attempts.
  • DOUBLECUP campaigns targeted users through fake CAPTCHA prompts on pages impersonating common business platforms, including NetSuite, Odoo, HubSpot, and Salesforce.

A new Russian service called DOUBLECUP helps criminals set up fake login pages that show fake CAPTCHA prompts and trick visitors into running a copied command. If the victim uses Windows or macOS, the command can pull harmful code hidden inside an image saved by the browser and install programs that gather information or let attackers control the computer. This matters because the pages impersonated widely used business services like NetSuite, Odoo, HubSpot, and Salesforce, and the malware uses methods designed to make it harder to shut down.

Fake Roblox Xeno script launcher pushes infostealer, RAT malware

Fake Xeno Executor installers promoted to Roblox players are delivering a Java-based RAT and infostealer that can steal browser data, gaming and payment account tokens, crypto wallets, and enable remote control. Bitdefender says the campaign is evolving and advises users to avoid third-party Roblox tools from untrusted sources.
KEY POINTS
  • 01Bitdefender discovered a campaign targeting Roblox users with fake Xeno Executor installers that has been active since the start of the year and rose sharply in March before stabilizing.
  • 02The fake Xeno installers are promoted through gaming forums, Discord communities, and compromised or impersonated accounts as an “undetected” version of Xeno Executor.
  • 03When victims run the fake xeno.exe file, it launches a first-stage malware loader that checks for Java Runtime Environment, starts an obfuscated Java payload disguised as decompiler.exe, and downloads the final malware payload.
  • 04The final payload is a Java-based remote access and information-stealing tool that can steal browser data, gaming and payment account tokens, cryptocurrency wallet data, and provide surveillance and remote control capabilities.
  • 05Bitdefender believes the campaign is the same as the Powercat campaign previously documented by ThreatLocker, but with updated malware capabilities and new command-and-control infrastructure.

Fake Xeno Executor installers are infecting Roblox players with malware that provides remote access and steals sensitive information. Xeno Executor is a popular third-party Roblox utility for running scripts, including cheats, and attackers are advertising the fake version as an “undetected” release. Bitdefender found that the campaign has targeted Roblox users since the start of the year, rose sharply in March, and then stabilized.

The fake installers are promoted through gaming forums, Discord communities, and compromised or impersonated accounts controlled by the attackers. Victims download ZIP archives or self-extracting archives that are made to look authentic by recreating a legitimate Xeno installation structure, including genuine Lua scripts and plausible filenames. When users launch the included xeno.exe file, they run a first-stage malware loader instead of the legitimate Xeno executable.

The loader checks for Java Runtime Environment, extracts it if needed, reads local validation keys for the attackers’ command-and-control server, and launches an obfuscated Java payload disguised as decompiler.exe. The final payload is a Java-based remote access and information-stealing tool that can steal browser data, Discord, Roblox, Minecraft and Microsoft Store tokens, payment information, and cryptocurrency wallet data. It also supports keylogging, mouse activity logging, screenshots, desktop streaming, webcam access, file transfers, PowerShell commands, and an interactive remote shell.

  • The attackers increase trust by recreating the directory structure of a legitimate Xeno installation, including genuine Lua scripts, and using plausible filenames, so a package that looks authentic is not enough to prove it is safe.
  • The campaign exploits Roblox anti-cheat blocking cycles by advertising the fake installer as an “undetected” Xeno version, specifically targeting users who expect frequent unofficial updates.
  • The malware’s use of Java Runtime Environment checks and extraction means victims may still be infected even if Java is not already installed on their system.
  • Bitdefender’s link to the earlier Powercat campaign, along with new capabilities and new command-and-control infrastructure, shows the operation has continued to evolve rather than remaining a static one-off campaign.

Criminals are spreading fake installers for Xeno Executor, a third-party Roblox tool, to trick Roblox players into running harmful software instead of the real program. People who install it can have private data stolen from browsers and accounts like Discord, Roblox, Minecraft, Microsoft Store, and crypto wallets, and the attackers can also watch activity or control the computer remotely. This matters because players looking for cheats or unofficial tools could lose accounts, payment information, and personal files.

Bitcoin hardware wallet maker destroys some inventory after more than $88 million stolen

Coinkite destroyed remaining Coldcard hardware wallet inventory shipped with vulnerable firmware after attackers exploited a seed-generation flaw to steal at least 1,367 BTC, worth about $88.6 million, from customers. The company has released patched firmware and halted shipments of affected devices.
KEY POINTS
  • 01Coinkite said it destroyed remaining Coldcard inventory manufactured with vulnerable firmware after customers were robbed of bitcoin through a firmware vulnerability.
  • 02Galaxy Research said the hackers behind the campaign stole at least 1,367.05 BTC, worth about $88.6 million, from 4,585 addresses.
  • 03Coldcard released patched firmware that it says prevents the issue going forward and halted shipments when the vulnerability was confirmed.
  • 04Chainalysis said the attacker targeted high-value wallets early, causing the cumulative value stolen to reach roughly $30 million in the first 10 minutes.
  • 05Coinkite did not respond to requests for comment about whether it will compensate victims.

Canadian company Coinkite said it destroyed remaining inventory of Coldcard bitcoin hardware wallets manufactured with vulnerable firmware after customers were robbed of bitcoin. The devices are used to store bitcoin offline rather than on an exchange. The company confirmed that a vulnerability previously discovered in March 2021 is now being used to breach accounts.

Cybersecurity firm Galaxy Research said the hackers behind the campaign stole at least 1,367.05 BTC, worth about \(88.6 million, from 4,585 addresses. Chainalysis said two of the biggest victims lost a combined \)4 million, and bitcoin holders discussed losses on social media. Chainalysis also said the attacker targeted high-value wallets early, causing the cumulative value stolen to reach roughly $30 million in the first 10 minutes.

Coldcard said it has been working with customers to move funds and released patched firmware that it says prevents the issue going forward. The company said its high-security system locks cannot be upgraded until a user initializes the device, so it could not ship units with affected firmware and risk users missing the upgrade. Coinkite did not respond to requests for comment about whether it will compensate victims, and the FBI declined to comment on whether it is investigating the campaign.

  • Coldcard said affected devices should not be disposed of because they may become essential if stolen funds are recovered and legal coordination with law enforcement proceeds.
  • The company destroyed affected inventory rather than simply shipping devices with upgrade instructions because its high-security system locks prevent upgrades until a user initializes the device.
  • Chainalysis said the attacker’s early focus on the largest wallets suggests the victim wallet population had been studied before the thefts began.
  • A Coinkite senior official linked the incident partly to artificial intelligence-assisted code reviews, saying they may help criminals find old software flaws faster than experts can keep up.

A Canadian company called Coinkite destroyed some of its remaining Coldcard bitcoin wallet devices after criminals used a flaw in the device software to steal at least $88.6 million from customers. The affected people are bitcoin owners who used these devices to keep their money offline, and some victims lost millions of dollars. This matters because a product meant to protect people’s savings instead helped expose them to theft, and the company is now trying to help customers move funds while law enforcement may need the devices if money is recovered.

This is a high-impact, specific incident involving active exploitation of a hardware wallet firmware vulnerability and at least $88.6 million in stolen bitcoin. Security professionals should read it because it highlights real-world consequences of latent firmware flaws, patch deployment constraints, and attacker prioritization of high-value targets.

18 Malicious npm Packages Deliver Cross-Platform RAT to Alibaba Tool Users

Researchers found 18 malicious npm packages targeting Alibaba tool users with a cross-platform RAT, using dependency chains that impersonate private Alibaba packages to infect Chinese-speaking developer environments. Anyone who installed the packages should assume compromise, rotate credentials from a clean machine, and audit systems for suspicious activity.
KEY POINTS
  • 01Cybersecurity researchers discovered 18 malicious npm packages targeting users of Alibaba developer tools with a cross-platform remote access trojan in a targeted software supply chain campaign against Chinese-speaking environments.
  • 02The package lib-mtop was published under the same unscoped name as a private Alibaba package, and later versions added a loader that fetches and executes a remote JavaScript payload using curl.
  • 03The campaign split malicious loader functionality across multiple packages in the same dependency tree, with top-layer packages impersonating private @ali-scoped packages and smart-config-manager acting as a middle-layer bridge.
  • 04The payload behaves differently by operating system, including trojanizing Alilang on Windows, downloading and running a temporary binary on Linux, and adding a background script and Launch Agent on macOS.
  • 05Users who installed any of the listed packages are advised to assume compromise, rotate sensitive credentials from a clean machine, and audit developer systems for suspicious activity.

Cybersecurity researchers discovered 18 malicious npm packages targeting users of Alibaba developer tools with a cross-platform remote access trojan. The campaign impersonated private Alibaba-related packages and appears aimed at Chinese-speaking developer environments. One package, lib-mtop, was first published in November 2023 without functionality, but later versions added a loader that fetched and executed a remote JavaScript payload.

The attack split malicious functionality across multiple packages in the same dependency tree, with lure packages depending on smart-config-manager as a bridge to lower-layer packages containing loader logic. A rule engine used the vm module to choose payload behavior based on the victim’s operating system, and the payload was retrieved from a domain made to resemble Alibaba infrastructure. On Windows it targeted Alilang, on Linux it downloaded and ran a binary from /tmp, and on macOS it modified ~/.zshrc and created a Launch Agent.

The final payload is described as a complex backdoor with command execution, file upload and download, host reconnaissance, payload staging, and lateral movement capabilities. It can also persist by injecting malicious code into enterprise collaboration applications such as DingTalk, Wukong, and Qoder. Users who installed any listed package are advised to assume compromise, rotate sensitive credentials from a clean machine, and audit developer systems for suspicious activity.

  • The attack hid its malicious loader across several otherwise separate npm packages, meaning a single package may appear harmless unless the full dependency tree is examined together.
  • The lure packages were designed to work normally in environments that had access to the real private Alibaba packages, while also installing extra malicious dependencies.
  • The payload download domain was made to resemble Alibaba infrastructure, which could help the activity blend into normal developer network traffic.
  • The final backdoor included lateral-spread capabilities and persistence through enterprise collaboration applications, so the risk extends beyond the initial developer machine.
  • The campaign’s low download counts do not necessarily indicate low impact because the packages appear to have been aimed at a narrow set of Alibaba-related developer environments.

Researchers found 18 harmful software packages on npm that were made to look like tools used by Alibaba developers, especially in Chinese-speaking work environments. If someone installed them, the packages could download hidden software that gives attackers control of the computer, lets them steal or move files, run commands, and spread through workplace apps like DingTalk, Wukong, and Qoder. This matters because the campaign appears aimed at industrial spying, and affected users are told to assume their computers were compromised, change sensitive credentials from a clean machine, and check for suspicious activity.

Developers in the Crosshairs: Fake AI Tools Deliver Infostealer

Attackers are cloning popular AI and developer GitHub repositories to trick users into running a multi-stage SmartLoader chain that delivers infostealers. Both loader stages use Polygon blockchain-based EtherHiding to dynamically resolve C2 infrastructure, making takedowns and blocklisting harder.
KEY POINTS
  • 01Netskope Threat Labs found ongoing campaigns in which attackers clone and impersonate known GitHub repositories for AI resources and developer tools to deliver a previously analyzed Malware-as-a-Service infostealer.
  • 02The campaign targets AI users and developers, with victims mainly in North America, Asia, and Southern Europe and the financial services, banking, and technology sectors leading.
  • 03The malicious payload is delivered as a four-file zip archive containing lua51.dll, compiler.exe, Application.bat, and gc.txt, where compiler.exe runs the obfuscated Lua code stored in the text file.
  • 04The loader chain uses SmartLoader twice, with the first Lua script obfuscated using Prometheus and the second-stage Lua script showing indicators consistent with MoonSec V3.
  • 05Both SmartLoader stages resolve their command-and-control server address at runtime from a Polygon smart contract using EtherHiding, allowing operators to redirect implants by updating the smart contract value.

Netskope Threat Labs reports that attackers behind a previously analyzed Malware-as-a-Service NodeJS infostealer have shifted delivery methods from ClickFix-style social engineering to cloned and impersonated GitHub repositories. The repositories imitate popular AI resources and developer tools, including lures related to Claude, ComfyUI, AI coding assistants, Python security guides, and Rust frameworks. The campaign mainly targets AI users and developers in North America, Asia, and Southern Europe, with financial services, banking, and technology sectors leading among affected segments.

The malicious download arrives as a four-file zip archive containing a LuaJIT runtime DLL, a renamed LuaJIT interpreter, a batch script, and a text file containing obfuscated Lua code. The first-stage Lua script is identified as Prometheus-obfuscated, while the second-stage script shows structural indicators consistent with MoonSec V3. The payload design makes the harmful behavior appear only when all files are present and launched together, while the text file and interpreter may appear harmless when inspected separately.

The campaign uses SmartLoader twice in a redundant multi-stage chain, and both loader stages resolve their command-and-control server address from a Polygon smart contract at runtime using EtherHiding. SmartLoader collects geolocation data, captures a screenshot, sends an encrypted beacon, receives tasking, establishes persistence through a scheduled task, and downloads additional payloads from GitHub-hosted files. Netskope states that compromising developer environments is significant because developers often have access to source code, cloud credentials, API keys, code-signing certificates, and CI/CD pipelines, creating the potential for software supply chain attacks.

  • The campaign’s loader chain is intentionally redundant: SmartLoader is deployed twice, and both stages use the same Polygon smart contract to resolve infrastructure, so blocking only one stage may not stop the full infection flow.
  • The malicious Lua code is stored in a plain text file and only becomes active when executed with the bundled LuaJIT interpreter and DLL, which can evade security checks that inspect files individually rather than as a combined package.
  • The use of EtherHiding lets the attackers change the command-and-control IP address by updating a smart contract value, allowing them to redirect deployed malware without changing the payload itself.
  • The first and second loader stages use different Lua obfuscators, Prometheus and likely MoonSec V3, which increases analysis complexity across an otherwise similar attack flow.
  • The GitHub lures rely on cloned repositories that still appear authentic at the root level and may list the original contributor, making installation instructions and download URLs especially important places to verify.

Attackers are copying popular GitHub pages for AI tools and developer resources, then hiding harmful downloads inside them or changing installation links so people trust and run them. The main targets are AI users and software developers, especially in North America, Asia, and Southern Europe, with financial services, banking, and technology organizations most affected. This matters because developers often have access to source code, cloud logins, secret keys, and software release systems, so stealing from their computers could lead to wider attacks on other people and companies.

Targeted Attack on Government Entities in the Middle East | Part 2

ThreatLabz analyzed BINDCLOAK, a previously undocumented modular Windows backdoor used against Middle Eastern government entities and assessed with high confidence to be a variant of OctLurk. The malware uses encrypted TLS-over-TCP C2, reflective plugin loading, token-based privilege escalation, and EDR evasion techniques, indicating a sophisticated East Asia-linked threat actor expanding operations beyond Central Asia.
KEY POINTS
  • 01ThreatLabz analyzed BINDCLOAK, a previously undocumented 64-bit modular Windows backdoor written in C++ that was deployed on victims’ machines during post-compromise activity.
  • 02BINDCLOAK was decrypted and reflectively loaded by the MIXEDKEY loader in a multi-stage attack chain targeting government entities in the Middle East.
  • 03BINDCLOAK uses a complex message routing mechanism and encrypted TLS-over-TCP communications to manage its command-and-control channel.
  • 04The backdoor supports commands for collecting and managing user and process tokens, starting and stopping modules, reflectively loading plugin DLLs, and preventing the infected machine from entering sleep mode.
  • 05ThreatLabz assesses with high confidence that BINDCLOAK is a variant of OctLurk based on code similarities and shared command-and-control infrastructure.

ThreatLabz published Part 2 of its technical analysis on new tools used by an East Asia-linked threat actor targeting government entities in the Middle East. The report focuses on BINDCLOAK, a previously undocumented 64-bit modular Windows backdoor written in C++ that was deployed during post-compromise activity. ThreatLabz assesses with high confidence that BINDCLOAK is a variant of OctLurk based on code similarities and shared command-and-control infrastructure.

BINDCLOAK is decrypted and reflectively loaded by the MIXEDKEY loader as part of a multi-stage attack chain. It generates a host identifier from the computer name and C:\ volume serial number, sends a beacon containing host information, and uses encrypted TLS-over-TCP communications with a complex message routing mechanism. Its commands support token collection and management, module control, reflective loading of plugin DLLs, and preventing the infected machine from entering sleep mode.

The article says BINDCLOAK uses endpoint detection and response evasion techniques, including routing LoadLibraryW calls through RtlQueueWorkItem when loading plugin dependencies. ThreatLabz links the campaign to OctLurk through SSL certificate reuse and overlapping infrastructure, including cert.hypersnet[.]com and about.blsouqs[.]com. The report states that the campaign identified in July 2026 shows an expansion of operations from Central Asia to the Middle East, with a key focus on the energy vertical.

  • BINDCLOAK’s host identifier is only 4 bytes and is derived from the computer name and C:\ volume serial number, making those host artifacts important for interpreting its command-and-control messages.
  • The C2 encryption scheme sends the second XOR key in cleartext, so captured network payloads can be decrypted by reversing the documented compression and two-pass XOR process.
  • BINDCLOAK’s plugin loader deliberately routes LoadLibraryW calls through RtlQueueWorkItem to avoid suspicious library-loading behavior from unbacked executable memory regions.
  • The C2 domain cert.hypersnet[.]com reused the same SSL certificate as the OctLurk C2 domain about.blsouqs[.]com, providing a concrete infrastructure link between BINDCLOAK and OctLurk activity.
  • The article identifies contacts.ftabnews[.]com and ftabnews[.]com as likely threat actor infrastructure based on observed ping activity and overlap in registrar, name servers, and hosting ASN.

Researchers found a new hidden tool called BINDCLOAK that was placed on victims’ Windows computers during attacks on government entities in the Middle East, with a focus on the energy sector. The tool lets attackers quietly connect to infected machines, gather information, load extra pieces of software, and use stolen or provided login access to run with higher privileges. The researchers say the same group is linked to earlier attacks in Central Asia, which matters because it shows the group is expanding its targets and has strong technical capabilities.
