Two malicious LiteLLM releases, versions 1.82.7 and 1.82.8, were available on PyPI for about 40 minutes on March 24 and contained credential-stealing code. CloudSEK says a dataset built from roughly 434,000 captured files maps potential exposure to more than 2,500 organizations, though the article emphasizes this is not a confirmed victim count. The exposed material may include cloud keys, SSH keys, Kubernetes tokens, database passwords, and other secrets from systems that installed the compromised packages.

The incident is tied to the wider TeamPCP supply-chain campaign linked to Aqua Security’s Trivy scanner, which Google tracks as UNC6780. The FBI warned that actors affiliated with the campaign are likely to use exfiltrated credentials long after the initial compromise and advised organizations to rotate CI/CD secrets, publishing tokens, and cloud credentials. The campaign’s downstream impact is supported by reports from Checkmarx, Mercor, and CERT-EU describing unauthorized access, malicious artifacts, and a compromised European Commission AWS account.

A key technical detail is that LiteLLM 1.82.8 included a litellm_init.pth file that Python processes at interpreter startup, so the malicious code could run even if LiteLLM was not imported. The packages sent stolen data to models.litellm[.]cloud, an attacker-controlled domain unrelated to the project. Organizations assessing exposure are advised to check for LiteLLM 1.82.7 or 1.82.8 installations during the March 24 audit window, rotate any accessible secrets, and search GitHub organizations for campaign-related repositories named tpcp-docs or docs-tpcp.
