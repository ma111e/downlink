Hackers exploit macOS Screen Sharing flaw to deploy Monero miner

Hackers are actively exploiting a macOS Screen Sharing authentication bypass flaw, CVE-2026-65400, on internet-exposed systems to gain root access and install a Monero miner. Users should install Apple’s latest macOS updates or disable Screen Sharing if it is not needed.
KEY POINTS
  • 01The Netherlands’ National Cyber Security Centre warned that hackers are actively exploiting a macOS Screen Sharing authentication bypass vulnerability after public exploit code emerged.
  • 02Apple fixed CVE-2026-65400 on August 6 in macOS Tahoe 26.6.1 and earlier releases, with updates also available for macOS Sequoia 15.7.9 and macOS Sonoma 14.8.9.
  • 03The flaw allows network-based attackers to gain access without valid credentials when macOS Screen Sharing is exposed over TCP port 5900.
  • 04The NCSC said it received reports of active exploitation on multiple systems where port 5900 was accessible from the internet.
  • 05According to the NCSC, attackers obtained root access on affected systems and placed a Monero cryptocurrency miner.

The Netherlands’ National Cyber Security Centre is warning that hackers are actively exploiting a macOS authentication bypass vulnerability after public exploit code emerged. The issue is in macOS Screen Sharing, Apple’s built-in remote desktop feature that uses the VNC protocol over TCP port 5900. Apple fixed CVE-2026-65400 on August 6 in macOS Tahoe 26.6.1 and earlier releases.

The flaw allows network-based attackers to gain access without valid credentials. The NCSC said it received a report that the vulnerability is being exploited in the wild on systems where port 5900 is exposed to the internet. According to the agency, attackers obtained root access on affected systems and placed a Monero cryptocurrency miner.

Apple’s updates for macOS Tahoe 26.6.1, macOS Sequoia 15.7.9, and macOS Sonoma 14.8.9 address the vulnerability by improving state management mechanisms to enforce correct credential validation. Users who cannot update immediately are advised to disable Screen Sharing in System Settings if they do not need it. The NCSC has not shared details on when the attacks began, whether they go beyond cryptocurrency mining, or how many systems have been affected.

  • Systems are specifically at risk when TCP port 5900 is reachable from the internet, so exposure of Screen Sharing is a key factor in the reported attacks.
  • Disabling Screen Sharing through System Settings is an immediate mitigation for users who cannot install the macOS updates right away.
  • The reported intrusions show that this flaw can lead to root-level access, not just limited remote desktop use.
  • Apple’s fix is described as improving state management to enforce correct credential validation, indicating the issue involved improper handling of authentication state.

A Dutch government cyber agency says hackers are breaking into Macs through Apple’s Screen Sharing feature when it is reachable from the internet. Apple has released fixes for the issue, which affects macOS Tahoe, Sequoia, and Sonoma, and people who cannot update right away are advised to turn off Screen Sharing if they do not need it. This matters because attackers can get full control of affected computers and have already used that access to install software that secretly mines Monero cryptocurrency.

  • 02The article describes an evolving attack chain where a stolen OAuth token provides access to Gmail and Drive, enables email account takeover, and supports lateral movement through credentials, password resets, or magic links.
  • 03The article warns that AI agents connected to Google Workspace use legitimate OAuth grants to read email and Drive, and can follow the same path as attackers if they behave unexpectedly or have broader access than needed.
  • 04The article argues that defenses should cover the full workspace chain across email, OAuth, Drive, and account behavior rather than stopping at inbox security.

The article argues that the Vercel and Composio breaches show a repeated workspace attack pattern in which email was not the initial entry point. Instead, the described chain begins with a stolen OAuth token that gives access into Google Workspace data such as Gmail and Drive. The author says this changes the old security model that treated email as the main dangerous channel and everything else in the workspace as relatively safe.

In the newer chain, OAuth access can allow attackers to read sensitive data, take over email accounts, and move laterally using credentials stored in Drive or password resets and magic links delivered through email. The article notes that OAuth tokens can survive password resets, may not expire, and are difficult for users and many security teams to observe. It also describes stolen OAuth tokens as a supply chain issue when a compromised supplier results in access into another environment.

The article connects this same chain to AI agents that employees authorize to use Google Workspace through legitimate OAuth grants.   • OAuth tokens are especially risky because the article says they can survive password resets, may not expire, and are hard for users and many security teams to observe.
  • The article frames stolen OAuth tokens as a supply chain risk because a compromised supplier can create access into another organization’s environment.
  • The same controls proposed for attacker activity, such as limiting access to sensitive Gmail and Drive data and redacting password reset links, are presented as useful for reducing accidental harm from AI agents as well.
  • The article argues that the most important AI-agent controls may be protections around the workspace environment the agent operates in, rather than controls placed only on the agent itself.

The article says recent Vercel and Composio incidents show a newer pattern where access to Google Workspace can start through an app’s saved permission to an account, rather than through a bad email. This can let someone read Gmail and Drive, take over email, and use password reset messages or saved credentials to reach other services. It also warns that workplace AI tools connected to Gmail and Drive can follow a similar path by accident if they have more access than they need, affecting employees and organizations using Google Workspace. The broader risk is that private messages, files, credentials, and connected business systems can be exposed if defenses only focus on the inbox.

The United States was the most targeted country with 1,721 attacks, followed by Canada, Brazil, Mexico, and Colombia.

The article says attackers focused on industries where downtime, sensitive data exposure, patient safety, financial data, or supply-chain disruption creates pressure to pay.
