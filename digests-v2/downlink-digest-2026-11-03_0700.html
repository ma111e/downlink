Synology NAS Devices Targeted in Ransomware Attacks Exploiting Patched DSM Flaw

Synology warns that attackers are exploiting an already patched DSM flaw to deploy C3RB3R ransomware on NAS devices running outdated software. Users should immediately update DSM to the fixed version for their release and enable automatic updates.
KEY POINTS
  • 01Synology says threat actors are exploiting a DSM vulnerability patched in December 2024 to target NAS devices running outdated software.
  • 02The attacks encrypt data and demand a ransom, and customer reports identify the ransomware as C3RB3R, which appends the .L0CK3D extension to files.
  • 03Synology linked the attacks to an advisory covering CVE-2024-10441, CVE-2024-50629, and CVE-2024-10445.
  • 04CVE-2024-10441 has a CVSS score of 9.8 and can enable remote code execution in DSM's system plugin daemon through unspecified vectors.
  • 05Synology urges users to update DSM to fixed releases and enable automatic updates.

Synology is warning that threat actors are targeting Network Attached Storage devices running outdated versions of DiskStation Manager (DSM) with ransomware. The attackers are exploiting a flaw patched in December 2024 to encrypt data and demand payment. Customer reports associate the incidents with C3RB3R ransomware, which has been observed adding the “.L0CK3D” extension to locked files.

Synology did not name the exact vulnerability used in the attacks, but it linked to a November 2024 advisory covering three DSM issues: CVE-2024-10441, CVE-2024-50629, and CVE-2024-10445. The most severe, CVE-2024-10441, has a CVSS score of 9.8 and could allow remote code execution in DSM’s system plugin daemon. Synology recommends users update to the fixed DSM release for their version and enable automatic updates to keep their devices protected.

  • Synology did not identify the exact flaw being used in the current attacks, but it directed users to an advisory containing three DSM issues, including CVE-2024-10441, a 9.8-rated remote code execution flaw.
  • The fixes are available across multiple DSM release branches, including DSM 6.2 through DSM 7.2.2, so users do not necessarily need to move to the newest major release to apply a security update.
  • Customer reports associate the current incidents with C3RB3R ransomware and the ".L0CK3D" file extension, giving affected users a concrete indicator of the reported activity.
  • Synology NAS devices have faced prior ransomware-related threats through both software weaknesses and attempts to guess commonly used administrator credentials, showing that keeping software updated addresses only one of the risks described in the article.

Synology says criminals are breaking into some of its network storage devices that have not installed a software update released in December 2024. They lock the files stored on the device and demand money to unlock them, with some victims reporting files renamed with “.L0CK3D.” This matters because these devices can hold important personal or business data, and older software can leave owners exposed even after a fix is available. Synology urges affected users to update their device software and turn on automatic updates.

This is an active ransomware campaign exploiting a previously patched DSM vulnerability on Synology NAS devices, with data encryption and extortion already reported. Security professionals responsible for Synology deployments should urgently verify DSM versions and apply the listed fixes.

Hackers Exploit BTCPay Server Flaw to Steal Bitcoin and Litecoin From Hot Wallets

Attackers are draining Bitcoin and Litecoin hot wallets from BTCPay Server instances running version 2.4.1 or earlier by exploiting a flaw patched in 2.4.2. Users should upgrade to 2.4.7 and treat affected servers and their wallet secrets as compromised, migrating to a fresh server and new wallet.
KEY POINTS
  • 01Attackers stole Bitcoin and Litecoin from hot wallets on BTCPay Server instances running version 2.4.1 or earlier.
  • 02BTCPay Server said the attackers used a different method to exploit the vulnerability fixed in version 2.4.2, released on August 7, 2026.
  • 03BTCPay Server recommends that users of version 2.4.1 or earlier move to a fresh server with a new wallet and treat the machine and all stored secrets as compromised.
  • 04BTCPay Server said it has received no credible reports of hot-wallet drains from users running version 2.4.7.
  • 05Mercado Bitcoin temporarily paused deposits and withdrawals after a security breach that it said involved approximately $38 million in assets, with $11 million already blocked.

BTCPay Server warned that attackers stole Bitcoin and Litecoin from hot wallets on instances running version 2.4.1 or earlier. The self-hosted cryptocurrency payment processor said the attackers used a different method to exploit the vulnerability fixed in version 2.4.2. Reports of the campaign began appearing around November 1, 2026, although BTCPay Server said it is unknown when exploitation first started.

Users of version 2.4.1 or earlier are advised to move to a fresh server with a new wallet, including those who have not identified any theft. BTCPay Server said suspected affected systems and all secrets stored on them should be treated as compromised. Version 2.4.7 addresses one critical and several medium-severity issues, and BTCPay Server said it had received no credible reports of hot-wallet drains involving that current release. An earlier advisory said an unauthenticated remote attacker could obtain LND credential files and use them to take control of an LND node and move funds.

  • BTCPay Server advises users of version 2.4.1 or earlier to rebuild on a fresh server with a new wallet even when no theft has been detected, indicating that an apparently unaffected instance may still contain exposed secrets.
  • The earlier disclosed flaw could let an unauthenticated remote party obtain LND credential files and use them to take control of an LND node and move funds.
  • BTCPay Server recommends retaining only the funds required for daily operations in an internet-connected wallet and keeping the remaining spending keys off the server.
  • Some hosting providers may have automatically shut down BTCPay Server instances running older versions to prevent further exploitation.

Hackers stole Bitcoin and Litecoin from online wallets run through older versions of BTCPay Server, a tool businesses can use to accept cryptocurrency payments. People using version 2.4.1 or older may be affected and are being urged to move to a new server and create a new wallet, even if they have not yet noticed missing money. The incident shows that money kept in internet-connected wallets can be quickly taken if the computer holding the wallet’s access information is compromised, amid other recent cryptocurrency thefts and exchange breaches.

This reports active, in-the-wild theft of Bitcoin and Litecoin from BTCPay Server hot wallets on versions 2.4.1 and earlier. Organizations running affected instances need to upgrade and potentially rebuild systems and wallets because stored credentials may be compromised.

New Wave of Refrigeration Cyberattacks Hits Supermarkets Across Europe, Forcing Stores to Pull Food

Cyberattacks on internet-connected refrigeration controllers disrupted supermarkets and small food retailers across several European countries, causing some stores to remove or discard chilled and frozen goods. The incidents appear to target outdated, internet-exposed Danfoss and possibly Copeland systems with default credentials or unpatched software, prompting calls to isolate controllers and use secure remote access.
KEY POINTS
  • 01Attackers remotely changed refrigeration settings at supermarkets and food retailers in multiple European countries, warming fridges and freezers and prompting some businesses to remove or discard food.
  • 02Belgian, Swedish, Estonian, Irish, Dutch, Finnish, Portuguese, and Italian businesses reported affected refrigeration systems, although the reported number of stores and impact varied by company.
  • 03Several affected systems were made by Danfoss, while a Belgian butcher reported that Copeland equipment was also targeted; some incidents involved older systems, outdated software, internet exposure, or default passwords.
  • 04No group had claimed responsibility, and authorities had not determined whether the incidents were linked to the earlier attacks on French supermarkets.
  • 05CERT-FR advised operators to remove affected refrigeration controllers from direct internet access, review configurations and defrost schedules, use secure remote connections, change default passwords, and update firmware.

Attackers remotely changed refrigeration settings at supermarkets and food retailers in Belgium, Sweden, Estonia, and other European countries overnight into November 2. The changes placed units into defrost mode or raised temperature settings, including reported settings of 50°C at stores in Sweden and Estonia. Some retailers removed chilled and frozen products from sale or discarded spoiled goods, while others contained the problem before products were damaged.

The incidents affected a limited number of stores at chains including Delhaize, Carrefour, ICA, Coop, SuperValu, Selver, and Intermarché, as well as smaller businesses. Several affected systems used Danfoss refrigeration controls, and a Belgian butcher reported that Copeland equipment was also targeted. Reports cited older, unpatched systems, direct internet exposure, and default passwords as contributing weaknesses, while authorities had not identified those responsible or confirmed links to the earlier French incidents.

CERT-FR advised operators to prevent direct internet access to affected controllers, review configurations and defrost schedules, use secure remote connections, change default passwords, and update firmware. It warned that end-of-life devices without security updates are highly likely to be compromised if left connected to the internet, and that a factory reset alone does not prevent reinfection. Danfoss said most units affected in France in October were older AK-SM 800 and AK-SC 355 models that it no longer updates.

  • The reported incidents could cause immediate physical and financial consequences: one Belgian butcher estimated €15,000 in spoiled meat, while stores in several countries removed chilled or frozen goods as a precaution.
  • A commanded temperature of 50°C did not always mean equipment reached that temperature; at the affected Estonian Selver store, the freezer rose only about 2–3°C before the issue was resolved in roughly 10 minutes.
  • Some affected stores were connected through refrigeration systems outside retailers’ central networks, meaning corporate protections did not necessarily cover the equipment controlling food storage.
  • CERT-FR warned that factory-resetting an end-of-life controller is not a lasting remedy if it remains internet-accessible, because devices without security fixes can be compromised again.
  • The article indicates that securing these installations may require physical changes as well as software updates, according to Sabcobel’s chief executive.

People remotely changed the temperature settings on supermarket refrigerators and freezers in several European countries, causing some units to warm up and forcing stores to remove or throw away food. Affected businesses included chains such as Delhaize, Carrefour, ICA, Coop, SuperValu, and Selver, as well as smaller shops. The incidents show that older refrigeration equipment connected to the internet can create real-world losses and food-safety problems when it is not kept updated and securely connected.

This reports an active, cross-border campaign affecting internet-connected refrigeration controllers at supermarkets and food retailers, with real-world operational and food-loss consequences. MLEP in KICS for Networks 5.0: how machine learning helps track network behavior of OT devices

Kaspersky Industrial CyberSecurity for Networks 5.0 introduces MLEP, a machine-learning component that analyzes industrial network behavior to improve OT asset categorization and flag deviations such as new hosts, protocols, scanning activity, unusual transfer volumes, and atypical operating times.
KEY POINTS
  • 01Kaspersky Industrial CyberSecurity for Networks 5.0 includes the Machine Learning Event Processor (MLEP), which can refine industrial device categories and detect unusual network behavior.
  • 02MLEP represents network sessions as 15-second event fragments containing endpoint, port, direction, protocol, packet-count, and packet-size information rather than storing every packet separately.
  • 03MLEP can use similar recurring communication patterns among known and uncategorized assets to suggest a category for devices whose roles are not identified directly.
  • 04The initial MLEP release includes six preconfigured anomaly monitors for new external hosts, new destination-address-and-port combinations, unusually large outbound data volumes, atypical activity times, new protocols, and activity resembling scanning.
  • 05MLEP alerts are intended to help analysts correlate behavior changes with other events and reconstruct activity around an already detected incident.

Kaspersky Industrial CyberSecurity for Networks 5.0 includes the Machine Learning Event Processor (MLEP), a service designed to refine industrial-device categories and detect unusual network behavior. The article describes how incomplete or outdated asset inventories can make it difficult to distinguish expected industrial communications from suspicious ones. MLEP uses recurring communication patterns to help identify a device’s likely role when direct device information is unavailable.

MLEP converts network sessions into 15-second event fragments that record endpoints, ports, traffic direction, protocols, packet counts, and packet sizes. It compares a device’s current behavior with its observed history and includes preconfigured detections for new external hosts, new destination-and-port combinations, unusually large data transfers, atypical activity times, new protocols, and activity resembling scanning. The resulting alerts are intended to help analysts investigate changes, correlate them with other events and device context, and reconstruct activity around an incident.

  • MLEP can improve an incomplete industrial asset inventory by comparing an unknown device’s recurring communication patterns with devices whose categories are already known, even when direct identifying traffic is unavailable.
  • The system deliberately analyzes 15-second traffic summaries rather than individual packets, which reduces storage and processing needs but prevents it from reconstructing the exact packet order or command contents.
  • MLEP’s anomaly alerts identify changes worth investigating rather than proving malicious activity, so analysts must correlate them with device roles, protocol information, other events, and operational context.
  • Category suggestions are constrained by existing device metadata and rules, but their quality still depends on how much network traffic is visible and how often the device communicates.

The article describes a new feature in Kaspersky’s industrial-network security product that learns how devices normally communicate and uses those patterns to identify unknown equipment and unusual activity. It is aimed at organizations running industrial facilities, where records of connected equipment may be incomplete or outdated. This matters because attackers can use normal-looking connections and approved tools, so changes such as a device contacting a new system, sending far more data, or operating at an unusual time can help investigators find suspicious behavior.

This is a vendor-focused technical overview of MLEP capabilities in Kaspersky Industrial CyberSecurity for Networks 5.0, not a report of a specific incident, vulnerability, or urgent defensive action. It may be useful to OT security practitioners evaluating behavioral network monitoring, but it is evergreen promotional content.
