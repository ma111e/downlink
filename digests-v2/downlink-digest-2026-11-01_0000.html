  • 03The infection chain abuses .NET's AppDomainManager mechanism to load malicious code through a legitimate Patch My PC component and uses layered encoded, compressed, or encrypted payloads.

Kaspersky has detailed NetamLoader, a previously undocumented .NET loading framework discovered in an intrusion targeting a custom Windows 10 build used exclusively by government entities in Asia. The activity has not been attributed to a known threat actor, and Kaspersky identified one victim through telemetry. It is also unknown whether more systems were compromised or whether sensitive data was taken.

The malicious files were contained in a CAB archive placed in a Windows Update-related directory alongside legitimate Patch My PC components. The chain uses .NET application startup settings to load malicious code, then decodes multiple layers of encrypted or compressed files, bypasses Windows antimalware scanning, and ultimately runs a plugin within dllhost.exe. CVSS 10.0 LXD, MicroCloud Flaw Lets Attackers Impersonate Trusted Clients Without a Private Key

Canonical patched CVE-2026-112816, a CVSS 10.0 LXD and MicroCloud flaw that lets network-reachable attackers impersonate trusted mTLS clients using only their public certificates. Update LXD and MicroCloud immediately and restrict HTTPS API access until patched.
KEY POINTS
  • 01CVE-2026-112816 is a CVSS 10.0 flaw in Canonical LXD and MicroCloud that can allow an attacker to impersonate a trusted client without its private key.
  • 02The issue occurs because the server checked every certificate supplied by a client against its trust store, even though the connection proves ownership only of the private key for the first certificate.
  • 03Exploitation requires network access to the HTTPS API and a public certificate for a client that the server already trusts.
  • 04Canonical released fixed LXD versions 6.10.1, 5.21.9, 5.0.11, and 4.0.15, plus MicroCloud versions 3.4.1 and 2.1.5.
  • 05There is no public evidence that the flaw has been exploited, and CISA assessed it as not known to be exploited as of October 30.

Canonical released fixes for CVE-2026-112816, a CVSS 10.0 flaw affecting LXD and MicroCloud. The issue could allow an attacker with network access to the HTTPS API and a trusted client’s public certificate to log in as that client without its private key. If the impersonated client has sufficient privileges, Canonical said the attacker could gain root access to the host machine.

The flaw stems from the server accepting any certificate in a supplied certificate chain that appears in its trust store, although only the first certificate is proven to belong to the connecting client. An attacker could therefore attach a trusted client’s public certificate behind their own certificate and be accepted as that trusted client. Canonical advised updating LXD and MicroCloud, verifying the installed version after refreshing snaps, and restricting network access to the API until patches are in place; there is no public evidence the flaw has been exploited.

  • The impersonation method does not require stealing a trusted client’s private key because its public certificate can be added behind an attacker-controlled certificate in the submitted certificate chain.
  • Standalone LXD installations are not exposed to this risk by default unless an administrator enables the network API with the core.https_address setting.
  • In MicroCloud, someone able to capture a member’s public certificate while it joins the cluster could later log in as that member.
  • There is no configuration-based fix for the issue; restricting access to the network listener is the only temporary risk-reduction step until updates are installed.
  • Because fixed LXD releases were still moving from the candidate channel to stable, administrators should verify the installed version after refreshing the snap.

Canonical fixed a serious flaw in its LXD and MicroCloud software that could let someone pretend to be an approved user without possessing that user’s secret login key. The risk applies to systems whose management interface can be reached over a network, including MicroCloud groups of connected machines. A successful intruder could control the affected virtual machines and, if they impersonate a powerful account, potentially take full control of the underlying computer. Users should install the updated versions and limit network access to the management interface until they do.

  • Following redirect chains to inspect the final page was necessary in this case because the cloned branding, payment request, and service-blocking threat were absent from the email body itself.

An employee at an Israeli real-estate investment company received a Hebrew email pretending to be from mobile carrier Pelephone, asking them to update a payment method. Although the email sounded calm and showed Pelephone’s real web address, its links led through another service to a fake Pelephone payment page that threatened to block the person’s phone line. This matters because scammers can make ordinary-looking messages appear trustworthy while placing the real pressure and payment trap on a website reached after clicking.
