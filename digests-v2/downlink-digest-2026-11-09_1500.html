Attackers are actively exploiting the SSHole vulnerability, CVE-2026-123158, in OpenSSH on certain musl-based Linux systems, including Alpine Linux. The flaw can let an attacker sign in to accounts configured with an asterisk (*) in their password field to prevent password logins. Exploitation attempts began on November 5, when proof-of-concept code became available, and successful exploitation was recorded the following day. OpenSSH fixed the issue in version 10.6p2, released on November 5.

SSHole works because an oversized password can cause musl’s password-hashing function to return an asterisk on error, which OpenSSH incorrectly accepts as matching the account’s stored value. GreyNoise observed attackers performing system and container reconnaissance, querying cloud metadata services, attempting to obtain password hashes and root SSH keys, and modifying authorized_keys files for persistent access. One attacker gained root privileges and installed the TAC Agent command-and-control implant, although it could not reach its server. Administrators should update OpenSSH or disable SSH password authentication, and review systems for unexpected successful password logins to asterisk-marked accounts, unauthorized SSH keys, and TAC Agent files or startup services.

  • The flaw does not affect accounts with valid password hashes; it requires specific authentication settings and targets accounts marked with an asterisk to block password logins.
  • Successful exploitation was recorded roughly 40 hours after the fix was released, highlighting how quickly public exploit code was used in observed intrusions.
  • One observed attacker obtained root access and installed TAC Agent, but the implant failed to contact its command-and-control server and did not receive tasks.
  • GreyNoise’s 27.5 million port-22 scans and 20.1 million attempted SSH sessions are not, by themselves, confirmed SSHole attacks, so raw internet scanning volume should not be treated as proof of compromise.
  • Unexpected successful password logins to accounts whose /etc/shadow password entry is an asterisk are a particularly relevant indicator for investigating this issue.

Hackers are using a flaw called SSHole in a commonly used way to remotely access Linux computers, especially some systems using Alpine Linux and similar lightweight software. The flaw can let them sign in to accounts that were supposed to be blocked from password access, then run commands, look for passwords and secret access keys, and try to keep access for later. This matters because affected cloud and virtual systems can be taken over, sometimes all the way to their most powerful administrator account, unless their OpenSSH software is updated or password sign-ins are turned off.
