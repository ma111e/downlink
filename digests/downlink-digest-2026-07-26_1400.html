In plain words

GitHub and PyPI are adding waiting periods before some software updates can spread: GitHub’s Dependabot will wait three days before suggesting new package versions, and PyPI will stop people from adding new files to a release after 14 days. This affects software maintainers and developers who rely on these services to publish or update code. It matters because attackers have recently used popular software packages to spread harmful code, and these delays give security tools and maintainers more time to catch problems before many projects copy the bad code.

Summary
GitHub and PyPI are adding time-based safeguards to reduce supply-chain risk: Dependabot now waits 72 hours before suggesting new dependency updates, and PyPI blocks adding files to releases after 14 days. The goal is to limit how quickly malicious or compromised packages can spread before detection and cleanup.

GitHub and PyPI have introduced time-based defenses meant to reduce supply-chain attacks and limit their impact. Dependabot now has a default three-day cooldown before issuing dependency update pull requests, while PyPI now rejects new files uploaded to releases older than 14 days. The measures follow multiple high-profile attacks affecting development ecosystems over the past year, including the chalk and debug attacks, s1ngularity, Shai-Hulud, and GhostAction.

GitHub said Dependabot’s 72-hour delay is intended to reduce the risk of projects automatically adopting newly published malicious packages. The company said many recent malicious npm packages were detected and flagged within minutes, but maintainers and vendors still needed time to remove them. GitHub chose three days as a balance between avoiding risky releases and keeping up with upgrades, and users can configure the cooldown to be shorter or longer.

PyPI’s 14-day cutoff is designed to stop attackers who compromise publishing tokens or workflows from adding malicious files to old, trusted releases. PyPI said only a very small percentage of projects legitimately uploaded files more than two weeks after publishing a release. The article notes that no known past PyPI attacks have been confirmed to use this release poisoning technique, but PyPI is acting preventatively to block the possibility.

  • GitHub chose a 72-hour Dependabot cooldown because recent malicious npm packages were often detected within minutes, but the remaining risk came from the time needed for maintainers and vendors to remove them.
  • Dependabot’s cooldown is not a complete defense against longer-term package compromise, so GitHub still recommends lockfiles, restricted-scope tokens, and disabling unnecessary installation scripts in CI.
  • PyPI’s 14-day cutoff is preventive rather than reactive, since the article says no confirmed past PyPI attacks have used the release-poisoning technique it blocks.
  • PyPI found that only a very small percentage of projects legitimately uploaded files more than two weeks after publishing a release, which made the cutoff less disruptive.
