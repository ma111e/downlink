In plain words

CISA, a U.S. government cybersecurity agency, warned that attackers are already using a serious flaw in Microsoft SharePoint Server, a product many organizations run on their own networks. The affected versions are SharePoint Server Subscription Edition, 2019, and 2016, and U.S. federal civilian agencies must install Microsoft’s fixes by July 19, 2026. This matters because the flaw can let an attacker run their own code on a SharePoint server, steal important server keys, stay inside the system, and install harmful software.

Summary
CISA added a newly patched Microsoft SharePoint Server zero-day, CVE-2026-58644, to its Known Exploited Vulnerabilities catalog after confirming active exploitation, requiring U.S. federal agencies to patch by July 19, 2026. Organizations running on-premises SharePoint should urgently apply updates, verify defenses like AMSI, and check for signs of compromise.

CISA added a newly patched Microsoft SharePoint Server vulnerability, CVE-2026-58644, to its Known Exploited Vulnerabilities catalog. Federal Civilian Executive Branch agencies are required to apply the fixes by July 19, 2026. Microsoft revised its bulletin to clarify that the flaw has been exploited in the wild, meaning it was used as a zero-day before patches were available.

CVE-2026-58644 is a critical deserialization of untrusted data vulnerability with a CVSS score of 9.8. Microsoft said that, in a network-based attack, an attacker authenticated as at least a Site Owner could write arbitrary code to inject and execute code remotely on the SharePoint Server. The flaw affects Microsoft SharePoint Server Subscription Edition, Microsoft SharePoint Server 2019, and Microsoft SharePoint Enterprise Server 2016.

CISA also warned of active exploitation of multiple SharePoint Server vulnerabilities, including CVE-2026-32201, CVE-2026-45659, CVE-2026-56164, and CVE-2026-58644, that could allow unauthorized access to on-premises instances. The agency said the activity can involve remote code execution and post-exploitation actions such as stealing IIS machine keys, using deserialization techniques for persistence, and deploying malware. CISA recommended applying Microsoft updates, verifying AMSI integration, removing intrusion artifacts before rotating IIS machine keys, improving logging, limiting internet exposure, and restricting access to SharePoint Central Administration.

  • CISA’s July 19, 2026 deadline gives federal agencies only a few days from the July 14 Patch Tuesday release to remediate CVE-2026-58644, reflecting the urgency created by confirmed exploitation before fixes were available.
  • CISA specifically advises removing intrusion artifacts before rotating IIS machine keys, because rotating keys while harvesting tools remain present could allow attackers to steal the new keys as well.
  • The SharePoint hardening guidance goes beyond patching by recommending reduced internet exposure, blocked external access to Central Administration, and restricted farm and database communications, indicating that configuration changes are part of the immediate containment strategy.
  • Microsoft revised its bulletin after release to clarify that CVE-2026-58644 had been exploited in the wild, meaning organizations relying only on the original Patch Tuesday context may have underestimated the urgency of the update.

  • 02CVE-2026-58644 is a critical deserialization of untrusted data vulnerability with a CVSS score of 9.8 that allows an unauthorized attacker to execute arbitrary code.
  • 03Microsoft said the vulnerability can be exploited remotely over the internet and has low attack complexity because attackers need no significant prior system knowledge and can repeatedly succeed with a payload against the vulnerable component.
  • 04The vulnerability affects Microsoft SharePoint Server Subscription Edition, Microsoft SharePoint Server 2019, and Microsoft SharePoint Enterprise Server 2016.
  • 05CISA warned that multiple SharePoint Server vulnerabilities, including CVE-2026-58644, are being actively exploited to gain unauthorized access to on-premises instances and support post-exploitation activity such as stealing IIS machine keys and deploying malware.

In plain words

The U.S. Cybersecurity and Infrastructure Security Agency says attackers are already using two serious weaknesses in Fortinet’s FortiSandbox threat detection platform, and it has ordered federal agencies to fix affected systems by July 19. Fortinet has released updates, and administrators are told to upgrade because the flaws can let outsiders run their own commands on vulnerable systems without needing a password or any action from a user. This matters because Fortinet weaknesses have often been used in spying campaigns and ransomware attacks, and CISA tracks 28 Fortinet flaws that have been exploited in recent years.

Summary
CISA says two critical Fortinet FortiSandbox flaws are being actively exploited and has ordered U.S. federal agencies to patch affected systems by July 19. The vulnerabilities allow unauthenticated remote code execution via command injection, so admins should upgrade immediately.

CISA ordered U.S. government agencies to prioritize patching two actively exploited critical vulnerabilities in Fortinet’s FortiSandbox threat detection platform. The flaws are tracked as CVE-2026-39808 and CVE-2026-25089, and Fortinet addressed them on April 14 and June 9, respectively. CISA added both vulnerabilities to its Known Exploited Vulnerabilities catalog and requires federal agencies to patch vulnerable FortiSandbox instances by Sunday, July 19.

Fortinet’s advisories said successful exploitation allows unauthenticated threat actors to remotely execute unauthorized code through low-complexity command injection attacks that require no user interaction. Administrators must upgrade affected deployments to the latest released versions to resolve the issues and block incoming attacks. Fortinet has not yet tagged the two vulnerabilities as used in attacks, and it had not replied to BleepingComputer’s emails about in-the-wild exploitation.

Threat intelligence company Defused reported on June 16 that attackers had started abusing multiple Fortinet FortiSandbox vulnerabilities, including CVE-2026-39808 and CVE-2026-25089. The article also notes other Fortinet flaws patched earlier in the year that were reported as exploited, including a FortiClient EMS SQL injection vulnerability and a path traversal vulnerability. CISA tracks 28 Fortinet vulnerabilities exploited in attacks in recent years, 13 of which have also been abused in ransomware attacks.

  • CISA’s emergency patch deadline leaves federal agencies only a few days to remediate, reflecting the urgency assigned once the flaws were added to the Known Exploited Vulnerabilities catalog.
  • The article highlights a gap between Fortinet’s public advisories and external exploitation reports, noting that Fortinet had not yet labeled the two flaws as exploited even after Defused and CISA reported in-the-wild activity.
  • Defused reported exploitation of an additional FortiSandbox issue, CVE-2026-39813, but CISA’s action in this article only covers CVE-2026-39808 and CVE-2026-25089.
  • Fortinet products have a substantial history of real-world abuse, with CISA tracking 28 exploited Fortinet vulnerabilities in recent years and 13 also used in ransomware attacks.
