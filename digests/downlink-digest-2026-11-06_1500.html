The risk affects WordPress versions 4.7 through 7.1.3, especially sites that download a full update package, because a temporary copy of the site software may be reachable online before it is removed. Summary

Administrators should block web access to wp-content/upgrade before updating to WordPress 7.1.4 or the applicable supported branch fix.

WordPress released fixes for CVE-2026-119977 in version 7.1.4 and supported older branches, but some sites can still be exposed while applying the update. The flaw affects WordPress 4.7 through 7.1.3 and has been added to CISA’s catalog of known exploited vulnerabilities. Researchers and Wordfence observed evidence of attack activity intended to catch sites during their update windows.

During an affected core update, the old WordPress updater can unpack a temporary copy of WordPress in the web-accessible wp-content/upgrade directory before the patched code takes effect. On sites running 5.9 or later, the old code can use a predictable temporary folder name, potentially allowing an unauthenticated attacker to reach the installer and run code with the web server’s permissions. Umut Bayram recommends blocking web access to wp-content/upgrade before updating, or manually updating outside the web root; WP-CLI does not avoid the issue because it uses the same updater.

  • Installing a security fix can itself create a brief exposure window because the update initially uses the site's old updater code rather than the newly patched code.
  • Whether an update is exposed is not simply determined by whether it is partial or complete; the relevant question is whether the package contains installer files and whether the updater already on the site has been fixed.
  • Blocking web access to wp-content/upgrade does not prevent WordPress from updating because WordPress accesses that folder directly on the server's disk.
  • Using WP-CLI does not avoid this issue because its wp core update command uses the same updater and temporary folder.
  • An .htaccess rule placed inside wp-content/upgrade is ineffective because the old updater deletes that folder's contents before unpacking the update.
