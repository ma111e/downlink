In plain words

Metabase, a tool companies use to view and analyze business data, warned that attackers were already using a serious flaw to get administrator access without logging in. This affects people and organizations running their own Metabase versions 1.58 and above that have not been updated, while Metabase Cloud has already been fixed. With administrator access, attackers could change settings, steal saved database passwords, read connected data, and export it; Framework said customer names, contact details, addresses, and login IPs were accessed in the hack.

Summary
Metabase disclosed a maximum-severity zero-day affecting versions 1.58 and later that was exploited to gain unauthenticated admin access via SQL injection. Self-hosted users should patch immediately, block the password reset endpoint as a workaround, and check logs for the listed compromise pattern.

Metabase warned that a maximum-severity security flaw affecting its business intelligence and data visualization software has been exploited in the wild as a zero-day. The vulnerability has a CVSS score of 10.0 and does not have a CVE identifier. It allows an unauthenticated remote attacker to inject arbitrary SQL into the Metabase application database and gain administrator access to the instance.

With administrator access, an attacker can change the application configuration, steal stored credentials for connected databases, read any data available through those connections, and export data. Metabase said its Cloud instances have already been updated to the latest version. Users running self-hosted versions are advised to apply the security patches immediately.

The affected releases include versions from x.58.0 through vulnerable builds in the x.63 line, with fixed versions released for each supported branch listed in the article. As a temporary workaround, Metabase advised blocking the “/api/session/reset_password” endpoint until fixes can be applied. Metabase also shared indicators of compromise involving a 400 response to “POST /api/session/reset_password” followed by a 200 response to “GET /api/user/current,” and said this pattern likely indicates compromise.

  • A likely compromise can be identified by a specific log pattern: a 400 response to “POST /api/session/reset_password” followed by a 200 response to “GET /api/user/current.”
  • Metabase recommends more than patching for exposed instances, including deleting all active sessions from the core_session table, reviewing API keys and administrator accounts, rotating connected database credentials, and checking data warehouse and Metabase activity logs.
  • The vulnerable path involves the password reset endpoint, so Metabase recommends blocking “/api/session/reset_password” as a temporary workaround until affected self-hosted instances can be updated.
  • The flaw does not yet have a CVE identifier despite being rated CVSS 10.0 and already being exploited in the wild.

  • 02The flaw has a CVSS score of 10.0, does not have a CVE identifier, and allows an unauthenticated remote attacker to inject arbitrary SQL into the Metabase application database to gain administrator access.
  • 03Metabase said the issue affects versions 1.58 and above, and it released fixed versions for the x.58 through x.63 release lines while Metabase Cloud instances have already been updated.
  • 04Metabase advised self-hosted users to apply patches immediately or temporarily block the “/api/session/reset_password” endpoint until fixes can be applied.

This matters because N-central is used to manage other computers, so attackers who get in can reach those managed systems and even set up a way to stay connected after their original access is removed.

Summary

N-able said a limited number of customers have been affected by the exploitation activity. Customers running on-premise versions are advised to update their instances to 2026.3.1.10 immediately. The U.S. cybersecurity agency CISA added a serious flaw in Progress Kemp LoadMaster devices to its list of problems that are being used by attackers. The flaw could let someone with no valid login run commands on an affected device, and 792 attempts to use it were reported from 65 internet addresses in 18 countries. U.S. federal civilian agencies are being told to install fixes by August 10, 2026, because affected devices could otherwise be taken over and put networks at risk.

Summary
CISA added the critical Progress Kemp LoadMaster command injection flaw CVE-2026-8037 to its Known Exploited Vulnerabilities catalog after hundreds of exploitation attempts were observed. Federal agencies have been directed to patch affected appliances by August 10, 2026.

CISA added a critical-severity security flaw affecting Progress Kemp LoadMaster to its Known Exploited Vulnerabilities catalog after reports of active exploitation in the wild. The flaw is tracked as CVE-2026-8037 and has a CVSS score of 9.6. CISA said the issue allows an unauthenticated attacker to execute arbitrary commands on a LoadMaster appliance by exploiting unsanitized input in multiple command endpoints.

watchTowr Labs described the issue as present in a function named escape_quotes() within the load balancer application. Its analysis said the flaw stemmed from improper handling of user-supplied input, enabling command injection. Successful exploitation can allow an attacker to run arbitrary commands on an affected appliance without valid credentials.

eSentire previously reported active exploitation efforts targeting the flaw, though it said those efforts were largely unsuccessful. KEVIntel telemetry recorded 792 exploitation attempts over 41 days from 65 unique IP addresses in 18 countries, with the last activity recorded on August 4, 2026. Federal Civilian Executive Branch agencies are recommended to apply the necessary patches by August 10, 2026, in accordance with Binding Operational Directive 26-04.

  • The flaw does not require valid credentials to exploit, which makes exposed LoadMaster appliances especially urgent to patch or otherwise protect.
  • Although eSentire said the observed exploitation efforts were largely unsuccessful, CISA still added the flaw to the KEV catalog, indicating that unsuccessful attempts were enough to trigger federal remediation requirements.
  • The exploitation activity appears geographically distributed, with attempts coming from 65 unique IP addresses across 18 countries rather than from only a small number of sources.
  • Federal Civilian Executive Branch agencies were given only until August 10, 2026 to apply patches, showing that CISA treated the issue as requiring rapid remediation after the KEV listing.

In plain words

Researchers found that the design code inside an email can sometimes break out of the message area and interfere with the webmail page around it. Tests affected services including Outlook, Gmail, Fastmail, Proton Mail, Yahoo Mail, and AOL Mail, with examples that could capture a typed password, reveal login tokens, redirect clicks, or trick AI tools that read email. This matters because a message that looks like ordinary email content could be used to steal access to accounts or sensitive information if webmail providers do not better isolate and limit what emails can do.

Summary
PortSwigger research shows that allowed HTML/CSS in major webmail services can escape email boundaries to spoof login screens, leak tokens, hijack UI actions, and manipulate AI email tools. The key defense is stricter isolation of email content, especially sandboxed iframes and tighter CSS and resource-request controls.

PortSwigger researcher Gareth Heyes presented research at Black Hat USA 2026 showing that content inside an email can escape its message boundary and interfere with the surrounding webmail interface. The attack chains span Outlook, Gmail, Fastmail, Proton Mail, Yahoo Mail, and AOL Mail. The techniques can capture passwords, take over third-party accounts, leak tokens, hijack trusted UI actions, and manipulate AI tools that read email. The paper presents proof-of-concept research and does not report malicious exploitation.

The research follows two paths: abusing HTML and CSS already allowed by webmail services, or creating a discrepancy between what a sanitizer approves and what the browser or application ultimately creates. Demonstrations included an Outlook and Firefox chain that spoofed a Microsoft sign-in screen, a Yahoo and AOL paste race that could expose a Medium email-login token, and a Gmail and Claude Cowork chain that could leak a Slack token after prompt injection and user interaction. The researcher said Fastmail fixed two CSS mutation bugs and a Proton Mail proxy bypass stopped working on retest, while Outlook label-jacking and Gmail’s image-set() bypass still worked when the research was published. The paper recommends isolating HTML email in sandboxed iframes and tightly restricting CSS, custom attributes, select menus, and image requests.

  • The research shows that dangerous behavior can arise not only from HTML and CSS that webmail services already allow, but also from mismatches between what a sanitizer approves and what the browser or application later creates.
  • Some attack paths worked around common defenses in unexpected ways, including a Gmail image-set() fallback that still made an external request despite sanitization and a click-based exfiltration method for cases where CSP blocks external resources.
  • The Outlook chain depended on several separate behaviors combining, including labels triggering controls outside the message, application JavaScript creating new DOM nodes from sanitized custom attributes, and a Firefox select-menu timing behavior enabling real-time capture.
  • AI-connected email expanded the impact of email content because hidden or injected instructions could influence tools such as Claude Cowork and OpenAI Atlas after they processed or interpreted messages.
  • Fix status varied across providers and techniques, with Fastmail fixing two CSS mutation bugs and a Proton Mail proxy bypass no longer working on retest, while Outlook label-jacking and Gmail's image-set() bypass still worked when the research was published.
Key Points

Atlassian fixed one version involving a specially crafted link, but another version hidden inside content Rovo reads was still reported as unresolved when it was published. The real-world concern is that a helpful workplace assistant can become a way for private company information to leave the organization.

Summary
Researchers found Atlassian Rovo could be manipulated into exfiltrating Jira and Confluence data accessible to a signed-in user through prompt-injection techniques. Atlassian has fixed the one-click Rovo URL flaw, but the separate content-borne exfiltration path was reported as still unresolved as of August 5, 2026.

Atlassian’s Rovo assistant was found to be susceptible to attacker-controlled instructions that could make it collect Jira or Confluence data accessible to a signed-in user and send that data to an outside server. PromptArmor and Varonis Threat Labs found this behavior independently through different routes. The article says only one of those routes is confirmed closed.

PromptArmor hid instructions in content that Rovo reads, such as an uploaded file, and said Rovo could gather internal Jira and Confluence data and exfiltrate it through a URL request without a separate approval step. The firm said the chain still worked when Rovo’s web-search option was disabled, because the outbound request used a separate URL-retrieval capability. PromptArmor said it disclosed the issue to Atlassian on May 23, 2026, and published on August 5 after what it described as no further communication.

Varonis Threat Labs found a separate one-click flaw in the rovoChatPrompt URL parameter, which could preload attacker instructions into Rovo Chat for an authenticated user. Bugcrowd’s disclosure record says Atlassian fixed that issue server-side on July 8, 2026, and the reporter validated the fix. The article says Rovo’s access follows the signed-in user’s permissions across Atlassian products and connected third-party apps, so the risk involves data that user can already reach rather than a demonstrated tenant-wide authorization bypass.

  • Disabling Rovo’s web-search option should not be treated as a complete security boundary, because PromptArmor reported that its exfiltration chain used a separate URL-retrieval capability even when web search was off.
  • There is no customer patch for either issue described: the one-click link flaw was fixed server-side by Atlassian, while the remaining lever for the content-borne path is controlling which apps and groups can use Rovo.
  • The practical impact depends heavily on ordinary user permissions and connector scope, because Rovo can reach data through Atlassian products and connected third-party apps that the signed-in user is already allowed to access.
  • The two disclosures do not prove the same problem was fixed, because the confirmed July 8 server-side fix applies to the rovoChatPrompt link flaw, while PromptArmor’s later report described a separate content-borne route as still working when published.
