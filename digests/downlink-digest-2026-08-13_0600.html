In plain words

Attackers have started using a newly public example attack against Microsoft SharePoint, a Microsoft system many organizations use to manage websites and files. The flaw can let someone who is not logged in pretend to be a normal user or even an administrator on a vulnerable SharePoint server, which could let them view files or change data. Microsoft fixed the issue in its July 2026 updates, so organizations that run SharePoint are affected if they have not updated.

Summary
Attackers are actively exploiting CVE-2026-55040, a critical Microsoft SharePoint authentication bypass, after Rapid7 released public PoC code. Organizations should urgently apply Microsoft’s July 2026 patches to prevent unauthenticated attackers from impersonating SharePoint users or administrators.

Threat actors have begun exploiting CVE-2026-55040, a critical Microsoft SharePoint security feature bypass vulnerability, after the release of public proof-of-concept code. Microsoft patched the flaw in its July 2026 Patch Tuesday updates and said it stems from weak authentication that allows impersonation. Successful exploitation can allow an attacker to disclose files and modify data, though Microsoft said it cannot affect system availability.

Rapid7 said the vulnerability is caused by several issues in the JWT token validation pipeline for Bearer service-to-service tokens. The attack chain allows an unauthenticated remote attacker to forge a valid JWT and impersonate any SharePoint site user, including an administrator. Rapid7’s Python-based proof of concept uses the forged token to query a target’s domain controller, enumerate users by SID, and locate a site administrator.

KEVIntel telemetry recorded 12 exploitation attempts since July 19, 2026, with eight occurring on August 12 and 13 after the PoC release. The attempts originated from eight unique IP addresses across Hong Kong, Japan, the Netherlands, Taiwan, and the U.S. The article says it is unclear who is behind the exploitation activity or what their goals are, and advises SharePoint users to keep their instances up to date.

  • The exploitation timeline shows a clear increase immediately after the public PoC release, with eight of the 12 recorded attempts occurring on August 12 and 13.
  • The vulnerability does not require stealing a real user’s credentials because the attack chain allows an unauthenticated attacker to forge a valid JWT and impersonate any SharePoint site user.
  • The PoC is designed to help identify a site administrator by querying the target’s domain controller and enumerating users by SID, which makes administrator impersonation a practical attack path.
  • Although Microsoft said the flaw cannot affect system availability, successful exploitation can still expose files and allow data modification, making patching urgent for confidentiality and integrity reasons.

In plain words

The article explains a serious flaw in Adobe Commerce and Magento Open Source, software used to run online stores, that can let someone without a login switch into a real customer’s account. This affects public storefronts on certain versions, including not only main shopping sites but also staging, campaign, and older sites that companies may have forgotten about. In the real world, this matters because attackers could see customers’ personal information and order history, and many businesses may not know all the store sites they need to fix.

Summary
CVE-2026-71362 is a critical Adobe Commerce and Magento Open Source authorization flaw that can let unauthenticated attackers take over customer sessions on public storefronts. Adobe has released fixes, and organizations should urgently inventory and patch all production and non-production stores while monitoring for exploitation.

CVE-2026-71362 is a critical incorrect authorization vulnerability in Adobe Commerce and Magento Open Source with a CVSS v3.1 score of 9.1. The article says the flaw is caused by the platform failing to correctly bind a customer identity to an account session. Exploitation requires no authentication, no administrator privileges, and no user interaction, with network access to a public storefront as the only precondition.

Sansec’s patch analysis found that the issue can allow an attacker to switch an active session to a different customer account, giving the attacker that customer’s authenticated context, including stored personal data and order history. Adobe says it is not aware of exploits in the wild for the issues in the release, while Sansec reports that its Shield web application firewall is already blocking exploitation attempts against this CVE. The article says defenders should assume attack traffic exists and verify patch level and exposure against their own hosts and vendors.

Affected assets include Adobe Commerce 2.4.4 through 2.4.9 and Magento Open Source 2.4.6 through 2.4.9 at the -2026-jul build and earlier, with fixes issued in Adobe bulletin APSB26-92 on August 11, 2026. The article emphasizes that exposed assets may include staging, preproduction, UAT, developer, and campaign storefronts, not just primary commerce domains. Recommended actions include inventorying all Adobe Commerce and Magento hosts, deploying WAF coverage, invalidating active customer sessions after fixing, monitoring logs for account or session switching, and scanning previously exposed stores for backdoors.

  • The article highlights a conflict between Adobe’s statement that it is not aware of in-the-wild exploitation and Sansec’s report that its Shield WAF is already blocking exploitation attempts, so defenders should verify exposure directly rather than relying only on the vendor advisory.
  • Remediation may take longer for stores that are not already on the latest supported point release because Adobe distributes the fixes as isolated patch files that require the latest -p release for the branch before they can be applied.
  • The article emphasizes that exposure is often concentrated in forgotten or externally managed storefronts, such as staging, preproduction, UAT, developer, and campaign sites, rather than only primary production commerce domains.
  • CyCognito’s observed exposure data found Communication Services leading with 34.5% of identified assets, which the article ties to media and entertainment groups running many separate merchandise, ticketing, licensing, and promotional storefronts with different owners and patch cadences.

Armored Likho expands its cyber-espionage toolkit

In plain words

Researchers found a new spying campaign by the Armored Likho group that uses a fake donation app to trick people and organizations in Russia. Once installed, the tools can steal Telegram access data so attackers can read chats and download files, and can also secretly record conversations through the computer’s microphone. The affected targets include private individuals, major companies, government bodies, IT, and education, making this a serious privacy and intelligence-gathering threat.

Summary
Kaspersky researchers uncovered a new Armored Likho cyber-espionage campaign targeting Russia that uses a fake donation app to deploy the Rust-based Still Toolkit. Its new modules steal Telegram session data and perform covert audio surveillance, showing the group is expanding into a more cohesive and capable spying toolset.

In May 2026, Kaspersky discovered a new cyber-espionage campaign by Armored Likho, also known as Eagle Werewolf, targeting private individuals and organizations in Russia. The affected sectors include major corporations, the public sector, IT, and education. The campaign begins with a fake donation service app that appears legitimate while secretly decrypting and launching the next-stage payload.

The most significant finding is the Still Toolkit, a new Rust-based cyber-espionage toolkit made up of Still Sync and Still Audio. Still Sync steals Telegram session data and can use it to access the victim’s Telegram account through the Telegram API, collecting chats, media files, user details, and information about private chats, groups, and channels. Still Audio is an audio surveillance implant that detects speech, records conversations, encodes the recordings, and sends them to a command-and-control server.

Kaspersky attributes the campaign to Armored Likho with high confidence based on overlaps with earlier campaigns, including matching dropper architecture, shared sysmarker generation logic, reuse of an encryption algorithm and key, and similar infrastructure patterns. The attackers use domains and hosting providers that differ from the February campaign but follow similar naming patterns that mimic Windows system services and update mechanisms. Kaspersky says the new tools show the group is expanding its cyber-espionage capabilities into a cohesive tool ecosystem designed for long-term use and further expansion.

  • Still Sync does not perform malicious actions until it successfully registers with its command-and-control server and retrieves settings, meaning its behavior can depend on live server-side configuration rather than only what is embedded in the sample.
  • Still Sync uses multiple fallback methods to access Telegram files, including abusing SeBackupPrivilege, Shadow Copy, and Robocopy in backup mode, which shows the operators designed it to keep collecting data even when normal file access fails.
  • Still Audio uses a GitHub-hosted dead drop as a fallback for command-and-control information after three days of server unreachability, using the same Blowfish ECB encryption algorithm and key previously seen in AquilaRAT.
  • The audio implant does not fully hide its microphone use from Windows settings; in the analyzed sample, IntAudio.exe appeared as “Intel Audio” in the list of apps using the microphone.
  • The attackers’ infrastructure avoids direct domain and IP overlap with the February campaign but still reuses hosting-provider choices and Windows-service-like domain naming patterns, which Kaspersky cites as part of the attribution picture.
Key Points
  • 01Kaspersky discovered a May 2026 cyber-espionage campaign by Armored Likho, also known as Eagle Werewolf, targeting private individuals and organizations in Russia, including major corporations, the public sector, IT, and education.
  • 02The campaign starts with a fake donation service app built in Rust with the Tauri framework, which displays a legitimate-looking catalog while quietly decrypting and launching the next-stage payload.
  • 03The newly identified Still Toolkit includes Still Sync, a Rust-based tool that steals Telegram session data and can use it to pull chat logs, media files, user details, and information about chats, groups, and channels through the Telegram API.
  • 04The Still Toolkit also includes Still Audio, a Rust-based audio surveillance implant that detects speech, records conversations, encodes recordings with libmp3lame, and sends them to a command-and-control server.
  • 05Kaspersky attributes the campaign to Armored Likho based on overlaps with earlier campaigns, including identical dropper architecture, matching sysmarker generation logic, shared encryption algorithm and key, and similar infrastructure patterns.
