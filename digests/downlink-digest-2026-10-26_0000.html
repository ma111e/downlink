Cloudflare disclosed a tenant-isolation issue in its GLM-5.3 Workers AI model that caused some customers to receive responses containing data from other customers’ recent requests. The exposure was present from the model’s August 27, 2026 launch until Cloudflare disabled it on September 9, and it affected 155 responses to prompts longer than 681,280 tokens.   • Increasing cache capacity prevented valid requests from reaching the faulty rejection path, but Cloudflare also patched SGLang because future configuration changes could recreate the same unsafe condition.
  • Cloudflare’s broader hardening addresses cases where a cancelled request can still be writing data into memory later assigned to another request, showing that safe cleanup must be coordinated across both parts of the AI serving system.
  • Cloudflare is pursuing checks that verify a request owns each memory page before it is used, aiming to stop an affected request instead of returning another user’s data.
