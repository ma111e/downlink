In plain words

The article warns about a serious flaw in software used to unpack Brotli-compressed data, affecting some versions of .NET, Node.js, and other software platforms. A specially made compressed file or web request could cause an unpatched application to reveal data, crash, or potentially let an attacker take control. It is especially relevant to web applications that accept Brotli-compressed requests, automatically unpack responses from other services, or process untrusted compressed uploads. Fixes are available, and organizations should update affected software or temporarily stop accepting Brotli-compressed data.

Summary
CVE-2026-111497 is a critical out-of-bounds write in the Google Brotli decoder that can corrupt memory when untrusted Brotli data is decompressed, affecting unpatched .NET, Node.js, and other runtimes. Organizations should urgently update .NET to 8.0.33, 9.0.22, 10.0.14, or 11 RC3 and disable Brotli decompression paths where patching is not yet complete.

CVE-2026-111497 is an out-of-bounds write flaw in the Google Brotli decoder used by .NET, Node.js, and other runtimes. A crafted Brotli stream can cause an unpatched decoder to write beyond its buffer and corrupt adjacent memory. The resulting impact can include information disclosure, denial of service, or potentially code execution, and CISA added the issue to its Known Exploited Vulnerabilities catalog on 27 October 2026.

In .NET, an attacker must be able to make an application decompress Brotli data they control, such as through ASP.NET Core request decompression, HttpClient automatic response decompression, or direct use of BrotliStream or BrotliDecoder. These paths are not enabled by default, and .NET Framework is not affected. Microsoft released updates for .NET 8.0.33, 9.0.22, 10.0.14, and 11 RC3; until updates are fully deployed, organizations can remove Brotli decompression settings or reject Content-Encoding: br requests at a reverse proxy or load balancer.

  • In .NET, exposure depends on configuration rather than default behavior: request decompression, HttpClient Brotli response decompression, and direct Brotli decoding are not enabled by default.
  • External scans can identify ASP.NET Core or Kestrel systems but cannot determine whether Brotli request decompression is enabled, so organizations must verify the relevant settings internally.
  • Self-contained, NativeAOT, and containerized .NET applications require rebuilding and redeploying with patched runtime components, rather than relying only on a host runtime update.
  • Although reliable code execution has been demonstrated against Node.js in a controlled environment, no .NET-specific exploitation has been published, and crashes remain reproducible on unpatched decoders.
  • A temporary mitigation is to reject Brotli-compressed HTTP request bodies at a reverse proxy or load balancer while updates are being deployed.
Key Points
  • 01CVE-2026-111497 is an out-of-bounds write flaw in the Google Brotli decompression library that can allow memory reading or corruption through a crafted Brotli stream.
  • 02The issue affects unpatched .NET 8, 9, 10, and pre-RC3 .NET 11 releases when applications decompress attacker-controlled Brotli data, while .NET Framework is not affected.
  • 03Microsoft released fixes in .NET 8.0.33, 9.0.22, 10.0.14, and 11 RC3 on 25 October 2026.
  • 04CISA added CVE-2026-111497 to its Known Exploited Vulnerabilities catalog on 27 October 2026, with reported exploitation so far focused on Node.js.
  • 05Organizations should update affected runtimes and, until patching is complete, remove or block Brotli decompression for untrusted requests, HTTP responses, and application inputs.

JUSTIFICATION

Security professionals should assess exposed .NET, Node.js, and other affected runtime deployments immediately and apply available fixes or mitigations.
