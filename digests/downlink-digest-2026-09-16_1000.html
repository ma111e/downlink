Varonis Threat Labs demonstrated TrustSink, a credential-phishing technique that turns a trusted Microsoft Entra External Authentication Method provider into a persistent password-capture mechanism. An attacker with a Global Administrator or Authentication Policy Administrator role can register a rogue provider that presents users with a convincing Microsoft-style password page during a normal MFA sign-in flow. The provider records the password in plaintext, then returns a valid signed token so the user reaches the intended application without an error.

The proof of concept used a minimal FastAPI OpenID Connect server that supplied Entra with a discovery document and public signing key, redirected users to a fake password page, and posted a signed response back to Microsoft. Resetting a user’s password alone does not remove the threat because the rogue provider can capture the replacement password at the next sign-in. Defenders should monitor Authentication Methods Policy changes, newly created related applications and service principals, unfamiliar external-provider issuers in sign-in logs, and remove unauthorized providers before resetting affected credentials.

  • Microsoft Entra accepted tokens signed by the rogue provider’s self-generated key as long as the key ID and signature matched, without validating a certificate chain or the key’s origin.
  • The phishing page appears after users have already entered their real password on Microsoft’s site, making a second password request seem plausible within the same sign-in process.
  • An unfamiliar external-provider issuer reporting hardware-key claims such as "amr: [hwk]" is a particularly reliable sign-in-log indicator because the provider cannot avoid identifying itself there.
  • Registering the external method unexpectedly added a FIDO key to the test user’s SearchableDeviceKey property, creating an additional artifact defenders can investigate.
  • Automated deployment created an application, service principal, and delegated permission grant within seconds of one another, providing a correlated audit trail even though the tool’s user-agent string can be changed.
