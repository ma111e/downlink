Hotel Wi-Fi attacks use custom malware to breach Microsoft 365 accounts
bleepingcomputer.com · 04 Aug 2026 00:17 UTC openai-codex / gpt-5.5
TAGSandroidapt29chocoshellclickfixcornflakedevice-code-phishingdns-hijackingfruitstonemicrosoftmicrosoft-365microsoft-entra-idmidnight-blizzardoauth-code-phishingrussiastorm-2945

In plain words

Microsoft says a Russian-linked hacking group has been tampering with hotel and conference center Wi-Fi sign-in systems so travelers can be sent to fake Microsoft 365 sign-in pages or fake update pages. People using these public networks could have their work accounts stolen or unknowingly install harmful software that can watch what they do, steal files, and capture passwords. This matters because business travelers often rely on hotel Wi-Fi, and a stolen Microsoft 365 account can give attackers access to work email, documents, and other company information.

Summary
Microsoft says Russia-linked Midnight Blizzard is hijacking hotel and conference Wi-Fi networks to redirect travelers to fake Microsoft 365 login or update pages, stealing credentials and deploying custom malware. Users should treat public captive-portal Wi-Fi as untrusted and avoid entering corporate credentials or installing updates prompted through these networks.

Microsoft has linked a global campaign targeting hospitality Wi-Fi networks to the Russian threat actor Midnight Blizzard, also known as APT29. Microsoft tracks the activity as CaptiveCrunch and attributes it to Storm-2945, a sub-cluster of Midnight Blizzard. The campaign targets travelers using hotel and conference center Wi-Fi networks and has been active since at least early May, while related device and OAuth code phishing operations have been running since February.

The attackers manipulate DNS and HTTP traffic on networks served by captive portal equipment, allowing them to intercept user connections. After changing DNS settings, they can redirect victims to fake Microsoft 365 login pages, device code phishing pages that abuse Microsoft Entra ID authentication flows, or fake browser and operating system update pages. Microsoft also found evidence on some ClickFix landing pages suggesting Android devices may be targeted with an APK file.

Microsoft identified two Windows malware families used in the campaign, CornFlake and ChocoShell. CornFlake is a Go-based remote access trojan with capabilities including remote shell access, keylogging, screenshot capture, microphone and webcam surveillance, Microsoft 365 session token theft, and file exfiltration. ChocoShell is an in-memory PowerShell credential stealer that targets browser cookies, saved passwords, Microsoft 365 and Azure AD tokens, and Wi-Fi credentials. Microsoft recommends treating hotel and conference Wi-Fi as untrusted, using private cellular or managed connections when possible, adopting phishing-resistant authentication, and disabling Microsoft Entra device code authentication when it is not needed.

  • Microsoft said it could not determine the exact initial compromise, but observed signs of breaches in shared infrastructure rather than isolated Wi-Fi devices.
  • The campaign gives the attackers multiple paths from the same captive portal manipulation, including Microsoft 365 phishing, device code phishing, and fake update pages that deliver malware.
  • Microsoft found evidence on some ClickFix landing pages that the attackers may also be targeting Android devices by attempting to deliver an APK file.
  • CornFlake uses fake progress windows such as Windows update, Defender scan, browser update, or network diagnostics screens to distract users while it installs persistence in the background.
  • Microsoft assessed that AI tools were likely used to develop CornFlake and ChocoShell because of extensive comments found in the code.
Key Points
  • 01Microsoft linked a global campaign targeting hospitality Wi-Fi networks to the Russian threat actor Midnight Blizzard, also known as APT29, and tracks the sub-cluster as Storm-2945.
  • 02The attackers manipulate DNS and HTTP traffic on captive portal equipment to redirect hotel and conference center Wi-Fi users to Microsoft 365 phishing pages, device code phishing pages, or fake update pages that deliver malware.
  • 03Microsoft identified two Windows malware families, CornFlake and ChocoShell, with capabilities for persistent access, credential theft, surveillance, and data exfiltration.
  • 04CornFlake is a Go-based remote access trojan that can steal Microsoft 365 session tokens, capture screenshots, monitor the clipboard, log keystrokes, access the microphone and webcam, and exfiltrate files.
  • 05Microsoft recommends treating hotel and conference Wi-Fi as untrusted, using private cellular or managed connections when possible, adopting phishing-resistant authentication, and disabling Microsoft Entra device code authentication when it is not needed.

New Pass-ta-key attacks let malware hijack Google-synced passkeys

In plain words

Researchers found three ways that harmful software already running on a Windows computer can misuse Google Password Manager’s saved passkeys in Chrome to help break into a person’s online accounts. People using Google-synced passkeys on an already-compromised Windows device are the ones affected, and some websites can be at higher risk if they do not properly check that the real user confirmed the sign-in. This matters because passkeys are safer than passwords in many ways, but they do not fully protect accounts when the computer itself has been taken over.

Summary
Researchers found three “Pass-ta-key” attacks that let malware already running on a Windows device abuse Google Password Manager’s synced passkeys to bypass verification or extract private keys. The findings show passkeys are still vulnerable when the user’s device is compromised, especially if services fail to properly validate user verification.

Security researchers at Palo Alto Networks’ Unit 42 discovered three attacks, collectively called Pass-ta-key, that target Google Password Manager in Chrome on already-compromised Windows devices with a Trusted Platform Module. The attacks can abuse Google-synced passkeys to take over accounts, bypass user verification, or extract passkey private keys. The researchers said the attacks do not break passkey cryptography, but instead exploit weaknesses in how Chrome and Google’s cloud authenticator handle device trust, onboarding, recovery, and synced credentials.

The first Pass-ta-key technique lets unprivileged malware impersonate a trusted device and request a valid authentication response from Google’s cloud authenticator without administrator privileges, user interaction, biometrics, or unlocking the device. This can fail when a service properly checks the User Verified flag, as GitHub did, but Unit 42 said it succeeded against eBay because eBay did not properly validate that flag despite requiring user verification. eBay fixed the issue after the researchers reported it.

The Silver Pass-ta-key technique allows attackers to register their own user-verification key with Google’s cloud authenticator, while the Golden Pass-ta-key technique allows malware to obtain the security domain secret used to encrypt synced passkeys. Unit 42 said Google removed the secret from Chrome’s FIDO logs after disclosure, but the secret is still sent to Chrome and remains temporarily accessible in browser process memory. The researchers warned that the stolen master key could decrypt current and future synced passkeys, and recommended that websites properly validate user verification and that credential managers harden device registration, recovery, and master key handling.

  • A service can require user verification and still be vulnerable if it does not properly validate the User Verified flag, as Unit 42 demonstrated with eBay before the issue was fixed.
  • The first Pass-ta-key attack does not require administrator privileges, user interaction, biometrics, or unlocking the device, which makes local malware more dangerous than many users may assume.
  • Google removed the security domain secret from Chrome's FIDO logs after disclosure, but Unit 42 said the secret is still sent to Chrome and remains temporarily accessible in browser process memory.
  • Unit 42 said Google's current implementation provides no way to rotate or revoke the stolen security domain secret, meaning current and future synced passkeys remain protected by the same secret.
  • The researchers' recommendations place responsibility not only on Google Password Manager but also on websites, which need to require and properly validate user verification for passkey logins.
Key Points
  • 01Palo Alto Networks' Unit 42 discovered three attacks, collectively called "Pass-ta-key," that target Google Password Manager in Chrome on already-compromised Windows devices with a Trusted Platform Module.
  • 02The first Pass-ta-key technique lets unprivileged malware impersonate a trusted device and request a valid passkey authentication response from Google's cloud authenticator without administrator privileges, user interaction, biometrics, or unlocking the device.
  • 03The Silver Pass-ta-key technique allows attackers to register their own user-verification key with Google's cloud authenticator, enabling access to accounts that properly require and validate user verification.
  • 04The Golden Pass-ta-key technique allows malware to obtain the security domain secret used to encrypt synced passkeys, which can then be used to decrypt passkey records and recover private keys.
  • 05Unit 42 said passkeys remain significantly safer than traditional passwords, but the attacks show they do not eliminate the risks posed by malware already running on a compromised device.
