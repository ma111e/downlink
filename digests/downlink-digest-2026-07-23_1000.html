Summary
A nine-year-old Linux XFS filesystem flaw dubbed RefluXFS lets local attackers reliably overwrite protected files and gain root privileges on many major distributions. Organizations should apply vendor-fixed kernels and reboot, as there are no practical mitigations.

A nine-year-old race condition vulnerability in the Linux kernel’s XFS filesystem, tracked as CVE-2026-64600 and dubbed RefluXFS, allows local attackers to overwrite protected files and gain root privileges. Qualys Threat Research Unit found and reported the flaw, which affects systems using XFS with reflink enabled, running Linux kernel v4.11 or later, with a directory writable by an unprivileged local user and a high-value root-owned target file or SUID-root binary. Qualys estimates the issue could potentially affect more than 16.4 million systems based on analysis using its Cybersecurity Asset Management software.

Qualys said attackers can reflink-clone a target file such as /etc/passwd or a SUID-root binary into a scratch file they own, then race concurrent O_DIRECT writes on that scratch file. A lock-drop window in the kernel’s copy-on-write allocation path can cause one write to land in the physical block still backing the original protected file. The change is made directly on disk, persists across reboot, produces no kernel log output, and does not touch the target file’s inode, so a modified SUID-root binary keeps its SUID bit.

The vulnerability has existed since kernel version 4.11 after a February 2017 commit and was patched on July 16 after a fix was merged into the Linux kernel source tree. Affected distributions listed in the article include Red Hat Enterprise Linux, Oracle Linux, Amazon Linux, Fedora, CentOS Stream, Rocky Linux, AlmaLinux, and CloudLinux. Qualys said standard protections including SELinux, kernel lockdown, container isolation mechanisms, KASLR, SMEP, and SMAP do not block the attack, and recommended immediate kernel patching and a reboot because there are no reliable or practical mitigations or temporary configuration changes.

  • RefluXFS can modify the physical disk blocks backing a protected file without touching that file's inode, which means a changed SUID-root binary can keep its SUID bit.
  • Qualys said exploitation leaves no kernel log output and survives reboot, making successful attacks harder to notice through ordinary system logging or by simply restarting the system.
  • The vulnerability affects default XFS reflink configurations on major enterprise Linux distributions, increasing the urgency for organizations using standard deployments rather than only unusual setups.
  • Qualys said the flaw was identified during a research effort that integrated Anthropic's Claude Mythos Preview into a manual audit workflow, with researchers later reproducing and independently verifying the exploit.
  • Qualys stated there are no reliable temporary configuration changes or practical mitigations, so the actionable response is to install vendor-fixed kernels and reboot.
