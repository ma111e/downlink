In plain words

The article compares tools that let organizations test their own software for weaknesses using AI while keeping their code and test results inside their own buildings or private networks. This matters especially to banks, defense organizations, government agencies, and healthcare providers that may be forbidden from sending sensitive information to outside cloud services. It argues that these tools can test software more often than traditional once-a-year reviews, helping teams find problems introduced as they release changes quickly. The article presents Aikido Machine as the leading managed option because it can examine source code locally and confirm whether a weakness can actually be used.

Summary
For regulated organizations that cannot send source code or findings to the cloud, on-prem AI pentesting tools offer continuous in-network testing, but capabilities differ sharply. The article positions Aikido Machine as the strongest managed, air-gapped whitebox option for code-aware application and API testing, while alternatives focus more on infrastructure, blackbox testing, or self-managed deployments.

The article compares six AI-powered penetration-testing tools that can run on premises or within an organization’s network: Aikido Security, Pentera, RidgeBot, Horizon3.ai NodeZero, Zero Hunt, and Strix. It says these options matter for regulated organizations, including those in banking, defense, government, and healthcare, that cannot send source code or security findings to external cloud services. The article argues that traditional manual testing is too infrequent for teams that release software rapidly, while older automated web testing finds only more superficial issues. It presents continuous AI testing as a way to test applications, APIs, and infrastructure more regularly.

A central distinction is whether a tool can operate fully air-gapped, meaning its model processing, source-code access, and findings all remain within the customer’s network with no external calls. The article also distinguishes whitebox testing, which uses source code to examine application logic, from blackbox and graybox approaches that test from outside without full code access. It states that Aikido Machine, Zero Hunt, and Strix can meet a fully in-network or air-gapped requirement, while NodeZero sends orchestration and results through Horizon3.ai’s cloud portal. Pentera, RidgeBot, and NodeZero are described as stronger for network and infrastructure validation than for code-aware application testing.

The article positions Aikido Machine as the leading managed on-premises choice because it runs the full pentesting stack locally on H200 GPUs, can receive signed offline updates in air-gapped mode, and performs whitebox testing by default. It says Aikido Machine supplies managed hardware, support commitments, GPU replacement, and updates, whereas Strix is self-hosted software that customers must deploy, tune, and maintain. According to Aikido’s cited benchmark, its on-premises engine matched the cloud version on critical and high-severity findings across three production applications, though the article notes local deployments may trade some speed and finding volume for keeping data inside the network.

  • A tool can run inside an organization’s network yet still fail a true air-gap requirement if it sends orchestration data or results to a vendor cloud, as the article says Horizon3.ai NodeZero does.
  • The article says that moving AI pentesting on-premises does not automatically mean it matches cloud performance: local deployments may trade some speed and total finding volume for keeping data inside the network.
  • According to the article’s cited research, giving a testing tool access to source code can uncover substantially more issues than testing only from the outside, with whitebox testing finding seven times more vulnerabilities than blackbox testing on the same repositories.
  • For fully offline deployments, operational support is a key distinction: Aikido provides managed hardware, updates, and GPU replacement, whereas Strix requires the customer to operate and tune the self-hosted software.
  • The article notes that web-application testing is not equally mature across the compared platforms, describing Pentera’s capability as private beta and NodeZero’s as newly introduced in July 2026.

In plain words

The article explains that attackers often begin in one part of an organization and then move through several others, such as employee computers, online services, user accounts, and company networks. Unit 42 says 43% of investigated attacks involved four or more of these areas, making it easy for separate security tools and teams to miss that individual warning signs are connected. This affects organizations using many connected systems because a small suspicious event can become a larger effort to access or steal sensitive data. The article argues that security teams need to link information from across the organization and keep improving how they spot and stop these connected incidents.

Summary
Attackers increasingly pivot across endpoint, cloud, identity, network and SaaS environments, so SOCs must correlate cross-domain evidence into a single attack path rather than investigate isolated alerts. The article advocates AI-driven correlation, continuous monitoring, threat hunting and iterative detection and response improvements.

Unit 42 describes how adversaries often move beyond their initial point of access, pivoting across endpoint, cloud, network, identity and software-as-a-service environments. Its 2026 Global Incident Response Report found that 43% of attacks involved activity across four or more attack surfaces, with some spanning up to eight. Disconnected security tools can leave visibility gaps that make it difficult for analysts to recognize these events as one connected intrusion.

The article says an investigation may start with an apparently isolated signal, such as an endpoint alert, unusual cloud-resource provisioning or an unfamiliar application requesting elevated permissions. As the intrusion progresses, attackers may change SaaS permissions, reconfigure cloud resources, stage sensitive data for exfiltration and create unusual network connections. It recommends AI-driven correlation, continuous monitoring, threat hunting and ongoing refinement of detections, correlation rules, automation and response workflows so analysts can reconstruct and respond to the complete attack path.

  • An incident may begin with a seemingly routine event, such as an endpoint alert, unusual cloud administration activity, or an unfamiliar application seeking higher permissions, none of which necessarily reveals the wider intrusion on its own.
  • Threat hunting should look for attacker behavior even when that behavior has not yet produced an alert, helping teams find activity that automated detections may have missed.
  • The article treats each investigation as feedback for improving future response by identifying where analysts lost context, where rules were weak, and which response steps caused delays.
  • Continuous SOC engineering is presented as an operational process that improves the data connections, detection logic, correlation rules, automation and analyst workflows that support security operations.

  • 03Related signals may include changed SaaS permissions, newly provisioned or reconfigured cloud resources, data staged for removal, and unusual network connections.
  • 04The article recommends AI-driven correlation to connect seemingly unrelated signals into a unified attack path so analysts can investigate a connected incident rather than isolated alerts.
  • 05Unit 42 Managed XSIAM continuously optimizes data integrations, detection logic, custom correlation rules, automated response playbooks and investigation workflows.
