In plain words

A U.S. government cybersecurity agency says criminals are actively taking advantage of serious weaknesses in WSO2 business software, Adobe Commerce and Magento online-store software, Microsoft SharePoint, and MikroTik RouterOS. The WSO2 and Adobe problems are especially serious because they may let someone take control of administrator accounts or customer accounts without already having access. Organizations using these products, including those in banking, government, telecommunications, logistics, and online retail, need to install fixes or take other protective steps quickly to reduce the risk of unauthorized access.

Summary
CISA added actively exploited critical flaws in WSO2 products (CVE-2026-5430) and Adobe Commerce/Magento (CVE-2026-71362) to its KEV catalog, warning that attackers can gain administrative control or hijack customer accounts. It also flagged exploited Microsoft SharePoint and MikroTik RouterOS vulnerabilities and urged organizations to patch or mitigate urgently.

CISA has added two critical vulnerabilities to its Known Exploited Vulnerabilities catalog: CVE-2026-5430 in multiple WSO2 products and CVE-2026-71362 in Adobe Commerce and Magento. The agency also warned that attackers are exploiting CVE-2026-65660, a high-severity Microsoft SharePoint code-injection issue, and CVE-2026-67279, a MikroTik RouterOS pre-authentication SSH workflow bypass. Federal agencies using the affected WSO2 and Adobe products have until September 27 to apply updates or mitigations, discontinue use, while SharePoint and RouterOS fixes are due September 28.

The WSO2 flaw has a maximum severity score and results from its JWT login mechanism accepting tokens signed with an unsupported algorithm. WSO2 said successful exploitation could let an attacker compromise administrator accounts and gain full control; watchTowr reproduced an attack in which a forged token exposed API endpoints and application credentials. Sansec reported that the Adobe Commerce and Magento flaw can be used to hijack customer accounts without an existing account, administrator privileges, or user interaction. CISA encouraged all organizations, not only federal agencies, to prioritize remediation of issues listed in its catalog.

  • watchTowr observed only a limited number of WSO2 exploitation attempts from one IP address, but the attacker targeted the wrong WSO2 product for CVE-2026-5430.
  • When watchTowr reproduced the WSO2 attack against the correct product, a forged token exposed API endpoints and application credentials.
  • The Adobe Commerce flaw reportedly can be used to hijack customer accounts without an existing account, administrator privileges, or user interaction.
  • WSO2 technology is used by nearly 1,000 customers in sectors including banking, government, telecommunications, and logistics, increasing the importance of prompt mitigation.

88
In plain words

Two GitHub add-ons that help projects manage issue and comment pages were briefly made available again after they had previously been altered to steal sensitive access information. Projects that use these add-ons by their version names may have automatically run the harmful code the next time their routine checks ran. This matters because a previously contained problem could become active again without anyone changing their own project settings, putting software projects and their stored credentials at risk.

Summary
Previously compromised actions-cool GitHub Actions repositories were briefly re-enabled with malicious release tags intact, causing workflows using version tags to resume executing the Mini Shai-Hulud credential-stealing payload. Organizations should remove or SHA-pin the affected actions, review workflow runs, and rotate potentially exposed secrets.

GitHub disabled the actions-cool/issues-helper and actions-cool/maintain-one-comment repositories for a second time after they became accessible again on September 16, 2026. The actions had originally been compromised on May 18, 2026, to run code that collected sensitive credentials from CI/CD workflows and sent them to an attacker-controlled server. The activity was linked to the Mini Shai-Hulud cluster through the shared exfiltration domain t.m-kosche[.]com and overlaps with malicious npm packages in the @antv ecosystem.

According to Socket, the repositories’ release tags had not been cleaned up and still pointed to the malicious content introduced in May. As a result, workflows that referenced either action through a version tag resumed downloading and running the payload after the repositories became available, without a new code release or changes to workflow files. Workflows pinned to a full commit SHA from before May 18, 2026, were not affected; developers are advised to remove or pin the actions to a known-clean earlier SHA, rotate exposed secrets, and review workflow runs and repository history.

  • The threat resumed without a newly published malicious version, a newly hijacked account, or any change to affected projects' workflow files; restoring access to repositories whose version tags still referenced malicious content was sufficient.
  • Because the affected actions commonly run daily or when issues and pull requests are opened, most affected repositories may have run the payload within a day of the repositories being re-enabled.
  • A full commit-SHA reference to a version from before May 18, 2026, was not affected, illustrating that fixed commit references avoid reliance on the current state of an upstream repository and its mutable version tags.
Key Points
  • 01GitHub disabled the actions-cool/issues-helper and actions-cool/maintain-one-comment repositories again after they became accessible on September 16, 2026.
  • 02Their release tags still pointed to malicious code introduced on May 18, 2026, so workflows using version tags could download and run the payload when the repositories returned online.
  • 03The malicious workflows harvested sensitive CI/CD credentials and sent them to an attacker-controlled server, and the activity was linked to the Mini Shai-Hulud cluster.
  • 04Workflows pinned to a full commit SHA from before May 18, 2026, were not affected.
  • 05Developers are advised to remove or pin the affected actions to a known-clean pre-May 18 SHA, rotate exposed secrets, and review workflow and repository history.
