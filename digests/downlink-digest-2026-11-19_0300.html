In plain words

PHP, software used by many websites and online services, plans to release fixes on November 19, 2026, for serious security problems affecting every supported version. One expected issue could let an outsider run commands on a server, but only in unusual setups involving certain website session settings. People and organizations running PHP should install the fixes quickly, especially because recently fixed PHP flaws have already been used in limited real-world attacks against internet-facing security devices.

Summary
PHP will release security updates on November 19, 2026, for critical vulnerabilities affecting all supported versions, including an expected RCE flaw under uncommon session-configuration conditions. Administrators should apply the updates promptly and can disable session upload progress as an interim mitigation.

PHP maintainers announced that a security release scheduled for November 19, 2026, between 2:00 and 2:30 p.m. UTC, will address vulnerabilities affecting all supported PHP versions. The highest severity is rated critical, although PHP said critical issues require non-default configurations or uncommon setups. Users are advised to apply the updates as soon as they are available.

The release is expected to include CVE-2026-115560, a remote code execution issue that requires a particular combination of session serialization settings and enabled session upload progress. As an interim measure, PHP urged users to set session.upload_progress.enabled=0 and restart PHP workers. The advisory follows recently patched PHP2Shell flaws, CVE-2026-109618 and CVE-2026-109619, which have seen limited active exploitation against publicly accessible Palo Alto Networks management interfaces and Check Point Security Gateways.

  • The expected CVE-2026-115560 issue depends on a specific combination of session settings, so PHP deployments using the affected serialization-handler pattern face the most immediate exposure.
  • Disabling session upload progress is only effective after restarting the PHP worker, making a configuration change alone insufficient as an interim safeguard.
  • The advisory arrives soon after PHP2Shell flaws were patched and then actively targeted against internet-facing Palo Alto Networks and Check Point systems, underscoring the operational urgency of applying PHP updates when released.
