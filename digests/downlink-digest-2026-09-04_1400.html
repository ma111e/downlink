PostgreSQL released updates for CVE-2026-6471, a 12-year-old flaw in logical decoding that can allow an account with the REPLICATION attribute to run arbitrary code as the operating-system user running the database server. The issue has existed since logical decoding was introduced in PostgreSQL 9.4 in 2014. Versions before PostgreSQL 18.6, 17.11, 16.15, 15.19, and 14.24 are affected.

Exploitation requires a replication account and a server running with wal_level set to logical, a setup used by backup tools, standby servers, change data capture pipelines, and monitoring systems. On Windows, Cyera said a server could resolve a network path over SMB and fetch a library from an attacker-controlled machine, while Linux and macOS require NFS automounting for a similar result.

The fix adds a new output_plugin_libraries server parameter that whitelists logical decoding output plugin libraries, defaulting to pgoutput and test_decoding. Administrators using other plugins, including wal2json and decoderbufs, must add them to the list and reload the PostgreSQL configuration after updating, or logical decoding will be refused. The article also notes a remaining issue with pg_createsubscriber checks and says CVE-2026-6471 was not in CISA’s Known Exploited Vulnerabilities catalog as of September 4.

  • The existing PostgreSQL restriction that limits non-superusers to administrator-controlled plugin paths was not applied on the replication path, allowing quoted plugin names with path separators and ../ traversal to reach the loader directly.
  • Before updating, administrators are advised to query pg_replication_slots for previously used plugins because the new whitelist may refuse logical decoding after the patch if non-default plugins are not listed.
