  • Docker changed the account-conversion process so personal access tokens are no longer transferred and a user must consent before being named an organization owner.

Summary

The SlugFest flaw reportedly exposed more than 1,500 npm packages to potential supply-chain hijacking without credential theft.

GitHub has changed npm trusted publishing so that newly created, unvalidated configurations expire after 48 hours unless they complete a successful publish. The change follows Bloom Security’s discovery of a loophole that could allow attackers to publish new versions of packages without stealing the maintainer’s credentials. GitHub said a first successful publish validates the configuration and binds it to the repository’s immutable identity.

Bloom Security found that npm initially relied on a repository’s owner/name address, or slug, rather than its permanent GitHub identity. If a repository was renamed, transferred, or deleted and its old slug became available, an attacker could claim that slug, obtain a short-lived publishing credential through a workflow, and publish a malicious version of the affected package if the trusted-publisher binding had never been used. The company identified more than 1,500 potentially vulnerable packages with over 10 million collective downloads, and warned that automated coding agents may pull harmful latest versions without human review.

  • The risky period is limited to trusted-publisher configurations that have never successfully published, because the first successful publish binds the configuration to the repository’s permanent identity.
  • Renaming, transferring, or deleting a repository can create the condition for a takeover without compromising a maintainer account, as a newly claimed owner/repository name can match the old trust configuration.
  • Maintainers can reduce exposure by deleting and recreating trusted-publisher bindings whenever a repository is renamed or transferred, and by removing bindings before deleting a repository.
  • Automated coding agents can amplify the impact because they may select the latest package version and install a malicious update without a person checking its origin.
  • GitHub’s 48-hour expiration rule forces a new trusted-publisher configuration to be used promptly or removed, reducing the time in which an unused repository name can be reclaimed.
