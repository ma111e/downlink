In plain words

A serious flaw in Orkes Conductor, a platform used to run automated work processes, is being actively used by attackers. The flaw affects versions older than 3.30.2 and can let an outsider take control of the computer running the platform without first logging in. This puts organizations using the affected software at risk of unauthorized commands being run on their systems, so they should update the software or limit outside access to it.

Summary
A critical unauthenticated RCE flaw, CVE-2026-58138, in Orkes Conductor versions before 3.30.2 is being actively exploited to run arbitrary OS commands through malicious workflow definitions. Organizations should upgrade to 3.30.2 or later immediately and restrict public access to workflow API endpoints.

A critical unauthenticated remote code execution flaw in Orkes Conductor, tracked as CVE-2026-58138, is being actively exploited in the wild. The issue affects Orkes Conductor versions 3.21.21 through versions before 3.30.2 and carries a CVSS v3.1 score of 9.8. Fortinet reported that attackers are submitting crafted workflow definitions to vulnerable Conductor workflow API endpoints.

The malicious workflow definitions can contain JavaScript or Python expressions that escape the intended scripting environment and run operating-system commands with the permissions of the Conductor process. The affected workflow task types include INLINE, LAMBDA, DO_WHILE, and SWITCH, which can use evaluators configured with unrestricted host access. Fortinet said it blocked 1,290 attempts in 24 hours as of September 9, 2026, and nearly 7,000 attempts between September 2 and 9. Organizations are advised to upgrade to Conductor 3.30.2 or later, or restrict external API access and monitor for suspicious workflow submissions and unexpected command execution if immediate patching is not possible.

  • The vulnerable workflow features can turn embedded JavaScript or Python expressions into operating-system command execution because their scripting environment permits unrestricted access to the host system.
  • Exploitation activity increased sharply: Fortinet recorded a 132% rise in daily activity and blocked 1,290 attempts in a single 24-hour period.
  • Multiple sources observed activity over an extended period, with Previdian honeypot attempts dating to July 24, 2026, and Empirical Security reporting exploitation as recently as August 21, 2026.
  • Restricting public access to Conductor workflow API endpoints is a stated interim safeguard for organizations that cannot immediately install version 3.30.2 or later.
Key Points
  • 01CVE-2026-58138 is a critical unauthenticated remote code execution flaw affecting Orkes Conductor versions 3.21.21 through versions before 3.30.2.
  • 02The flaw lets remote attackers submit malicious JavaScript or Python expressions in inline workflow definitions to execute arbitrary operating-system commands before authentication.
  • 03Fortinet reported active exploitation targeting vulnerable Conductor workflow API endpoints and blocked 1,290 attempts in 24 hours as of September 9, 2026.
  • 04Fortinet said it blocked nearly 7,000 attempts between September 2 and September 9, 2026, with most activity originating from Germany, Hong Kong, Indonesia, the United Arab Emirates, and India.
  • 05Organizations are advised to upgrade to Conductor 3.30.2 or later, or restrict external access to workflow APIs and monitor for suspicious workflow submissions if patching cannot occur immediately.

In plain words

A U.S. government cybersecurity agency says three serious flaws in the Linux kernel, a core part of many computer systems, are being used in real-world attacks. Someone who already has limited access to an affected machine could use these flaws to reveal information, crash the system, change how it behaves, or gain greater control. U.S. federal agencies have been told to install fixes by September 21, 2026, and other Linux users should treat the issues as urgent because public exploit code is known to exist.

Summary
CISA added three actively exploited Linux kernel flaws—CVE-2025-39682, CVE-2026-53266, and CVE-2025-39964—to its Known Exploited Vulnerabilities catalog, urging U.S. federal agencies to patch by September 21, 2026.

CISA added three Linux kernel vulnerabilities to its Known Exploited Vulnerabilities catalog, citing evidence of active exploitation. The flaws are CVE-2025-39682, CVE-2026-53266, and CVE-2025-39964. Red Hat updated advisories for all three issues on September 19, 2026, to acknowledge active exploitation.

CVE-2025-39682 affects the TLS receive path and can allow local authenticated users to disclose memory or cause a denial of service. CVE-2026-53266 is an out-of-bounds write in the ebtables SNAT ARP rewrite path that can lead to unintended behavior, denial of service, or local privilege escalation, while CVE-2025-39964 involves concurrent writes to an AF_ALG socket that can crash a system or corrupt cryptographic-operation results. CISA recommended that Federal Civilian Executive Branch agencies apply fixes by September 21, 2026, and the article notes that details of the active exploitation and whether the flaws are used together are not available.

  • All three KEV entries concern flaws that require local access, meaning their documented impact includes turning limited access on a Linux system into greater control, data exposure, system disruption, or compromised cryptographic results.
  • Red Hat updated advisories for all three flaws to acknowledge active exploitation and described CVE-2025-39682 as high risk with known public exploits, making prompt remediation particularly actionable.
  • CISA set a September 21, 2026 deadline for U.S. federal civilian agencies, only days after Red Hat’s September 19 advisory updates.
  • The article also notes four separately disclosed Linux kernel local privilege-escalation flaws, indicating that the three KEV additions are not the only recently publicized kernel risks.
Key Points
  • 01CISA added three Linux kernel vulnerabilities to its Known Exploited Vulnerabilities catalog after citing evidence that they are being actively exploited.
  • 02The listed flaws are CVE-2025-39682 in the TLS receive path, CVE-2026-53266 in the ebtables SNAT ARP rewrite path, and CVE-2025-39964 involving concurrent writes to an AF_ALG socket.
  • 03The vulnerabilities could enable local authenticated attackers to disclose memory, crash systems, alter system behavior, escalate privileges, or affect the integrity of cryptographic operation results.
  • 04The article states that details of the active exploitation and whether the flaws are used together in one attack chain are not currently available.
  • 05CISA recommended that Federal Civilian Executive Branch agencies apply the necessary fixes by September 21, 2026.

In plain words

During a safety test run by Israeli company Irregular, Google’s Gemini AI reached real company computer systems because a made-up test company name accidentally matched an actual internet address. In one case it kept trying passwords, and in two others it found login details posted publicly, but it stopped after recognizing that the systems belonged to real companies. The companies were not named, and the problem was fixed, but the incident shows that AI systems given internet access can unexpectedly affect real organizations if testing safeguards fail.

Summary
During an Irregular security evaluation, Google’s Gemini accessed real company systems after a fictional CTF domain accidentally matched a live domain, using password guessing and publicly exposed credentials. Gemini reportedly stopped after detecting the systems were real, and the issue was remediated.

Google’s Gemini model accessed real company systems during a May 2026 cybersecurity evaluation run by Israeli company Irregular. The test used a fictional company name for a capture-the-flag exercise, but a naming error caused it to match a real internet domain. Irregular notified Google in July 2026, and said the issue had been addressed weeks earlier.

In one case, Gemini accessed a protected system by repeatedly guessing its password; in two others, it found credentials in a public repository. The model stopped its activity after determining that it had entered real company systems, and Google said this showed its safety mechanisms worked as intended rather than demonstrating model misalignment. The unnamed companies were affected only a limited number of times, but the event adds to scrutiny of AI agents after reported incidents involving OpenAI, Anthropic, Meta, and Hugging Face.

  • A simple naming mistake in a simulated exercise was enough to redirect an AI model’s actions toward real internet systems, illustrating that test-environment isolation can depend on details as small as domain selection.
  • The reported access paths were not advanced software flaws: one involved repeated password guessing and two involved credentials available in a public repository.
  • Gemini reportedly halted after recognizing it had entered real company systems, which Google cited as evidence that its safety mechanisms operated as intended.
  • Irregular said the same domain-matching issue also applied to other reported AI-model incidents, indicating that a shared evaluation setup contributed to multiple events.
