In plain words

Google is preparing a Chrome change that would stop unwanted extensions from taking over the New Tab page or changing the default search engine on regular consumer Windows and macOS computers. This matters because malicious programs can currently make Chrome think an extension was installed by an administrator, which can prevent people from removing it and may redirect their searches to suspicious websites. The feature is still under review and is not yet available in stable Chrome.

Summary
Google is working on a Chrome security feature that will block policy-installed extensions on unmanaged Windows and macOS devices from hijacking the New Tab page or default search engine. The change aims to stop malware from abusing enterprise policies to lock unwanted extensions onto consumer PCs.

Google is preparing a new Chrome security feature that would block policy-installed extensions from hijacking the New Tab page or changing the default search engine. BleepingComputer spotted the protection in work-in-progress Chromium Gerrit changes, and it has not shipped yet. Google plans to enable it by default once the changes are approved.

The feature targets unmanaged consumer Windows and macOS devices, which Google describes as low-trust environments because Chrome reads locally stored policies without confirmation from a trusted authority such as a domain or mobile device management service. Malware has abused Chrome enterprise policies on regular consumer PCs by adding local policy keys and force-installing extensions that replace the New Tab page, change the search engine, or redirect searches to suspicious websites. Chrome may then believe the extension was installed by an administrator, preventing users from removing or disabling it and sometimes showing a confusing “Managed by your organization” message.

Under the proposed protection, Chrome would cancel installation attempts for policy-controlled extensions that override the New Tab page or default search engine and save the extension ID in a blocked-extension preference. Chrome would also stop trying to download the same blocked extension during future policy checks, and manually installed extensions would no longer be converted into locked policy-controlled extensions. If a previously managed device loses trusted management status but still has local policy keys, Chrome would automatically uninstall affected New Tab and search-engine override extensions, while legitimate administrators would have an escape-hatch policy to disable the protection when needed.

  • The planned protection specifically targets unmanaged consumer Windows and macOS devices because Chrome treats locally stored policy settings on those systems as lower trust when they are not backed by a domain or mobile device management service.
  • Google is addressing persistence as well as initial installation by having Chrome remember blocked extension IDs and skip future download attempts during policy checks.
  • The change would prevent a manually installed extension from later being turned into a locked, policy-controlled extension, preserving the user’s ability to disable or remove it.
  • If a device loses trusted management status but still has local policy keys, Chrome would automatically remove affected New Tab and search-engine override extensions.
  • Google plans an escape-hatch policy for legitimate administrators whose required enterprise extensions override the New Tab page or search engine.
