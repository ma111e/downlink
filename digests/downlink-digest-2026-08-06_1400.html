New Interrupt Injection Attack Can Bypass Spectre v2 Defenses on Intel and AMD CPUs
thehackernews.com · 06 Aug 2026 16:17 UTC openai-codex / gpt-5.5

In plain words

MIT researchers found that an ordinary program on a Linux computer can carefully time an interruption in the processor and get around protections meant to stop it from reading protected information from the computer’s core system. This mainly affects shared systems using affected AMD or Intel processors where someone can run local code, and the researchers showed it could leak kernel memory, including enough to find and read the file that stores password hashes on Linux. AMD says a Linux kernel fix has been shipped through normal operating system updates, while Intel said it does not think a new fix is needed. The broader concern is that protections built into modern processors can still fail if attackers can slip activity into tiny timing gaps.

Summary
MIT researchers found a new “Interrupt Injection” technique that can bypass some Spectre v2 defenses on Intel and AMD CPUs by timing interrupts to re-poison branch predictors after mitigation runs. AMD says affected Linux systems need a kernel update, while Intel does not currently plan a new mitigation.

MIT CSAIL researchers Daniël Trujillo and Mengjia Yan described a technique called INTERRUPT INJECTION that can bypass Spectre v2 defenses on Intel and AMD CPUs. The attack allows an unprivileged Linux program to time a hardware interrupt so it lands after the processor sanitizes its branch predictor but before the kernel uses it, letting the attacker re-poison the predictor. On an AMD Zen 2 system running Linux 6.14 with default Spectre v2 mitigations enabled, their exploit leaked arbitrary kernel memory at 5.47 bytes per second with 91.97% accuracy.

The researchers disclosed the issue to AMD and Intel on February 5, and AMD said it planned a kernel patch. A Linux kernel fix titled “x86/bugs: Make Safe-RET robust against interrupt injection” was committed on June 2 and changes register handling so the Safe-RET sequence is treated as completed while avoiding a RET instruction after the interrupt returns. AMD later published bulletin AMD-SB-7061, naming Zen 1 through Zen 4 processors as affected and saying the issue appears associated with the Linux implementation of Safe RET.

The article says the risk is most relevant to shared systems running affected processors because the attack needs only local code execution and no privileges. The researchers demonstrated enough kernel memory leakage to locate and read /etc/shadow, which stores Linux password hashes, in five of ten attempts. Intel paid a discretionary bug bounty bonus but, according to the paper, said it does not consider additional mitigation necessary and pointed to existing guidance.

  • Administrators may have difficulty verifying exposure because AMD’s bulletin and MIT’s announcement did not link to the Linux kernel commit, no CVE was listed, and the relevant Linux vulnerability-status documentation did not mention interrupts when checked by The Hacker News.
  • The practical risk is concentrated on shared systems because the technique requires only local code execution without privileges, meaning one user’s program could target protected kernel memory on an affected processor.
  • The attack shows that the interrupt-return path must be treated as part of Spectre v2 defense logic, because interrupts can occur between the moment a processor protection runs and the moment the protected operation uses that state.
  • The demonstrated AMD attack did not need a new disclosure gadget because it used Inception, the 2023 AMD flaw that Safe-RET was designed to stop, to turn the interrupt handler itself into a training gadget.
  • There is a vendor response gap: AMD has shipped or planned a Linux kernel mitigation for affected Zen processors, while Intel paid a bug bounty bonus but said no additional mitigation is required despite the researchers observing mispredictions on Intel systems.
Key Points
  • 01MIT CSAIL researchers Daniël Trujillo and Mengjia Yan named a new technique INTERRUPT INJECTION, which lets an unprivileged Linux program time a hardware interrupt to re-poison a processor’s branch predictor after Spectre v2 defenses have run.
  • 02On an AMD Zen 2 system running Linux 6.14 with default Spectre v2 mitigations enabled, the researchers’ exploit leaked arbitrary kernel memory at 5.47 bytes per second with 91.97% accuracy and located and read /etc/shadow in five of ten attempts.
  • 03AMD published bulletin AMD-SB-7061, titled “Safe RET Interrupt Vulnerability,” naming Zen 1 through Zen 4 processors as affected and saying the issue appears associated with the Linux implementation of the Safe RET mitigation.
  • 04A Linux kernel fix, “x86/bugs: Make Safe-RET robust against interrupt injection,” was committed on June 2 and changes interrupt handling so the Safe-RET sequence is treated as completed and a RET instruction is not executed after the interrupt returns.
