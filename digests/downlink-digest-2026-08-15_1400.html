In plain words

A new malicious program called Evooo1Bot is taking over internet-connected gateway devices from brands including Alcatel, NETGEAR, Tenda, Mitsubishi Electric, Telesquare, and D-Link by using already-known security flaws. Once inside, it can use those devices to secretly pass along attackers’ internet traffic, steal login information, try passwords on other machines, and overwhelm websites or services with traffic. This matters because ordinary routers and similar devices can be turned into tools for hiding criminal activity or disrupting online services, especially when they are outdated, still use default passwords, or have remote access left on.

Summary
A new Mirai-based Linux botnet called Evooo1Bot is exploiting known flaws in internet-facing routers and gateway devices to turn them into SOCKS5 proxy relays, steal credentials, brute-force SSH, and launch DDoS attacks. Defenders should patch IoT firmware, change default credentials, disable remote admin access, and replace unsupported devices.

A new Mirai-based modular Linux botnet malware called Evooo1Bot has been targeting internet-facing gateway devices and turning them into SOCKS5 traffic relay nodes. Fortinet researchers found that the malware reuses Mirai’s DDoS engine while adding encrypted command-and-control communications, an SSH brute-force scanner, a SOCKS relay module, a credential sniffer, and an exploit arsenal. Since at least July, it has targeted devices from Alcatel, NETGEAR, Tenda, Mitsubishi Electric, Telesquare, and D-Link by exploiting known vulnerabilities.

Newer Evooo1Bot builds include a separate vulnerability-exploitation module targeting Hikvision cameras, Atlassian Confluence, Zyxel firewalls, TP-Link routers, D-Link NAS devices, WSO2 products, Kubernetes ingress-nginx, and vulnerable PHP-CGI installations. When exploitation succeeds, a script downloads one of 12 malware builds matching the host CPU architecture and then clears Bash history to remove traces of the attack. Fortinet noted that some embedded exploits are incorrectly implemented, causing exploitation attempts to fail.

Evooo1Bot uses encrypted command-and-control communications over port 443 and checks for debuggers, security tools, sandboxes, virtual machines, containers, and honeypots before launching. It establishes persistence through systemd, SysV init, shell profiles, and rc.local, while a cron job tries to re-download the payload every five minutes. Its modules allow operators to open an interactive shell, transfer files, sniff credentials, run SOCKS5 proxy sessions, brute-force SSH logins, and launch DDoS attacks using 16 flood methods.

  • Evooo1Bot’s operators can potentially monetize infected devices as residential proxy infrastructure because its SOCKS5 relay supports multiple independent proxying sessions at the same time.
  • Some embedded exploits in Evooo1Bot are incorrectly implemented, which causes failed exploitation despite the malware carrying a broad exploit arsenal.
  • The malware makes repeated reinfection attempts through a cron job that re-downloads the payload every five minutes, so simply removing the binary may not be enough if persistence mechanisms remain.
  • Evooo1Bot performs checks for debuggers, security tools, sandboxes, virtual machines, containers, and honeypots before launching, making analysis and detection more difficult.
  • The SSH scanner uses 150 username and password combinations focused on enterprise-oriented accounts and performs post-login checks to avoid honeypots.
