In plain words

U.S. cyber officials warned that criminals are actively using two serious software flaws: one in N-able’s MailAssure email service and another in MONAI Label, a medical-imaging application. The MailAssure incident disrupted service, while attackers used the MONAI Label flaw to place their own files on a university server and gain full control of it. The case matters because the MONAI attack was reportedly carried out with AI agents that could plan and adjust their actions with little human direction, and related campaigns have targeted businesses, payment systems, cloud accounts, and cryptocurrency services.

Summary
CISA added actively exploited flaws in N-able MailAssure and MONAI Label to its KEV catalog, including a MONAI Label zero-day reportedly exploited by AI agents to gain root-level reverse-shell access. Organizations should urgently patch CVE-2026-134624 and CVE-2026-133968.

CISA added two actively exploited vulnerabilities to its Known Exploited Vulnerabilities catalog: CVE-2026-134624 in N-able MailAssure and CVE-2026-133968 in MONAI Label. The MailAssure flaw is a server-side request forgery issue that allows an authenticated API user to reach arbitrary internal hosts and ports and send crafted data to internal services. N-able linked its exploitation to a November 16 security incident that disrupted Mail Assure and SpamExperts Hosted Cloud, although the company said affected functions were restored and its investigation found exploitation confined to one hosted server.

The MONAI Label flaw lets an unauthenticated remote attacker write files outside the intended data directory and could result in remote code execution. A suspected China-linked actor reportedly used CAIRN AI agents to identify and exploit the zero-day in about 11 minutes, then wrote a Python reverse-shell payload to sitecustomize.py and triggered a training endpoint to obtain a root shell. The article places this activity within a broader set of AI-driven campaigns involving ARTEX, AntiFox, and CyberStrikeAI, which have targeted organizations, payment services, cloud environments, and cryptocurrency exchanges. Federal Civilian Executive Branch agencies were advised to apply fixes for both vulnerabilities by November 26, 2026.

  • The MONAI Label zero-day was reportedly identified and exploited by AI agents in about 11 minutes, showing that the agents could discover and use an unknown flaw with minimal human direction.
  • The attackers reportedly gained persistent root-level access by writing a payload to Python’s automatically imported sitecustomize.py file and then triggering a training endpoint to start a new Python process.
  • AWS described an ARTEX campaign in which stolen AI-model access keys funded the AI processing used to find additional credentials, creating a self-sustaining operation.
  • ARTEX activity against AWS environments used both compromised long-term access keys and public Cognito user pools, including account registration and account enumeration through collected tokens.
  • Previdian observed ARTEX-related traffic attempting several high-impact techniques, including application discovery, authentication probing, remote code execution attempts, path traversal, and retrieval of sensitive configuration data.

  • 02CVE-2026-134624 is a critical MailAssure flaw that lets an authenticated API user reach arbitrary internal hosts and ports and send crafted data to internal services.

  • 04A suspected China-linked actor reportedly used CAIRN AI agents to identify and exploit the MONAI Label zero-day, then used a Python startup file and a training API endpoint to establish a root reverse shell.

OpenAI and Cisco Unveil AI-Assisted Linux Security Tool to Block Exploits Before Patching
thehackernews.com · 24 Nov 2026 06:02 UTC openai-codex / gpt-5.6-terra
TAGSciscocodexebpfelasticsearchisovalentjapanjava4shelllinuxopenaishirudotetragon

In plain words

OpenAI and Cisco released Shirudo, a free tool for Linux computers that can use AI to create temporary protections against newly discovered software flaws without taking services offline. It is intended for organizations running Linux-based applications, helping them block harmful activity while they test and install a permanent fix. This matters because AI is making it faster to find and misuse software weaknesses, while updates can still take days or months to reach many systems.

Summary
OpenAI and Cisco have launched Shirudo, an open-source Linux runtime that uses AI-generated, signed eBPF “shields” to block known exploit paths without restarting services while patches are tested and deployed.

OpenAI and Cisco have launched Shirudo, an open-source Linux runtime designed to let AI agents create temporary protections against exploits without interrupting running services. The project aims to give defenders time to test and deploy permanent patches while reducing the risk from newly identified software flaws. OpenAI described it as an initial step toward infrastructure that can adapt to threats while continuing to operate.

Shirudo uses eBPF, which allows lightweight sandboxed programs to run inside the Linux kernel without changing system code or restarting the machine. Its guardian agent can create targeted “shields” that block vulnerable code paths, first allowing teams to monitor their effect before enabling active blocking. Shields are cryptographically signed, delivered in .bee packages through OCI-compliant registries, and validated using TPM-based checks; in a controlled experiment, OpenAI said a Codex-generated shield blocked a Java4Shell attempt against a running Elasticsearch service without a restart.

  • Shirudo is designed as a temporary bridge to patching rather than a replacement for it: shields are meant to be retired after the permanent software fix is deployed.
  • Before a shield begins blocking activity, operators can observe its effect on an application, allowing them to check that legitimate requests still work while the exploit path is stopped.
  • Shields are packaged for distribution through OCI-compatible registries and validated with cryptographic signatures and TPM-based trust checks before target systems load them.
  • Cisco describes agents as using both open-source code and vendor disclosures to map a flaw to affected assets and attack paths before generating a narrowly targeted defense.
  • The project is motivated by the gap between increasingly fast AI-assisted vulnerability discovery and the days, weeks, or months often required to deploy fixes broadly.
Key Points
  • 01OpenAI and Cisco launched Shirudo, an open-source Linux runtime intended to let AI agents deploy temporary safeguards against exploits without interrupting running services.
  • 02Shirudo uses eBPF, a Linux capability for running lightweight sandboxed programs in the kernel, to block vulnerable code paths without restarting the system.
  • 03Security teams can monitor the effect of a proposed Shirudo shield before enforcing it, and shields are cryptographically signed and verified before loading.
  • 04Shirudo is built on Tetragon, an eBPF-based security platform developed and open-sourced by Isovalent.
  • 05In a controlled experiment, OpenAI said a Codex-generated shield blocked a Java4Shell exploit attempt against a running Elasticsearch service without requiring a restart.
