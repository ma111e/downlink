In plain words

Researchers found that AI coding helpers can be tricked into inventing the same fake project or plugin names, and attackers could register those names so the helper downloads their trap instead of the real thing. People using assistants such as Cursor, Windsurf, GitHub Copilot, Cline, Gemini CLI, Claude Code, or OpenClaw are affected if they let the tool fetch outside resources and run commands without checking. In tests, this could make the assistant run attacker-supplied code on the user’s computer, and at a large enough scale it could help build a network of infected machines.

Summary
Researchers describe HalluSquatting, an attack where adversaries register names that AI coding assistants predictably hallucinate for popular repositories or plugins, then use hidden prompt-injection instructions to make the assistant fetch and run attacker code. The key defense is to prevent agents from automatically installing or executing fetched resources without verifying the real source.

Researchers describe a new attack they call HalluSquatting, which exploits AI coding assistants that invent realistic but nonexistent names for repositories, plugins, or other resources. An attacker can identify a fake name the assistant repeatedly uses, register it on GitHub or a plugin store, and place hidden instructions inside it. When a user asks the assistant to fetch the intended popular resource, the assistant may instead retrieve the attacker-controlled one.

The attack matters because it can lead an assistant to run attacker-supplied code on the user’s machine if the assistant is allowed to fetch outside resources and execute commands with little review. The researchers frame this as a possible botnet-building method because one planted fake name tied to a popular resource could reach many machines. In tests, tools including Cursor, Windsurf, GitHub Copilot, Cline, Google’s Gemini CLI, and OpenClaw assistants were made to run harmless placeholder payloads.

Technically, the attack chains an AI hallucination with indirect prompt injection, where instructions hidden in fetched content hijack what the assistant does next. The researchers reported that the same wrong names appeared consistently in experiments, with peak rates of up to 85% for repository requests and 100% for skill installs. The article says the most effective mitigation is for assistants to search before fetching, while users should avoid unattended auto-run modes and verify repository or package names before allowing an agent to pull them in.

  • The article identifies auto-run modes such as Claude Code's skip-permissions flag and Gemini CLI's yolo mode as the main exposure because they remove the command review step that would otherwise interrupt the attack path.
  • The researchers found that hallucinated resource names can be consistent across different prompts and models from different companies, making them practical targets for attackers rather than random one-off mistakes.
  • The article says marketplace screening is not a reliable backstop, citing Trail of Bits' June test in which malicious skills passed several store scanners in under an hour.
  • A simple lookup before fetching a repository or plugin is presented as the most effective fix because it grounds the assistant in what actually exists and reduces name guessing.
  • Platforms can reduce risk by reserving well-known repository names under new accounts and pre-registering likely AI-invented names so they point back to the real project.

  • 03In experiments, assistants reached for the same wrong name in up to 85% of repository requests and 100% of skill installs, and tools including Cursor, Windsurf, GitHub Copilot, Cline, Gemini CLI, and OpenClaw were made to run harmless attacker-supplied code.
