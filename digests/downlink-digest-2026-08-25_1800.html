In plain words

Socket has launched a new beta connection with Asana, a work-tracking tool, so security warnings from Socket can become assigned Asana tasks. This affects Socket customers on Business and Enterprise plans whose teams use Asana to manage fixing problems. It matters because teams no longer have to copy issues into Asana by hand or update two places separately, which can help the right people track and finish the work more reliably.

Summary
Socket launched a beta Asana integration for Business and Enterprise plans that turns Socket alerts into assigned, trackable Asana tasks. Teams can create tasks manually or through automated ticketing rules and keep alert and task status synced between both systems.

Socket launched Socket for Asana, a new integration that turns Socket alerts into assigned and trackable Asana tasks. Teams can create tasks one at a time from the Socket dashboard or automatically through ticketing rules. The integration is intended to remove the manual work of recreating findings in Asana and updating both Socket and Asana separately.

Owners or Admins in a Socket organization can connect an Asana workspace from Settings → Integrations → Asana using OAuth. Socket supports connecting multiple Asana workspaces to the same Socket organization, so tasks can be routed to the projects and teams responsible for resolving them. When creating a task from an alert, users can choose the Asana workspace and project, then add tags and an assignee.

Automated ticketing rules can create and update Asana tasks when alert events occur across a Socket organization. Rules can use alert events, conditions such as type, priority, or repository, and settings for workspace, project, tags, assignee, and status updates. The integration can keep linked Asana tasks and Socket alerts in sync, including completing the Asana task when an alert is cleared or triage-ignoring the Socket alert when the linked Asana task is completed. Socket for Asana is available in beta on Business and Enterprise plans.

  • Only an Owner or Admin in a Socket organization can connect Asana, so teams must involve someone with those Socket permissions before they can use the integration.
  • The integration supports multiple Asana workspaces in one Socket organization, which is useful for routing alerts to different projects and teams rather than forcing all remediation work into one workspace.
  • Ticketing rules can target alerts by attributes such as type, priority, and repository, allowing teams to send high-priority findings to a different workflow than lower-priority findings.
  • The two-way sync can reduce cleanup work after remediation because completing a linked Asana task can automatically triage-ignore the related Socket alert.
Key Points
