Ninja Forms plugin flaw exploited to hack WordPress sites
bleepingcomputer.com · 06 Oct 2026 21:00 UTC openai-codex / gpt-5.6-terra
TAGScve-2026-93836cve-2026-94504hidden-administrator-accountimgcdn1-comninja-formspatchstackstored-cross-site-scriptingunauthenticated-file-managerwoocommercewordpresswp-smart-thumbnailswpc-product-bundles-for-woocommerce
93
In plain words

Hackers are using weaknesses in older versions of the Ninja Forms and WPC Product Bundles add-ons for WordPress to take control of websites after a site administrator views a booby-trapped form submission or order. More than 500,000 sites use Ninja Forms, while more than 30,000 use WPC Product Bundles, so many website owners may be at risk. The intruders can add administrator accounts that are hidden from the normal user list and leave other ways to return even after one malicious add-on is removed, meaning an infected site may remain under their control. Updating the add-ons blocks new break-ins but does not clean up sites already affected.

Summary
Attackers are actively exploiting stored XSS flaws in outdated Ninja Forms and WPC Product Bundles for WooCommerce plugins to install backdoors and create hidden WordPress administrator accounts. Administrators should update to Ninja Forms 3.15.4+ and WPC Product Bundles 8.6.7+ and investigate existing sites for compromise, since patching alone does not remove persistence.

Hackers are exploiting stored cross-site scripting flaws in the Ninja Forms and WPC Product Bundles for WooCommerce WordPress plugins to compromise sites. The affected versions are Ninja Forms 3.15.3 and earlier, tracked as CVE-2026-94504, and WPC Product Bundles for WooCommerce 8.6.6 and earlier, tracked as CVE-2026-93836. Patchstack observed attacks against WPC Product Bundles users on October 4 and against Ninja Forms users the following day, with both campaigns using JavaScript delivered from imgcdn1[.]com.

The attackers insert malicious JavaScript into WooCommerce order data or Ninja Forms submissions, where it runs after a logged-in WordPress administrator opens the content. The script uses the administrator’s session to install a fake plugin called “WP Smart Thumbnails” and create administrator accounts. The compromise provides several ways back into a site, including a hidden administrator account, a secret login URL, and an unauthenticated file manager; some persistence remains even if the visible malicious plugin is removed.

Ninja Forms is installed on more than 500,000 sites, while WPC Product Bundles for WooCommerce is active on more than 30,000 sites. Administrators are advised to update to Ninja Forms 3.15.4 or later and WPC Product Bundles for WooCommerce 8.6.7 or later. Updating prevents further exploitation but does not remove existing infections, so administrators are also urged to check their sites for signs of compromise.

  • Although the flaws require an authenticated session to be exploited, an attacker can trigger the takeover when a legitimate WordPress administrator simply opens a malicious order or form submission.
  • The same JavaScript payload was served from imgcdn1[.]com in both plugin campaigns, which Patchstack says indicates the same threat actor is likely behind them.
  • Removing the fake “WP Smart Thumbnails” plugin may not eliminate the compromise because separate auxiliary plugins preserve the hidden account and secret login route.
  • The hidden administrator account is designed not to appear in the WordPress user list, administrator filter, or displayed user totals, despite retaining full administrator privileges.
  • The auxiliary attack plugins use backdated timestamps to make detection more difficult.
Key Points
  • 01Attackers are exploiting stored cross-site scripting flaws in Ninja Forms versions 3.15.3 and earlier and WPC Product Bundles for WooCommerce versions 8.6.6 and earlier.
  • 02The attacks place malicious JavaScript in WooCommerce order data or Ninja Forms submissions, which runs when a logged-in WordPress administrator views the content.
  • 03The script installs a malicious plugin posing as “WP Smart Thumbnails” and creates administrator accounts, including one hidden from the WordPress dashboard’s user list.
  • 04The infection provides multiple ways to regain access, including a secret login URL and an unauthenticated file manager, and some persistence remains even if the malicious plugin is removed.
  • 05Administrators should update to Ninja Forms 3.15.4 or later and WPC Product Bundles for WooCommerce 8.6.7 or later, while checking for compromise because updates do not remove existing infections.

Linux Backdoors Impersonate Email Security Tools to Evade Detection in Korea and Taiwan
thehackernews.com · 06 Oct 2026 18:24 UTC openai-codex / gpt-5.6-terra

In plain words

Researchers found hidden programs on Linux-based telecom and network devices in South Korea and Taiwan that pretend to be familiar email-security software so they are less likely to be noticed. These programs can give attackers remote control, let them copy or delete files, and route communications through the infected device. This matters because telecom and edge devices sit at important points in a network, so compromising them can support spying and make it harder for organizations to detect unauthorized access.

Summary
Rapid7 uncovered Linux backdoors targeting telecom and edge appliances in South Korea and Taiwan that masquerade as local email-security tools and use covert BPF- and SMTP-based communications. The malware, including BPFDoor, Rekoobe, and the newly identified AVERAT, enables remote shell access, file transfer, proxying, and persistence while evading conventional network detection.

Rapid7 reported Linux backdoors targeting telecom and network appliances in South Korea and Taiwan that disguise themselves as legitimate email-security products and ordinary system processes. The activity includes a new BPFDoor variant and a BPF Rekoobe build aimed at South Korean systems, as well as a previously unreported implant called AVERAT deployed against Taiwanese ShareTech appliances. The samples impersonate products such as SpamSniper and ShareTech, while another BPFDoor artifact uses the process name “ora_ppmond,” resembling Oracle-related process naming.

BPFDoor uses Berkeley Packet Filter functionality to inspect incoming network traffic and activates after receiving a magic packet; Rapid7 said operators have also placed this trigger inside standard HTTPS POST requests. Once activated, it can launch TinyShell to provide interactive access and support file uploads and downloads. AVERAT communicates with its command server over TCP port 25 using SMTP and supports functions including file transfer, process enumeration and termination, interactive shells, proxying, rebooting, and loading shared-object modules. Rapid7 recommended reviewing unexpected raw packet sockets and BPF filters, auditing outbound port 25 traffic from non-mail processes, identifying suspicious daemon-like process names, and limiting management access to edge devices.

  • The implants use regionalized impersonation: South Korea-focused samples mimic SpamSniper components, while malware on Taiwanese appliances is staged from a ShareTech add-on directory and derives an encryption key from the string "ShareTech."
  • BPFDoor operators adapted after static network signatures were developed by placing their trigger inside standard HTTPS POST requests, relying on SSL offloading in telecom environments to make it harder for conventional inspection to see.
  • The Rekoobe-based backdoor watches network traffic specifically associated with port 25 and names its processes after SpamSniper components, combining traffic monitoring with product-specific disguise.
  • AVERAT’s dropper deletes both its staged payload files 10 seconds after execution, while the remaining implant can change its callback settings, command server details, and capabilities at runtime.
Key Points
  • 01Rapid7 identified Linux backdoors targeting telecom and network appliances in South Korea and Taiwan that impersonate local email-security products and legitimate-looking processes.
  • 02The activity includes a new BPFDoor variant and a BPF Rekoobe build against South Korean targets, plus a previously unreported Linux implant named AVERAT deployed against Taiwanese ShareTech appliances.
  • 03BPFDoor uses Berkeley Packet Filter functionality to inspect incoming traffic and activates only after detecting a magic packet, with some operators wrapping triggers in HTTPS POST requests to evade network inspection.
  • 04AVERAT uses SMTP for command-and-control, periodically contacts mx.zxopfds[.]com over TCP port 25, and supports file transfers, process control, interactive shells, proxying, rebooting, and loading additional modules.
  • 05Rapid7 recommended that organizations review unexpected raw packet sockets and BPF filters, audit outbound TCP port 25 connections from non-mail processes, look for processes masquerading as common daemons, and restrict management access to edge appliances.

In plain words

Researchers found fake websites posing as advertising services for popular AI chatbots such as ChatGPT, Gemini, and Claude. These sites use convincing fake sign-in pop-ups to steal usernames, passwords, and one-time verification codes from advertising agency staff and business account managers. Stolen ad accounts can be used to spend a company’s advertising budget, sold to others, and may take weeks or months for the real owner to recover, affecting both agencies and their clients.

Summary
Researchers uncovered a phishing platform that impersonates AI advertising tools for ChatGPT, Gemini, Claude, and other brands, using browser-in-the-browser fake login windows to steal credentials and MFA codes. The campaign targets ad-account administrators and agencies, enabling attackers to hijack and monetize valuable advertising accounts.

Researchers at Island disclosed a human-operated phishing platform that imitates advertising tools for AI brands including ChatGPT, Gemini, Claude, Perplexity, Meta Muse, and Manus. The fake sites claim to offer services such as campaign optimization, spending audits, and advertising-account connections. They are intended to steal login credentials and multi-factor authentication codes from agency staff, media buyers, and advertising-account administrators.

Clicking a “Connect” button opens a convincing fake sign-in window inside the victim’s real browser, with an address bar that appears to show trusted services such as Google Accounts or Okta. The platform records password attempts, fingerprints the device, exchanges data with an operator through Socket.IO, and lets the operator select the next verification challenge shown to the victim. Stolen advertising accounts can be used to run unauthorized campaigns or sold, while attackers may add their own administrators and reduce the legitimate owner’s access, making recovery take weeks or months.

  • The phishing operation can adapt in real time because operators select which MFA prompt a victim sees after receiving the victim’s device information and password attempt.
  • The scammers rapidly build credibility by tailoring each fake AI brand’s advertising pitch, such as campaign planning, spend audits, or manager-account support, rather than using one generic landing page.
  • The same underlying platform supports unrelated fraud themes, including Google Ads payment claims and fake recruitment sites, and its earlier source code was exposed through publicly accessible GitHub repositories.
  • Removing a payment card may be quick after an ad-account takeover, but attackers can add their own administrators and reduce the real owner’s access, leaving account recovery to take weeks or months.
Key Points
  • 01Researchers identified a human-operated phishing platform that impersonates advertising products for AI chatbot brands including Google Gemini, Anthropic Claude, OpenAI ChatGPT, Perplexity, Meta Muse, and Manus.
  • 02The fake sites use a browser-in-the-browser technique that displays counterfeit login windows with trusted-looking address bars to capture account credentials and MFA codes.
  • 03The platform fingerprints victims' devices, sends data through Socket.IO endpoints, and enables operators to choose the MFA challenge presented during a login flow.
  • 04The AI advertising campaign targets agency staff, media buyers, and manager-account administrators, whose accounts may be used for unauthorized advertising or sold for profit.
  • 05Island said the broader platform also includes Google Ads refund and payment scams and fake recruitment sites impersonating Tesla, Louis Vuitton, Nike, and Adecco.

In plain words

Socket has started experimentally checking extensions from the VS Code Marketplace, which are add-ons that developers install in their coding program. This matters because a harmful add-on, or a later harmful update to a trusted one, can read company code and passwords, send data elsewhere, or run programs on a developer’s computer. GitHub said a malicious update to the Nx Console extension led to the theft of internal code repositories, showing that one compromised add-on on one employee’s machine can affect an entire organization.

Summary
Socket has launched experimental scanning for more than 100,000 VS Code Marketplace extensions to help organizations detect risky or malicious behaviors before installation or automatic updates. The move follows incidents such as the compromised Nx Console update and Socket’s GlassWorm investigation, which showed extensions can steal code, download payloads, and execute processes.

Socket has launched experimental scanning for VS Code Marketplace extensions, adding coverage for more than 100,000 extensions alongside its existing Open VSX coverage. The service is intended to help teams assess extensions before adopting them, including the tools developers use in environments containing source code, credentials, and company infrastructure. Socket says its analysis examines extension code, dependencies, activation patterns, and capabilities such as file access, network activity, process execution, bundled executables, obfuscation, and hidden functionality.

The announcement highlights the risk of malicious extension updates, noting GitHub’s disclosure that a poisoned update to the legitimate Nx Console extension on an employee device led to the exfiltration of internal repositories. Socket also cites its GlassWorm investigation, which connected four VS Code Marketplace extensions and six Open VSX extensions, including two confirmed malicious extensions. One malicious theme used encrypted JavaScript and a Solana dead drop to locate and execute additional payloads, demonstrating that even apparently harmless extensions can conceal harmful behavior.

  • Allowlisting an extension at installation is not sufficient by itself, because automatic updates can replace previously vetted code with malicious code while retaining the same extension name and publisher.
  • Seemingly low-risk extensions such as color themes can be used to conceal harmful behavior; Socket found one theme that downloaded and ran an additional script while hiding the Windows command window.
  • Reviewing an extension in isolation can miss campaign-level risk: Socket linked related GlassWorm extensions through code reuse, shared infrastructure, and publishing patterns, including extensions without active malicious payloads in the analyzed versions.
  • An extension’s activation behavior is a meaningful review factor because it determines when its executable code runs, alongside its access to files, network connections, and external processes.
