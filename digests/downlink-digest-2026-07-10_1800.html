In plain words

Researchers found six flaws in U-Boot, software used to start many embedded Linux devices such as server management controllers, networking equipment, industrial systems, internet-connected devices, and other appliances. These flaws could let attackers crash devices or run harmful code very early, before the main operating system and its security protections start. Fixes have been accepted into U-Boot, but each hardware maker must include them in its own updates, and older devices that no longer get updates may never be fixed.

Summary
Six vulnerabilities in the widely used U-Boot bootloader could let attackers crash devices or run malicious code before the operating system loads, enabling stealthy and persistent firmware compromise. Patches are upstream, but affected devices remain at risk until hardware vendors ship firmware updates, and older unsupported products may never be fixed.

Binarly disclosed six vulnerabilities in the widely used U-Boot bootloader that could allow attackers to execute malicious code during device boot or crash vulnerable devices. U-Boot is used in many embedded Linux devices, including enterprise servers’ Baseboard Management Controllers, networking equipment, industrial systems, IoT devices, and other appliances. Because U-Boot loads the operating system, flaws in this component can affect a device before the operating system and its security software start.

The vulnerabilities are in U-Boot’s FIT signature verification code, which is tied to checking firmware images during startup. Binarly said two of the flaws can potentially lead to arbitrary code execution during firmware verification, while four others can be exploited to crash vulnerable devices. The disclosed issues include BRLY-2026-037 through BRLY-2026-042, covering memory corruption, out-of-bounds read, null pointer dereference, improper validation of externally stored firmware data, and unbounded recursion.

Binarly said most of the vulnerable code has existed since U-Boot version 2013.07, potentially affecting more than 50 stable releases and downstream vendor forks. The company reported the vulnerabilities to U-Boot maintainers and submitted patches for all six issues, which have been accepted upstream. However, hardware manufacturers must incorporate the fixes into their own firmware updates before customers receive them, and older or unsupported devices may never be patched.

  • The flaws are especially difficult to remediate at scale because U-Boot fixes must pass through individual hardware vendors before reaching customers, even though patches have already been accepted upstream.
  • Devices that support remote firmware updates, such as BMCs, may be exposed without an attacker needing physical access if the management interface has already been compromised.
  • The age of the affected code means the issue is not limited to current U-Boot releases and may extend across many vendor-maintained firmware forks.
  • Older or unsupported devices may remain permanently vulnerable because they may never receive firmware updates containing the accepted fixes.
Key Points
  • 01Binarly disclosed six vulnerabilities in U-Boot's FIT signature verification code that range in impact from denial of service to arbitrary code execution during verification of an untrusted image.
  • 02U-Boot is widely used in embedded Linux devices, including enterprise servers' Baseboard Management Controllers, networking equipment, industrial systems, IoT devices, and other appliances.
  • 03Two of the flaws can potentially lead to arbitrary code execution during firmware verification, while the remaining four can be exploited to crash vulnerable devices.
  • 04Most of the vulnerable code has existed since U-Boot version 2013.07, potentially affecting more than 50 stable releases and downstream vendor firmware forks.
  • 05Patches for all six issues have been accepted upstream, but hardware manufacturers must incorporate the fixes into their own firmware updates before customers receive them.

The European Parliament voted to revive a rule allowing big tech companies to voluntarily scan users’ messages for child sexual abuse material. The rule dates to 2021 and had expired in April after lawmakers could not agree on how to proceed amid privacy objections. The renewed legal cover allows companies such as Google, Microsoft, and Meta to continue these scans until 2028.

The vote took place the day before summer recess under an unusual procedure that required an absolute majority to block the provision, meaning absent lawmakers counted in practice as support for it. Critics said this was especially concerning because Parliament had rejected the same measure three months earlier under normal circumstances. A larger debate continues over a proposed permanent framework called Chat Control 2.0, which in its most extreme form could require providers to scan conversations and hosted content, including in end-to-end encrypted communications.

  • The measure passed despite more present lawmakers opposing it than supporting it because the procedure treated absent lawmakers as votes in favor unless an absolute majority voted to kill the provision.
