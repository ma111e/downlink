In plain words

Check Point released fixes for a serious weakness that could let an outsider take complete control of computers used to manage its firewalls and store their activity records. Organizations using Check Point Security Management Server or Log Server are affected, and attackers do not need an account or anyone to click anything to abuse it. If left unpatched, the flaw could allow criminals to control security systems that protect and monitor a company’s network, so Check Point recommends installing the update or limiting access to trusted networks.

Summary
Check Point patched CVE-2026-91843, a critical stack-based buffer overflow in Security Management Server and Log Server login handling that can give unauthenticated attackers root-level remote code execution. Organizations should apply the LivePatch promptly or restrict trusted clients and monitor for "Username too long" failed-login alerts.

Check Point released security updates for CVE-2026-91843, a critical stack-based buffer overflow in the login process for Security Management Server instances. The issue also affects Check Point Log Server systems, which collect and store firewall logs. Successful exploitation can let an attacker without privileges execute code remotely with root-level access in a low-complexity attack requiring no user interaction.

Check Point said organizations unable to deploy the latest LivePatch can harden affected systems and restrict SmartConsole access to trusted IP addresses or subnets. Teams can look for the alert “Administrator failed to log in: Username too long” in Audit and Admin login logs to identify possible attempts. Although Check Point has not marked CVE-2026-91843 as exploited in the wild, the company recently patched other critical flaws affecting its firewalls and management systems, and the Dutch NCSC warned exploitation of two of those flaws may occur soon.

  • A specific failed-login message, "Administrator failed to log in: Username too long," provides a concrete indicator that security teams can search for in Audit and Admin login logs.
  • Organizations that cannot immediately install the LivePatch can reduce exposure by limiting SmartConsole trusted-client access to approved IP addresses or subnets.
  • The related CVE-2026-85103 flaw affects all Security Management Server deployments regardless of configuration, including systems where VPN functionality is not used or configured.
  • Check Point has recently faced multiple critical flaws affecting firewalls and management systems, while two earlier authentication-bypass zero-days were already exploited in attacks.

In plain words

Researchers say a person claiming to be a bug bounty hunter uploaded more than 100 harmful software packages to npm, a popular download site used by developers. When installed, the packages could collect login tokens, code-hosting credentials, and secrets used by automated software-building systems from developers’ computers. The stolen information may have been used to find weaknesses in company systems and seek rewards, showing how fake software downloads and AI-assisted code can make it easier to target organizations.

Summary
CrowdStrike links the PhantomRaven npm campaign to a purported bug bounty hunter who likely used an LLM to create a JavaScript stealer that harvested developer credentials, CI/CD secrets, and system data. The actor allegedly used malicious npm and PyPI packages to compromise targets and identify vulnerabilities for bounty claims.

CrowdStrike linked the development and distribution of the JavaScript information stealer PhantomRaven to a financially motivated actor who claimed to be a bug bounty hunter. The company assessed with high confidence that the malware was likely created with help from a large language model, citing verbose comments, placeholder code, and token-analysis patterns. PhantomRaven was first reported by Koi Security and DCODX in late October 2025 in a campaign involving more than 100 malicious npm packages.

The packages used typosquatting and slopsquatting, then retrieved code from an external server so the harmful functionality was less likely to be detected in the published packages themselves. Once installed, the code gathered authentication tokens, CI/CD secrets, GitHub credentials, public IP addresses, email addresses, Git and npm configuration details, and environment variables from GitHub Actions, GitLab CI, Jenkins, and CircleCI. CrowdStrike said the actor may have used the stolen information to identify bug bounty opportunities rather than sell it, and linked the operation to similar attempts involving the PyPI repository.

  • The campaign used remotely retrieved code so the published npm packages could appear less suspicious to security tools while still delivering the information stealer after installation.
  • PhantomRaven targeted development environments broadly, collecting data from Git and npm settings as well as automation systems including GitHub Actions, GitLab CI, Jenkins, and CircleCI.
  • CrowdStrike said it had not found stolen PhantomRaven data in stealer-log shops, supporting its assessment that the operator likely used the collected information to identify bug bounty opportunities rather than resell it.
  • The same operator was linked to attempts to distribute similar information-stealing code through both npm and PyPI, extending the activity across two major developer package repositories.
  • CrowdStrike’s assessment that an LLM likely helped create the malware highlights that the actor may have reduced the effort needed to develop proprietary tooling.

thehackernews.com · 18 Sep 2026 06:17 UTC openai-codex / gpt-5.6-terra

In plain words

Researchers found a new Android threat called RatHat that is spread through fake download sites, deceptive ads, and text-message scams that trick people into installing harmful apps. It can steal passwords, text messages, screen activity, and phone unlock details, and may keep remote control of a phone even after the victim deletes the app. This matters because attackers could use that access to take over accounts, bank information, and other sensitive data from affected Android users.

Summary
Researchers identified RatHat, an Android malware attributed to China-based actors that abuses Accessibility permissions and wireless ADB pairing to gain persistent shell access even after the malicious app is uninstalled. It uses AI-assisted device navigation, credential overlays, SMS interception, screen recording, and reverse tunnels for remote control.

Researchers at Zimperium have identified RatHat, an Android malware assessed to be operated by China-based threat actors. It is distributed through targeted text-message phishing, malicious advertisements, deceptive download portals, and third-party forums that prompt users to install malicious APK files. The initial app acts as a dropper and includes several anti-analysis measures intended to hinder automated inspection.

RatHat abuses Android Accessibility permissions to unlock Developer Options, enable Wireless Debugging, and obtain an Android Debug Bridge pairing code. It then uses local Android Debug Bridge access to run a Go-based agent with shell-level privileges and an FRP reverse tunnel that gives operators continuing access to the device. This access can remain after the malicious app is uninstalled, and the separate component can check whether the app is present and reinstall it.

The malware can use fake overlays to capture credentials, record screens, intercept SMS messages, collect files and lock-screen details, capture keystrokes, and record touches on the display. It also sends the device’s live Accessibility screen data to a generative AI assistant to identify on-screen text, find locations for automated taps, and navigate actions such as scrolling. Zimperium said the combination of independently running components, persistent device access, and real-time AI decision loops makes signature-based mobile security controls insufficient.

  • RatHat’s use of local wireless debugging allows it to move beyond normal Android app restrictions by creating separate programs that run with device shell privileges.
  • Removing the visible malicious app may not remove the attacker’s access, because its independently running component can check for the app and reinstall it.
  • The malware is designed to hinder automated inspection through package manipulation, malformed manifest data, poisoned code instructions, and encrypted strings.
  • Its use of a reverse tunnel gives operators a general route to the device’s debugging service, rather than limiting them to RatHat’s built-in data-stealing features.
  • The malware uses a generative AI assistant to turn live screen-accessibility data into automated actions, such as locating screen elements and scrolling.
Key Points
  • 01Researchers at Zimperium identified RatHat, an Android malware assessed to be operated by China-based threat actors and distributed through smishing, malvertising, deceptive download portals, and third-party forums.
  • 02RatHat abuses Android Accessibility permissions to unlock Developer Options, enable Wireless Debugging, and obtain a six-digit Android Debug Bridge pairing code.
  • 03After gaining local Android Debug Bridge access, RatHat can run a Go-based agent and establish a reverse tunnel through FRP, allowing attackers to retain shell access even if the malicious app is uninstalled.
  • 04The malware can display credential-stealing overlays, record the screen, intercept SMS messages, collect device data and lock-screen credentials, capture keystrokes, and log screen touches.
  • 05RatHat sends the device’s Accessibility screen data to a generative AI assistant to identify on-screen text, locate targets for automated taps, and issue navigation actions such as scrolling.

In plain words

A Microsoft security update, KB5002914, caused some Excel users to be unable to copy and paste, fill cells automatically, or drag formulas, often without any warning that the action failed. Microsoft has released KB5002665 to fix the problem for the installer-based version of Office 2016, while users of Excel Online and Excel 2019, 2021, and 2024 still need to use Paste Special as a workaround. Removing the faulty update can restore normal behavior, but it also removes fixes for serious security flaws that could let others run code or view information.

Summary
Microsoft released KB5002665 to fix silent copy-and-paste, autofill, and formula-dragging failures caused by the KB5002914 security update, but only for MSI-based Office 2016 installations. Users of other affected Excel versions should use Paste Special until a broader fix is available.

Microsoft released KB5002665 to address a problem caused by the September 2026 KB5002914 security update, which made some Excel copy-and-paste operations fail silently. The issue also affected autofill and formula dragging, with users receiving no error message or other indication that the destination cell was unchanged. Microsoft attributed the problem to a code regression.

The new update fixes the issue only for Microsoft Installer-based Office 2016 installations and does not apply to Office 2016 Click-to-Run editions such as Microsoft Office 365 Home. Excel Online and Excel 2019, 2021, 2024, and 2016 users remain affected, and Microsoft recommends using Paste Special, including the Ctrl+Alt+V shortcut, as a temporary workaround. Although uninstalling KB5002914 can restore normal copy-and-paste behavior, doing so also removes patches for remote code execution and information disclosure vulnerabilities.

  • The failure can be difficult to detect because Excel leaves the source selected and provides no beep or error message while making no change at the destination.
  • Microsoft's released fix is limited to MSI-based Office 2016, so even some Office 2016 users on Click-to-Run editions do not receive the remedy.
  • Using Paste Special with Ctrl+Alt+V provides a temporary way to paste formulas, values, formats, or links without removing the security update.
  • Rolling back KB5002914 may restore normal copy-and-paste behavior, but it also removes numerous fixes for remote code execution and information disclosure issues.
