In plain words

Google released September 2026 security updates for Pixel phones to fix 110 problems, including one that may already be used in carefully chosen attacks. The most urgent issue affects the phone’s cellular connection and could let someone nearby gain more control over a targeted device without the owner doing anything. Pixel owners should install the update, because it reduces the risk of unauthorized access to their phones.

Summary
Google’s September 2026 Pixel update fixes 110 flaws, including CVE-2026-58704, an actively exploited modem vulnerability that can enable nearby attackers with basic device privileges to escalate access without user interaction. Pixel users should install the September security update promptly.

Google released its September 2026 security patches for Pixel devices, fixing 110 vulnerabilities. The update includes CVE-2026-58704, a high-severity cellular modem flaw that Google says may be under limited, targeted exploitation. Google urged owners of supported devices to install the 2026-09-05 patch level.

CVE-2026-58704 is caused by authorization and protection failures, including a logic error that can bypass permissions in the cellular modem. An attacker on an adjacent network who already has basic privileges on a targeted device could gain higher privileges without user interaction. The bulletin also covers 109 additional issues, including 12 remote-code-execution vulnerabilities and 89 privilege-escalation vulnerabilities rated critical or high severity.

  • The actively exploited flaw is in the cellular modem, meaning the described attacker position is on a nearby or adjacent network rather than requiring the phone owner to interact with a malicious link or app.
  • Google’s description says the flaw requires an attacker to already have basic privileges on the targeted device, but it can then provide higher privileges through a low-complexity logic error.
  • Pixel devices receive their own security bulletins and updates separately from the standard monthly Android patches because Google directly controls their hardware platform and exclusive features.
  • Beyond the actively exploited modem issue, the update includes 12 remote-code-execution flaws and 89 privilege-escalation flaws rated critical or high severity.
Key Points
  • 01Google released September 2026 security patches for Pixel devices that address 110 vulnerabilities.
  • 02Google said CVE-2026-58704, a high-severity flaw in the cellular modem component, may be under limited targeted exploitation.
  • 03The modem flaw can allow an attacker on an adjacent network with basic privileges on a targeted device to gain higher privileges without user interaction.
  • 04The Pixel bulletin also lists 109 other issues, including 12 remote-code-execution flaws and 89 privilege-escalation flaws rated critical or high severity.
  • 05Pixel users can install the update through Settings, then Security & privacy, System & updates, and Security update.

How to Mitigate the Lethal Trifecta That Infects 98% of Agents
netskope.com · 16 Sep 2026 07:01 UTC openai-codex / gpt-5.6-terra
TAGScloud-security-alliancejailbreakingmitre-atlasmodel-context-protocolnetskopeowasp-top-10-for-llm-applicationsprompt-injection
45
In plain words

The article warns that an AI helper can be tricked into stealing private company information when it can read sensitive data, consume material from outside sources, and send information elsewhere. A malicious instruction hidden in a document, email, web page, or other content may persuade the helper to act against its owner’s wishes. Companies and employees using AI helpers are affected, especially as more people create their own, and the stakes include exposing business data or allowing unwanted real-world actions. The article recommends splitting high-risk tasks between separate helpers and limiting what each one can read, access, and send.

Summary
AI agents become highly vulnerable to prompt-injection-driven data theft when they combine access to sensitive data, untrusted content, and outbound actions. Reduce the risk by separating these capabilities across agents and enforcing least privilege, content inspection, DLP, and action controls.

The article discusses the “lethal trifecta” for AI agents: access to private data, exposure to untrusted content, and the ability to communicate externally or take consequential actions. It states that when all three capabilities coexist, malicious instructions embedded in documents, emails, web pages, images, or third-party responses can trick an agent into accessing sensitive information and sending it to an attacker. The article distinguishes prompt injection, which targets applications built on language models, from jailbreaking, which attempts to bypass protections built into the models themselves.

The article recommends designing workflows so that no single agent has all three capabilities, such as separating a document-reading agent from an action-taking agent that cannot directly access untrusted material. For existing agents that cannot immediately be redesigned, it recommends identifying agent capabilities, inspecting incoming content, converting documents to flat PDFs, restricting privileges and approved tools, applying data-loss-prevention policies, and governing outbound actions. It also recommends analyzing prompts and responses for jailbreaks, prompt injections, and multi-turn attacks, while noting that employees may create personal agents without knowing how to secure them.

  • The article argues that the most effective architectural safeguard is to ensure no single AI agent simultaneously handles untrusted material, sensitive data, and external actions.
  • An action-taking agent can be constrained to accept instructions only from authenticated internal orchestrators, rather than directly from arbitrary external content.
  • Converting common document formats to flat PDFs before AI agents consume them is proposed as a way to reduce risk from documents that may contain executable code or malicious instructions.
  • Controlling outbound actions is presented as particularly significant because it can break the path that allows an agent’s access to private data and untrusted input to result in data theft.
  • The article notes that personal agents created by employees may lack security safeguards because people may not know how to build them more safely.
Key Points
  • 01The article describes the AI-agent “lethal trifecta” as the combination of access to private data, exposure to untrusted content, and the ability to communicate or act externally.
  • 02When an agent has all three capabilities, malicious instructions in untrusted content can trick it into accessing private data and sending it to an attacker.
  • 03The article distinguishes prompt injection, which attacks applications built on language models, from jailbreaking, which attempts to bypass protections built into the models themselves.
  • 04The article recommends designing automation as multiple agents, such as separating a document-reading agent from an action-taking agent that does not directly receive untrusted content.
  • 05For agents that cannot immediately be redesigned, the article recommends discovering agent capabilities, inspecting incoming content, enforcing least-privilege access and data-loss controls, governing agent actions, and analyzing prompts and responses for malicious instructions.
