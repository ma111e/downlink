Attackers Exploit Critical Siemens IoT2050 Flaw to Plant Remote Command Backdoors
thehackernews.com · 03 Nov 2026 05:34 UTC openai-codex / gpt-5.6-terra
TAGSarbitrary-command-executioncve-2026-58115industrial-osnode-redsiemenssimatic-iot2050-advanced
94
In plain words

Attackers are actively taking advantage of a serious weakness in Siemens SIMATIC IoT2050 Advanced industrial devices when they have the Node-RED software installed. The flaw can let someone on the internet take control of an affected device without a password, download harmful programs, or leave a hidden way to run commands later. This matters because these devices are used in industrial settings, and Siemens says users should update them or remove or secure the affected software.

Summary
Attackers are actively exploiting CVE-2026-58115, a critical unauthenticated Node-RED flaw in Siemens SIMATIC IoT2050 Advanced devices, to deploy malicious flows that download malware or create persistent remote command backdoors. Organizations should update to version 4.3.4.1 or later or remove and properly secure Node-RED.

Attackers are actively exploiting CVE-2026-58115, a maximum-severity flaw affecting Siemens SIMATIC IoT2050 Advanced devices running Industrial OS with Node-RED installed. The missing authentication in Node-RED’s HTTP interface allows an unauthenticated remote attacker to create malicious flows and execute code on the underlying server with maximum privileges. VulnCheck observed attempts against its honeypots as of October 30, 2026.

Observed exploits deployed and automatically triggered Node-RED flows that downloaded a Linux bot binary from an attacker-controlled server, with the request hidden behind three encoding layers. The payload was saved as /dev/shm/.b and executed, while later activity used a two-stage downloader or saved a payload as /tmp/.kworker. Other flows created HTTP command backdoors that could execute commands supplied through a query parameter. Siemens fixed the issue in version 4.3.4.1 or later and recommends uninstalling Node-RED or securing its access with HTTPS and authentication.

  • The observed exploit was end-to-end automated: it installed a Node-RED flow, triggered that flow, and downloaded a binary from an attacker-controlled server, while concealing the request behind three encoding layers.
  • Attackers shifted from directly downloading a bot binary to a two-stage process that first retrieves a shell script named "wget.sh," indicating that the delivery method changed during the observed campaign.
  • Some malicious flows did not download a payload at all; instead, they exposed HTTP paths such as "/cmd" and passed query-parameter input to command execution, allowing attackers to send commands later.
  • The article notes that this HTTP-based backdoor can remain available even when a memory-backed implant disappears after a reboot.
Key Points
  • 01CVE-2026-58115 is a maximum-severity missing-authentication flaw affecting Siemens SIMATIC IoT2050 Advanced devices running Industrial OS with Node-RED installed.
  • 02An unauthenticated remote attacker can use the Node-RED HTTP interface to create malicious flows and execute arbitrary code on the affected server with maximum privileges.
  • 03VulnCheck observed exploitation attempts against its honeypots that deployed Node-RED flows to download and run Linux bot binaries or establish command-execution backdoors.
  • 04Siemens fixed the issue in version 4.3.4.1 and later, and recommends removing Node-RED or securing its access controls.
  • 05Observed payloads were downloaded from attacker-controlled servers and saved under names such as /dev/shm/.b and /tmp/.kworker before execution.

Attackers Target Unpatched CryptoPayment Gateway Flaw That Can Expose Wallet Credentials
thehackernews.com · 03 Nov 2026 05:34 UTC openai-codex / gpt-5.6-terra
TAGScryptopayment-gatewaycve-2026-81648defused-cybernistwordpresswp-scan
88
In plain words

Attackers are trying to use a serious flaw in the CryptoPayment Gateway add-on for WordPress websites. Websites using versions 1.2.1 or 1.2.2 could have payment settings changed, files deleted, and cryptocurrency wallet login details exposed without the owner’s permission. Because no fix is available and the add-on has been removed from WordPress’s download directory, owners should remove it, change their wallet keys, and check for suspicious changes.

Summary
Attackers are actively exploiting CVE-2026-81648, an unpatched CVSS 10 flaw in the CryptoPayment Gateway WordPress plugin that can expose wallet credentials, alter gateway settings, and delete server files. Site owners should remove the plugin immediately, rotate wallet keys, and investigate for unauthorized changes.

Defused Cyber reported that threat actors are attempting to exploit CVE-2026-81648, an unpatched maximum-severity flaw in the CryptoPayment Gateway WordPress plugin. The vulnerability has a CVSS score of 10.0 and affects versions 1.2.1 through 1.2.2, including the latest release. Defused Cyber said it observed exploitation attempts originating from infrastructure advertising “Anonymous KYC-Free VPS Hosting.”

The flaw stems from an AJAX endpoint that lacks an authorization check, allowing unauthenticated users to invoke administrative operations. Attackers could delete arbitrary server files, overwrite payment-gateway settings, and recover stored wallet credentials in cleartext. No fix is known, and the plugin was closed in the WordPress Plugin Directory on August 28, 2026; site owners are advised to remove it, rotate wallet keys, and check for suspicious changes.

  • The affected versions include 1.2.2, the plugin’s latest release, so simply updating the plugin does not address the issue.
  • Stored wallet credentials can be recovered in cleartext, making key rotation necessary even after the plugin is removed.
  • Although the plugin has been closed in the WordPress Plugin Directory, it recorded 20 downloads in the preceding seven days.
  • The exploitation attempts observed by Defused Cyber came from infrastructure advertising “Anonymous KYC-Free VPS Hosting.”
Key Points
  • 01Defused Cyber reported in-the-wild attempts to exploit CVE-2026-81648, a CVSS 10.0 flaw in the CryptoPayment Gateway WordPress plugin.
  • 02The flaw affects CryptoPayment Gateway versions 1.2.1 through 1.2.2 and lets unauthenticated users invoke administrative operations through an AJAX endpoint without an authorization check.
  • 03Successful exploitation can allow arbitrary server-file deletion, payment-gateway configuration overwrites, and recovery of stored wallet credentials in cleartext.
  • 04No fix is known, and the plugin was closed on the WordPress Plugin Directory on August 28, 2026, because of an unspecified security issue.
  • 05Site owners are advised to remove the plugin, rotate wallet keys, and audit their sites for suspicious changes.
