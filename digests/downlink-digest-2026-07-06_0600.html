In plain words

Researchers found that harmful add-ons for AI coding tools can be changed so they look safe to the programs that check them, while still stealing passwords, copying code, or opening backdoors when they run. This affects people and teams using tools like Claude Code, OpenAI Codex, and OpenClaw, especially when they install add-ons from public marketplaces uploaded by strangers. The broader risk is that a “passed” safety check may not mean much if the harmful behavior only appears after the add-on starts running, so the real protection has to include watching what it actually does on the user’s machine.

Summary
Researchers found that malicious AI agent “skills” can evade static scanners at high rates using simple obfuscation and self-extracting payloads, while still running normally on tools like Claude Code and OpenAI Codex. The key takeaway is that teams should not trust scan badges alone and need runtime behavior monitoring, least-privilege access, and stricter vetting for agent extensions.

Researchers at the Hong Kong University of Science and Technology found that scanners meant to detect malicious AI agent skills can be bypassed by disguised skills that still work as intended. Their paper, “Cloak and Detonate,” tested these techniques against eight scanners and 1,613 malicious skills from ClawHub. The strongest method, self-extracting packing, bypassed every scanner tested more than 90% of the time, and most of them more than 99% of the time.

The researchers’ tool, SKILLCLOAK, disguises malicious skills in two ways: by rewriting scanner-triggering bytes or by hiding the payload in skipped directories such as .git/ and rebuilding it only when the agent runs it. The article says this matters because skills run with the agent’s access to files, terminals, and saved passwords, and a malicious one can steal credentials, copy source code, or install a backdoor. The cloaked skills reportedly worked just as well as the originals on Claude Code and OpenAI Codex.

The researchers also built SKILLDETONATE, a runtime checker that runs skills in a sandbox and watches what they read, write, and send. In controlled testing, it caught 97% of attacks with a 2% false-positive rate, and on real-world malicious skills it caught 87%. The article notes that public marketplaces already contain malicious skills and says static scanning should be treated as a starting point, while the more durable defense is watching what a skill does when it runs.

  • The same design choice that makes skills portable across agents also increases risk, because a single malicious bundle can run across different AI coding agents with the agent’s access to files, terminals, and saved passwords.
  • Scanner performance can collapse after cloaking: Cisco’s scanner reportedly caught 99% of real-world malicious skills before cloaking but only about 10% after cloaking.
  • Directories and limits that scanners ignore for practical reasons, such as skipped .git/ folders or size caps, become useful hiding places for malicious payloads.
  • A one-time marketplace approval is insufficient because several examples in the article involve code or instructions that change, unpack, or get fetched only when the skill or tool runs.
  • Runtime checking is more expensive than static scanning, taking a couple of minutes per skill instead of a few seconds, but the article frames it as a pre-deployment cost rather than a constant runtime burden.
Key Points

  • 02The SKILLCLOAK tool rewrites malicious skills either by altering scanner-triggering bytes or by using self-extracting packing that hides the payload in skipped directories such as .git/.
  • 03Across eight scanners and 1,613 malicious skills from ClawHub, the self-extracting packing method bypassed each scanner more than 90% of the time and bypassed most of them more than 99% of the time.
  • 04The researchers proposed SKILLDETONATE, a sandbox-based runtime checker that watches file access, writes, and data transfers, and caught 97% of attacks in controlled tests with a 2% false-positive rate.
  • 05The article says public marketplaces already contain malicious skills, including Bitdefender’s finding that roughly 17% of skills checked on one marketplace carried hidden malicious code and Koi Security’s count of 341 malicious skills in the ClawHavoc campaign.

In plain words

The article describes phishing campaigns where attackers trick people into copying a one-time code from a fake document page and entering it on a real Microsoft login page, so simply checking that the website is Microsoft is not enough. People using Microsoft work accounts are affected, including users targeted by emails posing as law firm notices or order confirmations, with newer versions aimed at places such as Brazil. If victims approve the request, attackers can get access to their email, OneDrive files, and Teams conversations without stealing the password directly.

Summary
Attackers are abusing Microsoft’s legitimate Device Code Flow to trick users into entering one-time codes on official Microsoft pages, allowing them to obtain access and refresh tokens even when MFA is completed. Organizations should disable Device Code Flow where unnecessary and monitor DeviceCodeSignIn events for anomalous activity.

The article describes a Device Code Phishing campaign that abused Microsoft’s legitimate Device Authorization Grant flow. Instead of asking victims to enter credentials on a fake domain, attackers guided them to enter a one-time code on Microsoft’s real authentication page. This undermines the common advice to only check whether a login page is on the correct domain. The campaign observed by Kaspersky ran from early April to mid-May 2026 and used phishing emails styled as law firm notices with password-protected PDF attachments.

The attack flow led victims from a PDF link through redirects and CAPTCHA pages to a phishing page that displayed a one-time code fetched by the attacker’s server-side application. Clicking the code copied it to the clipboard and redirected the victim to Microsoft’s official device login page, where the victim entered the code and completed MFA. After successful authentication, the attacker obtained access_token, refresh_token, and id_token values, enabling access to the victim’s mailbox, OneDrive files, and Teams conversations. The article also describes a later Portuguese-language variant targeting users in Brazil that used Cacoo.com as a trusted open redirect before sending victims to the same type of code-entry flow.

The article recommends that users avoid entering authorization codes from unexpected emails or messages, even when the link points to an official Microsoft domain. It also advises checking redirect parameters such as redirect_uri, return_url, or next and confirming the final loaded URL before entering corporate credentials. For enterprises, it recommends evaluating whether Device Code Flow is needed, disabling it globally through Conditional Access policies if not required, monitoring DeviceCodeSignIn events, enforcing device compliance states, and alerting on unusual sign-in behavior.

  • Checking for a legitimate Microsoft domain is insufficient in this scenario because the victim completes the decisive step on Microsoft’s real authentication page rather than on a fake login form.
  • MFA does not prevent this attack when the user is tricked into approving the Device Authorization Grant flow, because successful authentication causes tokens to be issued to the attacker-controlled application.
  • The refresh_token is especially important because it lets the attacker renew access after the initial access token expires, allowing continued access without further user interaction.
  • Open redirects on trusted services such as Microsoft-linked URLs and Cacoo.com were used to make phishing links appear safer while still routing victims to attacker-controlled infrastructure.
  • Monitoring specifically for DeviceCodeSignIn events is a targeted detection opportunity because the attack relies on the Device Code Flow rather than ordinary password theft.
Key Points
  • 01The article describes a Device Code Phishing campaign in which attackers instructed victims to enter a one-time code on Microsoft’s legitimate device login page as part of the OAuth 2.0 Device Authorization Grant flow.
  • 02In the observed campaign from early April to mid-May 2026, victims received phishing emails styled as law firm notices with password-protected PDF attachments that led them through redirects and CAPTCHA pages to a phishing page displaying a one-time code.
  • 03After victims entered the code and completed MFA on Microsoft’s official page, the attackers obtained access_token, refresh_token, and id_token values that enabled access to email, OneDrive files, and Teams conversations.
  • 04A later variant targeting users in Brazil used an email in Portuguese and a link through the legitimate Cacoo.com domain as an open redirect to the phishing infrastructure.
  • 05The article recommends that users avoid entering unexpected authorization codes and that enterprises consider disabling Device Code Flow if unnecessary, monitor DeviceCodeSignIn events, enforce device compliance, and alert on unusual sign-in behavior.

In plain words

Researchers found a serious flaw in Opera GX, the gaming version of the Opera browser, that let a harmful website add a browser “mod” without asking and use it to pull details from pages the person later visited. In a test, they could rebuild a signed-in user’s full Gmail address after a single visit, with no click needed. Opera says it has fixed the issue in Opera GX version 130.0.5847.89 and found no evidence it was used against real users. It matters because a feature meant only to change how sites look could quietly follow someone across websites and reveal private information before they had a chance to remove it.

Summary
Opera patched a critical Opera GX flaw that let malicious websites silently install GX Mods and use CSS to steal data, such as a signed-in user’s Gmail address, from pages the victim visited. Users should ensure they are on Opera GX version 130.0.5847.89 or later.

Researchers found a flaw in Opera GX, the gaming-focused version of the Opera browser, that let a malicious website silently install a browser mod and use it to steal specific data from pages a victim visited. In a proof of concept, they reconstructed a signed-in user’s full Gmail address from a single visit without requiring any click. Opera patched the flaw in Opera GX version 130.0.5847.89 and said it found no evidence that it had been used in the wild.

The issue came from Opera GX’s mod installation behavior, where GX Mods could be downloaded and enabled automatically without an approval prompt. Although GX Mods cannot run JavaScript and have no permissions, their CSS could apply to every page the browser opened, creating what the researchers called a universal CSS injection. The researchers used CSS attribute selectors to trigger requests to an attacker-controlled server when parts of a hidden value matched, allowing the Gmail address to be rebuilt from overlapping three-letter chunks.

Opera’s bug bounty team ultimately rated the issue P1, its highest severity, and paid the maximum $5,000 award for a critical bug. The article notes that Opera had been warned about the auto-install behavior in 2023, when a researcher used it as part of an address-bar spoofing attack that Opera patched without removing the underlying auto-install path. The researchers also documented a separate crash issue involving loading a .crx file in private mode, which affected regular Opera as well as Opera GX.

  • The attack showed that CSS-only data theft became more dangerous in Opera GX because the injected styling was not limited to one page and could follow the victim across every site the browser opened.
  • The removal notice was not an effective safeguard in the researchers' demonstration because the redirect and data leak could occur within seconds, before a user could realistically read the notice and click Remove.
  • The underlying auto-install behavior had been identified in 2023, but Opera initially patched only the specific address-bar spoofing attack rather than removing the auto-install path that enabled this later issue.
  • The researchers demonstrated the severity to Opera's bug bounty triage team by reconstructing an analyst's own Gmail address during reproduction, after the issue was initially rated only P3.
  • A separate issue documented by the researchers showed that loading a .crx in private mode could crash the browser and dump every open tab, affecting regular Opera as well as Opera GX.
Key Points

  • 03Opera patched the flaw in Opera GX version 130.0.5847.89 and said it found no evidence that the issue was exploited in the wild.

Its builder, loader, and dropper tools are designed to help operators package payloads and evade detection across multiple delivery scenarios.

Cybersecurity researchers have flagged QuimaRAT, a new Java-based remote access trojan capable of targeting Windows, Linux, and macOS environments. LevelBlue says the malware is advertised under a malware-as-a-service model, with prices ranging from \(150 for one month to \)1,200 for lifetime access. The Quima suite includes Quima Control, Quima Builder, Quima Loader, and Quima Dropper, covering remote administration, payload building, browser-based delivery, and HTML/SVG payload generation.

QuimaRAT is described as a modular Java project built using Apache Maven and containing embedded Java Native Access native libraries for multiple operating systems and architectures. The malware also includes environment validation, sandbox and virtual environment evasion, single-instance execution using a lock file, and operating system-specific persistence methods.

The malware can communicate with its command-and-control server over TCP, WebSocket, TLS, or HTTPS, and includes a watchdog component to reconnect if contact is lost. In plain words

Researchers at Shandong University showed that a computer cut off from all networks can still leak stolen data if harmful software is already running on it. Their method, called TrojPix, makes tiny changes to what appears on the screen so the video cable gives off a weak signal that a nearby receiver can read. This mainly matters for highly protected computers that rely on being physically separated from networks, because the tests suggest whole files could be sent out quickly while the screen appears dark or normal.

Summary
Researchers demonstrated TrojPix, a covert channel that lets malware on an air-gapped computer leak data by subtly modulating screen pixels so video cables emit decodable radio signals. It is lab research, but its reported speed of up to 8.1 Mbps shows that once malware is present, air-gapped systems could potentially exfiltrate whole files quickly unless protected with physical shielding, fiber links, and strong malware prevention.

Researchers at Shandong University have demonstrated TrojPix, a technique for leaking data from computers that are cut off from every network. TrojPix works by subtly modifying on-screen pixels in ways people cannot see, causing the video cable carrying them to radiate a faint radio signal that a nearby receiver can decode. The article emphasizes that TrojPix requires malware to already be on the target machine, so it is a way to get stolen data out rather than a way to break in.

In testing, TrojPix reached a peak throughput of 8.1 Mbps and a maximum distance of 208 meters, though those figures were measured separately. The article notes that this speed is much faster than most air-gap covert channels and could move a 100 MB file in under two minutes. It also says real-world range would depend on barriers such as walls, shielding, and noise.

The researchers call the method imperceptible pixel modulation and say it needs no administrator rights or hardware changes, only user-level malware that can draw to the screen. They describe modes that either make the display appear dark as if powered off or hide the signal inside ordinary-looking screen content. Suggested countermeasures include using fiber-optic video links instead of copper, shielding cables and rooms where warranted, and keeping malware off the machine in the first place.

  • TrojPix shifts air-gap leakage from password-sized data to whole-file exfiltration, because its reported 8.1 Mbps peak rate could move a 100 MB file in under two minutes.
  • The channel can operate while the monitor appears switched off or while ordinary-looking content is on screen, so visual inspection of the display may not reveal that data is being transmitted.
  • Because the emission itself cannot be patched away, the article frames the most practical defenses as physical controls such as fiber-optic video links, shielding, and TEMPEST-rated environments.
  • The technique was tested across nine monitor brands and fifteen video cables, indicating the researchers did not find it limited to one narrow hardware setup.
  • Despite its high lab performance, the article emphasizes that real-world practicality depends on conditions such as walls, shielding, and radio noise, and that known real-world air-gap compromises have used USB drives rather than radio leakage.
