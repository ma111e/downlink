Attackers' AI Agents Found a Zero-Day in Medical-Imaging Software and Gained Root Access
thehackernews.com · 21 Nov 2026 11:03 UTC openai-codex / gpt-5.6-terra
TAGSamazoncairnchinacve-2026-133968monai-labelpath-traversalproject-monai
88
In plain words

Suspected China-linked hackers used automated AI tools to find a previously unknown weakness in MONAI Label, software universities use to organize medical scans and train imaging systems. The flaw let anyone who could reach an unprotected server place files where they should not be able to, and on one university server it reportedly led to complete control of the machine. A source-code fix exists but no updated installable version has been released, so exposed users need to limit access and review their systems. The case shows that automated AI tools can speed up the discovery and use of software flaws, potentially putting research systems and the data they handle at greater risk.

Summary
China-linked operators reportedly used Cairn AI agents to discover and exploit a critical path-traversal zero-day in exposed MONAI Label servers, achieving root access on at least one university system. No patched release is available yet, so organizations should restrict network exposure, enable authentication, and run MONAI Label with minimal privileges.

Suspected China-linked operators used Cairn, an open-source framework for automated AI penetration-testing agents, to find a previously unknown flaw in MONAI Label. Amazon Threat Intelligence said the agents mapped the application’s interface and obtained the ability to write files on a university server in roughly 11 minutes. The operator reportedly selected targets and set the goal of gaining shell access, while the agents chose methods independently.

The issue, CVE-2026-133968, is a critical path-traversal flaw affecting MONAI Label 0.8.5 and earlier in the default configuration, where authentication is disabled. It allows a network-reachable, unauthenticated caller to write files outside the intended storage folder; on one university server, the attackers later used this capability to place a Python startup file and gain root access when a training feature launched a new Python process. Project MONAI has merged a source-code fix but has not released a patched package, so affected users are advised to restrict network access, enable authentication, limit service-account permissions, and check exposed systems for unexpected Python startup files or unusual training jobs.

Amazon based its account on a reconstruction aided by an exposed, unprotected Cairn control panel belonging to the operators, which revealed prompts, settings, and run history. The company linked the activity to a China-related actor with moderate confidence based on Simplified Chinese prompts, China Standard Time settings, and target selection, but did not name a group or establish government involvement. The report does not show that patient records were taken or that clinical systems were reached, and it notes that root access on one server does not mean every MONAI Label deployment would be affected in the same way.

  • Amazon reconstructed the campaign because the attackers exposed their own Cairn control panel without a password, revealing agent prompts, task settings, and run history.
  • The reported root compromise was not an automatic result of the file-writing flaw: it depended on placing a Python startup file and triggering a feature that launched a new Python process, and would vary with each server's configuration and permissions.
  • Although the fix has been merged into MONAI Label’s source code, the latest published package remains version 0.8.5, so users cannot assume an ordinary package installation contains the correction.
  • The operator reportedly provided the targets and a goal of obtaining shell access, while the AI agents independently mapped the application and selected methods to pursue that goal.
Key Points
  • 01Suspected China-linked operators used Cairn, an open-source AI-agent framework, to discover and exploit a previously unknown path-traversal flaw in MONAI Label.
  • 02The flaw affects MONAI Label 0.8.5 and earlier default installations, where authentication is disabled and user-provided file identifiers can cause files to be written outside the intended storage folder.
  • 03Amazon Threat Intelligence reported that the agents reached the ability to write files to a university server in roughly 11 minutes and later obtained root access on one server by placing a Python startup file and triggering a training feature.
  • 04Project MONAI merged a source-code fix on October 19, but its advisory says no patched release is yet available; the CVE record identifies the issue as CVE-2026-133968 with a critical 9.8 score.
  • 05Organizations running MONAI Label should restrict untrusted network access, enable authentication, use limited service accounts, confirm source builds include the fix, and inspect exposed systems for unexpected Python startup files or unusual training jobs.

GnuPG Warns Critical GPGME Flaw Could Expose App Data via Malicious OpenPGP Keys
thehackernews.com · 21 Nov 2026 11:05 UTC openai-codex / gpt-5.6-terra
TAGScve-2026-129975gitlabgnupggnupg-desktopgnupg-vs-desktopgpg4wingpgmesamba
88
In plain words

GnuPG has fixed a serious flaw in GPGME, a component that many programs use to handle encrypted and signed messages. A specially crafted OpenPGP key with an extremely long name field could cause affected programs to reveal data, and the project says it may even be possible to make a program run unwanted code. Mail and chat programs, Samba, and GnuPG’s Windows software may be affected, so users and software makers should install the fixed updates, including GPGME 2.3.1 or Gpg4win 5.1.2.

Summary
GnuPG has patched a critical double-free flaw (CVE-2026-129975) in GPGME that malicious OpenPGP keys could use to expose application data and potentially enable remote code execution. Users should update to GPGME 2.3.1, Gpg4win 5.1.2, or rebuild applications with bundled or statically linked vulnerable copies.

GnuPG warned of CVE-2026-129975, a critical flaw in GPGME that can be triggered by a malicious OpenPGP key with an unusually long user ID. The issue affects software using GPGME versions before 2.3.0, including programs that load it as a shared library, Windows DLL, or statically linked component. GnuPG said the flaw could expose data from affected applications, and remote code execution cannot be ruled out.

The problem is a double-free memory error in the read_status() and read_colon_line() routines, which process status lines and key listings from GnuPG. When long input causes buffer expansion and an error occurs before the new buffer address is saved, cleanup can attempt to release already freed memory again. GnuPG released GPGME 2.3.1 and Gpg4win 5.1.2, while legacy users can use version 1.24.4 or the advisory’s patch; bundled and statically linked copies require rebuilt application releases.

  • Updating only a system-installed GPGME library will not protect applications that include their own bundled or statically linked copy; those applications require rebuilt releases from their developers.
  • The advisory provides no temporary workaround for software that cannot yet update, making installation of a fixed release or patch the stated remediation path.
  • The bug can be reached through signed data sent to an application, rather than necessarily requiring a user to manually import a malicious key.
  • The double-free occurs when an error interrupts buffer resizing, leaving the program with a reference to memory that has already been released.
  • GnuPG moved disclosure forward because GitLab needed to update earlier in response to the separate Ruby2Shell issue.
Key Points
  • 01GnuPG warned that CVE-2026-129975 is a critical double-free flaw in GPGME triggered by malicious OpenPGP keys with unusually long user IDs.
  • 02The flaw affects software using GPGME versions before 2.3.0, including shared, Windows DLL, and statically linked installations.
  • 03Affected software can include many mail and XMPP clients, Samba, Gpg4win, GnuPG Desktop, and GnuPG VS-Desktop.
  • 04GnuPG has released GPGME 2.3.1 and Gpg4win 5.1.2 to address the issue, while the legacy branch received version 1.24.4.
  • 05The project reported no known exploitation, but said the flaw could expose application data and that remote code execution cannot be ruled out.

A Single Malicious Webpage Let Researchers Hijack Meta Muse and Access Private Chats
thehackernews.com · 21 Nov 2026 11:53 UTC openai-codex / gpt-5.6-terra
TAGSlinux-kernelmetameta-musenebusecsentinel
82
In plain words

Researchers found that a harmful webpage could trick Meta’s Muse assistant into sending a user’s private chats and saved information to an outside server without asking permission. By combining additional weaknesses, they could also take control of that user’s separate cloud computer and reach saved account sign-in details. The test did not target real users or spread to other users’ computers, and the researchers say Meta fixed the problems before the findings were published. It matters because AI assistants that can access online accounts may hold highly personal information and can make purchases, so a single unsafe webpage could have serious consequences if protections fail.

Summary
Researchers showed that a malicious webpage could hijack Meta Muse’s cloud environment to access and alter private chats, memories, and potentially connected-account credentials, though the attack was contained to one user’s machine. NebuSec said Meta fixed the reported flaws before disclosure.

NebuSec researchers demonstrated in a laboratory that a malicious webpage could extract and alter a Meta Muse user’s private conversations and stored memories without an approval prompt. The same approach could potentially reach credentials Muse keeps for connected accounts. The demonstration did not target real users and remained inside the individual user’s cloud machine.

The researchers chained a flaw in Muse’s built-in browser with a Linux kernel flaw to gain full control of that cloud machine. This access reached the credential store, saved files, and Sentinel, the monitoring layer intended to control outbound actions and isolate sensitive data from the agent. The compromise did not extend to the shared server beneath the machine or to other users’ machines, and NebuSec said all reported exploits were fixed before publication.

  • Muse’s protections were designed on the assumption that the AI agent itself could be manipulated, yet the researchers found a path that reached protected components by taking over the user’s cloud machine rather than relying on the agent alone.
  • The reported issue was not limited to reading private information: the malicious webpage could also alter a user’s stored conversations and memories without an approval prompt.
  • Although connected-account passwords and tokens were intended to be inaccessible to the agent, the researchers said full control of the cloud machine could reach the credential store.
  • The demonstrated compromise remained confined to a single user’s cloud machine and did not extend to the shared underlying server or other users’ machines.
Key Points
  • 01NebuSec researchers demonstrated that a malicious webpage could extract and alter Meta Muse users’ private conversations and stored memories without showing an approval prompt.
  • 02The researchers chained a flaw in Muse’s built-in browser with a Linux kernel flaw to take full control of an individual user’s cloud machine.
  • 03Full control of the cloud machine could reach Muse’s credential store, saved files, and Sentinel monitoring layer, although the test did not escape to the underlying shared server or other users’ machines.
  • 04The demonstration was conducted in a laboratory and did not target real users, according to the article.
  • 05NebuSec said it reported the findings to Meta Muse’s team and that all described exploits were fixed before publication.

JUSTIFICATION

This is a concrete, high-impact security finding affecting Meta Muse, where a malicious webpage could expose private data and potentially connected-account credentials by taking over a user’s cloud machine. The flaws were reportedly fixed before publication and no real users were targeted, reducing immediate urgency, but the findings have broad relevance for AI-agent security design.
