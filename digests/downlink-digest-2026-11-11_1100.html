Because Token controls both Rehearsal and its own platform, it can lock and dim the application while the agent is active, record every move including blocked actions, and restrict the agent to read-only dashboard access. The article says emerging measures such as browser controls, WebMCP, and Web Bot Auth each provide part of the needed context, but do not yet combine agent identity, proof of the person it represents, and a narrower task-specific permission scope. It recommends that security teams identify browser and endpoint agents using authenticated sessions, map them to users and owners, review their access, and require explicit approval or stronger authentication before sensitive or irreversible actions.

  • A browser agent’s use of a person’s existing session means that a session cookie does not reveal whether the person or the agent is operating the application.
  • Token limited Rehearsal’s risk by making dashboard access read-only, refusing to fill secret fields, and requiring user approval before saving changes.
  • The article identifies a gap between emerging controls: browsers may know an agent is driving, WebMCP can label actions as read-only or consequential, and Web Bot Auth can identify an agent, but these mechanisms do not yet combine delegation and narrower permissions.
  • Organizations can add a passkey prompt or similar stronger confirmation for sensitive or irreversible actions even when they cannot determine whether a person or an agent performed a click.
Key Points
  • 01Token’s Rehearsal browser agent operates within a user’s authenticated session, so the application server cannot inherently distinguish its actions from those of the user.
  • 02Because Token controls both Rehearsal and its platform, it can lock the interface while the agent acts, record all agent moves, and limit the agent to read-only dashboard access unless the user approves a change.
  • 03The article says Chrome and Microsoft provide some controls for agentic browsing, while WebMCP can expose website actions to agents and Web Bot Auth can verify which agent made a request.
  • 04The article argues that current approaches do not combine agent identity, proof of the person an agent represents, and a permission scope narrower than that person’s access.
