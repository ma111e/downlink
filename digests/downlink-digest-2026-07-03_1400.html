North Korea-Linked npm Packages Mimic Rollup Polyfills to Steal Developer Secrets
thehackernews.com · 03 Jul 2026 16:07 UTC openai-codex / gpt-5.5
TAGSbeavertailcontagious-interviewjfrogjsonkeeperlazarusnorth-koreanpmnut-tree-fork-nut-jsottercookiequirky-tokenreact-icon-svgsrollup-packages-polyfill-corerollup-plugin-polyfill-connectrollup-runtime-polyfill-coreswift-parse-stream

In plain words

Researchers found that attackers tied to North Korea uploaded fake software packages that looked like normal Rollup helper tools used by developers. If installed, the packages could let the attackers control a developer’s computer and steal things like source code, browser data, cloud keys, SSH keys, crypto wallet information, and project secrets. This matters because developer computers and build machines often hold access to many other systems, so one poisoned package can put wider projects, companies, and users at risk.

Summary
North Korea-linked actors published malicious npm packages that impersonate Rollup polyfill tooling to infect developer machines, enable remote access, and steal credentials, browser data, crypto wallets, and project secrets. Developers who installed the named packages should remove them, assume compromise, and rotate exposed credentials.

Threat actors tied to North Korea have been linked by JFrog to malicious npm packages that masqueraded as Rollup polyfill tooling. The packages rollup-packages-polyfill-core and rollup-runtime-polyfill-core mimicked the legitimate rollup-plugin-polyfill-node project, including its description, repository metadata, and package shape. The campaign also involved quirky-token, react-icon-svgs, rollup-plugin-polyfill-connect, and swift-parse-stream, all of which have been removed from the npm registry.

The attack used a layered structure in which the lookalike packages installed second-stage packages that posed as SVG utilities. Those second-stage packages fetched a JSON object from JSONKeeper and executed JavaScript from its model field. The malware checked for cloud development environments, sandboxes, serverless runtimes, and analysis infrastructure before contacting 216.126.236[.]244 to fetch an encrypted JavaScript payload.

Later payload stages enabled remote access, interactive terminal sessions, command execution, screenshot capture, process termination, mouse and keyboard control on Windows, browser and cryptocurrency wallet data theft, file collection, and periodic clipboard capture. JFrog said Rollup plugins are often loaded on developer workstations and CI jobs, where source code, npm tokens, Git credentials, cloud keys, SSH keys, browser data, and project secrets may be present. Users who installed the named packages were advised to remove them, assume compromise, rotate credentials, block malicious egress channels, and enable dependency scanning in CI/CD pipelines.

  • The campaign used a layered package structure in which plausible-looking first-stage packages installed separate second-stage packages, which can make quick dependency reviews and registry-side scanning less likely to reveal the full behavior.
  • The malware specifically avoided cloud development environments, sandboxes, serverless runtimes, and analysis infrastructure, indicating that testing suspicious packages only in such environments may miss the payload described in the article.
  • The file collector targeted editor history and configurations for tools including Visual Studio Code, Windsurf, Cursor, AWS, Azure, Google Gemini, Anthropic Claude, Foundry, SSH, and Zsh, showing that developer and AI tool artifacts were explicit collection targets.
  • The article notes repeated North Korea-linked use of Rollup polyfill impersonation, including a prior package named rollup-plugin-polyfill-route, making similarly named Rollup polyfill packages a particularly important area for scrutiny.
  • Several unrelated supply-chain campaigns in the article harvested overlapping secrets such as SSH keys, cloud credentials, npm tokens, Docker configurations, shell history, and wallet data, so affected users are advised to assume compromise and rotate credentials rather than only uninstall packages.

ARToken PhaaS exposes EvilTokens' Microsoft 365 phishing toolkit

In plain words

Researchers found a phishing service called ARToken that appears linked to EvilTokens and is built to break into Microsoft 365 accounts. It tricks people into signing in through a real Microsoft page, then gives criminals access to the person’s email, SharePoint, and OneDrive files, even when extra login checks are used. This matters because workers such as accounts payable staff can be targeted with fake invoice emails, letting attackers steal data, hide their activity, and send convincing fraud emails from compromised accounts.

Summary
Cisco Talos uncovered ARToken, a phishing-as-a-service panel linked to EvilTokens that helps attackers compromise Microsoft 365 accounts through device code phishing, steal tokens, maintain persistent access, and automate BEC activity. The findings show EvilTokens affiliates have a broad toolkit for bypassing MFA and abusing Outlook, SharePoint, and OneDrive after account takeover.

Cisco Talos researchers discovered a phishing-as-a-service platform called ARToken while investigating phishing infrastructure used in an incident response engagement. The platform includes a React-based management panel called ARToken Panel that exposed more than 80 API endpoints. Talos found multiple technical similarities suggesting ARToken is tied to the EvilTokens phishing platform, including identical Microsoft device code authentication API calls and the same primary refresh token endpoints documented in prior EvilTokens research.

ARToken is designed to compromise Microsoft 365 accounts by stealing authentication tokens, establishing persistent access using Primary Refresh Tokens, and accessing Outlook mailboxes, SharePoint sites, and OneDrive files. The platform supports business email compromise activity by allowing attackers to send emails as compromised users, create inbox rules that forward or hide messages, monitor mailboxes for keywords, and download attachments. It also includes tools to deploy phishing infrastructure through Cloudflare Workers and operate as a multi-tenant service where affiliates manage campaigns through dedicated workspaces.

The article explains that EvilTokens focuses on Microsoft’s device code authentication workflow, where victims enter a legitimate Microsoft-issued code on Microsoft’s official device login page and authentication tokens are issued to the attacker. Because victims authenticate through Microsoft’s legitimate infrastructure, the attacks can bypass multi-factor authentication protections. Talos also found phishing emails tied to the platform that impersonated legitimate vendors in invoice-themed lures targeting accounts payable employees and displayed what appeared to be a legitimate SharePoint address while redirecting victims to an attacker-controlled Microsoft 365 workspace.

  • ARToken shows that EvilTokens-related activity is not limited to initial credential theft, because the affiliate panel includes post-compromise tools for mailbox monitoring, inbox rule manipulation, file access, and BEC automation.
  • The use of Microsoft’s legitimate device login page makes these phishing attacks harder to recognize, because victims enter the code on real Microsoft infrastructure while the resulting tokens are issued to the attacker.
  • The platform’s ability to refresh stolen tokens and elevate access to Primary Refresh Tokens indicates that a single successful device code phishing event can lead to persistent Microsoft 365 access beyond the initial login session.
  • Attackers using ARToken can make phishing links appear more trustworthy by showing what looks like a legitimate SharePoint address while actually sending victims to a look-alike tenant inside the attacker’s Microsoft 365 workspace.
  • ARToken’s Cloudflare Workers deployment model and multi-tenant workspace design suggest EvilTokens-style phishing is being operationalized for affiliates who can manage separate campaigns through a service-like platform.

NetNut proxy network disrupted, 2 million infected devices cut off

In plain words

Google, the FBI, and other partners disrupted NetNut, a service that secretly used at least 2 million infected home devices, including Android devices, smart TVs, and streaming boxes, to hide the online activity of criminals and spying groups. People whose devices were infected could have their home internet address used for unwanted traffic, which may cause their devices or connections to look suspicious or be blocked by internet providers or online services. This matters because hundreds of threat groups were using NetNut to reach victims, try large numbers of passwords, and make harmful activity look like it came from ordinary homes.

Summary
Google, the FBI, and industry partners disrupted NetNut, a major residential proxy botnet that routed malicious traffic through at least 2 million compromised Android devices, smart TVs, and streaming boxes. The operation seized domains, cut off command-and-control infrastructure, and disabled infected apps via Google Play Protect.

A joint operation involving Google disrupted NetNut, also known as Popa, a residential proxy network that gave access to millions of compromised Android devices, smart TVs, and streaming boxes. Google Threat Intelligence Group estimated that NetNut controlled at least 2 million infected devices globally. The operation included Google, the FBI, Lumen Technologies, The Shadowserver Foundation, and other industry partners.

NetNut allowed cybercriminals and espionage groups to hide behind legitimate home internet addresses when launching attacks. Google said it observed 316 distinct threat clusters using suspected NetNut exit nodes in one week last month, including cybercriminal and espionage groups. Threat actors used NetNut to access their own infrastructure, conduct password-spraying attacks, and reach victim environments.

Google disabled accounts and services on its infrastructure that NetNut operators used for malware command-and-control, blocking access to critical backend infrastructure. The FBI took down domains used by the service, including netnut.com. Google also warned users and disabled infected applications using Google Play Protect, and shared technical details about NetNut SDKs and backend infrastructure with platform providers, law enforcement agencies, and cybersecurity researchers.

  • NetNut’s disruption could affect many other residential proxy services because Google said the network has a reseller program that allows whitelabeling and fuels many popular proxy offerings.
  • Taking down one residential proxy service may not fully remove the capacity from the ecosystem because operators often buy replacement capacity from competing providers and become resellers themselves.
  • Consumer devices can become part of these networks not only through apps users install, but also through malware that is pre-installed before purchase.
  • The real-world impact on infected users can include their home internet addresses being flagged as suspicious or blocked by internet service providers or online services, even if they were unaware their devices were being used.
Key Points
  • 01A joint operation involving Google disrupted NetNut, also known as Popa, a residential proxy network estimated to control at least 2 million compromised devices globally, including Android devices, smart TVs, and streaming boxes.
  • 02Google said NetNut was powered by trojanized applications and botnets such as Badbox 2.0 that package proxy plugins.
  • 03The disruption involved Google, the FBI, Lumen Technologies, The Shadowserver Foundation, and other industry partners, and the FBI took down domains including netnut.com.
  • 04Google observed 316 distinct threat clusters using suspected NetNut exit nodes in one week last month, including cybercriminal and espionage groups.
  • 05Google disabled accounts and services used by NetNut operators for command-and-control infrastructure and protected users by warning them and disabling infected applications through Google Play Protect.
