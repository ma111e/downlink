5 attack chains that started with assets nobody thought to test

In plain words

The article describes five cases where internet-facing systems that seemed unimportant—such as an old reporting server, a subsidiary’s registration service, a supplier-built app, and a public demo—provided routes to highly sensitive systems. Affected organizations included transportation, IT services, pharmaceutical, and healthcare companies, with potential exposure of live vehicle-routing controls, payment-related systems, customer databases, competitors’ data, and patient records. It matters because companies often test only the systems they already consider important, while forgotten or low-priority systems can still give criminals a way into the most valuable information and operations.

Summary
Organizations that focus pentesting only on obvious critical systems can miss overlooked external assets—such as legacy servers, subsidiary platforms, supplier applications, and demos—that provide paths to sensitive data and production controls. The article argues that comprehensive attack-surface discovery and scalable AI-driven testing are needed to identify these hidden attack chains.

The article presents five attack chains identified during CyCognito AI pentesting that began with external assets organizations might not prioritize for testing. It cites Synack and Omdia research finding that organizations test about 32% of their attack surface on average, leaving roughly two thirds untested. The examples involve a hostname-less operations server, an unpatched legacy reporting server, a subsidiary registration service, a supplier-built application, and a public demo environment.

In the cases described, crafted requests bypassed an authentication gateway, XML-processing flaws exposed local files and passwords, and an unauthenticated SQL injection reached a shared environment containing 59 databases. The identified paths could expose live transportation-routing controls, systems in PCI scope, production customer databases, data belonging to other companies, and patient records across four institutions. The article argues that organizations need complete external attack-surface discovery, including asset relationships and technologies, plus efficient testing that can cover more assets and revisit them as they change.

  • Assets that lack a public hostname can still be externally reachable and may provide access to critical operational systems, as shown by the transportation company’s IP-address-only server.
  • Security controls can fail when two systems interpret the same web address differently: the login gateway treated a crafted request as a stylesheet while the backend treated it as an application request.
  • A supplier-managed application can create exposure beyond its customer’s own data when it runs in a shared environment with databases belonging to other organizations.
  • A demo environment containing only synthetic data can still expose real security weaknesses when it uses the same application code as production.
  • Previous manual pentests missed several of the article’s attack paths, including those involving a subsidiary registration server, a supplier application, and a healthcare demo.
Key Points
  • 01Research cited by the article found that organizations pentest about 32% of their attack surface on average, leaving roughly two thirds untested.
  • 02An externally reachable, hostname-less operations server at a transportation company allowed an authentication bypass that exposed live vehicle cargo information and rerouting controls.
  • 03An outdated analytics server at a global IT services company enabled unauthenticated file reading, disclosure of an administrative password, and a path to a machine in a payment-card environment.
  • 04A third-party clinical-data application at a pharmaceutical company contained an unauthenticated SQL injection that reached a shared database environment containing 59 databases, including databases of 14 other companies.
  • 05A public healthcare-platform demo using production application code exposed patient records across four institutions and allowed a low-privilege clinician account to modify records and create non-expiring patient-portal tokens.

In plain words

A group called Storm-1865 pretended to be Booking.com and sent messages to hotel staff that led them to fake Booking.com pages. The pages told staff to copy and paste a command into their computers, which could install software used to steal passwords and payment information. Booking.com itself was not breached, but accommodation partners and customers were affected, showing how criminals can misuse a trusted company name to reach other victims. Cyble says monitoring fake websites, copied brand material, and leaked account details can help stop these scams earlier.

Summary
Cyble argues that its Brand Intelligence & Protection service could disrupt Storm-1865’s Booking.com ClickFix phishing campaign by detecting lookalike domains, cloned phishing pages, and exposed credentials before more hospitality partners are victimized.

Microsoft Threat Intelligence reported that Storm-1865 impersonated Booking.com from December 2024 to target hotel and hospitality staff across North America, Europe, Oceania, and South and Southeast Asia. The group used messages about negative reviews, guest inquiries, promotions, or account verification to lead recipients to fake CAPTCHA pages overlaid on a faint Booking.com page. Those pages instructed victims to open the Windows Run box and paste a command that had already been copied to their clipboard.

The command used mshta.exe to download malware including XWorm, Lumma Stealer, VenomRAT, AsyncRAT, Danabot, and NetSupport RAT, which Microsoft said could steal credentials and financial data. Booking.com said its own systems were not breached, but some accommodation partners and customers were affected. The article argues that Cyble Brand Intelligence & Protection could help reduce this type of abuse by identifying lookalike domains, copied pages and brand assets, phishing lures, and exposed credentials, while noting that endpoint and email controls are needed to stop the pasted command itself.

  • A company can be harmed by criminals borrowing its name even when its own systems are not breached, because its partners and customers may trust messages and websites that appear to come from it.
  • When phishing messages are sent from ordinary Gmail or iCloud Mail accounts rather than a fake company email domain, the fraudulent website becomes the key asset to identify and remove.
  • The article distinguishes between stopping the copy-and-paste command with email and device protections and reducing exposure earlier by finding lookalike domains and fake pages before recipients reach them.
  • Monitoring newly registered lookalike domains can provide an opportunity to identify a brand impersonation site before it begins hosting a fraudulent page.
Key Points
  • 01Microsoft reported that Storm-1865 impersonated Booking.com from December 2024 to target hotel and hospitality staff across North America, Europe, Oceania, and South and Southeast Asia.
  • 02The campaign used Booking.com-themed emails and PDFs to send victims to fake CAPTCHA pages that instructed them to paste a pre-copied command into the Windows Run box.
  • 03The command used mshta.exe to retrieve credential- and payment-data-stealing malware, including XWorm, Lumma Stealer, VenomRAT, AsyncRAT, Danabot, and NetSupport RAT.
  • 04Booking.com stated that its own systems were not breached, although some accommodation partners and customers were affected.
  • 05The article presents Cyble Brand Intelligence & Protection as a way to identify lookalike domains, cloned phishing pages, brand-related lures, and exposed credentials, while noting it did not participate in the response to this campaign.

Deploying AI agents securely: how Kaspersky products mitigate AI threats

In plain words

The article explains how companies can keep track of and control AI assistants that can read data, run commands, and connect to online services using an employee’s access. Businesses are affected because these tools can be tricked by harmful instructions, unsafe add-ons, or attacker-controlled connections into exposing passwords, files, or other sensitive information. Kaspersky describes its products for blocking unapproved AI tools, watching for risky behavior, and checking downloaded AI files and add-ons for hidden harmful code. The broader concern is that AI assistants can help employees work faster but can also give attackers new ways into company systems if they are not carefully managed.

Summary
Kaspersky promotes a layered approach to securing enterprise AI agents: discover and restrict them with application and web controls, monitor risky behavior with EDR detections, and scan agent skills and LLM files for malicious code. The article highlights risks such as unsafe auto-approval settings, credential-file access, malicious MCP server artifacts, and untrusted agent extensions.

Kaspersky describes AI agents as a growing corporate-security concern because they can access data, run commands, and interact with external services using a user’s privileges. The article says agentic tools, particularly software-development agents, are among the most popular AI applications observed in Kaspersky telemetry, while AI-related software and services have accumulated more than 2,500 published vulnerabilities since 2025. It argues that organizations need visibility and controls because agents may execute harmful instructions from documents, web pages, emails, downloaded skills, or unsafe external sources.

Kaspersky Endpoint Security can use Application Control to allow or block AI tools and Web Control to restrict access to AI-as-a-service websites. Kaspersky EDR monitors agents as processes and includes rules for behavior such as access to credential files, execution with automatic approval or disabled sandboxing, suspicious MCP server artifacts, and unusual applications connecting to known LLM APIs. Kaspersky Threat Intelligence Portal provides AI-agent profiles and detection-rule information, while Kaspersky Scan Engine can scan agent skills, associated scripts, generated files, and certain LLM model formats for malicious code.

  • An AI agent’s launch alone does not indicate an attack; the article says investigators need to connect suspicious actions to the specific agent and the conditions under which it was running.
  • Existing behavior-based detections can identify many malicious actions performed by AI agents because traces such as suspicious PowerShell commands, scheduled-task persistence, credential theft, process relationships, and network activity remain recognizable regardless of what initiated them.
  • The article identifies “YOLO mode” and disabled sandboxing as risky agent settings because they allow actions to proceed without user confirmation, although those settings alone do not prove malicious activity.
  • AI tools that run models locally can evade visibility based only on external AI-service connections, so the article notes that creation or modification of local model files can reveal their presence.
  • Agent skills and some LLM model-file formats can carry malicious code, meaning a seemingly harmless AI agent can introduce threats through downloaded instructions, helper scripts, or model files.
Key Points
  • 01AI agents can access data, run commands, and interact with external services using user privileges, creating security risks when deployed without security-team oversight or well-designed policies.
  • 02Kaspersky Endpoint Security provides Application Control and Web Control features that organizations can use to restrict AI agent software and access to websites offering AI as a service.
  • 03Kaspersky EDR includes specialized rules that identify AI agents accessing credential, token, or key files; launching with automatic approval or disabled sandboxing; creating suspicious MCP server files; and unusual applications connecting to external LLM APIs.
  • 04Kaspersky Threat Intelligence Portal provides AI-agent profiles and Hunt Hub detection rules with information such as system artifacts, audit sources, MITRE ATT&CK mappings, detection logic, and possible false positives.
  • 05Kaspersky Scan Engine can scan AI-agent skills, associated scripts, agent-generated files, and potentially dangerous LLM model formats for malicious code.
