Microsoft Store App Found Delivering Vinci RAT Capable of Remote System Control

In plain words

Attackers used a fake download page and an app that had been available through the Microsoft Store to install Vinci RAT, a program that can let criminals control a victim’s computer from afar. The app watched the Downloads folder, contacted attacker-controlled servers, and repeatedly restarted itself so it could remain on the computer. People seeking tools such as a snipping app, Microsoft Teams, or Roblox downloads could be targeted, putting their files, programs, and computer access at risk. The case shows that even software delivered through a trusted app store can be abused to gain lasting access to computers.

Summary
A malicious Microsoft Store app called Setup Assistant was used to deliver Vinci RAT, giving attackers persistent remote control through obfuscated JavaScript and PowerShell payloads. The campaign used fake software download sites and a Microsoft-signed installer to lure victims before the app was removed from the Store.

Cybersecurity firm eSentire reported that attackers used a fake snipping-tool website to distribute a Microsoft-signed installer named Snipping-Tool.exe. Running it installed Setup Assistant, an Electron-based application published by ETPS Ltd. through the Microsoft Store. The application was designed to act as a backdoor, communicating with attacker-controlled servers and executing supplied PowerShell or JavaScript code.

The activity ultimately deployed Vinci RAT, which can identify the affected system, list installed security tools, provide remote and reverse-shell access, deliver files, and run several kinds of code. Its PowerShell stager disabled Windows AMSI, created a scheduled task that ran every 10 minutes, contacted monkeysholder[.]info, and downloaded the RAT payload. eSentire also identified related codes-team[.]com subdomains that appeared to impersonate Microsoft Teams and Roblox download pages; Setup Assistant was no longer available in the Microsoft Store when the article was published.

  • The campaign combined a Microsoft-signed installer and a Microsoft Store-hosted application with fake download pages, showing that trusted-looking distribution paths were part of the delivery chain.
  • Setup Assistant could wait for specific filenames such as MSTeamsSetup.exe or Reader_install.exe to appear in the Downloads folder before contacting its control server and running the response.
  • The attackers’ codes-team[.]com infrastructure included subdomains impersonating Microsoft Teams and Roblox download pages, indicating that the same infrastructure supported multiple software-themed lures.
  • eSentire said it reported the app through Microsoft’s abuse form on November 10, 2026, but received a response that the app was not a terms violation before the app later became unavailable.
Key Points
  • 01Researchers at eSentire reported that attackers used a fake snipping-tool website to deliver a Microsoft-signed installer named Snipping-Tool.exe, which installed the Microsoft Store app Setup Assistant.
  • 02Setup Assistant, an Electron-based application published by ETPS Ltd., used obfuscated JavaScript to communicate with attacker-controlled infrastructure and execute PowerShell or JavaScript supplied by that infrastructure.
  • 03The campaign deployed Vinci RAT, which can identify the infected computer, check installed security tools, provide remote shell access, transfer files, and run shellcode, DLL, EXE, and PowerShell payloads.
  • 04A PowerShell stager disabled Windows AMSI, created a scheduled task that ran every 10 minutes, contacted monkeysholder[.]info, and downloaded the Vinci RAT payload.
  • 05The Setup Assistant app was no longer accessible in the Microsoft Store at the time of reporting, and eSentire said Microsoft had previously responded to its abuse report by stating that the app did not violate its terms.

It is broadly relevant because it combines trusted software distribution, fake download pages, PowerShell execution, AMSI disabling, and scheduled-task persistence.

SAP says it found suspicious activity in the online systems its developers use to build software, after reports that intruders may have obtained employee access codes and copied or changed company software code. SAP says it has found no evidence that customer business data was accessed, but it has limited developer access, paused some automated work, and replaced digital checks used to confirm that software has not been changed. This matters because SAP software helps businesses and public institutions run accounting, purchasing, supply chains, and human-resources work, so changed software could affect many organizations if it were delivered to customers.

SAP confirmed a cybersecurity incident involving suspicious activity in its GitHub-based development environment, with reports that stolen employee tokens may have enabled source-code access or modification. In plain words

Microsoft says its next major server software release, Windows Server 2028, will no longer include WSUS, a tool companies use to download and distribute Microsoft updates to many work computers from one central place. Businesses that depend on it will need to plan a move to Microsoft’s online update-management services, while people using older supported server versions can keep using WSUS for now. Microsoft is also removing older components such as VBScript, WMIC, and WINS, partly because criminals can misuse them.

Summary
Microsoft will remove the WSUS server role from Windows Server 2028, though WSUS remains supported on earlier releases such as Windows Server 2025 for their support lifecycles. Organizations are being directed toward cloud-based update-management tools including Windows Autopatch, Microsoft Intune, and Azure Update Manager.

Microsoft has confirmed that Windows Server 2028 will remove the Windows Server Update Services (WSUS) server role. WSUS, introduced in 2005, lets IT administrators centrally manage and distribute Microsoft product updates across corporate networks instead of having every device download updates separately. Microsoft formally deprecated WSUS in September 2024, while stating that it would continue maintaining its existing functionality and publishing updates through the channel.

WSUS will remain supported on earlier Windows Server versions, including Windows Server 2025, for the duration of their support lifecycles, and those installations can still manage updates for supported Windows clients and Windows Server 2028. Microsoft recommends organizations move to Windows Autopatch and Microsoft Intune for client updates and Azure Update Manager for server updates, while acknowledging the needs of disconnected and tightly controlled environments. Windows Server 2028 will also remove VBScript, the WMIC command-line utility, and WINS support; Microsoft links the removal of some of these older components to reducing abuse by malware and attack techniques.

  • Removing the WSUS role from Windows Server 2028 does not prevent WSUS hosted on earlier supported Windows Server releases from distributing updates to Windows Server 2028 systems.
  • Microsoft has acknowledged that disconnected and highly controlled environments still need update-management support, but it has not yet provided details on its planned approach.
  • The WSUS change follows its September 2024 deprecation, meaning the service remains operational on supported earlier server releases but is no longer receiving new features.
  • Windows Server 2028 combines the WSUS removal with the removal of older components such as VBScript, WMIC, and WINS, which Microsoft links to reducing abuse by malware and attack techniques.
Key Points
  • 01Microsoft will remove the Windows Server Update Services (WSUS) server role from Windows Server 2028.
  • 02WSUS remains available and supported on earlier Windows Server releases, including Windows Server 2025, for each release’s support lifecycle.
  • 03Organizations can continue using WSUS hosted on earlier supported Windows Server releases to manage updates for supported Windows clients and servers, including Windows Server 2028.
  • 04Microsoft recommends that organizations move client update management to Windows Autopatch and Microsoft Intune and server update management to Azure Update Manager.
  • 05Windows Server 2028 will also remove VBScript, WMIC, and Windows Internet Name Service (WINS) support.
OPEN SOURCE ↗
JUSTIFICATION

Microsoft has confirmed a concrete product-lifecycle change that affects organizations relying on WSUS for centralized Windows update distribution. It is not an immediate security emergency, but enterprise administrators should plan migration toward the recommended cloud-based update-management tools and account for other legacy component removals in Windows Server 2028.

Japan’s education ministry said someone broke into the system it uses to publish government contract and bidding information. The incident may have exposed nearly 1,700 email addresses and 164,000 business records, including company and employee names, affecting organizations eligible to bid for ministry work. The ministry cut the system off from other networks and says it has not found evidence that the information was made public or misused, but the case adds to a recent series of cyber incidents involving Japanese companies and public institutions.

Summary
Japan’s education ministry said hackers breached its government procurement system, potentially exposing 164,000 business records and nearly 1,700 email addresses. MEXT isolated the system, reported the incident to data protection authorities, and says it has found no evidence of public disclosure or misuse.

Japan’s Ministry of Education, Culture, Sports, Science and Technology (MEXT) disclosed that hackers breached its government procurement system. The ministry detected the intrusion on October 1, nearly two months before announcing it publicly. Its investigation found that the intruders may have obtained information stored in the system’s database.

The potentially exposed information includes nearly 1,700 email addresses and 164,000 records containing company names, employee names, and other business information. The system publishes government tenders, contracts, and procurement opportunities, and the affected records concern companies eligible to participate in ministry bidding processes. MEXT said it blocked the system’s communications with internal and external networks, found no evidence of public disclosure or misuse, and reported the incident to Japan’s data protection authorities while continuing its investigation with other government agencies.

  • The ministry detected the intrusion on October 1 but did not publicly disclose it until nearly two months later.
  • The potentially exposed records concern companies eligible for ministry bidding processes, meaning the incident may affect organizations that interact with the government procurement system rather than only ministry staff.
  • MEXT isolated the affected system from both internal and external networks, indicating containment involved cutting off its communications broadly.
  • The ministry has not identified the perpetrators or explained how access was gained, and it said there is no indication that this incident is connected to other recent cyber incidents in Japan.
