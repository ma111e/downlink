CVE-2026-109618 and CVE-2026-109619: PHP Vulnerable to Unauthenticated RCE Attacks

In plain words

The article reports two serious flaws in PHP, software used by many websites and online services, that could let an outsider take control of an affected server without logging in or getting anyone to click anything. They affect PHP versions from 5.4 onward, including systems behind widely used platforms such as WordPress, Drupal, Joomla, and Magento. This matters because automated attacks could target large numbers of internet-facing servers, potentially exposing data, passwords, access tokens, and other sensitive information. Organizations are urged to install the emergency updates immediately or take unpatched PHP services offline or away from untrusted networks.

Summary
Two critical PHP core flaws, CVE-2026-109618 and CVE-2026-109619 (PHP2Shell), reportedly enable unauthenticated remote code execution on PHP 5.4+ systems. Organizations should urgently upgrade to patched supported releases or disable/isolate unpatchable PHP instances.

On October 21, 2026, two critical PHP vulnerabilities, CVE-2026-109618 and CVE-2026-109619, collectively called PHP2Shell, were publicly disclosed. Both have a CVSS v4.0 score of 9.2 and can allow an unauthenticated remote attacker to execute code on vulnerable servers. The article states that PHP versions from 5.4 onward are affected, including systems supporting applications such as WordPress, Drupal, Joomla, and Magento.

CVE-2026-109618 involves an out-of-memory condition that can leave PHP request data incompletely initialized, while CVE-2026-109619 involves stale internal pointers accessing memory that has already been freed. The flaws can be chained to make remote code execution more reliable and may also expose process memory containing passwords, tokens, API keys, and certificates. Organizations are advised to upgrade to PHP 8.5.12, 8.4.27, 8.3.36, or 8.2.35 where applicable, disable unpatched services when possible, and isolate end-of-life PHP deployments that cannot be promptly migrated.

  • Application-level security controls do not remove the risk because the article says both flaws are in PHP's core request-handling runtime, affecting every PHP application on a vulnerable installation.
  • The two flaws can be chained: the first can help shape memory contents, while the second can access stale memory in a later request handled by the same worker, making code execution more reliable.
  • A PHP version number alone may not determine exposure, because Linux distribution maintainers may have already backported the patches to older package versions.
  • For systems that cannot be patched immediately, the article identifies disabling the PHP service as the only way to ensure that instance is secure; configuration changes and network isolation are only interim risk-reduction measures.
  • Possible signs of attempted exploitation include unusual web-server segmentation faults, crash dumps, and abnormal memory use, which the article recommends reviewing in Apache, Nginx, and other server logs.
Key Points
  • 01CVE-2026-109618 and CVE-2026-109619, collectively called PHP2Shell, were publicly disclosed on October 21, 2026 and are rated 9.2 out of 10 under CVSS v4.0.
  • 02The article states that all PHP versions from 5.4 onward are affected, while fixes are available for PHP 8.5.12, 8.4.27, 8.3.36, and 8.2.35.
  • 03The flaws can allow an unauthenticated remote attacker to execute code on a vulnerable PHP server and potentially access sensitive memory containing passwords, tokens, API keys, or certificates.
  • 04The article describes CVE-2026-109618 as an out-of-memory error condition that can leave request data partially initialized, and CVE-2026-109619 as stale memory being accessed by a later request in the same PHP worker.
  • 05Organizations are advised to patch immediately, disable unpatched PHP services where possible, inventory PHP deployments, and isolate end-of-life instances that cannot yet be migrated.
