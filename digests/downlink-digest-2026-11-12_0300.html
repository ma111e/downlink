Critical Apache HTTP/2 Flaw Could Let Unauthenticated Attackers Execute Code Remotely
thehackernews.com · 12 Nov 2026 05:12 UTC openai-codex / gpt-5.6-terra

In plain words

A serious weakness was found in Apache HTTP Server, software used to run websites, when its newer HTTP/2 connection feature is turned on. An outsider could use it without logging in to take control of the server, putting the websites and services it supports at risk. Organizations using affected Apache versions should install version 2.4.71 or turn off the HTTP/2 feature until they can update.

Summary
Apache HTTP Server 2.4.55–2.4.70 has a critical unauthenticated remote-code-execution flaw in mod_http2 (CVE-2026-119618) when HTTP/2 is enabled; upgrade to 2.4.71 or disable h2/h2c until patched.

A critical flaw, CVE-2026-119618, affects Apache HTTP Server’s HTTP/2 module, mod_http2, in versions 2.4.55 through 2.4.70. If HTTP/2 is enabled, an unauthenticated remote attacker could run code on the server and potentially take control of its server process. Apache fixed the issue in version 2.4.71. Red Hat assigned a CVSS score of 9.8, and said public research had demonstrated a reliable exploit against a default configuration with mod_http2 enabled.

Only servers configured with the h2 or h2c protocols are affected, and HTTP/2 can be enabled either server-wide or for individual virtual hosts. Organizations that cannot update immediately can remove h2 and h2c from the Protocols directive and use Protocols http/1.1 instead. Red Hat released fixes for RHEL 9 and 10, while RHEL 8 and earlier do not contain the vulnerable code; Debian unstable is fixed, but several Debian releases and Amazon Linux versions were still listed as vulnerable or awaiting fixes. Standalone mod_h2 versions 2.0.8 through 2.0.42 are also affected, and no fixed standalone release had been published.

  • HTTP/2 may be enabled globally or only for individual virtual hosts, so administrators need to check both the server-wide configuration and each virtual host when assessing exposure.
  • Red Hat rated the issue as Important rather than Critical on RHEL 9 and 10 because its mod_http2 packages use a separate memory allocator for each HTTP/2 stream, which the vendor says makes exploitation much harder.
  • Red Hat stated that public research demonstrated a reliable exploit against a default mod_http2-enabled configuration, while Wiz said no exploit was available and reported no known exploitation in the wild.
  • The standalone mod_h2 project has no fixed release, and its archived repository ends with version 2.0.42, which is affected; disabling h2 and h2c is therefore the stated option for those builds.
  • Updating to Apache HTTP Server 2.4.67 to address the earlier CVE-2026-23918 would not protect a server from this newer flaw, because versions through 2.4.70 remain affected.
Key Points
  • 01CVE-2026-119618 is a critical flaw in Apache HTTP Server's mod_http2 module that can allow unauthenticated remote code execution on servers with HTTP/2 enabled.
  • 02The flaw affects Apache HTTP Server versions 2.4.55 through 2.4.70 and is fixed in version 2.4.71.
  • 03Red Hat released fixes for Red Hat Enterprise Linux 9 and 10, while Red Hat Enterprise Linux 8 and earlier are not affected.
  • 04Debian unstable has been fixed with apache2 2.4.71-1, while Debian bookworm, trixie, and forky were listed as vulnerable and Amazon Linux releases were awaiting fixes.
  • 05Organizations unable to update can remove h2 and h2c from Apache's Protocols directive and leave Protocols http/1.1 as a temporary mitigation.

ScreenConnect Attacks Target at Least 288 Endpoints Across 48 Organizations With Rogue Clients
thehackernews.com · 12 Nov 2026 04:39 UTC openai-codex / gpt-5.6-terra
TAGSconnectwisehuntresslabtech-plusmicrosoft-defenderpowershell-execution-policy-bypassrmm-plussckitscreenconnectsession-cookie-theftsophostrapwatch

In plain words

Attackers gained access to some ConnectWise ScreenConnect remote-support accounts and used them to install their own hidden remote-control software on at least 288 devices across 48 organizations. This can let them keep control of affected computers even after the original account access is removed. The software may also spread when support technicians connect to infected devices, potentially putting more customer systems and technician accounts at risk.

Summary
Attackers are abusing compromised ConnectWise ScreenConnect panels or operator sessions to deploy rogue clients and the SCKit toolkit, affecting at least 288 endpoints across 48 organizations. ConnectWise disabled five third-party extensions as a precaution, while investigators have found no evidence of a ScreenConnect vulnerability or compromise of ConnectWise infrastructure.

ConnectWise disabled five third-party ScreenConnect extensions after reports of unauthorized access, affecting about 400 partner environments where at least one extension was installed. The company said it has no evidence that its infrastructure was compromised or that ScreenConnect contains a vulnerability, and it is investigating whether attackers abused independently installed extensions. Huntress observed attackers using cloud-hosted ScreenConnect panels to deploy rogue ScreenConnect clients on at least 288 managed endpoints across 48 organizations. Available telemetry suggests compromised credentials or hijacked operator sessions may have provided initial access, although the exact access method remains unclear.

The rogue clients deliver SCKit, a malicious toolkit that establishes persistent remote access and can intercept session cookies. Its components can add Microsoft Defender exclusions, create a scheduled task called TrapWatch, install another attacker-controlled ScreenConnect client, and replace a legitimate ScreenConnect installation. Huntress described a possible worm-like path in which an infected endpoint can target a technician who connects to it, then use the technician’s access to reach other ScreenConnect panels and endpoints; however, it had not observed a successful full progression of that path. Sophos also reported unauthorized deployments involving identified ScreenConnect instance IDs and infrastructure that downloaded and silently installed malicious ScreenConnect clients.

  • The rogue ScreenConnect client creates persistence that no longer depends on the initially compromised ScreenConnect panel, so removing access to that panel alone may not remove the attacker’s foothold.
  • The suspected spread to technician workstations and then to additional endpoints was reconstructed from malware scripts and tools, but Huntress had not observed a successful instance of that full spread path at the time of reporting.
  • The malware can use ScreenConnect’s Shared Toolbox to instruct every reachable connected device to run a payload as the highest-privilege system account, then delete the toolbox item about 60 seconds later.
  • Attackers assigned sequential numbers to compromised managed service providers, and the observed numbering began partway through the sequence, suggesting additional organizations may have been compromised before the reported cases.
  • Having one of the five disabled extensions installed does not by itself show that an organization was compromised, because their command-execution interface is protected by a partner-configured passphrase.
Key Points
  • 01ConnectWise disabled five third-party ScreenConnect extensions as a precaution after reports of unauthorized access, while stating it found no evidence of a ScreenConnect vulnerability or compromise of its own infrastructure.
  • 02Huntress observed attackers use cloud-hosted ScreenConnect panels to deploy rogue ScreenConnect clients to at least 288 managed endpoints across 48 organizations.
  • 03The observed activity uses the SCKit toolkit to establish persistent remote access, create a relay mechanism for intercepting session cookies, add Microsoft Defender exclusions, and create a scheduled task named TrapWatch.
  • 04Huntress said available telemetry points to compromised credentials or hijacked operator sessions as possible initial access methods, although the exact method remains unclear.
  • 05Sophos observed unauthorized ScreenConnect client deployments from three ScreenConnect instance IDs, including commands that downloaded and silently installed a ScreenConnect client from an identified IP address.

In plain words

The article explains how AI can investigate fake Microsoft Teams websites by checking who registered them, safely viewing copied login pages, finding related sites, and tracking how people may be led to them through search results or ads. These scams can affect anyone searching for or joining a Teams meeting, because the sites imitate familiar Microsoft pages and may try to lure visitors into downloading files. AI can help security staff spot these campaigns faster, but people still need to review its conclusions and approve actions because scammers can hide misleading instructions in the emails and web pages the AI reads.

Summary
Agentic AI can accelerate phishing investigations by gathering evidence across domains, cloned pages, search results, and infrastructure, but humans must validate attribution and approve any external or production actions. Because attackers can embed prompt-injection instructions in phishing content, agents need evidence trails, strict permissions, and controls that treat fetched content as untrusted data.

The article examines whether agentic AI can investigate phishing campaigns by collecting domain-registration data, safely rendering suspicious pages, finding related infrastructure, extracting indicators, and producing an evidence-backed verdict. It cites a Microsoft randomized trial of 167 security analysts in which users of the Security Copilot Phishing Triage Agent found up to 6.5 times more true positives per minute and were up to 77% more accurate. The article cautions that the study tested Microsoft’s own product and that its agent had 100% precision and recall on the test corpus, results that should not be expected unchanged in production.

Using lookalike Microsoft Teams domains identified by Steven Lim, including teams-online[.]com, teams-livemeeting[.]com, and teams-cloud[.]live, the article outlines an evidence-driven investigation. The domains used cloned Teams-style join pages, and the article describes search ads, organic results, and an AI-generated search answer as possible ways visitors could reach them; one fake update prompt downloaded a text file named realtek-demo.txt. It warns that attackers can hide instructions intended to mislead AI systems inside emails, attachments, and web pages, so agents should treat fetched content as untrusted data, log their tool use, attach evidence to every claim, and require human approval for blocks, takedowns, and other outward-facing actions.

  • A newly registered, privacy-protected lookalike domain with no threat-intelligence verdict should be treated as lacking information rather than as safe.
  • Phishing investigations cannot rely only on email because victims may reach impersonation sites through sponsored search results, ordinary rankings, or AI-generated search answers.
  • A shared registrar is weak evidence of a common operator, so claims that multiple domains belong to the same actor should require stronger links such as shared infrastructure, certificates, page code, or tracking identifiers.
  • The fake Teams update downloaded a text file named realtek-demo.txt, so the article advises reporting it as a staged lure rather than claiming malware delivery without evidence of an executable payload.
  • The article notes that AI performance figures from Microsoft's test corpus, where the agent had 100% precision and recall, should not be assumed to match production conditions.
Key Points
  • 01Agentic AI can independently collect phishing-investigation evidence such as domain registration details, safely captured web pages, related infrastructure, and indicators, but the article recommends human approval for actions such as blocks and takedown requests.
  • 02A Microsoft randomized trial involving 167 security analysts found that analysts using the Security Copilot Phishing Triage Agent found up to 6.5 times more true positives per minute and were up to 77% more accurate, although the article notes the trial used Microsoft's own product and test corpus.
  • 03The article uses lookalike Microsoft Teams domains, including teams-online[.]com, teams-livemeeting[.]com, and teams-cloud[.]live, to show how an investigation can connect cloned pages, young privacy-protected registrations, search placement, and a fake update lure.
  • 04The article warns that attackers can place hidden instructions in phishing emails, attachments, and web content intended to influence AI systems that read or summarize them.
  • 05It recommends treating all fetched content as untrusted data, separating read access from action permissions, requiring evidence for each verdict claim, logging tool calls, and retaining human approval for actions outside the organization.
