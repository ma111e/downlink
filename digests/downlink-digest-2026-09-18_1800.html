Public Exploits Released for Four Linux Kernel Flaws That Enable Local Root
thehackernews.com · 18 Sep 2026 18:02 UTC openai-codex / gpt-5.6-terra

In plain words

A researcher released working code that takes advantage of four newly fixed problems in Linux, the software that runs many servers and computers, to let someone with limited access take complete control. People and organizations using older, unpatched Linux versions are affected, especially shared systems where multiple users can log in. Although there are no known real-world attacks yet, making the code public increases the chance that criminals or other attackers could use it, so installing available updates is important.

Summary
Public proof-of-concept exploits for four Linux kernel flaws—DirtyAH6, TUNderflow, PPPoEject, and DiagSpill—can allow local users to gain root access on unpatched systems. Organizations should install distribution updates containing all four fixes, as disabling unprivileged user namespaces only mitigates three of the flaws.

Security researcher Asim Manizada released working exploit code for four Linux kernel flaws—DirtyAH6, TUNderflow, PPPoEject, and DiagSpill—that can allow a local user to gain root access. Linux kernel maintainers fixed all four flaws in recent weeks, but systems running older kernels remain at risk now that public exploit code is available. The exploits are tuned to specific kernel builds, may crash systems, and have not been reported as used in real-world attacks.

DirtyAH6, TUNderflow, and PPPoEject can be reached by ordinary users when unprivileged user namespaces are enabled, while DiagSpill needs no user namespaces or special privileges if the SCTP networking module is available. Two flaws can be triggered remotely only in narrow scenarios and mainly to crash a host: DirtyAH6 on certain IPv6 routers or gateways, and DiagSpill when non-default SCTP options are enabled. Users should update to kernels containing all four fixes and consult their Linux distribution’s security advisories, while disabling unprivileged user namespaces or unused affected features can reduce some exposure when patching is delayed.

  • Disabling unprivileged user namespaces can reduce exposure to three of the four flaws, but it does not mitigate DiagSpill or protect against processes that already have network-administration privileges.
  • Two flaws have narrow network-triggered crash scenarios: DirtyAH6 can affect IPv6 routers or gateways adding an Authentication Header in transport mode, while DiagSpill requires non-default SCTP options to be enabled.
  • Although all four bugs are in different networking components, their underlying coding mistakes are longstanding memory-safety issues ranging from 10 to 21 years old.
  • The public exploits were deliberately released after a coordinated hold with Linux distributions, but users must check their distribution advisories because distributions may backport fixes without using the upstream kernel version numbers.

Happy Birthday, Shai-Hulud
socket.dev · 18 Sep 2026 18:46 UTC openai-codex / gpt-5.6-terra

In plain words

The article looks back at Shai-Hulud, a malicious program that spread through npm, a widely used source of software building blocks, after criminals took over trusted packages such as tinycolor. It searched developers’ computers and automated build systems for passwords and access keys, then used those keys to infect more packages and potentially steal data or damage files. Hundreds of packages and more than a thousand organizations were affected over repeated waves, while many developers had to repeatedly replace access keys and check their software. Although police arrested two people allegedly tied to later attacks, the original creators are unknown and the code has been widely copied, making future incidents easier for others to carry out.

Summary
One year after the first npm Shai-Hulud compromise, its credential-stealing, self-propagating supply-chain technique has evolved into repeated waves run by multiple actors, aided by publicly released code and CI token hijacking. Although two alleged TeamPCP members were arrested, the original worm’s authors remain unidentified and the threat persists across the npm ecosystem.

A malicious version of @ctrl/tinycolor published to npm in September 2025 launched the first known self-propagating worm in the npm ecosystem. The Shai-Hulud payload used TruffleHog to search for npm tokens, GitHub credentials, and cloud keys, sent stolen secrets to attacker-controlled locations, and used stolen npm tokens to infect and republish other packages. It also created a GitHub Actions workflow for persistence, and researchers ultimately counted compromised packages in the hundreds.

Later waves expanded the threat through pre-install execution, new payloads, and a destructive fallback that could attempt to wipe a user’s home directory. In 2026, TeamPCP released source code for a Shai-Hulud worm framework, while multiple operators began running similar campaigns; one May burst pushed more than 400 malicious versions across 172 packages by hijacking short-lived OIDC tokens from CI. Australian police arrested two alleged TeamPCP members in August 2026, but the original authors of the September and November 2025 attacks remain unidentified, and the publicly copied code continues to enable new campaigns.

  • The threat evolved beyond stolen long-lived credentials: one May 2026 wave spread through hijacked short-lived OIDC tokens from CI systems, showing that short-lived access tokens did not prevent that campaign.
  • Moving malicious code to the pre-install step in November 2025 expanded exposure from package users to developer machines and automated build pipelines before installation completed.
  • TeamPCP’s release of the worm’s source code in May 2026 lowered the barrier for other operators, and the article reports that multiple actors were running Shai-Hulud-style campaigns by mid-2026.
  • Arrests of alleged TeamPCP operators do not resolve attribution for the original Shai-Hulud incidents, because the September and November 2025 attacks were never definitively linked to TeamPCP.
Key Points
  • 01A malicious version of @ctrl/tinycolor published to npm in September 2025 initiated the first known self-propagating worm in the npm ecosystem, which spread into dozens of packages and CrowdStrike’s npm namespace.
  • 02The Shai-Hulud payload used TruffleHog to find npm tokens, GitHub credentials, and cloud keys, sent discovered secrets to attacker-controlled locations, added a GitHub Actions workflow for persistence, and republished itself using stolen npm tokens.
  • 03A November 2025 wave moved execution to the pre-install step, introduced setup_bun.js and bun_environment.js, and included a fallback that could attempt to wipe a user’s home directory.
  • 04Later 2026 campaigns used publicly released Shai-Hulud source code, including a May burst that pushed more than 400 malicious versions across 172 packages by hijacking short-lived OIDC tokens from CI.
  • 05Australian Federal Police arrested two men in Western Australia on August 26, 2026 over alleged TeamPCP involvement, but the original authors of the September and November 2025 Shai-Hulud attacks remain unidentified.
