Unpatched Cacti Zero-Day Enables RCE in Just Four HTTP Requests via Guest Access
thehackernews.com · 27 Nov 2026 05:48 UTC openai-codex / gpt-5.6-terra
TAGS4http2root4http2shellcacticacti-corephp-popensecond-order-sql-injectionstacked-sql-queries

In plain words

A newly disclosed, unpatched flaw in Cacti, a tool organizations use to monitor their computer networks, can let an outsider take control of the server without logging in when guest access is enabled. It affects the latest Cacti Core 1.2.31 release and can be triggered with only four web requests. This matters because Cacti servers may hold connection details and passwords for routers, switches, and other systems, giving an intruder a possible path into a wider network or the ability to hide monitoring alerts.

Summary
An unpatched zero-day in Cacti Core 1.2.31 lets unauthenticated guest users achieve remote code execution in four HTTP requests by chaining stored SQL injection with unsafe poller command execution. Until a fix is released, disable guest access, restrict web-interface exposure, and inspect poller configurations for suspicious commands.

A newly disclosed, unpatched zero-day in Cacti Core 1.2.31 can allow unauthenticated remote code execution when the guest account is enabled. The proof-of-concept, tracked as 4HTTP2SHELL and 4HTTP2ROOT, reportedly reaches command execution as the Cacti server user in four HTTP requests. It does not require a login, valid API key, or phishing.

The issue begins when guest access is used to write non-numeric text into the preview_graphs_per_page setting, which controls graph pagination in Preview Mode. When the graph preview page is loaded with default filters, the stored value can be used for arbitrary SQL queries, including modification of a Cacti poller-table record. Calling the realtime poller endpoint then causes the modified command string to be passed to PHP’s popen() without allowlist or sanitization checks. Because Cacti can store credentials and connection details for network devices and servers, a compromised Cacti server could provide wider network access or enable suppression of alerts; users are advised to disable guest access, restrict web-interface access, and review poller entries for unexpected commands.

  • The flaw turns a seemingly minor graph-display preference into a path for server command execution because the value is stored first and only becomes dangerous later when Cacti loads the graph preview page.
  • An attacker does not need a Cacti login, valid API key, or phishing step if the default guest surface is enabled, making exposure of the web interface particularly consequential.
  • Compromise of a Cacti server could extend beyond the monitoring system because it may contain credentials and connection details for network devices and servers.
  • The same poller-table manipulation that enables command execution could also be used to suppress alerts, potentially reducing visibility into malicious activity.
Key Points
  • 01A proof-of-concept zero-day, tracked as 4HTTP2SHELL and 4HTTP2ROOT, can enable unauthenticated remote code execution in Cacti Core 1.2.31 when the guest account is enabled.
  • 02The attack uses guest access to store non-numeric text in the preview_graphs_per_page setting, which is later used to execute arbitrary database queries when the graph preview page is loaded.
  • 03The demonstrated attack modifies a Cacti poller-table record and then invokes the realtime poller endpoint, causing the stored command string to be passed to PHP's popen() function without allowlist or sanitization checks.
  • 04The researcher identified four contributing failures: guest users can write arbitrary strings to a numeric setting, stored defaults bypass validation, the PDO driver permits stacked statements through a SQL LIMIT clause, and the poller executes database-stored command strings.
  • 05Until a fix is available, users are advised to disable the guest account, limit access to the Cacti web interface, and review poller configuration entries for unexpected commands.

Switzerland Confirms AI-Assisted Cyberattacks Breached Critical Infrastructure Operators
thehackernews.com · 27 Nov 2026 06:04 UTC openai-codex / gpt-5.6-terra

In plain words

Swiss authorities say attackers using AI-powered software broke into four organizations, including two operators of essential services, though no major disruptions were reported. The victims also included small and medium-sized businesses, and similar fast-moving attacks have been reported in Italy, the United Kingdom, and at the European Commission. This matters because the software can automatically search for known weaknesses, try many ways in parallel, and adapt quickly, leaving organizations less time to stop intruders before services or data are affected.

Summary
Switzerland confirmed its first AI-agent-assisted intrusions, including successful breaches of critical-infrastructure operators, reflecting a wider European rise in autonomous attacks that exploit familiar weaknesses at far greater speed and scale. Authorities urge rapid patching, reduced internet exposure, strong authentication, and behavior-based monitoring.

Switzerland’s National Cyber Security Centre said attackers using AI agents breached systems at four of five Swiss organizations in recently reported cases. Three incidents targeted critical-infrastructure operators, with two successful intrusions, though no major disruptions were reported. The victims, which were not named, also included small and medium-sized companies. The agency described the cases as a shift in the cyber-threat landscape.

The agency said agentic offensive frameworks can scan for known unpatched weaknesses, conduct many attempts in parallel, and change methods when defenses react. Italy’s CSIRT Italia similarly reported campaigns in which autonomous AI agents compromised many systems within hours by combining security flaws, configuration errors, and stolen credentials. The UK National Cyber Security Centre said it has seen a marked rise in AI-assisted attacks since September 2026, including incidents causing downtime on internet-facing services and footholds for further activity.

Authorities emphasized that the attacks commonly rely on familiar weaknesses, including credentials committed to code repositories, poorly configured infrastructure, missing or default authentication, and API weaknesses. They recommended prioritizing patches for exposed systems, isolating systems that cannot be patched quickly, reducing internet exposure, using MFA or passkeys, and monitoring for unusual behavior, request bursts, error rates, and data volumes. The article also notes that attackers using ARTEX previously breached European Commission human-resources, medical-reimbursement, and translation systems.

  • The Swiss agency’s initial advisory said every known case involved a successful compromise, while a subsequent interview reported compromises in four of five confirmed cases without explaining the changed count.
  • The reported AI-agent activity often exploits long-standing problems such as exposed credentials, weak API security, default or missing authentication, and infrastructure configuration errors rather than requiring novel flaws.
  • Individual agent actions can resemble ordinary user or API activity, so identifying them depends on recognizing patterns such as request bursts, high error rates, unusual data transfers, and the sequence of actions.
  • The UK agency noted that these automated frameworks are noisy despite being fast and persistent, which can make them easier to detect when organizations correlate their logs.
  • Switzerland said the number of AI attack tools freely available online has nearly doubled since October, while emphasizing that this figure measures available tools rather than attacks or victims.
Key Points
  • 01Switzerland’s National Cyber Security Centre said AI agents breached systems in four of five confirmed recent attacks on Swiss organizations.
  • 02Three attacks targeted critical-infrastructure operators, and two succeeded without causing major reported disruptions.
  • 03Swiss authorities said agentic offensive frameworks can scan for known unpatched weaknesses, run attacks in parallel, and switch methods when defenses respond.
  • 04Italy’s CSIRT Italia reported that AI-directed autonomous agents compromised many systems within hours by combining vulnerabilities, configuration errors, and compromised credentials.
  • 05Swiss, Italian, and UK authorities recommended rapid patching, limiting internet exposure, strong authentication, and monitoring for unusual activity.
