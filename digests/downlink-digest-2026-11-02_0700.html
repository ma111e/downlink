In plain words

Ivanti released updates for two security problems in its Connect Secure remote-access systems that criminals have been using together with an earlier flaw to take complete control of affected devices without logging in. Organizations that use these internet-facing systems are at risk because they can provide a direct path into company networks and sensitive business or customer data. More than 5,000 Connect Secure devices are visible online, and U.S. federal agencies have been told to fix the earlier flaw by Friday.

Summary
Ivanti patched two additional Connect Secure zero-days, CVE-2026-111357 and CVE-2026-118527, that attackers chained with a previously patched authentication bypass to obtain unauthenticated root-level access. Administrators should urgently update exposed appliances, as exploitation has been observed since early October.

Ivanti released updates for two Connect Secure flaws, CVE-2026-111357 and CVE-2026-118527, that attackers had chained in zero-day attacks since at least October 1. CVE-2026-111357 is a high-severity privilege-escalation issue, while CVE-2026-118527 allows authenticated attackers to upload files to an unpatched device. The flaws were used alongside CVE-2026-104935, an authentication-bypass vulnerability Ivanti patched the previous month.

Volexity reported that UTA0576 had chained the three flaws since at least October 3 to gain root-level code execution on fully patched Connect Secure devices without logging in. According to Volexity, the actor did not deploy malware or a web shell, instead re-exploiting devices for each command and tampering with logs to evade Ivanti’s Integrity Checker Tool. CISA added CVE-2026-104935 to its catalog of actively exploited vulnerabilities and ordered U.S. federal agencies to patch by Friday, while Shadowserver tracks more than 5,000 Internet-exposed Connect Secure instances.

  • Patching CVE-2026-104935 first removed the primary attack path, but Ivanti later disclosed that attackers had been combining it with two additional flaws, showing why organizations should apply the full set of Connect Secure updates rather than treating the earlier patch as sufficient.
  • UTA0576 reportedly did not deploy malware or a web shell; instead, it re-exploited the device for each command and altered logs, a method that Volexity said evaded Ivanti's Integrity Checker Tool.
  • The scale of potential exposure remains significant: Shadowserver observed more than 5,000 Internet-exposed Connect Secure instances, while the article says it is unknown how many have been secured.
  • CISA's addition of CVE-2026-104935 to its actively exploited vulnerabilities catalog and its deadline for federal agencies indicate that the issue is being treated as an urgent, active risk.

  • 02Attackers chained these two flaws with the previously patched CVE-2026-104935 authentication bypass to obtain unauthenticated root-level code execution on fully patched Connect Secure devices.

Critical Linux kernel TCP vulnerability can allow remote code execution (CVE-2026-98432)
aikido.dev · 02 Nov 2026 09:00 UTC openai-codex / gpt-5.6-terra

In plain words

The article describes a serious flaw in many versions of Linux, the software that runs servers and the computers behind many online services. An outsider could potentially use it to take full control of an internet-reachable server without needing an account, especially where a certain connection feature is enabled. This affects the underlying machines used by cloud services and containers, so updating the server software and restarting those machines is urgent even when a website sits behind a proxy or load balancer.

Summary
CVE-2026-98432 is a critical Linux kernel IPv4 TCP use-after-free flaw that may enable unauthenticated remote code execution on reachable MPTCP-enabled services. Install your vendor’s patched kernel and reboot immediately; disabling MPTCP and filtering IPv4 IP options are only temporary mitigations.

CVE-2026-98432 is a critical flaw in Linux kernel IPv4 TCP connection handling that affects kernel 4.4 and later. The Linux kernel CVE team rates it 9.8 out of 10, while vendor assessments vary because the issue relies on winning a timing race. Anthropic reported that an unreleased Claude research model produced an exploit that gained root-level command execution on a Linux server with an MPTCP listener. No vendor advisory had reported exploitation in the wild as of October 29, 2026.

The flaw occurs when the kernel can free connection-related IP-options memory while another processor is still using it, potentially allowing memory disclosure, memory corruption, or a crash. Internet-reachable Linux hosts with IPv4 TCP ports are affected, including cloud virtual machines and the underlying nodes that run containers; a proxy on the same host does not prevent the kernel from handling the connection. The complete remediation is to install the vendor-patched kernel and reboot into it, while disabling MPTCP or dropping IPv4 packets carrying IP options are temporary measures. Operators should verify the running kernel with uname -r, because installing an update without rebooting does not activate the fix.

  • Go 1.24 and later programs request MPTCP listeners by default where the kernel permits it, which can expose a Go server even if its operator did not intentionally enable that feature.
  • A proxy running on the same Linux host does not protect that host, because its kernel still processes the incoming TCP connection before the proxy handles application traffic.
  • An installed kernel update is not sufficient until the machine restarts into it; the article notes that a host may appear fixed in scanning results even though it is still running the old kernel.
  • According to Anthropic, a failed attempt at the timing-dependent exploit only fails that connection attempt rather than crashing the target, allowing an attacker to keep retrying.
  • For containers, the relevant software to patch is the Linux kernel on the underlying node, not the container image itself.
Key Points
  • 01CVE-2026-98432 is a Linux kernel IPv4 TCP use-after-free flaw affecting kernel version 4.4 and later, which the kernel CVE team rates 9.8 out of 10.
  • 02Anthropic reported that an unreleased Claude research model produced an exploit that achieved root-level command execution on a Linux server with an MPTCP listener.
  • 03Installing a vendor-patched kernel and rebooting is the complete remediation, while disabling MPTCP or dropping IPv4 packets with IP options are temporary exposure-reduction measures.
  • 04Internet-reachable Linux hosts, including EC2 instances, ECS container instances, and EKS nodes, are affected when they expose an IPv4 TCP port; the container host kernel is what matters for containers.
  • 05No vendor advisory had reported exploitation in the wild as of October 29, 2026.

CyberStrikeAI in the wild: the use of AI in real-world attacks on organizations
securelist.com · 02 Nov 2026 08:00 UTC openai-codex / gpt-5.6-terra
TAGSafricaas-rep-roastingchinacyberstrikeaidcsyncgolden-ticketimpacketkasperskykerberoastinglatin-americalsass-minidumpmicrosoftmimikatzscheduled-taskwmi

In plain words

Kaspersky found attackers using CyberStrikeAI, a publicly available tool that lets an AI help direct malicious software on infected computers, against education organizations in several African and Latin American countries. After getting into victims’ systems, the attackers used the AI-assisted setup to gather information, move through networks, obtain account passwords, and copy database data. This matters because AI can make complex break-ins faster and easier for attackers, even when they rely on familiar methods that security tools can already recognize.

Summary
Kaspersky documented a real-world campaign against education-sector organizations in Africa and Latin America in which attackers used the open-source CyberStrikeAI framework to have a server-side LLM orchestrate post-exploitation actions through conventional C2 implants. The AI did not introduce novel on-host techniques, but accelerated familiar domain-compromise steps including reconnaissance, credential dumping, lateral movement, and data collection.

Kaspersky identified a campaign targeting education-sector organizations in several countries across Africa and Latin America that used the open-source CyberStrikeAI framework during post-exploitation. Attackers initially gained access through a compromised SQL Server, conducted manual reconnaissance, and later deployed a CyberStrikeAI implant. The framework uses a large language model on the command-and-control server to plan actions, select tools, and generate commands, while the implant executes those commands on compromised hosts.

In the observed incident, the attackers established persistence and performed local reconnaissance within minutes, conducted domain reconnaissance over several hours, and later performed lateral movement, credential dumping, and database export. They used familiar techniques including PowerShell, scheduled tasks, WMI, SMB, LSASS dumping through comsvcs.dll, DCSync, Golden Ticket attacks, and SQL and LDAP queries. Kaspersky concluded that AI orchestration can make these activities faster and lower the skill barrier for operators, but the on-host behaviors remain recognizable through established endpoint and network detection methods.

  • The AI component operated entirely on the attackers’ control server, so infected computers showed conventional command-and-control activity rather than local AI-service requests or unusual resource use.
  • Because the framework’s LLM can generate different forms of the same command and can remove an individual operator’s stylistic patterns, command behavior is less useful for attribution than build metadata and network artifacts.
  • A CyberStrikeAI server generates a new self-signed TLS certificate at every startup, making its certificate not_before value useful for reconstructing server restart chronology from scan history.
  • The implant’s fixed X-Implant-Token HTTP header is embedded at build time and can link payloads and network activity to the same command-and-control server.
  • The article concludes that established detection for scheduled tasks, LSASS dumping, WMI-based remote execution, LDAP reconnaissance, and similar behaviors remains effective because the AI orchestrator uses familiar post-compromise techniques.
Key Points
  • 01Kaspersky identified a campaign targeting education-sector organizations in several countries across Africa and Latin America that used the open-source CyberStrikeAI framework during post-exploitation.
  • 02CyberStrikeAI uses a server-side large language model to plan actions, select tools, and generate commands, while a conventional implant on compromised hosts executes those commands.
  • 03In one incident, attackers moved from deploying the CyberStrikeAI agent to persistence and local reconnaissance within two minutes, domain reconnaissance over five hours, and lateral movement, credential dumping, and database export within about one hour during the final stage.
  • 04The attackers used familiar techniques including scheduled tasks, PowerShell, WMI, SMB, LSASS memory dumping, DCSync, Golden Ticket attacks, and SQL and LDAP queries.
  • 05Kaspersky could not link the activity to a known threat group, although Chinese-language script comments, use of Chinese services, and server restart timing suggested a possible Chinese-speaking operator.
