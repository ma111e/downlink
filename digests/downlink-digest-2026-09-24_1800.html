In plain words

Researchers found a program called Carbonato that breaks into computers running Docker, a tool used to run software, when those computers are left open online without a password. It installs an AI-driven helper that can follow commands sent through Telegram, search for valuable login details and keys, and send the results back to its operators. Because it can automatically look for and infect other similarly exposed computers, one compromised machine can lead to more, putting organizations’ systems and sensitive access information at risk.

Summary
Carbonato is a worm-like botnet targeting unauthenticated Docker daemons on port 2375, deploying privileged containers and the Hermes Agent AI framework to steal credentials, execute commands, and persist on hosts. Defenders should keep Docker APIs off public networks and require authentication for Docker registries.

ThreatDown researchers discovered Carbonato, a worm-like botnet malware that targets Docker hosts whose daemon API is exposed on port 2375 without authentication. It was found in an unauthenticated Docker registry containing nearly 60 repositories and 4.3 GB of image data, with operational evidence spanning October 2024 to August 2026. Carbonato instructs the exposed Docker service to launch a privileged container, allowing access to the underlying host.

After infection, Carbonato opens a reverse SSH tunnel, installs an SSH server using an operator key, reports deployments through Telegram, and establishes persistence through cron jobs, systemd timers, rc.local, and OpenRC hooks. It also installs the Hermes Agent AI framework with a customized agent called GH0ST, which can receive Telegram tasks, collect AI API keys and credentials, run commands, and return results. The malware scans networks connected to infected hosts every five minutes for additional exposed Docker services, while defenders can look for the GH0ST persona file, CARBONATO_API_KEY, unexpected Telegram traffic, and reverse SSH tunnels toward AS262145.

  • Carbonato combines automated spreading with an operator-driven AI command loop: the agent interprets Telegram tasks, writes and runs terminal commands, reviews results, and reports back to the same chat.
  • The malware’s distribution infrastructure was exposed in an unauthenticated Docker registry containing nearly 60 repositories and 4.3 GB of image data, giving researchers operational evidence from October 2024 through August 2026.
  • Actionable indicators include a GH0ST persona file, the CARBONATO_API_KEY setting, unexpected Telegram communications, and reverse SSH tunnels to AS262145.
Key Points
  • 01Carbonato is a worm-like botnet malware that targets Docker hosts with unauthenticated daemon APIs exposed on port 2375.
  • 02The malware launches a privileged container, opens a reverse SSH tunnel, installs an SSH server with the operators' key, and establishes persistence through cron jobs, systemd timers, rc.local, and OpenRC hooks.
  • 03Carbonato installs the Hermes Agent framework and a customized agent named GH0ST that receives task commands through Telegram.
  • 04The GH0ST agent can collect AI API keys, SSH credentials, access tokens, and other data, run commands on infected hosts, and return results to a Telegram chat.
  • 05ThreatDown recommends keeping Docker daemon APIs off the network and requiring authentication on registries to prevent Carbonato infections.

In plain words

A researcher found that a harmful app installed on certain OnePlus phones could take complete control of the phone without asking the owner for any permissions. The issue was demonstrated on current and older OnePlus devices and may also affect OPPO phones because the companies share software. Although the app must first be installed, it could then access the phone at its deepest level, putting personal data and the device itself at risk until OnePlus releases a fix.

Summary
Unpatched flaws in OnePlus’s OxygenOS let a locally installed malicious app gain full root access without requesting permissions by chaining vulnerable OnePlus system services. The issues reportedly affect multiple OnePlus and OPPO devices, and no fix or CVE had been released at disclosure time.

Researcher Rasmus Moorats disclosed two unpatched OnePlus software flaws that a malicious locally installed Android app can chain to gain full root control without requesting permissions. He demonstrated the technique on a stock OnePlus 15 running the latest OxygenOS and also confirmed it on an older OnePlus 12 Pro. OnePlus told him that more OnePlus and OPPO devices may be affected because the companies use shared software.

The first flaw is in AtlasService, a root-running debugging service that accepts calls from any app and places unchecked app-provided text into a system command. That initially provides restricted root access, which can then be used to call OnePlus’s olc2 hardware helper and execute arbitrary shell commands with broad low-level Linux privileges. As of the September 24 disclosure, OnePlus had confirmed the flaws but had released no fix, assigned no CVE, and published no advisory; the article says the practical defense is to install apps only from trusted sources, since the attack requires a malicious app to already be installed.

  • The malicious app does not need to request permissions or show a prompt, so a user may not receive the usual warning signs before it gains control.
  • The first weakness alone provides only limited control, but chaining it with the second OnePlus service reaches the deepest system-level access, including the ability to load kernel code.
  • Until a fix is released, the article identifies installing apps only from trusted sources as the practical defense because the technique cannot begin unless a malicious app is already installed.
  • OnePlus asserted that it has the exclusive right to decide when the flaws may be publicly disclosed and warned the researcher of potential legal liability for publishing without its permission.
Key Points
  • 01Researcher Rasmus Moorats chained two unpatched flaws in OnePlus software to let a malicious installed app gain root-level control on a OnePlus 15 running the latest OxygenOS without requesting special permissions.
  • 02The first flaw is in OnePlus’s root-running AtlasService, which accepts calls from any app and passes unchecked app-supplied text into a system command, while the second involves the olc2 hardware helper executing shell commands for a root caller.
  • 03Moorats also confirmed the technique on an older OnePlus 12 Pro and said OnePlus told him the flaws affect additional OnePlus and OPPO devices that share software.
  • 04OnePlus confirmed both flaws in May 2026 but had released no fix, assigned no CVE, and published no advisory by Moorats’s September 24 disclosure.
  • 05The attack requires a malicious app to already be installed and running locally, and the article says there is no evidence the flaws have been used in real-world attacks.

Summary

MacSync, a Swift-based information-stealing program targeting macOS, has added a delivery method that uses public iCloud Calendar events to provide new payloads. Kaspersky reported that a downloader retrieves commands from a calendar event description and passes the retrieved data to the zsh shell. Commands placed after the event’s DESCRIPTION line download an archive containing an app bundle that acts as a dropper for later MacSync stages.

MacSync has been distributed through ClickFix-style social engineering, fake free or cracked software, and a fake cryptocurrency wallet named Toria that was promoted on social media. Its data-stealing component targets browser information and saved credentials, cryptocurrency wallet data, Telegram data, the Keychain file, device information, and SSH, AWS, Kubernetes, Git, and shell configuration files.   • The malware’s persistence is layered across a LaunchAgent, the user’s .zshrc file, and global Git hooks, and it also checks whether it needs to re-establish itself after reboot.
  • The Finder-disguised backdoor attempts to prevent macOS alerts from reaching users by terminating notification processes.
  • Beyond stealing data, the backdoor can alter a victim’s software environment by installing a browser extension or replacing an installed Ledger wallet application with versions supplied by its control server.

In plain words

U.S. Senators Mark Warner and Ted Cruz introduced a bill that would help phone and internet companies follow voluntary safety practices and earn an optional certification showing they do so. The bill follows the Salt Typhoon campaign, in which Chinese government-backed hackers reportedly spent years inside major U.S. telecom companies, accessing detailed calling records and sometimes calls and text messages. The affected information included communications involving senior government officials, showing that weaknesses in phone networks can expose both private people’s data and national-security communications. The proposal matters because it seeks to make these networks harder to break into, but unlike earlier rules, companies would not be legally required to adopt the practices.

Summary
Bipartisan senators introduced legislation to create voluntary, telecom-specific cybersecurity best practices and an optional independent certification program after the Salt Typhoon campaign compromised major U.S. carriers. The proposal favors industry-led guidance over the mandatory FCC telecom security rules that were repealed.

Bipartisan U.S. Senators Mark Warner and Ted Cruz introduced the Telecommunications Cybersecurity and Resilience Act, which would develop voluntary cybersecurity best practices for telecommunications companies. The bill would establish a Telecommunications Cybersecurity Working Group within the National Telecommunications and Information Administration, bringing together telecom firms, suppliers, cybersecurity experts, and federal officials. It would also create an optional certification process through which an independent third party could assess whether a company has implemented and maintained the practices.

The proposal follows the Salt Typhoon campaign, in which Chinese government-backed hackers reportedly gained years-long access to at least nine major U.S. telecommunications companies, including Verizon, AT&T, and Lumen. The intruders accessed detailed call records and, in some cases, intercepted call audio and text messages, with reporting saying they sought information on about 150 high-profile targets. Biden administration officials said measures including secure configurations, timely patching, monitoring for unusual activity, and multi-factor authentication for administrator accounts would have made the campaign more difficult and costly for the attackers. The voluntary approach replaces previously repealed FCC rules that would have required telecoms to secure their networks and annually certify that they had cybersecurity risk-management plans.

  • The legislation represents a shift from the previously repealed mandatory FCC telecom security requirements to voluntary practices and optional certification.
  • The Salt Typhoon intrusions reportedly gave attackers access not only to detailed call records but, in some cases, to call audio and text messages.
  • Biden administration officials concluded that baseline measures such as secure configurations, timely patching, monitoring for unusual activity, and multi-factor authentication for administrator accounts would have made the campaign harder and more costly for the attackers.
  • The proposed practices would be telecom-specific, reviewed every two years, and updated after major cyber incidents rather than remaining fixed over time.
Key Points
  • 01Senators Mark Warner and Ted Cruz introduced the Telecommunications Cybersecurity and Resilience Act to develop voluntary cybersecurity best practices for telecommunications companies.
  • 02The bill would establish a Telecommunications Cybersecurity Working Group within the National Telecommunications and Information Administration, including telecom companies, suppliers, cybersecurity experts, and federal officials.
  • 03The working group would review its recommended practices every two years, update them after major cyber incidents, and report annually to Congress.
  • 04The proposal would create an optional certification process in which an independent third party assesses whether a company has implemented and maintained the recommended practices.
  • 05The bill follows Salt Typhoon intrusions attributed to Chinese government-backed hackers that compromised at least nine U.S. telecommunications companies, including Verizon, AT&T, and Lumen.
