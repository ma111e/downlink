A threat actor used compromised AWS identity credentials associated with Qubole, a cloud data processing and analytics platform, to access multiple customer AWS environments.   • Previously configured but otherwise unused cross-account roles still provided attackers with a pathway into customer environments once Qubole IAM credentials were compromised.
  • The attackers collected secrets at a reported rate of 100 passwords and keys in seven minutes, highlighting how quickly a cloud intrusion can expand through exposed credentials.
  • Rather than targeting a predefined dataset, the attackers listed and downloaded data from every S3 bucket reachable through each assumed role, making excessive role permissions especially consequential.

Summary

Users should upgrade to Git 2.56.1 or the corresponding patched maintenance release and avoid recursively cloning untrusted repositories until updated.

Git released fixes for CVE-2026-111760, a flaw that can allow a malicious repository to run attacker-controlled code when it is recursively cloned with its submodules. The fixes are available in Git 2.56.1 and maintenance releases for versions 2.50 through 2.55. GitHub has applied the fixes to github.com and GitHub Enterprise Cloud, and released fixed GitHub Enterprise Server versions 3.19.15, 3.20.11, 3.21.9, and 3.22.4.

The issue is caused by an integer truncation in Git’s index handling, where an extremely long path can pass a safety check but later be written under a shorter attacker-chosen name, including .git. In a newly cloned submodule, .git is a file, allowing an attacker to replace it with a symbolic link to a folder containing malicious hooks or configuration; Git hooks can run programs at defined points. The releases also fix five additional issues involving path traversal, memory corruption, crashes from oversized patches, and unsafe fast-import features, while GitHub advises users to update and avoid recursively cloning untrusted repositories until fixed.

  • The recursive-clone issue depends on submodules because a newly cloned submodule uses a .git file, whereas Git refuses to replace an existing .git folder with a symbolic link.
  • Updating Git itself may not be sufficient where applications ship their own embedded copy of Git, so those applications also need updated versions.
  • Code-hosting servers may be exposed to CVE-2026-105437 through git merge-tree checks on pull or merge requests, because a repository-controlled .gitattributes setting can trigger the flaw.
  • Servers unable to immediately upgrade can reduce exposure to CVE-2026-105437 by setting conflict-marker-size=7 in each repository’s info/attributes file or disabling merge checks for untrusted repositories.
  • Git now blocks three risky git fast-import features in input streams by default, allowing them only when --allow-unsafe-features is explicitly set.
