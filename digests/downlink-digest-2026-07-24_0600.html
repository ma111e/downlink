In plain words

The Clop criminal group is breaking into internet-facing PTC Windchill and FlexPLM systems and stealing sensitive product information from companies. These systems are used by engineering, manufacturing, quality, supply chain, aerospace, defense, automotive, retail, and medical technology organizations to manage products from idea to manufacturing. The issue matters because stolen documents can be used for extortion, and Clop has a history of publishing stolen data online when victims refuse to pay.

Summary
Clop is exploiting a critical PTC Windchill and FlexPLM remote code execution flaw, CVE-2026-12569, to deploy JSP webshells and steal sensitive product data for extortion. Organizations using these platforms should urgently patch, restrict exposure, and check for compromise.

The Clop ransomware gang is targeting Internet-exposed PTC Windchill and FlexPLM instances in a new data theft extortion campaign. ReliaQuest reported that attackers are actively exploiting CVE-2026-12569, a critical improper input validation and unsafe deserialization vulnerability affecting the two PLM platforms. The flaw enables unauthenticated remote code execution, and attackers have been deploying JSP web shells to run commands and exfiltrate sensitive product data.

PTC began releasing security patches for CVE-2026-12569 on June 17 and urged customers to review their environments for indicators of compromise. CISA added the vulnerability to its Known Exploited Vulnerabilities catalog after PTC warned customers of heightened threat activity and ordered U.S. federal agencies to secure affected systems within three days. German authorities also acted urgently, with BSI reportedly emailing and calling PTC customers during the night to warn them to patch as quickly as possible.

Windchill and FlexPLM are Product Lifecycle Management platforms used to track, design, and manage products from concept through manufacturing. PTC says its products are used by more than 30,000 customers globally, including over 1,500 brand and retail customers using FlexPLM, across sectors such as aerospace, defense, automotive, heavy machinery, retail, and medtech. Clop has a history of stealing data from enterprise platforms and publishing stolen files on its dark web leak site if victims refuse to pay a ransom.

  • Clop’s use of a newly announced extortion email address, support@cryptohox.com, is consistent with the group’s pattern of changing contact addresses before launching a new extortion campaign.
  • Government response indicates unusual urgency, with CISA requiring U.S. federal agencies to secure affected systems within three days and Germany’s BSI reportedly contacting PTC customers during the night.
  • ReliaQuest’s recommended response goes beyond patching: suspected victims should isolate affected servers, collect forensic artifacts, and rotate exposed credentials before restoring service.
  • The targeted platforms may contain especially valuable data because Windchill and FlexPLM are used to manage product design and manufacturing information across sectors including aerospace, defense, automotive, retail, and medtech.

In plain words

Redis, a widely used data software project, released seven security fixes after researchers published working examples showing how someone with the right login access could make affected Redis versions run commands they choose. People and organizations using the listed Redis 6.2, 7.2, 7.4, 8.2, 8.4, 8.6, or 8.8 branches may need to install the fixed version for their branch, especially because some versions that were updated in May still needed another update in July. The real-world risk is that these flaws could let an intruder take control of a Redis server, so Redis users are told to upgrade, limit who can use the RESTORE command, and block untrusted network access.

Summary
Redis released seven security updates after researchers published authenticated RCE proof-of-concepts abusing RESTORE to exploit memory corruption in Redis Streams and RedisBloom TDigest loaders. Users should upgrade to the fixed branch release immediately and revoke RESTORE from accounts that do not strictly need it.

Redis shipped seven security releases on July 23 after researchers published authenticated remote code execution proof-of-concept exploits for stock Redis 6.2.22, 7.4.9, 8.6.4, and 8.8.0. Redis says the underlying memory flaws may lead to remote code execution. The article says neither Redis’s July 23 release notes nor the reviewed public proof-of-concept repositories reported in-the-wild exploitation as of July 24, 2026.

All four exploit chains require the RESTORE command. The Redis Streams chains also need EVAL and XGROUP, while the Redis 8.8.0 chain needs EVAL and the bundled RedisBloom module. The article describes one path as a Streams shared-ownership bug that can lead to a double free, and the other as an out-of-bounds write in the RedisBloom TDigest RDB loader.

Redis 6.2.23, 7.2.15, and 7.4.10 fix the Streams shared-NACK use-after-free, while Redis 8.2.8, 8.4.5, and 8.6.5 fix both the Streams issue and the RedisBloom and TDigest out-of-bounds writes. Redis 8.8.1 fixes the RedisBloom and TDigest loaders, while the Streams guard was already present in Redis 8.8.0. The article recommends upgrading to the fixed release for the deployed branch, revoking RESTORE from accounts that do not strictly need it, and blocking untrusted network access.

  • Restricting the RESTORE command is an especially high-value mitigation because the article says it cuts off both disclosed exploit paths, even though the chains differ internally.
  • Being “recently patched” was not enough in this case, because Redis 6.2.22 and 7.4.9 were May security update targets but still lacked the shared-NACK ownership guard fixed in July.
  • The public vulnerability tracking picture was incomplete at publication time, as Redis’s July release notes listed no CVE or CVSS score for the new bug classes and NVD still only showed the May records.
  • The Redis 8.6.4 release notes cited a pull request for the Streams fix, but the article’s source review found the tagged 8.6.4 source did not contain the duplicate-ownership check that appeared in 8.6.5.
  • The article distinguishes confirmed facts from self-reported AI claims: Redis’s public record confirms the flaws and fixes, but not the claimed count of 19 zero-days or the degree of agent autonomy.

In plain words

Ukraine’s computer emergency team warned that a Russia-aligned group is sending deceptive emails that lead Windows users to download a fake Notepad++ add-on, which can secretly install harmful programs. The people most directly affected are users and organizations that open these files, especially in Ukraine, while the article also describes related Russian-linked spying campaigns against Western government and business email systems. This matters because these operations can steal sensitive communications, keep long-term access to mail systems, and may test techniques in Ukraine before using them more widely against NATO allies and others.

Summary
CERT-UA warns that Russia-aligned UAC-0099 is using phishing emails to deliver a fake Notepad++ plugin that installs the MATCHBOIL.V2 loader on Windows systems. The campaign highlights continued Russian targeting of Ukrainian and Western organizations using deceptive software packages and webmail exploitation techniques.

CERT-UA warned of a new campaign that uses a malicious program disguised as a Notepad++ plugin to compromise Windows systems. The activity is attributed to UAC-0099, a Russia-aligned threat cluster active since at least mid-2022. The group has previously used WinRAR flaws, phishing emails, and malware including LONEPAGE, MATCHBOIL, MATCHWOK, and DRAGSTARE.

The latest attacks begin with a phishing email containing an image attachment that leads through a shortened URL to a file-sharing service hosting a ZIP archive. The archive contains a VBScript masquerading as a PDF, which displays a decoy PDF while downloading another archive named Evernote.zip. That archive includes a legitimate copy of Notepad++ 8.8.3, a malicious NppExport.dll plugin, a password-protected updater.rar archive, and winrar.exe.

The malicious DLL, codenamed LUNCHPOKE, unpacks updater.rar and sets up persistence by creating a scheduled task that runs RemoteLibUpdater.exe every three minutes. RemoteLibUpdater.exe is BURNYBEAR, a loader for InitTest.dll, a modified version of the C#-based MATCHBOIL loader now called MATCHBOIL.V2. CERT-UA recommends organizations update WinRAR, 7-Zip, and Notepad++ to the latest versions to reduce the risk of known vulnerabilities being used in follow-on attacks.

  • CERT-UA’s mitigation advice is broader than the fake Notepad++ plugin itself, urging organizations to update WinRAR, 7-Zip, and Notepad++ because known flaws in these tools can support follow-on attacks.
  • The campaign uses a full legitimate copy of Notepad++ alongside a malicious plugin, which makes the malware delivery package appear more credible while abusing normal plugin-loading behavior.
  • BURNYBEAR contains a destructive fallback behavior: if RemoteLibUpdater.exe is run without the expected arguments, it attempts to exhaust the computer’s RAM and processor resources.
  • The article highlights a broader Russian-linked pattern in which Ukrainian users are targeted first both as a priority and as a testing ground before techniques are used against U.S. and other NATO-aligned targets.
  • Laundry Bear’s Zimbra campaign is notable because it can trigger by viewing a malicious email in a vulnerable webmail service, rather than requiring the user to click a link or open a file.

NodeBB Patches Eight AI-Found Flaws Exposing Admin Access and Private Chats
thehackernews.com · 24 Jul 2026 07:41 UTC openai-codex / gpt-5.5

In plain words

NodeBB, software used to run online forums, fixed eight serious weaknesses that an AI security tool found, including problems that could let people see private chats, view private forum areas, change posts, or reach parts of the administrator area. Every version before 4.14.0 is affected, and forum owners are told to upgrade to 4.14.2. Forums freshly installed on version 4 were more exposed because their connection to other social sites was on by default, while upgraded version 3 forums were affected by fewer of the flaws unless that feature had been turned back on. This matters because private conversations and administrator tools on public forums could be exposed even when no real-world attacks have been reported yet.

Summary
NodeBB patched eight high-severity flaws found by AI testing that could expose admin access, private messages, private categories, and enable XSS or post manipulation, with all versions before 4.14.0 affected. Administrators should upgrade to 4.14.2 because disabling federation only reduces exposure and does not fix all issues.

Eight security flaws in NodeBB were publicly disclosed along with exploit code, after Aikido Security said its AI pentest agents found them during a six-hour review of the forum software’s source code. Aikido rated all eight as high severity, and every NodeBB version before 4.14.0 is affected. NodeBB has fixed all eight, and administrators are advised to upgrade to version 4.14.2.

The flaws included a settings issue that could let a regular forum member open the admin dashboard, unauthenticated access to private messages and private categories, post takeover, vote inflation, and malicious code planted through federation-related paths. The widest flaw involved NodeBB’s page-building process, where user input could smuggle in translation codes that later allowed an attacker to plant a link that runs code when clicked. Most access from the admin dashboard issue was read-only, but it included items such as the error log and exported user lists, and the user could also change the site logo.

Five of the eight issues were in NodeBB’s federation code, which affects exposure differently depending on how a forum was installed or upgraded. Fresh version 4 installations federate by default and had all eight flaws, while forums upgraded from version 3 had federation switched off automatically and were affected by only three unless an administrator turned federation back on. None of the eight flaws has a CVE tracking number, and the article says no attacks using them have been reported.

  • Disabling federation is not a complete mitigation because three of the eight flaws are unrelated to NodeBB's federation code.
  • Fresh NodeBB version 4 installations were more exposed than upgraded version 3 forums because federation is enabled by default on fresh version 4 installs but was automatically switched off during version 3 upgrades.
  • The admin dashboard issue shows a server-side authorization gap because the interface blocked the dangerous homepage setting only in the browser, where it could be bypassed.
  • The fixes were spread across multiple releases from May through July, so administrators need the latest 4.14.2 release rather than assuming a single earlier patch fully addressed the problem.
  • The 4.14.0 template-handling rebuild touched 325 files, so upgrading may require extra work for sites using custom themes or plugins.
Key Points

  • 02Every NodeBB version before 4.14.0 is affected, all eight flaws have been fixed, and administrators are advised to upgrade to version 4.14.2.
  • 03The flaws included a member-accessible admin dashboard issue, unauthenticated access to private messages and private categories, a sitewide link-based code execution issue, post takeover, vote inflation, and two federation-based malicious code issues.
  • 04Five of the eight flaws were in NodeBB's federation code, so freshly installed version 4 forums with federation on by default had all eight flaws, while upgraded version 3 forums with federation off had only three applicable flaws.
  • 05None of the eight flaws has a CVE tracking number, and nobody has reported attacks using them.
