In plain words

Researchers found serious flaws in WordPress, the software used by more than 500 million websites, and public examples showing how to abuse them have now appeared online. Websites running affected WordPress versions 6.9.x and 7.0.x could be taken over by someone without needing to log in first. WordPress has released fixes and turned on forced automatic security updates for supported affected sites, but site owners are still being urged to update immediately because early real-world abuse has already been reported.

Summary
Public exploits are now available for the critical WordPress Core “wp2shell” flaws that can enable unauthenticated remote code execution on affected 6.9.x and 7.0.x sites. Administrators should immediately update to WordPress 7.0.2 or 6.9.5, with WAF or REST API blocking only as temporary mitigation.

Public proof-of-concept exploits have been released for the critical “wp2shell” remote code execution vulnerabilities affecting WordPress Core. The flaws, tracked as CVE-2026-63030 and CVE-2026-60137, can be chained to achieve pre-authentication remote code execution against WordPress installs running affected 6.9.x and 7.0.x versions. Searchlight Cyber said the attack has no preconditions and can be exploited by an anonymous user against a stock WordPress installation with no plugins.

The complete RCE chain affects WordPress 6.9.0 through 6.9.4 and WordPress 7.0.0 through 7.0.1, and it has been fixed in WordPress 6.9.5 and 7.0.2. WordPress enabled forced automatic security updates for supported installations running affected versions and urged site owners to update immediately. The SQL injection flaw also affects WordPress 6.8.0 through 6.8.5, but the article says it cannot be chained to RCE there because the REST API batch-route confusion bug was added in WordPress 6.9.

Searchlight Cyber is withholding technical details and created wp2shell.com so administrators can test whether their installations are vulnerable. For organizations unable to update immediately, it recommends temporarily blocking anonymous REST API access or blocking /wp-json/batch/v1 and ?rest_route=/batch/v1 at a WAF level. Cloudflare deployed WAF protections for both vulnerabilities, and watchTowr said it has seen public exploit code in circulation and the first signs of in-the-wild exploitation.

  • The RCE risk is version-dependent: WordPress 6.8.x is affected by the SQL injection flaw, but the article says it cannot be chained to remote code execution because the REST API batch-route confusion bug was introduced only in WordPress 6.9.
  • Searchlight Cyber withheld technical details and created a testing site for administrators, but multiple public GitHub proof-of-concept exploits appeared anyway, shrinking the patching window for site owners.
  • Some public exploits reportedly rely on cracking an administrator password after extracting WordPress password hashes, while others claim pre-authentication remote code execution, showing that the public exploit landscape is not uniform.
  • The recommended temporary mitigations focus specifically on blocking anonymous REST API access or the batch endpoint, indicating that reducing exposure to `/wp-json/batch/v1` and `?rest_route=/batch/v1` is a practical short-term control when immediate patching is not possible.
  • Cloudflare’s WAF protections were deployed even for free accounts, but Cloudflare explicitly said these protections only reduce exposure and are not a substitute for updating WordPress.
Key Points

  • 02The wp2shell attack chains CVE-2026-63030, a REST API batch-route confusion flaw, with CVE-2026-60137, an SQL injection flaw in the author__not_in parameter of WP_Query.

In plain words

Elastic Security Labs found a North Korea-linked campaign where fake recruiters offered developers coding challenges that contained hidden harmful code inside image files. Developers who ran these projects could have their saved browser passwords, crypto wallet data, personal files, and clipboard contents stolen, while the attackers also gained remote access to the computer. This matters because one compromised developer can give attackers a starting point to reach the organizations and software projects that depend on that developer’s work.

Summary
Elastic Security Labs uncovered a DPRK-aligned Contagious Interview campaign that lures developers with fake coding challenges and hides OTTERCOOKIE-like malware inside SVG files. Running the trojanized projects can steal browser credentials, crypto wallets, sensitive files and clipboard data while installing a Socket.IO-based remote access backdoor.

Elastic Security Labs discovered a new DPRK-aligned Contagious Interview campaign, tracked as REF9403, after a fake recruiter targeted its community Slack workspace with a job posting and coding challenge. The trojanized projects were fully functional e-commerce templates, but they silently executed malicious code when users ran the server. Elastic said the activity overlaps with prior reporting on OTTERCOOKIE based on code similarity, behavior, and related infrastructure.

The campaign matters because developers are the direct targets, and a compromised developer machine can provide attackers with access to credentials, keys, wallets, files, and potentially downstream organizations. The payload delivered four main capabilities: a browser credential and crypto wallet stealer, a file stealer, a Socket.IO-based remote access trojan, and a clipboard stealer. The malware collected browser login data, wallet extension databases, sensitive files, shell histories, cloud and SSH configuration paths, and macOS keychain data.

A key technique in the infection chain was hiding Base64 payload fragments inside HTML comments across SVG flag images in the project’s assets directory. A JavaScript file reassembled the fragments in alphabetical order, decoded them with a custom Base64 function, and executed the result with eval during server startup. Elastic also observed command-and-control activity using rightwidth[.]dev subdomains, including upload endpoints, a Socket.IO controller, and Windows second-stage download paths.

  • The trojanized repositories had zero antivirus detections at the time of writing, showing that benign-looking coding assignments can evade standard file reputation checks even when they contain active credential theft and remote access code.
  • The campaign used fully functional e-commerce projects copied from legitimate templates, so a project running correctly was not evidence that it was safe.
  • The malware avoided simple detection patterns by hiding payload fragments in SVG comments and decoding them with a custom Base64 function before using eval, rather than relying on common decoding methods such as Buffer.from or atob.
  • The file stealer’s exclusion list deliberately avoided many common developer and AI-coding-tool directories such as .claude, .cursor, .gemini, and .windsurf, indicating the attackers tuned collection to reduce noise on developer systems.
  • The malware tagged virtual machines and sandboxes in its command-and-control response but did not stop running, which means analysis environments may still observe behavior while operators can separately prioritize likely real victims.
Key Points

  • 02The trojanized projects hid Base64-encoded payload fragments inside HTML comments across SVG flag images, then reassembled and executed the payload when the project server started.
  • 03Running the malicious project delivered four OTTERCOOKIE-aligned capabilities: a browser credential and crypto wallet stealer, a file stealer, a Socket.IO-based remote access trojan, and a clipboard stealer.
  • 04The malware targeted developer machines across Windows, macOS, and Linux by collecting browser data, wallet extension databases, sensitive files, shell histories, cloud and SSH configuration paths, and macOS keychain data.

In plain words

Microsoft says it has seen a rise in attacks against its business customers using a password-stealing program called ACR Stealer. The attackers trick people into copying and running commands that secretly install the program, which can take saved browser passwords, sign-in tokens, cookies, and sensitive work files from places like Desktop, Downloads, OneDrive, and SharePoint. This matters because stolen sign-in data and documents can give criminals access to company accounts and private business information.

Summary
Microsoft says ACR Stealer attacks are surging against enterprise customers, using ClickFix lures, WebDAV, MSHTA, and obfuscated PowerShell to steal browser credentials, tokens, and business documents. Organizations should restrict risky script/tool execution and web-based delivery paths to reduce exposure.

Microsoft has observed a surge in attacks using ACR Stealer malware against its enterprise customers between late April and mid-June. The malware is used to steal browser-stored passwords, authentication tokens, and sensitive documents. Microsoft says ACR Stealer is a malware-as-a-service operation believed to be a rebranding of Amatera Stealer.

Microsoft highlighted two prevalent delivery chains involving ClickFix social-engineering lures. One chain runs a malicious DLL from a remote WebDAV share using rundll32.exe, then uses obfuscated PowerShell, a bundled Python loader, a scheduled task for persistence, timestamp manipulation, PowerShell history clearing, and in-memory payload execution. Some variants use public blockchain services as dead-drop resolvers to obtain updated payload locations or command-and-control addresses.

A second chain uses ClickFix to launch MSHTA, retrieve malicious content from the attacker’s server, and run an obfuscated PowerShell downloader that extracts an encrypted payload hidden inside a publicly hosted JPEG image. The malware targets passwords, cookies, session data, authentication tokens, Chromium browser databases on Chrome and Edge, PDFs, Microsoft 365 documents, Desktop and Downloads folders, and enterprise-synchronized OneDrive and SharePoint directories. Microsoft recommends avoiding copied command instructions, filtering and blocking low-reputation or new domains, restricting unnecessary online resources, and using application control rules for tools such as PowerShell, Python, mshta.exe, and rundll32.exe.

  • The ACR Stealer campaigns rely heavily on trusted Windows utilities such as MSHTA, rundll32.exe, PowerShell, and scheduled tasks, making application control around these tools especially relevant when they launch content from remote or user-writeable locations.
  • Some ACR Stealer variants use public blockchain services as dead-drop resolvers for updated payload locations or command-and-control addresses, so blocking only fixed attacker servers may be insufficient for the observed activity.
  • The WebDAV-based campaign uses GUID-style directories and legitimate-looking filenames such as google.ct to make malicious network paths appear normal, which makes domain and resource reputation filtering more important than filename appearance alone.
  • The malware specifically targets enterprise-synchronized OneDrive and SharePoint directories in addition to local Desktop and Downloads folders, increasing the potential business impact beyond a single infected device.
Key Points
  • 01Microsoft observed a surge between late April and mid-June in attacks using ACR Stealer to steal browser-stored passwords, authentication tokens, and sensitive documents from enterprise customers.
  • 02The threat actor used ClickFix social engineering, WebDAV servers, and the MSHTA utility to deliver the ACR Stealer payload.
  • 03One common intrusion chain uses a ClickFix lure to run a malicious DLL from a remote WebDAV share with rundll32.exe, followed by obfuscated PowerShell, a bundled Python loader, persistence through a scheduled task, and in-memory payload execution.
  • 04A second common intrusion chain uses ClickFix to launch MSHTA, retrieve malicious content from the attacker’s server, run an obfuscated PowerShell downloader, and execute an encrypted payload hidden inside a publicly hosted JPEG image.
  • 05Microsoft recommends defenses including avoiding copied command instructions from websites, filtering or blocking low-reputation and new domains, restricting unnecessary online resources, and using application control rules for tools such as PowerShell, Python, mshta.exe, and rundll32.exe.

7-Zip version 26.02 was released to fix a remote code execution vulnerability that could allow attackers to execute malicious code if users open specially crafted compressed files. The flaw was disclosed by Lunbun researcher Landon Peng and exists in 7-Zip’s processing of XZ-compressed data. According to a Zero Day Initiative advisory, specially crafted XZ data can trigger a heap-based buffer overflow and potentially allow arbitrary code execution as the user.

The developer has not published technical details about the flaw, but the 26.02 source code changes suggest it is related to how 7-Zip tracks available space while decompressing XZ data. The patch adds checks to ensure the decoder cannot write beyond the remaining available space in an output buffer. The advisory says exploitation requires user interaction, such as visiting a malicious page or opening a malicious archive file.

7-Zip does not include an automatic update feature, so users must manually download the latest version from 7-zip.org to receive the fix. The article notes that 7-Zip is widely used on Windows and that flaws in archive utilities can be attractive to threat actors. There are currently no reports that attackers are actively exploiting this newly disclosed vulnerability, but users are advised to update to version 26.02 as soon as possible.
