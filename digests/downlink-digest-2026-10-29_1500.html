    In plain words

    Researchers found 70 harmful AI add-ons disguised as useful tools for programmers and office work. These add-ons told users to install an extra program that could steal saved passwords, logged-in website access, and sensitive files from Mac computers used for work. Even though the add-ons had strong safety ratings in a popular directory, they could put company accounts, code, and internal systems at risk, showing that ratings alone are not enough to prove an AI add-on is safe.

    Summary
    Cyera Research found 70 malicious AI skills posing as developer and productivity tools that instructed users to install the Atomic macOS Stealer (AMOS), potentially exposing corporate credentials, browser sessions, and sensitive files. All carried favorable marketplace security grades, underscoring that organizations must review full skill packages and prevent agents from installing software without explicit human approval.

    Cyera Research found 516 exhibits linked to an operation distributing Atomic macOS Stealer (AMOS) and confirmed 70 new malicious AI skills across six repositories and platforms in September 2026. The skills posed as developer and productivity tools, then instructed users to install a supposedly required additional component that delivered credential-stealing malware. All 70 skills had high security grades from Skills Directory when collected, despite being malicious.

    AMOS is designed to collect saved passwords, browser sessions, and sensitive files, which on a corporate Mac could expose company accounts, code, cloud access, or operational information. Skills Directory’s published grading methodology covers the main SKILL.md instruction file rather than all bundled scripts and supporting files, so its grades do not guarantee safety. The article recommends requiring direct human approval before agents install software, reviewing complete skill packages, educating employees to report suspicious AI assets, assigning owners to sensitive skills, and continuously monitoring agent behavior.

    • A favorable marketplace grade can create misplaced confidence because Skills Directory’s published methodology evaluates the main SKILL.md instruction file rather than every bundled script and supporting file.
    • Removing malicious skills from a repository reduces future availability but does not establish whether users or agents already followed their instructions, installed software, or exposed information.
    • The risk extends beyond the initial AI product approval: a skill can later introduce a dependency, request additional access, or direct activity to an outside service, changing what the agent can do.
    • Instructions labeled “Prerequisites,” “Setup,” “IMPORTANT,” or “CRITICAL REQUIREMENT” should receive added scrutiny when they demand extra installation before a skill can perform its promised function.

Researchers found hundreds of add-ons for AI assistants that secretly tell people or the assistants to install software that steals passwords, browser information, and other private files from Mac computers. The harmful instructions were hidden among normal-looking setup notes, and some add-ons received strong safety ratings from online marketplaces despite being dangerous. Summary
Cyera identified 516 AI-agent skills linked to the Atomic macOS Stealer (AMOS) campaign, including 70 confirmed malicious skills that received high automated security grades on popular marketplaces. The skills hide fake setup prerequisites that trick users or agents into downloading and executing credential-stealing payloads, demonstrating a major supply-chain risk for AI skill ecosystems.

Cyera Research identified 516 AI skills associated with the Atomic macOS Stealer (AMOS) campaign across AI-skill repositories and related datasets. Of 70 skills confirmed as malicious across six repositories in September 2026, every one had received an A or B automated security grade from a popular marketplace when Cyera found it. The findings show that apparently useful AI-agent skills can conceal harmful installation instructions within ordinary-looking documentation.

The poisoned skills commonly present fake software prerequisites, directing macOS users to decode Base64 text and run it through Bash, while Windows users may be told to download and execute a separate package. AMOS can collect browser passwords and session cookies, keychain information, and sensitive files before sending them to attacker-controlled infrastructure. Cyera found substantial infrastructure reuse, with 91.92.242.30 accounting for 83.7% of payload-host references and two glot.io snippets accounting for 95.9% of paste-relay references.

  • Most newly identified malicious skills were marked malicious and removed from repositories roughly one week after collection, indicating a period in which published skills could remain available before removal.

How to Vet AI Agent Skills: Lessons From a Fake PDF Skill

In plain words

Researchers found a fake version of Anthropic’s PDF helper for AI agents that kept the familiar name and working PDF files but replaced its directions and included a program that could let someone else control a Linux computer. Employees and organizations using copied AI helper packages could be affected, especially where those helpers can access documents, passwords, or company systems. The case shows that a familiar name is not enough: companies need to check every file and instruction in an AI tool before allowing it to run.

Summary
Cyera researchers found a malicious copy of Anthropic’s PDF skill that preserved legitimate-looking files and branding while replacing its instructions and adding a Linux backdoor. Organizations should verify every file and instruction in AI skill packages, restrict agent permissions, and scrutinize unexpected executables or network destinations.

Cyera Research analyzed a malicious copy of Anthropic’s PDF skill that retained the familiar name, description, and 11 files matching the official package. The altered package replaced the main SKILL.md instructions and added a 5 MB Linux executable containing a backdoor. Cyera identified the original ZIP file and five related archives observed between May 23 and July 14, 2026.

The SKILL.md file was reduced from 315 lines to 19 and instructed the agent to make a network call to a Chinese domain. If the added executable runs, a remote operator may be able to issue commands using the permissions of the account that launched it, although researchers found no direct code or instructions to execute the binary. The article says organizations should verify complete skill packages against their claimed sources, inspect instructions as well as bundled code, investigate unexpected files and network destinations, and limit agent permissions for network access and software execution.

  • A package can appear trustworthy even when its recognizable name, description, and legitimate processing scripts are unchanged, because altered instructions can redefine what an AI agent is asked to do.
  • Traditional scanning of executable code alone may miss AI-skill risks, since the written instructions that guide an agent’s actions also require review for hidden or unexpected behavior.
  • Comparing every file in a downloaded skill against its claimed source would have exposed both the rewritten instruction file and the added executable, despite 11 files matching the official package exactly.
  • The risk from a suspicious skill depends heavily on the permissions available to the agent or account running it, making limits on network access and program execution an important safeguard.
Key Points
  • 01Cyera researchers identified a malicious copy of Anthropic’s PDF skill that retained its familiar name, description, and 11 legitimate matching files while altering its main instruction file and adding a Linux executable containing a backdoor.
  • 02The malicious SKILL.md was reduced from 315 lines to 19 lines and instructed the agent to make a network call to a Chinese domain.
  • 03If the added program runs, a remote operator may be able to issue commands with the permissions of the account that launched it.
  • 04The researchers found no direct code or instructions to execute the added binary, but the instructions were configured to call an external URL whose domain resolved to a private IP address during the research.
  • 05Cyera recommends that organizations verify complete AI skill packages against claimed sources, inspect changed instructions and unexpected files, and limit agent permissions for network access and software execution.

It is broadly relevant to organizations adopting AI agents, although the article reports no confirmed execution of the backdoor or identified victim impact.

In plain words

The article discusses PHP2Shell, two serious flaws in PHP that could let someone take control of a website or server without signing in. Millions of internet-connected computers and websites may be affected, but public estimates differ because services count and scan the internet in different ways. This matters because organizations need accurate information to find their own exposed systems, apply fixes, and understand whether suspicious activity may come from attackers using the flaws.

Summary
Censys argues that widely differing PHP2Shell exposure counts reflect differences in scanners, units of measurement, banner visibility, query logic, and scan timing. It promotes its first-party Internet Map as a comprehensive way to track affected PHP hosts, web properties, patching progress, and related attacker infrastructure.

PHP announced emergency fixes on October 20 for two pre-authentication remote code execution flaws, CVE-2026-109618 and CVE-2026-109619, known together as PHP2Shell. The disclosure was complicated by an exploit-chain video posted by a credited research team and by Chainguard publishing rebuilt PHP images before the coordinated release. Reports of real-world exploitation changed rapidly, with two vendors retracting early claims tying incidents to these CVEs, while the flaws were added to CISA’s Known Exploited Vulnerabilities catalog.

The article argues that differing PHP2Shell exposure totals often reflect different scanners, counting methods, banner availability, search behavior, and scan timing rather than a simple disagreement over facts. A shared-hosting IP can serve thousands of websites, version banners may be hidden or may reflect distributions that have backported fixes, and text searches can accidentally count overlapping version strings repeatedly. Censys says its first-party Internet Map scans all ports daily, identifies services on both common and uncommon ports, excludes honeypots from its PHP2Shell query, and retains historical records to measure when individual services move from affected to fixed.

  • A single shared-hosting IP address can represent thousands of websites, which Censys says explains how 4.18 million hosts can correspond to 67.6 million web properties.
  • PHP services that hide their version by disabling the X-Powered-By header can shift reported exposure totals by tens of millions depending on whether a measurement excludes or separately counts them.
  • Text-based searches for a version such as PHP/5.4.1 can unintentionally include PHP 5.4.10 through 5.4.19, and summing version-by-version results can count the same hosts repeatedly.
  • During widespread exploitation events, rapidly deployed honeypots can inflate simple exposure counts, which is why Censys excludes services labeled as honeypots from its PHP2Shell query.
  • Censys reports that newly exposed hosts can be reached within 2 to 11 hours and that services are revisited roughly every 8 to 14 hours, so reported patching changes depend on when scanners observe the updated service.
Key Points
  • 01PHP announced emergency fixes on October 20 for two pre-authentication remote code execution flaws, CVE-2026-109618 and CVE-2026-109619, collectively known as PHP2Shell.
  • 02Public PHP2Shell exposure counts can differ substantially because sources use different scanners, count different objects such as IP addresses or websites, and apply different matching and timing methods.
  • 03Censys states that its Internet Map uses first-party scanners to scan all 65,535 ports daily and fingerprint open services, including PHP services on nonstandard ports.
  • 04PHP version banners can overstate exposure because Linux distributions may backport security fixes while retaining older visible version numbers.
  • 05Censys says it retains four years of searchable service history, allowing it to track when individual services move from affected to fixed.

In plain words

An OpenCode user reported that people could get around limits on free AI coding tools by changing their internet address, then later described using that method heavily. Other users blamed the person when free access became more restricted and responded with serious online harassment, while some people using shared privacy services were also blocked despite not necessarily abusing the system. The incident shows how demand for free AI computing can lead to misuse, tighter limits that affect ordinary users, and hostile behavior toward people involved in exposing a problem.

Summary
An OpenCode user who publicized and later promoted an IP-switching workaround for free hosted AI-model limits was subjected to severe harassment after users blamed them for tighter restrictions. It remains unclear whether OpenCode fully fixed the bypass, while shared VPN users report being caught by network-level enforcement.

An OpenCode user reported that free hosted AI-model limits tied to IP addresses could allegedly be bypassed by changing IP addresses through a VPN while keeping a coding session active. The author initially suggested tying limits to accounts and detecting rapid IP changes, but later reopened the issue to promote the workaround and claimed to have used it extensively. The public GitHub thread was later deleted, though an archived version remains available.

The discussion drew severe harassment against the reporter, including suicide encouragement, requests for identifying information, and an unsupported claimed million-dollar reward. OpenCode contributors said that enforcing limits without authentication was difficult and that abuse harmed efforts to provide free access. Users also reported that shared VPN addresses were being blocked, sometimes affecting people who said they had not abused the service, while it remained unclear whether OpenCode’s October infrastructure and IP-handling changes fully stopped the IP-switching workaround.

  • The reporter’s position reversed over time: they initially proposed binding free-use limits to accounts and detecting rapid IP changes, then later reopened the issue to promote the same IP-switching method.
  • OpenCode’s October change addressing spoofed IP headers did not necessarily prevent users from switching to a genuinely different IP address through a VPN.
  • Network-based enforcement can affect users sharing VPN addresses, as OpenCode said it could not make individual exceptions for shared addresses that had been flagged.
  • The workaround had circulated beyond the GitHub issue before the late-October backlash, with a September Hacker News commenter recommending high-quality proxies for effectively unlimited agent compute.
  • OpenCode’s application release notes did not announce a fix for the bypass, and the article notes that hosted-service enforcement could have changed separately from a software release.
