Hackers are actively exploiting CVE-2026-20896, a critical authentication bypass vulnerability in the official Docker image for the Gitea self-hosted Git service. The flaw allows attackers to impersonate any user, including administrators. Security researcher Michael Clark at Sysdig said exploitation started less than two weeks before the vulnerability was publicly disclosed.

The issue affects official Gitea Docker images up to and including version 1.26.2 in the default configuration. Gitea’s official Docker image ships with REVERSE_PROXY_TRUSTED_PROXIES=*, and with reverse-proxy authentication enabled, Gitea trusts the X-WEBAUTH-USER header from any source IP. This means an unauthenticated internet client can become whichever user it claims to be if it can reach the Gitea container’s HTTP port directly.

Gitea released versions 1.26.3 and 1.26.4 to address CVE-2026-20896 and advised users to upgrade directly to the most recent release. Singapore’s cybersecurity agency also warned that the flaw is being actively exploited. If upgrading is not possible, the agency recommended restricting REVERSE_PROXY_TRUSTED_PROXIES to specific trusted IP addresses and reviewing access logs for suspicious activity.

  • The vulnerability is especially dangerous because the official Docker image’s default setting trusts identity headers from any source IP, so exposure of the container’s HTTP port directly can turn a configuration default into full user impersonation.
  • Sysdig observed the first in-the-wild exploitation 13 days after the advisory, showing that attackers moved quickly after public disclosure.
  • Gitea advised users to upgrade directly to the latest release rather than stopping at version 1.26.3 because version 1.26.4 fixes an additional issue and a regression introduced in 1.26.3.
  • Even without an immediate upgrade, organizations can reduce exposure by replacing the wildcard REVERSE_PROXY_TRUSTED_PROXIES setting with specific trusted IP addresses.
  • Because attackers can impersonate known or guessable accounts such as “admin” or “gitea_admin,” access log review is important to determine whether compromise has already occurred.

The flaws are reached while U-Boot is still reading an untrusted image, before it has checked the image signature.

The two most serious issues are BRLY-2026-037 and BRLY-2026-038, which stem from U-Boot using unchecked values returned by fdt_get_name.
