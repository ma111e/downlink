CVE-2026-111497: Node2Shell / HTTP2Shell Vulnerability May Allow RCE
zscaler.com · 28 Oct 2026 16:11 UTC openai-codex / gpt-5.6-terra
TAGS.netbuncontent-encoding-brcve-2026-111497envoy-proxygooglehttp2shellistiojava-brotli4jlibbrotlinode-jsnode2shellout-of-bounds-writepython-brotlizscaler
96
In plain words

A serious flaw called CVE-2026-111497 was found in Brotli, a tool many websites and apps use to shrink data before sending it over the internet. It can be triggered when affected software, including Node.js, Bun, Python, .NET, Envoy, and Istio, opens specially made compressed data from an attacker. This could crash an app, expose information held in its memory, or potentially let an attacker take control of it. Organizations need to update affected software and watch for suspicious compressed web requests or responses.

Summary
CVE-2026-111497 (Node2Shell/HTTP2Shell) is a critical out-of-bounds write in the Brotli decoder that can enable crashes, memory disclosure, or remote code execution when vulnerable software decompresses attacker-controlled Brotli data. Organizations should urgently patch affected Node.js, Bun, .NET, Python, Envoy, and other Brotli-dependent components, especially internet-facing services that accept Content-Encoding: br requests or fetch external content.

CVE-2026-111497, also known as Node2Shell and HTTP2Shell, is a critical out-of-bounds write vulnerability in Google’s Brotli decoder disclosed by the Node.js project on October 21, 2026. The flaw has a CVSS 4.0 score of 9.2 and can be triggered when vulnerable software decompresses attacker-controlled Brotli data. Successful exploitation may crash a process, disclose process memory, or enable remote code execution. Imperva reported demonstrating code execution in fresh containers using the official Node.js 24.22.0 Linux arm64 image, although multiple attempts were required in its test environment.

The issue affects a range of software using the vulnerable decoder, including Node.js, Bun, Python Brotli bindings, .NET, Envoy Proxy, Istio, Java brotli4j, libbrotli, curl/libcurl dependencies, and Linux distribution packages. It may be reached through malicious Brotli-compressed HTTP requests sent to a server or through crafted Brotli-compressed responses processed by clients, such as those used by fetch functions, webhooks, crawlers, URL previews, and API integrations. The technical flaw occurs when Brotli’s block-decoding fast path does not properly handle a failed block-type-and-length decode, allowing processing to continue in an invalid state and potentially causing an out-of-bounds write. Zscaler Deception observed 402 related events from 20 source IP addresses targeting 12 customers within 24 hours of disclosure, with 60% categorized as exploitation attempts.

Zscaler recommends patching affected runtimes, libraries, and infrastructure components, with priority given to services that decompress untrusted data. Organizations should rebuild and redeploy containers with patched images because host library updates do not replace bundled decoder copies in applications or existing container images. Where patching is delayed, the article recommends disabling Brotli decoding on vulnerable paths where supported and monitoring for malformed Brotli payloads, unexpected crashes, abnormal memory faults, child processes, and outbound connections.

  • Exposure is not limited to web servers accepting compressed requests: a vulnerable application can also be affected when it automatically decompresses a crafted Brotli response from an external website, webhook, URL preview, crawler, scraper, or API integration.
  • Updating a system-wide Brotli package may not fix every affected application because some runtimes, libraries, and container images bundle their own copy of the decoder.
  • Host-level library updates do not update already deployed container images, so organizations need to rebuild and redeploy workloads with patched base images and verify versions running in containers.
  • Zscaler Deception recorded both reconnaissance and exploitation attempts within 24 hours of disclosure, with exploitation attempts accounting for 60% of the 402 observed events.
Key Points
  • 01CVE-2026-111497, also called Node2Shell and HTTP2Shell, is a critical out-of-bounds write flaw in Google’s Brotli decoder that can cause crashes, memory disclosure, or remote code execution when processing attacker-controlled Brotli data.
  • 02The vulnerability can be reached through crafted Brotli-compressed HTTP requests sent to servers or through malicious Brotli-compressed responses automatically decoded by client applications.
  • 03Affected software may include Node.js, Bun, Python Brotli bindings, .NET, Envoy Proxy, Istio, Java brotli4j, libbrotli, and curl/libcurl through Brotli dependencies.
  • 04Zscaler Deception observed 402 events from 20 source IP addresses targeting 12 customers within 24 hours of public disclosure, with 40% classified as reconnaissance and 60% as exploitation attempts.
  • 05Organizations are advised to patch vulnerable components, rebuild and redeploy containers using patched images, disable Brotli decoding on vulnerable paths if patching is delayed, and monitor for crashes or unusual process and network behavior.

In plain words

Researchers found hundreds of seemingly useful add-ons for AI assistants that hid instructions telling people or the AI to install password-stealing software, including Atomic macOS Stealer. These add-ons appeared on popular marketplaces and often received strong automated safety ratings, so Mac and Windows users could be misled into trusting them. The stolen information can include saved browser passwords, login sessions, keychain data, and personal files, showing that AI add-ons need careful review rather than trust based on their name or rating.

Summary
Cyera identified 516 poisoned AI-agent skills that used fake setup requirements and encoded commands to deliver the Atomic macOS Stealer (AMOS), often while receiving high automated security grades. Organizations should inspect entire skill packages and block skills that direct users or agents to download external tools, decode Base64 commands, or execute shell installers.

Cyera Research identified 516 samples linked to a campaign distributing Atomic macOS Stealer (AMOS) through poisoned AI-agent skills. The skills appeared on popular marketplaces and used plausible documentation mixed with fake setup requirements to persuade users or agents to install credential-stealing malware. The campaign follows the ClawHavoc pattern of hiding malicious instructions inside skills intended for OpenClaw agents, although the article says the approach can affect any agent that uses skills.

The malicious instructions commonly directed macOS users to decode Base64 text and run it through Bash, while Windows users were sent to download archives and execute programs. Researchers found that 91.92.242.30 represented 83.7% of payload-host references, and two glot.io snippets represented 95.9% of paste-relay references. Automated marketplace checks failed to catch the threat: all 70 confirmed-malicious skills found on evaluated platforms received high security grades, and reviewing only a main SKILL.md file can miss harmful content in bundled files or oversized README files.

  • High marketplace safety grades were not reliable indicators of safety: all 70 confirmed-malicious skills on evaluated platforms received high grades, and Skills Directory’s grading methodology covers only SKILL.md rather than bundled scripts or other files.
  • The campaign’s infrastructure was highly reusable, with one payload host, 91.92.242.30, appearing in 83.7% of references and two glot.io snippets accounting for 95.9% of paste-relay references.
  • Reviewing only a skill’s main instruction file can miss malicious content, as JFrog reported an encoded dropper hidden in an approximately 22 MB README.md.
  • Specific warning signs identified by the researchers include download links to ZIP or EXE files, glot.io references, claims that a skill “will not work” unless openclaw-agent is installed, and Base64-decoding commands piped into Bash.
Key Points
  • 01Cyera Research identified 516 samples classified as part of an Atomic macOS Stealer (AMOS) campaign distributed through poisoned AI-agent skills.
  • 02The malicious skills used fake prerequisites and setup instructions to direct users or agents to download external files or decode and execute commands, with macOS instructions often using Base64-decoded Bash commands.
  • 03In the analyzed sample, 91.92.242.30 accounted for 83.7% of payload-host references, and two glot.io snippets accounted for 95.9% of paste-relay references.
  • 04All 70 confirmed-malicious skills identified on platforms with automated evaluation received high security grades, indicating that those checks missed malicious instructions embedded in skill files.
  • 05AMOS can collect browser passwords and session cookies, keychain information, and sensitive files before sending the data to attacker-controlled infrastructure.

    In plain words

    Researchers found a fake version of a tool meant to help an AI assistant work with PDF files that used Anthropic’s name and kept many legitimate files, but replaced the main directions and included a program that could let a remote person control the computer. Employees and organizations using AI assistants could be affected if they download copied tools from untrusted sources, especially on computers with company documents or saved login details.     Summary
    Cyera researchers found a trojanized copy of Anthropic’s PDF skill that preserved legitimate scripts and branding but replaced its instructions and added a Linux backdoor. Organizations should verify every file and instruction in AI-agent skill packages, not just names or known code, and restrict agent permissions and network access.

    Cyera Research analyzed a fake copy of Anthropic’s PDF skill that retained the familiar name, description, and 11 files matching the official skill. The package replaced the main SKILL.md instructions and added a 5 MB Linux executable containing a backdoor. Cyera identified the original ZIP archive and five related archives observed between May 23 and July 14, 2026.

    The altered SKILL.md was shortened from 315 lines to 19 and directed the agent to make a network call to a Chinese domain. If the bundled executable ran, a remote operator could issue commands with the permissions of the account that launched it, although researchers found no direct instructions to execute the binary. The article says organizations should verify complete skill packages against claimed sources, inspect instructions as well as code, investigate unexpected executables and network destinations, and keep agent permissions proportionate to the task.

    • Checking only a skill’s name, description, or expected scripts can miss malicious changes, because this package preserved 11 legitimate files while replacing the instruction file and adding an executable.
    • AI-skill reviews need to examine both executable content and written instructions, since the instructions determine what an agent will do with its available tools and permissions.
    • A file-comparison process across the entire package would have exposed both the shortened, rewritten SKILL.md file and the unexpected 5 MB Linux binary.
    • The researchers found no direct instruction to execute the bundled binary, but the altered instructions directed the agent to contact an external URL whose domain resolved to a private IP address at the time of the research.
    • When a suspicious skill is found internally, responders should determine whether it was present, whether its instructions were followed, and whether any bundled program ran.

Summary

It retained the original name, description, and 11 identical files, but replaced the legitimate SKILL.md instructions and added two files not present in the original package. The modified instructions directed an agent to contact an external hostname, while the added system_linux executable contained an obfuscated Linux backdoor.

The 5 MB, statically linked Go executable decrypts a hard-coded destination, opens a plain TCP connection to 81.70.101[.]115:2345, and attaches /bin/bash to that connection. Researchers observed five similar tar archives from May through July 2026, but could not determine how they were distributed, whether anyone installed them, or whether the binary was launched. The case demonstrates that a familiar skill name and largely legitimate file set can conceal harmful instructions or executables, so organizations should verify complete skill packages and investigate unexpected commands, binaries, and network destinations before allowing agents to use them.

  • A package can appear trustworthy through its familiar name, description, and mostly unchanged legitimate files while concentrating harmful behavior in a replaced instruction file and an added executable.
  • Reviewing only bundled scripts would have missed the altered SKILL.md and the added reverse-shell program, demonstrating the need to inspect an entire skill package rather than selected files.
  • The article distinguishes confirmed malicious capability from an observed compromise: researchers identified the reverse shell and network destinations but did not observe installation, execution, or a successful follow-on response.
  • The case maps to malicious-skill and software-supply-chain risks, but the article cautions that these frameworks do not establish how the package was distributed or whether an established distribution channel was compromised.

Summary
Ransomware crews are increasingly relying on social engineering and stolen-data extortion instead of encrypting systems, especially targeting law firms and other data-sensitive mid-market organizations. Because paying for a promise to delete data offers little protection from leaks or repeat extortion, organizations should prioritize identity defenses, incident coordination, and recoverable operations.

The article warns that law-firm senior partners are being personally targeted through tailored emails and phone calls built from information on public firm profile pages. It says the Q3 2026 leak of Silent Ransom Group internal chats revealed victims that had paid to keep incidents private and demonstrated the unreliability of paying for silence. The article describes a shift away from broadly encrypting systems and toward stealing data from cloud and software-service environments, then demanding payment to prevent disclosure.

Coveware by Veeam reported that the Q3 2026 median ransom payment rose 167% from Q2 to \(400,000, while the average payment fell 45% to \)1,025,278. Phishing and social engineering accounted for about 29% of initial access, with compromised remote access at 22–23% and compromised credentials at 14–15%; attackers then often use ordinary administrative routes and cloud services to move through environments and remove data. Nearly 80% of data-exfiltration-only incidents were resolved without payment, because payment does not remove notification obligations or provide a verifiable guarantee that stolen data will be deleted, resold, or used in later extortion.

  • The combination of a higher median payment and a lower average payment suggests that mid-market victims are facing higher baseline demands while larger enterprises are declining multimillion-dollar demands when their operations remain available.
  • The article finds that tracking individual ransomware-group names is becoming less useful because no group held more than 6% of cases in Q3 2026 and several groups rapidly entered the rankings.
  • Because attacker activity can resemble ordinary employee or administrator logins, the article recommends validating the user, device, and purpose of access continuously rather than relying only on initial authentication.
  • The article cautions that isolated efforts to cut off attackers’ control channels can cause them to switch tools or accelerate their actions, making coordinated incident oversight important.
  • For data-theft-only extortion, the central problem is often legal, regulatory, and reputational management rather than restoring technology, since stolen data cannot be recovered and deletion promises cannot be verified.
