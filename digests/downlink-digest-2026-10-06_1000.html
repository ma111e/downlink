Summary
Malicious spreadsheets can exploit Java-enabled database refresh features in LibreOffice and Apache OpenOffice to execute attacker-controlled code on opening without macro warnings. LibreOffice fixed the issue in versions 26.2.5 and 26.8.0, while OpenOffice users should disable Java or avoid untrusted files until 4.1.17 is released.

Security researchers demonstrated that malicious spreadsheets can cause LibreOffice and Apache OpenOffice to run attacker-controlled code as soon as they are opened, without displaying a macro warning. The proof of concept requires Java support to be enabled and has been tested on Windows and Linux. There are no reports that the technique has been used in real attacks. The researchers used Calculator as a harmless demonstration payload, though the same route can run other Java code.

The technique chains normal spreadsheet features: a Calc database range automatically refreshes data from an external database file, which can specify a Java database driver and a location for its code. When the spreadsheet opens, the software can download the database file and Java code, then start the driver inside the office program. LibreOffice fixed CVE-2026-63277 in versions 26.2.5 and 26.8.0, while Apache OpenOffice remains affected through version 4.1.16 under CVE-2026-59265. Until OpenOffice 4.1.17 is released, users can disable Java or avoid opening untrusted spreadsheets.

  • The code execution path abuses several legitimate features in sequence—automatic data refresh, downloading an external database file, and loading a Java driver—rather than relying on macros.
  • The malicious database file and Java code can be hosted on an attacker-controlled server, even though the proof of concept kept them on the same machine for convenience.
  • The demonstrated technique worked on both Windows and Linux, indicating it is not limited to a single operating system.
  • Until Apache OpenOffice releases version 4.1.17, disabling Java is a direct mitigation for affected users.
