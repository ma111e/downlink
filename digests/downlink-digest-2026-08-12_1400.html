In plain words

This matters because fully updated Windows 11 computers and remote desktop environments can be affected, and an attacker who succeeds can run commands with the highest level of access on the machine.

Summary
Researchers showed that Windows Plug and Play can be abused with fake USB devices, or even RDP USB redirection, to make Windows install vulnerable vendor software and gain SYSTEM privileges. Disabling co-installers helps against some chains, but sensitive environments should also restrict device installation and disable unnecessary PnP redirection.

Security researchers Alejandro Hernando and Borja Martínez disclosed “Plug and Pwn” attacks that abuse Windows Plug and Play to trigger Windows into installing vulnerable or insecure vendor software and gain NT AUTHORITY\SYSTEM privileges. The research was presented at DEF CON 34 and focuses on the Windows device installation path itself rather than a single vendor installer. Some demonstrated attacks require no user interaction or logged-in user, while another can be performed remotely over RDP without physical USB hardware connected to the targeted computer.

The researchers used FaceDancer with Cynthion and GreatFET hardware connected to a small Linux computer to emulate USB devices. By making the hardware appear to Windows as specific USB devices, they caused the operating system to recognize the emulated hardware and install associated vendor driver packages. In one zero-click physical demonstration against a fully updated Windows 11 computer with nobody logged in, they impersonated Sierra Wireless and Sony FeliCa devices to manipulate DNS settings, redirect an unencrypted download, place a malicious file with SYSTEM privileges, and open a SYSTEM reverse shell in about five minutes.

The researchers also demonstrated “NoPlug & Pwn,” which abuses RDP USB redirection by sending specific USB descriptors through a Python RDP client so the remote Windows host treats them as a legitimate USB device. In that demonstration, they impersonated an Intel RealSense camera whose Windows Update package contains a co-installer that can be abused through DLL hijacking to obtain SYSTEM privileges. Will Dormann suggested enabling the DisableCoInstallers registry value, and Hernando said it helps disrupt some demonstrated attacks, but he also recommended pairing it with device installation restrictions or hardware-ID allow-lists and disabling Plug and Play device redirection on RDP and VDI hosts that do not need it.

  • Disabling co-installers is only a partial mitigation because Windows can still expose organizations to risk through Plug and Play enumeration, Windows Update driver resolution, driver staging, INF processing, and INF-installed services.
  • Remote desktop environments are a notable exposure point because the researchers’ RDP-based attack works when USB redirection is enabled, which Hernando said is common in virtual desktop environments.
  • The researchers found that making a fake USB device appear as a composite device can cause Windows to load usbccgp.sys and enumerate each interface separately, helping the fake device match a vendor package instead of a built-in Windows driver.
  • For sensitive systems, Hernando recommended combining DisableCoInstallers with device installation restrictions or hardware-ID allow-lists and turning off Plug and Play device redirection on RDP and VDI hosts that do not need it.
