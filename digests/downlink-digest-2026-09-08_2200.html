In plain words

Adobe reported a severe flaw called “StyleSmuggler” in Adobe Commerce, Adobe Commerce B2B, and Magento Open Source that can let someone on the internet take control of an online store without needing a login. It has already been used against real storefronts since at least September 4, 2026, with attackers placing hidden access tools on compromised sites. This matters because affected online shops may be exposed to theft, tampering, or disruption unless they apply Adobe’s emergency fix and check for signs of compromise.

Summary
Adobe disclosed a critical unauthenticated RCE flaw, CVE-2026-75650 “StyleSmuggler,” affecting Adobe Commerce, Adobe Commerce B2B, and Magento Open Source, with confirmed in-the-wild exploitation. Organizations should immediately apply Adobe’s VULN-39341 hotfix and treat any internet-exposed unpatched instance since September 4, 2026 as potentially compromised.

Adobe disclosed CVE-2026-75650, dubbed “StyleSmuggler,” on September 7, 2026. The vulnerability received a maximal initial CVSS score of 10.0 and affects Adobe Commerce, Adobe Commerce B2B, and Magento Open Source. CISA added the vulnerability to its Known Exploited Vulnerabilities catalog on September 8, 2026.

The flaw allows an unauthenticated network-based attacker to execute arbitrary code by injecting PHP through Magento’s email template engine. The article identifies the root cause as improper neutralization of special elements used in a template engine, tracked as CWE-1336. It says attackers can trigger execution through a “Payment Transaction Failed Reminder” email.

Exploitation has been confirmed in the wild since at least September 4, 2026, with threat actors deploying a Rust-based Linux backdoor and PHP web shells on compromised storefronts. The article recommends identifying all Adobe Commerce and Magento deployments, applying Adobe’s VULN-39341 Composer hotfix from bulletin APSB26-146, and following Adobe’s verification workflow. It also advises treating any unpatched internet-exposed instance as potentially compromised, checking Sansec’s indicators of compromise, deploying WAF rules, and monitoring for unusual PHP process spawning and unexpected outbound connections.

  • Any internet-exposed affected instance that remained unpatched on or after September 4, 2026 requires investigation, because exploitation was observed before Adobe’s September 7 disclosure.
  • Remediation depends on applying the VULN-39341 Composer hotfix from Adobe bulletin APSB26-146, which the article emphasizes is an emergency hotfix rather than a full minor release.
  • Defensive monitoring should focus on Magento email generation behavior because the described execution path involves injected PHP being triggered through a “Payment Transaction Failed Reminder” email.
  • Compromise checks should include Sansec’s host, network, and media-directory indicators of compromise in addition to monitoring for unusual PHP process spawning and unexpected outbound connections.

  • 02The vulnerability affects Adobe Commerce, Adobe Commerce B2B, and Magento Open Source and allows unauthenticated remote code execution through PHP injection in Magento’s email template engine.
  • 03Exploitation has been confirmed in the wild since at least September 4, 2026, with attackers deploying a Rust-based Linux backdoor and PHP web shells on compromised storefronts.

In plain words

Microsoft is adding a new Windows 11 feature that lets apps tell whether someone is a child, teenager, or adult without seeing their exact birthday. This affects Windows users with Microsoft accounts and app developers, because apps can use the information to adjust features and protections for younger people. Microsoft says users may be able to verify their age once through their Microsoft account and have apps check that status instead of asking again and again. This matters because age-appropriate protections are becoming more important, especially in apps that include AI experiences.

Summary
Microsoft is adding Windows 11 APIs that let apps determine whether a user is a child, teen, or adult without exposing their exact birthdate. The system ties into Microsoft Age Verification so users can verify once and let apps apply age-appropriate safeguards, including for AI experiences.

Microsoft is adding new age-awareness APIs to Windows 11 that allow apps to determine whether a user is a child, teenager, or adult without exposing the user’s exact date of birth. The Windows Age API uses information associated with a Microsoft account and can return age ranges such as under 10, 10-12, 13-15, 16-17, and 18+. Microsoft says apps receive only the age-related signal needed for the experience, not sensitive personal data such as a full date of birth.

Developers will be able to use GetUserAgeRangeAsync to retrieve age groups and GetAgeVerificationStatusAsync to determine whether a user’s age has been verified rather than self-reported. Microsoft says the APIs could let apps automatically adjust features and safeguards for younger users without requiring parents to configure every app individually, including in AI experiences. The APIs will work alongside Microsoft Age Verification, which stores a verified age status with a Microsoft account under a “verify once → use everywhere” model.

Age verification is already available through Microsoft storefronts in Singapore, Brazil, and Australia, with more regions planned as regulatory requirements expand. Microsoft is also increasing the visibility of parental controls during Windows setup in regions including France. The Windows Age APIs are broadly available to Windows Insiders now and will roll out to all Windows users soon.

  • Microsoft is separating age range from age verification, so an app can distinguish between a user’s stated age category and whether that age has actually been verified.
  • The “verify once → use everywhere” model shifts repeated age checks away from individual apps and toward a Microsoft account-level status that apps can query through Windows.
  • The rollout is being tied to regional regulatory pressure, with age verification already available in Singapore, Brazil, and Australia and parental control visibility increasing during Windows setup in regions including France.
  • Microsoft explicitly connects the new APIs to AI experiences, indicating that age-based safeguards are expected to apply beyond traditional app settings and content controls.
Key Points

  • 02The Windows Age API can return age ranges including under 10, 10-12, 13-15, 16-17, and 18+ using information associated with a Microsoft account.
  • 03Developers can use GetUserAgeRangeAsync to retrieve age groups and GetAgeVerificationStatusAsync to check whether a user's age has been verified rather than self-reported.
  • 04Microsoft says the APIs could let apps automatically adjust features and safeguards for younger users, including in AI experiences, without requiring parents to configure every app individually.
