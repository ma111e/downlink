New CrashStealer malware poses as Apple crash reporting tool

In plain words

A new Mac threat called CrashStealer pretends to be Apple’s crash reporting tool and is delivered through an installer that Apple computers may accept without warning. It tricks people into typing their Mac password, then can steal saved passwords, browser logins, cryptocurrency wallet data, and personal files from folders like Documents and Downloads. This matters because affected Mac users could lose access to important accounts, private data, and cryptocurrency while the program hides behind something that looks like a normal Apple tool.

Summary
A new macOS infostealer called CrashStealer is impersonating Apple’s CrashReporter tool and using a signed, notarized installer to bypass Gatekeeper and trick users into entering their password. It steals Keychain data, browser credentials, password manager data, crypto wallets, and files before encrypting and exfiltrating them to its C2 server.

A new macOS information-stealing malware called CrashStealer is pretending to be Apple’s crash-reporting tool to steal credentials, Keychain data, and cryptocurrency wallets. Researchers began tracking it in May while it appeared to still be in development, and observed it being used in attacks in early July. The malware’s binary uses the name “CrashReporter.app,” creates a LaunchAgent named “com.apple.crashreporter.helper,” and uses the legitimate tool’s icon and metadata to look like an Apple component.

Jamf researchers say CrashStealer is delivered through a signed and Apple-notarized installer called “Werkbit Setup,” which allows it to bypass macOS Gatekeeper without warnings. When launched, it displays a fake macOS password prompt and validates the entered password locally using the dscl command-line tool. CrashStealer targets browser credentials and cookies, more than 80 cryptocurrency wallet extensions, 14 password managers, and files from user directories such as Documents and Downloads.

Before exfiltrating stolen data, CrashStealer encrypts it with AES-256-GCM, packages it into hidden ZIP archives, and uploads it to a command-and-control server using libcurl. Jamf says CrashStealer is distinct from other infostealer families because of its client-side encryption mechanism and native C++ implementation. The campaign uses a fake software site registered in late June, with downloads gated behind a meeting PIN, and Jamf’s report provides indicators of compromise including malicious tool names, hashes, delivery infrastructure, and filesystem artifacts.

  • CrashStealer’s signed and Apple-notarized installer shows that macOS Gatekeeper may not warn users even when the delivered application is malicious.
  • The fake software site requires a meeting PIN before downloading the payload, which Jamf says indicates the campaign is limited to visitors who provide the right code.
  • CrashStealer re-signs itself for persistence, rewriting code-signature data so the binary’s hash changes even though the code remains untouched.
  • Jamf highlighted CrashStealer as distinct from other macOS infostealers because it uses client-side AES-256-GCM encryption and is implemented natively in C++.

  • 03When launched, CrashStealer shows a fake macOS password prompt and validates the entered password locally using the dscl command-line tool.
  • 04CrashStealer targets browser credentials and cookies, more than 80 cryptocurrency wallet extensions, 14 password managers, and files from user directories such as Documents and Downloads.

Hackers backdoor Jscrambler npm package with infostealer malware

In plain words

Jscrambler said someone broke into the account it uses to publish its JavaScript developer package and uploaded versions that secretly tried to steal sensitive information during installation. About 1,500 downloads happened before the bad versions were removed, so developers or companies that used those versions may have had source code, passwords, cloud access keys, chat app data, browser data, or cryptocurrency wallet information exposed. This matters because one trusted software package can be used to reach many projects and businesses that depend on it.

Summary
Jscrambler disclosed that attackers used compromised npm publishing credentials to release malicious versions of its package containing infostealer malware, resulting in about 1,500 downloads before removal. Developers who installed the affected versions should treat their environments as compromised, rotate secrets, and update to the latest safe release.

Jscrambler disclosed that a threat actor published malicious versions of its jscrambler npm package, which is used with the company’s Code Integrity product. The affected releases were 8.14, 8.16, 8.17, and 8.20, and they included information-stealing malware that executed during the preinstall hook. Jscrambler said the incident was limited to that package and did not affect other products, including Webpage Integrity.

The malicious package remained available for about two hours before Jscrambler deprecated it and released safe version 8.22. npm statistics showed that the malicious package was downloaded 1,479 times during that window. The affected package was also a dependency for four other Jscrambler packages, which the company deprecated and replaced with new versions.

Socket detected and analyzed the compromise, reporting that the malware targeted source code, developer credentials, cloud credentials, AI coding tool configurations, cryptocurrency wallets, browser data, and messaging apps. Socket also reported that the malware used strong per-string obfuscation with the ChaCha20-Poly1305 encryption algorithm, making the code difficult to reverse-engineer. Jscrambler said the compromise was possible because of compromised npm publishing credentials, which it revoked, and advised affected developers to treat their environments as compromised, rotate all secrets, and restore from safe backups.

  • The malicious package was live for only two hours but still reached 1,479 downloads, showing how quickly a compromised npm package can spread through developer environments.
  • Because the compromised package was also a dependency for four other Jscrambler packages, users could have been exposed even if they installed one of those related packages rather than the main jscrambler package directly.
  • The malware targeted a broad mix of developer, cloud, browser, messaging, AI coding tool, and cryptocurrency data, so Jscrambler’s guidance to rotate all secrets is more practical than trying to identify only one affected credential type.
  • Socket reported that the malware used ChaCha20-Poly1305 per-string obfuscation, making analysis harder even though the package was removed quickly.
Key Points
  • 01Jscrambler disclosed that a threat actor published malicious versions of its jscrambler npm package used with the company’s Code Integrity product.
  • 02The malicious releases, versions 8.14, 8.16, 8.17, and 8.20, included information-stealing malware that executed during the preinstall hook.
  • 03The malicious package remained available for about two hours, was downloaded 1,479 times, and was replaced by safe version 8.22.
  • 04Socket reported that the malware targeted source code, developer secrets, cloud credentials, AI coding tool configurations, cryptocurrency wallets, browser data, and messaging app data.
  • 05Jscrambler said the incident was caused by compromised npm publishing credentials, which it revoked, and advised affected developers to treat environments as compromised and rotate all secrets.

Japan’s largest taxi and chauffeur operator by group revenue, Nihon Kotsu, said its internal systems were subjected to unauthorized external access involving a malware infection. The incident occurred early Saturday morning over the weekend and forced the company to shut down part of its infrastructure. Nihon Kotsu has annual revenue of roughly $1 billion, employs 18,228 people, and operates 8,558 taxis and more than two thousand chauffeur vehicles.

The company has engaged external cybersecurity experts to help investigate and recover systems, and it is looking into whether data was leaked, though no leak had been confirmed.
