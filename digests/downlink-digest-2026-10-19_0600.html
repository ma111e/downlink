Unpatched Broadcom Wi-Fi Flaw Lets Attackers in Range Run Code as Root on Routers
thehackernews.com · 19 Oct 2026 06:29 UTC openai-codex / gpt-5.6-terra
TAGSaskey-tcg3000bcm3380bcm3383bcm33834belgiumbroadcomcert-coordination-centerhostapdorange-belgiumproximusreverse-shellsagemcom-bbox3v-plustelenetvoowps-message-fragmentation

In plain words

A researcher found a flaw in Wi-Fi connection software used in many Broadcom-based home routers that could let someone nearby take complete control of a router without knowing its Wi-Fi password. The issue was shown on internet-provider routers in Belgium, including devices from Proximus, Orange Belgium, and VOO, and may affect millions of routers worldwide. Some older devices may never receive a fix, meaning owners may need to replace them. If abused, the flaw could let a nearby intruder steal the Wi-Fi password, join the network, or control the router.

Summary
An unpatched flaw in Broadcom’s WPS implementation lets attackers within Wi‑Fi range send crafted setup frames and execute code as root on affected routers without knowing the network password. Millions of older and newer Broadcom-based devices may be exposed, with replacement often the only practical mitigation for unsupported models.

Researcher Quentin Kaiser disclosed an unpatched flaw in Broadcom’s Wi-Fi Protected Setup software that can let an attacker within radio range run code as root on affected routers without knowing the Wi-Fi password or completing a pairing step. The flaw stems from improper handling of fragmented Wi-Fi setup messages, allowing crafted messages to corrupt router memory. Kaiser demonstrated both reading a router’s Wi-Fi password and running a remote command line over Wi-Fi frames.

The issue was demonstrated on gateways used by Orange Belgium and Proximus and was found on devices from three of Belgium’s four major providers, including VOO. Kaiser estimates that millions of Broadcom-based devices may be affected, including older BCM3380, BCM3383, and BCM33834 chips that he says have no usable fix. No CVE has been assigned and no patch has been deployed for the affected routers; Kaiser provides firmware-scanning rules and a live-network checking script for triage, while replacement is the practical option for devices that cannot be fixed.

  • The demonstrated attacks did not require the attacker to know the Wi-Fi password or complete a pairing process, and one proof of concept carried a remote command shell entirely over Wi-Fi frames without an outside server.
  • Broadcom reportedly knew about the flaw since 2018 and advised customers to switch to hostapd after an incomplete fix, yet no CVE was assigned, which Kaiser says left many device makers without clear tracking for remediation.
  • The article describes the older eCos-based BCM3380, BCM3383, and BCM33834 devices as a “forever day” because no usable fix exists for them, making replacement the practical option.
  • Kaiser’s YARA rules and live-network script are only triage tools: even a patched device can trigger a match, so a positive result does not confirm that a device remains vulnerable.
Key Points
  • 01Researcher Quentin Kaiser disclosed that a flaw in Broadcom’s Wi-Fi Protected Setup software can allow an attacker within radio range to run code as root on affected routers without a Wi-Fi password or pairing step.
  • 02Kaiser demonstrated the flaw against Belgian provider gateways, reading the Wi-Fi password from an Orange Belgium Askey TCG3000 and opening a Wi-Fi-carried reverse shell on a Proximus Sagemcom BBOX3V+.
  • 03The vulnerable code affects older eCos-based Broadcom BCM3380, BCM3383, and BCM33834 chips as well as newer Linux-based BCM3390, BCM65xx, and BCM68xx families, potentially affecting millions of devices.
  • 04Kaiser says older eCos-based devices have no usable fix and may remain permanently vulnerable, while newer models could be fixed if manufacturers move to hostapd Wi-Fi software.
  • 05No CVE has been assigned and no patch has been deployed for the affected routers; Kaiser provides YARA rules and a live-access-point checking script as triage tools.

It has no assigned CVE or deployed patch, and some older affected devices may require replacement, though no real-world exploitation has been reported.

In plain words

Microsoft says its October 2026 Windows Server security update can prevent some organizations using their own Exchange email servers from signing in to webmail or sending and receiving email properly. The problem affects some systems running Windows Server 2019 or newer, with the impact varying based on how busy the email server is. Microsoft has provided a temporary settings change and is working on a permanent fix, while advising customers not to remove the separate Exchange security updates.

Summary
Microsoft says October 2026 Windows Server security updates can disrupt Outlook on the web sign-ins and mail delivery on some on-premises Exchange servers due to a new Endpoint Mapper memory limit. A temporary registry change raising the Endpoint Lookup call cap can mitigate the issue while Microsoft develops a fix.

Microsoft confirmed that October 2026 Windows Server security updates can cause sign-in and mail-delivery problems on some on-premises Exchange Server systems running Windows Server 2019 or later. Users may be unable to sign in to Outlook on the web, Outlook messages may remain in the Outbox, and Exchange may have trouble accessing mailboxes during mailbox replication. Some affected systems also show a MapiExceptionMdbOffline error and Event ID 1006 in the application log.

Microsoft said the Windows update introduced a default cap of 512 simultaneous Endpoint Lookup calls, which may be too low for heavily loaded Exchange Server environments. The severity and timing of the problem vary by server load, and some Exchange servers may never be affected. Microsoft provided a temporary workaround that raises the Endpoint Mapper limit through the EpmapSavedContextCap registry value, requires a reboot, and may need further adjustment if the issue returns. Microsoft also said the problem is unrelated to the October 2026 Exchange Server security updates and advised customers not to uninstall those updates.

  • The disruption is tied to a Windows Server change rather than the October 2026 Exchange Server security updates, so any Exchange version running on affected Windows versions can be impacted.
  • The issue may appear differently across organizations: heavily loaded Exchange servers are more likely to reach the new limit quickly, while some servers may never experience a problem.
  • Microsoft's workaround increases the allowed simultaneous Endpoint Lookup calls from the default limit of 512 to 65,536, but administrators are instructed to monitor the environment afterward because the higher limit also permits Endpoint Mapper to use more memory.
Key Points
  • 01Microsoft confirmed that October 2026 Windows Server security updates can cause Outlook on the web sign-in and mail delivery problems on some on-premises Exchange Server systems running Windows Server 2019 or later.
  • 02Affected users may be unable to access email, messages sent from Outlook may remain in the Outbox, and Exchange may have trouble accessing mailboxes during mailbox replication.
  • 03Microsoft said the update introduced a default limit of 512 simultaneous Endpoint Lookup calls, which may be insufficient for heavily loaded Exchange Server workloads.
  • 04Microsoft provided a temporary workaround that raises the Endpoint Mapper limit through the EpmapSavedContextCap registry value and requires rebooting the Exchange Server.
  • 05Microsoft said the issue is unrelated to October 2026 Exchange Server security updates and advised customers not to uninstall those updates.

OpenCode Console Breach May Have Exposed OpenAI, Anthropic, and Google API Keys

In plain words

OpenCode says someone got into an older part of its optional online Console service and may have seen AI service keys saved there by some users. About 1.4% of Console users with linked OpenAI, Anthropic, or Google accounts were affected and were told to cancel and replace their keys. These keys can let anyone who has them use paid AI services on the owner’s account, which may result in unexpected charges.

Summary
OpenCode says an intruder accessed a legacy Console system, potentially exposing OpenAI, Anthropic, and Google API keys stored by 1.4% of Console users. Affected users should immediately revoke and replace provider keys and review their accounts for unauthorized usage.

OpenCode said an intruder accessed a legacy system connected to its optional Console service on the night of October 16, potentially exposing AI-provider API keys stored by users. The affected population was 1.4% of Console users, all with an external provider linked, and OpenCode emailed those users on October 17 instructing them to revoke and replace their keys. OpenCode said users who did not receive the email were not affected. The company described the incident as ongoing and said it was working with Anthropic, OpenAI, and Google.

Console stores a workspace’s OpenAI, Anthropic, or Google key so team members can use provider models without seeing the key, while keys configured in OpenCode’s command-line and desktop apps are stored locally in a SQLite database and were not involved. A copied provider key can be used to make billable requests directly against the owner’s account, and removing it from Console or applying a Console budget does not stop that use. Users were advised to revoke keys at the provider, update applications using the old keys, and review provider billing and usage from at least October 16. Some users reported unauthorized charges, although OpenCode said only that keys may have been exposed and did not confirm that any were copied or used.

  • Deleting a potentially exposed key from OpenCode Console does not stop someone else from using it; only revoking it through OpenAI, Anthropic, or Google prevents further use.
  • A spending cap set in OpenCode Console cannot limit fraudulent charges made directly with a copied provider key, because the Console only tracks requests sent through its own gateway.
  • Keys saved in OpenCode’s local command-line and desktop applications were not part of this incident because those keys are stored in a SQLite database on the user’s machine.
  • Using separate provider keys for different tools can reduce the impact of a copied key and make suspicious use easier to identify.
Key Points
  • 01OpenCode said an intruder accessed a legacy system connected to its optional Console service on the night of October 16, potentially exposing third-party AI provider keys saved there.
  • 02OpenCode said 1.4% of Console users were affected, all of whom had linked an outside provider, and it emailed them on October 17 to revoke and replace their keys.
  • 03The incident involved keys stored in OpenCode Console, while keys added locally to OpenCode’s command-line and desktop applications remain in a SQLite database on the user’s machine.
  • 04OpenCode advised affected users to review provider usage and billing for unauthorized requests, and some users reported charges they said they did not make.
  • 05OpenCode described the incident as ongoing and related to a large-scale model-distillation campaign, but did not disclose how the legacy system was accessed or whether any keys were copied or used.

This is a specific, ongoing incident in which a legacy OpenCode Console system may have exposed OpenAI, Anthropic, and Google provider API keys, with some users reporting substantial unauthorized charges. It is particularly actionable for affected Console users, who need to revoke and replace stored keys and check provider billing.

In plain words

The article describes a North Korean scheme in which people use the identities and appearances of citizens in the United States, Europe, or Latin America to get remote technology jobs. Most of the salary is then sent back to the North Korean worker through methods such as cryptocurrency or wire transfers. Financial institutions and the companies hiring these workers can be affected because ordinary identity checks may appear valid, while the arrangement can create sanctions and money-laundering risks.

Summary
North Korean operatives use legitimate or rented identities and domestic residential connections to secure remote IT jobs, allowing them to evade standard KYC and AML checks while routing salary payments back to North Korea. Financial institutions should analyze connection origins, payment-routing changes, and hiring anomalies before onboarding.

Silent Push reports on a North Korean recruiting scheme found on Discord, where recruiters offer U.S., European Union, and Latin American citizens 35% of a remote-job salary to serve as the visible applicant and legal identity. The remaining 65% is sent to the North Korean worker through cryptocurrency, wire transfers, or third-party payment processors. The scheme uses stolen, rented, or borrowed identities to obtain remote technical jobs while routing wages back to the operator.

The arrangement can pass document-based identity and anti-money-laundering checks because the identity is legitimate and the connection appears to originate from a clean domestic residential IP address. The actual operator may sit behind that final connection through a residential proxy or a remote-control relay in a laptop farm. The report advises financial institutions to examine where an applicant’s connection begins, watch for early salary-routing requests to electronic money institutions or third-party accounts, train recruiters on suspicious interview and employment patterns, and establish information-sharing handoffs between HR and cybersecurity teams.

  • A legitimate identity and a domestic residential IP address can allow this scheme to pass standard document-based identity and anti-money-laundering checks, even when the actual worker is elsewhere.
  • Checking the origin of an applicant's connection before its final residential internet address can expose operators using residential proxies or remote-control relays.
  • An early request to send salary to an electronic money institution or third-party account is identified as a potential sanctions and money-laundering indicator.
  • The report emphasizes that HR, fraud, and cybersecurity teams need defined information handoffs and named responsibility for detecting suspicious applicants before onboarding.
Key Points
  • 01Silent Push identified a North Korean recruiting scheme on Discord in which a recruiter offered U.S., European Union, and Latin American citizens 35% of a salary to provide their identity and appear on job applications.
  • 02The remaining 65% of the salary is sent to the North Korean worker through cryptocurrency, wire transfers, or third-party payment processors.
