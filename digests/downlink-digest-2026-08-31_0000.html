CVE-2026-75604 is a critical path traversal flaw in Next.js that can allow an unauthenticated attacker to write files outside the framework’s on-disk cache directory and reach remote code execution on the host. The vulnerability is tracked as CWE-22 and published by Vercel as GHSA-p293-qw3h-jr36. It has a CVSS v3.1 base score of 9.0, with no authentication or user interaction required.

The issue is specific to self-hosted Windows deployments because Windows treats backslashes as directory separators. Percent-encoded backslash sequences can reach the Next.js routing layer without normalization, allowing an attacker to steer a filesystem cache write when certain routing and incremental static regeneration conditions are present. Linux, macOS, and applications running on Vercel’s managed platform are not affected.

Affected versions include Next.js 13.4 up to 15.5.24 and 16.0 up to 16.3.3, when the application uses the Pages Router or the App Router without Cache Components and runs on a Windows filesystem. Vercel released fixed versions in Next.js 15.5.24 and 16.3.3, and the article states there is no known workaround for affected Windows-hosted applications. Recommended actions include inventorying Windows-hosted Next.js deployments, confirming pinned versions, monitoring cache paths, blocking percent-encoded backslash sequences, and auditing externally reachable incremental static regeneration routes.

  • The sector distribution is relatively flat despite Industrials, Information Technology, and Consumer Discretionary leading observed exposure, suggesting framework choice by agencies or business units can spread risk across many industries.
  • Upgrading for CVE-2026-75604 also changes AVIF image handling because the same security release disables AVIF optimization in response to a separate critical libheif issue.
  • WAF blocking of percent-encoded backslash sequences is presented only as a stopgap because it filters requests without removing the underlying flaw.
