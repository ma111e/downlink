In plain words

Microsoft released its August 2026 security update, fixing 421 problems across products such as Windows, SharePoint Server, Exchange Server, Office, Azure services, Teams, and others. Microsoft says one of these problems has already been used in real attacks, and many of the most serious issues could let someone run code, gain higher access, steal information, or impersonate others. Cisco Talos also released new Snort detection rules so organizations using those tools can look for attempts to abuse some of these issues.

Summary
Microsoft’s August 2026 Patch Tuesday fixes 421 vulnerabilities, including 62 critical flaws and one Windows Ancillary Function Driver for WinSock privilege escalation bug already exploited in the wild. Cisco Talos released new Snort rules to help detect exploitation attempts for selected vulnerabilities.

Microsoft released its August 2026 monthly security update, addressing 421 vulnerabilities across a range of products. Microsoft marked 62 of the vulnerabilities as critical, and 40 of those critical issues are remote code execution vulnerabilities. Microsoft also noted that one vulnerability disclosed this month, CVE-2026-68820 in the Windows Ancillary Function Driver for WinSock, has been exploited in the wild.

The article highlights several critical vulnerabilities that Microsoft considers more likely to be exploited, including flaws in Windows Deployment Services TFTP Server, Microsoft SharePoint Server, and Windows DHCP Server. It also lists many critical issues considered less likely or unlikely to be exploited, affecting products such as Microsoft Excel, Microsoft Office, Exchange Server, Windows DNS Server, Windows Device Health Attestation, Azure services, Microsoft Teams, and Microsoft QUIC. Impacts described in the article include remote code execution, elevation of privilege, information disclosure, and spoofing.

Cisco Talos also identified several important vulnerabilities that Microsoft rates as more likely to be exploited, including issues in Visual Studio Code, SharePoint Server, Microsoft High Performance Computing Pack, Windows TCP/IP, Windows Kernel, Windows HTTP.sys, Kerberos, and other Windows components. In response to the disclosures, Talos released a new Snort ruleset to detect attempts to exploit some of the vulnerabilities. The article provides Snort 2 and Snort 3 rule coverage identifiers and notes that additional rules may be released later.

  • The only vulnerability Microsoft says has been exploited in the wild this month is not one of the highest-scoring flaws; CVE-2026-68820 has a CVSS base score of 7.0 and affects the Windows Ancillary Function Driver for WinSock.
  • Several vulnerabilities with very high CVSS scores, including CVE-2026-56162, CVE-2026-63508, and CVE-2026-65667 with 10.0 scores, are listed under “other critical vulnerabilities” rather than among the flaws Microsoft considers more likely to be exploited.
  • Microsoft’s “more likely” critical vulnerabilities include network-reachable flaws in Windows Deployment Services TFTP Server, SharePoint Server, and Windows DHCP Server, giving defenders specific server-side products to prioritize.
  • Talos highlights many “important” vulnerabilities as more likely to be exploited, showing that Microsoft’s exploitation likelihood is not limited to vulnerabilities marked critical.
  • Cisco Talos provided specific Snort 2 and Snort 3 rule coverage identifiers, allowing users of those rule sets to verify whether they have detection coverage for some of the disclosed vulnerabilities.

In plain words

The article says a Russia-linked group called Midnight Blizzard has been tampering with hotel and conference Wi-Fi sign-in pages so travelers are sent to fake Microsoft 365 pages or fake update prompts. People using these networks can have their work account passwords, login approvals, and device data stolen, and some may be tricked into installing harmful software. This matters because it turns ordinary travel Wi-Fi into a way to break into Microsoft 365 accounts across many kinds of organizations, even when extra login checks are in place.

Summary
Microsoft says Russia-linked Midnight Blizzard is hijacking hotel and conference Wi-Fi captive portals to redirect travelers to fake Microsoft 365 login, device-code phishing, and malware pages. The campaign can bypass conventional MFA and deliver CornFlake and ChocoShell to steal credentials, tokens, and cloud access.

Microsoft Threat Intelligence reported an ongoing credential theft campaign called CaptiveCrunch, attributed to Storm-2945, a sub-cluster of Midnight Blizzard linked to Russia. The campaign manipulates DNS and HTTP traffic on captive portal networks at hospitality venues such as hotels and conference centers. Victims are redirected to attacker-controlled infrastructure for Microsoft 365 credential harvesting, device code phishing, and malware delivery.

The article says evidence suggests Storm-2945 compromised shared captive portal services rather than breaching each location individually, with compromised gateways identified in several U.S. cities, India, and Saudi Arabia. CaptiveCrunch targets travelers across a broad range of sectors and has expanded to target Android devices through malicious APK files. Microsoft assessed that Storm-2945 used AI tools to support a significant portion of its operations, including development of the CornFlake and ChocoShell malware.

Storm-2945 uses phishing pages impersonating Microsoft 365, device code phishing pages abusing Microsoft Entra ID authentication, and fake browser or operating system update pages using the ClickFix technique. CornFlake is described as a Go-based Windows RAT with capabilities including keylogging, screenshot capture, surveillance, file exfiltration, USB monitoring, and remote shell execution. ChocoShell is described as an in-memory PowerShell information stealer that disables AMSI, performs sandbox and VM detection, harvests browser credentials and Microsoft 365 and Azure AD/WAM tokens, and exfiltrates collected data to C2 endpoints disguised as tracking pixels and JavaScript files.

  • The article says evidence points to compromised shared captive portal services rather than separate breaches at each hotel or venue, which means one service compromise could affect travelers across multiple locations.
  • Storm-2945’s use of Microsoft Entra device code phishing is especially notable because the article says it abuses a legitimate authentication flow and can bypass conventional multifactor authentication.
  • The campaign combines network-level redirection with fake Microsoft 365 pages and fake update prompts, so users may be attacked before they ever reach a trusted corporate network or normal work login page.
  • The article highlights outbound DNS control as an actionable defense, recommending that organizations block DNS traffic to all destinations except Zscaler’s resolvers to prevent queries from leaking to poisoned resolvers.
  • Microsoft assessed that AI tools supported a significant portion of the operation, including development of CornFlake and ChocoShell, partly based on unusually detailed comments found in the malware code.
Key Points
  • 01Microsoft Threat Intelligence reported an ongoing credential theft campaign called CaptiveCrunch and attributed it to Storm-2945, a sub-cluster of Midnight Blizzard linked to Russia.
  • 02The campaign manipulates DNS and HTTP traffic on captive portal networks at hotels, conference centers, and similar venues to redirect victims to attacker-controlled infrastructure.
  • 03Victims are sent to fake Microsoft 365 sign-in pages, device code phishing pages abusing Microsoft Entra ID authentication, or fake browser and operating system update pages using the ClickFix technique.
  • 04The campaign delivers CornFlake, a Go-based Windows remote access trojan, and ChocoShell, an in-memory PowerShell information stealer that harvests browser credentials and Microsoft 365 and Azure AD/WAM tokens.
  • 05ReliaQuest identified compromised gateways in several U.S. cities, India, and Saudi Arabia, and the article says CaptiveCrunch has expanded to target Android devices through malicious APK files.

In plain words

Researchers found 737 free Chrome add-ons claiming to be VPN or proxy tools, many pretending to be well-known privacy brands, that sent users’ entire browser activity through servers controlled by one provider. The add-ons mainly targeted Russian-speaking people trying to reach blocked services like Instagram, ChatGPT, and YouTube, including users who thought they were installing trusted tools such as AmneziaVPN or AntiZapret. This matters because, while connected, the operator could see where users were browsing, their source internet address, and anything they typed into non-secure websites, while some paid “premium” server locations did not exist.

Summary
Socket researchers found 737 Chrome VPN/proxy extensions, many impersonating trusted privacy brands, that route users’ entire browser traffic through SOCKS5 proxies controlled by a single Russian-linked Myxa VPN operation. The campaign targets Russian-speaking users seeking censorship circumvention and exposes their browsing activity while also using DNS-over-HTTPS evasion, fake premium servers, and Chrome Web Store policy evasion.

Socket’s Threat Research Team identified a campaign of 737 free VPN and proxy extensions published across at least 40 Chrome Web Store developer accounts. Of these, 274 impersonated 66 established VPN and privacy brands, including Proton VPN, NordVPN, Surfshark, Cloudflare’s 1.1.1.1, Google’s Outline, AmneziaVPN, and AntiZapret. The campaign accumulated 75,486 install-count bucket totals, with 516 extensions still active when Socket collected the corpus.

Socket analyzed code from 522 retrieved extensions and found that 520 configured Chrome to route browser traffic through SOCKS5 proxy infrastructure on port 1082, using a bypass list limited to loopback addresses. The extensions mainly targeted Russian-speaking users seeking access to blocked services such as Instagram, ChatGPT, and YouTube. Socket also found 104 extensions that used Cloudflare and Google DNS-over-HTTPS endpoints to resolve their own proxy hostnames and then gave Chrome raw IP addresses.

The report says the extensions placed the operator in a position to observe destinations, TLS SNI values, users’ source IP addresses, and any plain HTTP request contents while connected. Socket also documented non-existent premium server locations, false statements submitted to Chrome Web Store reviewers, post-approval code substitution, and remote configuration behavior. Google had removed 221 of the 737 extensions, but 516 remained live at the time the corpus was collected.

  • The article emphasizes that the proxy behavior alone is not enough to distinguish a malicious browser VPN from a legitimate one, because a real browser-scoped VPN would also need to use Chrome’s proxy capability; the stronger evidence comes from surrounding conduct such as brand impersonation, fake premium locations, false review justifications, and post-approval code substitution.
  • DNS blocking alone would not fully disrupt the campaign because 104 extensions resolved their proxy hostnames through Cloudflare and Google DNS-over-HTTPS endpoints and then handed Chrome raw IP addresses instead of domains.
  • Permission-based review and monitoring can miss meaningful risk changes because 49 extensions received post-approval code updates while the manifest permission set stayed unchanged, including cases where the reviewed and shipped manifests differed only by version and update URL.
  • Chrome Web Store takedowns did not remove the broader operation, as publishers often retained live extensions after removals and one removed extension had 50 structurally identical live counterparts carrying 3,217 installs.
  • Clustering extensions by normalized code structure is more effective than relying on extension IDs or file hashes in this campaign because the actor regenerated names, comments, branding, and server lists across logically similar builds.
Key Points
  • 01Socket’s Threat Research Team identified 737 free VPN and proxy extensions across at least 40 Chrome Web Store developer accounts, with 274 impersonating 66 established VPN and privacy brands.
  • 02Socket analyzed code from 522 retrieved extensions and found that 520 configured Chrome to route browser traffic through the same SOCKS5 proxy infrastructure on port 1082 with only loopback addresses in the bypass list.
  • 03The campaign accumulated 75,486 Chrome Web Store install-count bucket totals across all 737 extensions, including 58,318 installs on 516 extensions that were active when the corpus was collected.
  • 04The extensions mainly targeted Russian-speaking users seeking access to blocked services, and 690 of 734 extensions in the source dataset were Russian-targeted by at least one of Socket’s tests.
  • 05Socket found that all 200 premium server hostnames tested for Japan, Singapore, Canada, Australia, and Turkey returned no A record, while those entries were marked as premium in the shipped server lists.

In plain words

DeadLock is a crime group that locks organizations’ files, steals their data, and then demands payment, and by July its leak site listed 80 mostly European victims across industries such as IT, mining, transportation, manufacturing, hospitality, and consumer goods. Microsoft says the group is now using blockchain-backed and decentralized services to keep its victim chat and leak activity harder to shut down. This matters because it can make it harder for law enforcement or service providers to disrupt the criminals’ communication with victims, although Microsoft notes some parts can still be removed or blocked.

Summary
DeadLock ransomware is using Polygon blockchain smart contracts and decentralized services to keep victim communications and leak-site infrastructure online even if traditional servers are taken down. Microsoft says the setup improves resilience but still depends on components like proxies, RPC endpoints, and Wasabi-hosted files that can be disrupted.

DeadLock ransomware is using decentralized infrastructure backed by blockchain services to protect its victim communications and data-leak activity. The operation emerged in mid-2025 and uses double-extortion tactics, combining data theft or leaks with file encryption to pressure victims into paying. By July, its data leak site listed 80 organizations, mostly in Europe, across sectors including IT, mining, transportation, manufacturing, hospitality, and consumer goods.

Microsoft researchers observed DeadLock being deployed by multiple groups, including an affiliate previously linked to the Lynx and INC ransomware ecosystems. The operators use the Polygon blockchain to store configuration data and leak-site posts, while the victim-facing HTML chat page retrieves the current chat-proxy address through a read-only eth_call. DeadLock also uses the decentralized Session network to encrypt victim communications and provides access to stolen files hosted on Wasabi.

Microsoft said this setup lets the operators replace the chat proxy without modifying the victim-facing application and reduces dependence on conventional domains and web servers that law enforcement can take down. However, Microsoft noted the resilience is not absolute because communications still require the custom proxy, public Polygon RPC endpoints must remain accessible, and Wasabi-hosted files can be removed. DeadLock’s locker avoids certain countries and encrypts selected non-system directories using per-file XChaCha20 keys protected with Curve25519, while limiting resource usage so the victim may continue using the machine during encryption.

  • DeadLock’s use of blockchain-stored command-and-control addresses is notable because Microsoft says this technique is common among cybercriminals but rare in ransomware operations.
  • DeadLock’s infrastructure is more resilient than a conventional Tor or web-server setup, but Microsoft notes it still has disruption points because it depends on a custom proxy, accessible public Polygon RPC endpoints, and removable Wasabi-hosted files.
  • DeadLock is designed to reduce visible disruption during encryption by limiting itself to up to 29% of system memory and 70% of CPU resources so victims may continue using the machine without major performance issues.
  • DeadLock speeds up encryption of larger files by encrypting 512-byte blocks intermittently while still making the files mostly irrecoverable.
  • Microsoft’s defensive recommendations emphasize blocking ransomware behavior after access is gained, including EDR in block mode, tamper protection, Controlled Folder Access, and rules that restrict PsExec and WMI-based lateral movement.
Key Points
  • 01DeadLock ransomware uses decentralized infrastructure backed by blockchain services to support victim communications and data-leak activity.
  • 02Microsoft researchers found that DeadLock stores configuration data and leak-site posts on the Polygon blockchain, with its HTML chat page retrieving the current chat-proxy address through a read-only eth_call.
  • 03DeadLock also uses the decentralized Session network to encrypt victim communications and provides access to stolen files hosted on the Wasabi cloud service.
  • 04Microsoft reported that DeadLock avoids countries in the former Soviet Union and Commonwealth of Independent States region, as well as Iran, Syria, Oman, and Yemen.
  • 05DeadLock encrypts selected non-system directories with per-file XChaCha20 keys protected by Curve25519 and renames encrypted files with a victim-specific identifier and the .dlock extension.

In plain words

Google says Chrome reduced unwanted notifications on Android by more than 7 billion per day in early 2026. These pop-up messages can be used to spread scams, trick people into fake payments, or send them to harmful sites, so this affects people who use Chrome and receive website notifications. Chrome can now automatically turn off notification permission for inactive or suspicious sites, and users can review or turn permissions back on if they choose.

Summary
Google says Chrome’s layered anti-abuse defenses cut more than 7 billion unwanted Android notifications per day by automatically revoking permissions, limiting abusive sites, and detecting coordinated malicious notification networks. Users can review or restore blocked notification permissions in Chrome settings or Safety Hub.

Google says Chrome’s anti-abuse systems reduced unwanted notifications on Android by more than 7 billion per day during the first quarter of 2026. The company says notification abuse is increasingly used to distribute scams, malware, phishing attempts, and fraudulent payment requests. Google describes its approach as a “Swiss cheese” defense model, where overlapping systems try to stop abuse at different stages.

Chrome can automatically remove notification permissions from inactive websites and from sites that repeatedly trigger suspicious-notification warnings. When Chrome revokes permission, it can automatically unsubscribe users from a site’s notifications, while still allowing them to review and restore permissions in Safety Hub. Users can also unsubscribe directly from Android’s notifications panel.

Google also analyzes behavior across networks of related websites, including coordinated service-worker activity, to identify groups distributing malicious or deceptive notifications. The company considers factors such as notification volume, time users spend on a site, permission-prompt frequency, and engagement. Sites classified as disruptive can be limited to 1,000 messages per minute, with excess requests returning an HTTP 429 error, and repeat offenders can face more aggressive restrictions.

  • Chrome’s defenses do not rely only on the content of an individual website; Google also evaluates networks of related sites and coordinated service-worker activity to find persistent bad actors.
  • Notification permissions may be revoked automatically even when a site’s visible content does not appear inherently malicious, based on broader behavior patterns.
  • Google’s enforcement can throttle disruptive sites at the request level, with repeat offenders facing more aggressive restrictions that are only reset after non-disruptive behavior.
  • Users have two practical places to regain control over notifications: Safety Hub for reviewing automatically revoked permissions and Android’s notification panel for unsubscribing directly.
Key Points
  • 01Google says Chrome's anti-abuse systems reduced unwanted notifications on Android by more than 7 billion per day during the first quarter of 2026.
  • 02Google says notification abuse is increasingly used to distribute scams, malware, phishing attempts, and fraudulent payment requests.
  • 03Chrome can automatically remove notification permissions from inactive websites and from sites that repeatedly trigger suspicious-notification warnings.
