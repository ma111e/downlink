Health-ISAC’s Hacking Healthcare highlights a newly published request for information from the National Institute of Standards and Technology about potential changes to the National Vulnerability Database. The article says NIST is considering how the NVD could be revised in response to the rapid evolution of AI and its effect on the cyber threat landscape. It notes that public and private sector efforts are also looking at defensive uses of AI and new vulnerability clearinghouses to coordinate a growing influx of data.

The article describes the NVD as the U.S. government repository of standards-based vulnerability management data and a foundational resource for vulnerability management, software security, compliance automation, and cybersecurity risk analysis. It explains that the NVD helps contextualize and enrich Common Vulnerabilities and Exposures records, which are important for cyber defenders and tools. NIST says traditional approaches such as periodic scanning, static prioritization, and manual remediation are becoming increasingly inadequate.

NIST’s RFI seeks input across seven categories, including strategic planning, technical architecture decisions, standards and best practices, data governance, and community collaboration. Example questions ask how vulnerability information dissemination can be improved and how the NVD can better integrate with vulnerability disclosure programs, vendor advisories, threat intelligence providers, asset management platforms, security tool vendors, and remediation workflows. Responses are due on or before October 13, 2026, at 11:59 p.m. Eastern Time.

In plain words

Socket is expanding its security coverage to Firefox add-ons, so companies can see which browser add-ons their employees use and whether those add-ons are behaving dangerously. This matters because a Firefox add-on that looks harmless can later be updated into something that steals wallet recovery phrases, private keys, passwords, clipboard contents, or other data, often without a new warning to the user. Companies using Firefox are affected because add-ons can read and change web pages, watch browsing activity, and send information to outside services.

Summary
Socket is adding Firefox extension coverage to its browser extension security product, scanning Mozilla’s add-ons ecosystem for malicious behavior, risky permissions, suspicious infrastructure, and dangerous version changes. The launch follows Socket research showing trusted Firefox extensions can be repurposed through automatic updates into wallet stealers, credential thieves, and clipboard monitors.

Socket is expanding its browser extension security coverage to Firefox, giving security teams visibility into extensions used across their organizations. The company says it now proactively scans every Firefox extension listed in Mozilla’s official addons.mozilla.org directory, which Mozilla’s public API listed as 97,100 Firefox-compatible extensions at the time of publication. Socket also says it will continue monitoring new releases so teams can see when an extension’s behavior changes.

The article says Firefox extensions are an enterprise blind spot because they can read and modify web pages, access tabs, interact with the clipboard, observe browsing activity, and communicate with external services. It emphasizes that extension names, publishers, install counts, and permission lists do not show what the code actually does or where it sends data. Updates from Mozilla’s official add-ons directory are delivered automatically, and a new prompt appears only when an update adds permissions, so behavior can change within already granted permissions without another prompt.

Socket’s recent Firefox threat research identified 77 linked Firefox extension identities active from at least March through August 2026, with 40 confirmed as malicious and 37 described as deceptive sports-score shells connected through shared code, infrastructure, and version histories. The malicious extensions delivered remotely controlled wallet-phishing pages, captured recovery phrases and private keys, exfiltrated wallet keyrings, or stole credentials and clipboard contents. Firefox extension protection is now available in Experimental to Socket enterprise customers, expanding the browser extension coverage Socket previously introduced with Chrome.

  • A Firefox extension can become malicious without triggering a new user permission prompt if its update changes behavior while staying within permissions the user already granted.
  • Permission review alone can miss serious risk, because one remote-loader cluster in Socket’s research requested only `storage` and `tabs` while still presenting significant danger.
  • Version history is especially important for extension security because nine confirmed malicious extension identities had previously shipped as sports-score shells before becoming wallet stealers.
  • Install counts, reviews, familiar branding, and a clean initial release are weak indicators of safety once an extension identity can be repurposed through automatic updates.
  • Socket’s analysis focuses on linking code, metadata, infrastructure, and version changes, which can reveal coordinated campaigns that may not be visible from individual extension listings alone.
Key Points

  • 02Mozilla's public API listed 97,100 Firefox-compatible extensions at the time of publication, and Socket says it will continue monitoring new releases for behavior changes.
  • 03Socket's Firefox threat research identified 77 linked Firefox extension identities active from at least March through August 2026, with 40 confirmed as malicious and 37 described as deceptive sports-score shells connected through shared code, infrastructure, and version histories.
  • 04The malicious Firefox extensions delivered remotely controlled wallet-phishing pages, captured recovery phrases and private keys, exfiltrated wallet keyrings, or stole credentials and clipboard contents.
  • 05Firefox extension protection is now available in Experimental to Socket enterprise customers, expanding the browser extension coverage Socket introduced with Chrome.
