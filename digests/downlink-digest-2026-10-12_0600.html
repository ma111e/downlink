Attackers Exploit CVSS 10.0 Bricksforge WordPress Flaw Enabling Unauthenticated RCE
thehackernews.com · 12 Oct 2026 09:02 UTC openai-codex / gpt-5.6-terra

In plain words

Criminals are actively taking advantage of a serious flaw in the Bricksforge add-on used by some WordPress websites, letting them place and run harmful files without needing to log in. Websites using Bricksforge version 3.1.8.9 or older are affected, and owners should update because an intruder could take over the site, steal information, or leave hidden access behind. The article also notes similar problems in two other WordPress add-ons, showing that unpatched website software can expose many sites to compromise.

Summary
Attackers are actively exploiting CVE-2026-85097, a CVSS 10.0 flaw in Bricksforge for WordPress versions through 3.1.8.9, to upload PHP payloads and achieve unauthenticated remote code execution. Site owners should update Bricksforge to a patched release immediately and investigate suspicious form submissions and PHP files in its temporary upload directory.

Patchstack reported active exploitation of CVE-2026-85097, a CVSS 10.0 vulnerability in the Bricksforge WordPress plugin. The flaw affects versions through 3.1.8.9 and allows unauthenticated attackers to upload and run arbitrary PHP code, potentially taking control of a website, stealing data, deploying web shells, and maintaining access. Bricksforge patched the issue in version 3.1.8.10, and the article advises users to update to the latest release, version 4.0.1.

The issue occurs because Bricksforge validates a file’s type at upload but later trusts file metadata supplied during form submission, including an unvalidated URL field in the temporaryFileUploads parameter. Attackers can obtain a valid nonce, upload an image file containing PHP code, then submit manipulated metadata that points to the image on disk while assigning it a PHP filename for execution. Patchstack observed attacks against Bricksforge form-submission endpoints, including automated attempts using alternate, mixed-case, and encoded PHP extensions, and recommends reviewing suspicious submissions and unexpected PHP files in the Bricksforge temporary upload directory.

  • The Bricksforge issue arises not because the initial upload check fails, but because the plugin later trusts file-location information supplied during form submission, allowing an already accepted image file to be placed under a PHP filename.
  • Attackers tested alternate, mixed-case, and encoded PHP filename extensions, indicating that simple filtering for only the standard “.php” extension may not detect all observed attempts.
  • Patchstack observed one cluster of 44 IP addresses sending 56 identical requests within seconds and another testing 25 filename variations, patterns it said indicate automated activity using rotating proxies or distributed infrastructure.
  • Updating WPC Product Bundles for WooCommerce or Ninja Forms stops additional exploitation but does not remove an existing infection, so owners must also check directly for hidden administrator accounts, must-use plugins, and server logs.
  • For Bricksforge, the article specifically identifies repeated submissions containing the “temporaryFileUploads” parameter and unexpected PHP files in the plugin’s temporary upload directory as useful signs to investigate.
Key Points
  • 01Patchstack reported active exploitation of CVE-2026-85097, a CVSS 10.0 Bricksforge vulnerability that permits unauthenticated attackers to upload and execute arbitrary PHP code on affected WordPress sites.
  • 02The flaw affects Bricksforge versions through 3.1.8.9 and was patched in version 3.1.8.10; the article advises updating to the latest version, 4.0.1.
  • 03Attackers obtain a nonce, upload a GIF or PNG file containing PHP code, and then submit manipulated file metadata that causes the content to be written under a PHP filename.
  • 04Patchstack observed attacks against the Bricksforge REST form-submission endpoint and the WordPress admin AJAX endpoint, including attempts using alternate, mixed-case, and encoded PHP extensions.
  • 05The article also reports exploited XSS flaws in WPC Product Bundles for WooCommerce and Ninja Forms that can deliver a script to install a backdoor plugin and create unauthorized administrator accounts.

CyberXero Uses Claude Code in Campaign That Stole Over 628,000 Ukrainian Records
thehackernews.com · 12 Oct 2026 07:26 UTC openai-codex / gpt-5.6-terra
TAGSadaptixc2brazilchinaclaude-codecobalt-strikecyberxerodevice-code-phishingjapanmasterblacknetherlandspassword-sprayingpentagipolandsql-injectionukraine

In plain words

Researchers say a Russian-speaking criminal group called CyberXero used AI software and common hacking tools to break into websites, online stores, and some Ukrainian energy and utility organizations. The group reportedly stole more than 628,000 records about people in Ukraine, while other victims were found in Poland, China, and the Netherlands. The report also describes a separate operation that used stolen company data to send millions of fake invoice messages in Brazil, showing how AI can help criminals carry out scams and break-ins at a much larger scale.

Summary
SOCRadar reports that Russian-speaking initial-access broker CyberXero used Claude Code and other AI agents alongside Cobalt Strike to automate attacks on WordPress, e-commerce, Redis, and Ukrainian critical-infrastructure targets, stealing more than 628,000 Ukrainian records. The exposed attacker workspace also shows how AI-assisted offensive tooling is being used to scale both access-broker activity and financially motivated fraud operations.

SOCRadar reported that a Russian-speaking initial-access broker called CyberXero conducted two AI-assisted campaigns: a global automated effort against WordPress and e-commerce platforms, and a more selective effort against Ukrainian energy and critical-infrastructure organizations. Confirmed theft from four Ukrainian organizations reportedly exposed more than 628,000 records related to Ukrainian individuals, while confirmed compromises also occurred in Poland, China, and the Netherlands. Researchers discovered an exposed directory containing the actor’s AI session logs, scripts, reconnaissance data, tooling, configurations, and exfiltrated victim data.

CyberXero used Claude Code with 51 specialized agents for scanning, exploit chaining, reconnaissance, and post-exploitation, and linked the self-hosted PentAGI agent to Cobalt Strike for payload generation and penetration-testing execution. In one recorded automated run, the operation scanned 4,708 targets, identified access to 429 WordPress administration panels, and deployed 32 web shells in 61 seconds. The article also describes Operation Master, a separate SOCRadar-tracked operation that combined network compromises and data theft with a Brazilian invoice-fraud platform that sent more than 2.4 million email, SMS, and WhatsApp messages.

  • CyberXero separated its activity into a high-volume, automated path aimed at monetizable WordPress and e-commerce access and a selective path focused on deep reconnaissance of Ukrainian energy and utility targets, for which SOCRadar found no obvious direct financial motive.
  • One automated run scanned 4,708 targets, identified access to 429 WordPress administration panels, and deployed 32 web shells within 61 seconds, illustrating the speed documented in the exposed operational data.
  • The leaked AI transcripts show that safety controls sometimes blocked harmful tasks, including backdoor installation, firewall disabling, lateral movement, web-shell deployment, and a scan using a forged ownership token; however, the operator reportedly retried by opening new sessions framed as authorized testing.
  • The Operation Master fraud platform generated more than 2.4 million messages and 622,666 personalized invoice links, but recorded 169,906 target interactions, indicating that the campaign tracked recipient engagement at scale.
  • Organizations exposing Redis servers were specifically advised to check for unexpected SSH authorized-key entries, in addition to rogue WordPress administrators and WSO web shells.
Key Points
  • 01SOCRadar attributed a two-pronged campaign targeting WordPress, e-commerce platforms, and Ukrainian critical infrastructure to a Russian-speaking initial-access broker it calls CyberXero.
  • 02The campaign reportedly caused confirmed data theft from four Ukrainian organizations, exposing more than 628,000 records tied to Ukrainian individuals, with additional confirmed compromises in Poland, China, and the Netherlands.
  • 03An exposed directory on a server at 46.21.250[.]135 contained CyberXero's AI session logs, scripts with plaintext tokens, exploitation tools, reconnaissance output, AI agent configurations, and victim data.
  • 04CyberXero used Claude Code with 51 specialized agents and connected the self-hosted PentAGI AI agent to Cobalt Strike for payload generation and penetration-testing execution.
  • 05SOCRadar also described Operation Master, which allegedly combined enterprise intrusions and stolen databases with an automated invoice-fraud platform that generated more than 2.4 million email, SMS, and WhatsApp messages targeting Brazilian recipients.
