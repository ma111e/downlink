In plain words

U.S. officials say ransomware groups are using a serious weakness in WatchGuard Firebox internet security devices to break into organizations’ networks. The problem affects certain Firebox devices that have not received WatchGuard’s December fixes, particularly when they use a specific type of remote connection. This matters because thousands of potentially exposed devices remain online, putting the small and midsize businesses that rely on them at risk of having their systems locked up or disrupted for payment.

Summary
CISA warns that ransomware groups are exploiting the critical WatchGuard Firebox RCE flaw CVE-2025-14733, affecting unpatched Fireware OS devices configured with IKEv2 VPN. Organizations should apply WatchGuard’s patches immediately and check vendor-provided indicators of compromise.

CISA has confirmed that ransomware gangs are exploiting CVE-2025-14733, a critical remote-code-execution flaw in WatchGuard Firebox firewalls. The vulnerability is an out-of-bounds write that allows unauthenticated attackers to run malicious code remotely in low-complexity attacks. CISA updated its Known Exploited Vulnerabilities catalog to state that ransomware groups are using the flaw, although it did not provide details on the attacks.

CVE-2025-14733 affects Firebox devices running specified Fireware OS 11.x, 12.x, and 2025.1 versions. WatchGuard issued patches in December and said unpatched devices are vulnerable when configured for IKEv2 VPN; devices may also remain exposed if a branch-office VPN to a static gateway peer is still configured even after vulnerable configurations are removed. Shadowserver found more than 115,000 exposed unpatched devices in December, and nearly 9,000 remained unsecured nine months later.

  • Removing an IKEv2 VPN configuration may not fully eliminate exposure if the Firebox still has a branch-office VPN connection to a static gateway peer configured.
  • WatchGuard published indicators of compromise, giving organizations a way to check whether their Firebox devices may already have been breached rather than relying only on patching.
  • Despite public patches and active-exploitation warnings, Shadowserver found that nearly 9,000 affected Firebox devices remained unsecured nine months later.
  • The article notes that CVE-2025-14733 is almost identical to the earlier Firebox RCE flaw CVE-2025-9242, which was also later identified by CISA as actively exploited.
Key Points
  • 01CISA says ransomware gangs are exploiting CVE-2025-14733, a critical WatchGuard Firebox flaw that can let an unauthenticated attacker run malicious code remotely.
  • 02CVE-2025-14733 affects Firebox devices running specified Fireware OS 11.x, 12.x, and 2025.1 releases, and WatchGuard issued security patches for it in December.
  • 03WatchGuard said unpatched Firebox devices are vulnerable when configured to use IKEv2 VPN, and some devices may remain at risk if a branch-office VPN to a static gateway peer is configured.
  • 04Shadowserver reported that more than 115,000 vulnerable Firebox devices were exposed online in December and that nearly 9,000 remained unsecured nine months later.
  • 05CISA added CVE-2025-14733 to its Known Exploited Vulnerabilities catalog and required U.S. federal agencies to secure affected systems within one week.

In plain words

SAP fixed a critical flaw called CVE-2026-44756 that could let an outsider run commands on affected SAP business systems without first logging in. It can affect many SAP products, especially public-facing services used for web access, employee tools, and connections between business systems. If abused, the flaw could allow attackers to steal account information, change settings, access active user sessions, or alter SAP software, so organizations need to find exposed systems and install SAP’s update quickly.

Summary
SAP patched CVE-2026-44756 (OVERPASS), a critical pre-authentication SAP kernel flaw that can enable remote code execution through HTTP(S), SAP GUI, or RFC services. Organizations should urgently apply SAP Security Note 3747649 and restrict exposed SAP endpoints until patching is complete.

CVE-2026-44756, tracked by SAP as OVERPASS, is a critical CVSS 10.0 memory corruption flaw in SAP kernel processing of Extended Passport data. Missing boundary validation during data processing can cause unsafe memory behavior when externally supplied length fields are handled. Because this occurs as a session opens, an unauthenticated attacker with network access to a listening SAP service can potentially execute operating system commands under the SAP system account.

The flaw is reachable through HTTP/HTTPS services, SAP GUI connections, and system-to-system RFC connections, so no single network control covers every affected path. Affected product lines include SAP S/4HANA, SAP ERP and Business Suite, SAP NetWeaver Application Server ABAP, SAP Web Dispatcher, SAP BW/4HANA, SAP Enterprise Portal, SAP PI/PO, and SAP Solution Manager. SAP released a kernel fix through Security Note 3747649 on September 8, 2026; organizations are advised to identify internet-facing SAP endpoints, restrict RFC and SAP Dispatcher access, and use the HTTP-specific workaround in Note 3756304 if patching must wait.

  • The HTTP-specific workaround in SAP Note 3756304 is not a complete mitigation because SAP GUI and RFC paths can still reach the vulnerable kernel code.
  • The article says exposure data was largely based on service fingerprints rather than confirmed version checks, meaning observed systems should be treated as potentially exposed rather than definitively vulnerable.
  • Internet-facing SAP systems may be missed by routine patch processes because they are often Web Dispatcher or Internet Communication Manager endpoints supporting legitimate Fiori, WebGUI, or API traffic.
  • Third-party-operated, regional, subsidiary, and partner integration SAP environments can complicate remediation because patch responsibility may be split across different operational owners.
  • A single kernel patch remediates all three affected access paths, but organizations must verify the correct target patch level for each kernel release rather than assuming one uniform version.
Key Points
  • 01CVE-2026-44756, also called OVERPASS, is a CVSS 10.0 memory corruption flaw in SAP kernel processing of Extended Passport data.
  • 02An unauthenticated attacker with network access to a listening SAP service can potentially execute operating system commands through HTTP/HTTPS, SAP GUI, or RFC protocol paths.
  • 03Affected SAP products include SAP S/4HANA, SAP ERP and Business Suite, SAP NetWeaver Application Server ABAP, SAP Web Dispatcher, SAP BW/4HANA, SAP Enterprise Portal, SAP PI/PO, and SAP Solution Manager.
  • 04SAP released a fix on September 8, 2026 through SAP Security Note 3747649, while SAP Note 3756304 provides an HTTP-specific workaround for organizations that cannot patch immediately.
  • 05The article states that there was no public evidence of exploitation in the wild as of publication and recommends identifying exposed SAP endpoints, restricting RFC and SAP Dispatcher access, and confirming patching.

In plain words

Researchers found that nearly one in ten internet-facing LiteLLM systems accepted the simple example administrator password shown in the product’s setup guide. Organizations using those systems could have their paid AI service keys, private AI conversations, and cloud-account access exposed to anyone who knew that password. This can let criminals use costly AI services on the victim’s bill or potentially reach other company systems, so operators need to replace the example password and install current security updates.

Summary
Nearly 10% of internet-exposed LiteLLM gateways scanned by Wiz accepted the documented default admin key, potentially exposing provider API keys and cloud IAM credentials. Operators should immediately rotate the master key, upgrade to LiteLLM 1.84.0 or later, and restrict risky MCP, guardrail, and outbound pass-through access.

Wiz Research found that 294 of 3,074 internet-facing LiteLLM gateways scanned in February accepted sk-1234, the example administrator key in LiteLLM’s setup guide. Of those, 191 had no master key configured and would accept any key, while the remaining systems retained the documented example value. Because the master key is both the administrator credential and the mechanism enabling authentication, an exposed or default key can give an attacker broad control of the gateway. LiteLLM’s guide still showed sk-1234 as of September 9, alongside an instruction to replace it before real use.

An administrator can access stored model-provider API keys, prompts and responses, connected MCP tools, and pass-through endpoints. Wiz demonstrated that pass-through endpoints could be directed to cloud instance metadata services to retrieve IAM credentials, including with IMDSv2 by forwarding required headers through LiteLLM’s x-pass- feature. The article also covers several fixed LiteLLM flaws, including MCP authentication bypasses, command execution through MCP test endpoints, and guardrail-related code execution issues; CISA added CVE-2026-59822 to its Known Exploited Vulnerabilities catalog. Operators are advised to replace the master key, upgrade to LiteLLM 1.84.0 or later, restrict risky MCP and guardrail endpoints if unable to upgrade, limit outbound network access, and rotate credentials if compromise is suspected.

  • The LiteLLM master key is especially consequential because it both enables authentication and acts as the administrator credential, so leaving it unset previously gave every caller full administrator rights.
  • Using IMDSv2 alone does not prevent the demonstrated cloud-credential retrieval path, because LiteLLM can forward specially prefixed client headers to the cloud metadata service.
  • Updating LiteLLM does not remove malicious guardrails already registered by an attacker or SSH keys they may have added, so suspected compromise requires credential rotation and configuration review in addition to patching.
  • The February and August internet-exposure counts cannot be compared because Wiz said most of the more than 85,000 instances observed in August appeared to be honeypots or test systems.
Key Points
  • 01Wiz found that 294 of 3,074 internet-facing LiteLLM gateways scanned in February accepted the example admin key "sk-1234," with 191 accepting any key because no master key was configured.
  • 02LiteLLM administrators can access stored model-provider API keys, prompts and responses, connected MCP tools, and pass-through routes that Wiz demonstrated could retrieve cloud instance credentials.
  • 03LiteLLM versions before 1.82.0-stable allowed callers full administrator rights when no master key was set and contained a custom guardrail flaw that enabled code execution inside the gateway container.
  • 04CISA added CVE-2026-59822, an MCP authentication bypass affecting LiteLLM versions before 1.84.0, to its Known Exploited Vulnerabilities catalog, while Wiz observed probing of its honeypots using single-character Bearer tokens.
  • 05The article recommends changing the master key, upgrading to LiteLLM 1.84.0 or later, blocking vulnerable MCP and guardrail endpoints when upgrades are not possible, and restricting outbound network access and cloud permissions.
