    In plain words

    A harmful update to the Tensorlake software package was published on npm, a common source for software developers, and it can steal passwords, access keys, and other private information from a developer’s computer. It can also use stolen access to copy itself into other software projects and set up files that run again when a project is opened in VS Code or Claude Code. People who installed version 0.5.144 or ran the affected Tensorlake code are at risk, and they must first remove its hidden token-checking service before canceling their GitHub access token, because canceling it can trigger deletion of their personal files.

    Summary
    The npm package tensorlake@0.5.144 is compromised with a credential-stealing worm that spreads through GitHub and npm and installs a monitor that can wipe a victim’s home directory if its stolen GitHub token is revoked. Remove the gh-token-monitor persistence mechanism before rotating any credentials, and pin Tensorlake to 0.5.143.

    tensorlake@0.5.144 on npm was compromised with code that runs during installation, steals credentials and other sensitive files, and attempts to spread into other packages and repositories. The malicious files were pushed directly to the tensorlakeai/tensorlake main branch under a maintainer identity before the affected version was released through the repository’s release workflow. Although the release has an npm provenance attestation, the article notes that provenance shows where a package was built, not whether its code is safe.

    The installation hook targets developer machines, skips CI, downloads Bun, and runs an obfuscated file that collects GitHub and npm tokens, cloud and Kubernetes credentials, SSH keys, browser logins, and AI-tool configuration files. Stolen npm tokens can be used to republish infected packages, while stolen GitHub tokens can be used to add .claude and .vscode files that execute when repositories are opened in Claude Code or VS Code. The malware also installs a gh-token-monitor service that can delete the user’s home directory if its stolen GitHub token is revoked, so affected users are instructed to remove that service before rotating credentials.

    • The malicious release had a valid npm provenance attestation because it was published from the legitimate repository’s release workflow, showing that provenance identifies where a package was built rather than whether its code is safe.
    • Revoking the stolen GitHub token before disabling the installed monitor can trigger deletion of the user’s home directory, so cleanup order is critical.
    • The install hook intentionally skips CI systems, indicating that developer computers rather than automated build jobs are the primary target.
    • The malware can persist beyond the initial package installation by placing configuration files in repositories that run when someone opens them in Claude Code or VS Code.
    • The compromised code was pushed directly to the Tensorlake main branch without pull requests before the affected npm version was published.
    Key Points
    • 01The npm package tensorlake@0.5.144 contains a malicious preinstall hook that runs when the package is installed on developer machines and is designed to skip CI environments.
    • 02The payload steals GitHub and npm tokens, cloud keys, Kubernetes and Vault secrets, SSH keys, saved browser logins, and configuration files for Claude, Cursor, and Windsurf.
    • 03Using stolen npm and GitHub tokens, the malware can republish infected packages and commit .claude and .vscode files to repositories accessible to the victim.
    • 04The malware installs a gh-token-monitor service that checks a stolen GitHub token every 60 seconds and deletes the user’s home directory if the token is rejected.
    • 05Affected users should remove the gh-token-monitor service before revoking or rotating GitHub tokens and other credentials.

    A harmful version of the tensorlake software package, version 0.5.144, was published for developers to download from npm after someone gained access to its code repository. It can copy passwords, cloud access keys, cryptocurrency wallet information, and data stored by web browsers, then send them to the attacker while trying to spread into other software projects.     Summary
    The npm package tensorlake version 0.5.144 was compromised with a Shai-Hulud worm that steals credentials and browser wallet data, self-propagates through supply chains, and can wipe hosts if its embedded GitHub token is revoked. Treat any installation as fully compromised: remove the version, investigate affected systems, and immediately rotate all potentially exposed secrets.

    On 8 October 2026, a threat actor published tensorlake version 0.5.144 to npm with a variant of the Shai-Hulud worm. Tensorlake is a serverless sandbox for AI agents with more than 100,000 reported lifetime npm installs. The article reports no evidence that the attacker published compromised tensorlake packages to PyPI or Cargo. The malicious code was introduced after the attacker made verified commits under a maintainer identity in the tensorlake GitHub repository.

    The package’s preinstall script runs an obfuscated setup script that drops Bun and uses it to execute an obfuscated Shai-Hulud payload. The payload attempts to steal sensitive environment variables, local credential files, browser-store data, and IndexedDB and LevelDB data associated with 14 cryptocurrency wallet browser extensions. It uses the hardcoded domain iseekaigogo[.]com and can retrieve an alternate command-and-control destination from an attacker-controlled Ethereum contract. The article advises treating any infected system as fully compromised and immediately rotating all secrets and credentials it contained.

    • The payload includes a tensorlake-specific WORMTAG marker, which the article says indicates a new compromise rather than reinfection from an earlier Shai-Hulud wave.
    • Although the tensorlake repository was compromised for about 20 hours, the attacker only succeeded in publishing the malicious package to npm; the article found no evidence of publication to PyPI or Cargo.
    • The malware expands beyond common developer and cloud credentials by targeting IndexedDB and LevelDB files from 14 named cryptocurrency wallet browser extensions.
    • It can retrieve its command-and-control destination through an attacker-controlled Ethereum contract using multiple public Ethereum RPC services, even though the contract’s latest value matches its hardcoded domain.
    • The payload includes a dead-man’s switch intended to wipe infected machines if an embedded GitHub token is revoked, making credential response and investigation particularly time-sensitive.
    Key Points
    • 01A compromised version of the tensorlake npm package, version 0.5.144, was published on 8 October 2026 and contains a variant of the Shai-Hulud worm.
    • 02The malware runs through a preinstall script, installs or uses the Bun runtime, and executes an obfuscated payload in lib/Math_Symbol.js.
    • 03The payload attempts to collect sensitive environment variables, local credential files, browser data, and data from 14 cryptocurrency browser extensions.
    • 04The malware uses the hardcoded domain iseekaigogo[.]com and can also retrieve an alternate command-and-control address from an Ethereum contract.
    • 05The article advises treating infected systems as fully compromised and immediately rotating any secrets or credentials they contained.

Tensorlake’s npm SDK version 0.5.144 was compromised with the Shai-Hulud/ChainDrop credential-stealing worm, which runs during installation via a preinstall hook and can steal secrets, establish persistence, and spread through npm. Organizations that installed it should treat affected hosts as compromised, remove persistence before revoking tokens, and rebuild systems from trusted sources.

Tensorlake’s npm SDK version 0.5.144 was compromised in a ChainDrop/Shai-Hulud supply-chain attack. Published on October 8, 2026, the release contained obfuscated malware and was flagged by Socket about 11 minutes later. The malicious package used a preinstall hook, meaning its code could run during installation without a developer importing the SDK or starting an AI agent.

The payload targets credentials and sensitive data from npm, GitHub, AWS, Kubernetes, HashiCorp Vault, SSH keys, environment files, cryptocurrency wallets, messaging applications, and AI development tools. It can send collected data to attackers, establish persistent access, execute remotely supplied code, and use stolen npm publishing credentials to spread to other packages. Its remote endpoint is resolved through an Ethereum contract using public RPC endpoints, with a GitHub fallback.

Organizations that installed tensorlake@0.5.144 should treat hosts where the installation script ran as compromised. The article advises blocking the version, isolating affected systems, investigating persistence, and removing the gh-token-monitor before revoking GitHub tokens because revocation can trigger an attacker-supplied handler intended to wipe the user’s home directory. Teams should then replace exposed credentials, audit connected accounts for unauthorized activity, and rebuild affected environments from trusted sources.

  • Installing the compromised SDK was sufficient for exposure because its preinstall hook ran before developers imported the package or used any AI agent functionality.
  • The package’s use in AI-agent infrastructure does not protect the installation environment: the malicious code runs on the developer workstation, server, or build runner before any generated code reaches Tensorlake’s isolated sandbox.
  • The remote control endpoint was not hardcoded; the payload resolved it through an Ethereum contract using public RPC services, with a GitHub fallback.
  • Revoking a stolen GitHub token before removing the persistent gh-token-monitor can trigger attacker-supplied code intended to wipe the affected user’s home directory.
  • The reported 12,000 weekly downloads reflect the package’s overall usage and do not establish how many times the malicious release was downloaded or how many systems were infected.
Key Points
  • 01Tensorlake npm SDK version 0.5.144, published on October 8, 2026, contained obfuscated malicious code associated with the ChainDrop/Shai-Hulud supply-chain campaign.
  • 02A preinstall script ran the malicious loader during package installation, so the code could execute without a developer importing the SDK or starting an agent.
  • 03The payload targeted npm and GitHub tokens, AWS and Kubernetes credentials, HashiCorp Vault, SSH keys, environment files, cryptocurrency wallets, messaging-app data, and AI development-tool configuration files.
  • 04The malware could exfiltrate collected secrets, establish persistence, execute attacker-supplied code, and use stolen npm publishing credentials to spread to additional packages.
  • 05Organizations that installed tensorlake@0.5.144 are advised to isolate affected hosts, remove the gh-token-monitor persistence mechanism before revoking tokens, rotate exposed credentials, and rebuild affected environments from trusted sources.
