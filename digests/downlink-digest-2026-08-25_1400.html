In plain words

The article describes a flaw in NVIDIA NemoClaw, a tool for running the OpenClaw AI agent, where simply visiting a malicious website could give the attacker control over the local Ollama model service on a developer’s machine. People using NemoClaw with local Ollama are affected, and the attacker could quietly change how the model behaves so the AI agent follows hidden instructions later. This matters because the agent may have access to code, internal tools, cloud services, or other work resources, so controlling the agent can put more than just one computer at risk.

Summary
A NemoClaw configuration that exposes Ollama on 0.0.0.0 lets a malicious website use DNS rebinding to gain unauthenticated access to the local model server. An attacker can then persistently poison the model’s chat template, silently steering the victim’s AI agent even when it supplies its own system prompt.

A vulnerability in NVIDIA NemoClaw, identified in the article as CVE-2026-65105, can let an attacker gain full, unauthenticated control over the local Ollama model server used by the OpenClaw AI agent. The attack can begin with a single visit to an attacker-controlled webpage. Oasis Security found the issue during research into non-human identity and AI agent risks and reported the findings to NVIDIA through its Product Security Incident Response Team before publication.

NemoClaw configures Ollama with OLLAMA_HOST=0.0.0.0:11434 so OpenShell Docker containers can reach the host’s local inference service. That binding exposes Ollama on every network interface and causes Ollama’s Host header validation to be skipped, leaving only CORS protections. The article explains that DNS rebinding can bypass those remaining protections by making browser requests to the attacker’s domain reach the victim’s local Ollama API while still appearing same-origin.

Once the attacker has access to Ollama’s API, they can run inference on the victim’s hardware, enumerate models and system details, delete or pull models, and modify model configurations. The article highlights model template poisoning as the most impactful payload, because changing the model’s chat template can append attacker-controlled instructions to future conversations even when the OpenClaw agent sends its own system prompt. The poisoned template persists across future interactions, affects all consumers of the model, and could steer an agent that has access to organizational resources such as source control systems, CI/CD pipelines, internal APIs, cloud services, communication platforms, and MCP servers.

  • The installation message says NemoClaw is using Ollama on localhost:11434, but the actual binding is 0.0.0.0, which can give users a misleading impression that the service is only reachable locally.
  • Ollama’s Host header protection is specifically disabled when the service is bound to a non-loopback address, so NemoClaw’s container-reachability choice removes a defense designed to stop browser-based local service access.
  • Poisoning the model’s system field is less effective against OpenClaw because the agent supplies its own system prompt, but poisoning the model template works because it changes how all future messages are rendered before the model sees them.
  • The poisoned template can preserve the model’s original formatting and tool-rendering behavior while adding hidden instructions, making the compromise harder to notice through normal model use.
  • OpenShell sandboxing may protect the host endpoint, but the article emphasizes that the practical blast radius comes from the AI agent’s authorized access to organizational resources such as source control, CI/CD pipelines, internal APIs, cloud services, and MCP servers.
Key Points
  • 01A vulnerability in NVIDIA NemoClaw can let an attacker gain full, unauthenticated control over the local Ollama model server after the victim visits an attacker-controlled webpage.
  • 02NemoClaw starts Ollama with OLLAMA_HOST=0.0.0.0:11434 so OpenShell containers can reach it, which exposes the unauthenticated Ollama API beyond localhost and disables Ollama’s Host header validation.
  • 03The attack uses DNS rebinding so browser requests to the attacker’s domain are redirected to the victim’s local Ollama instance while still passing Ollama’s remaining CORS checks.
  • 04With access to the Ollama API, an attacker can run inference on the victim’s hardware, enumerate installed models and system details, delete or pull models, and modify model configurations.
  • 05The researchers found that poisoning the model’s chat template through Ollama’s /api/create endpoint can persistently append attacker-controlled instructions to future agent interactions, even when the OpenClaw agent sends its own system prompt.
