Red Hat has released kernel updates for RHEL 8, 9, and 10 to address CVE-2026-98432, a Linux IPv4 TCP use-after-free flaw rated Critical at 9.8. The Linux kernel CVE team also rates the issue 9.8, while Red Hat raised its initial 5.9 Moderate rating after further assessment. Ubuntu fixes for 22.04 LTS, 24.04 LTS, and 26.04 LTS are currently in the opt-in -proposed testing channel, while Ubuntu 20.04, 18.04, and 16.04 do not yet have fixes.

The issue occurs when a server accepts an IPv4 TCP connection and passes IP options to a new socket without copying them, allowing a retransmitted request to cause the kernel to read memory that has already been freed. A remote attacker needs no login and can trigger the race by sending connection requests with IPv4 Record Route or Timestamp options to a listening TCP port. Red Hat’s interim nftables rule drops inbound IPv4 TCP packets carrying IP options, but it is not a complete mitigation and can be bypassed by traffic between containers on the same host. No active exploitation had been reported, although Anthropic said an internal research model created a remote root exploit for Linux servers with an MPTCP listener.

  • Disabling Multipath TCP alone is not considered sufficient because the underlying flaw is in the IPv4 TCP path rather than Multipath TCP itself.
