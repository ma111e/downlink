A high-severity flaw in the open-source Windmill developer platform is being actively exploited in the wild, according to VulnCheck. The vulnerability, tracked as CVE-2026-29059 with a CVSS score of 7.5, is an unauthenticated path traversal issue in Windmill’s get_log_file endpoint. VulnCheck said exploitation efforts have targeted the endpoint to extract sensitive information from /etc/passwd, and it identified about 170 vulnerable exposed systems across 24 countries.

Windmill said the vulnerable filename parameter was concatenated into a file path without sanitization, allowing attackers to read arbitrary server files using ../ sequences. Windmill noted that SUPERADMIN_SECRET is not set by default, so standalone instances without it configured are limited to arbitrary file read impact. The issue was fixed in Windmill 1.603.3 by adding sanitization checks to the filename parameter.

The article also notes that CISA added four other exploited vulnerabilities to its Known Exploited Vulnerabilities catalog, including two WordPress bugs known as wp2shell, a DD-WRT buffer overflow, and a Langflow remote code execution flaw. Wordfence described wp2shell as a major WordPress Core security event because of its unauthenticated reachability, broad attack surface, path to administrator access and code execution, and public proof-of-concept availability. KEVIntel reported exploitation attempts against the Langflow flaw from 46 unique attacker IP addresses across 17 countries, with observed payloads including checks, attempts to read /etc/passwd, AWS credential access, environment variable collection, malware downloads, and shell script execution.
