Emerging Threat: (CVE-2026-56291) Balbooa Forms Remote Code Execution via Unauthenticated File Upload
cycognito.com · 12 Jul 2026 18:48 UTC openai-codex / gpt-5.5
TAGSarbitrary-file-uploadbalbooa-formscisacisa-known-exploited-vulnerabilitiescom-baformscve-2026-56291cwe-434cycognitojoomlaunauthenticated-file-upload
95
In plain words

A serious flaw was found in Balbooa Forms, a tool used on Joomla websites to build forms, that lets any visitor upload a harmful file and then run it on the website’s server. Public Joomla sites that use Balbooa Forms version 2.4.0 or earlier are affected, especially sites with contact, registration, survey, or file attachment forms. This matters because criminals are already using the flaw to take control of sites, steal data, deface pages, add hidden access for later, or use one hacked site to attack others.

Summary
CVE-2026-56291 is a critical, actively exploited unauthenticated file upload flaw in Balbooa Forms for Joomla that can let attackers upload and run PHP files for full remote code execution. Sites using Balbooa Forms 2.4.0 or earlier should update to 2.4.1 immediately and check for compromise.

CVE-2026-56291 is an unauthenticated arbitrary file upload vulnerability in Balbooa Forms, a commercial drag-and-drop form builder for Joomla installed as the com_baforms component. The flaw affects Balbooa Forms up to and including version 2.4.0 and is classified as CWE-434. It has a CVSS v3.1 base score of 9.8 and a CVSS v4.0 base score of 10.0, and the article says it is listed in CISA’s Known Exploited Vulnerabilities catalog and is being actively exploited in the wild.

The vulnerable frontend attachment upload accepts files from anonymous visitors without a login, CSRF token, or extension allow-list. Because the upload handler trusts the caller-supplied filename and Joomla’s built-in filename cleaner does not strip a .php extension, an attacker can upload a PHP file into a web-served directory and then request it in a browser. By default, uploaded files land under images/baforms/uploads/ inside the web root, where they can be served and executed directly. The article states that the practical impact is full remote code execution, which can enable data theft, defacement, backdoors, or pivoting to other systems.

Balbooa fixed the vulnerability in Balbooa Forms 2.4.1, released on 9 July 2026, and any installation on 2.4.0 or earlier should be treated as vulnerable until updated. The article says updating alone is not sufficient because the flaw was exploited before the patch shipped, so exposed sites should be checked for compromise, including unexpected files in the upload directory and unfamiliar administrator accounts. Recommended actions include inventorying internet-facing Joomla sites, identifying Balbooa Forms installations, restricting upload endpoints where feasible, blocking script execution in upload directories, monitoring relevant POST requests, auditing Super User accounts, and scanning for unexpected PHP files.

  • Updating to Balbooa Forms 2.4.1 is not enough by itself because the flaw was exploited before the patch was released, so previously exposed sites need compromise checks as well.
  • The exposed assets may be difficult to identify externally because Joomla can be detected from the internet but extensions such as Balbooa Forms are not always fingerprintable.
  • Risk is concentrated in forgotten or loosely governed public web properties such as campaign sites, registration pages, localized microsites, and older brand or regional sites rather than only in core applications.
  • A practical mitigation before all upgrades are confirmed is to block script execution specifically in upload directories such as images/baforms/uploads/.
  • The upload endpoint can be reachable to any visitor even without a published form or guest setting being enabled, which makes simple assumptions about form visibility unreliable.
Key Points
  • 01CVE-2026-56291 is an unauthenticated arbitrary file upload vulnerability in Balbooa Forms, the com_baforms component for Joomla, and is classified as CWE-434.
  • 02The vulnerability affects Balbooa Forms up to and including version 2.4.0 and can allow an anonymous attacker to upload a PHP file into a web-served directory and execute it for remote code execution.
  • 03The flaw has a CVSS v3.1 base score of 9.8 and a CVSS v4.0 base score of 10.0, is listed in CISA’s Known Exploited Vulnerabilities catalog, and is being actively exploited in the wild.
  • 04Balbooa fixed the vulnerability in Balbooa Forms 2.4.1, released on 9 July 2026, but sites that ran affected versions while exposed should also be checked for signs of compromise.
  • 05Recommended actions include inventorying internet-facing Joomla sites, identifying Balbooa Forms installations, blocking script execution in upload directories, monitoring relevant POST requests, auditing Super User accounts, and scanning upload directories for unexpected PHP files.

RedHook Android malware now uses Wireless ADB for shell access

In plain words

A new version of the RedHook Android malware can trick people into giving it special phone permissions, then turn on hidden developer features to control the phone without needing it to be connected to a computer. Android users who install fake apps from fake Google Play sites and approve these permissions can be affected. Once active, it can watch the screen, record typing, steal contacts and messages, install or remove apps, open the camera, and keep itself running. This matters because attackers are impersonating government agencies and financial institutions to get victims to install it, putting personal and financial information at risk.

Summary
RedHook Android malware now abuses Wireless ADB by tricking users into granting Accessibility permissions, giving attackers shell-level access without rooting the device. This lets it silently run privileged commands, steal data, control the screen, install or remove apps, and maintain persistence.

A new version of the RedHook Android malware abuses Android Wireless Debugging to gain shell-level privileges without requiring a computer connection. Group-IB researchers analyzed the release and said it significantly expands the malware’s capabilities compared with the previous variant documented in 2025. The malware also retains remote access trojan features, including screen streaming, keystroke interception, UI automation, and credential theft.

RedHook tricks victims into granting Accessibility permissions, then uses them to manipulate Settings, enable Developer Options, and activate Wireless Debugging. It retrieves the pairing code shown on the screen and connects to the phone’s ADB service through the loopback interface at 127.0.0.1. Once paired, it gains shell UID 2000 privileges, which are more powerful than normal Android app permissions but are not root-level.

The malware deploys a Shizuku-based framework to run shell commands, grant itself additional permissions, change protected Android settings, and silently install or remove applications. Group-IB reported that the current version supports 53 server-issued commands, including screen capture, simulated gestures, device locking and unlocking, data collection, fake dialogs, camera activation, and rebooting. RedHook is distributed through social engineering in which attackers impersonate government agencies or financial institutions and direct victims to fake Google Play sites.

  • RedHook’s abuse of Wireless ADB is notable because the article says the entire attack chain works without rooting the device and can apply across Android devices if the user is tricked into approving Accessibility Service permissions.
  • The malware’s use of Shizuku is significant because Shizuku is described as a legitimate Android utility for power users and developers, showing RedHook incorporates legitimate tooling into its privileged command execution chain.
  • RedHook combines several persistence methods at once, including silent audio playback, WakeLocks, mutually restarting services, a five-minute watchdog alarm, restart after boot, and oom_score_adj changes to reduce the chance of termination.
  • The distribution method remains heavily dependent on social engineering, with attackers impersonating government agencies or financial institutions and directing victims to fake Google Play sites.
Key Points

  • 02RedHook tricks victims into granting Accessibility permissions, then uses those permissions to enable Developer Options, activate Wireless Debugging, retrieve the pairing code, and connect to the phone’s ADB service through 127.0.0.1.
  • 03Once paired, RedHook gains shell UID 2000 privileges, which are more powerful than normal Android app permissions but are not root-level privileges.
  • 04The malware uses a Shizuku-based framework to execute shell commands, grant itself additional permissions, modify protected Android settings, and silently install or remove applications.
  • 05Group-IB reported that the latest RedHook version supports 53 server-issued commands, including screen streaming, screenshots, simulated gestures, app installation and removal, data collection, overlay creation, camera activation, and device rebooting.

In plain words

A freight and logistics company received an email that looked almost empty, but the attached calendar invite contained fake internal compliance pages, a link, and a QR code meant to trick an operations manager into entering their login details. The message reached the inbox even after two email-filtering systems treated it as safe, because the dangerous parts were hidden inside the calendar file rather than the email text. This matters because one employee completing what looked like a normal workplace review could have handed attackers access to company accounts, and the article says breaches that start this way can cost millions of dollars.

Summary
A phishing email hid its entire credential-harvesting lure inside an .ics calendar invite, using embedded images, a personalized link, and a QR code to bypass body-focused email scanning. The key lesson is that defenses must inspect and render calendar attachments, including OCR and QR decoding, instead of treating them as harmless scheduling data.

A freight and logistics company received a phishing email whose body was almost empty, containing only an unusual sender banner and an inline company logo. The attack was hidden inside an .ics calendar invite attachment that carried a multi-page internal compliance lure as embedded base64 images. The lure impersonated an internal “Code of Conduct Assessment” and pushed the recipient toward a credential-harvesting page.

The calendar file contained both a plaintext personalized phishing link and a QR code encoding the same URL, with the recipient’s corporate email address included in the URL path. The credential-harvest domain was mghins[.]net, an aged, Cloudflare-fronted domain with no MX, SPF, or DMARC records. The message came from a compromised Microsoft 365 mailbox on a legitimate domain, but authentication alignment broke after it was relayed through unauthorized infrastructure.

The message reached the inbox even though a Barracuda gateway scored it benign and Microsoft assigned it a trusted spam confidence level of -1. IRONSCALES Themis flagged it at 90% phishing confidence by rendering and OCRing the embedded images, decoding the QR code, and correlating sender and relay mismatches. The article’s main defensive takeaway is that calendar invites should be inspected like content-bearing attachments, including embedded images, hidden links, and QR codes.

  • Calendar invites can become an email security blind spot because some gateways treat .ics files as scheduling data rather than attachments whose images, links, and QR codes need inspection.
  • A nearly empty email body can be a deliberate evasion tactic, because body-focused scanners may have no visible text, link, or button to score.
  • An older, quiet domain with no mail records can evade reputation checks that focus heavily on newly registered phishing domains.
  • Embedding the recipient’s own email address in the phishing URL can make the credential page appear more legitimate by letting it pre-fill or personalize the victim’s identity.
  • QR codes inside attachments can move the victim from a corporate computer to a personal phone, where company email controls may not protect the user.

  • 02The .ics file contained a multi-page internal compliance lure rendered as embedded base64 images, along with a personalized credential-harvest link and a QR code encoding the same URL.
  • 03The phishing URL used the recipient’s own corporate email address in the path, allowing the landing page to appear personalized to that mailbox.
