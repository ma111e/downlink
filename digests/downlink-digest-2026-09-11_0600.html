In plain words

Cisco says three groups have been using two flaws in its Secure Firewall Management Center software to break into organizations’ systems without proper permission. The affected organizations could have passwords and other sensitive information stolen, while attackers may install hidden access tools, disrupt security software, or lock selected computers and demand money through Qilin ransomware. Cisco has released fixes and urges customers using the affected software to install them quickly; U.S. federal civilian agencies are required to do so by September 12, 2026.

Summary
Cisco warns that ransomware and state-linked threat clusters are actively exploiting two patched Secure Firewall Management Center flaws to gain access, steal credentials, deploy backdoors, and in one case launch Qilin ransomware. Organizations should immediately apply Cisco’s hotfixes for CVE-2026-20079 and CVE-2026-20316.

Cisco disclosed that three threat clusters linked to ransomware and state-sponsored activity have exploited two recently patched vulnerabilities in Cisco Secure Firewall Management Center (FMC). CVE-2026-20079, rated 10.0, allows an unauthenticated remote attacker to bypass web-interface authentication, execute scripts, and obtain root access to the underlying operating system. CVE-2026-20316, rated 5.3, allows unauthenticated remote login through a low-privilege account and can be combined with other FMC flaws to elevate privileges.

UAT-12197 used the critical flaw to install JSP web shells and a Java-based command tool to query internal databases and obtain authentication data and credentials. UAT-11823 exploited both flaws to deploy a Netcat reverse shell, harvest managed-device configurations, and install a Cyclops Blink variant previously attributed to Sandworm. UAT-11988 used CVE-2026-20316 for initial access, conducted reconnaissance and credential collection with built-in FMC tools, and deployed Qilin ransomware on selected systems. Cisco urges affected customers to apply released hotfixes, while CISA has added both flaws to its Known Exploited Vulnerabilities catalog and requires U.S. federal civilian agencies to patch CVE-2026-20079 by September 12, 2026.

  • The two flaws support different levels of access: CVE-2026-20079 can enable remote root-level access, while CVE-2026-20316 provides low-privilege access that can be combined with other FMC flaws to gain more control.
  • The same affected FMC platform was used for distinct attacker goals, including credential collection, harvesting managed-device configurations, deployment of a state-linked Cyclops Blink variant, and Qilin ransomware operations.
  • The Qilin-linked activity relied in part on legitimate built-in FMC tools to map the victim environment and identify systems for encryption, rather than relying only on externally introduced tools.
  • Patch urgency is reinforced by Cisco’s hotfix recommendation, its planned broader hardening release, and CISA’s requirement that U.S. federal civilian agencies remediate CVE-2026-20079 by September 12, 2026.
Key Points
  • 01Cisco reported that three threat clusters linked to ransomware and state-sponsored activity exploited two recently patched Cisco Secure Firewall Management Center vulnerabilities.
  • 02CVE-2026-20079 is a critical authentication-bypass flaw that can let an unauthenticated remote attacker execute scripts and obtain root access to the underlying operating system.
  • 03UAT-12197 used CVE-2026-20079 to deploy web shells and a Java-based command tool that queried internal databases for user authentication data and credentials.
  • 04UAT-11823 exploited both flaws to deploy a reverse shell, collect managed-device configurations, and install a Cyclops Blink variant.
  • 05UAT-11988 exploited CVE-2026-20316, used built-in FMC tools for reconnaissance and credential collection, and deployed Qilin ransomware on selected systems.

thehackernews.com · 11 Sep 2026 07:31 UTC openai-codex / gpt-5.6-terra

In plain words

Attackers have been breaking into unpatched self-hosted JFrog Artifactory servers, which companies use to store software components for their build systems, and giving themselves full administrator control. They used flaws that let them obtain access without logging in, create hidden administrator accounts, and install programs that let them continue controlling the server. This matters because a compromised software repository can affect the systems and software that depend on it, and simply installing the updates may not remove accounts, access keys, or backdoors already planted.

Summary
Attackers are actively chaining two patched JFrog Artifactory flaws, CVE-2026-42018 and CVE-2026-42016, to obtain administrator access and deploy persistent backdoors on unpatched self-hosted servers. Organizations should urgently upgrade, rotate join keys and tokens, and investigate for rogue admin accounts, plugins, and activity attributed to token:anonymous.

Wiz observed attackers exploiting unpatched self-hosted JFrog Artifactory servers between August 15 and September 8 by chaining CVE-2026-42018 and CVE-2026-42016. The first flaw can provide an internal anonymous-user token to someone who has not logged in, while the second can let that low-privilege token be exchanged for one with administrator scope. Actions performed with the resulting token may appear in logs as token:anonymous, despite having administrator-level permissions. Wiz saw some attackers create new administrator accounts in less than five minutes.

With administrator access, attackers created persistent administrator accounts, installed malicious Groovy plugins that enabled code execution on the server, and ran shell commands to explore files. A dropper downloaded a binary over HTTP into locations such as /tmp and opened a command-and-control channel, while a custom Rust backdoor was also seen in multiple cases. Separately, CVE-2026-82329 is a critical authentication bypass that can grant unauthenticated attackers administrator privileges on its own across affected Artifactory release branches. Updating Artifactory is necessary, but it does not remove accounts, tokens, backdoors, or join keys that may already have been created or stolen, so the article recommends reviewing administrator accounts and configuration changes and rotating join keys and relevant tokens.

  • Administrator actions performed through the chained flaws can appear in Artifactory logs as "token:anonymous," which can obscure that an attacker had elevated privileges.
  • Wiz observed some attackers progress from an unauthenticated request to creating a new administrator account in under five minutes.
  • Although the two-flaw chain does not affect certain newer Artifactory branches, the separate CVE-2026-82329 authentication bypass can still affect releases up to version 7.161.
  • For CVE-2026-82329, organizations unable to upgrade immediately can add a randomly generated extra join key in system.yaml so only their own keys are accepted during service registration.
  • Fastly recorded roughly 406,000 CVE-2026-82329 exploitation attempts on September 2, but noted that these traffic observations do not represent confirmed compromises.
Key Points
  • 01Wiz observed attacks from August 15 to September 8 that chained CVE-2026-42018 and CVE-2026-42016 in unpatched self-hosted JFrog Artifactory servers to obtain administrator-level access.
  • 02CVE-2026-42018 can return an internal anonymous-user token to an unauthenticated caller, while CVE-2026-42016 can allow a low-privilege token to be exchanged for one with administrator scope.
  • 03Attackers created administrator accounts, installed malicious Groovy plugins for server code execution, ran shell commands, and in some cases deployed a custom Rust backdoor.
  • 04CVE-2026-82329 is a separate critical authentication bypass that can grant unauthenticated attackers administrator privileges on affected Artifactory branches without requiring another flaw.
  • 05Patching does not remove administrator accounts, tokens, backdoors, or join keys that attackers may have already created or stolen, so affected organizations should also rotate join keys and tokens and review accounts and configuration changes.

In plain words

A China-linked hacking group used a weakness in the Windows version of Sogou Input Method, a Chinese typing tool used by hundreds of millions of people, to install software that gave them remote control of a victim’s computer. Someone could be led to a harmful link through email or chat, and the program’s outdated built-in web browser allowed the attackers to run programs as the signed-in user. Tencent released an update to block this route, but the article says the old browser component and some of its safety protections remain unchanged, making updates and awareness important for users who may have been exposed.

Summary
China-linked UNC3569 exploited a Sogou Input Method Windows flaw to use a single crafted link to launch an outdated, unsandboxed Chromium instance and install the GRAYRABBIT backdoor. Tencent patched the link-handler entry point in Sogou Input Method version 16.3.0.3498, but its embedded Chromium 80 engine and disabled browser protections remain.

Gen Digital said China-linked UNC3569 exploited a flaw in the Windows version of Sogou Input Method to install its GRAYRABBIT backdoor. The attack used a crafted sgbiz: link to pass attacker-controlled arguments to Sogou’s settings program, which opened an attacker-selected site in the application’s built-in browser. Gen said a victim clicking the link was enough to give the attacker code execution with the logged-in user’s privileges, although Tencent said social engineering would be needed to have the user authorize a browser pop-up.

The exploit used CVE-2021-38003, a Chrome JavaScript-engine flaw fixed in 2021 but still present in Sogou’s Chromium 80 build from 2020. Gen found that Sogou’s browser sandbox and same-origin protection were disabled, removing a normal barrier between a compromised web page and the computer. The payload used a malicious DLL loaded through 7-Zip to install GRAYRABBIT, which provides remote command access and communicates over RC4-scrambled TCP on port 443.

Tencent released a fix in Sogou Input Method version 16.3.0.3498 that blocks unapproved web addresses in the sgbiz: link handler. However, Gen found that the product still uses Chromium 80 and retains the disabled browser security settings. The article advises updating Sogou Input Method and checking for published indicators, including files written to C:\Users\Public\Documents and connections to mail.uaiubifas[.]top.

  • Tencent’s patch restricts the web addresses accepted by the Sogou link handler, but Gen found that the product still uses Chromium 80 with its sandbox and web-security protections disabled.
  • The malicious loader avoided many automated analysis environments by decrypting its payload only when it detected at least 50 running processes, then removed itself using an NTFS alternate data stream.
  • Even though the backdoor used port 443, its communications were RC4-scrambled plain TCP rather than normal TLS-encrypted web traffic, providing a specific detection clue.
  • The affected input method has a very large potential reach: Citizen Lab estimated more than 455 million monthly users across Windows, Android, and iOS, although Gen’s reported flaw is in the Windows version.
Key Points

  • 02A crafted sgbiz: link could pass attacker-controlled arguments to Sogou's settings program, which opened the attacker’s chosen website in its built-in browser.
  • 03The attack used CVE-2021-38003 in Sogou’s Chromium 80-based browser, whose sandbox and same-origin protections were disabled, to run code with the logged-in user’s privileges.
  • 04The attackers used a malicious DLL loaded by 7-Zip to decrypt and install GRAYRABBIT, which communicates with mail.uaiubifas[.]top over RC4-scrambled TCP traffic on port 443.
