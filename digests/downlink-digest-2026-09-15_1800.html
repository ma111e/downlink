Summary

Customers should restore from a known-safe backup or remove the malicious plugin files, object-cache directory, and associated database entries.

An unauthorized party compromised the adminmenueditor.com website and distributed malicious updates for Admin Menu Editor Pro, a premium WordPress plugin. Versions 2.35 and 2.36 contained an added file, includes/wp-user-consent.php, that installed a web shell and created a hidden user account on affected sites. The initial malicious version 2.35 was available from approximately 06:00 to 13:00 UTC before developer Janis Elsts removed it and released version 2.36. However, the attacker still had access to the website and also compromised that replacement version.

At least 230 customers installed the first malicious update on at least 1,500 sites, and the total may be larger because several hundred additional customers downloaded the plugin near the relevant time window. The developer believes the attacker likely had root-level server access and took the website offline while restoring it safely. Customers using versions 2.35 or 2.36 should check for the added PHP file, a /wp-content/object-cache/ directory, hidden database users beginning with wp_, and wp_ocache* database options. Restoring from a safe backup made before September 14 is the recommended fix; version 2.34 and the free Admin Menu Editor plugin are believed to be unaffected.

  • A safe backup from before September 14 is described as the most reliable recovery method, indicating that removing the plugin alone may not fully undo the changes.

In plain words

Researchers uncovered KREMLIN, a banking-focused program that tricks people with fake bank, invoice, or company documents and then adds a harmful extension to Chrome or Edge. The extension can steal passwords, login cookies that may keep someone signed in, browsing information, screenshots, and the contents of web pages. The campaign has mainly affected people in Brazil, and its operators use Ethereum-based online records to frequently change their control servers, making the operation harder to shut down.

Summary
Elastic researchers uncovered KREMLIN, a Brazilian banking-malware operation that installs malicious Chrome and Edge extensions to steal credentials, session tokens, cookies, and browser data. The campaign uses multi-stage loaders, SentinelOne DLL sideloading, Chromium preference-integrity bypasses, and Ethereum smart contracts to rotate its command-and-control infrastructure.

Elastic Security Labs has identified a Brazilian banking-malware operation, tracked as REF9334, that delivers a toolkit called KREMLIN. Active since at least May 2025, the operation uses lures impersonating Brazilian banks, invoices, or companies to persuade victims to run a JavaScript file. The malware ultimately installs a malicious browser extension in Google Chrome or Microsoft Edge to steal credentials, session tokens, cookies, browser storage, screenshots, and web-page content.

KREMLIN uses multi-stage JavaScript loaders, a custom C++ installer, and a legitimate SentinelOne binary to sideload an unsigned DLL disguised as SentinelAgentCore.dll. It bypasses Chromium extension-integrity protections by modifying Secure Preferences, enabling developer mode, and adding forged metadata, while Ethereum smart contracts provide changing locations for payloads and command-and-control servers. Elastic registered the malware’s network-canary domain and observed 1,515 infected systems attempting to contact it, with more than 98% geolocated in Brazil; this action temporarily degraded the campaign’s anti-sandbox defense and may give defenders more time to identify affected endpoints.

  • KREMLIN uses an Ethereum smart contract as a resilient lookup mechanism for payload and command-server locations, allowing its operators to change infrastructure without embedding fixed addresses in the malware.
  • The malware’s anti-analysis network check created an unexpected defensive opportunity: after Elastic registered the unregistered canary domain, infected systems contacting it could be identified, and the campaign’s defense mechanism was temporarily degraded.
  • The malicious extension is only downloaded when it is absent or its locally installed version differs from the version reported by the operator-controlled server, reducing unnecessary downloads.
  • Although the extension attempts to collect up to 1,000 browser-history entries from the prior 15 days, researchers noted that this likely fails because its manifest does not request browser-history permission.
Key Points

  • 02KREMLIN uses document-themed JavaScript files to launch multi-stage loaders, then installs a malicious Chrome or Edge extension named “AVSync System Inc.” that steals credentials, session tokens, cookies, browser storage, screenshots, and page contents.

  • 04KREMLIN bypasses Chromium extension protections by modifying Secure Preferences, enabling developer mode, and generating forged metadata to register its malicious extension.

Victims may be tricked into entering bank details, speaking to fake fraud agents, or downloading a harmful file. This matters because the criminals can quickly replace blocked addresses and hide fake pages from researchers, allowing scams and account theft to continue at scale.

Summary
Silent Push identified a large phishing ecosystem using fast-flux DNS services to rapidly rotate IP infrastructure and evade takedowns, including campaigns impersonating Canadian banks and international financial brands. The operators combine DNS rotation with traffic cloaking, per-victim URLs, live credential theft, callback scams, and gated malware downloads to defeat automated scanning.

Silent Push reported identifying thousands of live phishing domains using fast-flux infrastructure, in which domains rapidly rotate across many IP addresses, networks, and countries to make IP-based blocking difficult. The company said it purchased access to a fast-flux service to study its customer setup and develop detection analytics based on the DNS delegation layer used by customers. Its platform query combined nameserver, ASN, and IP-diversity indicators to find domains associated with the service.

One cluster targeted nearly 2,000 domains, with roughly 90% impersonating Canadian organizations including banks, the tax authority, Canada Post, and provincial benefit programs. These sites used Keitaro traffic-distribution cloaking, single-use victim URLs, device profiling, and 404 responses for many scanners, researchers, and foreign visitors, while operators could collect keystrokes and direct victims through additional phishing steps. A second cluster used fake fraud hotlines and cloned login forms, then offered a Windows executable in a password-protected ZIP only after a live agent supplied a one-time code, limiting exposure to automated scanning.

The article argues that the provider-controlled DNS delegation layer offers a detection opportunity even as underlying IP addresses change. It recommends DNS-level monitoring for high IP and ASN diversity, low DNS time-to-live values, and inconsistent IP geolocation, as well as blocking confirmed malicious domains, IPs, and infrastructure tied to bulletproof or abuse-tolerant networks. Silent Push also cites a joint CISA advisory that calls fast flux a national-security threat and encourages accurate, reliable, and timely detection and blocking capabilities.

  • The provider-controlled DNS delegation layer is a durable detection point because fast-flux providers keep their own domains separate from customer infrastructure while customers delegate domains to provider-controlled nameservers.
  • The Canadian phishing operation used commercial traffic-distribution cloaking to show most outside scanners a 404 page, while selected Canadian residential visitors received single-use phishing URLs.
  • The phishing kits were operator-driven rather than static: operators could receive victim keystrokes before form submission, direct victims through additional pages, and test stolen credentials against real banks in parallel.
  • The callback operation withheld its malicious Windows download until a live agent issued a one-time code, and delivered it in a password-protected ZIP to reduce exposure to email and web scanning.
  • Fast-flux services were marketed as subscription products with customer portals, support systems, anonymous registration, and cryptocurrency payments, lowering the barrier for phishing operators to use rapidly changing infrastructure.
Key Points

  • 02The identified infrastructure rapidly rotates a domain across IP addresses and networks, which makes IP-address blocking less effective.
  • 03One phishing cluster targeted nearly 2,000 domains, with roughly nine in ten impersonating Canadian organizations such as major banks, the tax authority, Canada Post, and provincial benefit programs.
  • 04The Canadian banking campaign used Keitaro traffic distribution software to filter visitors, showing phishing pages to selected Canadian residential users while many other visitors received a 404 page.

Summary

While some deployments appear to be labs, others show sophisticated operational infrastructure, making these fingerprints useful for proactive network and host-based detection.

Mythic is an open-source, plugin-based command-and-control framework used for authorized red-team work and also observed in unauthorized intrusions. As of September 11, 2026, Censys tracked 131 unique internet-exposed Mythic hosts across 307 service hits. Most of these hosts could be identified through default deployment fingerprints, including self-signed certificates with O=Mythic or O=Mythic C2, which appeared on 115 hosts.

Port 7443 appeared on 99 tracked hosts, and Mythic’s default Nginx reverse proxy returns HTTP 502 responses to unauthenticated requests on that port. Ten hosts also exposed other command-and-control frameworks, including Sliver, Adaptix C2, Havoc, and FRP; the article distinguishes an apparent multi-tool lab cluster from a separate cluster that used custom domains, custom payload development, Discord-related scripts, and Mythic tasking scripts. Censys recommends using certificate names, the default CN=operators to CN=multiplayer certificate chain, port 7443 activity, and unexpected Mythic Docker container names to detect potential Mythic infrastructure or internal systems communicating with it.

  • Default Mythic certificate subject organizations, "Mythic" and "Mythic C2," covered 115 of 131 tracked hosts, giving defenders a high-coverage way to identify many exposed deployments.
  • A shared nine-port fingerprint, identical self-signed certificate, generic reverse DNS, and multiple C2 frameworks across three hosts led the article to assess that cluster as a shared lab or training fleet rather than an operational deployment.
  • The article shows that a Mythic-only footprint can still support substantial custom tooling: one four-host cluster included eleven sequential Windows payload builds, Rust source code, Discord transport diagnostics, steganography scripts, and Mythic tasking scripts.
  • Only 6 tracked hosts retained Mythic’s unchanged internal certificate chain from "CN=operators" to "CN=multiplayer," making that combination a narrower but especially specific default-installation indicator.
  • Port-based counts should be interpreted carefully because the article’s port aggregation includes every open port on matched hosts, rather than proving that each port is a Mythic listener.
