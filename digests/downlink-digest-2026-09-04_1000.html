Summary

Google updated Chrome to address an actively exploited high-severity zero-day flaw in the V8 engine and 11 other vulnerabilities. The exploited issue is tracked as CVE-2026-85046 and is described as a type confusion vulnerability. Google said an exploit for the flaw exists in the wild but did not disclose technical or exploitation details to give users and dependent projects time to apply the fix.

The update brings Chrome to version 152.0.7977.82/.83 on Windows and macOS and 152.0.7977.82 on Linux as part of a gradual rollout. Type confusion flaws can cause software to misinterpret one type of object as another, allowing attackers to corrupt memory. Because V8 is Chrome’s JavaScript and WebAssembly engine, the article says CVE-2026-85046 could potentially be triggered by a specially crafted HTML page containing malicious JavaScript, potentially allowing remote code execution within Chrome’s sandboxed renderer process.

The update also addresses nine other high-severity vulnerabilities, including use-after-free and out-of-bounds memory flaws in several Chrome components and a race condition in V8. CVE-2026-85046 is the sixth actively exploited Chrome bug Google has fixed since the start of the year. Chrome users are advised to update through Settings > About Chrome and restart the browser, while users of Chrome-based browsers such as Microsoft Edge, Brave, Opera, and Vivaldi may need to wait a few additional days for fixes.

Summary
Kaspersky reports that the financially motivated Toy Ghouls group has added custom backdoors to its arsenal, using HiveMQ MQTT and Matrix/Element as command-and-control channels. The shift from public tools to custom malware suggests the group is becoming more sophisticated and harder to detect.

Kaspersky reports that Toy Ghouls, also known as Bearlyfy, Laboo.boo, and Feral Wolf, has begun using a custom backdoor against Russian organizations. The group previously relied on tools from public GitHub repositories, leaked Babuk and LockBit ransomware builders, and later its own GenieLocker ransomware. In early July 2026, researchers observed the group using a custom backdoor for the first time.

Two versions of the backdoor were identified: mqtt-bird-agent 0.1.0, which uses the HiveMQ MQTT broker as its C2 server, and matrix-bird-agent 0.1.0, which relies on the Element messenger. The attackers deliver the backdoors and configuration files to compromised systems using Windows Remote Management with tools such as Evil-WinRM and WinRM-fs. Both versions can run interactively or establish persistence as Windows services, and they use configuration data that may be encrypted with a machine-bound key.

Both backdoor versions contact ip-api.com at startup to determine the system’s public IP address and country of origin. They send status and system metrics, receive commands from the attackers, execute those commands through PowerShell or the Windows command line, and return execution results. The article concludes that Toy Ghouls’ move from public tools to custom-built malware and unconventional C2 channels suggests an effort to make attacks more sophisticated and evade detection for longer.

  • The backdoor’s configuration becomes tied to the infected machine using the Windows MachineGuid value, so investigators may need access to the original host to decrypt sealed configuration data.
  • The Element version removes its configuration file after first run and stores the sealed configuration in HKLM\Software\synapse\Config\SealedConfig, making registry examination important even if config.toml is missing.
  • The attackers disguise persistence with service names and descriptions that resemble legitimate Windows components, including cplsupport as “Problem Reports Control Panel” and wtas as “Windows Telemetry Aggregator Service.”
  • The use of legitimate services such as broker.hivemq.com, meet.element.tw, and ip-api.com means suspicious activity may appear as connections to otherwise normal internet resources rather than obviously malicious infrastructure.

This matters because even emails that pass normal sender checks can still be scams, and stolen legitimate mail is being reused to make phishing harder to spot.

Summary
A credential-phishing email passed SPF, DKIM, DMARC, and Microsoft composite authentication by using controlled or repurposed infrastructure, then hid a malicious settlement-agreement link behind an ESP tracker. Its key evasion tactic was padding the short lure with a stolen legitimate commercial email to make the message look statistically normal to scanners while keeping the real phish visible to the victim.

A fully authenticated phishing email reached two mailboxes at a food service packaging manufacturer with an empty subject, a four-line settlement approval lure, and a single link. SPF, DKIM, DMARC, and Microsoft composite authentication all passed, but the sender alias asserted the recipient organization’s own name from an unrelated sending domain. Themis scored the message at 89% confidence for credential theft, and both affected mailboxes were quarantined and mitigated.

The link was labeled as a signer approval settlement agreement PDF using the recipient company’s name, but no attachment was present. Its hover text advertised one unrelated commercial domain, while the actual link went through a Mandrill click tracking URL to a credential page on secure.individual-elegance.co.za. The article says the tracker received a mixed verdict and the terminal page was scored as malicious.

The most notable technique was padding: after roughly seventy blank line breaks, the email reproduced a complete, unrelated legitimate commercial email that had been sent to a different person at a different organization. This stolen filler changed the message’s link ratios, text volume, and boilerplate profile while pushing the borrowed content below what a reader would likely see. The article recommends normalizing messages before scoring them, detecting unrelated appended markup, resolving tracking links to their final destination, and checking for display-name impersonation, malformed sender local parts, and mismatched anchor titles and destinations.

  • The strongest available authentication result did not reduce the phishing risk in this case because the sending domain authenticated itself, not the organization named in the sender alias.
  • The stolen legitimate email padding changed measurable content ratios such as link count, text volume, and boilerplate presence, making the message appear more like normal commercial mail to automated analysis.
  • Long runs of blank line breaks served a dual purpose: they hid the borrowed content from the reader while still allowing parsers to count it as part of the message.
  • The malformed sender local part containing marketing tracking parameters was an actionable signal that the kit had likely pasted a scraped tracking string into an email address field.
  • Comparing an anchor’s visible hover title with its actual destination and resolving ESP tracking links to their final landing page were decisive checks that did not depend on sender authentication.
Key Points

  • 02The visible lure was a four-line settlement approval message using the recipient’s first name, full email address, and company name, with a single link disguised as a signer approval settlement agreement PDF.
  • 03The link used a Mandrill click tracking URL that relayed to a credential page on secure.individual-elegance.co.za, which the platform scored as malicious.
